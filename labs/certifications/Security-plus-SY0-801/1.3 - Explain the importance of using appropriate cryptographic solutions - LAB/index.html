Aurelia Regional Health Network keeps patient records, runs a public appointment portal, and ships nightly backup tapes. Last quarter: a laptop was stolen from a clinician’s car, a network engineer reported unknown traffic on a switch span port, and the administrator who built the backup system left the company — without handing over keys. The (fictional) HCS-11 audit lands this week. Your job: commission every cryptographic control properly, not just “turn on some encryption”.

Knowledge core — the five decisions this lab drills (objective 1.3 sub-areas)
1. PUBLIC KEY INFRASTRUCTURE A key pair is two mathematically linked halves: · PUBLIC key → shared with the world: others ENCRYPT to you, VERIFY your signatures · PRIVATE key → never leaves your control: you DECRYPT, you SIGN · KEY ESCROW → a trusted third party holds key copies so data is recoverable 2. CERTIFICATES A certificate binds a public key to an identity, signed by an authority (CA) you already trust — the ROOT OF TRUST chain. · CSR = signed request (identity + public key) sent to a CA · Types: third-party CA · internal CA · self-signed; wildcard (*.arhn.example) covers one label deep, SAN lists explicit alternative names · Revocation: CRL (periodic downloaded list) vs OCSP (real-time query) vs OCSP stapling (server presents the signed status itself) 3. ENCRYPTION Symmetric = one shared secret, fast, bulk data (AES-256). Asymmetric = key pair, slow, used for key exchange + signatures. Levels: full-disk · partition · file · volume · database · record Protocols: transport (TLS), key exchange (ephemeral ECDHE → PFS), algorithms + key length (AES-256 beats AES-128 beats nothing) 4. HASHING & SIGNATURES A hash is a one-way fingerprint: integrity only. A salt (unique random value per password) defeats rainbow tables. DIGITAL SIGNATURE = hash of the document encrypted with the signer's PRIVATE key, verified by anyone with the PUBLIC key. Proves integrity, authenticity and NON-REPUDIATION — not confidentiality. 5. KEY MANAGEMENT Keys age. Rotate them, escrow the irreplaceable ones, destroy the retired ones, choose adequate lengths — or the best cipher protects nothing.

Debrief — what you commissioned, and what it defends

Detection opportunities you now own

  • Certificate expiry & revocation monitoring: alert on notAfter < 14 days, and on any REVOKED OCSP answer for a live service (INC-004 pattern).
  • TLS posture telemetry: log negotiated protocol, key exchange and cipher per session; alert on non-ephemeral exchanges and short key lengths.
  • Password-store audits: alert on identical hashes across accounts (unsalted store symptom) and on legacy algorithm use (MD5).
  • Integrity verification jobs: scheduled hash comparisons of backups and manifests — the bench you ran, automated.
  • Key inventory reviews: unescrowed keys, keys older than rotation policy, keys of departed staff still active.

Blue-team takeaways

  • Confidentiality, integrity and non-repudiation come from different tools; no single control delivers all three.
  • Revocation is only real if you check it — CRL for offline, OCSP for live proof, stapling for speed at scale.
  • Salt passwords per user; identical hashes across accounts are an incident, not a curiosity.
  • Escrow the keys whose loss is unrecoverable; destroy the keys whose life is over.
  • Short keys and legacy hashes (MD5, 1024-bit RSA) are tomorrow’s incident filed under “works fine”.

Red-team mindset takeaways

  • Sniffers feast on non-encrypted links (INC-002) — unencrypted traffic on a span port is a free win, like T1040.
  • A departed admin with unescrowed, unrevoked access is a standing backdoor; credentials and certs outlive employment.
  • Expired certificates still serving traffic (INC-004) mean trust was assumed, not verified.
  • Unsalted password dumps crack in one precompute pass.
