The night Meridian Press went on air

Meridian Press runs a publishing floor and a TV studio in one building. The office LAN (VLAN 10 · 10.10.10.0/24) holds workstations, a laptop, a printer and a domain server. The studio LAN (VLAN 20 · 10.20.30.0/24) holds two cameras and a recorder. A router — R1 — is the only door between them and to the internet. Out in the world, a content-delivery network advertises one service address, 198.51.100.7, from three cities at once.

Everything that moves inside this building is one of four traffic types: a message for one recipient (unicast), a shout for everyone on the floor (broadcast), a program for subscribed viewers only (multicast), or a call routed to the nearest of many identical desks (anycast). As the dispatcher on duty, you will address real messages, watch exactly who receives them, read the capture binder, watch the meters, and set the switchboard — until you can classify, detect and control all four types cold.

Certification relevance. N10-009 exam objective 1.4 — “Explain common networking ports, protocols, services, and traffic types” — lists traffic types as a tested bullet: unicast, multicast, anycast, broadcast. This lab covers that bullet end-to-end (official course Lesson 1.5). Expect 1–3 exam questions on this area.

Unicast & anycast — “one recipient”

Unicast is the default: the sender names one IP, the frame carries that NIC’s MAC, and the network delivers one copy. When a router forwards it between VLANs, it is still unicast — only the TTL changes.

Anycast borrows unicast. The same address is advertised from several sites (usually via BGP); routing delivers each packet to the topologically nearest instance — the lowest routing metric wins, not the lowest latency necessarily. There is no new address range and no new protocol: anycast is a deployment model. Consequences worth knowing: if the nearest twin dies, the next-nearest answers (transparent failover); but a stateful TCP session can break mid-flight when routing starts delivering to a different twin. That is why anycast suits connectionless services like DNS and CDN delivery. DNS root servers and public resolvers are the textbook deployments, and spreading load across twins helps absorb DoS traffic.

Broadcast — “everyone, now”

A broadcast frame is delivered to every node in the broadcast domain — the L3 area bounded by routers. Switches flood it inside the VLAN; the router refuses to forward it further. Two address flavors:

  • Limited 255.255.255.255 / MAC FF:FF:FF:FF:FF:FF — never leaves the local segment. ARP requests and DHCP Discover live here.
  • Directed — the all-ones host address of a remote subnet (e.g. 10.20.30.255). Routers can forward it, and once did; since RFC 2644 they refuse by default because it is a weapon for amplification attacks (smurf). Legitimate exceptions exist — Wake-on-LAN — and must be granted narrowly.

Each VLAN is one broadcast domain; a flat network of hundreds of hosts drowns in broadcast overhead, and a Layer-2 loop can turn broadcasts into a broadcast storm. Don’t confuse domain types: a switch port is its own collision domain, while the whole VLAN shares one broadcast domain.

Multicast — “subscribers only”

The sender sends one stream; only hosts that joined the group receive copies. IPv4 reserves Class D 224.0.0.0/4 for groups — never assign it to a host. Two special blocks: 224.0.0.0/24 is link-local control traffic routers never forward (OSPF 224.0.0.5/6, RIPv2 .9, EIGRP .10, VRRP .18, IGMP .22, mDNS .251), and 239.0.0.0/8 is organization-local scope (RFC 2365) — your private multicast space. SSDP discovery rides 239.255.255.250.

Membership is signalled by IGMP (v1 join-only, v2 adds leave, v3 adds source filtering) simplified. But a switch has no idea about IGMP unless you enable IGMP snooping — and snooping only learns members if something sends IGMP queries (a querier). Without it, switches flood multicast exactly like broadcast: every IPTV viewer’s traffic lands on every desk. Crossing subnets needs multicast routing (PIM) concept-level. The Ethernet mapping 01:00:5E + the low 23 bits of the IP means 32 group IPs can share one MAC — NICs filter the leftovers in software simplified.

IPv6 deleted broadcast
Exam favourite: IPv6 has no broadcast at all. Its jobs were handed to multicast:
  • ff02::1 — all nodes on the link (the “everyone” shout).
  • ff02::2 — all routers on the link.
  • Solicited-node multicast ff02::1:ffXX:XXXX (MAC 33:33:ff…) — Neighbor Discovery (NDP) asks “who has this address?” to a tiny per-target group instead of ARP’s whole-floor broadcast; only the owner answers.

Context you may see in the same objective: traffic flows — north-south (client↔datacenter, in/out of the DC) vs east-west (server↔server, inside it). Not one of the four types, but it appears alongside them in N10-009.

Who uses what — real protocols you will recognize: ARP request → broadcast · DHCP Discover → broadcast · OSPF hello → multicast 224.0.0.5 · IPTV channel → multicast 239.x · HTTPS page load → unicast · DNS query to a public resolver → unicast packet delivered by an anycast service. On the wire, anycast looks like unicast — that distinction is a beloved exam trap.

    Mitigation recommendations

    • Bound the shout: segment flat networks into VLANs/subnets — each VLAN is one broadcast domain; routers are its wall. (Residual: more subnets to manage.)
    • Tame the stream: IGMP snooping on every access switch plus a querier; without queries, snooping learns nothing and multicast floods like broadcast. (Residual: silent misconfiguration.)
    • Refuse the relay: keep directed-broadcast forwarding off (RFC 2644 default); grant only narrow exceptions like Wake-on-LAN. (Residual: exceptions must be scoped and audited.)
    • Cap the storm: storm control on access/uplink ports to rate-limit broadcast surges from loops. (Residual: can drop legitimate traffic if tuned badly.)
    • Watch the twins: monitor anycast node health and failover; know which twin served which user. (Residual: TCP sessions can still break on route shifts.)
    Blue-team takeaways
    • Classify frames by destination addressing, never by protocol habit: a DNS query to an anycast resolver is a unicast packet.
    • Baseline every VLAN’s broadcast rate; storms and sweeps are visible long before users complain.
    • Audit snooping+querier as a pair — each without the other is a silent flood.
    • Treat any directed broadcast crossing a router as an incident signal, not noise.
    Operator’s view (know the other side)
    • An ARP sweep is the cheapest host-discovery scan on a flat net — oversized broadcast domains advertise their own inventory.
    • Directed broadcast once powered smurf-style amplification; RFC 2644 closed the default door. Old kits and exceptions reopen it.
    • Multicast streams are efficient and leaky: unencrypted IPTV/marketing feeds reach every joined member — membership is not confidentiality.
    • Anycast is resilience infrastructure: attackers target it with volume; defenders use it to spread that volume.
