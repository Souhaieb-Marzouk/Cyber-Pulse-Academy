NimbusCare Regional Health runs its patient-booking portal in a cloud VPC on two internal subnets. Over the weekend, change ticket CHG-2481 migrated the stack: a new load balancer went live, the legacy on-premises NTP server was retired, and a fleet of new VMs was scheduled to autoscale in Sunday night.

Monday 08:52 the alert feed erupts: the portal won't load by name but opens by IP, a dozen new VMs are stuck booting with 169.254.x.x addresses, and the BATCH-01 analytics node throws Kerberos and TLS certificate errors. The storage team is already shouting about an object-store latency alarm.

Your job: work the ward like a clinician — triage → diagnose with the right tool → treat → recheck vitals → prevent readmission — across the three foundational services this lesson covers: DNS, DHCP and NTP. That is exactly the Cloud+ CV0-004 Troubleshooting domain skill: “resolving disruptions in services like DNS, DHCP, and NTP.”

Mitigation recommendations

  • DNS hygiene: correct records + TTL ≤ 300 s inside change windows; peer-reviewed zone changes with rollback; split-horizon audits so private-zone records match reality. As network controls this maps to MITRE M1037 Filter Network Traffic and M1031 Network Intrusion Prevention on the DNS path.
  • DHCP hardening: capacity planning (secondary ranges before autoscaling events), option-003/006 reviews, DHCP snooping + split scopes against rogue servers (M1030 Network Segmentation, M1031).
  • Time integrity: ≥ 3 independent sources (internal pool + provider time service), offset as a monitored SLO, resync procedures in every runbook that touches auth.
  • Process: every one of today's three outages traces to change CHG-2481 — change management with post-change verification is the cheapest mitigation in the room.

Blue-team takeaways

  • Name the service before touching a fix: the symptom (“can't connect”) is shared by all three disruptions; the evidence (name vs address vs clock) is not.
  • Verify at every layer the service feeds: resolution → address → gateway → time → auth. “Fixed” means re-measured green, not “command ran”.
  • Alert on leading indicators (utilization, offset, record drift), not on user pain.
  • Log timestamps are only correlatable while time integrity holds — guard NTP like a detection control.

Red-team mindset (defensive awareness)

  • The same services you just repaired are attacker terrain: T1071.004 — DNS as C2 tunnels commands in lookups (SUNBURST, BONDUPDATER, FIN7), which is why DNS answers belong in detection.
  • A rogue DHCP server is not only an outage — it is position: T1557.003 — DHCP Spoofing feeds victims an attacker gateway (Adversary-in-the-Middle; see also Sea Turtle's DNS-redirect tradecraft under T1557).
  • Trusted time is forensic ground truth: T1070.006 — Timestomp (APT29, Lazarus Group) forges file times to blend in — but it can't forge a well-monitored clock's view of the world.
