T1110.004 Brute Force: Credential Stuffing

T1110.004Credential AccessVery hardTechnique

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

Credential stuffing is an attack that replays username and password pairs stolen from one website against a different website. It works because many people reuse the same password everywhere. Each attempt uses a real password, just not for this service. Lockouts rarely fire, because each account is usually tried only once.

Why should you care?

Breaches at other companies become your problem, because your users hold accounts elsewhere too. An attacker does not need to break your defences, only to find one reused password. A single success can open a mailbox, a file store or an administrative console. This traffic also comes from many different addresses and looks like real logins, so it is genuinely hard to spot without looking at patterns.

How it works, in plain steps

  1. An attacker obtains a large list of usernames and passwords from a breach at some other company.
  2. Automated tools try those pairs against your login page, thousands of times per hour.
  3. Most attempts simply fail, but the reuse rate means that some logins succeed.
  4. Bot traffic is spread across many addresses, so blocking one address changes nothing.
  5. The attacker checks what each working account can reach, then acts quickly before anyone resets a password.

Real-world example

Imagine a master key that fits one brand of padlock. Thieves steal a box of those keys from a shop, then walk a street trying each key on every door of that brand. The key was never made for these houses, but it opens them anyway because the owner bought the same lock. Credential stuffing works like this. The password was stolen somewhere else, yet it still opens your door.

Key takeaways

  • People reuse passwords, so a breach elsewhere can unlock an account here.
  • Multi-factor authentication breaks stuffing, because a stolen password is not enough on its own.
  • Ten logins from ten countries in one minute is not normal user behaviour.

In more detail

Credential stuffing is an automated credential access technique in which the adversary replays username and password pairs obtained from a breach of one service against authentication endpoints of other services, exploiting the fact that people reuse passwords across systems. Because each attempt uses a valid credential for some unrelated site, failure rates are low enough that modest volumes of traffic produce a meaningful number of successful logins, and per-account lockout counters are rarely triggered since each account typically sees one attempt. Attacks are usually executed from distributed residential proxy networks or botnets so that source reputation and address-based throttling do not stop the campaign. Artefacts appear in authentication and web telemetry. Identity provider or application logs show a large number of logins from many distinct addresses that share a narrow fingerprint: identical client or user agent strings, identical header ordering, uniform inter-request timing, and no preceding session or page views. The ratio of successful to failed logins is often unusually high compared with normal user behaviour, and the first action after a successful login frequently differs from that account's historical pattern, such as immediately creating access tokens, changing registered authentication methods, or reading mailbox rules. Account recovery and password reset events may cluster afterwards if the legitimate user is displaced. Benign lookalikes include shared network address translation egress, corporate proxy pools, and users travelling. What separates stuffing is the breadth of accounts touched, the uniformity of the client fingerprint, the absence of normal session establishment, and the correlation of the username set with a known third-party breach. Detection therefore depends on joining authentication outcomes with network-level fingerprinting rather than on any single log source.

What you will practise

  • Explain how password reuse and third-party breach data make stuffing viable, and why per-account lockout does not stop it.
  • Identify the client fingerprint characteristics that distinguish automated replay from genuine interactive login.
  • Correlate successful authentications with post-login behaviour to determine whether an account was actually taken over.
  • Analyse source address distribution and proxy patterns to differentiate stuffing infrastructure from corporate egress.
  • Prioritise accounts for forced reset and session revocation based on observed post-authentication activity.
  • Map credential stuffing to ATT&CK and describe the controls that reduce impact when passwords are already compromised.
