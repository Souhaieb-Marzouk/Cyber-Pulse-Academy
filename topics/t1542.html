T1542 Pre-OS Boot

T1542PersistenceExtremeTechnique

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

This technique is hiding malicious code in the parts of a computer that start it up. These parts run before the operating system loads. The word boot means the first moments when a machine switches on.

Why should you care?

Code below the operating system runs before your security tools do. Reinstalling the operating system may not remove it. It can survive a disk replacement on other components. This makes an infection very hard to detect and very slow to remove.

How it works, in plain steps

  1. When you press the power button, firmware checks the hardware. Firmware is the built in software stored on the mainboard.
  2. The firmware picks a boot device and runs a small program. That program then starts the operating system.
  3. An attacker with the right access writes their own code into one of those early steps, not into normal files.
  4. The machine starts, the hidden code runs first and can hide itself before the operating system loads.
  5. Because the code sits below the operating system, antivirus tools inside it usually see nothing unusual.
  6. Repair often means updating or rebuilding that component, or replacing the hardware, not just reinstalling.

Real-world example

Think of a hotel that rewrites the printed instructions in the lobby for every new guest. New staff are trained from those instructions, so they follow the false steps without knowing. Cleaning the rooms changes nothing, because the lie is printed in the lobby, not written on the walls.

Key takeaways

  • Malicious code below the operating system survives reinstallation, so plan for rebuild or replacement.
  • Record known good firmware versions and settings, because you can only spot a change if you know the original.
  • Log and review firmware update activity, since that is often the moment the change happens.

In more detail

Pre-OS Boot is persistence and defence evasion placed below the operating system, in the code that runs before it starts. Every machine follows a start up path in which firmware initialises the hardware, selects a boot device, loads a small bootstrap program, and only then hands control to the operating system loader. An attacker who can write at any point along that path gains execution that continues across reinstalls of the operating system and is invisible to defences running inside it, because those defences are not yet loaded when the malicious code runs. The parent technique groups several distinct targets: system firmware such as BIOS or UEFI, firmware on other hardware components, bootkit modification of boot records or the UEFI system partition, replacement of network device boot images, and network boot images loaded from a file transfer server. Each leaves different evidence, and firmware and boot records can be compared against known good measurements, hashes or vendor versions, while firmware update attempts themselves are logged and can be monitored. The behaviour to watch is a write to a region the operating system should never modify during normal use, and the practical response is to treat such a host as untrustworthy and rebuild it rather than clean it.

What you will practise

  • Outline the start up path from firmware to operating system and name the stages an attacker can modify.
  • Explain why code running before the operating system is difficult for host based defences to detect.
  • Explain why reinstalling an operating system may not remove a pre boot implant.
  • Describe the evidence sources, such as firmware version records and boot measurements, that reveal tampering.
  • List the sub-techniques under this parent and the different component each one targets.
