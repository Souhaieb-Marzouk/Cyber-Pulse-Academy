T1673 Virtual Machine Discovery

T1673DiscoveryExtremeTechnique

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

This is when an attacker looks around at the virtual machines on a host. Virtual machines are computers that run inside a bigger physical computer. Once the attacker reaches the software that manages those machines, they can list all of them. They then know which ones are running and which are worth attacking.

Why should you care?

The list of virtual machines is a map of everything the host runs, including file servers, databases and backups. Attackers use that map to choose the targets that hurt most. They often go straight for virtual disks, because that affects many systems at once. Virtualisation hosts are also rarely watched as closely as ordinary servers, so a quiet listing can pass unnoticed. Spotting this enumeration early can give you a warning before any damage happens.

How it works, in plain steps

  1. The attacker first obtains access to the hypervisor or to the tool that manages it, such as a management console.
  2. They run a built-in command that lists running processes or all registered virtual machines on the host.
  3. The command returns names, identifiers, power state and the resources each machine uses.
  4. They may instead open a graphical management interface or call the platform's interfaces to pull the same list automatically.
  5. They compare the list with what they already know to pick the most valuable or easiest targets.
  6. They then move on to damaging actions, such as stopping services or encrypting virtual disks.

Real-world example

Picture a night manager in a hotel who is not supposed to be there. Before doing anything else, she reads the room list at the front desk. It tells her which rooms are occupied, which guests are VIPs, and which rooms are empty and easy to enter. She does not touch anything yet. The list alone decides where she goes next, and reading a list at a desk looks like ordinary work.

Key takeaways

  • An inventory of virtual machines is a target list, so treat it as a warning sign.
  • Hypervisor and management console logs record who listed what and from where.
  • The same commands are legitimate, so judge them by source, account and timing.

In more detail

Virtual machine discovery is enumeration performed at the virtualisation layer rather than inside a guest. An actor who reaches a hypervisor or its management plane lists the guests the host runs, using the hypervisor command line, the management interface, or provider APIs. Native tooling is common and unremarkable in itself: listing running processes and all registered guests through the hypervisor shell returns names, identifiers, power state and resource allocation, and a graphical management console such as vCenter shows the same inventory to anyone who can authenticate. The value to the actor is target selection. The inventory reveals which guests are powered on, which are valuable, and which might be easier to reach, feeding follow-on behaviour such as stopping services, deleting or encrypting virtual disks, or encrypting a datastore wholesale. Telemetry lives in hypervisor and management plane logs: shell history on the host, task and event records in vCenter, authentication events on management interfaces, and API calls against the virtualisation endpoints. Legitimate administrators run the same commands, so the differentiator is context: unusual source addresses, sessions from outside the administrative jump path, off-hours execution, or enumeration performed by an account or API key not tied to a person. The listing is often a short, quiet step immediately before destructive activity, so it is worth alerting on as a precursor.

What you will practise

  • Explain what a hypervisor manages and why it holds a complete inventory of guests.
  • Describe how command line and graphical interfaces both expose the virtual machine list.
  • Explain how the inventory informs follow-on targeting and destructive actions.
  • Identify the hypervisor and management plane logs that record enumeration.
  • Explain how to separate legitimate administrative listing from suspicious discovery.
