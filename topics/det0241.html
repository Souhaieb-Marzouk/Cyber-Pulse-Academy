DET0241 Detect Forged Kerberos Silver Tickets (T1558.002)

DET0241Detection StrategyVery hardDetection Strategy

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

This detection looks for fake service tickets in the Kerberos login system. A service ticket is a short lived pass. One computer gives it to another so a user can use a service. A fake ticket is made with a stolen service key, not by the central login server. The rule looks for tickets that were never requested in the normal way.

Why should you care?

A fake service ticket lets an attacker reach one service as if they were a real user. The central login server never sees the request, so the usual alarm does not ring. It is a common step after an attacker steals a service account key. Because the pass looks valid to the target service, only careful log review finds it.

How it works, in plain steps

  1. A user or service asks the domain controller for a ticket to reach another service.
  2. The domain controller records that request, including the account and the service name.
  3. The rule groups these records by account, source host and service name over a short window.
  4. It compares the list of services to those that really run on the target host.
  5. It also checks the encryption type and whether a matching ticket granting ticket request exists.
  6. Accounts that touch many services from one host, or services that do not exist, raise an alert.

Real-world example

Think of a concert hall where each room has its own stamp on your hand. A real stamp comes from the front desk, which writes your name in a book. Someone who stole the room stamp can mark their own hand and walk straight in. The door staff see a valid stamp, but the front desk book has no matching entry for that visit.

Key takeaways

  • A forged service ticket avoids the domain controller, so normal ticket request logs look quiet.
  • Look for one account using many services from one host, or services that are not installed there.
  • Volume alone is weak, so compare against a baseline of normal service use per account.

In more detail

This strategy detects forged Kerberos service tickets, often called silver tickets, which are service tickets built locally with a stolen service account key instead of being issued by the domain controller. The technique matters because a forged service ticket needs no authentication to the domain controller, leaves no ticket granting ticket request, and can grant access to a service host while looking like a normal single sign on event. Detection depends on Kerberos service ticket request records, logon records that show reuse of one account across many services, and comparison against the set of services that actually run on a host. The main way it fails is noise: healthy environments request service tickets constantly, so the rule only works once encryption types, source hosts and service names are baselined per account.

What you will practise

  • Describe the difference between a service ticket and a ticket granting ticket.
  • Explain why a forged service ticket produces no ticket granting ticket request record.
  • Identify the Kerberos service ticket request fields that name the account, service and source host.
  • Correlate service ticket requests with the services that should exist on a target host.
  • Recognise encryption type downgrades as a signal of locally created tickets.
  • Build a per account baseline of normal service access to reduce false alerts.
