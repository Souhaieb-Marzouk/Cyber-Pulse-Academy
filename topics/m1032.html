M1032 Multi-factor Authentication

M1032Enterprise MitigationVery hardMitigation

Multi-factor authentication is the requirement that a login present at least two independent evidence types, so that possession of a password alone is insufficient to establish a session. In real environments it appears in several forms with very different security properties: hardware-backed phishing-resistant factors using FIDO2 or platform credentials, push notifications through an authenticator application, time-based one-time codes, and legacy telephony methods such as SMS or voice callbacks. It is deployed for interactive user sign-in, for privileged and administrative access through a bastion or privileged access workstation, for remote access gateways including VPN and virtual desktop entry points, and increasingly for machine identities where certificate or workload identity stands in for a second factor. The control directly breaks password spraying, credential stuffing, and the reuse of harvested credentials, and it removes the immediate value of most credential phishing because the stolen password cannot complete a session. It also meaningfully constrains lateral movement that depends on reusing captured password hashes or plaintext credentials, since the second factor is not present in memory. The honest limitations are where most breaches still occur. Push-based and code-based factors are vulnerable to real-time relay, where an attacker proxies the authentication prompt to the victim and the victim approves it. Legacy protocols that cannot present a second factor become a bypass path unless they are disabled or brokered. Service accounts, scheduled tasks, and API clients typically cannot perform interactive multi-factor authentication and are excluded, creating a large credential-only attack surface. Failure modes include enrolling users but never enforcing, allowing remembered sessions for months, leaving a break-glass account with a static password, and treating the presence of any second factor as equivalent to a phishing-resistant one.

What you will practise

  • Explain the difference between phishing-resistant hardware-backed factors and relayable factors, and the risk each carries.
  • Describe how to roll out multi-factor authentication for interactive sign-in, remote access, and privileged administration in phases.
  • Identify the legacy authentication paths and non-interactive accounts that bypass multi-factor enforcement and describe how to close them.
  • Explain how real-time prompt relay and adversary-in-the-middle proxying defeat push and code factors in practice.
  • Describe how conditional access, device state, and session lifetime policy combine with multi-factor authentication.
  • Evaluate an authentication estate and rank the residual risks that multi-factor authentication does not remove.
