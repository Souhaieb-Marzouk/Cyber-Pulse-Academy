DET0368 Hardware Supply Chain Compromise Detection via Host Status & Boot Integrity Checks

DET0368Detection StrategyVery hardDetection Strategy

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

A hardware supply chain attack means a device was changed before you received it or before it booted. This detection compares what a computer reports about its own boot process and hardware against a record of what it should look like. It catches unexpected firmware, boot settings and device changes.

Why should you care?

Code that runs before the operating system can hide from normal security tools. Standard endpoint agents start later, so they may never see it. This makes the boot measurement record one of the few trustworthy sources you have. Reviewing it also helps you notice a device that was tampered with in transit.

How it works, in plain steps

  1. Collect the boot measurement values that the Trusted Platform Module records during start up.
  2. Compare those values with a stored baseline for the same hardware model and firmware version.
  3. Collect Secure Boot state changes, including edits to the allowed signature database.
  4. Collect firmware update events and device inventory changes from the management controller.
  5. Alert when measurements do not match the baseline, or when Secure Boot is turned off, or when an unknown device appears.
  6. Attach the asset record so the analyst can see when the machine was received and who last serviced it.

Real-world example

Think of a hospital sign in sheet at the theatre door. Every person who enters writes their name and staff number. If the sheet later shows a name that no manager recognises, you check the door camera. The boot measurements are that sheet for your computer.

Key takeaways

  • Firmware and boot code sit below your endpoint agents, so you need measurements, not scans.
  • A baseline of known good values is the whole detection; without one you can only report changes.
  • Secure Boot being switched off is a strong signal on its own and deserves a look.

In more detail

This strategy covers the host-visible portion of a hardware supply chain compromise, where tampered firmware, an added expansion card, or a modified boot loader is present before the operating system trusts anything on disk. Detection relies on measurements and attestation rather than on file scanning: Trusted Platform Module Platform Configuration Register values compared with a known good baseline, Secure Boot state and signature database changes, firmware update events from the management controller, and inventory deltas in the hardware inventory table. The technique is hard to detect because the implant sits below the operating system and can hide itself from ordinary agents. Practical failure modes are an unmeasured fleet, no stored baseline, and inventory data that is refreshed only during long maintenance cycles.

What you will practise

  • Describe how a hardware supply chain compromise differs from a software supply chain attack.
  • Explain what a boot measurement is and why it can be trusted more than an agent report.
  • Collect and store a baseline of boot measurements for each hardware model you own.
  • Investigate an unexpected Secure Boot configuration change on a server.
  • Assess which parts of your fleet produce no integrity telemetry at all.
