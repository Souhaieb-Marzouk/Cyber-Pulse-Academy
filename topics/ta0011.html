TA0011 Command and Control

TA0011EnterpriseExtremeTactic

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

Command and control, often shortened to C2, is how an attacker talks to the computers they have taken over. The infected machine calls home to ask for instructions and to send back results. The attacker hides this conversation inside ordinary-looking traffic, such as web requests or domain name lookups.

Why should you care?

Without a channel home, an attacker's access is nearly useless. They cannot give orders or receive stolen data. That makes this stage a good place to break the chain. It is also a gift for defenders, because regular callbacks look mechanical. They repeat on a timer, with similar sizes. A program contacting the same unknown address every sixty seconds is not a person browsing.

How it works, in plain steps

  1. Malicious code runs on a victim machine and needs orders from its owner.
  2. It contacts an address the attacker controls, often a website or a rented server.
  3. Because the machine starts the conversation, your firewall, a guard that checks network traffic, usually allows it out.
  4. The traffic is disguised, perhaps as normal web browsing or as harmless name lookups.
  5. It repeats on a schedule, which is exactly what makes it stand out once you look.

Real-world example

Think of a spy inside a building. The spy cannot shout across the street, so they leave a chalk mark on a wall at the same time each evening. A passer-by sees nothing unusual. The handler walks past, reads the mark and leaves new instructions. The system works because it is regular and boring. Security teams catch spies by noticing the same small mark appearing every evening at the same spot.

Key takeaways

  • C2 is the link between an attacker and the machines they control.
  • Regular, repetitive outbound traffic is a classic warning sign worth checking.
  • Know which destinations your network should normally talk to each day.

In more detail

Command and Control is the tactic that describes how an adversary maintains communication with compromised systems, tasking them and receiving results through channels that must remain usable while looking as ordinary as possible. Behaviours include beaconing over web protocols to attacker-controlled or compromised sites, tunnelling through DNS, using application layer protocols such as mail or messaging services, abusing legitimate remote monitoring and management tooling and cloud services as relays, and encrypting or encoding traffic to defeat content inspection. From a defender's perspective, this is one of the richest tactics for network and endpoint analytics because sustained communication has structural properties: regularity of timing, consistency of payload size, long-lived sessions to destinations that are new to the environment, and repeated resolution of domains that no user or service should need. Endpoint evidence complements it through process-to-network correlation, showing which binary opened the connection, and through anomalous child processes that inherit a network session. Detection is difficult in isolation because beaconing to a content delivery network resembles software updates, because DNS tunnelling looks like ordinary recursive queries until volume and entropy are considered, and because adversaries deliberately use the same services and protocols as the business. Practical detection combines flow analytics, DNS and proxy logs, TLS metadata such as certificate and JA3-style fingerprints, and endpoint context, plus the discipline to build a baseline of expected egress before hunting for what should not be there.

What you will practise

  • Describe the main command and control channels and how each appears in network, DNS, proxy, TLS, and endpoint telemetry.
  • Analyse beaconing behaviour using interval regularity, jitter, payload size consistency, and destination history rather than content inspection alone.
  • Detect DNS tunnelling and covert channels by examining query volume, subdomain entropy, and response characteristics.
  • Correlate endpoint process data with network sessions to attribute an outbound connection to the process that opened it.
  • Baseline expected egress so that new destinations, unusual protocols, and long-lived sessions stand out.
  • Explain how egress filtering, protocol allow-listing, and TLS inspection trade off against operational cost and privacy.
