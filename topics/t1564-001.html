T1564.001 Hide Artifacts: Hidden Files and Directories

T1564.001StealthExtremeTechnique

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

This sub-technique is about making files and folders invisible in normal listings. On Linux and macOS a name that starts with a dot is hidden by default. On Windows a file can be marked with a hidden setting. The file still exists and still works exactly as before. It is the file part of the wider artifact hiding technique.

Why should you care?

When you open a folder and see nothing odd, you tend to trust it. An attacker counts on that habit. Hiding needs no special software, only an ordinary system command or a dot at the start of a name. Many real programs also use hidden files for settings, so hidden items are not automatically suspicious. You need to check for hidden entries on purpose and compare them with what belongs there. Otherwise your search stops at the point the attacker chose.

How it works, in plain steps

  1. The attacker writes their file or folder to a location on the target system.
  2. On Linux and macOS they begin the name with a dot, which hides it by default.
  3. On macOS they may also set a special flag that keeps it out of the file browser.
  4. On Windows they use the attributes command or program code to set the hidden flag.
  5. The item stays on the disk and keeps working, but normal listings skip over it.
  6. Defenders must list hidden entries and compare them with a trusted baseline.

Real-world example

Think of a shop that publishes a price list on the wall for customers. A staff member adds one extra line to the list in pale ink that matches the paper. Customers never notice that line. The offer is real when a colleague reads it, and the item is still sold at the till. Nothing was removed from the shop, only from the part of the list that people actually read.

Key takeaways

  • A dot at the start of a name or a hidden attribute hides presentation, not the file.
  • Hidden items are common in real systems, so context and baselines matter.
  • A newly hidden executable outside configuration folders deserves urgent attention.

In more detail

Hidden files and directories is the file system half of artifact hiding, and it exploits conventions that every major operating system uses to keep the user's workspace tidy. On Linux and macOS a leading period in a name marks the item as hidden from ordinary directory listings and from the graphical file browser, so a directory such as a dotted configuration folder is invisible unless the user explicitly asks to see it. macOS adds an additional per file hidden flag that keeps an item out of Finder while leaving it visible to terminal commands, which means two tools on the same machine can disagree about whether a file exists. On Windows the hidden attribute is applied through the attributes utility or programmatically, and directories and files behave the same way once marked, while an item named with only a space is an especially awkward case for tooling that trims names. The critical property for defenders is that hiding changes presentation, not existence. Nothing is encrypted, nothing is moved off the host, and normal file system operations still apply. File creation and modification telemetry, disk level inventory, integrity baselines over known trusted directories, and backups that copy hidden items all still record the artifact. Detection is therefore an enumeration and comparison problem: the answer comes from querying the file system in a way that includes hidden entries and comparing that against what should be there. Because configuration directories and dotted files are everywhere in real environments, the useful signal is a new or modified hidden item in a location where hidden items do not normally appear, and especially a hidden executable.
