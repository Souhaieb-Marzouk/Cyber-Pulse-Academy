DET0258 Linux Python Startup Hook Persistence via .pth and Customize Files (T1546.018)

DET0258Detection StrategyVery hardDetection Strategy

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

Python is a programming language used by many tools and servers. It can be told to run extra code every time it starts. A startup hook is a file that holds that extra code. Attackers like hooks because the code runs again after every reboot. This detection watches the folders where Python keeps those special files.

Why should you care?

Servers often run Python tools that nobody reinstalls or reviews. A startup hook hides inside those folders and looks like part of the program. There is no new service and no new scheduled job, so the usual persistence checks find nothing. The code runs with the same rights as the tool that starts it, which is often a service account. Watching these folders gives you one of the few chances to catch it.

How it works, in plain steps

  1. A file monitor watches the interpreter library folders, such as the site packages and distribution packages directories, for new files.
  2. The rule selects files with a path configuration extension and the known startup module names.
  3. It compares the new file with the software package list that should own that folder.
  4. A file that no installed package claims is treated as suspicious and given a score.
  5. The alert includes the writing process, so an analyst can see what created the hook.

Real-world example

Think of a staff notice board in an office kitchen. Anyone who pins a note there reaches every employee who walks past. A person who wants to influence the whole office does not need to meet anyone. They only need to pin one note. A Python startup hook is that notice board. The interpreter reads it on every launch, and the note is easy to overlook.

Key takeaways

  • Startup hooks run automatically without any service or scheduled task.
  • The folder that holds them is often left out of system file monitoring.
  • Comparing each new file against the installed package list is the key check.

In more detail

This detection strategy covers Python startup hook persistence, tracked as T1546.018, where an adversary places code that the interpreter loads automatically at startup. Two mechanisms matter most: the path configuration file, which can execute any line that begins with import, and the customization module that Python imports on every launch. Neither needs a service, a scheduled task, or a registry autorun entry, so common persistence checks miss both. The telemetry is file creation and modification inside the interpreter library directories, plus environment variable writes. It fails when hosts lack file monitoring on those paths, which is the usual case because administrators treat them as application files rather than operating system files.

What you will practise

  • Name the Python startup mechanisms that execute code when the interpreter launches
  • Configure file monitoring for interpreter library directories on servers
  • Distinguish package owned files from unclaimed files in those directories
  • Correlate a hook file with the process that created it
  • Explain why environment variable changes such as the startup module setting also matter
