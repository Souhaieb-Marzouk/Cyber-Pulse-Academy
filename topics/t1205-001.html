T1205.001 Traffic Signaling: Port Knocking

T1205.001PersistenceExtremeTechnique

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

Port knocking is a secret knock made of network connections. The attacker tries to connect to several closed ports in a set order. When the system sees the right order, it opens the real door. Until then, everything looks shut.

Why should you care?

A scanner will report that no interesting port is open, so the machine looks clean. The door only appears for someone who knows the order. This makes hidden remote access hard to find with normal checks. Without traffic records you may never know the knock happened.

How it works, in plain steps

  1. The attacker knows an agreed list of ports and the order in which to touch them.
  2. They send a connection attempt to each port in turn, and these attempts normally fail.
  3. Software on the target watches the traffic, often using a packet capture library.
  4. When the whole sequence matches, the program takes it as a valid signal.
  5. It then opens the real service port, or starts listening and answering commands.
  6. After the session ends the port is closed again, so the next scan finds nothing.

Real-world example

Think of a post office with a counter that is closed after hours. Staff agreed that three knocks on the shutter, a pause, then one on the glass means a colleague needs the back door. Anyone watching sees only someone knocking on a closed counter. The knocking is the key, and the counter stays shut for everyone else.

Key takeaways

  • One source touching several closed ports in a short, repeated order is a strong clue.
  • Look at what happens right after the sequence, such as a port opening for a moment.
  • Vulnerability scanning looks similar, so confirm the source and the repetition pattern.

In more detail

Port knocking is the best known form of traffic signaling: the trigger is a predefined order of connection attempts to ports that are closed and therefore look unremarkable in a scan. The parent technique covers any magic value or packet characteristic; this sub-technique narrows it to the sequence of destination ports, optionally with a source, timing or protocol condition attached. Once the full sequence is seen, either a host firewall rule is changed to admit the real connection, or custom code begins listening or calls home, so the service exists only for the client that knocked correctly. The same sequence can also be used in the other direction, as a signal sent out to a listening server so that a beacon appears to be ordinary failed connections. Detection is statistical and behavioural rather than signature based: several connections to different closed ports from one source inside a short window, a repeated identical sequence from the same address across days, a port that starts accepting connections seconds after such a sequence, and firewall or packet filter logs that show the rule change or the first successful connection to a port with no listening service before it. Normal vulnerability scanning can look similar, so source identity, repetition and what happens immediately afterwards are what separate the two.

What you will practise

  • Explain how port knocking differs from other forms of traffic signaling in the parent technique.
  • Describe how a matched sequence causes a firewall rule change or a custom listener to start.
  • Explain why port knocking is invisible to a simple port scan.
  • Identify the sequence of failed connections and the brief port opening as detection evidence.
  • Distinguish malicious knocking patterns from routine vulnerability scanning activity.
