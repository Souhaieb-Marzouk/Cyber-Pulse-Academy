Impossible Travel Sign-In

Detection StrategyVery hardDetection Strategy

Impossible travel sign-in detection identifies authentication events for the same account from two geographically distant locations within a time window that makes physical travel between them infeasible, which is a long standing indicator that credentials are being used by more than one party. The behaviour matters because it applies after the credential theft has already happened and does not depend on the attacker using tools on an endpoint: a valid account used from an unexpected place will authenticate successfully, satisfy most policy checks, and appear in logs as a normal user unless the spatial and temporal relationship between consecutive sign-ins is evaluated. The telemetry required is identity provider or directory sign-in logs containing the account, timestamp, source address, resolved location, client application, authentication method and outcome, plus an address geolocation source with accuracy metadata and a device or session identifier where the platform provides one so that concurrent sessions can be distinguished from sequential ones. The signal survives common evasion because credentialed access from a remote network must traverse the internet and will be geolocated to that network's registered location; virtual private network and proxy use changes the apparent origin but does not remove the discrepancy when the legitimate user is simultaneously active, and the discrepancy often becomes larger, not smaller, when commercial hosting ranges are used. The detection breaks down in practice for well documented reasons: mobile carrier routing, corporate virtual private network egress points that concentrate users in one datacentre, satellite links, and inaccurate geolocation databases all produce apparent travel that never happened. Authentication through a shared egress also means many accounts can appear to move simultaneously, which is a strong signal that the location source, not the user, moved. Ineffective handling of these cases causes rapid alert fatigue, so mature implementations combine distance and time thresholds with a check for whether the same address serves many accounts, treat virtual private network and known egress ranges as neutral rather than anomalous, and require a second signal such as an unfamiliar device, a failed multi-factor challenge, or a suspicious post-authentication action before escalating to an incident.

What you will practise

  • Compute travel velocity between consecutive sign-ins and choose thresholds that reflect realistic commercial travel.
  • Identify systemic geolocation artefacts such as corporate egress concentrators and carrier routing that cause mass false positives.
  • Interpret simultaneous or overlapping sessions for one account as stronger evidence than sequential location change.
  • Combine travel anomalies with device familiarity, authentication method and post-authentication activity to set severity.
  • Describe the containment and verification steps for a confirmed stolen credential, including session revocation and token invalidation.
  • Assess the effect of virtual private network, proxy and hosting network usage on the reliability of geolocation indicators.
