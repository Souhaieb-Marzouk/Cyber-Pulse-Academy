DET0396 Detect Access to macOS Keychain for Credential Theft

DET0396Detection StrategyVery hardDetection Strategy

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

This detection looks for programs on a Mac that read or copy saved passwords from the keychain. The keychain is the encrypted password store that comes with macOS. The alert means a program accessed protected secrets, especially a program that does not normally do so.

Why should you care?

People save many passwords in the keychain, including mail, file shares and work applications. If an attacker reads it, they gain those accounts without guessing anything. On a Mac that is already unlocked, the attacker may not even need a password. Normal user activity also reads the keychain, so the challenge is telling friendly programs from hostile ones. This detection gives you the evidence to make that call.

How it works, in plain steps

  1. The Mac records keychain access in the unified log and through the Endpoint Security framework.
  2. Your log collection agent forwards those records to the security monitoring platform and adds the host name and user.
  3. The rule selects accesses to keychain database files and to the security command line tool used with keychain options.
  4. It checks which program performed the access, using its file path and signing identifier.
  5. Programs that are not signed by your approved developers, or that run from temporary folders, are marked suspicious.
  6. The alert lists the program, the account, the host and the time so you can decide quickly.

Real-world example

Think of a hospital sign-in sheet for the medicine cabinet. Nurses open the cabinet all day, so the sheet is busy and boring. The sheet becomes useful when someone who never works on that ward opens the cabinet at three in the morning. The keychain log works the same way, and the unusual visitor is the story.

Key takeaways

  • The keychain holds many credentials, so reading it is a high value step for an attacker.
  • You must know which programs normally read the keychain before this rule becomes useful.
  • An unsigned or temporary folder program reading keychain data is a strong warning sign.

In more detail

This detection strategy covers credential access against the macOS keychain, the encrypted store that holds saved passwords, tokens, certificates and secure notes, matching the technique for credentials from password stores on macOS. The technique matters because a single unlocked keychain gives an intruder plaintext secrets for mail, browsers, shares and developer services without any further exploitation. Useful telemetry includes Endpoint Security framework file and process events, the unified log securityd keychain access messages, and process creation records for the built in security utility when it is used with keychain arguments. The main failure mode is volume: many signed applications read keychain items during normal startup, so a rule that alerts on every keychain access produces so many alerts that analysts stop reading them.

What you will practise

  • Describe what the macOS keychain stores and why it is a high value target.
  • Name the log sources that record keychain access on macOS.
  • Distinguish routine signed application access from suspicious keychain reads.
  • Use file path and signing identifier to judge whether a keychain reader is trustworthy.
  • Explain how keychain dumps by command line utilities appear in telemetry.
