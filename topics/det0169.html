DET0169 Detection Strategy for Cloud Infrastructure Discovery

DET0169Detection StrategyVery hardDetection Strategy

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

Cloud infrastructure discovery is when someone lists the resources inside a cloud account to learn what is there. This detection watches for a sudden wide sweep of read-only listing calls. It catches the reconnaissance that usually comes before an attacker steals data or changes systems.

Why should you care?

Cloud accounts hold a lot of systems, and one stolen key can list all of them in minutes. A single discovery sweep can map every server, bucket and network rule you own. If you only watch for changes, you miss the quiet step before them. Catching the sweep early gives you time to disable the key and warn your team.

How it works, in plain steps

  1. Your cloud provider records every application programming interface call in an audit log. An application programming interface, or API, is the way software asks the cloud to do something.
  2. Each log entry names the account or role that made the call, the service, the action name, the time and the source address.
  3. The detection counts listing actions, such as Describe or List calls, per identity over a short window.
  4. It compares that count with what the same identity normally does, and flags a result far above the baseline.
  5. The alert shows which identities swept many services, so an analyst can review the activity and decide if it was allowed.
  6. If the sweep comes from a new address or an unusual user agent, the alert is raised in priority.

Real-world example

Think of a warehouse night watchman. A worker walking to one shelf is normal. Someone walking down every aisle, writing on a clipboard what each shelf holds, is worth a radio call. The watchman does not stop the walk. He reports it, because the person may be planning a theft.

Key takeaways

  • Discovery is quiet reconnaissance, so it is easy to miss without API audit logs.
  • The useful signal is a wide sweep of listing calls by one identity in a short time.
  • You must baseline your own automation first, or the alert will drown you.

In more detail

This strategy detects cloud infrastructure discovery, the reconnaissance step in which an adversary enumerates the compute, storage, network and identity objects inside a cloud account before acting on them. In AWS this appears as bursts of read-only control plane calls such as DescribeInstances, ListBuckets or DescribeSecurityGroups, and in Azure as repeated resource listing operations. The telemetry that makes it visible is the cloud provider audit log, which records who called which API, from which address, with which user agent. The main way it fails in practice is volume: infrastructure-as-code runners, inventory scanners, backup agents and cost tools make the same calls legitimately, so the rule only becomes useful once those principals and call patterns are baselined and filtered.

What you will practise

  • Explain why cloud reconnaissance is worth detecting before any destructive action occurs
  • Identify the audit log fields that tie an API call to an identity, a source address and a user agent
  • Describe how a per-identity baseline of normal listing activity is built and maintained
  • Distinguish benign inventory or deployment automation from an unusual breadth of listing calls
  • Tune scope, thresholds and filters so the rule stays useful without losing coverage
