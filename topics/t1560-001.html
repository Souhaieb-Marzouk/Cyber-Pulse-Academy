T1560.001 Archive Collected Data: Archive via Utility

T1560.001CollectionExtremeTechnique

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

This is the version of data packing that uses an existing archiving program. The attacker uses a tool already installed on the computer, such as tar or zip. They point that tool at the files they want to take. No new hacking software is needed, only a normal utility used for a bad purpose. It differs from the parent technique because a utility does the work. The malware itself does not contain the packing code.

Why should you care?

These utilities are installed on almost every company computer and server already. Their presence proves nothing, so you cannot block them without breaking real work. That makes this a favourite method for attackers who want to stay quiet. The one advantage for defenders is that running a utility usually creates a record with its arguments. Collect the process creation events and read the arguments inside them. You can then tell a routine backup from an archive built in a temporary folder at midnight.

How it works, in plain steps

  1. The attacker already has files or records gathered on the machine that they want.
  2. They call a built in utility such as tar, zip, makecab, or xcopy to package them.
  3. Command options choose the compression level, the output name, and sometimes a password.
  4. Some tools encrypt the result or turn it into encoded text that looks like harmless data.
  5. The finished file is left in a temporary or ordinary folder ready for transfer.
  6. Defenders read the recorded command arguments and check where the output file appeared.

Real-world example

Imagine a removal company that loads everything into tape sealed boxes. The tape is sold in every shop for packing books and clothes, so nobody finds it odd. What gives the crew away is the timing and the place. They sealed forty boxes in an empty office at two in the morning. They used a loading bay that is normally shut. The tape was ordinary, but the pattern was not.

Key takeaways

  • Preinstalled tools such as tar and zip are normal, so their use alone proves nothing.
  • Process creation records keep the command arguments, which show what was packaged.
  • The location of the archive and the transfer that follows are the strongest clues.

In more detail

This sub-technique narrows archive collection to the use of preinstalled or third party archiving programs rather than libraries or custom code. The adversary runs a tool such as tar on Linux and macOS, zip, makecab or diantz on Windows, or xcopy to gather and copy files with selected options, and may also use certutil to Base64 encode content before it leaves the host. The security value for the adversary is that these binaries already exist on most systems and are signed by the vendor, so nothing new has to be dropped and the noisy creation of a novel archiving executable is avoided. The cost is a rich forensic trail compared with other archiving approaches, because invoking a utility usually creates a process with a recorded command line. Process creation telemetry, which on Windows includes Security event 4688 and Sysmon event 1, exposes the tool name alongside its arguments and the user context that ran it, and that combination is a far stronger signal than the presence of the executable alone. Detection depends on behaviour: archives written into temporary or user profile paths, archive commands executed by server processes or service accounts that never touch archives, and a burst of compression activity immediately followed by a large outbound transfer. Backup, software deployment, and support staff produce the same tools and often the same arguments, so the distinguishing features are the named source files, the destination, the account, and the timing.

What you will practise

  • Name common built in archiving utilities on Windows, Linux, and macOS.
  • Explain why using a preinstalled signed utility can help an attacker avoid detection.
  • Explain how process creation telemetry such as Windows Security 4688 or Sysmon 1 reveals archiving commands.
  • Interpret archive command arguments to decide what data was packaged and where it went.
  • Tell a legitimate backup or support archive apart from a suspicious one using context.
  • Describe how Base64 encoding of collected data fits into this sub-technique.
