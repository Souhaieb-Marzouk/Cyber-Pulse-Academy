T1095 Non-Application Layer Protocol

T1095Command and ControlExtremeTechnique

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

This technique means an attacker hides their control traffic inside simple network protocols instead of normal web traffic. A protocol is an agreed set of rules that computers follow when they talk. Every network message uses one, and some of them are rarely checked by security teams.

Why should you care?

Most monitoring watches web and email traffic, so a channel that avoids them can pass unseen. Some of these protocols must be allowed for the network to work at all, so you cannot simply block them. Attackers also use them to reach virtual machines on a single physical server without any traffic leaving that machine.

How it works, in plain steps

  1. The attacker picks a protocol that is allowed through firewalls, such as ping or raw UDP.
  2. The implant puts its stolen data inside the payload of that protocol's messages.
  3. It sends the messages to a server the attacker controls, on a normal-looking schedule.
  4. The server replies in the same protocol, carrying new instructions for the implant.
  5. On a physical server, guest machines may reach the host over a shared channel instead of the network.
  6. That channel never touches a router or switch, so standard capture tools cannot see it.

Real-world example

Imagine a factory where workers shout one word across the floor to say a machine is fine. Nobody reads those shouts closely, because they happen all day and mean nothing. Two workers agree that three shouts in a row now mean something secret. The words never change and look completely normal, yet a real message travels through them.

Key takeaways

  • Watch protocol behaviour, not just protocol names: size, timing and repetition give it away.
  • Ping traffic that is large, frequent or sent between odd hosts is worth investigating.
  • Virtualisation channels between guests and the host bypass normal network monitoring.

In more detail

Non-application layer protocol command and control carries attacker traffic inside protocols that sit below the application layer of the OSI model, that is, beneath HTTP, DNS and similar services. Documented examples include network layer options such as ICMP echo requests, transport layer options such as raw UDP or TCP handled directly by a socket, session layer mechanisms such as SOCKS, and tunnelled or redirected protocols such as serial over LAN. Because ICMP support is mandatory on IP hosts and is often less scrutinised than web traffic, an implant can encode tasking inside echo request and reply payloads and appear as ordinary ping activity. In virtualised environments the virtual machine communication interface lets a guest talk to the hypervisor host over a channel that never leaves the physical server, so it is invisible to external network monitoring and to local capture tools. Detection relies on protocol behaviour rather than content: payload sizes that are large, constant or patterned, echo traffic between hosts that never normally ping each other, unusual volumes at odd hours, and socket or hypervisor events that do not correspond to any expected service.

What you will practise

  • Explain what a non-application layer protocol is and why it can hide command and control traffic.
  • Describe several behaviours bundled in this technique, including ICMP tunnelling and virtualisation channels.
  • Recognise the traffic patterns that distinguish tunnelled traffic from normal protocol use.
  • Identify the log and capture sources, including flow records and hypervisor auditing, that support detection.
  • Explain why these protocols cannot simply be blocked everywhere.
