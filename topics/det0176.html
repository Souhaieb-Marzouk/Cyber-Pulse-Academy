DET0176 Drive-by Compromise — Behavior-based, Multi-platform Detection Strategy (T1189)

DET0176Detection StrategyVery hardDetection Strategy

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

A drive-by compromise means a person visits a normal looking website and gets infected without clicking anything. The website or its adverts were tampered with. This detection looks for the strange behaviours that follow in the browser on the user's computer.

Why should you care?

The user did nothing wrong, so training and warnings do not help. Trusted sites are used, so web blocking lists are not enough. It can affect many staff in a short time if the site is popular at your company. Catching the browser behaviour fast limits how many computers are harmed.

How it works, in plain steps

  1. The browser writes records of pages it visits, and the network records the addresses it connects to.
  2. The operating system writes an event when any program starts, including which program started it.
  3. The detection looks for a browser or an office program starting a script host, such as a PowerShell or Windows Script Host process.
  4. It also looks for a new executable written into a download or temporary folder and started soon after.
  5. The network records are checked for a chain of redirects that ends at a host with a poor reputation, or that serves a file instead of a page.
  6. When the process chain and the network chain agree on the same time and the same computer, the alert is raised for review.

Real-world example

Think of a food market where one stall's sign is swapped overnight. Shoppers follow the sign in good faith and buy from the wrong stall. The shoppers did nothing careless. Only comparing the sign with the market's official map shows the swap.

Key takeaways

  • Drive-by compromise needs no user mistake, so you cannot train it away.
  • Look at what the browser started, not only at which site it visited.
  • Correlate the redirect chain with the process chain on the same host and time.

In more detail

This strategy detects drive-by compromise, where an adversary compromises a website or its advertising content so that merely visiting the page causes a browser or browser plugin to run attacker code. The technique is hard to catch at the moment of delivery because the malicious content is served by a site the user trusts, so detection leans on the client side chain: browser or office application spawning an unexpected child process, script interpreters launched by a browser, new executables written to user download or temporary directories followed by execution, and proxy or secure web gateway records of a redirect chain that ends at an exploit kit pattern. The common failure is that modern browsers generate many legitimate child processes and script hosts, so precision depends on correlating the parent chain, the file path and the outbound connection destination rather than any single event.

What you will practise

  • Explain how a trusted website or advert can deliver exploitation without user interaction
  • Identify browser and office parent child process patterns that indicate script execution
  • Correlate proxy redirect chains with local file creation and process execution on the same host
  • Use reputation and content type signals to separate exploit delivery from normal browsing
  • Prioritise containment actions that stop further infection from the same delivery host
