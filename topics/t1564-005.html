T1564.005 Hide Artifacts: Hidden File System

T1564.005StealthExtremeTechnique

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

Your computer stores files in a structure called a file system. A hidden file system is a second, private structure that the operating system does not show you. The attacker keeps their own files inside it. Because it is never opened as a normal volume, folders and searches do not reveal what it holds.

Why should you care?

If security tools cannot see the storage, they cannot scan it. Malicious files can sit on a disk for months without appearing in any folder. Backups and software inventories will miss them too. A hidden file system can survive cleanup work that only removes visible files. Finding one usually needs a deeper look at the raw disk.

How it works, in plain steps

  1. The attacker creates a storage area that the normal operating system does not recognise as a volume.
  2. One method hides a small file system inside disk space that no partition currently uses.
  3. Another method drops a whole partition image as one large file among normal files.
  4. A third method spreads file pieces across the disk in an order the system does not expect.
  5. A custom driver or loader inside the malware reads that storage directly from the disk.
  6. Because the volume is never mounted, normal searches and scanners see empty space.

Real-world example

Imagine a large warehouse full of labelled shelves. An inventory team walks the aisles and writes down what it finds. One worker builds a small sealed room in a corner and stores boxes inside it. The room has no door on the aisle, so the team walks past it every day. The boxes are real and they take up space, but no list mentions them. A hidden file system is that sealed room. Only someone who measures the whole building and notices the missing floor space will ask what is there.

Key takeaways

  • Data can live on a disk without ever appearing in a folder.
  • Raw disk checks and volume analysis find storage that file listings miss.
  • Legitimate disk images exist, so confirm the source before you raise an alert.

In more detail

Hidden File System describes an adversary maintaining a private storage structure that the operating system never mounts or presents. Payloads and working data live inside it, so directory listings, indexing services and file-based scanners never see the contents. Implementations range from a small volume embedded in unused disk space, to a portable partition image dropped as an ordinary file, to content fragments scattered across the disk in ways the resident file system does not describe. Detection leans on raw disk access, drivers or processes that read below the file system layer, and unusually structured image files, which then have to be separated from legitimate backup, forensic and virtualisation images.

What you will practise

  • Explain what a file system is and what it means for one to be hidden.
  • Describe the main ways an attacker can build storage outside normal volumes.
  • Identify telemetry that shows raw disk or below-file-system access.
  • Distinguish a malicious hidden volume from a legitimate disk image.
  • Outline a response step for a host that may contain a hidden volume.
