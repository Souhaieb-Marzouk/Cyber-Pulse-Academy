DET0486 Detecting Odbcconf Proxy Execution of Malicious DLLs

DET0486Detection StrategyVery hardDetection Strategy

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

This plan looks at a Windows tool called odbcconf, which sets up database drivers. The tool can also load a library file when it is told to. Attackers use it because the program is signed and trusted. The detection watches for the tool loading a library from an unusual place.

Why should you care?

Security tools often allow signed Microsoft programs to run. An attacker who abuses that trust can load code without a new file that looks obviously bad. The library can sit in a folder the user can write to. Mixing a trusted program with an untrusted library is the warning sign. Catching it stops a quiet way of running code.

How it works, in plain steps

  1. The endpoint agent records the start of each process with the full command line that launched it.
  2. The rule selects the ODBC configuration utility and checks its arguments, such as a register or response file option.
  3. A second event source records which libraries the new process loads, with the path and signature of each.
  4. The detection keeps only cases where the library path is outside the system folders.
  5. It also notes a short lived process, because the utility often exits as soon as the library is loaded.
  6. The combination of the utility, a suspicious argument and an unusual library path raises the alert.

Real-world example

Think of a courier van that is allowed through the factory gate without a search. A driver uses that trust to carry a parcel out of the loading bay. The gate guard only checks the van, not the parcel inside. In the same way, the ODBC utility is accepted because it is signed. The library it carries is the real problem.

Key takeaways

  • A signed system utility can still be used to load unwanted code.
  • The command line arguments are what make the utility interesting.
  • Pair the process event with a library load to cut false alerts.

In more detail

The Open Database Connectivity (ODBC) configuration utility, odbcconf.exe, is a signed Microsoft binary that can be told to register a dynamic link library, which makes it a convenient way to load code while the process image on disk looks trusted. The detection strategy pairs process creation telemetry that captures the command line with module load events for the process, because the arguments alone are noisy while the arguments plus a library loaded from a user writable folder are a strong signal. Coverage fails when command line auditing is off, since the utility name by itself appears in legitimate driver and application deployments on almost every managed endpoint.

What you will practise

  • Explain what the ODBC configuration utility does in normal administration.
  • Identify the arguments that cause it to load a library.
  • Correlate its process creation with a library load from a user writable path.
  • Recognise legitimate driver deployment behaviour that produces the same events.
  • Explain how missing command line auditing reduces detection quality.
