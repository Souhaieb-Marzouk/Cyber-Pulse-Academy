DET0026 Windows Detection Strategy for T1547.012 - Print Processor DLL Persistence

DET0026Detection StrategyVery hardDetection Strategy

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

The print spooler is the Windows part that manages printing. It can load extra files called print processors to handle different print jobs. This detection looks for a new print processor, or one that points to a strange file. It catches a file that starts every time the computer prints or boots.

Why should you care?

The spooler starts early and runs with high rights, so anything it loads runs with those rights. This gives an attacker a way to stay on a machine across restarts. It looks like normal printing setup, which few teams review closely. A strange file loaded by a trusted service is easy to miss. Catching it removes a durable foothold.

How it works, in plain steps

  1. The sensor writes an event whenever a program changes a registry key, including the old and new values.
  2. The rule watches the registry keys that list print processors and print monitors.
  3. It checks the value added: a normal entry is a signed vendor file in a system or driver directory.
  4. It then collects module load events where the print spooler process loaded the file named in the registry.
  5. Both events are joined by host and file path. A registry entry that is never loaded is only a lead.
  6. The alert lists the registry change, the loading process and the file path with its signature state.

Real-world example

Think of a hotel that keeps a list of approved luggage handlers at the front desk. Someone adds a new name to the list. The front desk then lets that person walk into your room without a question. The list looks official. Print processor detection is the record of who added that name and whether the person ever showed up.

Key takeaways

  • Persistence here hides behind a normal printing feature. So check that registry key on a schedule.
  • The registry change alone is a lead; the spooler loading the file confirms it.
  • Legitimate print processors are signed and live in standard driver directories.

In more detail

This strategy detects print processor persistence, mapped to ATT&CK technique T1547.012, where an adversary registers a malicious dynamic link library as a print processor so that the Windows print spooler loads it automatically at start up and every time a print job is processed. The change is a registry write under the print processor key, followed by the spooler service loading the registered module from a path that is not the system directory. Detection therefore needs registry modification telemetry for the print processor and print monitor keys, module load events attributed to the spooler process, and service start or restart events that explain when the load occurred. The strongest correlation is a new registry value naming a library outside the system directories and a later image load of that exact library by the spooler, especially where the library is unsigned. The strategy fails in practice because printer driver installation legitimately adds print processors, so the rule must distinguish signed vendor packages in standard directories from a library sitting in a temporary or user writable folder.

What you will practise

  • Explain how the print spooler can be made to load attacker supplied code at start up
  • Identify the registry keys that register print processors and print monitors
  • Read module load events to attribute a library load to the print spooler process
  • Judge a registered library by path, signature and publisher rather than by name
  • Separate printer driver installation from a malicious print processor registration
