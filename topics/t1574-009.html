T1574.009 Hijack Execution Flow: Path Interception by Unquoted Path

T1574.009ExecutionExtremeTechnique

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

An unquoted service path is a small mistake in how a program path is written down. Windows sees a path with spaces but no quotation marks around it. So Windows tries several possible folders before it finds the program. An attacker can put their own program in one of those earlier folders.

Why should you care?

Many services run with high rights, such as the SYSTEM account. If your program starts from the wrong folder, the attacker program inherits those high rights. This can give an attacker full control of the machine. It can also survive reboots, because the service starts again every time. The mistake is invisible until someone looks closely at the path.

How it works, in plain steps

  1. A service or shortcut stores a path that has spaces and no quotation marks around it.
  2. Windows cannot tell where the folder name ends and the program name begins.
  3. So Windows tries each possible program name built from the start of the path.
  4. An attacker writes a file with the same name into an earlier folder in that list.
  5. Windows runs the attacker file first and never reaches the real program.
  6. Because a service starts the file, it runs with the service account rights every time.

Real-world example

Think of a courier with a handwritten address that reads Flat 3 Riverside Court. The handwriting has no commas, so the courier reads it as three possible stops. A stranger waits at the first stop, takes the parcel, and signs for it. The real resident at Flat 3 never learns the parcel arrived. The handwritten address is the unquoted path, and the stranger at the first stop is the attacker file that Windows chooses first.

Key takeaways

  • Always wrap service and shortcut paths that contain spaces in quotation marks.
  • Check file permissions on every folder that sits above a service program.
  • Watch process creation logs for service programs starting from unusual folders.

In more detail

This sub-technique abuses ambiguity in how Windows resolves an executable path that contains spaces but is not enclosed in quotation marks. Because the stored path is unquoted, the CreateProcess routine tries each space-delimited prefix in turn, so a binary named program.exe placed in an earlier directory wins over the intended target deeper in the tree. The vulnerable reference is usually a service ImagePath value in the registry or a shortcut target, and exploitation requires only write access to one of the parent directories. Where the original executable is launched on a schedule, at boot, or by a privileged context, the same weakness yields persistence and privilege escalation. Detection rests on process creation telemetry: audit Windows Security 4688 events or Sysmon 1 and look for service-hosted parent processes whose child image path sits in a directory that is not the intended installation directory. Comparing ImagePath strings without quotes against the actual loaded binary, monitoring writes to top-level directories, and enabling registry auditing on the Services tree separate this from legitimate installers that briefly run from staging folders.
