T1550.002 Use Alternate Authentication Material: Pass the Hash

T1550.002Lateral MovementExtremeTechnique

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

Windows stores your password as a scrambled value called a hash. The system can check that hash without knowing the real password. This sub-technique is when an attacker steals the hash and logs in as you. They never need to know or guess your password.

Why should you care?

Attackers can move from one computer to many others with a single stolen hash. You cannot fix it by changing your password alone, and the login looks valid to the target machine. Cracking the hash is not even necessary, which makes the attack fast and cheap.

How it works, in plain steps

  1. Windows keeps a scrambled value of your password, called a hash, in protected memory.
  2. An attacker with administrator rights on a machine reads that memory and copies the hash.
  3. They send the hash to another computer instead of a typed password.
  4. The target computer checks the answer and accepts it, because the value is correct.
  5. The attacker now holds your rights on that machine and can reach more systems.
  6. A related trick turns the hash into a ticket so later logins look even more ordinary.

Real-world example

Think of a shared flat where the door has a keypad. Instead of remembering the code, you write the code on a card that the door reads. A thief who copies the card enters the flat any time. You can change the code all you like, but the copied card still opens the door. The door trusts the card rather than your memory.

Key takeaways

  • Hashes are reusable credentials, so keep them out of reach of attackers.
  • Limit administrator rights on workstations so hashes cannot be read locally.
  • Treat unusual successful network logons as an alert, not as routine traffic.

In more detail

This sub-technique is authentication replayed with a stolen NTLM password hash instead of the plaintext password. The Windows challenge and response logon path accepts a correctly computed response to a server challenge, and the hash is all the client needs to compute it, so an attacker holding a hash authenticates without cracking it. The hash is recovered through credential access activity such as memory dumping of the local security authority process or of the cached domain credential store, and it is then presented to remote services including administrative shares, remote procedure calls and remote desktop. Detection rests on network authentication logging: a successful network logon whose account and source workstation combination is unusual, or where the same account authenticates from addresses that do not fit its baseline. The behaviour is not malformed, so the discriminator is correlation and rarity rather than any single suspicious field. Overpass the hash is the related variant that converts the hash into a Kerberos ticket first.

What you will practise

  • Explain what a password hash is and why it is usable without cracking.
  • Describe how a hash is captured from a compromised Windows system.
  • Explain how overpass the hash turns a password hash into a Kerberos ticket.
  • Identify the logon events and network authentication records that reveal the reuse.
  • Describe controls that reduce the number of reusable hashes on a network.
