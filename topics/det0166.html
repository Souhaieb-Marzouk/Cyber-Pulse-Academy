DET0166 Detection Strategy for T1505.002 - Transport Agent Abuse (Windows/Linux)

DET0166Detection StrategyVery hardDetection Strategy

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

This detection watches the parts of a mail server that decide where email goes. An attacker can add a hidden rule or program that copies messages elsewhere. The mail keeps flowing normally, so nobody complains.

Why should you care?

A mail server already has permission to read and send mail, so an added rule inherits that trust. It can quietly copy every message to an outside address, which is a serious data loss. A hidden agent can also be used to send messages that look internal. Configuration changes are rare and reviewable, which makes detection practical.

How it works, in plain steps

  1. The mail server keeps its routing logic in configuration files and agent programs.
  2. A file monitoring tool records whenever those files or programs change.
  3. The mail log records each message, its sender, its recipients and the route taken.
  4. The detection links the configuration change to the messages that follow it.
  5. It looks for new recipients outside the organisation or unusual forwarding patterns.
  6. An analyst confirms whether a change ticket explains both the change and the flow.

Real-world example

Think of a company post room where staff sort all incoming letters. Someone adds a standing instruction that every letter from the finance desk is also photocopied to an outside address. The post room keeps working normally, and only the instruction sheet shows what changed.

Key takeaways

  • Monitor mail configuration and agent directories as security critical, not routine.
  • Link a configuration change to the message flows that appear afterwards.
  • Watch for outside recipients and forwarding patterns that the business does not expect.

In more detail

This strategy detects abuse of mail transport agents, the components that accept, route and deliver email, where an attacker adds or alters an agent or transport rule so that messages are copied, redirected or injected without the users or administrators noticing. The covered technique matters because the mail server is a trusted relay with access to internal and external conversations, so a hidden agent provides persistent collection and a quiet outbound channel that blends with ordinary mail. File integrity monitoring of mail configuration, mail server logs and process execution records make it possible, because a new agent or transport rule requires a file change and leaves a distinct process and message flow. The main failure mode is that administrators change mail configuration for legitimate reasons and mail servers are extremely chatty, so the rule must anchor on the modification plus the resulting anomalous flow rather than on message volume.

What you will practise

  • Describe what a mail transport agent does and why adding one is a persistence technique.
  • Identify the configuration paths and agent directories that must be integrity monitored.
  • Read mail log entries to reconstruct the route and recipients of a suspicious message.
  • Correlate a configuration change with new outside recipients or unexpected forwarding.
  • Explain how an added agent can both collect mail and provide an outbound channel.
