T1550.001 Use Alternate Authentication Material: Application Access Token

T1550.001Lateral MovementExtremeTechnique

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

When you let an app read your mail or files, the service gives that app a digital pass. The pass is called a token. The app shows the pass instead of your password. This sub-technique is when an attacker steals that pass and uses the app's access as if it were their own.

Why should you care?

The attacker never needs your password. They may never trigger a second factor prompt either. Access can last far longer than a password. This is especially true if the app may renew its pass in the background. Password changes do not help, because the pass is still valid.

How it works, in plain steps

  1. You approve an application, and the service issues it a token that grants specific access.
  2. The application stores the token in a file, a browser store, or service memory.
  3. An attacker who reaches that storage copies the token and takes it elsewhere.
  4. They send normal requests to the service and simply include the stolen token.
  5. The service sees a valid token and answers as if the real application asked.
  6. If a renewal token was also granted, the attacker can keep access after a password reset.

Real-world example

Imagine a members-only post office where you sign once and receive a paper pass for the month. Staff at the counter only glance at the pass, never at your face. If someone photographs your pass, they can collect your parcels every day. Changing your signature does not help, because the counter stopped checking signatures the moment you signed.

Key takeaways

  • A token is a bearer credential, so anyone holding it is treated as the real holder.
  • Review which applications hold consent, and remove ones nobody recognises.
  • Alert on tokens used from new addresses or by unexpected client applications.

In more detail

This sub-technique covers lateral movement and resource access performed with a stolen application access token rather than a password. Tokens are issued by authorisation frameworks such as OAuth after a consent step, and they authorise API calls on behalf of a user or service without the caller ever handling the underlying credential. Because the token is a bearer credential, possession is sufficient, so theft from a browser store, a mobile device, a build agent, a container environment variable or a configuration file converts directly into access. A refresh token or a token minting permission extends that access well past a password reset, and direct API use never triggers an interactive second factor, so the request pattern stays inside ordinary API traffic. Detection relies on identity provider and resource provider logs: token issuance and consent grants, the application identifier receiving the token, and the source address and user agent of the calls. Deviations such as a familiar user identifier paired with an unfamiliar application or address range are the practical discriminator.

What you will practise

  • Explain what an application access token is and how it replaces a password.
  • Describe how a token is stolen from a browser, a device or a configuration file.
  • Explain how a renewal token extends access beyond a password reset.
  • Identify the identity provider events that record token issue and consent grant.
  • Explain why API token use is difficult to distinguish from legitimate automation.
