DET0024 Detect Kerberos Ccache File Theft or Abuse (T1558.005)

DET0024Detection StrategyVery hardDetection Strategy

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

Kerberos is a login system that gives you a ticket instead of a password prompt each time. The ticket is stored in a file on disk, called a cache file. This detection watches those files for reading or copying by the wrong account. It catches someone stealing a ticket to act as another user.

Why should you care?

A ticket works like a temporary key to many services. If it is stolen, the thief can reach systems without knowing any password. The theft leaves a file access record instead of a login failure, so password alarms stay quiet. Tickets expire, so detecting the theft quickly is the only way to limit damage. It also helps you find which account was the real target.

How it works, in plain steps

  1. The sensor records file opens and reads, including which account performed the access and to which file.
  2. The rule filters for the file paths where Kerberos keeps its credential caches on Linux and macOS.
  3. It compares the owner of the cache file with the account doing the read, and flags mismatches.
  4. It also watches for tools that list, copy or dump tickets, which is an unusual action for a normal session.
  5. It then joins in authentication events to see whether a service ticket was requested for the stolen identity soon after.
  6. The alert shows the reading process, the owner of the file and the following authentication. The analyst can judge it.

Real-world example

Imagine a hotel cloakroom where each guest gets a numbered coat check tag. Someone photographs another guest's tag and then collects that coat. Nothing was broken and no password was guessed. Kerberos cache detection is the cloakroom log. It shows a tag being photographed by a person who does not own it.

Key takeaways

  • The cache file is as valuable as a password while the ticket lasts.
  • Compare the file owner with the account doing the read, and treat a mismatch as the signal.
  • Pair the read with the authentication that follows, because that proves use.

In more detail

This strategy detects theft or abuse of Kerberos credential cache files, mapped to ATT&CK technique T1558.005 Steal or Forge Kerberos Tickets: Ccache Files. On Linux and macOS hosts a user who authenticates with Kerberos receives a cache file holding a ticket granting ticket, and any process that can read that file can act as the user until the ticket expires. Attackers therefore read or copy cache files belonging to other accounts, most often root reading a service account cache or a compromised web application touching caches in a temporary directory. Detection combines file access and read telemetry for cache paths, process creation showing tools that list or export tickets, and the authentication events that follow when a stolen ticket is used from an unusual source address. The correlation that gives confidence is a read of a cache file by a process or account that does not own it, immediately followed by a service ticket request for that identity. The strategy fails in practice because root and management automation legitimately read caches, so ownership comparison and host role are essential.
