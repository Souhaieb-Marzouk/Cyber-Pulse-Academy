T1535 Unused/Unsupported Cloud Regions

T1535StealthExtremeTechnique

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

A cloud region is a group of data centres in one part of the world. Companies usually use only a few regions. This technique is an attacker building or running things in a region the company never watches.

Why should you care?

Most alarms are set up only for the regions you use. Activity elsewhere can run for months without anyone noticing. It may cost you a lot of money for machines you never ordered. It can also hide the systems an attacker uses to steal data.

How it works, in plain steps

  1. The attacker gets hold of an account that can create cloud resources. This is often a developer or administrator account.
  2. They check which regions the company uses. Any other region is a blind spot that no one monitors.
  3. They create servers, storage or network links in that quiet region, giving them a hidden base.
  4. Some regions lack certain security services, so the attacker may pick one where logging or scanning is weak.
  5. The new machines are then used for harmful work such as mining digital coins on your bill.
  6. The provider records every creation in an audit log. Those records exist, but only if you collect and review them.

Real-world example

Imagine a shop chain that owns a small warehouse in each city but only guards the one at head office. A thief rents space in a warehouse in a town the company forgot it owned, keeps stolen goods there for months, and the night guard at head office never walks past that door.

Key takeaways

  • Write down the cloud regions your business really uses, then alert on activity anywhere else.
  • Turn on provider audit logging for every region, not just your favourite ones.
  • Watch your cloud bill, because sudden cost in a strange region often means someone else is using it.

In more detail

Unused/Unsupported Cloud Regions is defence evasion through placement: the attacker creates or moves workload into a geographic region that the victim subscribes to but never operates in, so the activity falls outside the monitoring the organisation actually watches. Access normally comes from compromised credentials that can manage infrastructure, and the technique works because cloud providers offer many regions while most tenants use a small subset and centralise logging, alerting and security tooling on those. A related variation targets functional differences between regions, choosing one where an advanced detection or logging service is unavailable or not enabled. The technique is often an enabler rather than the payload, for example hosting compute that mines cryptocurrency, staging exfiltration endpoints, or running instances that a subscription never expected to pay for. Detection depends on governance rather than on the endpoint: provider audit logs and configuration snapshots that record resource creation in every region, cost and usage reports, service quota changes, and alerts on any activity outside an approved region list. Because the individual calls look like legitimate infrastructure work, the strongest signal is geography and identity, not the shape of the request.

What you will practise

  • Define a cloud region and explain why unused regions create monitoring blind spots.
  • Describe how an attacker with infrastructure credentials places resources outside an organisation's normal footprint.
  • Identify the cloud audit and billing records that reveal resource creation in an unexpected region.
  • Explain how regional differences in detection services can make one region more attractive to an attacker.
  • Describe a policy control that restricts resource creation to approved regions.
