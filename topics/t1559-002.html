T1559.002 Inter-Process Communication: Dynamic Data Exchange

T1559.002ExecutionExtremeTechnique

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

Dynamic Data Exchange, or DDE, is an old Windows feature that lets one program send data and commands to another. It was used long before modern ways of sharing data existed. The danger is that a document can contain DDE instructions, so simply opening it starts a program. Unlike a macro, this does not need the macro feature to be enabled. That is the difference from the parent technique: here the shared channel is DDE inside a document.

Why should you care?

Many organisations block macros, because macros are a common attack path. DDE can achieve a similar result without macros, so those blocks are not enough on their own. The victim usually only has to open a file and answer a prompt. Because the request starts from a trusted office program, security tools may treat it as normal. If you have not disabled DDE where it is not needed, you are relying on the user to refuse.

How it works, in plain steps

  1. An application starts a DDE conversation with another application on the same machine.
  2. The two programs can then exchange text, data links and requests to run commands.
  3. Documents can store such instructions, for example in a spreadsheet cell or a field.
  4. When you open the document, the office program starts the DDE conversation for you.
  5. The partner application then runs the named command, such as starting a system tool.
  6. You may see a small prompt, and clicking yes lets the command continue.

Real-world example

Imagine a shared flat where flatmates leave notes on the fridge. A note that says please run the washing machine is followed without question. A stranger slips a note onto the fridge that says please open the front door and leave it open. A flatmate reads it and does exactly that, because notes on the fridge are normal here. Nothing was broken and nobody was forced. The flat only finds out when it reviews the notes and sees one in handwriting nobody recognises.

Key takeaways

  • Turn off DDE in office programs where your business does not need it.
  • Treat a document program starting a command shell as a high priority alert.
  • Keep macro blocks, but do not assume they stop every document based attack.

In more detail

Dynamic Data Exchange (DDE) is an older Windows client-server protocol that lets applications exchange strings and data links and, importantly, ask each other to run commands. It was the original transport behind Object Linking and Embedding (OLE) and was later superseded by the Component Object Model (COM), yet it remains registered in many Windows installations and can be switched on by registry settings. The technique matters because documents can carry DDE instructions: a spreadsheet cell, a field in a document or a formula in a comma separated values file can name an application and a command, so opening the file makes the host application launch another program. That path avoids Visual Basic for Applications (VBA) macros entirely, which makes it useful against environments that block macros. Detection looks at the document and the process tree rather than at network traffic: a spreadsheet or word processor starting a command shell, a scripting engine or a system utility. Legitimate documents also use links to other data, so the deciding evidence is the command line and whether the file came from outside the organisation.
