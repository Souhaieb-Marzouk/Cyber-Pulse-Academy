T1665 Hide Infrastructure

T1665Command and ControlExtremeTechnique

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

Attackers need a place for their servers to live. Hiding infrastructure means making those servers hard to find, block, or trace back to the attacker. The aim is to keep the attack channel working for as long as possible.

Why should you care?

If defenders find and block an attacker's server, the attack stops working. Hiding that server makes the job much harder and buys the attacker time. It also makes the attacker's identity harder to prove. Some tricks even make the server look harmless to security tools while it still harms real users. That is why defenders cannot rely only on blocklists.

How it works, in plain steps

  1. The attacker sets up servers, often using rented cloud space or compromised hosting.
  2. They place a proxy or a virtual private network in front, so the real address stays hidden.
  3. They configure the server to answer only requests that match their chosen conditions.
  4. Security tools and researchers are sent harmless pages, or they are blocked entirely.
  5. Real victims receive the harmful content, sometimes after a redirect from a trusted site.
  6. They change domains and addresses often, so blocked entries quickly become useless.

Real-world example

Imagine a shop on a busy street with a friendly doorman at the entrance. Most visitors see ordinary shelves and nothing unusual. But the doorman recognises certain customers and quietly lets them through to a back room. If an inspector walks up, the doorman smiles and shows them the shop front. Nothing about the building looks wrong, and the police cannot close it because they cannot see any crime. Hiding infrastructure works like that doorman. The attacker's servers decide who sees the harmful content, while everyone else sees an empty shop.

Key takeaways

  • Attackers can show different content to victims and to security tools.
  • Blocklists go stale quickly, so watch the behaviour of the traffic itself.
  • Suspicious redirect chains and domains that serve almost nothing deserve a closer look.

In more detail

Hide infrastructure is the collection of tricks used to keep command and control systems alive and hard to attribute. Rather than hiding the channel once it is in use, the adversary hides the infrastructure itself, so that scanners, researchers, and defenders cannot easily find, block, or take it down. Common methods include placing the real server behind a proxy, a virtual private cloud, or residential exit nodes so the source address looks ordinary or matches the victim's region; filtering incoming requests by user agent, address, or geography so only intended victims receive harmful content; and using widely trusted hosting or URL shortening services to present benign pages that redirect later. Because the filtering is conditional, the same address can look harmless to a sandbox and harmful to a real target, which is exactly what frustrates automated analysis. Detection is therefore indirect: certificate and passive name resolution records for the underlying hosts, unusual redirect chains, request filtering that produces different responses, and long lived domains that serve almost no content to anyone else.
