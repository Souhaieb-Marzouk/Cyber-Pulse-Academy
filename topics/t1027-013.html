T1027.013 Obfuscated Files or Information: Encrypted/Encoded File

T1027.013StealthExtremeTechnique

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

Encrypted or encoded files are files whose content has been changed into a secret or unreadable form. Encryption uses a key, like a password, to lock the content. Encoding is a simpler change that hides the meaning without real protection, such as Base64. This is a sub-technique of Obfuscated Files or Information. Antivirus programs often look for known patterns, so hiding those patterns helps attackers pass by.

Why should you care?

A scanner cannot match a known bad pattern if the pattern is scrambled. The file looks empty or random until the moment it runs. This means an alert that depends on file content may never fire. You may also see an ordinary looking archive that asks for a password. Users often receive that password in the same message. You need to look at behaviour, not only at file contents.

How it works, in plain steps

  1. The attacker changes the file content using a standard method such as Base64 encoding.
  2. For stronger hiding they encrypt the content with a key that the malware carries or receives.
  3. They can apply both, sometimes in layers, and hide just the important parts of a file.
  4. The file travels to the victim, where it appears normal or unreadable to content scanners.
  5. When the file is opened, a small stub or script unlocks the content with the key.
  6. The clear content is then run in memory, so no readable copy stays on the disk.

Real-world example

Imagine posting a document in a locked suitcase. The airport scanner can only see a solid block, so it cannot tell paper from something dangerous. The suitcase passes because nothing inside matches any known shape. Only when the traveller reaches the hotel and unlocks it does the real content appear. The guard who checked the bag did their job properly. The bag was simply designed so that checking would reveal nothing.

Key takeaways

  • Unreadable file content should raise your interest rather than close an investigation.
  • A password protected or self extracting archive from outside your organisation deserves careful handling.
  • Watch what happens when the file opens, because decoding is usually followed by execution.

In more detail

Encrypting or encoding file content hides strings, byte patterns and configuration values so that signature and static analysis tools have nothing distinctive to match. The transformation may cover an entire file or only selected regions such as embedded command and control addresses, and it is frequently layered, for example a compressed archive that is also encrypted or a script whose sensitive strings are Base64 encoded. Because the protected content only becomes readable at the moment of use, defenders who rely on static inspection see noise while the real code is rebuilt in memory at execution time. Practical carriers include password protected office documents, encrypted archives with the password delivered in the message body, self extracting archives that unpack through an embedded stub, and custom or format specific schemes such as text files whose byte order marks steer how the content is read. Legitimate software also encodes and encrypts routinely, so the durable discrimination point is not the presence of encoding but what the decoded content turns out to be, whether decoding is followed immediately by execution, and whether a human or a program supplies the key.

What you will practise

  • Distinguish encryption from encoding and explain how each hides file content from static inspection.
  • Identify common carriers, including password protected documents, encrypted archives and self extracting archives.
  • Explain how this sub-technique differs from packing, steganography and embedded payloads.
  • Describe the artefacts and behaviours, such as decoding followed by in-memory execution, that support detection.
  • Explain why a decoded file still has to be examined before you can decide whether it is malicious.
