T1055 Process Injection

T1055Privilege EscalationExtremeTechnique

Process Injection covers techniques that place adversary code or data inside the address space of another running process so that execution appears to originate from a trusted binary. The parent technique spans several distinct mechanisms, including remote thread creation, memory allocation and writing followed by execution, section and file mapping abuse, asynchronous procedure calls, and manipulation of existing process or thread contexts, and its descendants differ mainly in which operating system interface they use to achieve the same result. Adversaries value injection because the code inherits the target process identity, token and reputation, can evade allow-listing that keys on the original image path, and can hide from tools that enumerate only top-level processes. The behaviour is most commonly described on Windows, but comparable approaches exist on Linux and macOS through debugging interfaces, dynamic loader features and memory mapping, and it appears in cloud and container workloads where a shared kernel makes cross-process visibility weaker. Telemetry is deliberately subtle: memory allocation and protection changes inside another process, thread creation in a process that should not create threads, cross-process handle acquisition, image loads from unusual paths, and instrumentation callbacks reported by endpoint agents. Because debuggers, crash reporters, backup agents, accessibility software, anti-cheat components and security products all legitimately manipulate other processes, an investigation hinges on establishing a benign parent, a signed and expected tool, and a plausible operational reason for the cross-process operation. When no such explanation exists, the combination of allocation, write, protection change and execution in one target process within a short window is far more meaningful than any single isolated event, and sequencing those events is what makes the detection defensible.

What you will practise

  • Describe the main injection mechanisms and the distinct API or system-call patterns each produces.
  • Interpret endpoint telemetry for cross-process memory allocation, protection changes and remote thread creation.
  • Explain which legitimate tools manipulate other processes and how to rule them out during triage.
  • Correlate injection indicators with subsequent credential access, network beaconing or defence impairment.
  • Assess how endpoint protection configuration affects both the visibility and the blocking of injection behaviour.
  • Write detection logic that sequences related events rather than alerting on isolated ones.
