DET0178 Behavioral Detection of Unauthorized VNC Remote Control Sessions

DET0178Detection StrategyVery hardDetection Strategy

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

Virtual Network Computing, or VNC, is software that lets one computer see and control another computer's screen. This detection looks for those sessions when they are not approved. It catches remote control that a helpdesk did not arrange.

Why should you care?

Once connected, an attacker can work on a machine with a normal looking desktop. Many tools of this kind are free and small, so staff can install them without help. The traffic often runs over a standard port, so it can pass simple filters. Finding an unexpected session early stops an attacker from using a real keyboard and mouse inside your network.

How it works, in plain steps

  1. These tools listen on well known service ports, and the network records show which host pairs exchanged traffic on them.
  2. The operating system records each program start, and the detection watches for the viewer and server programs.
  3. Installing the tool as a service creates a record, which shows that a listener was set up to start automatically.
  4. The detection links the network session to the process records on both hosts, using the same time window and addresses.
  5. It checks the direction. A workstation connecting out to an unknown address is more suspicious than a helpdesk jump host connecting in.
  6. It compares the account that signed in on the target with the list of people who are allowed to perform remote support.

Real-world example

Think of a hotel where cleaners have key cards for every room. That is expected. But a key card used at three in the morning, on a floor that cleaner never covers, is worth a call to the front desk. The card is legitimate. The pattern is not.

Key takeaways

  • Remote control tools are legitimate software, so you must judge the pattern, not the program.
  • Watch the service installation, the listener port and the session direction together.
  • Compare the acting account with the people approved for remote support.

In more detail

This strategy detects unauthorised remote control sessions over Virtual Network Computing, a remote desktop protocol that lets one host view and control another host's screen. It matters because the protocol is legitimate administration software, so signature and blocklist controls rarely stop it, and a session looks like ordinary remote support once established. Detection depends on network flow and firewall records for the well known service ports used by these tools, process creation of the viewer or server binaries, service installation records where the tool is deployed as a persistent listener, and authentication events on the target host in the same window. The main failure is that helpdesk and engineering teams use the same tools, so the rule must differentiate by direction, source asset, session duration, and whether the server component was newly installed rather than pre approved.

What you will practise

  • Explain how remote control software establishes a session and why signatures alone do not detect misuse
  • Identify network, process and service installation telemetry associated with remote control tools
  • Correlate a network session with the process and authentication evidence on the target host
  • Use direction, asset role and account context to separate approved support from intrusion
  • Document an approved remote support baseline that keeps the rule precise
