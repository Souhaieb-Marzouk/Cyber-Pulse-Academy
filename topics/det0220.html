DET0220 Detection of USB-Based Data Exfiltration

DET0220Detection StrategyVery hardDetection Strategy

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

This detection looks for files being copied onto a removable storage device, such as a USB stick. It uses two kinds of records together. One record shows that a device was connected. The other shows that files were written to it. Together they show a possible data theft.

Why should you care?

A USB stick can carry a large amount of data out of a building. It leaves no trace on the network at all. Network monitoring simply cannot see it. Without device and file records, this theft stays invisible. Those same records also help you prove what left and when.

How it works, in plain steps

  1. The operating system logs each new removable device, with its identity and the account that mounted it.
  2. File auditing logs each file that is written to a removable volume.
  3. The rule joins both kinds of record by the account and the time window.
  4. It counts how many files were copied and which folders they came from.
  5. It compares that pattern with the user's normal behaviour and with the sensitivity of those folders.
  6. A large copy from a sensitive folder to a newly connected device raises the alert.

Real-world example

Think of a warehouse where every pallet leaving the gate is weighed. One pallet of paper is ordinary. Ten pallets at midnight, from the secure aisle, is not. The weighing record is the evidence you need afterwards.

Key takeaways

  • Device connection records alone do not prove that a copy happened.
  • Join device events with file writes by account and by time.
  • The folder the files came from decides how serious the case is.

In more detail

This strategy covers T1052.001, Exfiltration over USB, where data leaves the network on removable media instead of over a network path that monitoring can see. Detection combines device connection telemetry, file level write or copy activity to removable volumes, and the sensitivity of the source directory, joined by the account and the time window. It fails most often on the data side: device arrival events are easy to collect, but proving that specific files were copied needs file auditing or a data loss prevention agent that many organisations never enable on user endpoints.

What you will practise

  • Explain what telemetry is needed to prove a file copy to removable media.
  • Describe how to join device connection events with file write events by account and time.
  • Identify which folders or data classes should raise severity when they are copied.
  • Explain why network monitoring alone cannot detect this technique.
  • Describe the privacy and legal limits that apply to monitoring removable media use.
