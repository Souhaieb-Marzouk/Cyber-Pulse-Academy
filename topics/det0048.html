DET0048 Detect Remote Email Collection via Abnormal Login and Programmatic Access

DET0048Detection StrategyVery hardDetection Strategy

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

This detection watches for mailbox access that does not come from a normal mail program. An attacker can sign in from anywhere and read mail through an automated tool. The result looks like a robot reading a mailbox. This rule looks at sign in records and mailbox audit records to spot that pattern.

Why should you care?

Remote collection leaves no trace on the computer, so endpoint alerts cannot help you. A stolen password plus an automated tool is enough to copy a whole mailbox. Mail holds reset links and contracts, so the damage spreads to other systems. The records exist, but they sit in the mail service rather than on the device.

How it works, in plain steps

  1. The mail service writes an audit record each time an item or folder is accessed.
  2. The identity service records each sign in, including the client program and the network location.
  3. The rule pairs those records, so an item read is tied to the session that performed it.
  4. It compares the client program and location against the recent history for that same account.
  5. New clients, impossible travel, or access outside working hours raise the risk score.
  6. A high score plus a burst of item reads raises the alert for the identity team.

Real-world example

Picture a library where members can request books by post. The librarian records every request and every pickup. Most members visit in person, and the log shows that habit. Now one member sends ten postal requests from another city in a single night. Each request alone is allowed, yet the pattern stands out. Remote email collection detection reads the same two records. The sign in is the postal request. The item read is the book leaving the shelf.

Key takeaways

  • Remote collection leaves no endpoint evidence, so mail service audit records are your only view.
  • Automated access is normal for integrations, so compare each session against that account history.
  • A new client identifier plus a new network location plus a burst of reads is a strong combination.

In more detail

This detection strategy covers T1114.002, Remote Email Collection, where an adversary authenticates to a mail service such as Microsoft 365 or Exchange and pulls mailbox content programmatically instead of using a normal client. It matters because the attacker never needs to touch the endpoint, so endpoint rules stay quiet while the mailbox empties. The telemetry that reveals it is identity and service side: unified audit log records for mailbox item access and mailbox permission changes, sign-in logs with client application, network location, and authentication method, and flow records showing non browser access to mail protocols. The main failure is the volume of legitimate mail clients and integrations that also use programmatic access, so the rule must compare against the user baseline and watch for new client identifiers or new network locations rather than any single event.

What you will practise

  • Explain how remote mailbox collection differs from local collection on a device.
  • Identify the audit, sign-in, and network telemetry available from a cloud mail service.
  • Describe the baseline fields that make automated mailbox access look unusual.
  • Write a pseudo rule that correlates a sign in record with mailbox item access.
  • Explain how mailbox permission changes support an attacker collecting other users mail.
  • Describe a triage path that confirms or clears a suspected remote collection quickly.
