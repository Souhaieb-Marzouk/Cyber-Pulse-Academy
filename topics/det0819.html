DET0819 Detection of Network Topology

DET0819Detection StrategyVery hardDetection Strategy

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

This detection looks for someone drawing a map of your internal network. The map shows which computers exist and how they connect. The rule watches for one host that contacts many internal addresses in a short time. It also watches for route table reads by unusual accounts.

Why should you care?

An attacker who has one stolen account wants more. A network map shows the next targets, such as servers and backup systems. Building the map makes almost no changes, so few alarms fire. Seeing the map being drawn tells you that an intruder is already inside.

How it works, in plain steps

  1. Routers and switches record log events when their routing tables or configuration are read.
  2. Firewalls and flow collectors record each internal connection attempt with the source, the destination and the port.
  3. Hosts record command lines when auditing is switched on, which captures map building tools and their options.
  4. The security monitoring platform joins these records by source host and by time.
  5. The rule counts how many distinct internal addresses one host contacted in a window, and how many subnets were covered.
  6. Hosts that sweep many subnets, or that run map commands outside change windows, raise the alert.

Real-world example

Think of a new cleaner in an office tower. On the first night the cleaner walks every floor and writes down which doors are locked. The cleaning itself takes ten minutes. The walk takes two hours. This detection notices the walk, not the cleaning.

Key takeaways

  • Topology discovery happens from a host that is already inside, so treat it as post compromise.
  • Count distinct internal addresses and subnets per source host in a window.
  • Change windows and network engineer workstations are the main source of false alarms.

In more detail

This detection strategy covers network topology discovery, the technique where an adversary maps how the target network is built: which subnets exist, how they route to each other, where the firewalls and jumps sit, and which internal addresses answer. It matters because an accurate map decides how the attacker moves after the first foothold, and because the collection is quiet, using routing protocol queries, simple network management protocol walks of routing tables, time to live probing and internal sweep of each discovered subnet. The telemetry that makes it possible is firewall and flow records for host sweeps inside the corporate space, router and switch logs for route table reads, simple network management protocol query logs, and command line auditing that captures traceroute and network configuration commands on hosts. Detection fails because network engineers run the same tools legitimately all day, so the rule depends on baseline behaviour and on the direction of the traffic, not on the tool name alone.

What you will practise

  • Define network topology discovery and explain why it follows an initial foothold.
  • Identify the router, firewall, flow and command line telemetry that reveals mapping.
  • Write a rule that counts distinct internal destinations per source host.
  • Describe how to profile network engineers and approved change windows.
  • Explain how a topology map supports lateral movement and target selection.
