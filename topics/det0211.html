DET0211 Detection of Direct VM Console Access via Cloud-Native Methods

DET0211Detection StrategyVery hardDetection Strategy

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

This detection watches for people connecting to a cloud virtual machine using the cloud provider's own tools. Those tools include the web console, a serial console, or a remote shell agent. It catches access that never touches your normal network path. The aim is to spot a login route that attackers like because it can skip your firewalls.

Why should you care?

An attacker who steals cloud credentials can reach a virtual machine without knowing its network position. Cloud consoles and remote shell agents often run with high privilege. They may not create the operating system logon events that your team already monitors. If you only watch inside the guest operating system, this activity can stay invisible. Watching the cloud audit log closes that gap.

How it works, in plain steps

  1. The cloud provider writes an audit record each time someone uses a console or agent to reach a virtual machine.
  2. Your platform collects those records into the security information and event management system, or SIEM. A SIEM is a tool that stores and searches log data.
  3. The rule keeps only console or agent sessions that start on a protected virtual machine.
  4. It compares the caller identity, the source address, and the time of day with a baseline of normal administrator behaviour.
  5. When the same identity also changed keys or firewall rules shortly before the session, the alert becomes stronger.
  6. An analyst then asks the machine owner whether the session was planned.

Real-world example

Think of a hospital sign-in sheet. The main door has a guard who writes down every visitor. A staff side door has its own paper list, kept in a different office. If you only ever read the main door sheet, you will miss everyone who used the side door. Cloud consoles are that side door, and their list lives in the cloud provider's audit log.

Key takeaways

  • Cloud consoles and remote shell agents can reach a virtual machine without a normal network path.
  • Watch the cloud audit log, because the guest operating system may record nothing at all.
  • A session is suspicious when it comes from a new identity, a new address, or an unusual hour.

In more detail

This detection strategy covers T1021.008, Direct Cloud VM Connections, where an actor reaches a cloud virtual machine through the provider's own console, serial port, or agent-based remote shell instead of a normal network path. Because those channels bypass host firewall rules and often leave no operating system logon record, cloud control plane audit telemetry is the only reliable evidence of the session. The main way it fails in practice is noisy administrative use of the same consoles, which pushes teams to over-filter and quietly lose coverage of the identities that matter.

What you will practise

  • Explain why direct cloud virtual machine connections can bypass host firewall rules and guest logon logging.
  • Identify which audit events record console, serial, and agent-based access in each cloud provider you use.
  • Build a baseline of normal administrator console use by identity, source address, and hour of day.
  • Correlate console sessions with nearby key, firewall, or identity changes to raise confidence.
  • Describe the main false positive sources and the filters that reduce them without hiding real abuse.
