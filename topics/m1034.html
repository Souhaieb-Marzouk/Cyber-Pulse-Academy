M1034 Limit Hardware Installation

M1034Enterprise MitigationVery hardMitigation

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

Limiting hardware installation means controlling which physical devices can be plugged into or added to a computer. Examples include memory sticks, external drives and unknown keyboards. The goal is to stop data leaving on a device, and to stop harmful hardware getting into the machine.

Why should you care?

A small memory stick can carry thousands of files out of a building in a pocket. A device that pretends to be a keyboard can type commands into a computer in seconds. Some hardware also carries its own hidden software. Network rules never see any of this, because the device never uses the network. Hardware rules close that gap.

How it works, in plain steps

  1. Decide which device types staff genuinely need, such as approved memory sticks for specific teams.
  2. Block the rest through a management tool that watches every port on the computer.
  3. Require signed drivers, so the software that comes with a device must be approved first.
  4. Record every device that is connected, including its type and who used it.
  5. Encrypt the devices you must allow, so a lost one does not leak your data.

Real-world example

Imagine a library where visitors may read any book but cannot bring in their own bags. Staff check the entrance, and a locker holds the few bags they must allow. Nothing walks out under a coat, and nothing unwanted walks in. Limiting hardware installation is that entrance check for computers: the ports are the doors, and the device rules decide what may pass through them.

Key takeaways

  • Physical ports are a data path that network controls simply cannot see.
  • Device classes differ in risk, so block by type instead of only blocking memory sticks.
  • Encrypt and log the removable devices you decide to allow.

In more detail

Limiting hardware installation restricts which physical devices may be attached to or installed inside a system, and it addresses risks that network controls cannot see. The mechanism has three layers: a policy that states what is allowed, a technical control that blocks or classifies a device when it is attached, and monitoring that reports what appeared. Real implementations include restricting mass storage through endpoint management, blocking unapproved device classes by vendor and product identifier, requiring signed drivers so rogue drivers cannot load, enabling firmware and port protections, and enforcing encryption for the removable media that must remain available. Evidence appears in device connection events, driver installation records, removable media audit logs and file copy events, which together can show whether data left the building on a memory stick. The usual misunderstanding is that blocking mass storage solves the problem; keyboards, network adapters, docking stations and malicious cable devices present different risks, so device classes matter more than a single on or off switch.

What you will practise
