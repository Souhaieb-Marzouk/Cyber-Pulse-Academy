T1668 Exclusive Control

T1668PersistenceExtremeTechnique

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

This is when an attacker who is already inside a computer locks the door behind them. They do not want any other criminal to get in the same way. So they fix or close the weakness they used, remove malware, and take away the access that let them in. They keep the machine for themselves.

Why should you care?

You may think two attackers on one machine is your problem solved, because they will fight each other. In reality it is worse. The first attacker makes the machine quieter by removing obvious signs, so your alerts fall while the intrusion continues. They also keep the full power of the machine for themselves, which matters if they are mining or encrypting. And if you later evict one actor, the other may already have a second hidden way back in.

How it works, in plain steps

  1. The attacker gains access using a known weakness, a stolen login, or a badly configured service.
  2. They confirm the access works and check that no other attacker or security tool is already active.
  3. They close the original way in, for example by applying the patch for the flaw they just used.
  4. They stop or remove the vulnerable service so the same path cannot be used again.
  5. They remove or disable other malware on the machine that belongs to different criminals.
  6. They strip extra permissions and close shares, so the machine looks tidier and they keep quiet, exclusive access.

Real-world example

Picture a burglar who gets into a shared flat through a broken window. Instead of grabbing what he can and leaving, he boards up the window from the inside. He then throws out the other burglar who was already hiding in the bedroom. Now he is the only intruder left. The flat looks tidy from the street, so the family sees no reason to call a repairman. The break-in is still happening, but every clue that would have revealed it has been removed.

Key takeaways

  • Unexplained patching, service removal or malware cleanup can be attacker activity.
  • Removing rival malware reduces noise, so a quieter host is not always a safer host.
  • Confirm every change against a ticket before you call it remediation.

In more detail

Exclusive control describes an adversary hardening a host it already owns so that rival actors cannot use the same foothold. The mechanism is anything that removes an entry path after the attacker is inside: applying the vendor patch for the vulnerability that was originally exploited, stopping or uninstalling the affected service, resetting or stripping privileges from the accounts that provided access, closing administrative shares, or deleting other malware families found on the host. In ransomware and cryptomining cases the motive is partly economic, because a machine mining or encrypting for one actor is worth less when a second actor is also running there. The detectable shape is unusual for maintenance: a patch or service change applied outside any change window, on a host that shows earlier exploitation artefacts, often performed by a non-standard administrative account or directly on the host. Endpoint logs record service stop and install events, hotfix or package activity with no matching ticket, and removal of files or autoruns belonging to other malware. Defenders should treat remediation that no team has claimed as suspicious, because the same actions appear in a legitimate incident response only when the response is documented.

What you will practise

  • Explain why an attacker would remove a vulnerability they already exploited.
  • List the kinds of changes, such as patch, service stop and privilege removal, used to close access.
  • Describe how exclusive control lowers the number of alerts a defender sees.
  • Identify endpoint telemetry that distinguishes unclaimed hardening from planned maintenance.
  • Explain how rival malware removal shows up in file and autorun data.
