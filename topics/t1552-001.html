T1552.001 Unsecured Credentials: Credentials In Files

T1552.001Credential AccessExtremeTechnique

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

This is the specific case where the loose secret is stored in a file. It could be a note someone wrote, a shared team password list, or a program's setup file. This sub-technique is when an attacker searches disks and shared folders for those files and reads what is inside.

Why should you care?

Setup files are copied between systems often, and they often contain real passwords. Shared folders give many people access, so one weak laptop becomes a path to everything. Finding one such file can give an attacker the keys to a whole service.

How it works, in plain steps

  1. The attacker searches disks and shared folders for likely filenames and keywords.
  2. Common words such as password, secret, and key send them to promising files.
  3. They open the setup files used by databases, cloud tools, and internal applications.
  4. They also inspect source code and programs that may contain a built-in password.
  5. Backups and saved machine images may hold copies of the same secrets.
  6. Any readable secret is then reused, or the whole file is copied off the machine.

Real-world example

Imagine a shared flat kitchen where everyone keeps a spare key in the cutlery drawer. It works well until a visitor opens the drawer while looking for a spoon. They now hold a key to the flat, and nobody notices because the drawer was never locked. The problem is not the lock on the door, but where the key was kept.

Key takeaways

  • Search your own systems for password files before someone else does.
  • Shared credential stores should be encrypted and access controlled.
  • Treat a large burst of file reads by a scripting tool as a warning sign.

In more detail

This sub-technique narrows the parent to secrets held in files, which is the broadest case because it includes user-created notes, shared team credential stores, application configuration, source code and binaries with embedded passwords, and the copies inside backups and saved virtual machine images. Adversaries typically work in two phases: a wide search for filenames and content matching likely keywords across local disks, mounted shares and cloud or container configuration directories, followed by targeted reading of the files that matched. The resulting artefacts are file read telemetry, remote share access records, and container or deployment logs where a secret was passed as a command parameter. Detection is difficult because configuration files are read constantly by legitimate agents, so the useful signal is an unusual reader in the process tree, a burst of reads across many directories, or a scripting interpreter touching files that the application itself normally opens. Copying the file off the host is itself a strong indicator.

What you will practise

  • Describe the kinds of files that commonly contain insecurely stored credentials.
  • Explain how an attacker searches a file system or share for candidate files.
  • Explain why backups and saved virtual machines are part of the search.
  • Identify the file access and share access records that reveal the activity.
  • Explain why copying a configuration file is suspicious even without modification.
