DET0869 Detection of Gather Victim Network Information

DET0869Detection StrategyVery hardDetection Strategy

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

Network information gathering is an early search for facts about your network. The attacker wants to learn your address ranges, your servers and your naming style. This detection looks for that search in your own domain name system, called DNS for short, and your firewall logs.

Why should you care?

You cannot defend a network you cannot see clearly, and neither can an attacker. They must map it first. That map shows what to attack and where to hide. The mapping leaves traces on your resolvers and your network devices. Those traces are often the first sign that someone is studying you.

How it works, in plain steps

  1. DNS servers and firewalls record every lookup and every blocked connection attempt. These records flow into your SIEM.
  2. The rule groups the records by the internal host that asked the question and by a fixed time window.
  3. It counts how many different names one host asked for, and how many of the answers were empty, meaning the name does not exist.
  4. Firewall events for connection attempts to many internal addresses that hold no service are counted in the same way.
  5. When one host passes the thresholds, the alert shows the host, the queries and the rejected addresses so an analyst can confirm the source is not an approved tool.

Real-world example

Imagine an information desk in a large office. A normal visitor asks for one room, gets the number and walks away. A person planning a burglary asks for the name of every room, every floor and every staff member, and notes which answers do not exist. The questions alone reveal the plan.

Key takeaways

  • Reconnaissance often looks like many failed answers rather than a successful attack.
  • The useful fields are the asking host, the name or address asked for, and the answer code.
  • You must know which of your own tools scan the network, or these alerts are noise.

In more detail

This detection strategy covers the gathering of victim network information, the reconnaissance step where an adversary maps your address ranges, name servers and internal hosts to plan a later intrusion. It matters because this mapping decides what the attacker targets next, and because most of the activity happens on your own resolvers and firewalls where you already collect data. The telemetry that makes it possible is the DNS query log, the firewall denial log and the network sensor output for name service traffic. The main way it fails in practice is baseline drift: backup software, inventory tools and monitoring agents produce the same volume of name lookups, so the rule must separate an internal system doing its normal job from one host suddenly probing many internal names.

What you will practise

  • Describe the type of information an adversary collects before an intrusion begins
  • Identify which of your own logs record name resolution and blocked connections
  • Build a baseline of normal name lookup volume for servers, workstations and appliances
  • Write a rule that counts distinct queried names and empty answers per internal host
  • Escalate a confirmed internal enumeration event and contain the source host
