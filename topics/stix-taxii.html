STIX and TAXII

Threat IntelligenceVery hardKeyword

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

STIX is a standard language for describing threats in a way computers can read. The name stands for Structured Threat Information Expression. TAXII, the Trusted Automated Exchange of Intelligence Information, is the delivery service that carries it. Together they let security tools share warnings without a human retyping anything.

Why should you care?

Before shared standards, every team sent warnings by email in its own format. Someone had to read each one and re-enter the details by hand. That is slow and full of mistakes. STIX and TAXII remove the retyping. A detection tool can pull new warnings and act on them within minutes. The trade-off is trust. You are accepting content that other people created, so you must validate it first.

How it works, in plain steps

  1. An analyst describes the threat using STIX objects, such as an attacker, a tool or a clue.
  2. Relationships link those objects, so a clue points to a technique and a report groups them.
  3. Each object gets a unique identifier and a modified time, so updates can be tracked.
  4. The objects are packed into a bundle, which is a single file of structured text.
  5. TAXII carries the bundle. A client polls a server collection, or subscribes to receive updates.
  6. The receiving tool validates the content, removes duplicates and decides what to block or hunt.

Real-world example

Think of shipping containers. Every country used to load goods in its own odd shapes, so docks wasted hours repacking. Then everyone agreed on one container size. A crane can now lift any container without opening it. TAXII is the shipping route, and STIX is the standard container. One more thing matters. You still inspect what arrives, because a sealed container can hold anything.

Key takeaways

  • STIX describes threat information in a structured way that tools can read.
  • TAXII moves those descriptions between organisations, removing slow manual retyping.
  • Always validate incoming bundles, because shared content can be wrong or poisoned.

In more detail

STIX is a structured language for expressing cyber threat intelligence and TAXII is the transport protocol that moves it between organisations, and together they are the standards that make machine-to-machine sharing practical. STIX is a graph-based data model, serialised as JSON, whose objects fall into domain objects, cyber observable objects and relationship objects. Domain objects describe high-level intelligence such as threat actors, campaigns, intrusion sets, malware, attack patterns, indicators, reports, courses of action and identities. Cyber observable objects describe the technical artefacts an analyst records, including files, processes, network traffic, domain names and registry keys. Relationship objects connect them, so an indicator can reference an attack pattern and a report can bundle the whole product. Patterning gives indicators a precise, testable expression language, which is what allows a detection platform to consume them without hand translation. TAXII is the transport layer: a client polls or subscribes to a server, and the server exposes API roots containing collections of STIX objects. TAXII collections are browsable sets of objects, while channels support publish and subscribe exchange. Versioning and identifier discipline matter operationally. Every object carries a stable identifier and a modified timestamp, and consumers deduplicate and resolve updates on that basis, so sloppy identifier generation causes silent divergence between sharing partners. Real deployments also need trust decisions, because receiving a bundle is receiving attacker-influenced content. Analysts must honour handling markings that express sharing caveats, and they must decide what tooling does when an object is malformed or uses extensions the consumer does not implement. A working pipeline therefore combines schema validation, deduplication, enrichment, confidence handling and a documented policy for what is automatically blocked, what is only hunted, and what is discarded.

What you will practise

  • You will be able to distinguish STIX domain objects, cyber observable objects and relationship objects and explain what each is for.
  • You will be able to validate, deduplicate and update STIX objects using identifiers and modified timestamps.
  • You will be able to explain how TAXII collections differ from channels and which fits a given sharing requirement.
  • You will be able to apply handling markings and confidence information when a bundle arrives from a partner.
  • You will be able to describe the failure modes of an unvalidated feed and the controls that prevent them.
  • You will be able to write a consumption policy that separates objects to block, to hunt and to discard.
