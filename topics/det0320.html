DET0320 Detection of System Network Connections Discovery Across Platforms

DET0320Detection StrategyVery hardDetection Strategy

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

This detection looks for commands that list the network connections of a computer. Such a list shows which programs are talking to which addresses, and which ports are open. Attackers run these commands to learn how they can move further.

Why should you care?

After entering one computer, an attacker needs a map of the network around it. Built in commands provide that map in seconds. Because the tools already exist on the system, downloaded software is not required. This detection is often the first sign that someone is exploring inside your network.

How it works, in plain steps

  1. An attacker runs a built in command, such as a port listing tool, on a computer they control.
  2. The operating system starts the command as a new process and records its full command line.
  3. The endpoint agent sends that process record to your central logging platform.
  4. The rule matches the command name, its arguments and the parent program that started it.
  5. It removes known administration scripts, monitoring agents and inventory tools by name and by schedule.
  6. What remains is scored. An alert is raised when that host or account runs this kind of command for the first time.

Real-world example

Think of a guest in a hotel who wants to know which rooms are occupied. They pick up the house phone and dial every room number one at a time. The phone system records each call. The front desk notices the pattern of many short calls from one handset, not any single call.

Key takeaways

  • Discovery uses commands that already exist, so file based detection rarely helps.
  • Command line logging is essential, because the arguments show what was requested.
  • Known administrative and monitoring scripts must be filtered or the alert volume is unusable.

In more detail

This strategy detects host based network connection discovery, the technique recorded in the assignment as t1049, where an attacker lists active connections, listening ports and routing tables to understand what a compromised host can reach. The commands involved are built into every operating system, so nothing new is installed and antivirus signatures rarely apply. Detection therefore relies on process creation with command line capture, augmented by shell history or audit records on servers, and it becomes useful only after you filter the administrative scripts and monitoring agents that run the same commands on a schedule. Correlating the executing parent process with the account and the host role is what turns a very noisy command line match into a reliable signal.

What you will practise

  • Describe what host based connection discovery reveals to an attacker
  • Identify the built in commands on Windows and Linux that list connections and ports
  • Explain why parent process and account context improve detection fidelity
  • Build a baseline of scheduled inventory and monitoring commands per host role
  • Write a rule that matches command arguments rather than tool names alone
  • Decide how to respond when discovery appears on a server that never runs such commands
