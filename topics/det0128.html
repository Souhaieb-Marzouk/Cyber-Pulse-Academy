DET0128 Detection Strategy for Hidden Windows

DET0128Detection StrategyVery hardDetection Strategy

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

A hidden window is a program window that runs on your computer but is never shown on the screen. The program still works and can still receive commands. Attackers hide windows so that you do not notice their tools. This detection looks for programs that create a window and then hide it straight away.

Why should you care?

Most people judge a computer by what they can see on the screen. If nothing appears, the machine looks quiet and healthy. An attacker can use that gap to run tools without raising suspicion. Some hidden tools can also take orders from a remote server. This detection helps you find activity that avoids the screen on purpose.

How it works, in plain steps

  1. The endpoint agent watches the calls that create, show, or hide a window.
  2. Hiding a window is normal alone, so the rule adds more context before it alerts.
  3. The rule checks which program made the call and where that program is stored.
  4. It also checks whether the program started recently or arrived from a temporary folder.
  5. The alert lists the process, the user account, and the title of the hidden window.
  6. An analyst then decides whether a known installed application caused the event.

Real-world example

Imagine a shop with a back room. Customers only ever see the front of the shop. A staff member can work in the back room all day, and the shop still looks normal. Now imagine a stranger slips into that back room. The front of the shop still looks fine, and no customer notices anything. This detection is like a camera in the back room. It records who goes in and what they do there. A hidden window is that back room, and the camera is the record of window calls.

Key takeaways

  • A hidden window is invisible to the user but still active on the machine.
  • Hiding a window is normal behaviour, so an alert needs extra context.
  • Without software that records window calls, this activity is very hard to see.

In more detail

Hidden windows (T1564.003) is a defense evasion technique in which a program creates or manipulates a graphical window and then conceals it so the user never sees the interface. The action itself is ordinary, so the detection strategy deliberately looks at context instead of the hiding call alone: which process hid a window, where that process lives, what started it, and whether it made network connections at the same time. Telemetry comes from endpoint agents that instrument window and desktop calls, from process creation records, and from short-lived process termination events. This strategy fails in two common ways. First, many legitimate applications hide windows on purpose, including tray utilities, installers, updaters, and backup helpers, so the base rate of the behaviour is very high. Second, on hosts without an agent that records user interface calls, a hidden window leaves almost nothing in the standard operating system event logs.

What you will practise

  • Describe what a hidden window is and why an attacker would use one.
  • Identify which telemetry sources can record a change in window visibility.
  • Explain why the hiding action alone is too common to alert on.
  • Build context checks around process path, parent process, and process start time.
  • Recognise the legitimate applications in your estate that hide their own windows.
