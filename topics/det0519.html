DET0519 Detect Persistence via Office Template Macro Injection or Registry Hijack

DET0519Detection StrategyVery hardDetection Strategy

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

This rule looks for a saved macro that starts by itself whenever a Word or Excel file opens. A macro is a small set of recorded steps that the program can replay. The rule watches two things. It watches the folder where these automatic templates are stored, and the settings that tell the program to load them. It catches the setup before the macro runs.

Why should you care?

Persistence like this survives reboots, password changes and normal cleanup. The user does not have to open a strange file. Everyday work is enough to run the code. The trick lives in one settings key and one template file. So it is easy to miss if you only watch documents. It also stays inside a program that most networks trust.

How it works, in plain steps

  1. The endpoint agent records every change to the registry, including the key that was written.
  2. The rule keeps writes under the Office application keys for the current user.
  3. A separate file watcher records new templates in the startup and add in folders.
  4. Writes performed by the office program itself during a normal save are treated as lower risk.
  5. Writes performed by a script host, an installer or an unsigned program score much higher.
  6. A settings change plus a script process starting from the office program is the alert.

Real-world example

Imagine a delivery office where every parcel goes into a pigeonhole before it reaches you. A worker changes the pigeonhole label so their own parcel is always placed on your desk first. The office still looks normal, and the parcel arrives every morning. This rule checks the label, not only the parcels.

Key takeaways

  • Automatic templates run on open, so they act like a scheduled task inside a document program.
  • Check both the template file and the settings that make it load, since either one alone is enough.
  • The writing process is the best clue, because normal users save through the office program itself.

In more detail

This detection strategy covers persistence through Office template macro injection, the sub technique tracked as T1137.001. Word and its siblings load macro content from a global template and from a set of registry values that decide which templates start automatically, so an attacker who can write a template or repoint those values gains code execution every time the application opens without touching a single document. The telemetry that makes it visible is registry writes under the Office application keys, file creation of templates in user writable startup and add in folders, process creation showing a document application spawning a scripting interpreter, and the user context in which those writes happen. The strategy fails in practice because organisations deploy legitimate templates through the same mechanism, so the detection must lean on the writing process, the file signer and the user profile rather than on the template file appearing at all.

What you will practise

  • Explain what a global template is and how it runs macro code when an office application starts.
  • Locate the registry values that decide which templates load automatically for a user.
  • Identify the folders where automatic templates and add ins are stored on a workstation.
  • Distinguish a legitimate template deployment from a suspicious one by writer, signer and timing.
  • Correlate a registry write or template creation with a later script process from the office program.
  • Describe a clean up step that removes the persistence without destroying the user documents.
