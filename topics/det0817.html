DET0817 Detection of Scanning IP Blocks

DET0817Detection StrategyVery hardDetection Strategy

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

This detection looks for someone testing many addresses in your internet range. The attacker checks which addresses answer and which services are open. The rule counts how many addresses one source touched in a short time. It also looks at how many ports were tried.

Why should you care?

A scan is the first real step of many attacks. It is noisy and cheap for the attacker, but it is also easy for you to block. If you miss it, the next step may be a login attempt with a stolen password. Noticing the scan gives you a free warning.

How it works, in plain steps

  1. Firewall and routing devices write a record for each connection attempt. The record holds the source, the destination and the port.
  2. Those records are sent to the security monitoring platform, called a security information and event management system.
  3. The rule groups attempts by source address and counts the distinct destination addresses and ports.
  4. It adds the timing pattern, because a scanner often uses the same small delay between attempts.
  5. Sources that cover many addresses or many ports in one short window are scored as a sweep.
  6. The alert shows the source, the count and the addresses that replied, so you can block and investigate.

Real-world example

Think of a night watchman on a street of fifty houses. He tries the handle of every front door in ten minutes. Nothing is stolen and no window is broken. However, the walk tells him which doors are unlocked. This detection watches the walk down the street.

Key takeaways

  • A scan is the cheapest warning you will get before an attack.
  • Count distinct addresses and ports from one source, not the number of packets.
  • Slow scanners stay under simple thresholds, so review weekly totals too.

In more detail

This detection strategy covers scanning IP blocks, the technique where an adversary probes a range of internet facing addresses to find live hosts, open services and software versions before choosing an entry point. It matters because the victim rarely sees an exploit attempt without a scan in front of it, and the scan is the moment when defenders can still block a source cheaply, before any credential is used. The telemetry that makes it possible is firewall deny logs, network flow records with byte and packet counters, intrusion detection sensor sweep signatures, and service logs that record version grabbing, such as web server requests for common administrative paths. Detection fails in practice because the public internet is scanned continuously, so a rule that alerts on every sweep drowns the analyst, and a rule tuned only to large sweeps misses the slow low rate scan that an experienced adversary prefers.

What you will practise

  • Define scanning of IP blocks and explain its place in the attack sequence.
  • Identify the firewall, flow and sensor fields that reveal a sweep.
  • Write a rule that counts distinct destination addresses and ports per source.
  • Describe the difference between a fast sweep and a slow low rate scan.
  • Explain how to confirm which hosts answered and what services they expose.
