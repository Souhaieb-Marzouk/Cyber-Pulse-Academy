T1686.002 Disable or Modify System Firewall: Network Device Firewall

T1686.002Defense ImpairmentExtremeTechnique

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

The main firewall technique covers any system that filters traffic. This version is about the firewall inside network devices. Routers, switches, and edge appliances all hold rules that decide what may pass. An attacker who reaches the device can change those rules.

Why should you care?

Network devices sit at the edge, so their rules protect many systems at once. One weakened rule can open a path to whole internal ranges. Attackers may also turn off logging, which hides their later steps. These devices are often managed with shared accounts, so blame is hard to place. Reviewing firewall changes quickly limits the damage they can cause.

How it works, in plain steps

  1. The attacker reaches the device interface using a valid account or a flaw in a public service.
  2. They read the current access control list, which states what traffic is allowed or blocked.
  3. Then they add a permit rule for broad internal ranges, or delete a rule that stopped them.
  4. On some devices they change interface settings that indirectly weaken the filtering.
  5. They may also reduce or switch off logging, so later rule matches leave no record.
  6. The device saves the new configuration, and that change is written into its logs.

Real-world example

Imagine a hospital night desk that controls which wards a visitor may enter. The night desk keeps a printed rule book for every ward. A thief does not force any ward door. They sit at the desk and add one line to that rule book. The new line says that all wards are open to everyone. The doors still work, and the guard still stands there. Only the printed list of open wards changed that night. Network devices keep the same kind of list, and its edits are the clue.

Key takeaways

  • Network device rules protect many systems, so a single edit can have a wide effect.
  • Compare each configuration change against an approved change ticket before you trust it.
  • Watch for logging being reduced in the same session as a rule change.

In more detail

Here the target is the filtering function inside network hardware such as routers, switches, and dedicated edge appliances, not a host or a cloud tenant. An attacker who reaches a management interface, either with valid device accounts or by exploiting a public-facing service, edits access control lists, security zones, or policy rules so that traffic which was previously blocked is now permitted, often by adding a broad permit for internal subnets. The evidence lives in the device configuration and its own telemetry: configuration diffs, commit and change records, authentication events on the management plane, and system messages about rule matches or about logging being turned off. Approved change windows produce the same events, so defenders lean on change tickets, the source address of the management session, and whether logging itself was weakened at the same moment.

What you will practise

  • Outline how change management records help separate approved work from malicious edits.
