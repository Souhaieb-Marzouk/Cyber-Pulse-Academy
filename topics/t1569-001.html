T1569.001 System Services: Launchctl

T1569.001ExecutionExtremeTechnique

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

Launchctl is a macOS command that talks to launchd, which is the part of the system that starts background jobs. Attackers use it to load a job file that runs their own program. The job can run straight away and can also come back after a restart. It is the macOS way of starting code through the service system.

Why should you care?

On macOS, launchd runs jobs for a single user and for the whole system, so a loaded job inherits real power. A small settings file plus one command is enough to run code. Software installers and administrators also use these jobs, so the action does not look strange on its own. Without a record of the jobs you expect, a malicious one hides easily among them.

How it works, in plain steps

  1. The attacker gets a command shell on the Mac, either directly or through remote access.
  2. They write a job file, called a property list, that names the program they want to run.
  3. They place that file in a launch agents folder for the user, or a launch daemons folder for the system.
  4. They run launchctl with the load or start subcommand, naming the file or the job label.
  5. The system then runs the named program with the rights of that user or that system job.
  6. Because the file stays in place, the job can start again after the next restart.

Real-world example

Imagine an office where the front desk keeps a list of timed jobs, such as turning on the lights at seven. Any member of staff may hand in a new card for that list. A person who slips in a card reading run this machine at midnight gets their machine started every night without touching it again. Using launchctl is the act of handing in that card.

Key takeaways

  • On macOS, the launch agents and launch daemons folders are the place to watch for new job files.
  • A single launchctl command can run code now and keep it running after a reboot.
  • Compare loaded jobs with a known inventory, and check who owns and signed each job file.

In more detail

Launchctl is the command line interface to launchd, the service management framework on macOS, and this sub technique covers its use for execution. Because launchd manages both system wide daemons and per user agents, an adversary with a shell can use launchctl to load, start, stop or unload a property list that points at their own binary. Typical invocations load a plist from a user or system LaunchAgents or LaunchDaemons directory, sometimes with the force flag that re enables a disabled job. This is the execution half of a pattern whose persistence half belongs to the Create or Modify System Process family: the property list survives reboot, while the load command makes the code run immediately. Telemetry includes unified log entries for launchd job loading and job start, process creation showing launchctl with load or start arguments, new or modified plist files in the launch directories, and a child process whose executable does not belong to a known application bundle. Defenders compare loaded jobs against an inventory and check plist ownership and signatures.
