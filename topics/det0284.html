DET0284 Detection Strategy for Exfiltration to Text Storage Sites

DET0284Detection StrategyVery hardDetection Strategy

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

Text storage sites are public web pages where people paste text and get a short link back. They are useful and legal, and many developers use them daily. Attackers sometimes copy stolen data into such a page so they can collect it later from somewhere else. This detection looks for uploads to those services that do not match normal business use.

Why should you care?

The destination is an ordinary website, so a block list of known names leaves many similar services open. An attacker can replace a blocked domain with another free text host in minutes. The upload is often small enough to slip under a normal data volume alarm. Watching the pattern of uploads gives you a chance to spot the loss while the data is still fresh.

How it works, in plain steps

  1. Your web proxy keeps a record of each request that passes through it. That record holds the host name, the full path, the method and the bytes sent.
  2. The rule selects requests that use the POST method. That method is how a browser or a tool sends a body of data.
  3. It compares the request body size with the size of the reply. An upload is large in one direction and small in the other.
  4. A DNS record or a flow record confirms that the same host contacted the service at about the same time.
  5. The rule then checks whether this user or this computer has ever used this kind of service before.
  6. Alerts that follow a sharp rise in file reads or a new archive file are ranked higher for review.

Real-world example

Picture a courier who leaves your building with a small envelope every day. Nobody minds, because small envelopes are normal and the courier is well known. One afternoon the same courier walks out with twenty large boxes and no delivery note. A good guard notices the size of the load, not only the door that was used.

Key takeaways

  • The size and direction of the request matter more than the name of the website.
  • Baseline who uses text and paste services, so that first time use stands out.
  • Without content inspection you can still detect volume and timing, but never the data itself.

In more detail

This strategy detects the movement of collected data to public text and paste style storage services, which adversaries favour because the destination is a legitimate, well known website that rarely looks hostile in a proxy log. The distinguishing evidence is not the domain alone but the shape of the request: an outbound POST with a large request body relative to the response, from a host or user with no history of using that service, often minutes after archive creation or a burst of document reads on the endpoint. Detection depends on web proxy or secure web gateway logs with full URLs and byte counts, DNS query telemetry, and network flow volume. It fails most often where transport layer security inspection is absent, so the rule sees only a host name and a byte count and can never read the payload.

What you will practise

  • Explain why public text storage services are attractive exfiltration destinations.
  • Read proxy logs well enough to separate an upload from a normal page visit.
  • Correlate outbound upload volume with endpoint file access around the same time.
  • Rank alerts using first time service use for a given user or host.
  • Describe the visibility limits that encrypted traffic places on this detection.
