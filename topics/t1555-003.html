T1555.003 Credentials from Password Stores: Credentials from Web Browsers

T1555.003Credential AccessExtremeTechnique

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

This technique means stealing the usernames and passwords that a web browser has saved for you. Browsers offer to remember logins so that you do not type them again. An attacker copies the browser's password file and then decrypts it on the same computer.

Why should you care?

One stolen browser profile can unlock email, banking, and work tools at the same time. Many people reuse passwords, so a single saved login can open several accounts. Browsers keep these secrets on the user's own disk, and the user's own session can often decrypt them. If you ignore saved browser passwords, one careless download can hand over a whole identity.

How it works, in plain steps

  1. Browsers offer to save each login, so the password file slowly fills with the sites you visit.
  2. On Windows, Chrome and Edge keep this list in a database file called Login Data.
  3. The stored passwords are encrypted with a key that is tied to your Windows logon.
  4. An attacker copies the file, then asks the Windows protection interface to unlock that key.
  5. The unlocked key decrypts every saved password, which can then be sent off the computer.
  6. Other tools instead read the memory of the running browser and pick out credentials directly.

Real-world example

Think of your browser as a helpful neighbour who keeps a spare key to every house on the street. You gave those keys willingly, because it saves you walking home again. The neighbour keeps them in a locked box, and the key to that box hangs on your own keyring. A thief who gets into your flat does not need to break the box. They pick up your keyring, open the box, and copy every spare key inside. Later they can enter any house on the street at a calm moment. The locked box was never the weak point. The weak point was that the only key to it sat in the same flat.

Key takeaways

  • Saved browser passwords are only as safe as the user account that protects them.
  • Watch for processes that read browser profile files outside normal browser activity.
  • Prefer a password manager with its own master password over browser password storage.

In more detail

Adversaries harvest saved website logins from the local credential stores that browsers keep for user convenience. On Windows the Chromium family writes a database file named Login Data, and the password column holds ciphertext protected by a key that is itself wrapped with the signed-in user's secrets, so copying the file alone is not enough. The attacker also reads the browser's local state file or asks the Data Protection API (DPAPI) to unwrap that key, then decrypts each stored row in memory. Firefox uses a logins file plus a key database, and other browsers keep comparable stores. Because the decryption happens locally under the user's own profile, the whole operation can run without elevation. Defenders see it as unusual file access inside the browser profile directory, a short-lived process that reads those paths, or a process calling credential-unprotect interfaces outside the browser. Legitimate sync, backup software and password-manager imports touch the same files, so the differentiators are the parent process, the account context, and whether the recovered values leave the host.

What you will practise

  • Explain what a browser credential store is and where it lives on disk.
  • Describe how saved passwords are encrypted and where the decryption key comes from.
  • Identify the log sources, such as process creation and file access events, that reveal the theft.
  • Distinguish malicious credential reading from browser sync, backup, and password import tools.
  • Recommend safer ways for end users to store and reuse passwords.
