T1557.003 Adversary-in-the-Middle: DHCP Spoofing

T1557.003Credential AccessExtremeTechnique

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

Dynamic Host Configuration Protocol (DHCP) is the service that gives your computer its network settings when it joins a network. These settings include your internet address, your gateway and your name servers. A DHCP spoofing attack is a fake version of that service running on the attacker's machine. It answers your request first and hands you settings that send your traffic through the attacker. This is the settings version of the parent technique.

Why should you care?

Your computer trusts the first good offer it receives, because DHCP has no built-in login. A fake server can therefore redirect everything you do without touching your device. It can also tell you to use the attacker as your gateway, or as your name server. From there, traffic can be copied or changed silently. The worst part is that your connection keeps working, so you have no reason to complain.

How it works, in plain steps

  1. Your computer joins a network and broadcasts a request for network settings to everyone nearby.
  2. A normal server offers an address, and your computer accepts the first suitable offer.
  3. The attacker runs a fake server and answers faster, or uses up the real server's addresses.
  4. The fake server sends settings that name the attacker as your gateway or name server.
  5. Your computer accepts those settings and sends all of its traffic through the attacker.
  6. The attacker forwards the traffic so everything still works, while copying or changing what passes.

Real-world example

Imagine arriving at a hotel where any staff member in the lobby may hand out room keys. The real receptionist is slow, so a stranger in a uniform reaches you first with a key card. That card opens a room the stranger controls, and all your calls are routed through their desk. You sleep well, because the room works, the lights work and the wifi works. The real receptionist never learns you were given the wrong key. The hotel only spots the problem later, when the records show two people issuing keys at once.

Key takeaways

  • DHCP has no authentication, so the network must decide which server may answer.
  • Compare the settings devices received with the settings you intended to give them.
  • Port security and client isolation stop most local spoofing before it starts.

In more detail

Dynamic Host Configuration Protocol (DHCP) lets a client obtain an IPv4 address and other network settings from a server it has not authenticated. The exchange is a broadcast discovery, an offer, a request and an acknowledgement, and the client accepts the first suitable offer it receives. An attacker on the same segment runs a rogue DHCP server and races the legitimate one, or exhausts the real address pool first, then hands out settings that point the victim at the attacker, such as a default gateway, a Domain Name System (DNS) server or a Proxy Auto-Configuration (PAC) file. The victim keeps working while all traffic flows through the attacker, who can sniff or modify it. Detection compares the settings clients actually received with the authorised configuration: legitimate DHCP leases, unexpected offer sources on a segment, conflicting gateway or DNS values, and internal names suddenly resolving through an external address. DHCP snooping with trusted ports removes most of the exposure, and legitimate causes such as a stray home router look similar, so the source port and the offered options usually settle it.

What you will practise

  • Describe the four steps of a normal DHCP exchange between client and server.
  • Explain how a rogue DHCP server can redirect a client's gateway, name server or proxy settings.
  • Explain how this sub-technique differs from ARP cache poisoning and name resolution poisoning.
  • Identify the logs and configuration records that reveal unauthorised DHCP offers.
  • List switch features that prevent rogue DHCP servers from serving clients.
