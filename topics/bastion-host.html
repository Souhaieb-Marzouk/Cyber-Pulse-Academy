Bastion Host

Security ArchitectureHardKeyword

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

A bastion host is a hardened server that guards the way into a private network. Administrators connect to it first, and from there they reach the systems inside. It is also called a jump host. Every management door into the network leads through this one machine.

Why should you care?

Every open management path into a network is a chance for an attacker. Many paths are hard to watch and hard to close. One guarded path is much easier to monitor and record. It also lets you demand strong login from every administrator. The result is that each admin session has a real name attached.

How it works, in plain steps

  1. A hardened server is placed in a separate and protected network zone.
  2. Only a few source addresses may reach it, and it accepts no other traffic.
  3. Administrators log in with multi factor authentication, which asks for two proofs.
  4. From the bastion they connect onwards to the internal systems they need.
  5. The bastion records every session, so later review of each action is possible.
  6. The server itself is patched often, because it is a valuable target.

Real-world example

Think of a stadium with one staff entrance. Players, cleaners and managers all enter there. Guards check every badge and write down the time. All the other doors stay locked from the inside. One busy door is far easier to watch than twenty quiet ones. The bastion host is that staff entrance.

Key takeaways

  • One guarded administrative path is easier to protect than many loose ones.
  • Use multi factor authentication and short lived access, not shared passwords.
  • Record and review sessions, because attribution is the point of a bastion.

In more detail

A bastion host, also called a jump host or jump server, is a hardened and closely monitored system that acts as the single entry point for administrative access into a protected network segment. Administrators connect to the bastion first and reach internal systems from there, so the number of paths that accept management traffic collapses to one that can be restricted by source address, watched continuously and reviewed. Modern implementations add multi factor authentication, short lived certificates or session brokering instead of standing credentials, command or keystroke logging, session recording, and just in time elevation so that access is granted for a task and then removed; many organisations now buy this as a managed access service rather than running a server. The real control is the chokepoint and the attribution it creates: every administrative session can be tied to a named human through one audited path. The mistake is building a bastion and then letting it hold long lived shared keys, or giving it no reachable systems at all, which turns the control into a formality that nobody uses.

What you will practise

  • Explain what a bastion host is and why administrative access is centralised.
  • Describe how source restrictions and network placement protect the bastion.
  • Explain how multi factor authentication and short lived access reduce credential risk.
  • Describe the value of session recording for investigation and accountability.
  • Recognise the configuration mistakes that make a bastion ineffective.
