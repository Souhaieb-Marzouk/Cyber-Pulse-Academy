T1505.006 Server Software Component: vSphere Installation Bundles

T1505.006PersistenceExtremeTechnique

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

VMware ESXi is a small operating system that runs virtual machines, which are software copies of computers. Updates and extra tools arrive as packages called vSphere Installation Bundles, or VIBs for short. This technique is about an attacker installing a harmful package so their code starts again every time the host boots.

Why should you care?

The hypervisor sits underneath every virtual machine, so access to it means access to much of the data centre. ESXi normally forgets most file changes when it restarts, which makes it hard for an attacker to stay. A package solves that problem because the host reinstalls its files on each boot. The host can also be told to ignore package trust checks, so a harmful package can look official. Few teams review hypervisor packages regularly, so a hidden one can last a long time.

How it works, in plain steps

  1. The attacker gains administrative access to the ESXi host, often with stolen credentials or a known flaw.
  2. They build a package that contains files, a description file and a signature block.
  3. They may copy the details of a trusted publisher so the package looks approved.
  4. They install it with the host command line tool, sometimes forcing the host to skip trust checks.
  5. The host unpacks the package and runs its files at every boot, restoring the changes made by the attacker.
  6. The package may also add firewall rules, open a listening port, or start a hidden program.

Real-world example

Picture a building manager who hands the same official maintenance kit to every caretaker each month. A fake kit looks identical on the outside, and the label claims it came from an approved supplier. When the caretaker follows it, the kit quietly adds a lock on the fire door that opens for one stranger. The kit returns to the shelf every month, so the problem never goes away.

Key takeaways

  • Hypervisor packages survive reboots even though most ESXi changes do not.
  • Check the host trust setting, because it decides which packages may install.
  • Keep a baseline of installed bundles and compare it after any change.

In more detail

vSphere Installation Bundles are the package format VMware uses to add or update software on ESXi hypervisors. A bundle contains a compressed payload archive that places files on the host, an XML descriptor that names the bundle and its dependencies, and a signature that determines the host acceptance level, the trust threshold that ESXi enforces before installation. That last detail is the crux of the technique: default hosts require at least a partner-supported level, but an operator with privileges can lower the acceptance level through the esxcli command line or install with the force option, which bypasses the check entirely. For an adversary who already holds host access, a bundle is an ideal persistence primitive, because ESXi keeps most file changes in memory and loses them on reboot, while an installed bundle can create start-up tasks, apply firewall rules, and drop binaries that are re-created on every boot. A forged descriptor can also present a malicious package as partner supported. Detection looks at the installation trail rather than at files: esxcli software installation logs, changes to the configured acceptance level, the installed bundle inventory compared with a known good list, unexplained firewall rules or listeners, and new start-up items that reference files outside the vendor set. Reboot survival is the reason these bundles matter, since a configuration-only change on ESXi would otherwise be temporary.

What you will practise

  • Describe what a vSphere Installation Bundle contains and what it does at boot.
  • Explain why package persistence is stronger than an in-memory ESXi change.
  • Identify host logs and settings that show a package was installed or trust was lowered.
  • Recognise disguised or forced package installations as suspicious activity.
  • Plan periodic reviews of hypervisor package inventories and firewall rules.
