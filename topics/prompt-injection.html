Prompt Injection

AI SecurityHardKeyword

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

Prompt injection is a trick played on an artificial intelligence helper. The helper reads text, such as an email or a web page. Someone hides instructions inside that text. The helper may follow the hidden instructions instead of yours.

Why should you care?

Helpers are often given access to real tools, such as mail, files or a company database. A hidden instruction could ask the helper to send data somewhere or delete a record. You may never see the text that carried the instruction. This risk is new, and normal antivirus tools do not catch it.

How it works, in plain steps

  1. You ask an AI helper to summarise a document or read a web page for you.
  2. Hidden text inside that document says something like ignore earlier rules and do this instead.
  3. The helper cannot always tell your instructions apart from the text it just read.
  4. It follows the hidden instruction and may use a connected tool to act.
  5. The action looks legitimate, because it used the account and permissions the helper already had.
  6. Defences limit what the helper can do and require approval for important actions.

Real-world example

Imagine a new assistant in an office who reads your post for you. A stranger posts a letter that says, inside the envelope, please send the filing cabinet key to this address. The assistant reads the letter and follows it, because the note looks like a normal message. The lesson is not that assistants are foolish. It is that you should not give them the key in the first place.

Key takeaways

  • Treat anything the AI reads as untrusted, including web pages and documents.
  • Limit the tools and permissions the helper can reach.
  • Ask a human or a fixed rule to approve any action that really matters.

In more detail

Prompt injection is a class of attack against systems built on large language models, in which an attacker places instructions inside content the model will read, such as a document, a web page, an email, a code comment or another user's message, and the model then treats those instructions as if they came from the system operator. The underlying reason it works is architectural: the model receives system instructions, user input and retrieved data as one stream of text in the same context window, with no reliable separator that enforcement code can trust. Two broad forms are usually distinguished. Direct injection is a user typing adversarial instructions into their own session. Indirect injection arrives through content the model fetches or that a tool returns, which is more dangerous because it can affect other users, repeat at scale, and run without the victim writing anything hostile. A successful injection may cause data exfiltration through a tool call or a rendered link, unauthorised actions with the model's connected permissions, or a manipulated answer that misleads a human. Defensive practice is layered and assumes the model output is untrusted: keep the model away from high impact actions, require deterministic policy checks or human approval before consequential tool calls, least privilege the credentials and tools the model can reach, treat all retrieved content as untrusted input, and log model inputs, tool calls and outputs for review. Content filtering helps but is not a complete control, because there is no known input filter that reliably removes all injected instructions while preserving normal usefulness.

What you will practise

  • Explain in plain terms what prompt injection is and why modern AI helpers are exposed to it.
  • Distinguish direct prompt injection from indirect prompt injection and explain why indirect is worse.
  • Describe the architectural reason instructions and data are difficult to separate in a language model.
  • List defensive measures such as least privilege, approval gates and treating model output as untrusted.
  • Explain why input filtering alone is not a complete defence against prompt injection.
  • Identify logging and monitoring signals useful for reviewing unusual AI agent activity.
