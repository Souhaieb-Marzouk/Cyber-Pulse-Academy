T1027.015 Obfuscated Files or Information: Compression

T1027.015StealthExtremeTechnique

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

Compression means packing data into a smaller form, and often joining several files into one container. Common examples are ZIP, 7z and RAR archives. This is a sub-technique of Obfuscated Files or Information. That parent technique covers hiding content from security tools. Attackers use archives to deliver harmful files that a filter might otherwise block.

Why should you care?

Filters often cannot read inside an archive, so the harmful file is hidden until someone unpacks it. A password protected archive hides content from every scanner, and users often receive the password in the same message. A self extracting archive runs its content as soon as it is opened, so one click is enough. Nested archives multiply the problem. If you block all archives, you may also block real business files, so you need context.

How it works, in plain steps

  1. The attacker places the harmful file inside a compressed archive, sometimes with a password.
  2. They may add a harmless document in the same archive so it looks like normal business.
  3. Some archives include a small program, called a stub, that unpacks the content when opened.
  4. Attackers can join several archives into one file so some tools miss the hidden parts.
  5. The archive arrives by email, chat or a download link and waits for the user to open it.
  6. Once unpacked, the file inside runs, and the packing itself leaves little readable evidence.

Real-world example

Think of a courier parcel wrapped in three layers of tape. The x-ray machine cannot see through the layers, so the guard waves it past the desk. A visitor takes it to a quiet room and unwraps it slowly. Inside is the item the guard was looking for. The wrapping was never illegal. Millions of parcels arrive taped this way every day, so the guard cannot simply stop every parcel.

Key takeaways

  • Treat password protected and nested archives from outside your organisation as high risk.
  • Watch self extracting archives carefully, because they unpack and run content in one step.
  • Follow what happens after extraction, since the packed file is what actually does harm.

In more detail

Compression reduces the size of a payload and packs several files into one container, which gives an attacker a delivery format that antivirus engines cannot read without unpacking it first. Common choices include ZIP, gzip, 7z and RAR archives, and self extracting archives that carry their own unpacking stub, so a single double click both extracts and launches the content without asking the user for a separate action. Compression is also used away from delivery: shellcode and staged data are compressed before being stowed in a non file location such as a registry value, because the encoded blob is smaller and less recognisable. A further evasion step is concatenation, where several archives are joined into one file so that some extraction tools read only the first central directory and never notice the embedded archive behind it. Compression is routinely layered with encryption, producing password protected archives whose password travels in the same message. Among all obfuscation methods this one is the most ambiguous, because compressed data is statistically indistinguishable from any other compressed data, so defenders cannot rely on inspection alone. Archives only become readable when a process extracts them and code runs, so useful signals include unusual extractor parent and child chains, self extracting archive execution, extraction of executables and scripts into user writable paths, and mail or web gateway metadata such as password protected attachments, mismatched internal file names and an archive nested inside another archive.

What you will practise

  • Explain how compression hides a payload from tools that cannot read archive contents.
  • Identify archive formats and techniques, including password protection, self extracting archives and concatenation.
  • Explain how this sub-technique differs from encrypted or encoded files and from packing used on executables.
  • Identify the artefacts, such as extraction chains and nested or encrypted archives, that support detection.
  • Decide when an archive is legitimate business content and when it needs closer inspection.
