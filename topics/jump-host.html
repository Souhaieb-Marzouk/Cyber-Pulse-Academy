Jump Host

Security ArchitectureHardKeyword

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

A jump host is a computer that you connect to first, before you reach the servers you really want. It is also called a bastion host or a jump server. Administrators use it as a single controlled doorway into a protected network. It is not there to do the work itself, only to pass your connection along safely.

Why should you care?

If every engineer can reach every server directly, you have hundreds of open doors and no clear record of who used them. One stolen laptop then gives an attacker a wide path into production. A jump host closes those extra doors and keeps them closed. It also gives you one place to check identity, record activity and cut off access quickly. Without it, nobody can really say who changed what.

How it works, in plain steps

  1. The protected servers sit on a network that your ordinary office computers cannot reach at all.
  2. The jump host is the only machine allowed to start connections towards those protected servers.
  3. You connect to the jump host first, using multi factor authentication, which means a password plus a second proof.
  4. From there you open your session onward, and the jump host passes the traffic through without storing it.
  5. The jump host logs who connected, when they connected, which server they reached and what they typed.
  6. Rights are granted for a short time, so access expires instead of lasting for years.

Real-world example

Think of a hospital ward where visitors cannot walk straight into patients' rooms. Everyone stops at the night desk first, signs in, says who they are visiting and receives a visitor badge. One corridor door is unlocked, and it is watched. All visitors pass that desk, so the staff can see who came in, at what time, and where they went. If a badge is lost, only one badge is cancelled. The ward is not sealed perfectly, but every entry has a record and a person watching. That desk is the jump host for the hospital.

Key takeaways

  • A jump host is the one approved doorway for administrative access into a protected network.
  • Its value comes from central logging, multi factor authentication and short lived rights.
  • A jump host without recording or strong login simply moves the risk to one busy machine.

In more detail

A jump host, also called a bastion host or jump server, is a hardened intermediary that administrators connect to before reaching systems on a protected network. It exists to remove direct management paths: instead of every engineer workstation holding credentials and reachability to every server, one well monitored system becomes the single doorway for administrative traffic. Because all sessions pass through it, the jump host is where multi factor authentication, per session authorisation, command and keystroke logging, file transfer control and time bound access can be enforced centrally. Its real security value is as a control and observation point, not as a magic boundary, since it concentrates privileged credentials and can become a single point of failure in both availability and compromise terms. It should sit in its own management segment, be reachable only from approved networks or a client virtual private network, run a minimal hardened build, and never double as a general purpose application server. The common mistake is deploying a jump host for convenience, to tidy up messy routing, without session recording, multi factor authentication or least privilege, which simply relocates the problem and creates a very attractive target.

What you will practise

  • Define what a jump host is and explain the access problem it is designed to solve.
  • Describe how administrative sessions are authenticated, authorised and recorded through a single entry point.
  • Explain the concentration risk of one privileged system and the hardening it therefore requires.
  • Compare a jump host with a client virtual private network as a way to reach protected systems.
  • Recognise weak jump host deployments that record little and grant standing administrator access.
