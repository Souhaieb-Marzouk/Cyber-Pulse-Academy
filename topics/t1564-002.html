T1564.002 Hide Artifacts: Hidden Users

T1564.002StealthExtremeTechnique

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

This sub-technique is about making a user account invisible on a computer. The account still exists and its password still works. It simply does not appear on the login screen or in the usual user list. On macOS, Windows, and Linux there are settings that can hide an account. It is the account part of the wider artifact hiding technique.

Why should you care?

An account you cannot see is an account you cannot check, disable, or delete. Attackers use hidden accounts to keep a way back into a machine even after the first problem is fixed. If you rebuild the computer and leave the account in place, the attacker can return later. Standard user list tools may show nothing unusual, so your check appears to pass. Only looking at the real account store and the settings that control visibility will reveal it.

How it works, in plain steps

  1. The attacker creates a new account, often giving it an ordinary looking name.
  2. They change a setting that controls whether the account appears in user lists.
  3. On macOS they can hide it from the login window and from System Preferences.
  4. On Windows a single registry value can keep the account off the logon screen.
  5. On Linux the settings of the login screen program can leave the account out.
  6. The account still works for remote access, tasks, and services, so it stays useful.

Real-world example

Picture an office building where every staff member's name is printed on a board beside the entrance. A manager adds a maintenance worker to the list of key holders but never adds the name to the board. The worker's card opens the door at any hour, and visitors at reception see only the names they expect. Nothing about the door or the card changed, only the board that everyone happens to read.

Key takeaways

  • Hidden accounts still work, so they remain a route back into a machine.
  • Hiding is a configuration change, which makes it easy to create and easy to miss.
  • Check the real account store and visibility settings, not just the login screen.

In more detail

Hidden users is the account focused branch of artifact hiding, and it matters because attacker created accounts are one of the most durable forms of persistence. Operating systems and desktop environments offer several ways to keep an account out of the place where people normally look, which is the logon screen and the graphical user management interface. On macOS an account can be created so that it never appears at the login window or in System Preferences, typically by giving it a low numeric identifier and enabling the setting that suppresses low numbered accounts, or by marking the account hidden through the directory service command line tool, with the home folder concealable as well. On Windows a registry value under the Winlogon special accounts key can suppress a named account from the logon screen, and no other property of the account changes. On Linux the visible account list is produced by the display manager, so the same goal is reached by configuring the greeter. The essential detection point is that every one of these methods affects presentation only. The account still exists in the account database, still holds its group memberships and its password or key material, and is still fully usable for remote logon, scheduled tasks, or service execution. Local account enumeration that bypasses the display layer, review of the registry and configuration stores that control visibility, and monitoring of account creation events all expose it. Missed hidden accounts are a common reason a compromised host is rebuilt and then recompromised.

What you will practise

  • Explain why attacker created accounts are valuable for persistence and why attackers hide them.
  • Describe how an account can be hidden on macOS using identifier and attribute settings.
  • Identify the Windows registry location that can suppress an account from the logon screen.
  • Explain how display manager configuration hides accounts from a Linux login greeter.
  • Explain why account enumeration tools may report a clean result while a hidden account exists.
  • Summarise how this sub-technique differs from the wider artifact hiding parent technique.
