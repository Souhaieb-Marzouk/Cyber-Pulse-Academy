T1033 System Owner/User Discovery

T1033DiscoveryExtremeTechnique

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

System owner and user discovery means finding out who uses a computer and which accounts are on it. The attacker may learn the current user or the accounts that log in often. They may also check whether someone is at the desk right now. This technique belongs to the discovery tactic, which covers learning about a victim network. It is a normal first look after getting a foothold.

Why should you care?

Knowing the user tells the attacker whose access to steal and who to imitate. A machine with an active user is often worth more than an idle server. This step is also very hard to alert on, because administrators run the same checks all day. If you ignore it, you lose an early warning sign of an intrusion. Small bursts of user lookups across many machines often come before bigger attacks.

How it works, in plain steps

  1. The attacker runs a simple command that prints the name of the current user.
  2. They read the answer or check settings that store the user name in plain values.
  3. They check who is logged in now and whether a session is active or idle.
  4. On many machines they list local accounts to find the ones worth targeting.
  5. They may look at which user owns important files or running processes.
  6. They repeat this on several hosts to see which are worth further effort.

Real-world example

Picture a cleaner who arrives in a shared office late at night. Before starting, they walk past the desks to see which chairs are occupied. They also read the name plates on the doors. That tells them which rooms to avoid and which to search. Nobody finds the walk suspicious, because staff walk those corridors all evening. The useful information was not locked away, it was simply on display.

Key takeaways

  • Treat unusual bursts of user and account queries as reconnaissance, even though the commands are ordinary.
  • Look at the parent process and the account behind the query, not only at the command text.
  • Correlate discovery activity across hosts, because one attacker tends to ask the same questions everywhere.

In more detail

System owner and user discovery is the reconnaissance step that answers who is behind the keyboard and which accounts matter on a host. An adversary wants the current user name, the accounts that normally log on, whether a human is active right now, and by implication whether the machine is worth deeper access or a shared jump box that should be left alone. Because account identity is threaded through almost every operating system surface, the discovery is rarely a single tool: it can come from a command such as whoami, from environment variables that hold the user name, from session listings, from process and file ownership, from local account enumeration, or as a side effect of credential dumping. The technique is cheap and overwhelmingly legitimate, so the useful discriminator is behavioural context rather than the command alone. Helpdesk scripts, administrators and management agents run the same utilities constantly, which is why detections should lean on clustering: a burst of user and system queries from one process or user across many hosts within a short window, account enumeration from a service account, discovery commands whose parent process is an office application or script host, or the same lookups repeated on hosts the account has never touched.

What you will practise

  • Explain why an adversary identifies the current user and the accounts that use a system.
  • Describe common discovery sources, including user name commands, session listings and file or process ownership.
  • Identify the log sources that record this activity, such as process creation records and shell history.
  • Explain how to separate routine administrative checks from reconnaissance by using context and clustering.
  • Describe what a burst of account or user queries across several hosts suggests about attacker intent.
