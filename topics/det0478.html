DET0478 User Execution – multi-surface behavior chain (documents/links → helper/unpacker → LOLBIN/child → egress)

DET0478Detection StrategyVery hardDetection Strategy

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

User execution means the attacker needs you to open something, such as a document, an installer or a link. This detection follows the whole story after that click. It watches which programs start next and whether anything reaches out to the internet.

Why should you care?

Most intrusions still begin with a person opening a file or following a link. A single alert about one process can be hard to judge. Following the chain shows intent, because those separate steps rarely appear together by accident. This approach also survives small changes in the attacker tools, because it tracks behaviour rather than names.

How it works, in plain steps

  1. The endpoint records every new process with its parent, its command line and the user account.
  2. The detection starts when a document reader, browser, mail client or archive tool starts a child process.
  3. It follows the child processes for a short time and records any scripting hosts or system utilities.
  4. It records files written to temporary or user folders during that window.
  5. It joins proxy and firewall logs to see whether the same host contacted a new or rare destination.
  6. A scored chain above the threshold becomes one alert with the full timeline for the analyst.

Real-world example

Picture a kitchen where each single step looks normal. Someone opens the fridge, takes out a box, uses a knife and turns on the oven. A good chef watches the whole sequence, not one step. Using a knife means little on its own. The full sequence tells you that a meal is being made. A strange sequence tells you something else is going on.

Key takeaways

  • One process event is weak evidence; the sequence is what carries meaning.
  • Chain detection survives small changes in attacker tooling because it tracks behaviour.
  • The egress step is the part that shows the chain was not ordinary work.

In more detail

This strategy detects user execution as a behavioural chain rather than a single file event, following the path from a document or link the user opened, through a helper or unpacker process, to a living off the land binary or child process, and finally to outbound network activity. It covers the user execution technique, where the adversary depends on a person to open a file or click a link, and accepts that no single event is conclusive. Detection joins endpoint process creation with parent and child relationships and command lines, file creation events for dropped payloads, and proxy or firewall records for the egress step. It fails in practice because document readers, browsers and archive tools spawn helper processes constantly for legitimate reasons, so the chain must be scored on rarity, timing and the reputation of the destination rather than on any one link.

What you will practise

  • Explain why user execution is best detected as a chain of behaviours.
  • Identify the process, file and network telemetry needed to join the chain.
  • Describe how parent and child relationships reveal the execution path after a click.
  • Score a chain by parent context, child rarity and destination reputation.
  • Present a chain alert as a timeline that an analyst can review quickly.
