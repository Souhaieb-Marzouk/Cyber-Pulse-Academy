IDS and IPS

Network SecurityVery hardKeyword

An intrusion detection system monitors network or host activity and raises alerts on behaviour that matches known attack signatures, deviates from a statistical baseline, or violates an explicit policy, while an intrusion prevention system sits inline and can drop the offending traffic in real time. Network sensors are usually deployed at chokepoints such as the internet edge, the data-centre core and the links between trust zones, fed by spans, taps or packet brokers, while host agents inspect system calls, file writes and process lineage that never appears on the wire. Detection logic spans signature matching, protocol anomaly checks, reputation feeds and behavioural models, and each family carries distinct failure modes: signatures miss novel variants and encoded payloads, while anomaly engines generate volume that overwhelms analysts. The dominant operational problem is rarely sensor coverage but triage capacity. A poorly tuned signature set produces thousands of low-value alerts every day, so genuine events are buried and mean time to detect degrades rather than improves. Mature teams suppress noisy signatures, tune thresholds against real baselines, enrich alerts with asset criticality and identity, and validate detection content with controlled tests before enabling prevention. Prevention deserves particular caution, because an inline device with a false positive becomes an availability incident, and an inline device with a decryption or evasion blind spot provides false assurance. Fragmentation, TCP evasion, protocol tunnelling, encrypted channels and high-throughput asymmetric paths all degrade inspection quality, so effective programmes treat detection and prevention as one detection-engineering discipline, keep content updates under change control, measure precision as well as coverage, and document the blind spots that remain.

What you will practise

  • You will be able to distinguish signature, anomaly and reputation-based detection and describe the failure modes of each.
  • You will be able to triage a sensor alert set by asset criticality, direction and expected business traffic.
  • You will be able to tune or suppress noisy signatures without creating an evasion gap.
  • You will be able to explain the operational risk of inline prevention and the conditions under which fail-open is acceptable.
  • You will be able to describe how fragmentation, encoding and encryption reduce inspection fidelity.
  • You will be able to evaluate detection coverage against a technique matrix and document the remaining blind spots.
