T1003.008 OS Credential Dumping: /etc/passwd and /etc/shadow

T1003.008Credential AccessExtremeTechnique

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

Linux keeps account details in two files. One lists the users and is readable by anyone. The other holds the password hashes and only the root user may read it. This sub-technique means stealing both files. It differs from the parent because the target is plain files on disk, not memory.

Why should you care?

The hash file can give an attacker every local password over time. Only root can read it, so success shows strong access is already held. Weak passwords can be cracked quickly on ordinary hardware. The files are small, so copying them takes only a moment. Monitoring these paths gives you a clear and early warning signal.

How it works, in plain steps

  1. Linux keeps basic account details in a file named passwd.
  2. Password hashes are kept separately in a file named shadow.
  3. The shadow file is readable only by the root user by default.
  4. An attacker who reaches root reads or copies both of these files.
  5. A utility joins them into one file that cracking tools can read.
  6. Cracking then runs offline and reveals any weak local passwords.

Real-world example

Imagine a library with two registers. One on the front desk lists members and is open to anyone. The second, kept in a locked office, records each member secret code. A thief who gets into the office photographs both registers together, so every name can be matched with a code. The library looks untouched. The passwd and shadow files are those two registers.

Key takeaways

  • The shadow file is the sensitive half and requires root to read.
  • Joining both files together makes offline cracking straightforward.
  • Audit rules and integrity checks on those paths repay the effort.

In more detail

This sub-technique covers reading the two Linux account files that together describe users and hold their password hashes. The passwd file lists accounts, numeric identifiers, home directories and login shells, and it is readable by any user, while the shadow file holds the hashes and is normally readable only by root. The adversary reads or copies both, frequently combining them with a utility that produces one file in the format cracking tools expect, then attacks the hashes offline at leisure. Privilege is the main barrier, so a root shell or a privileged file read is the pivot that makes the theft possible, and the files are small enough that the copy is quick and easily overlooked. Artefacts are limited to command lines that name the files, unusual reads by a process with no authentication role, and stray copies in temporary directories, which is why file integrity monitoring and audit rules on those paths give the clearest signal.
