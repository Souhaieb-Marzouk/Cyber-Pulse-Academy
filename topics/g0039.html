G0039 Suckfly

G0039Enterprise GroupExtremeThreat Group

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

Suckfly is a name used by security researchers for a group that spies on governments and companies. Public reports describe it as active from around 2014. The group is known for quietly using stolen logins and for signing its harmful programs so they look trustworthy.

Why should you care?

Suckfly shows how much damage a stolen password can cause. No trick or virus is needed if an attacker already looks like a normal user. The group also abused signing certificates (digital stamps that prove software is genuine), which means antivirus tools trusted the harmful files. That teaches a hard lesson. Trust signals such as a signature are useful, but they are not proof that software is safe, so behaviour on the endpoint still has to be checked.

How it works, in plain steps

  1. The attackers gather credentials, often by guessing them or by reusing passwords leaked from other breaches.
  2. They log in to a victim system with those valid accounts, so nothing looks unusual at first.
  3. They install secondary tools and create services so their access survives a restart.
  4. They obtain signing certificates, which are digital stamps that make a program look legitimate.
  5. They sign their harmful files with those stamps so security tools treat them as trusted software.
  6. Finally, they collect documents and move slowly through the network, hiding inside normal traffic.

Real-world example

Imagine a post office where letters are trusted if they carry an official stamp. A thief steals a real stamp and uses it on envelopes full of false bills. The clerk looks at the stamp, sees it is genuine, and sends the letters on without checking. Nothing about the stamp is fake, but the letters still cause harm. Suckfly did the same with software signatures. The stamp was real and stolen, so the harmful file passed inspection at the door.

Key takeaways

  • Valid stolen credentials can defeat controls that only look for suspicious software.
  • A valid digital signature proves origin, not good behaviour, so watch what a program does.
  • Long quiet intrusions are found by reviewing logins and services, not only by scanning files.

In more detail

Suckfly is a cyber espionage group tracked as G0039 and described in public reporting as active since at least 2014, with activity observed through 2017. The group conducted long running intrusions against government and commercial organisations in several countries, with reporting noting particular interest in technology and software organisations whose products were widely used elsewhere. Its tradecraft centred on obtaining valid credentials and abusing legitimate remote access, including stolen code signing material used to make its malware appear trusted, which is a supply chain risk because a signed file can bypass reputation checks that would otherwise flag it. Analysts reconstruct Suckfly activity from authentication logs showing logins from unexpected locations, endpoint records of service creation and credential theft utilities, digital signature anomalies on binaries, and network connections to infrastructure reused across campaigns. Attribution remains an assessment based on victimology and tooling overlap rather than a formal public conclusion, and reporting generally avoids naming a specific sponsoring state.

What you will practise

  • Explain what Suckfly is and summarise its reported targets and active years.
  • Describe how stolen code signing material weakens trust based security controls.
  • Explain why valid credentials make network intrusion harder to detect than malware alone.
  • List the log and endpoint evidence that supports investigation of a Suckfly style intrusion.
  • Discuss the limits of attribution when a group's identity rests on tooling overlap and victimology.
