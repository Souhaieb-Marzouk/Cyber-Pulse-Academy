T1561.002 Disk Wipe: Disk Structure Wipe

T1561.002ImpactExtremeTechnique

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

This sub-technique destroys the small parts of a disk that a computer needs in order to start. These parts hold the first instructions the machine runs and a map of where each section of the disk begins. If they are overwritten, the computer has no operating system to load. It is the structure focused part of the wider disk wipe technique. It can happen on its own or with a full content wipe.

Why should you care?

A computer with a destroyed boot area never reaches the login screen. Staff cannot work around that problem. The data may still sit on the disk, but nothing knows where it is without the map that was destroyed. Fixing a single machine is a technical job, and fixing hundreds at once is an emergency. Because the failure appears only at the next restart, an attacker can damage many machines before anyone notices. Monitoring low level access and keeping a clean copy of boot areas is essential.

How it works, in plain steps

  1. The attacker first obtains high level or system rights on the target machine.
  2. They open the raw disk device directly instead of using normal file operations on it.
  3. They overwrite the master boot record, which holds boot code and the partition table.
  4. Other boot structures or recovery areas may be damaged at the same time.
  5. When the machine restarts, the firmware finds nothing valid and booting fails.
  6. Defenders only see the result at reboot, but can catch the raw writes beforehand.

Real-world example

Picture a large public library. Destroying every book would take days and would be noticed. Instead someone removes the index cards and the shelf labels from the entrance hall. Every book is still on its shelf and undamaged. Yet no visitor and no librarian can find anything. The map of the building has vanished.

Key takeaways

  • Disk structure wipe destroys the boot code and partition map, not the bulk data.
  • The damage appears at the next restart, so the machine simply will not boot.
  • Many machines failing to boot at once points to a deliberate campaign.

In more detail

Disk structure wipe targets the small, critical regions of storage that a computer needs in order to start, rather than the bulk of the data. The master boot record holds the first code the firmware runs and the table describing where partitions begin, and if those bytes are overwritten the machine has nothing valid to hand over to an operating system. The same effect can be produced by damaging the partition table or other boot structures, and in many campaigns the structure wipe is performed together with a content wipe so that the whole device becomes unusable. Detection is difficult because the damage is only fully exposed at the next boot. Endpoint telemetry can still catch the moments before: an unexpected process opening the raw system device, driver or firmware level write activity in the first sectors of the disk, or a system that shuts down abnormally and then reports no bootable device. At scale the strongest indicator is correlation rather than any single event, because many machines across a site failing to boot within a short window, often with an identical error, is not a hardware coincidence. On network devices the equivalent action is a command line instruction that reformats the file system or erases the stored configuration. Recovery usually means reimaging firmware and boot structures and restoring data from a copy that was never reachable by the attacker, so write protected boot areas and firmware integrity checks are valuable controls.

What you will practise

  • Describe what the master boot record and partition table do during system startup.
  • Explain why destroying boot structures makes a machine unavailable even if data remains.
  • Explain how this sub-technique can occur alone or alongside a disk content wipe.
  • Identify the events that precede the damage, such as raw device access by odd processes.
  • Interpret a cluster of simultaneous boot failures across a site as a deliberate attack.
  • Outline controls such as firmware integrity checking, write protection, and reimaging plans.
