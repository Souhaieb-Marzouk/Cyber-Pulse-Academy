T1685.006 Disable or Modify Tools: Clear Linux or Mac System Logs

T1685.006Defense ImpairmentExtremeTechnique

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

Linux and macOS computers keep text files that record system activity, such as logins and service messages. These files usually live in one folder. This technique means an attacker deletes or empties those files. They may erase one file or many at once. The purpose is to hide what they did on the machine.

Why should you care?

These files are often the only evidence left on a Linux or Mac system. If they are deleted, you cannot tell who logged in, when a service changed, or how an attacker entered. Empty files are easy to overlook, because the folder still looks organised. You need copies on another machine and a way to notice files that change unexpectedly.

How it works, in plain steps

  1. The attacker gains root or administrator rights on the machine.
  2. They find the log folder and the files that record the events they care about.
  3. They delete those files, or empty them while leaving the file names in place.
  4. They may also clear the login records that store who was signed in.
  5. Some logs stop being written because the file no longer exists.
  6. Investigators find missing or empty records with no explanation in the system.

Real-world example

Imagine a shared flat where the kitchen whiteboard lists who used the washing machine and when. Someone wipes the board clean and puts the pen back in its place. The kitchen looks exactly as usual, and the flatmates cannot prove who ran four loads on Sunday. The board was never broken, only emptied.

Key takeaways

  • Watch the log directory for deleted, truncated, or unexpectedly empty files.
  • Copy logs to a central server so local deletion does not destroy the record.
  • Missing records from a period of interest deserve the same attention as strange entries.

In more detail

Clearing Linux or Mac System Logs is the Unix-family counterpart to deleting evidence already written, and it covers the text logs that most native services keep under the shared system log directory. On Linux the targets are the general message log, the authentication logs, the login records, kernel, scheduled job, mail, and web server logs; on macOS the same directory holds system, install, and application logs alongside the unified logging store. Deletion takes several forms, including truncating a file so it stays present and empty, removing it outright, or clearing login accounting records that live in binary form, and each leaves a different footprint. Because empty or missing files are not events in themselves, detection relies on file integrity monitoring of the log directory, on shipping copies off the host before tampering, and on correlating an unexplained absence of records with the activity that surrounds it.

What you will practise

  • Describe how truncation differs from deletion and how each appears on disk.
  • Explain why login records and binary log files need special attention.
  • Describe how file integrity monitoring and remote shipping reveal log tampering.
