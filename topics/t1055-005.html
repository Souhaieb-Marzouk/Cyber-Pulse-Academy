T1055.005 Process Injection: Thread Local Storage

T1055.005Privilege EscalationExtremeTechnique

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

Thread local storage is a small area of memory where a program keeps data for each thread. Windows also lets a program register callbacks, which are functions that run automatically at certain moments. This sub-technique is when an attacker points such a callback at their own code. It is part of the Process Injection parent technique. The difference is the timing. The attacker's code runs very early in the process, before the normal starting point.

Why should you care?

Code that runs before a program's normal start may also run before the security tools finish setting up. That makes the intruder harder to see. The trick lives in metadata rather than in obvious behaviour, so behavioural rules may miss it. It is often combined with other injection methods. That means one alert can hide another.

How it works, in plain steps

  1. Every program image may contain a list of callback functions that Windows calls when threads begin or end.
  2. The attacker builds a program, or edits one, so that a callback entry points at their own code.
  3. They get that image loaded inside a target process, often by swapping memory in a suspended process.
  4. When the process starts and its first thread is created, Windows calls the callback list as usual.
  5. The attacker's code therefore runs before the program's real entry point and before some defences are ready.
  6. The image on disk may still look normal, so a byte for byte comparison with a trusted copy is needed.

Real-world example

Think of a theatre where the doors open at seven and the audience is checked at the entrance. A stagehand arrives at six using a staff pass, while the security desk is still being set up. The stagehand hides a prop on the stage. When the audience arrives, everything looks normal and the checks run as planned. The prop appears during the performance and nobody can explain how it got there. The entrance log only shows the audience.

Key takeaways

  • Some code runs before a program's official starting point.
  • The trick hides in image metadata, so compare files with known good copies.
  • Early execution can precede the loading of security controls.

In more detail

This sub-technique abuses thread local storage callbacks, a documented part of the portable executable format. When an image has a thread local storage directory, the loader records addresses of callback functions there and calls them as threads start and end, which is a legitimate way for a program to set up or clean up per-thread data. Because those callbacks run during process initialisation, before the normal entry point, a payload that redirects them executes early, with the loading thread, under the image's identity. The practical forms are direct and indirect: an attacker can build or modify an image so that its callback table points at malicious code, and then get that image loaded into a target process using other injection methods, such as replacing an image in a suspended process, or they can alter an existing image's callback pointer in memory. The distinctive artefact is therefore temporal and structural rather than behavioural: the first thread of the process executing code from an unexpected address, a module whose declared callbacks do not match the vendor's copy on disk, or executable memory written before the process entry point is reached. Comparing image on-disk metadata and callback tables against a known good copy is the most reliable confirmation.

What you will practise

  • Explain what thread local storage callbacks are and when Windows calls them.
  • Describe how a callback pointer can be redirected to attacker code before the entry point.
  • Explain why early execution can precede the loading of security product hooks.
  • Identify the image metadata and timing evidence used to confirm this technique.
  • Explain how this technique is usually combined with other injection methods.
