DET0811 Detection of Search Engines

DET0811Detection StrategyVery hardDetection Strategy

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

Almost everyone uses a search engine every day, so this sounds impossible to detect. The clue is not the search itself but what is searched. This detection looks for web searches that pair your company name with sensitive words, such as password, database or login. It reports who searched and from where.

Why should you care?

People are the weakest link. Search engines are how attackers study them. A search can reveal a public document with a hidden account. It can also show an old test system that is still reachable. A job advert may list every tool the company runs. This is free research with no footprint on your network. Recording searches that mention your own organisation gives you a cheap early warning. It also shows you what is easy to find about you.

How it works, in plain steps

  1. Your secure web gateway writes a log line for each web request, including the search words if it inspects the address.
  2. The rule keeps requests that go to search engines.
  3. It checks whether the address also contains one of your protected terms, such as your domain or a product name.
  4. It records the account, the device and the address that made the request.
  5. Normal employee searching is filtered out by learning the usual volume and the usual accounts.
  6. Requests that fall outside the normal pattern are grouped and sent as a low priority lead.

Real-world example

Imagine a library with a sign in sheet at the door. Thousands of people come in each day to read, and nobody watches them. The librarian notices one visitor. This person only ever uses the reference desk to ask about one company. They ask about its address and its managers. They ask about its suppliers and its computer systems. Every question is allowed and nothing is broken. After the fifth visit, the librarian makes a note. This detection is that note. The searching is normal, the focus is not.

Key takeaways

  • The behaviour is normal, so you must make the rule about your own names, not about searching.
  • Encrypted search terms limit this detection, so record what your tooling can actually see.
  • The real benefit is discovery: these alerts show you what is already easy to find about your company.

In more detail

This strategy detects the use of search engines to collect information about the victim, ATT&CK sub technique T1593.002. The adversary runs ordinary web searches that combine the organisation name with terms for exposed documents, credentials, login pages, vendor products and staff, looking for anything the organisation published by mistake or revealed unintentionally. Because the searches go to public search engines, the only internal evidence is web egress telemetry: secure web gateway logs that retain the query string, transport layer security metadata that shows only the destination, and recursive domain name system resolver logs that show which search or translation service host was resolved. Detection is a correlation between a destination that is a search engine and a query term drawn from the organisation's own naming, weighted by the identity and address behind the request. The technique is deliberately unremarkable, so the signal is weak and the strategy depends entirely on context and volume. It fails because almost every employee searches the web all day, because encrypted query strings hide the search terms when the proxy does not perform content inspection, and because an adversary working from outside your network never appears in this telemetry at all.

What you will practise

  • Explain how search engine queries are used to collect information about an organisation
  • Identify the egress telemetry that can retain search query strings and destinations
  • Build a protected term list from organisation names, domains and product names
  • Establish a baseline of normal employee search volume to keep the rule usable
  • Recognise the telemetry gaps created by encrypted query strings and inspection limits
  • Use the findings to review what sensitive material is publicly discoverable
