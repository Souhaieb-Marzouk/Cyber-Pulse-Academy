T1546.004 Event Triggered Execution: Unix Shell Configuration Modification

T1546.004PersistenceExtremeTechnique

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

A shell is the program where you type commands on Linux or macOS. Each time a shell starts, it reads small text files that set things up for you. This technique is when an attacker hides their own commands inside one of those files.

Why should you care?

The hidden commands then run every time a shell starts, even after a restart. No extra service is needed, and the file already existed, so the change is easy to miss. Attackers can hide the edit by keeping the line quiet and adding it near the end. It is a simple and lasting trick.

How it works, in plain steps

  1. The attacker appends their command to a shell configuration file, or creates one if none exists.
  2. System files under the etc directory are used when the attacker has root rights.
  3. User files in the home directory are used when they only control a normal account.
  4. They usually hide the command by running it in the background or sending output nowhere.
  5. Some files run only for login shells, while others run for every interactive shell or new tab.
  6. Logout files can also be used, so code runs when the user closes the session.

Real-world example

Picture a shared flat with a noticeboard by the front door. Everyone reads it on the way in, because it holds the door code and the bin days. Someone adds one line at the bottom telling the reader to leave a spare key under a flowerpot. Every flatmate reads it and follows it, every single day.

Key takeaways

  • Shell configuration files run automatically, so they are a reliable place to hide commands.
  • Find them in the etc directory for all users and in the home directory for one user.
  • A line that downloads, decodes, or runs something hidden is the clearest warning sign.

In more detail

A Unix shell reads configuration files at defined points in its life cycle, and those files are ordinary text that executes with the rights of the account that owns them. The trigger is therefore the shell session itself: opening a terminal, connecting over the secure shell protocol, opening an extra interactive shell or tab, or logging out. The exact file depends on the shell and on whether the session is a login shell, so the common targets are the system-wide profile files under the etc directory and the per-user profile, login, and shell resource files in the home directory, with logout files used to run code when a session ends. Because the same feature is how developers set environment variables and aliases, a hidden line is easy to overlook and rarely breaks anything visible. Detection leans on file integrity monitoring of those paths, file creation and modification events, and process lineage in which a command or script appears as a child of a shell that a person or service started. The strongest differentiators against legitimate configuration are command lines that fetch or decode content, reference temporary or hidden directories, contact a remote host, or launch a binary that no package manager installed, especially when the file was modified outside a change window and its ownership or timestamps look altered.
