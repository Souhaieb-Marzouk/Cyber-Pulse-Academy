SHA-256

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

SHA-256, short for Secure Hash Algorithm 256, is a hash function. It takes any amount of data and produces a fixed 256-bit fingerprint, usually written as 64 characters. The same input always gives the same fingerprint, and any change, even one letter, gives a completely different one. You cannot turn a fingerprint back into the original data.

Why should you care?

SHA-256 is how computers check that a file arrived intact. Downloads, software updates and evidence bags all carry a fingerprint. If a single byte changed, the fingerprint no longer matches. But a fingerprint alone proves only that the data matches the fingerprint you were given. It does not prove who created it. You need a signature from a trusted source as well. SHA-256 is also fast, so it is unsafe for storing passwords.

How it works, in plain steps

  1. The input data is split into fixed-size blocks, and padding is added at the end.
  2. The function starts with eight fixed numbers that form its working state.
  3. Each block is mixed into that state through many rounds of simple operations.
  4. The operations include adding, rotating bits and combining values with logic rules.
  5. After the last block, the state is written out as the final 256-bit fingerprint.
  6. Changing one input bit scrambles the whole state, so the output looks unrelated.

Real-world example

Think of a wax seal pressed onto a document. The seal pattern depends on the whole document and on a fixed stamp. Change one word and the pattern no longer matches. Anyone with the stamp can make a new seal, so the seal shows the document is intact, not that a stranger wrote it. For that, you also need the writer's own signature.

Key takeaways

  • A hash is a one-way fingerprint: you can check it but not reverse it.
  • SHA-256 detects accidental change; only a signature proves who sent the data.
  • Never store passwords with a fast hash. Use a slow, salted method instead.

In more detail

SHA-256 is a cryptographic hash function from the SHA-2 family that maps an arbitrary-length input to a fixed 256-bit digest, and it is specified in FIPS 180-4. It belongs to the Merkle-Damgard construction with a Davies-Meyer compression function, processing 512-bit message blocks through 64 rounds over eight 32-bit state words. The function is designed to be preimage resistant, second-preimage resistant and collision resistant, so it is suitable for integrity verification, digital signature pre-hashing, message authentication when combined with a key, and content addressing. It is not a password storage function: its speed makes offline guessing cheap, and password hashing should use a memory-hard, salted construction instead. Integrity use cases bring their own failures, because comparing digests with a non-constant-time equality check leaks information and because hashing a downloaded artifact without binding it to a trusted signature only proves the artifact matches whatever digest was served alongside it. File integrity monitoring, software supply chain attestation, SBOM identification and forensic evidence records all rely on SHA-256 as a common language, so defenders need to know when a digest comparison is meaningful and when it is merely decorative. Extension-attack resistance is also relevant: because plain SHA-256 is a Merkle-Damgard construction, naive secret-prefix MACs built from it are forgeable, which is precisely why HMAC exists.

What you will practise

  • Explain the Merkle-Damgard structure of SHA-256 and what preimage, second-preimage and collision resistance each protect.
  • Distinguish integrity verification from authenticity and state what additional control is required for a trustworthy digest comparison.
  • Identify why SHA-256 must not be used directly for password storage and which construction to use instead.
  • Explain how length extension defeats secret-prefix construction and why HMAC is the correct keyed alternative.
  • Apply SHA-256 correctly in forensic evidence handling, file integrity monitoring and software supply chain records.
  • Assess the risk from deprecated hash functions still present in a certificate or signature policy.
