T1686 Disable or Modify System Firewall

T1686Defense ImpairmentExtremeTechnique

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

A firewall is a filter that decides which network traffic may enter or leave a computer or network. This technique means an attacker weakens or removes those filters. They may turn the firewall off, change one rule, or add a new opening. The purpose is to let their traffic through without being blocked.

Why should you care?

Firewalls are one of the main barriers between an attacker and the rest of your network. If a rule is opened, the attacker can reach systems that should be unreachable. Remote access tools can then connect freely. A single added rule can look harmless in a long list. Reviewing firewall settings and their changes is how you notice a door that was not there before.

How it works, in plain steps

  1. The attacker obtains administrator rights on the host or the management platform.
  2. They review the current firewall profiles and rule list to find what is blocked.
  3. They turn off a profile, or edit a rule so a blocked port is now allowed.
  4. They may add a new rule that permits remote access on an unusual port.
  5. The change takes effect, and their connection is no longer filtered.
  6. They use that path to move data, run tools, or reach other systems.

Real-world example

Think of a building where the front door is locked at night and every visitor must sign in. Someone adds a new side door to the plans and unlocks it, saying it is for deliveries. There is no sign on the door, and the main entrance still works as before. Nobody notices the extra way in until they check the building plans.

Key takeaways

  • Alert on firewall profile changes, rule edits, and newly added rules.
  • Keep a reviewed baseline of expected rules and compare it regularly.
  • Investigate traffic on unusual ports for well-known services.

In more detail

Disable or Modify System Firewall covers tampering with host-based and network firewall policy to remove restrictions on traffic and open paths for later action. Once sufficient privileges are held, the adversary turns off firewall profiles, edits existing rules so previously blocked ports or protocols are permitted, or adds rules that create covert channels, for example allowing a remote desktop protocol on an unusual port that is less scrutinised than the standard one. Platform specifics vary: on Windows the profiles and rules of the built-in firewall are the target, on Linux the packet filter rulesets, and on virtualisation platforms the firewall can be changed through the command line or the management interface. The resulting artefacts are configuration and policy changes rather than payload execution, so detection depends on configuration baselines, change auditing, and correlation with the sessions that the new rule permits.
