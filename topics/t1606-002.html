T1606.002 Forge Web Credentials: SAML Tokens

T1606.002Credential AccessExtremeTechnique

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

SAML, the Security Assertion Markup Language, is a way for one login system to tell other services who you are. That message is called a token. This sub-technique describes an attacker creating such a token himself, using a stolen signing certificate.

Why should you care?

With single sign on, many services trust the same login system. Forging one token can therefore open mail, file storage and administration consoles at once. The attacker chooses the name and the permissions inside the token. No password is typed, so second factor checks never run, and the entry can look like a normal sign in.

How it works, in plain steps

  1. The attacker steals the private key used to sign the federation tokens.
  2. Alternatively, he adds his own login server as a trusted federation partner.
  3. He then writes a complete token for any user and any set of permissions.
  4. He sets how long the token stays valid, sometimes far longer than normal.
  5. He signs it with the trusted certificate, so the signature looks genuine.
  6. Services read the token and grant access without any password check at all.

Real-world example

Picture a large office building where the front desk issues a signed visitor pass that every floor accepts. Security on each floor checks the signature, not your face. A thief cannot forge the manager signature by hand, so instead he steals the stamping machine from the front desk. Now he can print a pass for any name and mark it valid for a whole year. Every floor accepts the same pass, because the signature is genuine. Forging a SAML token is that stolen machine. One stamp gives access to every door in the building.

Key takeaways

  • Guard token signing keys as highly privileged secrets and rotate them regularly.
  • Monitor federation trust changes and new signing certificates as critical alerts.
  • Investigate privileged actions from sessions with no authentication record.

In more detail

SAML Tokens is the sub-technique of Forge Web Credentials in which the adversary creates Security Assertion Markup Language assertions and signs them with a token signing certificate they control, so that federated services accept them as issued by the trusted identity provider. In single sign on federation, services do not check passwords themselves; they trust assertions signed by the identity provider, and they cache or discover that provider signing key through federation metadata. An adversary who obtains the private key behind that certificate, or who holds enough administrative rights to register their own federation trust and certificate, can mint assertions for any user with any claims and any validity period. The assertion carries attributes ranging from group membership to administrative role, so a suitably crafted token can produce highly privileged access in a cloud directory. Because no password is used and no interactive sign in occurs, multi factor authentication is not exercised and the access looks like ordinary federated sign on. Detection is strongest at the federation layer rather than the application: new or replaced token signing certificates, changes to federation trust configuration or metadata, assertions signed by a key that is not the currently published one, rollover or validity windows that violate policy, and administrative or role sensitive activity from a session whose authentication record is missing or inconsistent. Legitimate federation changes are planned, documented and followed by certificate publication; forged token activity is not.
