DET0883 Detection of Botnet

DET0883Detection StrategyVery hardDetection Strategy

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

A botnet is a large group of infected computers that an attacker controls remotely. This detection looks for signs that your users or servers are talking to that kind of network. It catches both infected machines and traffic that is being relayed through bots to hide the real source.

Why should you care?

Attackers use botnets so their real location stays hidden. Traffic relayed through a bot often comes from a home internet address, so it does not look like a known bad server. If a machine in your network is part of a botnet, it can send spam, spread malware, or attack other companies. That puts your name on abuse reports and can break your internet reputation.

How it works, in plain steps

  1. Network devices and servers record connections, with the internal host, the outside address, the port, and the time.
  2. The detection checks each destination address and name against reputation data linked to botnet activity.
  3. It also looks for behaviour patterns, such as many hosts contacting one address on a fixed schedule.
  4. Identity records show whether remote access logins come from consumer internet addresses used by bots.
  5. Matches are grouped by internal host so one alert lists all the related connections.
  6. The analyst checks the host, isolates it if needed, and confirms with an endpoint scan or memory check.

Real-world example

Imagine a shop where every delivery is signed for at the door. A single van from an unknown address is normal. But when fifty shops in the same chain all sign for parcels from one small flat on the same street, at the same minute each night, the security team starts asking questions. The flat is the botnet, and the shops are the hosts that keep calling it.

Key takeaways

  • Botnet traffic hides behind ordinary home internet addresses, so address lists alone are weak.
  • Group alerts by internal host, because one infected machine usually makes many connections.
  • Reputation feeds change daily, so refresh them and expect some missing coverage.

In more detail

This strategy detects the use of botnet infrastructure against your environment, mapped to MITRE ATT&CK T1584.005 (Compromise Infrastructure: Botnet). Rather than building their own servers, adversaries rent or build networks of compromised hosts and use them as proxies, spam relays, and command and control relays, which makes the source of traffic look like an ordinary consumer internet connection. Detection relies on network and identity telemetry: proxy and firewall logs, DNS request logs, authentication records from remote access services, and reputation feeds that map addresses to botnet families. The main failure mode is that a single connection from a residential address proves nothing, so the detection has to correlate repeated or scheduled contact from many hosts, unusual process-to-destination pairs, and known command and control port behaviour. A second failure mode is infrastructure churn: sinkhole and reputation feeds lag behind new botnet address rotation, so list-only matching produces short-lived coverage.

What you will practise

  • Describe how botnets are used as relays and command and control for later stages of an intrusion
  • Identify which network and identity log sources reveal botnet contact from inside your estate
  • Correlate address reputation with connection behaviour such as fixed intervals and many-to-one fan-in
  • Differentiate a compromised internal host from an external bot relaying traffic toward your services
  • Document a response path that covers containment, verification, and abuse notification
