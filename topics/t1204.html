T1204 User Execution

T1204ExecutionExtremeTechnique

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

User execution means the attacker needs a person to do something, such as opening an attachment, enabling macros, or approving a login prompt. The code only runs because a real user chose to act. Attackers use it when they cannot reach the machine directly and must borrow a legitimate session.

Why should you care?

People are part of every workflow, so this step is hard to remove completely. One click can start malicious software with all the rights of that person. Blocking every prompt is not the answer, because staff then click without reading. The real goal is fewer, clearer warnings and fast detection when something does run.

How it works, in plain steps

  1. A message or download reaches the user and looks like normal business mail.
  2. The user opens a file, follows a link, or approves a permission request.
  3. That action starts a program, a script, or a document macro on the machine.
  4. The program runs with the user's rights and often hides inside a trusted app.
  5. It then connects out to fetch more tools or send data away.
  6. Defenders look at which program opened the file and what it started next.

Real-world example

Imagine a nightclub with a strict bouncer at the door. The attacker cannot pass, so they hand a guest a sealed envelope and ask the guest to carry it in. The guest is allowed inside, so the bouncer waves them through. Once the envelope is opened in the queue, the attacker's friend walks in behind. Nothing was broken. A trusted person simply did what they were asked.

Key takeaways

  • Your vigilance is a security control, but it is not a reliable one.
  • Watch which trusted program opened a file and what it started.
  • Keep alerts rare and meaningful so people actually read them.

In more detail

User Execution describes adversary reliance on a person to take an action that results in code running or a security decision being made in the attacker interest. It is the human step that completes many delivery chains: opening an attachment, enabling macros or add-ins, clicking through a security warning, running a downloaded installer, mounting a disk image, pasting and executing a copied command, or approving a fraudulent push notification. The technique appears wherever an adversary cannot reach a system directly and must borrow a legitimate user session and its privileges, which makes it relevant on Windows, macOS, Linux, mobile platforms and cloud consoles alike. The artefacts are a mixture of endpoint and identity telemetry: process creation showing a document reader, archive tool or installer spawning a shell or a scripting host, file creation in download and temporary directories, mark-of-the-web and quarantine attributes, macro and add-in events in productivity suites, click-through records for protected-view prompts, and authentication logs for push-notification or help-desk style social engineering. Investigators distinguish malicious from benign execution by examining the parent process, the file origin and zone information, whether the resulting process made outbound network connections, whether the same lure reached other users, and whether the account later exhibited behaviour inconsistent with its history. Because the triggering action is legitimate and user-driven, prevention leans on policy and interface friction rather than detection alone, and the honest measure of a control is how many prompts an ordinary employee must evaluate during a normal working day before the prompts themselves become the vulnerability.

What you will practise

  • Explain how user-initiated execution differs from remote exploitation and why that shapes the defensive response.
  • Trace a document, archive or installer parent process to the child processes and network activity it produced.
  • Read mark-of-the-web, quarantine and macro telemetry to establish how a file was obtained and opened.
  • Evaluate user-facing controls such as attachment policy, macro restriction and prompt design against real user behaviour.
  • Write detection logic for productivity and reader applications that spawn interpreters or shells.
  • Rank response urgency when a user action is confirmed versus merely suspected.
