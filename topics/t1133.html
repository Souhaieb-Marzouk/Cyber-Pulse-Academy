T1133 External Remote Services

T1133PersistenceExtremeTechnique

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

External remote services are the remote access tools a company deliberately publishes to the internet, such as a virtual private network gateway or a remote desktop portal. A virtual private network, or VPN, is an encrypted tunnel into the company network. Intruders use these same services to get in, or to come back later, with stolen credentials.

Why should you care?

These services must stay reachable, so you cannot simply block them. Every exposed gateway is a door that anyone on the internet can knock on. If one employee password is weak, or a gateway has an unpatched flaw, the whole internal network can be reached. Attackers also like these services for returning quietly after an initial cleanup, which is why they matter for persistence.

How it works, in plain steps

  1. The company publishes a remote access service so staff can work from outside.
  2. The intruder learns about it by scanning the internet for known service types.
  3. They sign in with credentials obtained elsewhere, or use an account issued to a contractor.
  4. Sometimes they attack the gateway itself, exploiting a weakness or a poor setting.
  5. They may also register an account on a hosted remote desktop platform the company never sees.
  6. Gateway logs show the source address, the client used and the session length.

Real-world example

Think of a shop with a staff entrance on a busy street. It has to stay open so employees can come and go, but it is also visible to everyone passing by. Anyone can walk up and try the handle. If the door lock is old, or one employee tells a stranger the code, the shop is open to anyone who looks like staff.

Key takeaways

  • Every service you publish to the internet is a door anyone can try.
  • Put multi-factor authentication in front of every remote access path.
  • Review gateway logs for logins from unexpected places or at odd hours.

In more detail

External Remote Services describes adversary use of legitimate remote access services to gain an initial foothold or to re-enter an environment from outside the perimeter. The services involved are ones the organisation exposes deliberately for business reasons: virtual private network concentrators, remote desktop gateways, remote shell and file transfer services, and hosted remote management or desktop-as-a-service platforms. Because the service is expected to be reachable and the protocol itself is legitimate, the technique sits on the boundary between initial access and persistence, and identical session types appear in both contexts. At a mechanism level an adversary authenticates with credentials obtained elsewhere, uses a valid account issued to a contractor or third party, exploits or misconfigures the gateway itself, or registers an account with a cloud-hosted remote access platform that the organisation cannot see at all. The telemetry lives mainly in the gateway and identity layers: authentication records with source address, client and device attributes, session start and duration, concurrent session anomalies, and configuration changes to the service, after which endpoint records show what the session did once established. Investigations separate legitimate remote work from abuse by examining the source network and its reputation, whether the account was expected to use that client and that geography, whether the session coincided with password spraying or credential stuffing activity, and whether the same account performed administrative actions outside its normal pattern. Strong controls tie every exposed service to multifactor authentication and device posture rather than treating network reachability as sufficient proof of identity, and they log enough session context to reconstruct who connected from where and when.

What you will practise

  • Inventory externally reachable remote access services and identify which are business-essential.
  • Read gateway authentication and session logs to establish source, client and duration for a session.
  • Correlate a remote session with identity anomalies and with post-authentication endpoint activity.
  • Evaluate multifactor, device posture and session recording controls for each remote access path.
  • Explain how third-party and hosted remote management platforms complicate visibility and attribution.
  • Write detection logic for remote sessions from unexpected geographies or concurrent with credential attacks.
