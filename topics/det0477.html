DET0477 Behavioral Detection of WinRM-Based Remote Access

DET0477Detection StrategyVery hardDetection Strategy

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

Windows Remote Management is a Windows feature that lets an administrator run commands on another computer. It uses the same kind of web traffic as a browser, on a fixed port. This detection looks for remote command sessions that do not come from your normal management systems.

Why should you care?

Remote management that is already built in needs no extra tooling on the target. An attacker with one valid account can move between servers without installing anything. The traffic may look like ordinary web traffic to a filter. Watching who uses this channel gives you a strong signal of movement inside the network.

How it works, in plain steps

  1. Each host records when it starts a remote management connection and to which target.
  2. The target host records the session, the account used and the client address.
  3. The detection joins the two records so one alert shows the full path.
  4. It flags sessions where the source address is not a known management server.
  5. It adds the processes started inside the session, such as a command shell or a scripting host.
  6. An analyst checks the account, the source host and the commands before deciding on containment.

Real-world example

Think of an office with an internal phone line used by managers to give instructions to other floors. It is convenient and everyone trusts it. A stranger who finds a phone can call any floor and give orders, and the call looks normal. This detection checks which extension is calling.

Key takeaways

  • Remote management is built into Windows and needs no extra software on the target.
  • The port number is not useful for detection because the protocol normally uses a web port.
  • Correlating client, server and child process turns three weak events into one strong alert.

In more detail

This strategy detects remote administration through Windows Remote Management (WinRM), which maps to the remote services technique for Windows Remote Management. Because WinRM uses Hypertext Transfer Protocol (HTTP) on ports 5985 and 5986 and is a normal management channel, port based filtering rarely helps and the useful evidence is the operability stack: the client side event that records the connection target, the server side event that records the authenticated session, and the process creation that follows inside a WinRS or PowerShell remoting session. Detection correlates those three across hosts and adds the source address and account to decide whether the pattern fits the management plane. It fails in practice because management servers, configuration tools and monitoring systems use WinRM legitimately and constantly, so the rule must filter known management sources rather than the protocol itself.

What you will practise

  • Explain what Windows Remote Management is and how clients reach a target host.
  • Identify the client side and server side event records for a remote management session.
  • Correlate a session with the processes it started on the target.
  • Distinguish a management server from a user workstation by source address and schedule.
  • Describe triage steps for an unexpected remote management session on a server.
