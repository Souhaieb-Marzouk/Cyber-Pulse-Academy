DET0469 Detection Strategy for Patch System Image on Network Devices

DET0469Detection StrategyVery hardDetection Strategy

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

Network devices such as routers and switches run an operating image, which is the software that makes the device work. An attacker who can replace that image can keep access even after a restart. This detection looks for image changes that were not planned and approved.

Why should you care?

An infected image can hide in the device and survive cleaning of other systems. Network devices often sit at trust boundaries, so access there is valuable. Many teams rarely inspect these devices, which gives an intruder time. Comparing images against a known good baseline is the main protection.

How it works, in plain steps

  1. Network devices send logs about logins, configuration changes and image operations to a central collector.
  2. The detection watches for commands that copy, verify or select a new system image or boot file.
  3. It records the version and file hash of the image that is running and the image set to boot next.
  4. It compares those values with the approved baseline for that device model and role.
  5. It raises an alert when the hash or version does not match, or when the change has no approved ticket.
  6. An analyst verifies the change with the network team and captures the current image for review.

Real-world example

Think of a shop that swaps its front door lock for a new one. Customers see the same shop and the same staff, but the shopkeeper no longer holds every key. Comparing the lock serial number with the order record would reveal the swap. This detection compares the device image with the order record.

Key takeaways

  • Replacing a device image can give access that survives a restart.
  • You cannot detect it without collecting device logs and keeping an image baseline.
  • A hash mismatch on a trust boundary device is urgent, even before you know the cause.

In more detail

This strategy detects replacement or modification of the operating image on routers, switches and firewalls, which maps to the patch system image technique used to establish persistence on network devices. The evidence lives in device management and log channels rather than on endpoints: configuration change logs, image management or boot variable commands, file transfer records for image uploads, authentication logs for privileged administrative access, and periodic hash or version baselines of the running image. Detection depends on comparing the running and booted image version and hash against the vendor-published and internally approved baseline. It fails most often because many networks do not collect device logs at all, and where they do, scheduled firmware upgrades and recovery rebuilds look identical to an unauthorised image load.

What you will practise

  • Explain what a system image is on a network device and why an attacker would change it.
  • List the log sources that record image operations, boot changes and privileged device access.
  • Describe how to build and maintain an approved image baseline with versions and hashes.
  • Differentiate a scheduled firmware upgrade from an unauthorised image load using change records.
  • Outline containment steps for a suspected compromised network device.
