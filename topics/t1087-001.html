T1087.001 Account Discovery: Local Account

T1087.001DiscoveryExtremeTechnique

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

This is asking one computer for the list of accounts stored on it. These are local accounts, which exist only on that machine. The attacker wants to know which names exist and which ones are administrators. Unlike the parent technique, which covers accounts of every kind, this sub-technique is limited to the accounts on one host.

Why should you care?

A list of local accounts shows an attacker exactly which names to try. It also reveals service and support accounts that people rarely watch. Administrator accounts stand out, and those are the valuable targets. The commands are short, so they are easy to overlook in a busy log. Watching for them on servers can give you an early warning.

How it works, in plain steps

  1. The attacker runs an account listing command, such as a built-in tool that prints local users.
  2. They list the local groups to see which accounts hold administrative rights.
  3. On Linux they may simply read the account file that stores user records.
  4. They repeat this on other hosts to see which local names appear everywhere.
  5. They use the results to pick targets for password guessing or credential theft.
  6. Defenders spot it when account listing commands run on servers without a setup reason.

Real-world example

Imagine a hotel night manager who wants to know which rooms are occupied and who holds a master key. They read the front desk list rather than walking the whole building. That list is the local account list, and it covers only this one hotel. It says nothing about other hotels in the chain, which is exactly how a local account differs from a domain account.

Key takeaways

  • Local account listings on servers are unusual and worth an alert.
  • Count the members of the local administrator group and keep that number small.
  • Renaming a default account does not hide it from a listing.

In more detail

Local Account discovery enumerates the accounts and groups defined in a single host's own account database rather than in the central directory. The adversary lists local users, lists local groups, and inspects group membership to learn which names exist and which carry administrative rights, sometimes reading the account file directly on Linux or using the vendor account tool on a hypervisor. The output is small and the commands are short, so the behaviour generates very little noise, and it rarely runs on production servers outside onboarding or troubleshooting. Its value to the adversary is as a target list for password guessing and credential theft, and often as a map of service accounts that nobody watches. For defenders the strongest signal is correlation: an account listing followed by repeated failed logons, or the same process later reading a credential store.

What you will practise

  • Explain how later credential theft relates to this discovery step.
  • Describe how to baseline legitimate administrative activity on servers.
