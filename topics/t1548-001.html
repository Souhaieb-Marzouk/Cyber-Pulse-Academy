T1548.001 Abuse Elevation Control Mechanism: Setuid and Setgid

T1548.001Privilege EscalationExtremeTechnique

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

On Linux and macOS, a file has permission settings. Two special settings are called setuid and setgid. When they are set, the program runs with the rights of the file owner or group, not the rights of the person who started it.

Why should you care?

Administrators use these settings for tools that need extra rights, such as changing your password. The danger is that the same setting can be abused. An attacker who can set it on their own program gains a way to keep running with more power. An attacker who finds an existing program with the setting and a flaw in it can take over another account, sometimes the root account.

How it works, in plain steps

  1. These bits are stored with the file permissions and are set with a change mode command.
  2. When the program starts, the system gives it the rights of its owner or group instead of yours.
  3. An attacker sets the bit on their own program so it always runs with those elevated rights.
  4. This is a common way to escape a restricted shell or another limited environment.
  5. Alternatively, the attacker searches the disk for existing programs that already have the bit.
  6. Detection checks the file listing for the special letter and compares against a known baseline.

Real-world example

Imagine an office where a cleaner's badge opens only the corridors. One cupboard key is stored on a special ring that the building manager owns. Anyone who holds that ring can open the manager's office, no matter whose badge they carry. A thief can either find the ring left on a desk, or make a copy of the ring for later use.

Key takeaways

  • A setuid program runs with its owner's rights, so the permission letter s on a file matters a lot.
  • Keep a baseline of which files carry these bits and investigate every new one.
  • Be careful with setuid programs in user-writable folders, and review third-party software that uses them.

In more detail

The setuid and setgid permission bits make a program run with the privileges of the file owner or group instead of the caller, and adversaries abuse them in two directions. They can set the bits on their own binary, so it keeps executing in an elevated context later, which is often used to escape a restricted execution environment such as a limited shell or a jailed session. They can also enumerate binaries that already carry these bits and target a known weakness in one of them, turning a legitimate administrative helper into a path to another account. The vulnerable artefacts are ordinary and enumerable: the permission characters in a long directory listing show an s in place of the execute flag, and a permission based search over the filesystem lists candidates. Defenders compare the set of setuid and setgid files with a known baseline for the distribution, investigate new additions and binaries in user-writable locations, and treat third-party software with these bits as a deliberate risk decision rather than an accident.

What you will practise

  • Define the setuid and setgid permission bits and explain whose privileges the program receives.
  • Explain how these bits are set and how they appear in a long directory listing.
  • Describe how an attacker uses a self-made setuid binary to keep an elevated execution context.
  • Describe how discovery of existing setuid binaries can lead to privilege escalation through a flaw.
  • Detect unexpected setuid and setgid files using baseline comparison and permission based searching.
  • Explain why third-party software requesting these bits should be reviewed before deployment.
