TA0007 Discovery

TA0007EnterpriseExtremeTactic

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

Discovery is the quiet exploring an attacker does after getting inside. They map out which people, computers, shared folders and security tools exist. The goal is to understand the network before choosing a target. Almost every action uses normal built-in tools, so it rarely looks like an attack.

Why should you care?

Attackers who understand your network cause far more damage. They find the servers that matter and the accounts worth stealing. For defenders, this stage is frustrating because the same commands run every day for honest reasons. You cannot block them all. Instead you look for unusual breadth, such as one machine asking about everything at once.

How it works, in plain steps

  1. The attacker lists local accounts, groups and permissions on the machine they already control.
  2. They ask the directory service for other users, computers and shared folders.
  3. They scan nearby network ranges to find live hosts and open services.
  4. They read configuration files and check which security tools are running here.
  5. They build a picture, then pick the shortest path to valuable systems and data.

Real-world example

Imagine a burglar who slips into a large hotel. Before taking anything, they walk the corridors. They note which doors are unlocked, where the staff keep keys, and which rooms look expensive. Nothing is stolen yet, and a guest walking the same corridors looks normal. The difference is intent and scale. One person wandering every floor, checking every door, is not a guest. That wandering is discovery.

Key takeaways

  • Discovery is how an attacker learns your network before deciding what to do.
  • The same commands are normal, so look for unusual breadth.
  • Remove what you do not need to share, especially open folders.

In more detail

Discovery is the tactic that covers the internal reconnaissance an adversary performs after gaining a foothold, mapping users, systems, shares, permissions, security controls, and network topology so that the next move is informed. Behaviours include enumerating local and domain accounts, querying directory services, listing remote systems and open shares, scanning internal address space for live hosts and services, reading configuration and cloud metadata, and checking for the presence of security tooling. The volume of telemetry is deceptive: almost all of this activity is native to the platform, produces normal-looking events, and is generated constantly by legitimate administration, inventory, monitoring, and software deployment. Command line and script block logging capture many of the queries, but only if enabled and centrally collected, since local logs are easily lost. Authentication records reveal lateral enumeration through logon types and target patterns, while cloud audit logs show unusual describe, list, or permission-enumeration calls from a principal that has never made them before. Detecting Discovery in isolation is close to impossible because the primitives are not malicious. Progress depends on baselining which hosts and accounts normally run which discovery commands, scoring breadth over any single action, and correlating a burst of enumeration from one identity with the privileged access or lateral movement that follows it. High-fidelity signals are rare, so prioritisation must be ruthless.

What you will practise

  • Enumerate the main discovery behaviours across endpoint, directory, network, and cloud environments and the evidence each produces.
  • Explain why native enumeration activity cannot be detected with signature-style rules and what baseline data is required instead.
  • Score discovery by breadth and rarity, for example a single host issuing many distinct enumeration commands in a short window.
  • Use authentication and network flow telemetry to detect internal scanning and share enumeration that command line logs miss.
  • Correlate a discovery burst with the privilege escalation or lateral movement that follows to judge intent.
  • Design a hunting hypothesis for post-compromise discovery that can be run repeatedly with low analyst cost.
