T1570 Lateral Tool Transfer

T1570Lateral MovementExtremeTechnique

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

This technique is about moving files between computers that an attacker has already broken into. The file might be a tool, a virus or a stolen document. The attacker copies it across the internal network instead of downloading it again from the internet. It is one step in moving deeper into a network.

Why should you care?

Company networks are usually trusted on the inside. A file copy between two servers may not raise any alarm. Attackers use that trust to spread tools without touching the internet gateway. They also avoid security tools that watch for downloads from outside. If you ignore internal file movement, an intrusion can grow quietly from one machine to many.

How it works, in plain steps

  1. The attacker already controls one computer inside the network, which is the starting point.
  2. A tool or payload file is stored on that first computer to keep it ready.
  3. The file is copied to a second computer using a shared folder or admin share.
  4. Remote desktop sessions can carry the file through a redirected drive or clipboard.
  5. Built in tools such as scp, rsync, curl or sftp move files between hosts as well.
  6. The copied file is then run on the second host, often to repeat the same steps.

Real-world example

Imagine a large hospital with an internal mail room. One department can send a parcel to another without it ever leaving the building. Nobody at the front gate checks it, because it never passes the gate. An attacker who controls one department desk uses that same internal mail to send tools to other desks. The parcels look ordinary, so staff ignore them. A good security team watches the internal mail, not only the front gate.

Key takeaways

  • Internal file copies are normal, so watch who copies what and from where.
  • Native tools like scp and curl leave command line records you can review.
  • Check whether the same file name appears on several hosts in a short time.

In more detail

Lateral tool transfer covers the copying of tools, payloads or collected files from one compromised host to another inside the same environment. Once a first foothold exists, an operator rarely needs to pull everything from the internet again; the file is pushed over an internal channel instead. The usual carriers are administrative file sharing over Server Message Block (SMB) shares, Remote Desktop Protocol (RDP) sessions with drive redirection or clipboard copy, and native utilities such as scp, rsync, curl and sftp. The artefacts therefore resemble ordinary administration: a file write on a share, an inbound remote desktop session, or a command line that names an internal address rather than an external one. Defenders separate hostile transfer from routine operations by looking at the source host, the file name and type, whether the writing process is a shell or a service, and whether those two machines normally exchange files at all.

What you will practise

  • Explain how tools move between hosts after an initial compromise.
  • Name common internal transfer channels, such as shared folders and remote desktop.
  • Identify the log sources that record file writes and remote sessions.
  • Describe how to tell a routine file copy from a suspicious one.
  • Explain the difference between ingress tool transfer and lateral tool transfer.
