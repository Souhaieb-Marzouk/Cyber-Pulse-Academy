TA0006 Credential Access

TA0006EnterpriseExtremeTactic

Credential Access is the tactic covering the theft, guessing, or interception of account secrets, and it is frequently the single most valuable step in an intrusion because a valid credential can bypass controls that would stop everything else. Behaviours include brute force and password spraying against exposed authentication services, credential stuffing with data from unrelated breaches, dumping stored secrets from operating system memory or credential stores, reading browser and password manager databases, extracting keys and tokens from files, configuration stores, and container environments, intercepting authentication traffic, and abusing directory services to obtain or relay credentials. Defenders can see a great deal here if identity and endpoint telemetry is centralised. Repeated authentication failures followed by a success, logon attempts with unusual logon types, access to the memory of security-sensitive processes, bulk reads of credential files, suspicious use of directory replication or ticket-granting operations, and secrets exposed in code repositories all map to concrete events. The tactic remains hard to detect in isolation because spraying stays below account lockout thresholds by design, because legitimate administrators run the same tooling that attackers do, and because stolen credentials produce successful authentications that look healthy. Detection requires combining authentication analytics, endpoint behavioural monitoring, secret-scanning in source control, and monitoring of where secrets are stored, with priority given to protecting the highest-value credentials first.

What you will practise

  • Explain the main credential access paths, from spraying and stuffing to memory dumping and secret extraction, and how each generates evidence.
  • Analyse authentication telemetry to identify spraying and stuffing patterns that stay below lockout thresholds.
  • Identify endpoint behaviours that indicate credential dumping and explain what must be logged to see them.
  • Design secret-scanning and key-management controls that reduce the value of a stolen credential or key.
  • Prioritise protections for privileged, service, and machine identities rather than treating all accounts equally.
  • Build a triage path from a suspicious authentication to confirmation of credential theft and the actions taken with it.
