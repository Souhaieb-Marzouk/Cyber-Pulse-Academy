DET0419 Detection Strategy for Dynamic Resolution using Domain Generation Algorithms.

DET0419Detection StrategyVery hardDetection Strategy

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

A domain generation algorithm is a small program that makes many random looking domain names. It builds them from a starting value, and the attacker registers only one of them. The infected computer tries the names one by one until it finds the right one. This detection looks for a computer asking for many names that do not exist.

Why should you care?

If the control address is fixed, defenders block it and the attack stops. A generated list changes every day, so blocking is only a short delay. The names look odd but not clearly wrong, so reputation lists often know nothing about them. Most of the lookups fail, which is unusual for normal software. That failure pattern is what a defender can actually see.

How it works, in plain steps

  1. A resolver keeps a record of each name lookup. It stores the name asked for, the answer and whether the name existed.
  2. The rule groups those records by the computer that made the request within a short time window.
  3. It counts how many different names each computer asked for and how many of those lookups failed.
  4. Normal software asks a small number of well known names, so a large count of failed lookups stands out.
  5. The rule also checks the shape of the names, such as their length, their character mix and their shared ending.
  6. When one computer shows many failed lookups and similar name shapes, the analyst gets an alert with sample names.

Real-world example

Think of someone ringing doorbells along a long street at night. Most houses are dark and nobody answers. A single unanswered bell means nothing. One person walks the whole street and rings every bell in the same quick rhythm. That is worth a call to the watchman. The pattern of many failures from one visitor is the clue.

Key takeaways

  • Failed name lookups are the strongest visible sign of a generated domain list.
  • Count unique names per client, because total queries alone will not separate the pattern from normal traffic.
  • Character statistics must be tuned per environment or they will flag legitimate advertising and content domains.

In more detail

This strategy covers the use of domain generation algorithms for dynamic resolution, tracked as T1568.002, where malware computes a large set of candidate domain names from a seed so that the operator only has to register one of them to regain contact. It matters because the victim needs no hardcoded address, so blocking a single name or address does not remove the channel and takedown attempts are defeated by design. The telemetry that makes detection possible is name resolution telemetry at scale: Domain Name System query logs with query name, record type, response code and client, passive resolution data from a recursive resolver, and endpoint network events that tie the querying process to the resolver traffic. The main way it fails is that a good algorithm produces names that look plausible, so character based statistics alone generate false positives on content delivery and advertising domains, and the reliable signals are a high volume of failed resolutions, a shared parent domain that is newly seen, and a client that queries far more unique names than its peers.

What you will practise

  • Explain what a domain generation algorithm is and why it defeats address blocking.
  • Read Domain Name System query logs and the fields that describe a failed lookup.
  • Measure unique query names and failure ratio per client over a fixed window.
  • Apply name shape features such as length, character distribution and shared parent domain.
  • Correlate a burst of failed lookups with the endpoint process that made them.
  • Explain why the domain list must be tuned to your own environment's legitimate traffic.
