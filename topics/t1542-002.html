T1542.002 Pre-OS Boot: Component Firmware

T1542.002PersistenceExtremeTechnique

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

Many parts inside a computer have their own small software, called firmware. Examples are the network card, the graphics card and the disk controller. This sub-technique is an attacker changing the firmware of one of those parts.

Why should you care?

These parts are often not checked for tampering, so a change can go unnoticed. The code runs outside the operating system, where your tools cannot look. It can survive a full disk wipe and even an operating system reinstall. It may quietly put other malware back after you clean the machine.

How it works, in plain steps

  1. The parent topic covers attacks on the whole start up chain. This sub-technique targets one hardware part instead of the mainboard chip.
  2. The attacker needs deep access to the machine, or they need to reach a management controller that updates the part.
  3. They flash the component with modified firmware. Flashing means writing new software into the part's memory chip.
  4. The change may add hidden storage, a hidden network path or code that runs at start up.
  5. Because the part is not part of the operating system, antivirus and file checks usually see nothing.
  6. Defenders must track firmware versions for each part and compare them with the vendor's official releases.

Real-world example

Picture a delivery van fleet. The company checks every driver and every parcel, but nobody checks the vans' own route computers. A thief reprograms one route computer so the van returns to a depot of the thief's choosing each night, and cleaning the drivers' lockers changes nothing.

Key takeaways

  • Inventory firmware versions for every component, not only for the mainboard.
  • Include management controllers and network cards in your monitoring and update plan.
  • If a component implant is confirmed, reflash or replace the part instead of trusting a software clean up.

In more detail

Component Firmware is the Pre-OS Boot sub-technique that targets firmware on hardware other than the mainboard: network interface cards, graphics adapters, storage controllers, disk drives, baseboard management controllers, batteries, docking stations and other peripherals. The parent category covers tampering with the start up chain, and System Firmware covers the BIOS or UEFI; this sub-technique moves the same idea into devices whose firmware often has no signature checking, no measured boot participation and no vendor update logging, which is exactly why it is attractive. Malicious component firmware executes outside the operating system and outside the main firmware, so it can survive disk reimaging, operating system reinstalls and typical endpoint clean up, and it can serve as a re infection point that restores other malicious components after remediation. It may also provide covert storage or a persistent foothold that host tools cannot observe. Evidence is scarce by design, so defenders lean on inventory and attestation: record firmware versions for every component and network card, compare them with vendor releases, monitor out of band update mechanisms such as the management controller, and watch for component updates that no maintenance window or ticket explains. Replacing or reflashing the affected component is usually the only reliable remediation.

What you will practise

  • Define component firmware and give examples of hardware that stores it.
  • Explain how this sub-technique differs from the System Firmware sub-technique of the same parent.
  • Describe why component firmware often escapes the integrity checks that protect main firmware.
  • Explain how a component level implant can survive reimaging and restore other malicious code.
  • Describe the inventory and update practices that make a component firmware change visible.
