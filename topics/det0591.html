DET0591 Cross-Platform Behavioral Detection of File Timestomping via Metadata Tampering

DET0591Detection StrategyVery hardDetection Strategy

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

Files carry hidden labels called timestamps. The labels record when a file was created, last changed and last opened. Timestomping means an attacker changes these labels so a file looks old. This detection looks for software that rewrites file times. It also looks for files whose times no longer match the system.

Why should you care?

Investigators build a story from time. They ask what happened first, what happened next and what was planted. If an attacker can rewrite file times, that story becomes unreliable. A malicious file can hide inside a folder of old files and look untouched for years. You would then miss it during a review, and you could also blame the wrong account for a change.

How it works, in plain steps

  1. Endpoint agents record file metadata changes on important folders, such as temporary and system directories.
  2. Process creation records show which program ran, who ran it and with which command line.
  3. The rule looks for known timestamp rewriting tools, such as touch, and for suspicious scripts or PowerShell commands that set file times.
  4. It then joins the process record to file metadata events written in the same short window on the same host.
  5. A trusted baseline, such as a backup index or a deployment record, is compared with the reported file times.
  6. When a file time is older than the baseline and the process context is odd, the alert fires for a human to review.

Real-world example

Picture a hotel guest book at the front desk. Staff write down the exact time each guest arrives and leaves. A dishonest employee does not destroy the book. Instead they erase one line and write a much earlier time. The guest then seems to have arrived days ago and looks ordinary. A careful manager would not trust the book alone. They would compare it with the door camera and the key card log. This detection does the same thing. The file timestamp is the guest book, and the process log is the camera.

Key takeaways

  • Timestamps are evidence, not truth. Attackers can change them, so you must compare them with another source.
  • One changed time proves nothing. The signal is a changed time plus an unusual process on the same host.
  • Keep a trusted baseline, such as backups or build records, or you cannot prove that a timestamp is wrong.

In more detail

This detection strategy covers file timestomping, tracked as ATT&CK technique T1070.006, where an adversary rewrites a file's recorded access, modification or creation times so that forensic timelines and content discovery tools miss the file. It pairs two independent telemetry streams: process execution that names native timestamp rewriting utilities and their arguments, and file system metadata change records from endpoint agents or file integrity monitoring. The pattern only becomes meaningful when those two streams are correlated against a trusted baseline, because legitimate tools such as archivers, package managers, build systems and backup clients rewrite timestamps constantly. In practice the strategy fails for three reasons: file metadata events are expensive so most teams disable them, the rewritten timestamps are rarely compared to any authoritative source, and process names are trivially spoofed or wrapped in scripts. Analysts should therefore treat the endpoint process context and the baseline divergence as the two halves of one signal, not as separate alerts.

What you will practise

  • Explain what file timestomping is and how it breaks timeline based investigation
  • Identify the telemetry that proves a file's metadata was rewritten on each operating system
  • Correlate file metadata change events with the process that caused them
  • Compare observed file times with a trusted baseline such as backup or build records
  • Recognise the normal tools that rewrite timestamps so false alerts are reduced
  • Describe how to scope this detection to high value folders instead of every file on the host
