DET0269 Behavioral Detection Strategy for Remote Service Logins and Post-Access Activity

DET0269Detection StrategyVery hardDetection Strategy

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

This detection watches for people or programs logging in to a computer from somewhere else on the network. It then checks what they do in the first moments after that remote login. Remote login itself is normal, so the detection looks for the combination of a remote login and strange follow-up activity.

Why should you care?

Once an attacker has one account, they often use remote login tools to move to other computers. This is called lateral movement. Each remote login looks harmless on its own, which is why many teams miss it. Watching what happens right after the login gives you a much stronger signal. It also helps you spot an account that is suddenly used from a machine it never touches.

How it works, in plain steps

  1. The operating system records each successful login in a security event. The logon type field says how the person connected.
  2. The detection selects logon types that mean remote access, such as type 10 for remote desktop and type 3 for network access.
  3. It ignores machine accounts, because computers log on to each other constantly for normal business.
  4. It then looks for a new process started in that same session within a few minutes of the login.
  5. It compares the source address and workstation name with a baseline of where that account normally connects from.
  6. If the source is new and the follow-up process is a command interpreter or discovery tool, the system raises an alert.

Real-world example

Think of a hospital sign-in sheet at the staff entrance. Nurses sign in every day, and that is normal. The night manager cares when someone signs in at an entrance they never use and then walks straight into the medicine store. The sign-in alone proves nothing. The sign-in plus the next action is the story.

Key takeaways

  • A remote login is context, not guilt. The value comes from what happens next in the same session.
  • Machine accounts generate huge numbers of logons, so filter them or your alert queue will drown.
  • Baselines of normal source addresses per account turn a noisy rule into a useful one.

In more detail

This strategy detects remote service logons and the activity that immediately follows them, which is the practical way to cover remote services as a lateral movement path. The technique covers remote desktop, secure shell, remote management and remote procedure call style access to a host, and the detection value is not the logon itself but the combination of an inbound remote logon with unusual follow-on process creation from that session. Telemetry comes from authentication records such as Windows Security event 4624 with logon type 10 or 3, secure shell authentication logs, and process creation events linked to the session identifier. It fails in practice because administrators and automation use the same services legitimately, so the rule has to focus on first-seen source addresses, machine accounts used interactively, and short time windows between logon and process creation.

What you will practise

  • Describe how remote services such as remote desktop and secure shell are abused for lateral movement after initial access.
  • Interpret the logon type field in Windows Security event 4624 and explain which values indicate remote access.
  • Correlate an authentication event with follow-on process creation using the session or logon identifier.
  • Differentiate routine administrative remote access from adversary lateral movement by source address and account baseline.
  • Assess the coverage gaps when remote management traffic is allowed between all hosts without segmentation.
