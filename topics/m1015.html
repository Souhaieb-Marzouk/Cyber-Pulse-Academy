M1015 Active Directory Configuration

M1015Enterprise MitigationVery hardMitigation

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

Active Directory is the company phone book and key cabinet for a Windows network. It holds user accounts, computers, and groups, and it decides who may log on where. Active Directory Configuration means setting it up with safe defaults and clear rules.

Why should you care?

If this system is weak, one stolen password can grow into control of the whole company. Attackers love it because it is present in almost every office and it holds great power. Small mistakes, like old accounts with high rights, are easy to miss and easy to abuse. Careful setup and regular review keep the damage small.

How it works, in plain steps

  1. Create a central policy that sets password length, lockout rules, and which devices users may log on from.
  2. Separate administrator accounts from normal daily accounts, and never browse the web as an administrator.
  3. Limit high privileges to a small set of people, and review membership of those groups often.
  4. Turn off old, weak authentication settings that exist only for very old software.
  5. Give each service its own account with the fewest rights it needs, and rotate its secrets.
  6. Record changes in the directory and alert when privileged groups are modified or new trust is added.

Real-world example

Picture a large office with one key cabinet at reception. In a bad setup, the master key hangs on an open hook. Copies are never collected from people who have left the company. In a good setup, each key opens only certain doors, and every issue is written in a log book. The master key sits in a safe that needs two people to open it. Active Directory Configuration is the whole installation around that cabinet. It decides how much trouble one stolen key can cause.

Key takeaways

  • Your directory holds the keys to everything, so treat changes to it as high risk.
  • Separate admin work from daily work, so a normal user's mistake is not fatal.
  • Switch on directory logging and review privileged group changes every week.

In more detail

Active Directory Configuration is the hardening of the directory service that stores users, computers, groups, and the rules that govern them, so that a single compromised workstation does not become a single compromised enterprise. The mechanism is centralisation: authentication settings, logon restrictions, delegation, and group membership are defined once in policy and applied everywhere, which means a misconfiguration is also applied everywhere. It appears in real environments as Group Policy Objects controlling password and lockout settings, tiered administration of servers and workstations, protected users groups, removal of legacy authentication protocols, management of service accounts, and auditing of directory changes. Evidence left behind includes directory service event logs, changes to privileged groups, unusual Kerberos ticket requests or delegation use, and policy objects created outside the change process. The most common misunderstandings are that a hardened directory is a one-time project, and that directory logging is on by default. Neither is true. Default installations keep weak legacy settings for compatibility, and the events that reveal abuse of the directory are frequently not collected or not forwarded, so administrators discover the problem only after accounts have been created and used. Directory changes are also rarely reviewed as carefully as firewall changes, even though they carry more power.

What you will practise

  • Explain how centralised directory policy both strengthens and concentrates security risk.
  • Describe how to structure privileged groups and separate administrative accounts.
  • Identify the directory events and audit trails that reveal misuse.
  • Explain why legacy authentication settings are dangerous and how to retire them.
  • Plan a periodic review of accounts, groups, and service credentials.
