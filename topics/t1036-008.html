T1036.008 Masquerading: Masquerade File Type

T1036.008StealthExtremeTechnique

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

This is when an attacker changes how a file describes itself so it looks harmless. Every file type has a small start marker, a kind of hidden label. The attacker can change that marker, the extension or the file's structure. The file then passes checks it should fail.

Why should you care?

Many checks trust the label a file carries. If a dangerous file says it is a picture, some tools believe it. That lets malware pass through upload forms and file transfers. Some files are built to work as two types at once, which defeats simple checks. You need to look inside the file, not at its label.

How it works, in plain steps

  1. The attacker takes a malicious payload in a script or program format.
  2. They rename it with a harmless extension such as an image or text type.
  3. They may also edit the first bytes, called the header, to match that type.
  4. Upload forms and file checks then treat the file as a harmless document.
  5. Some payloads are polyglots, so they open as a picture and also run as code.
  6. The right program on the server or host still executes the hidden logic.

Real-world example

Picture a post office that sorts parcels by the sticker on top. A sender puts a fragile goods sticker on a heavy crate. The sorting belt treats it as fragile and sends it down the wrong lane. Nobody opens the crate to check.

Key takeaways

  • A file extension is a claim, not a fact about the content.
  • Confirm file type by parsing the content, not by reading the header alone.
  • Alert when a file with an inert extension is executed by an interpreter.

In more detail

Masquerade file type changes a payload's internal format markers, extension, icon or structure so that content inspection classifies it as an inert document or image. The manipulated parts usually include the magic bytes at the start of the file, the extension, and the declared content type used by web servers or upload handlers. Practical variants include a script payload renamed with an image extension and served or uploaded as such, a file whose header claims one format while the body contains another, and polyglot files that behave as two formats at once so that a validator sees a picture while an interpreter executes the embedded logic. Detection is strongest when runtime behaviour is compared with declared type: a file with an image extension being interpreted by a scripting engine, an image served with an unexpected content type, or content that opens correctly in a viewer yet still results in execution. File type identification should be driven by parsed structure and content, not by extension or by a single trusted header field.
