DET0299 Multi-Platform File and Directory Permissions Modification Detection Strategy

DET0299Detection StrategyVery hardDetection Strategy

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

Every file and folder has a list of who may read it, change it or run it. That list is called the permissions. This rule looks for changes to that list on important files and folders. It is most interested when the change gives more access to someone who should not have it.

Why should you care?

Attackers rarely break into a locked folder directly. They change the lock first, then walk in later as if they belonged there. The folder still looks normal, so nobody notices that the door is now open. Watching the lock itself, rather than the folder, catches the problem at the moment it appears.

How it works, in plain steps

  1. The operating system can be told to record when the permissions of an object are changed.
  2. That record names the object, the account that made the change and the new access rights.
  3. The rule filters these records down to sensitive paths, such as system folders, backup folders and shared data folders.
  4. It compares the account making the change against the accounts that normally manage that path.
  5. It also checks whether the new rights include write, take ownership or full control. Those are the rights attackers want most.
  6. If an unexpected account grants broad rights on a sensitive path, the system raises an alert for review.

Real-world example

Picture an office where each storeroom has a sign listing who holds a key. A thief does not break the door. They quietly add their own name to the sign, then come back at night and unlock the door normally. The cleaner who checks the signs each evening would spot the new name, even though the door was never forced.

Key takeaways

  • Permission changes are a stepping stone, not the theft itself, so they are easy to miss without a rule.
  • The useful fields are the object, the account that made the change and the new rights granted.
  • You must scope to sensitive paths, because permission changes happen constantly everywhere else.

In more detail

This detection strategy covers modification of file and directory permissions, mapped to T1222, a defence evasion and access technique in which an adversary changes access control on files or folders to grant themselves or their tooling rights they were not given. It matters because permission changes are the quiet enabler for later steps: once a service account or a low-privileged user can write to a protected directory, the attacker can plant code or read data without touching an obviously sensitive object. Detection is possible from object access auditing on Windows that records permission changes, file permission telemetry from Linux auditd and change attribution from network attached storage, plus the metadata fields that name the target and the new access mask. The main practical failure is that permission changes are frequent and legitimate, so the rule depends heavily on scoping to sensitive paths and unusual actors, and it degrades badly wherever object access auditing is turned off or the editing account is not recorded.

What you will practise

  • Explain what file and directory permissions control and why attackers change them.
  • Identify the audit records on each platform that capture permission changes and who made them.
  • Interpret a new access mask to judge whether it grants dangerous rights such as write or full control.
  • Correlate a permission change with later write or execution activity against the same path.
  • Define the sensitive path list and the approved owner accounts for your environment.
  • Recognise why disabled object access auditing is itself a detection gap worth tracking.
