T1087.004 Account Discovery: Cloud Account

T1087.004DiscoveryExtremeTechnique

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

This is listing the accounts that exist inside a cloud service. Clouds use several kinds of identity, such as user accounts, service accounts and roles. A role is a set of permissions that can be given to an account. Unlike the parent technique, this sub-technique focuses on cloud identities rather than office computer logins.

Why should you care?

Cloud accounts often control data directly, so knowing them is the first step to reading it. A role with wide permissions can be far more powerful than its name suggests. Attackers look for these over-powerful roles first. Cloud providers keep detailed records of these calls, so this is a good place to catch an intruder. You need to know which accounts normally make such calls.

How it works, in plain steps

  1. The attacker obtains a cloud session, often by stealing a token, which is a temporary key.
  2. They use a provider command interface to list all users in the account or subscription.
  3. They list service accounts and roles to see what automated identities exist.
  4. They read permission policies to find roles that allow wide access to data.
  5. They may then assume a role or attach credentials to keep that access.
  6. Defenders detect these calls in the provider audit log, which records who asked for what.

Real-world example

Think of a large shared flat where each housemate has a labelled hook for their keys. A new lodger reads every label and works out whose key opens the storage room. They take nothing yet. Now they know which key they need to copy. Cloud account discovery is that reading of the labels, and the cloud audit log is the camera in the hallway.

Key takeaways

  • Cloud audit logs record identity enumeration, so review them.
  • Give roles the smallest set of permissions that still works.
  • Alert when a quiet account suddenly lists users, roles and policies.

In more detail

Cloud Account discovery enumerates identities inside a cloud provider or software-as-a-service tenant: users, groups, roles, service accounts, and the policies attached to them. Provider command-line interfaces and APIs return this data to any principal holding the right read permission, so one stolen token or access key can map every identity and its effective access level across a subscription, project, or tenant. The provider records each call in its audit log together with the caller identity, which makes detection comparatively strong: look for enumeration calls made by a principal that has never used them, for bursts of identity reads followed by policy changes or new credentials, and for role or policy listings by an account whose normal work never requires them. The result shapes both target selection and the choice of a role to assume for wider access.

What you will practise

  • Explain how a stolen token enables broad identity enumeration.

  • Explain how role and policy review limits over-privileged accounts.
  • Describe how this sub-technique differs from domain or local account discovery.
