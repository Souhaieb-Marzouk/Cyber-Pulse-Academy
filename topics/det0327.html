DET0327 Multi-event Detection Strategy for RDP-Based Remote Logins and Post-Access Activity

DET0327Detection StrategyVery hardDetection Strategy

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

This detection watches for remote desktop logins, where one computer shows another computer's screen over the network. It then checks what the person did right after signing in. A login on its own is normal, so the detection looks for the pair of login and unusual follow-up work.

Why should you care?

Attackers use stolen passwords to sign in to servers they should not reach. With remote desktop they can work as if they were sitting at the machine. One login event tells you very little, because staff use the same method every day. Linking the login to what happens next separates routine support work from an intruder exploring your network.

How it works, in plain steps

  1. The target computer logs a successful sign-in and records the sign-in type. Type ten means a remote desktop session.
  2. The same record lists the account name and the address of the computer that connected.
  3. The detection starts a short timer when that record appears, for example fifteen minutes.
  4. During the timer it collects new programs started on the target computer and any new accounts or services created.
  5. It compares those follow-up actions with what the account normally does on that host.
  6. If the pattern is new, it raises one alert that shows the login and everything that followed it.

Real-world example

Picture a door log at a factory. A single entry at three in the morning is not proof of a break-in, because the night crew works then. But the same entry shows a badge from the loading department. Two minutes later, the machine room alarm rings. Now the guard has a story worth investigating.

Key takeaways

  • A remote login is only the beginning of the signal, not the whole alert.
  • Correlating account, source address and follow-up actions is what makes the alert useful.
  • Set a short window, because intruder actions usually start within minutes of the login.

In more detail

This multi-event strategy detects interactive remote desktop logins (T1021.001) and the activity that follows them, because a successful remote desktop session alone is weak evidence while the sequence of session start, account used, source address and first actions after login is strong. Telemetry comes from Windows Security logon events with logon type 10, the remote desktop services operational log, Sysmon process creation on the target and authentication logs on the source. The correlation is what makes it work: it links the account, the originating host and the processes spawned inside the session window. It fails when session auditing is incomplete, when jump hosts hide the true origin, and when administrators legitimately work this way all day.

What you will practise

  • Describe how source address and account baselines separate support work from intrusion
  • Explain the impact of jump hosts and shared administrator accounts on this detection
  • Draft a correlation rule with a bounded window and a follow-up action requirement
