DET0246 Detection Strategy for MFA Interception via Input Capture and Smart Card Proxying

DET0246Detection StrategyVery hardDetection Strategy

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

This detection looks for attempts to steal or relay the second step of a login. That second step may be a code from an app or a hardware key you touch. An attacker can grab the code on your machine, or pass your key press through their own computer. The rule watches which programs touch the security key service and how one code gets used.

Why should you care?

The second step is what makes a stolen password less useful. If an attacker can capture or relay it, they can sign in as the real user. The service they sign in to sees nothing wrong, because the prompt really was answered. Only the way the answer travelled gives them away, so the rule must look at devices and programs.

How it works, in plain steps

  1. A user starts a sign in that needs a security key, a smart card or a code.
  2. The operating system routes that request through the smart card service or the credential provider.
  3. The rule records every program that opens or reads those interfaces, with its parent process.
  4. It also records when a key press or input hook is installed by an unusual program.
  5. Identity logs show the same factor used from two devices or two addresses at nearly the same time.
  6. When an unknown program touches the interface and the login repeats elsewhere, an alert is raised.

Real-world example

Think of a bank counter where the customer must read a code from a small device. A thief standing behind can copy the code and use it at another counter a minute later. The second counter sees a correct code, so nothing looks wrong. The only clue is that the same code was used in two places at once.

Key takeaways

  • A relayed second factor looks completely normal to the service being accessed.
  • Watch which processes touch the smart card and credential interfaces, not just that they are used.
  • Two sign ins with the same factor from different devices in a short window is a strong signal.

In more detail

This strategy detects interception of multi factor authentication, covering one time code capture on an endpoint and relay of smart card or security key authentication through an attacker controlled host. The technique matters because it defeats the control that most organisations rely on to stop credential theft, and it does so while the real service sees a successful and correctly answered prompt. Detection depends on endpoint process access and input capture events, smart card service and credential provider usage, and identity records that show one factor used from two different devices or addresses. The main way it fails is that legitimate smart card middleware, remote support tools and accessibility features touch the same interfaces, so use of those interfaces is only suspicious when it comes from a process that has no business doing it.

What you will practise

  • Explain how one time codes and hardware keys can be intercepted or relayed.
  • Identify the endpoint interfaces that a relay or capture tool must touch.
  • Describe how to baseline which processes normally use smart card services.
  • Correlate smart card or credential provider use with suspicious parent processes.
  • Recognise duplicate use of one factor from two devices or addresses.
  • Describe how input capture hooks are recorded on an endpoint.
