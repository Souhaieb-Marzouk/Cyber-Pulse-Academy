Explained in plain language

Simple definition

AI security is about keeping artificial intelligence systems safe and trustworthy. It also covers using AI to help defend other systems. The work includes protecting the data, the model and the tools around them. One common problem is prompt injection, where hidden text makes the model follow an attacker's order.

Why should you care?

An AI assistant may have permission to read files or send email. A trick that changes its instructions can then cause real harm. The same assistant can leak private data in its answers. Models are hard to test because the same input may give different results. Security teams must treat a model as untrusted.

How it works, in plain steps

  1. A model is trained or downloaded, and it becomes part of an application.
  2. Users, documents and web pages can all send text into that model.
  3. The model cannot easily tell your own instructions apart from hidden attacker text.
  4. Hidden text may order the model to ignore its rules or reveal private data.
  5. If the model can call tools, those orders can change real systems.
  6. Good defences limit the model's access and check its output before use.

Real-world example

Think of a new intern who is helpful but very literal. You tell her to sort the morning post. A stranger slips a note into the pile that says to forward every letter to another address. She cannot tell that the note is an order. You would not give that intern the master keys, and you would check her work.

Key takeaways

  • Treat model input as untrusted, including documents and web pages it reads.
  • Give an AI agent the least access it needs, and review that access often.
  • Check model output before it triggers a real action, such as sending mail.

In more detail

AI security covers two connected jobs: protecting artificial intelligence systems from attack, and using AI safely inside security operations. On the protection side it includes securing the model supply chain and weights, controlling who can read or change training data and prompts, constraining what an agent is permitted to do, sanitising untrusted content that reaches a model, and monitoring inputs and outputs for abuse. On the operations side it covers detection, triage and summarisation, where the new risks are automation bias, over-trust in a generated summary, and the assistant itself becoming an attack path. What makes this different from ordinary application security is non-deterministic output, natural language as an input channel that no parser fully validates, and retrieval or tool access that lets model output cause real changes in real systems. The mistake organisations make is hardening only the model endpoint while leaving the surrounding data pipeline, the retrieval sources and the permissions granted to the agent untouched.

What you will practise

  • Explain what AI security protects and how it differs from traditional application security.
  • Describe prompt injection conceptually and why natural language is hard to validate.
  • Explain how tool and data access turn a model mistake into a real world impact.
  • Identify the supply chain risks around models, weights and training data.
  • Describe how to constrain an AI assistant so its output is checked before it acts.
