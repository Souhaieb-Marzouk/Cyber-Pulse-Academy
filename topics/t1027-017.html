T1027.017 Obfuscated Files or Information: SVG Smuggling

T1027.017StealthExtremeTechnique

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

SVG files are picture files that describe a drawing with text instead of fixed dots. The full name is Scalable Vector Graphics. Because they are built from text, they can carry a small script, which is a piece of code. This is a sub-technique of Obfuscated Files or Information. The script hides inside something you think of as an image. When a browser shows the picture, the script can run.

Why should you care?

People trust pictures more than programs, so they open SVG files without worry. Many filters also treat SVG as an image and inspect it less strictly. A script inside the file can then download more harmful code or show a fake login page. The code runs as the user, so it inherits that user's access. Filtering by file type alone will not protect you here.

How it works, in plain steps

  1. The attacker builds an SVG file, or edits a real one, so it still shows a normal picture.
  2. They add a script tag with JavaScript, which browsers are allowed to run in SVG content.
  3. Inside the script they store encoded pieces that can rebuild another program later.
  4. They may instead add code that downloads a file or sends the user to another site.
  5. The SVG reaches the victim by email, chat or a web page and looks like an ordinary image.
  6. When it renders, the script runs quietly and does the work without any visible warning.

Real-world example

Imagine a museum display case holding a drawing on paper. A member of staff can lift the paper and find a small drawer underneath with a written instruction inside. Visitors only see the drawing, and the guards check the glass, not the paper. Because drawings are never expected to carry instructions, nobody lifts the sheet. The instruction is simple, but the hiding place is what makes it effective.

Key takeaways

  • Treat SVG files from outside your organisation as executable content, not as plain pictures.
  • Look for script elements and event handlers inside SVG files, especially in email attachments.
  • After an SVG renders, check what was downloaded and which processes started afterwards.

In more detail

SVG smuggling hides script inside Scalable Vector Graphics (SVG) files, which are vector images written in Extensible Markup Language (XML). Because script tags are a legitimate part of the format, a crafted image can carry JavaScript that the rendering context executes, and SVG content is frequently treated as an image by mail gateways, web filters and users, so it receives less scrutiny than a script or executable. The smuggled script commonly assembles a payload in the browser from encoded fragments, downloads a file, redirects the victim to a hostile site, or draws interactive content such as a fake login form or download button that collects credentials. The same technique is used on its own or nested inside a Hypertext Markup Language (HTML) page, a Portable Document Format (PDF) file or another document, which further obscures where the code originated. Defenders should treat an SVG file as executable content attached to a document: inspect it as text, look for script elements and event handler attributes, follow the network calls the render makes, and check the process tree and downloaded files afterwards. The gap that makes the technique work is a classification mistake, not a broken control, so the corrective step is to align how filters treat the format with what it can actually do.
