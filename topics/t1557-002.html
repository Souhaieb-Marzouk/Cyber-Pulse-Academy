T1557.002 Adversary-in-the-Middle: ARP Cache Poisoning

T1557.002Credential AccessExtremeTechnique

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

Address Resolution Protocol (ARP) is the small helper that finds the hardware address of a computer on your local network. It has no login and no checking, so any device may answer. Poisoning the ARP cache means telling other computers a false hardware address. The victim then sends its traffic to the attacker instead of the real gateway or server. This is the local network version of the parent technique.

Why should you care?

Everything on your local network uses ARP, and it trusts whichever reply arrives first. One attacker machine on the same floor can quietly stand between many victims and the internet. Older protocols that do not encrypt their traffic then give up passwords and data. The victims notice nothing, because their connections still work. Without network level monitoring, this can continue for months.

How it works, in plain steps

  1. A computer needs to send data to another local computer, but it only knows the internet address.
  2. It broadcasts a question asking which hardware address owns that internet address.
  3. The real owner normally replies, and the answer is saved in a small cache.
  4. The attacker replies faster, or sends an unsolicited reply, so their hardware address is saved instead.
  5. Traffic for the real server now goes to the attacker, who forwards it to avoid suspicion.
  6. While forwarding, the attacker copies unencrypted data and can change it before passing it on.

Real-world example

Picture a block of flats with one shared letterbox room and no name plates. To send a parcel to flat twelve, you shout down the corridor asking which door is flat twelve. The real tenant usually answers, but the neighbour next door answers first and says the parcel is for them. From then on, you leave flat twelve's parcels at the neighbour's door. The neighbour opens each parcel, copies the contents, reseals it and passes it on, so flat twelve still receives everything. Nobody complains, and the only hint is that two different doors sometimes claim to be flat twelve.

Key takeaways

  • ARP has no authentication, so the network must be protected by design.
  • Watch for one hardware address claiming many internet addresses.
  • Encrypt traffic end to end, because the path itself cannot be trusted.

In more detail

Address Resolution Protocol (ARP) maps an Internet Protocol version 4 (IPv4) address to a link layer address such as a Media Access Control (MAC) address, and it does so without any authentication. A host either answers a broadcast ARP request or accepts an unsolicited gratuitous reply, then stores the result in a small cache that it trusts. An attacker on the same network segment exploits this by answering faster than the legitimate owner or by broadcasting gratuitous replies, so victims store the attacker's MAC address for a gateway or a peer. Traffic between the two victims is then forwarded through the attacker, who can copy, modify or drop it and can capture credentials sent by insecure protocols. Detection compares ARP caches and switch forwarding tables with the address assignments recorded by Dynamic Host Configuration Protocol (DHCP) or network access control, and looks for repeated address changes, one MAC claiming many IPv4 addresses, or the same MAC on several switch ports. Legitimate causes include failover and virtual machine moves, so changes are judged by frequency and by ownership.

What you will practise

  • Explain how ARP resolves an IPv4 address to a hardware address on a local segment.
  • Describe how a gratuitous reply or a fast reply poisons another host's ARP cache.
  • Explain how this sub-technique differs from name resolution poisoning and from DHCP spoofing.
  • Identify the switch, ARP cache and address assignment records that expose cache poisoning.
  • List layer two controls that make ARP spoofing difficult on a switched network.
