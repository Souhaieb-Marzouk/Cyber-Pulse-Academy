SCS-C02 AWS Certified Security - Specialty

SCS-C02AWSExtremeCertificationUnofficial Study Resource

AWS Certified Security - Specialty is an advanced, scenario-driven certification that validates a practitioner's ability to design, implement, and operate security controls across AWS workloads, with emphasis on identity, detection, infrastructure protection, data protection, and incident response. It is aimed at security engineers, cloud security architects, and defenders who already hold an associate-level AWS certification or equivalent production experience, and who own security outcomes rather than individual services. For an employer, the credential is evidence that the holder can reason about AWS security end to end: writing and debugging identity-based and resource-based policies, understanding the evaluation order of permission boundaries, service control policies, and session policies, choosing and operating encryption with AWS KMS under a correctly written key policy, protecting data in transit and at rest, and building detective controls with CloudTrail, VPC Flow Logs, GuardDuty, Security Hub, and AWS Config. It also signals competence in response work: isolating compromised resources, preserving evidence, and applying repeatable remediation without breaking production. The exam is delivered as timed multiple-choice and multiple-response questions, and candidates must satisfy an overall scaled passing threshold rather than a per-domain minimum, so a weak area can only be offset by strength elsewhere. Questions are written as short architectures or incident narratives and frequently hinge on a single constraint in the wording, such as a requirement to eliminate long-lived credentials or to minimise operational overhead, so reading the whole stem before choosing an answer matters more than recall of service feature lists. Hands-on practice changes the outcome materially: practitioners who have built cross-account access with roles, trialled KMS key policies that fail closed, queried real CloudTrail data, and remediated a deliberately misconfigured test account are far better prepared than candidates who only read documentation, because the exam rewards knowing how a control behaves when two policies conflict.

Exam domains and objectives

  • Detection: designing and troubleshooting logging and monitoring that surfaces control-plane and data-plane events, including CloudTrail, VPC Flow Logs, and service audit trails, and tuning findings so that real signal is not buried in noise.
  • Incident Response: preparing runbooks and automation for compromised credentials and workloads, containing and isolating affected resources, and preserving evidence in a form that survives later review.
  • Infrastructure Security: segmenting networks with VPC design, security groups, network ACLs, and edge protection, and hardening compute and container platforms against abuse and unauthorised exposure.
  • Identity and Access Management: building least-privilege access with IAM policies, roles, permission boundaries, and federation, and diagnosing precisely why a given request is allowed or denied.
  • Data Protection: selecting and operating encryption in transit and at rest, managing keys, key policies, and rotation in AWS KMS, and applying classification and lifecycle controls to stored data.
  • Security Foundations and Governance: applying account-level guardrails, multi-account structure, configuration baselines, and compliance reporting across an AWS organisation.
  • Automation and Remediation: using event-driven pipelines and infrastructure as code to correct drift and act on findings consistently instead of through manual intervention.
