DET0118 Exploitation of Remote Services – multi-platform lateral movement detection

DET0118Detection StrategyVery hardDetection Strategy

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

This detection looks for an attacker who jumps from one computer to another. The attacker does this by attacking a service that is open to the network. A service is a program that listens for connections, such as file sharing or remote management. The rule joins network and host records to spot the jump.

Why should you care?

Lateral movement is how a small break in becomes a company wide incident. Attackers rarely write new tools for this step. They use a flaw in software that is already running and reachable. Because the traffic is ordinary for that service, you need to compare it with what normal looks like.

How it works, in plain steps

  1. The rule reads network flow records for connections to service ports on many hosts.
  2. It groups them by source address and counts how many different targets one source touched.
  3. It reads authentication records for the same service on those targets.
  4. It marks a target where access failed many times and then succeeded once.
  5. It looks for a new process on the target whose parent is the service that was reached.
  6. A wide fan out plus a child process from a service raises an alert.

Real-world example

Imagine a row of apartment doors with the same lock model. A locksmith with one key tries every door. Opening one door is normal. Trying forty doors from the same person in ten minutes is not. The building log shows each attempt, and only the pattern across all the doors reveals the intent.

Key takeaways

  • Look at fan out across hosts, not at a single connection.
  • The parent process of a new child on the target is the key host clue.
  • Failed access followed by success on a service is a strong signal.

In more detail

This strategy detects exploitation of a remote service used as a lateral movement step across Windows, Linux and appliances. The technique matters because a single vulnerable listening service can hand an attacker code execution on many hosts at once, and the network noise looks like ordinary service traffic. Detection depends on authentication records for the targeted service, application logs from the service itself, network flow data showing short lived connections to one port from one source, and process creation on the target host with an unusual parent. It fails in practice because the vulnerable service is designed to be accessed remotely, so no single event is decisive; the signal comes from the ratio of failed to successful access, the fan out across hosts, and the process that appears on the target after the connection.

What you will practise

  • Describe how remote service exploitation supports lateral movement
  • Select authentication and service log sources for Windows and Linux targets
  • Measure fan out from one source to many hosts as a detection signal
  • Correlate a service process with an unexpected child process on the target
  • Prioritise an alert by the value and exposure of the affected hosts
