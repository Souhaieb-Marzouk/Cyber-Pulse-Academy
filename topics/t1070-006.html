T1070.006 Indicator Removal: Timestomp

T1070.006StealthExtremeTechnique

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

Timestomping means changing the date and time values stored for a file. Every file records when it was made, changed, and opened. An attacker edits those values so their file looks old and harmless.

Why should you care?

Investigators often sort files by time to see what happened first. If the dates are false, that order is wrong. A malicious file can look like it has been on the server for years. You need a second source, such as a central log, before you trust a date on a file.

How it works, in plain steps

  1. A file system records several times for each file, such as creation, modification, and last access times.
  2. An attacker changes those times with a built-in tool or with code inside their own malware.
  3. They often set the new times to match other files in the same folder, so nothing looks out of place.
  4. On Windows one set of times is shown to users, and this set can be changed with normal user rights.
  5. A second set is kept for the kernel, and changing it normally needs stronger methods such as renaming the file.
  6. Attackers also rename the file so its name fits the folder it sits in, which completes the disguise.

Real-world example

Imagine a stranger slips a book onto a library shelf. Before leaving, they rewrite the date stamp inside the cover so it matches all the neighbouring books. The librarian sees an old shelf with old books and never notices the new arrival.

Key takeaways

  • A file timestamp is only a claim and it can be changed by anyone who can write the file.
  • On Windows, comparing the user-visible times with the kernel-held times reveals many changes.
  • Confirm suspicious dates with logs or inventories that were created before the change.

In more detail

Timestomping is the alteration of a file's recorded times so that a hostile file looks older, or at least looks like its neighbours. File systems store several times, typically creation, modification, last access, and a metadata change time, and an attacker can rewrite them with ordinary utilities, a short script, or library calls inside malware, commonly setting a dropped payload to match the dates of signed system binaries in the same folder. On Windows the manipulation targets the Master File Table (MFT), where the standard information attribute holds the times shown to users and applications, while the file name attribute holds a second set that the kernel uses and that is far harder to change; the mismatch between the two is the classic detection, which is why more capable actors perform double timestomping and adjust both. Defenders should treat timestamps as data that can lie and prefer independent sources: file creation and execution events that were already shipped to a central collector, System Monitor (Sysmon) file creation records, backup and shadow copy inventories, USN change journal entries, and package or installer databases. A payload bearing an old date but accompanied by a first-seen execution record, a newness in the endpoint inventory, or a file that appears in a directory whose other members it does not truly match is the pattern to look for, because copy, extraction, and build processes also stamp files with inherited times.
