T1560.003 Archive Collected Data: Archive via Custom Method

T1560.003CollectionExtremeTechnique

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

This is the version of data packing where the attacker writes their own packing code. They do not use a normal archiving program or a ready made library. Instead they build the scramble or squeeze step themselves, often with simple maths on each byte. It differs from the parent technique because nothing standard is used. There is very little for a security tool to recognise.

Why should you care?

Security tools often recognise known archiving programs or known file formats. Custom code has no known fingerprint, so those tools see only a strange file. If the attacker also encrypts the data, the result looks like random noise, which defeats content inspection. This makes custom methods a quiet way to prepare stolen data for transfer. As a defender, you must learn to judge files by behaviour and statistics instead of names.

How it works, in plain steps

  1. The attacker decides to avoid standard tools so that no known signature is present.
  2. They write their own routine that mixes or transforms the bytes of each collected file.
  3. A simple version combines each byte with a repeating secret value using one operation.
  4. Stronger versions implement a small stream cipher that produces very random looking output.
  5. The packed data is written out, often with a misleading or missing file extension.
  6. Defenders notice high randomness, odd sizes, and the process that produced the file.

Real-world example

Think of a student passing notes in class. Anyone can buy a padlock for a notebook, and a teacher may recognise the lock and ask for the key. This student invents a private code instead. Each letter is shifted by a number only two people know. The note looks like nonsense to everyone else. No shop sells the code, so there is nothing to look up or inspect.

Key takeaways

  • Custom packing leaves no tool, no library, and no standard archive header behind.
  • Encrypted or compressed custom output looks random, so entropy checks help.
  • Detect it through file behaviour, odd sizes, extensions, and surrounding activity.

In more detail

Archiving via custom method is the least observable of the three archive sub-techniques, because the attacker implements compression or encryption directly in their own code with no dependency on an external utility or a named library. Typical implementations are simple bitwise transforms such as exclusive OR against a repeating key, a small stream cipher written by hand, or a homemade version of a well documented compression algorithm. The output often carries none of the structural markers an analyst relies on: no standard archive header, no known file signature, no vendor format string, and no compression library imports to match against. Encrypted or well compressed output also looks statistically random, so a file that should contain readable documents fails a basic readability check. From a defender's perspective the artefacts move almost entirely to behaviour and statistics rather than signatures. Useful leads are a file that appears with wrong or missing extension, size relationships that do not match the source set, entropy per byte that is far higher than the format should produce, and the pattern of a process reading many documents and then writing a single opaque blob. Because custom code is unique to a campaign, static signatures are weak, so behavioural rules, entropy thresholds, and correlation with the surrounding collection and exfiltration activity carry the detection.

What you will practise

  • Explain why an adversary might implement compression or encryption instead of using a utility.
  • Describe how simple byte transformations such as exclusive OR hide file contents.
  • Explain why custom encrypted output appears random and how entropy analysis reveals it.
  • Identify the absence of standard file headers and signatures as a detection challenge.
  • Describe how to correlate a custom packed file with the collection activity before it.
  • Summarise when behavioural detection is more useful than signature based detection.
