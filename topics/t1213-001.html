T1213.001 Data from Information Repositories: Confluence

T1213.001CollectionExtremeTechnique

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

Confluence is a shared website where teams write and store documents, much like a company wiki. This sub-technique is the general idea of mining shared documents, narrowed to Confluence. The attacker uses its search box to find secrets and plans. It differs from the parent technique only in which tool is being searched.

Why should you care?

Confluence often sits beside the development team, so it holds a lot of technical detail. People paste test passwords and server names there because it is quick and convenient. Pages are easy to search, so one account can scan years of notes in minutes. If nobody reviews access, this becomes an easy win for an attacker. Old pages are especially risky, because they are rarely cleaned up.

How it works, in plain steps

  1. The parent technique covers shared repositories in general; this one targets the Confluence wiki.
  2. The attacker signs in with a valid account and uses the search box for likely key words.
  3. They browse space lists and read runbooks, design notes and setup guides.
  4. They open old page versions, where removed passwords often still sit in the history.
  5. They export whole spaces, or download attached files, to take the content away.
  6. They may create a personal access token so they can keep reading without a browser session.

Real-world example

Imagine a hospital staff room with a shelf of handover folders. Every nurse has a key, because everyone needs the folders. One folder holds the door code for the drug store, written there years ago for convenience. A new cleaner with a copied key reads that folder during a break. The shelf was well organised and easy to search, which is exactly why finding the secret took only a minute.

Key takeaways

  • A wiki is searchable, so secrets left in pages are found very quickly.
  • Old page versions often keep passwords that were deleted from the current page.
  • Review space permissions, and watch for space exports and token creation.

In more detail

Confluence is a wiki style information repository, so this sub-technique is the parent behaviour narrowed to one product family and its search, space and page model. It is usually deployed beside issue tracking tools in development teams, which means its content skews towards engineering: runbooks, design documents, environment details, source snippets and credentials pasted into pages for convenience. An adversary holding any valid account can use the built in search for words such as password, connection string, diagram or deprecated, then read pages, browse page history, follow links to internal resources and export a space or page tree. Evidence lives in application audit and access logs: search terms, high page read counts, space exports, permission and group changes, personal access token creation, and reads from a client address or session that does not match the account's normal behaviour. Legitimate heavy use concentrates on a few spaces a team owns, while mining looks broad and shallow across many spaces in a short window.

What you will practise

  • Explain how this sub-technique differs from the parent repository technique.
  • Describe how built in search and page history help an adversary find secrets.
  • Identify the audit events, such as exports and token creation, that reveal mining.
  • Explain why deployment beside development teams raises the value of the content.
  • Suggest two access control practices that reduce exposure of wiki content.
