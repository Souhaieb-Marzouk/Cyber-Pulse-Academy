Network Address Translation

Network FundamentalsHardKeyword

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

Network Address Translation is a way for one network device to rewrite the addresses on packets. It does this as the packets pass through. It lets many computers inside an office share a single public internet address. The device keeps a small table that remembers which reply belongs to which computer. You use it every day without noticing.

Why should you care?

There are far more computers in the world than available old-style internet addresses, so sharing is necessary. It also keeps the layout of your private network hidden from the outside. If the translation table is wrong or full, connections silently fail and users blame the network. Attackers can also abuse translation rules that point inward, because those rules open a path to an internal server. Understanding translation helps you read logs correctly, since one public address can stand for many real machines.

How it works, in plain steps

  1. A computer inside the office sends a packet out, using its own private address as the source.
  2. The edge router replaces that private source address with its public address.
  3. It also gives the packet a new source port and writes this pair into its translation table.
  4. The reply from the internet comes back addressed to the public address and that port.
  5. The router looks in the table, finds the matching entry and rewrites the address back.
  6. If no entry matches, the router drops the packet because no inside computer asked for it.

Real-world example

Think of a large office building with one street address. Every letter leaving the building is stamped with that single street address, not the desk number. The mail room keeps a list that says a reply for this name belongs to desk fourteen. When a reply arrives, the mail room reads the list and walks it to the right desk. A visitor cannot walk in and demand a desk. The mail room delivers only replies to letters that went out.

Key takeaways

  • Translation hides internal addresses and lets many devices share one public address.
  • It works because the device keeps a state table linking each outgoing flow to a reply.
  • It is not a security control; treat inward pointing translation rules as exposed services.

In more detail

Network Address Translation is the process of rewriting the source or destination addresses, and often the ports, in IP packet headers as the packet crosses a router or firewall. The common form used at the internet edge, sometimes called port address translation or NAT overload, lets many internal hosts share one public IPv4 address by mapping each flow to a distinct source port and keeping a state table of active translations. Other forms rewrite destination addresses to reach internal servers (destination NAT or port forwarding) or map whole static blocks. It appears on home and office edge routers, in cloud gateways, in container and virtualisation platforms, and in load balancers. Two mistakes recur: treating NAT as a security control when it is an address-conservation and topology-hiding mechanism that offers no authentication, and forgetting that any signature or log based on a raw source address, including internal asset attribution and some geographic blocks, becomes ambiguous once addresses are shared or rewritten. Protocols that embed addresses inside their payload need helper functions, and inbound connections generally require explicit translation rules.

What you will practise

  • Define network address translation and distinguish source, destination and port-based variants.
  • Explain how a translation state table matches outbound flows with inbound replies.
  • Describe situations where shared public addresses complicate logging or attribution.
  • Recognise why destination translation rules deserve special security review.
  • State why network address translation is not itself an authentication or access control mechanism.
