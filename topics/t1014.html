T1014 Rootkit

T1014StealthExtremeTechnique

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

A rootkit is software that hides other harmful software from the computer's own tools. It changes the answers those tools give, so harmful files and programs seem not to exist. Some rootkits work deep inside the system, where they are very hard to find. Their main job is to stay unseen.

Why should you care?

If the computer lies to you, your checks will pass while the attacker is still there. Antivirus scans, task lists and file searches may all return clean results. Cleaning the machine may not remove code that starts before the operating system does. This is why a suspected rootkit often means rebuilding the computer from scratch.

How it works, in plain steps

  1. The harmful code gets a foothold on the machine, often with high level permission.
  2. It installs a driver, kernel module or low level component that runs with deep access.
  3. That component watches the system calls used to list files, processes and connections.
  4. When a listing is requested, it removes or alters entries linked to the attacker.
  5. It may also block or change data returned to security tools that inspect the system.
  6. On reboot, boot level versions load very early, before normal protection starts.

Real-world example

Imagine a hotel where the night manager writes out the guest list. A thief bribes that manager to leave their name off every printed copy. The police, the auditor and the morning shift all read the list and see nothing wrong. The thief is in room twelve the whole time. A rootkit is that dishonest manager inside your computer, quietly editing every report before you read it.

Key takeaways

  • A rootkit attacks your ability to see, so a clean scan result proves very little.
  • Boot and firmware level hiding survives normal clean up, so rebuilding is often the only cure.
  • Verify with a source outside the running system, such as an offline scan or a second device.

In more detail

A rootkit is software whose main purpose is concealment: it intercepts or modifies the operating system calls that report system state, so tools asking about files, processes, services, drivers, network connections or registry keys receive a filtered answer. The hiding logic can live in user space through library or application programming interface hooks, in kernel space through drivers or kernel modules, in a hypervisor beneath the operating system, or in system firmware and boot code. Kernel and firmware variants are hardest to remove because they load before, or below, the tools meant to find them, and a variant that targets the boot sector is usually called a bootkit. Detection is therefore indirect: defenders look for driver or module loads without a reputable signature, mismatches between independent sources such as a raw disk view and the normal file listing, differences between captured network traffic and what local connection tools report, and integrity data gathered from outside the running system, such as trusted boot records, an offline disk scan or memory analysis.

What you will practise

  • Define a rootkit and explain how it differs from ordinary malicious software.
  • Describe the levels at which rootkit code can operate, from user space to firmware.
  • Explain why kernel and boot level hiding is so difficult to remove.
  • Identify indirect detection methods such as cross checking independent data sources.
  • Recognise the limits of on host scanning tools against a suspected rootkit.
