T1539 Steal Web Session Cookie

T1539Credential AccessExtremeTechnique

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

A session cookie is a small piece of data your browser keeps after you log in. It proves who you are to the website. This technique is an attacker stealing that cookie and using it to act as you.

Why should you care?

The cookie works without your password, so changing the password may not stop the attacker. It can bypass some extra sign in checks, because those checks already happened. A stolen cookie lets an attacker read your mail, files and admin pages. Browsers keep cookies for a long time, so the risk lasts.

How it works, in plain steps

  1. You sign in to a website. The site gives your browser a cookie. This is a short code that proves you already logged in.
  2. Malware on your computer copies cookies from the browser files on disk or from its memory while it runs.
  3. A fake login page can pass your details to the real site and keep the cookie it receives in return.
  4. Someone can also inject a script into a web page, so your own browser sends the cookie to the attacker.
  5. The attacker loads the stolen cookie into their own browser or tool and refreshes the page.
  6. The website sees a valid session and lets them in. Logging you out is often the only way to cut them off.

Real-world example

Think of a hotel wristband instead of a room key. Once you check in, the band opens your room, the pool and the gym. If someone copies the band code, they walk straight in, and the front desk never asks for a name or a passport again until the band is cancelled.

Key takeaways

  • A session cookie is a password substitute, so protect the device that holds it.
  • Sign out or end sessions immediately when you suspect theft, because changing a password alone may not help.
  • Watch for one session being used from two very different places or devices at the same time.

In more detail

Steal Web Session Cookie targets the bearer token that web services issue after a successful login. Once a browser or an application holds a valid session cookie, the server treats any request carrying it as already authenticated, so possession of the cookie is enough to act as that user without a password and often without a second factor, which is checked only at the moment of login. Cookies can be taken from several places: browser profile storage and its local database, process memory while the user is signed in, application memory for desktop clients that authenticate to cloud services, network traffic where transport protection is missing, and injected scripts running in the page, including code the victim is persuaded to run themselves. Proxy based phishing kits make the theft systematic by relaying a real login page so the victim solves the multi factor prompt while the attacker captures the resulting cookie. Artefacts depend on the route: file and memory reads of browser data by an unusual process, suspicious browser extensions, script or network activity toward a first party endpoint from an unexpected origin, and, most usefully, session reuse from a different address, device or client while the original session stays active. Cookies are long lived, so the same token may be replayed well after the theft.

What you will practise

  • Explain what a session cookie is and why it works as an authentication token.
  • Describe the main places attackers obtain cookies, including browser storage, memory and network traffic.
  • Explain how a proxy based phishing page captures a cookie while the victim completes a login.
  • Identify the sign in logs and session records that reveal cookie reuse from a new device or location.
  • Describe why ending the session, not only resetting the password, is needed after cookie theft.
