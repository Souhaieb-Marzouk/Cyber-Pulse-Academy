T1021 Remote Services

T1021Lateral MovementExtremeTechnique

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

Remote services is when an intruder uses normal remote access tools to log on to another computer, instead of breaking in with a software flaw. They rely on accounts and trust that already exist. Examples include remote desktop, remote shells and shared file access. To the target machine, the session simply looks like a valid login.

Why should you care?

This is how an intruder spreads from one machine to many. Because the login is real, it does not trigger the alarms that a broken software flaw would. Whole networks can be crossed with stolen credentials and built-in tools. If you do not watch who connects to which machine, you may only notice when the damage is done.

How it works, in plain steps

  1. The intruder already has a working account or key, usually taken from an earlier step.
  2. They open a remote session to another computer, using tools the company already trusts.
  3. Common choices are a remote desktop session, a remote shell or a shared folder.
  4. The destination records a normal login from an internal address, so nothing looks broken.
  5. From that new machine they repeat the whole process, hopping further inside the network.
  6. Investigators rebuild the path by pairing who logged in, from where, and when.

Real-world example

Think of a large hotel. A guest finds a lost staff key card in the lobby. That card opens staff corridors, linen rooms and the manager's office. The doors open normally, the lights behave and no lock is broken. Security only notices later, when the key card appears in rooms the guest never booked.

Key takeaways

  • Stolen credentials plus built-in remote tools let an intruder cross a network quietly.
  • Build a baseline of which machines normally connect to which, and from where.
  • An internal login from a workstation to a server it never touches is worth checking.

In more detail

Remote services is the use of legitimate remote access protocols and their native authentication to log on to another host and act there, rather than exploiting a vulnerability to gain a foothold. The technique exploits trust that already exists: domain credentials, SSH keys, administrative shares or a management plane that accepts connections from an internal network segment. Common carriers include Remote Desktop Protocol, Server Message Block and administrative shares, SSH, Windows Remote Management, and virtual network computing, with the same pattern appearing against cloud instances through their management interfaces. Mechanism level distinctions matter for detection. Interactive desktop protocols create session records and generate logon events with a network logon type on the destination. File sharing protocols leave share access records and service creation artefacts when tooling is copied and executed. Remote shell protocols produce authentication records, session start and end entries, and process trees whose parent is a remote service rather than a local shell. The consistent thread is that the destination sees an inbound authenticated session from an internal address that is not part of its normal peer set. Investigators reconstruct the movement path from source and destination pairs: which account authenticated, from which workstation, at what time, using which protocol, and whether that pair appears anywhere in historical baselines. Jump hosts, patch management, configuration management agents, helpdesk remote support, backup software and monitoring systems all legitimately connect to many hosts, so volume alone proves nothing. Discrimination comes from the account used, the protocol chosen relative to the destination role, the presence of default administrative share access or new service registration, off hours timing, whether the source is itself a workstation rather than a hardened management host, and whether discovery or credential access activity immediately precedes the connection. Sequence and context convert a common administrative event into evidence of lateral movement.

What you will practise

  • Explain how remote desktop, file sharing, SSH and remote management protocols differ in the logon and session artefacts they create.
  • Identify the authentication, service creation and session records that let investigators reconstruct a lateral movement path.
  • Build baselines of legitimate source to destination pairs for jump hosts, patch management and helpdesk tooling.
  • Recognise default administrative share access and new remote service registration as higher confidence indicators than connection volume alone.
  • Rank candidate lateral movement alerts by destination role, account privilege and proximity to discovery or credential access activity.
  • Select containment actions that terminate remote sessions while preserving destination side evidence.
