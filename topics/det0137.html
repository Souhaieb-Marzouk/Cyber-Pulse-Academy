DET0137 Detection Strategy for Disk Wipe via Direct Disk Access and Destructive Commands

DET0137Detection StrategyVery hardDetection Strategy

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

A disk wipe destroys the information on a hard drive. It removes the file system, so the computer can no longer start. Some tools wipe a disk on purpose, and attackers use them to destroy evidence or to damage a company. This detection looks for programs that touch the raw disk or run destructive commands.

Why should you care?

A wipe can destroy years of records in a few minutes. Backups are the only way back, and attackers often go after the backups first. Staff cannot work while machines are rebuilt. The damage is often worse than a theft, because the data is simply gone. This detection aims to give you minutes instead of days to stop the process.

How it works, in plain steps

  1. Process records show the command that ran and the arguments it used.
  2. The rule lists the commands that format, clean, or overwrite a disk or volume.
  3. Endpoint records show a program opening the raw disk device directly.
  4. The rule checks whether that program is an approved storage or backup tool.
  5. System records show volume errors or an unexpected disk removal soon after.
  6. An analyst then confirms whether a change ticket explains the activity.

Real-world example

Picture a records office with years of paper files. The manager authorises one clerk to shred old documents each Friday. That clerk holds the key to the shredder room. Now imagine a stranger takes the key and shreds every shelf in the building within ten minutes. Nothing was stolen and nothing was copied. The archive is simply empty. A disk wipe is that shredding run. The tools are normal, but the scale and the timing are not.

Key takeaways

  • The tools used in a wipe are ordinary, so context and scale decide the alert.
  • Raw disk access by a program that is not a storage tool is rare and serious.
  • Backups must be isolated, because a wipe often targets them first.

In more detail

Disk wipe (T1561) covers destructive actions that overwrite partition tables, volume structures, or raw disk sectors so that data becomes unrecoverable and systems no longer start. This detection strategy watches two very different shapes of the same impact: command line destruction through built-in disk, partition, and backup utilities, and direct raw device access from a process that is not a storage driver, a backup agent, or an approved imaging tool. The telemetry that makes it possible is process creation with command lines, endpoint records for raw disk handle requests and driver load events, and system level storage errors such as unexpected volume dismounts that follow within seconds. It fails because the same utilities are used for genuine maintenance, because raw device access is invisible without endpoint instrumentation, and because destruction finishes so quickly that an alert raised afterwards is recovery reporting rather than prevention.

What you will practise

  • Describe what a disk wipe destroys and why it is treated as an impact technique.
  • Recognise process creation patterns for built-in destructive disk utilities.
  • Identify raw disk or raw device access that no approved tool explains.
  • Correlate storage errors and volume dismounts with a preceding destructive command.
  • Explain why backup isolation changes the outcome of a destructive incident.
