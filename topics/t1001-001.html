T1001.001 Data Obfuscation: Junk Data

T1001.001Command and ControlExtremeTechnique

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

Junk data means adding random or useless characters to network messages. The real command is still inside each message. Those extra characters make the message harder to read or to match against known patterns. This is one specific way of hiding traffic. It differs from the parent by changing the message content instead of the protocol.

Why should you care?

Security tools often compare traffic against known patterns, which are called signatures. Junk data changes the message every time, so those signatures fail to match. This lets an attacker keep control of a computer while the traffic looks normal. If you rely only on signatures, you will miss these sessions. You need to look at traffic size and behaviour instead.

How it works, in plain steps

  1. The attacker picks a protocol the network already allows, such as a web request.
  2. Each command is wrapped with extra random characters before it is sent out.
  3. The junk may come before the command, after it, or between its letters.
  4. The receiving program knows the rule and removes the junk to read the command.
  5. Tools that expect a clean format see broken or meaningless content and often skip it.
  6. Analysts notice the session because payload sizes do not match normal use.

Real-world example

Think of a shared flat where notes are left on the fridge door. To hide a message, one flatmate writes a long shopping list. The real note sits in the middle of that list. Anyone glancing at the fridge sees only a normal list. The person who knows the rule reads only the third word of each line. The list looks ordinary and nobody questions it. Only the person who knows where to look understands the meaning.

Key takeaways

  • Junk data changes the message without changing the protocol being used.
  • Signature matching fails when the payload is different every single time.
  • Payload size, timing and shape are often the best available clues.

In more detail

Junk Data is the simplest form of data obfuscation: the adversary keeps a normal-looking protocol conversation but pads it with random or meaningless bytes. Junk may be prepended, appended, or interleaved between the meaningful characters, so a parser that expects a clean structure either fails or returns garbage. Because the wrapper protocol is unchanged, the traffic still passes firewalls and still resembles the protocol it mimics at connection level. Defenders notice sessions whose payload sizes are larger than the protocol needs, whose entropy sits where it should not, or whose content only decodes after the implant strips the padding. Comparing payload length and shape against expected protocol behaviour is usually more productive than reading the content.
