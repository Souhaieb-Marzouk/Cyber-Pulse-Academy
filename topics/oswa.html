OSWA OffSec OSWA

OSWAOffSecExtremeCertificationUnofficial Study Resource

The OffSec Web Assessor (OSWA) is an advanced, fully hands-on web application security certification built around OffSec's Advanced Web Attacks and Exploitation course, and it is aimed at experienced penetration testers, application security engineers and bug bounty hunters rather than newcomers. Candidates are expected to arrive already fluent in HTTP, browser security models and at least one server-side language, because the credential is designed to prove something narrower and deeper than generalist testing: that the holder can read application code, trace a user-controlled input to a dangerous sink, work around filtering, and turn a suspected flaw into a demonstrated proof of exploitation. For an employer, a pass is meaningful evidence that the candidate can assess modern, custom-built applications rather than only run a scanner and report its output, and that they can distinguish a genuinely exploitable finding from a theoretical one. The exam is practical and proctored, presenting a set of intentionally vulnerable target applications within a fixed time window, after which the candidate submits a professional report containing reproduction steps, impact analysis and remediation guidance for each verified issue. The targets are deliberately hardened and non-standard, so payloads that work unchanged in a training lab frequently fail; the candidate has to reason from the source code, understand the filter or parser behaviour, and adapt. What separates successful candidates from the rest is method rather than memorised payload lists: systematic mapping of the application, close review of authentication and authorisation logic, disciplined note-taking, and repeated practice writing findings that a development team could actually act on.

Exam domains and objectives

  • Web Assessment Methodology: scoping an application, mapping its attack surface and building a repeatable testing plan before attempting exploitation.
  • Source Code Review: reading server-side and client-side code to locate dangerous sinks, weak trust boundaries and logic flaws that black-box testing misses.
  • SQL Injection: identifying error-based, blind and second-order injection in custom application code, including reasoning about the filters intended to block it.
  • Cross-Site Scripting: finding stored, reflected and DOM-based execution contexts and explaining how output encoding and content security policy limit impact.
  • File Upload and Web Shell Risk: assessing upload functionality for type, extension and content filtering weaknesses and describing the post-exploitation risk they create.
  • OS Command and Argument Injection: tracing user input into process execution calls and evaluating the allow-lists and sanitisation intended to prevent it.
  • Server-Side Template Injection: recognising template engines that evaluate user input and assessing what functionality remains reachable when they do.
  • XML External Entity Injection: analysing XML parsers for external and parameter entity processing and the file and network reachability that follows.
  • Server-Side Request Forgery: testing URL and resource parameters for internal reachability, and treating network segmentation and metadata protections as the real boundary.
  • Insecure Deserialization: recognising serialized object formats in requests and cookies and assessing which gadget chains exist in the target technology stack.
  • Exploit Adaptation and Filter Bypass: adjusting known techniques for hardened, non-standard targets where off-the-shelf payloads fail to execute.
  • Reporting Web Findings: writing reproducible, evidence-backed findings with clear business impact and specific remediation guidance.
