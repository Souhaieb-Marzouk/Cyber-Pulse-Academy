G0139 TeamTNT

G0139Enterprise GroupExtremeThreat Group

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

TeamTNT is a name used by security researchers for a group that attacks cloud computers. These attackers look for servers and containers that are open to the internet by mistake. A container is a small, packaged piece of software that runs on a shared computer. The group usually steals computer power to make cryptocurrency, which is digital money.

Why should you care?

Many companies put servers online with weak or default passwords, and TeamTNT looks for exactly that. If the group enters, your cloud bill can grow very fast because your machines now mine digital money for someone else. The same access can also steal cloud keys, and those keys may open many other systems. The attackers often delete other intruders and turn off security tools, so they can stay for a long time.

How it works, in plain steps

  1. The attackers scan the whole internet for open cloud services, looking for ones that answer without a password.
  2. They log in with default or weak credentials, or reuse a leaked cloud access key, and take control of the machine.
  3. They run a mining program that uses your processor and electricity to earn digital money for the group.
  4. They read cloud metadata, which is a built-in service that can hold temporary keys, and use it to reach more accounts.
  5. They remove other miners and disable monitoring tools, so fewer alerts appear and the machine stays busy.
  6. They copy their scripts to other reachable machines, repeating the same steps across the whole cloud account.

Real-world example

Picture a hotel where every room door has the same code, and the code is printed on the key box in the lobby. Guests are honest, so nothing goes wrong for months. Then a stranger walks in, reads the code, and starts using empty rooms. They sleep there, cook there, and quietly charge the hotel for everything. Even worse, they find the master key cabinet, which opens every hotel in the city. TeamTNT behaves like that stranger. It does not break the door. It simply finds the door that was left unlocked and labeled, then helps itself to whatever is inside.

Key takeaways

  • An internet-facing service with a default or weak password is an open door for cloud attackers.
  • A sudden rise in cloud processor use or cost is a real warning sign that needs investigation.
  • Keep cloud access keys out of documents and code, and give each key as few rights as possible.

In more detail

TeamTNT is a cloud-focused intrusion set that became widely known for attacking internet-facing container and orchestration services, especially Docker and Kubernetes endpoints left reachable with weak or default credentials. The group's workflow starts with automated scanning for exposed management ports and readable cloud metadata, then moves to credential theft aimed at other cloud accounts, deployment of cryptomining payloads, and attempts to remove competing miners and weaken host defenses. In real environments its presence shows up as unexpected compute cost, consumer-grade mining binaries on servers, new privileged containers, modified container engine configuration, and unusual outbound connections to mining pools or credential-harvesting endpoints. A frequent misunderstanding is that the attack requires a software vulnerability: in most publicly documented cases the entry point was simply an exposed, unauthenticated interface or a leaked access key, so the effective fixes are network placement, authentication, and key hygiene rather than patching alone. Public reporting attributes the cluster with moderate confidence, and the name refers to a set of observed behaviors rather than to a confirmed organization.

What you will practise

  • Explain how exposed container and orchestration services allow an attacker to reach a cloud instance without exploiting a software memory bug.
  • Describe the cloud metadata service and why readable metadata turns a single host compromise into an account-wide problem.
  • Identify the evidence a cryptomining intrusion leaves in cloud billing, host process lists, and container engine configuration.
  • Outline the containment order for cloud coin mining: isolate the workload, rotate every reachable key, and rebuild rather than clean.
  • Summarise how public reporting attributes TeamTNT activity and where that attribution carries only moderate confidence.
