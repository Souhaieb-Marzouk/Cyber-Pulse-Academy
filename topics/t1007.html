T1007 System Service Discovery

T1007DiscoveryExtremeTechnique

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

System service discovery means listing the background programs and scheduled jobs that are set up on a computer. Services are programs that run without a person watching them. Scheduled tasks are jobs the computer runs at set times. The attacker wants a map of what this machine does and who protects it.

Why should you care?

Services show how a computer is used and what guards it. If an attacker knows which security service is running, they know what to switch off. Scheduled tasks often run with high permissions, so they are useful later. Reading this list is quiet, because the computer already has the commands needed to print it.

How it works, in plain steps

  1. The attacker opens a command shell on the computer, using an account they already control.
  2. They run a built-in command that asks the system for its list of services.
  3. They repeat this with other commands that show task lists or scheduled jobs.
  4. They compare the results to find security tools, backup agents and update services.
  5. They note which services run as a powerful system account rather than a normal user.
  6. They use the map to choose what to stop, change or abuse next.

Real-world example

Think of a hospital at night. A stranger walks up to the reception desk and asks for a list of every ward, every nurse on duty, and every doctor asleep upstairs. Nobody stops them, because asking is not forbidden. With that list they know which ward has no guard and which cupboard opens with a master key. System service discovery is that list. It breaks nothing by itself, but it shows the visitor exactly where the weak spots are.

Key takeaways

  • Listing services is normal work for many tools, so look at who asked and what happened next.
  • Service lists tell an attacker where your security software lives and how to switch it off.
  • Alert on bursts of discovery commands from one account in a short period.

In more detail

System service discovery is the enumeration of the services and scheduled tasks already registered on a host, used to understand what the machine does and where it can be pushed next. On Windows this usually appears as sc query, tasklist with the service option, net start or schtasks; on Linux and macOS the equivalents include systemctl with a service filter and crontab listings. An adversary gathers the same facts to find security agents that must be disabled, backup and update services that can be abused, and scheduled jobs that run with more privilege than the account they hold. The behaviour is visible in process creation records such as Windows Security event 4688 and Sysmon event 1, where the command line and the parent process carry most of the meaning. Inventory agents, configuration management tools and administrators run identical commands, so defenders weigh context instead: the account used, the role of the host, the volume of discovery inside a short window, and whether the results lead straight into a change such as a service stopped or a task created.

What you will practise

  • Separate routine inventory or administration from suspicious discovery activity.
  • Suggest logging and alerting that would reveal repeated discovery on a host.
