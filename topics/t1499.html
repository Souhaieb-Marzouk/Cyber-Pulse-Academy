T1499 Endpoint Denial of Service

T1499ImpactExtremeTechnique

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

An endpoint denial of service attack makes a service unavailable. It works by using up the resources on the computer that runs the service. The attacker may send fewer packets than a network flood. Each request is designed to cost the server more work than usual.

Why should you care?

This attack can succeed through a single machine, so it does not need a large criminal network. The network may look calm while the service is failing, which confuses people who only watch traffic graphs. Different services have different weak points, so one defence rule rarely covers all of them. Fast detection keeps a small problem from becoming a long outage.

How it works, in plain steps

  1. The attacker picks a service and learns which resource it depends on most.
  2. Requests are shaped to consume that resource, such as connections or memory.
  3. Some attacks target the operating system, for example by leaving connections unfinished.
  4. Others target the service program, such as a web server or name server.
  5. Others target expensive features that sit deep inside the application software itself.
  6. Resource use climbs, queues grow, and legitimate users see errors or timeouts.

Real-world example

Imagine a post office with one clerk and one trolley for parcels. A visitor brings a trolley load that must be checked item by item. The clerk works for an hour on that one customer. The queue outside is short and the street is quiet. Yet nobody else is served. Endpoint denial of service fills the clerk's time in the same way.

Key takeaways

  • This technique exhausts host resources, not the network path.
  • A single attacking machine can be enough to cause an outage.
  • Resource graphs, not just traffic graphs, reveal what is happening.

In more detail

Endpoint denial of service attacks the host and the software stack on it rather than the path to the host. Traffic may be modest in volume, but it is shaped to consume a resource the service cannot do without: connection state tables, worker threads, memory pools, name resolution caches, or processor cycles spent on expensive operations. The technique divides by the layer that bottlenecks first. Operating system exhaustion targets kernel managed limits such as half open connection tables and state lookup costs. Service exhaustion targets the daemon itself, for example a web server or name server, and exploits features of that protocol or implementation. Application exhaustion targets expensive functions inside the application, where a single crafted or simply repeated request can tie up far more resources than it costs to send. Spoofing and botnets apply here as well, mainly to hide origin and to raise request rates. Detection is best anchored in resource telemetry: abrupt climbs in connection counts, memory or processor use that do not match transaction volume, growing request queues, thread pool saturation, timeouts, and service restarts or crash dumps. Unlike a flood, an endpoint attack can be produced by a single host, so defenders should not require distributed sources before acting, and should be able to identify which layer is saturated in order to choose the right mitigation. Traffic manipulation in the network path has also been used to make legitimate clients generate requests toward a target, meaning the sending population can look entirely genuine.

What you will practise

  • Define endpoint denial of service and contrast it with network flooding.
  • Describe the operating system, service and application layers it targets.
  • Explain why low traffic volume can still produce a full outage.
  • Identify resource telemetry that reveals exhaustion on a host.
  • Explain how spoofing and botnets are used alongside endpoint attacks.
  • Describe how traffic manipulation can make genuine clients send the load.
