M1022 Restrict File and Directory Permissions

M1022Enterprise MitigationVery hardMitigation

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

File and directory permissions decide who may read, change, or run each file on a computer. Restricting them means removing access that people and programs do not need. The operating system then blocks the action, even if someone tries.

Why should you care?

If everyone can write to a program folder, an attacker can replace a program with their own version. If a service account can reach data far beyond its job, one stolen service password exposes everything. Poor permissions also let a normal user delete logs or change important files. Setting them properly means fewer ways for an attacker to gain a foothold and stay hidden.

How it works, in plain steps

  1. List the folders that matter most, such as system directories, log stores, and shared data.
  2. Give each group only the level it needs, such as read for most users and change for few.
  3. Check both the share setting and the folder setting, because the strictest rule wins.
  4. Review ownership after migrations, since files often keep the rights of the person who moved them.
  5. Audit access to sensitive folders and alert when a normal account changes them.
  6. Recheck the permissions on a schedule, because temporary exceptions quietly become permanent.

Real-world example

Picture an office kitchen with a shared fridge. Everyone may take food from the shelves. Only the person who owns each container should open it. The supply cupboard is different. Only two managers hold that key, because the contents are used by everyone. If the cupboard used the same open rule as the fridge, any visitor could help themselves or spoil the stock. File and directory permissions are those two sets of rules for your computers.

Key takeaways

  • The strictest of the share and folder rules is the one that actually applies.
  • Ordinary users should not be able to write into program or system folders.
  • Temporary permission changes must have an owner and an end date.

In more detail

Restrict File and Directory Permissions is the enforcement of access control at the file system layer, so that the operating system itself refuses an action that policy forbids. The mechanism rests on the distinction between a share permission and a file system permission, and on the fact that the effective right is the most restrictive combination of the two. It also relies on inheritance, ownership, and the token of the process doing the work, which is why a service running as a highly privileged account quietly inherits far more access than its purpose requires. In real environments the work looks like removing write access for ordinary users from program and system directories, tightening temporary and spool folders that every process can reach, replacing broad group membership with specific groups, auditing the shares that grew for one project and never closed, and correcting the ownership of files after a migration. Evidence appears in permission change events, access audit logs, share enumeration, and the discovery, usually during an incident, that a low privileged account could write into a directory that a scheduled task executes from. The common misunderstandings are that a hidden share is protected, and that restrictive permissions on the share are enough. Hidden names are not authorisation, and a share that grants read while the underlying folder grants change still allows modification through another path. A second misunderstanding is that inherited permissions are safe because they were set by default; default permissions on temporary and web directories are frequently the exact thing attackers abuse.

What you will practise

  • Explain how share permissions and file system permissions combine in practice.
  • Identify directories where write access for ordinary users creates serious risk.
  • Describe how inheritance and ownership complicate permission reviews.
  • Explain how to audit access to sensitive files and detect unauthorised changes.
  • Plan a permission review that survives staff changes and migrations.
