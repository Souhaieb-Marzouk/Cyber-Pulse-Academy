DET0552 Detection of Windows Service Creation or Modification

DET0552Detection StrategyVery hardDetection Strategy

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

A Windows service is a program that runs in the background, often with high rights, and can start by itself at boot. This detection looks for new services being added or existing services being pointed at a different program. Attackers do this to keep a foothold on a machine.

Why should you care?

A service survives a reboot, which means the attacker does not need to break in again. Services often run as the system account, so a service gives away the highest rights on the host. Noticing the change early is much cheaper than rebuilding the machine later.

How it works, in plain steps

  1. Windows writes an event when a program registers a new service, and the system log records the same registration.
  2. Sysmon, a monitoring tool that records detailed system activity, also logs writes to the services registry key.
  3. A SIEM, which is a central system that collects and searches log events, gathers these events from every host.
  4. The rule checks the service binary path and flags programs running from temporary or user writable folders.
  5. It also checks the account the service will use, and the process that performed the registration.
  6. Stored patterns are compared with a baseline of approved services, and anything outside that baseline is sent for review.

Real-world example

Think of a building where cleaners are given master keys. Adding a new name to the cleaner list is a quiet act, but it means that person can enter every room forever. This detection is the guard checking the cleaner list against the people the building manager actually hired.

Key takeaways

  • A service is valuable to an attacker mostly because it survives reboots and runs with high rights.
  • The interesting detail is the binary path, the service account and the parent process, not the fact that a service was created.
  • Turn on the service creation audit policy, or you will only see the registry half of this technique.

In more detail

This strategy covers Create or Modify System Process: Windows Service, the abuse of the Windows service control manager to install a persistent or privileged process. It matters because a service runs with high privilege and starts automatically, so the technique gives an attacker both persistence and often system level rights. The telemetry that catches it is Windows Security event 4697 for service installation, the system log entry written when a new service is registered, Sysmon event 13 registry value set against the services registry key, Sysmon event 1 for the service control tool, and the later process creation of the installed binary. The main failure mode is that legitimate software deploys services constantly, so the useful signal is not the creation itself but the binary path, the account it runs as, the signer and the parent process that registered it, and many organisations do not enable the audit policy that produces 4697 at all.

What you will practise

  • Explain why Windows services are used for persistence and privilege retention.
  • Identify the events that record service installation and service configuration changes.
  • Evaluate a new service by its binary path, signer, start type, service account and parent process.
  • Build a baseline of approved services per host role and alert on deviations.
  • Detect modification of an existing service rather than creation of a new one.
  • Describe the containment steps for a suspicious service, including recovery of the binary for analysis.
