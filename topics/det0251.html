DET0251 Behavioral Detection of Cloud Group Enumeration via API and CLI Access

DET0251Detection StrategyVery hardDetection Strategy

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

This detection looks for someone listing cloud groups and their members. Groups are collections of accounts that share permissions, like a team with a shared key. An attacker reads these lists to find who can do the most. The rule watches which account asks for the lists, with which tool, and how often.

Why should you care?

Mapping permissions is the cheap first step before an attack on an account. It needs only read access, which is common and rarely reviewed. Nothing in the environment changes, so there is no fault to notice. Catching the sweep gives you time to protect the powerful accounts before they are used.

How it works, in plain steps

  1. An account calls the cloud interface to list groups, roles or their members.
  2. The provider writes an audit record with the caller, the action, the address and the tool name.
  3. The rule counts these calls per account over a short window.
  4. It compares the count with the normal level for that account and its tool.
  5. It also checks whether the tool is a command line client rather than the normal web console.
  6. A sudden sweep of membership listings by a quiet account raises an alert.

Real-world example

Think of a thief who wants to rob an office. They read the staff notice board first. That board shows who holds the master key and who works late. Reading it breaks nothing. But if the cleaners report a stranger photographing the board at midnight, the guards know a plan is forming.

Key takeaways

  • Enumeration leaves no damage, so volume and tool choice are the signals.
  • Command line clients are unusual for accounts that normally use the web console.
  • Baseline which service accounts list groups, because automation does it constantly.

In more detail

This strategy detects enumeration of cloud groups, roles and their memberships through provider interfaces and command line tools, the discovery step an adversary takes to learn which identities hold power before choosing a target. The technique matters because group and role listing needs only read permissions that most accounts already hold, produces no change to the environment, and tells the attacker exactly where to aim next. Detection depends on cloud control plane audit records that carry the caller identity, the operation name and user agent, joined with the enterprise directory audit trail, and scored against the caller's normal enumeration volume. The main way it fails is that directories are full of legitimate automation that lists groups constantly, so the rule must key on the user agent of interactive tools and on volume per identity rather than on the operations alone.

What you will practise

  • Describe why group and role enumeration matters before an attack.
  • Identify the cloud audit fields that record the caller, operation and user agent.
  • Explain how to build a per identity baseline of enumeration volume.
  • Separate command line tool usage from normal console browsing.
  • Correlate cloud directory listing activity with the enterprise directory audit trail.
  • Recognise automation that legitimately lists groups and roles.
