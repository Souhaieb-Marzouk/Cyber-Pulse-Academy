DET0223 Detection of Adversary Abuse of Software Deployment Tools

DET0223Detection StrategyVery hardDetection Strategy

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

This detection watches the tools that push software to many computers at once. These tools can run commands as an administrator. An attacker who reaches one of them can act on thousands of machines. The rule looks for jobs that nobody planned or approved.

Why should you care?

One deployment server often controls every computer in the company. Its rights are very high. It is also part of daily work, so its activity rarely looks wrong. Attackers use it because it saves them effort and hides their actions inside normal traffic. Watching job creation is the only practical way to see the abuse.

How it works, in plain steps

  1. The deployment platform writes an audit record when an administrator creates a job or a package.
  2. That record names the account, the target group, the command, and the time of the job.
  3. The rule compares the account with the list of people and services allowed to deploy.
  4. It checks the command for interpreters, remote access tools, or scripts that are not part of a signed package.
  5. It joins the job record with endpoint execution logs to confirm the command really ran.
  6. A job from an unusual account, or a job that runs a shell command, raises the alert.

Real-world example

Think of a building master key that is kept in the manager's office. Staff use it every day for real work. The log then shows the key used at three in the morning. Somebody who does not work there used it, so you have a question to ask.

Key takeaways

  • Deployment tools run commands with high rights across many hosts.
  • The job audit log names the account, the target, and the command.
  • Compare every deployment job with the change record that approved it.

In more detail

This strategy covers T1072, Software Deployment Tools, where an actor abuses the same management platforms that administrators use to push software, so their commands execute with high privilege across many hosts at once. Detection is built on the deployment server's own audit records, joined with endpoint execution telemetry: job creation, operator account, target collection, and the command that actually ran. The hard part is that these platforms exist to run arbitrary commands, so only the ownership of the account, the timing against the change window, and the content of the command separate abuse from routine operations.

What you will practise

  • Explain why software deployment tools are valuable to an attacker.
  • Identify the audit records a deployment platform produces for job creation and execution.
  • Build a list of accounts and services that are authorised to deploy software.
  • Correlate a deployment job with endpoint process execution to confirm the action took place.
  • Describe how to link deployment activity to change management records.
