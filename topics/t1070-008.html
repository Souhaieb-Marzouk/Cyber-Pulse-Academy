T1070.008 Indicator Removal: Clear Mailbox Data

T1070.008StealthExtremeTechnique

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

This technique means changing or deleting email data to hide an intrusion. It can be individual messages, whole mailboxes, or the records that prove an export happened. The attacker wants to remove proof of their mail activity.

Why should you care?

Email is often how an attack starts, for example with a fake message to an employee. It is also a common way to steal data. If the messages and the mail logs are gone, it becomes very hard to prove what was sent or taken. This slows down both the investigation and any report you must write.

How it works, in plain steps

  1. An attacker gets access to a mailbox or to the mail server itself.
  2. They read or export mail using normal administrator tools, which the server records as requests.
  3. To hide the export they remove the export request from the server's request list.
  4. They delete messages, including the deleted items folder, so the mailbox looks tidy.
  5. On some systems they delete mail with a command line mail client or a local scripting interface.
  6. They may also add a mail rule that quietly drops security alerts or suspicious messages for everyone.

Real-world example

Picture a hospital night desk. A worker reads a patient file and takes notes from it. Before the morning shift, they shred the notes and also remove their entry from the sign-out sheet. The filing cabinet looks untouched, but the security camera at the desk still recorded the visit.

Key takeaways

  • Mail cleanup is not a small tidy up, because email is often the way in.
  • Server side records such as audit logs and message tracking survive mailbox deletions.
  • Mail rules that delete or hide messages for many users deserve a close look.

In more detail

Clearing mailbox data covers the deletion or rewriting of email and mail application records that would otherwise prove how an intrusion began and what was taken. Once an account or an on-premises mail server is under attacker control, the same interfaces that administrators use for compliance and migration work become cleanup tools: mailbox export requests can be removed after the data has been pulled, messages can be deleted through command line mail clients on Linux and macOS or through local scripting interfaces on macOS, and organization-wide transport rules can silently drop or redirect messages that security products would flag. Message content, headers, message tracking records, and the audit entries generated by the export or deletion itself are all in scope, so a defender should assume the visible folder state has been edited and lean on service side evidence that lives outside the mailbox. That means administrator audit logging and the unified audit trail for the mail platform, message tracking or transport logs on the server, the export request history or its awkward absence, rules and transport rule change records, and endpoint telemetry for command line mail clients and local scripting hosts. Evidence of bulk mailbox permission grants followed by export or purge activity, rules that target security notifications, and deletion bursts outside retention schedules are the strongest indicators.

What you will practise

  • Explain why attackers modify or delete mail and mailbox data.
  • Describe how mailbox exports and export requests appear in server side records.
  • Identify the log sources that record mail deletion and rule changes.
  • Explain how organization-wide mail rules can reduce the chance of detection.
  • Describe how to preserve mail evidence even when the messages have been removed.
