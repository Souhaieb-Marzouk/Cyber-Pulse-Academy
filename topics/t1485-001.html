T1485.001 Data Destruction: Lifecycle-Triggered Deletion

T1485.001ImpactExtremeTechnique

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

This is a way to destroy cloud stored data by changing a housekeeping rule. Cloud storage buckets can be told to delete their contents after a certain number of days. An attacker who can edit that rule sets it to delete everything very soon. This sub-technique is a cloud version of the wider data destruction technique.

Why should you care?

The attacker does not need to touch each file, so there is no flood of delete requests to alert you. The storage service does the work quietly, later, exactly as configured. If those buckets held the only copy of important records, the loss is complete. Lifecycle rules are also commonly used to remove old log files, so an attacker can hide their trail this way too.

How it works, in plain steps

  1. The adversary obtains permission to change storage configuration in the cloud account.
  2. They read the current lifecycle rules so their change fits the existing pattern.
  3. They write a new rule that expires all objects after a very short period, often one day.
  4. The storage service accepts the rule and begins applying it on its own timetable.
  5. Objects disappear gradually, which can look like normal retention instead of an attack.
  6. The same trick may be used on the buckets that hold the account audit logs.

Real-world example

Imagine an office where every Friday a cleaner empties any tray marked for shredding. Staff normally place a few old papers there. An intruder cannot carry the archive out, so instead they change the note on the tray to say that all trays are cleared every hour. The cleaner follows the new instruction, and by Monday the whole archive is gone. Nobody saw anyone take a single folder.

Key takeaways

  • Watch who changes storage lifecycle rules, not only who deletes objects.
  • Keep audit logs in a separate account or bucket that the workload cannot modify.
  • A short expiry period on a bucket full of business data is a serious red flag.

In more detail

Lifecycle triggered deletion is a cloud native form of data destruction. Object storage services let an owner attach a lifecycle policy to a bucket so objects are transitioned, archived or expired after a set number of days. An adversary holding the right permission simply rewrites that policy so every object expires almost immediately, and the provider service performs the deletion on its own schedule. The attacker never issues a bulk delete call, which makes the event look like routine housekeeping and delays the damage by the period written into the policy. The control plane record of the configuration change is the crucial evidence, and it often sits in a different log stream from the objects being removed. Storage access logs may show no deletion requests at all, so teams that monitor only object level activity miss it entirely.

What you will practise

  • Explain what a cloud storage lifecycle policy does in normal use.
  • State how this sub-technique differs from the wider data destruction technique.
  • Describe why a policy based deletion is harder to notice than a direct delete.
  • Identify the control plane log records that reveal a lifecycle policy change.
  • Explain why log storage buckets are an attractive target for this abuse.
  • Describe the controls that protect stored data from configuration based deletion.
