T1021.008 Remote Services: Direct Cloud VM Connections

T1021.008Lateral MovementExtremeTechnique

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

Cloud providers offer special ways to connect straight to a rented virtual machine. Examples include a serial console or a helper tool from the provider. This is different from running a script through the provider's management interface. It gives you a screen or a shell on the machine itself, even when normal network access is broken.

Why should you care?

These connections are meant for emergencies, so they often grant high privileges by default. They may still work when other remote access paths are blocked by a firewall. Evidence of the connection lives in the provider logs, which many teams never review. If you do not watch these paths, an attacker keeps a quiet way back in.

How it works, in plain steps

  1. A cloud provider offers console or connection services that reach a virtual machine directly.
  2. The operator signs in with a password, a Secure Shell key, or an application token.
  3. The provider checks the permission and opens a session to the virtual machine.
  4. That session usually starts with high rights, such as root or system level.
  5. The operator then works interactively at the console instead of sending one script.
  6. The provider logs the request, and the machine logs the sign-in if logging works.

Real-world example

Think of a bank vault with a service hatch at the back. The hatch is not the main door, and the guards rarely watch it. Only a few people know it exists, and it opens straight into the vault. Cloud console connections work like that hidden hatch. They bypass the usual entrance and often give the strongest access in the building.

Key takeaways

  • Console and instance connection services often grant high privileges by default.
  • The provider's own logs are the main place these sessions appear.
  • Review who can use these paths and remove the permission when it is not needed.

In more detail

This sub-technique covers logging straight into a cloud-hosted virtual machine through the provider's own console or connection service, instead of running scripts through the cloud API. Providers offer serial console access, instance connection helpers, and session managers that place an operator at a virtual keyboard or an equivalent shell. Authentication may use a password, a Secure Shell key, or an application token, and these paths often land with root or system level rights because they were designed for recovery and troubleshooting. The artefact trail is split: the provider records the connection request and who authorised it, while the guest records the logon and any commands if its own logging is healthy. A useful distinction from cloud administration command execution is that the operator receives an interactive console, not a one-shot script.
