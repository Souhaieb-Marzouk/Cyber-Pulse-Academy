T1583.003 Acquire Infrastructure: Virtual Private Server

T1583.003Resource DevelopmentExtremeTechnique

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

A virtual private server, usually shortened to VPS, is a rented computer in a data centre. The customer pays by the month and gets full control of it. This sub-technique is about an attacker renting that computer as a base. It is one kind of infrastructure covered by the wider parent technique.

Why should you care?

The attacker owns no hardware and shows no address. Payments can be made with cryptocurrency or a stolen card, and the provider may be in another country. When the operation ends, the machine is deleted, so the evidence disappears. Traffic from major cloud providers often looks normal, so it slips past simple blocklists.

How it works, in plain steps

  1. The attacker signs up with a hosting provider, often using invented details or a stolen payment method.
  2. The provider creates a virtual machine and gives it a public address from a large shared cloud range.
  3. The attacker logs in over the network and installs tools for phishing, scanning, or control traffic.
  4. The machine is configured to relay commands between victims and the attacker's real systems.
  5. When defenders block or investigate, the server is destroyed and a new one is created elsewhere.
  6. The attacker may keep several providers ready and rotate between them during one campaign.

Real-world example

Imagine a stranger who rents a locker in a busy station, uses it to store stolen goods, then empties it and stops paying. Staff only know the locker was rented online. The station looks normal, and by the time anyone checks, the renter is gone.

Key takeaways

  • A clean-looking address from a big cloud provider does not mean the server is friendly.
  • Watch for outbound connections to hosting ranges that your business has no reason to use.
  • Trends matter more than single events: one connection may be fine, a steady pattern is not.

In more detail

An adversary rents a virtual private server, a virtual machine or container sold by a cloud provider, and uses it as operational infrastructure. This sub-technique sits under Acquire Infrastructure and is narrower than the parent: the acquired asset is a rented, provider-hosted machine rather than a domain, a physical server, or a service account. The advantage is attribution distance combined with elasticity, because the operator never touches hardware, can rebuild an image in minutes, and can abandon it without a paper trail. Traffic leaves from well-known cloud address ranges, which many organisations treat as ordinary business traffic. Detectable traces are mostly on the provider side and in network metadata: newly seen addresses inside large cloud ranges, hosting provider autonomous system numbers appearing in outbound connections, short-lived host records, and abuse notifications. Defenders distinguish hostile rental from legitimate cloud use by asset inventory, destination reputation at connection time, user agent or protocol mismatch, and whether the same address is contacted by many hosts across unrelated business units.

What you will practise

  • Explain how this sub-technique differs from the parent Acquire Infrastructure technique.
  • Describe why rented cloud machines help an attacker avoid attribution.
  • Identify network and hosting artefacts that suggest hostile rented infrastructure.
  • Distinguish ordinary cloud service traffic from infrastructure used to control malware.
  • Describe how inventory and allowlists reduce blind trust in cloud address ranges.
