T1560 Archive Collected Data

T1560CollectionExtremeTechnique

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

This technique is about an attacker packing stolen data before sending it out. They squeeze the files into a smaller archive, like a zip file, so there is less to send. They often lock that archive with a password or encryption so nobody can read it on the way. The packing happens on the victim machine, before anything leaves the network.

Why should you care?

Smaller data is faster to copy out and easier to hide among normal traffic. Encrypted archives defeat tools that look inside files for signs of stolen records. If you only watch network traffic, you may see one big blob and learn nothing from it. Attackers also pack data into one tidy file so a failed transfer can be retried easily. Ignoring this step means losing your last clear chance to notice a theft in progress.

How it works, in plain steps

  1. The attacker first gathers the files or records they want to steal on the host.
  2. They then compress those files into one smaller archive file, such as a zip.
  3. They may add a password or encryption so the contents cannot be read in transit.
  4. The finished archive is stored in a temporary or ordinary looking folder.
  5. The archive is then sent out, often over a normal looking network connection.
  6. Defenders look for the archive file, the tool used, and the transfer that follows.

Real-world example

Think of a removal company emptying a flat. Instead of carrying many loose items, the workers pack everything into boxes. They tape the boxes shut and label them with plain names. The removal van then looks like any other van on the road. The boxes made the job quicker and stopped neighbours from seeing what was taken, even though the items never changed.

Key takeaways

  • Archiving shrinks stolen data and encryption hides its contents from inspection.
  • The packing happens locally, so network monitoring alone will often miss it.
  • Treat unusual large archives as a warning sign when a big outbound transfer follows.

In more detail

Archiving collected data is the packing step that sits between collection and exfiltration. The adversary takes files or records already gathered on a host, compresses them to shrink the total size, and often encrypts the result so that content inspection on the way out yields nothing readable. Both operations reduce the number of bytes crossing the network, which means a smaller, shorter, and less obvious transfer, and encryption additionally defeats deep packet inspection, content filters, and data loss prevention rules that depend on seeing file contents. The mechanism can be a command line utility, a linked compression library inside the malware, or a custom routine written by the developer, and the choice matters for detection because each leaves a different artefact. Utilities leave process creation records with their arguments, libraries leave almost nothing beyond the file itself, and custom methods leave only the output and possibly unusual entropy. The defender's problem is that archiving is a normal administrative activity everywhere, so the technique is recognised from context rather than from the act: who ran it, from which directory, against which set of files, at what time, and whether a large outbound transfer followed shortly afterwards. Staging locations such as temporary folders, user profile directories, and world writable paths are common, and anomalous archiving combined with an unusual destination is the pattern worth alerting on.

What you will practise

  • Explain why adversaries compress collected data before exfiltration.
  • Describe how encryption of an archive defeats content based inspection on the network.
  • List the host artefacts an archive leaves behind and which log records each one.
  • Compare utility based, library based, and custom archiving and the traces each one leaves.
  • Judge whether an archive on a host is routine administrative work or suspicious activity.
  • Identify the log sources that pair an archive event with a following outbound transfer.
