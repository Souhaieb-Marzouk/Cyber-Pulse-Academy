DET0810 Detection of Search Victim-Owned Websites

DET0810Detection StrategyVery hardDetection Strategy

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

Your company website is public, so anyone may read it. Some people read it in a way that shows they are collecting information, not shopping or reading news. This detection studies your web server logs for that behaviour. It looks for one visitor walking through many pages or staff listings in a short time.

Why should you care?

Public pages often leak more than intended. A staff page lists names and roles. A support page describes internal tools. A public upload folder can hold documents that were never meant to be shared. An attacker who reads all of it can build a believable story for a phishing message. The request log is the only place this behaviour is visible, and it is already being recorded. Reviewing it turns a quiet research walk into an early warning.

How it works, in plain steps

  1. Your web server writes a log line for every request. Each line has the page, the visitor address, the browser name and the result code.
  2. The rule counts how many different pages one visitor reads in a short window.
  3. It looks for signs of a walk, such as staff pages visited in order, or addresses with numbers that climb.
  4. It also checks for requests to file types that should never be public, such as backups or configuration files.
  5. Known search engine crawlers and your own monitoring tools are removed from the count.
  6. Visitors whose pattern looks like collection are grouped and raised with the pages they read.

Real-world example

Think of a shop with an open notice board. Most visitors read one or two notices and leave. One visitor stands there for twenty minutes. They copy every notice into a notebook. That includes the staff rota and the delivery schedule. Nothing was stolen and no lock was broken. But the shopkeeper would want to know about it. That notebook makes a burglary much easier to plan. Your web log is the record of who stood at the board.

Key takeaways

  • You can detect this reconnaissance, because the search happens on your own servers and is logged.
  • The signal is the pattern of a walk, not a single unusual page.
  • Look for mistakes too: public backup and configuration files are worse than any search.

In more detail

This strategy detects searches of victim owned websites, ATT&CK technique T1594, where an adversary browses the organisation's public sites to collect employee names, email addresses, technology details, support procedures and anything sensitive that was published by mistake. The telemetry is on the victim's own infrastructure, which makes this one of the few reconnaissance techniques that can be detected with confidence: web server and reverse proxy logs record each request with path, status code, user agent and client address, and a web application firewall logs the same traffic with attack and enumeration context. The pattern is methodical collection rather than browsing, for example a single client requesting many pages of one section in a short window, walking staff directories in numeric order, retrieving backup or configuration file extensions, or reading the published sitemap and then requesting pages outside it. Noise comes from search engine crawlers, uptime monitors, marketing analytics and content editors, all of which look similar. The strategy fails when logs are not retained long enough to see a campaign, when a web application firewall blocks a probe and therefore hides it from the analyst, and when the traffic is spread across many source addresses.

What you will practise

  • Explain how public website content supports later phishing and intrusion activity
  • Identify the web server and web application firewall fields needed to detect methodical collection
  • Build a request volume and breadth baseline per client address and user agent
  • Detect directory walking, sequential identifier enumeration and requests for non public file types
  • Recognise crawler, monitoring and content editor traffic that resembles collection
  • Feed website reconnaissance findings into exposure review and content clean up
