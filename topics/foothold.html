Foothold

Offensive SecurityVery hardKeyword

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

A foothold is the first stable way an intruder gets into a system. It is a small opening, not a full takeover. It might be one low-level session on a public server, a stolen username and password, or code running inside a browser. Its value is that it works again and again.

Why should you care?

Most big breaches start with one small opening. If you cannot spot that first access, you will not know an intruder is inside. A foothold often looks like normal activity, so it is easy to miss. Defenders should treat common entry paths as a checklist: phishing emails, exposed services, stolen passwords and weak cloud settings.

How it works, in plain steps

  1. An intruder picks a way in, such as a phishing email or an exposed login page.
  2. They send the first request and watch how the target answers it.
  3. When it works, they get a small amount of control, like a user session.
  4. They check what they can see and do from that one position.
  5. They test whether the access survives a reboot, a logout or a password change.

Real-world example

Imagine you own a shop. A thief finds a small side window that does not lock. They climb in, but they do not empty the till yet. Instead they hide a key under a mat outside and learn the shop layout. That side window is the foothold. The shop is not robbed, but someone now has a way in whenever they want. This is why a small, quiet opening deserves a serious response.

Key takeaways

  • A foothold is stable access, not a full takeover of the network.
  • Watch your remote access tools and login pages closely.
  • Small and quiet access can grow into a very serious breach.

In more detail

A foothold is the first durable, repeatable point of access an intruder establishes inside a target environment, giving command execution and a base from which further objectives are pursued. It is deliberately distinguished from full compromise: a foothold may be a single low-privileged shell on an internet-facing host, a valid credential pair, a session on a remote access appliance, or code running inside a user's active browser session, and its value lies in reliability rather than breadth. The paths that produce footholds are well documented and defensive teams should treat them as a checklist for exposure: phishing with an attachment or link, exploitation of public-facing services, abuse of stolen or guessed credentials against remote access services, trusted relationships with suppliers, and misconfigured cloud or container endpoints. Immediately after access is obtained, the intruder's priorities usually shift to understanding the local context, confirming that the access survives normal session end, and hiding the channel that will carry later stages. Detection therefore rarely depends on a single alert. It comes from correlating identity telemetry with endpoint and network evidence: authentications from unexpected geographies or protocols, new remote access sessions on appliances that normally see none, unusual parent and child process relationships, and outbound connections to infrastructure the organisation has never used before. Because a foothold is small by design, containment decisions hinge on whether the access is a one-off session or something that will re-establish itself, which is why rapid scoping and credential rotation accompany every confirmed incident.

What you will practise

  • You will be able to define a foothold and distinguish it from persistence, privilege escalation and full compromise.
  • You will be able to map common foothold vectors to the telemetry that each one generates.
  • You will be able to correlate identity, endpoint and network evidence to confirm whether an intrusion has established stable access.
  • You will be able to choose proportionate containment actions for a suspected foothold without destroying evidence.
  • You will be able to explain why remote access appliances and valid accounts dominate real-world initial access.
