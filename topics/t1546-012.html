T1546.012 Event Triggered Execution: Image File Execution Options Injection

T1546.012PersistenceExtremeTechnique

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

This technique uses a Windows registry area that joins a debugger to a chosen program. A debugger is a tool that inspects other programs. The value in the registry says which tool should start in front of that program. An attacker writes their own tool into that value. Then Windows starts the attacker's tool every time the chosen program starts. This sub-technique differs from its parent because a program name in the registry, not a sign in, sets off the code.

Why should you care?

This change needs only a small registry write, so it is easy to make and easy to overlook. An attacker can also aim it at a security tool, which stops that tool from starting at all. When it targets an accessibility program, the attacker's code runs as SYSTEM at the logon screen. If you never check this registry area, a written entry can keep an intruder on the machine for months.

How it works, in plain steps

  1. Image File Execution Options is a registry area that lets a developer attach a debugger to a program.
  2. Windows reads a value named Debugger under the subkey for the chosen program name.
  3. If that value exists, Windows starts the named debugger and passes the real program as an argument.
  4. An attacker sets the value to their own tool, so their code starts whenever the target starts.
  5. A second group of values can start a monitor program when a chosen process ends early.
  6. Attackers may point a debugger at a security tool, which prevents that tool from running at all.

Real-world example

Imagine an airport gate with a note that says before every passenger boards, send them to desk two first. Staff follow the note without thinking, because it is part of the normal routine. If someone rewrites the note, every passenger walks to a different desk that serves a different purpose. The Image File Execution Options value is that note. It sits in front of a program's name and decides what really runs first.

Key takeaways

  • A Debugger value in Image File Execution Options runs an attacker's tool before the chosen program.
  • The same area can disable a security tool or trigger a monitor when a process exits early.
  • Review this registry area and treat unexpected debugger paths as high priority.

In more detail

Image File Execution Options is a registry area that lets a developer attach a debugger to a program. Each targeted executable has a subkey, and a Debugger string value inside it is prepended to the image name when the process is created, so the debugger runs and the real binary becomes its argument. The same area supports silent process exit monitoring, where a monitor program is launched when a chosen process terminates early. An adversary writes those values to gain persistence, to run code inside a trusted process, or to disable a security tool by pointing its debugger at something harmless. On Windows Vista and later the technique can also be aimed at an accessibility binary, which gives SYSTEM execution at the logon screen. The artefacts are registry writes under the Image File Execution Options and SilentProcessExit paths, process creation where the debugger starts with the target binary as an argument, and image load records in which a security product never starts. Legitimate debugger entries exist on developer machines, so the discriminator is whether the debugger path is a known tool and whether the value was expected on that host.
