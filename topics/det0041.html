DET0041 Detection of Lifecycle Policy Modifications for Triggered Deletion in IaaS Cloud Storage

DET0041Detection StrategyVery hardDetection Strategy

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

Cloud storage can hold rules that delete old files for you. This detection watches those rules. It looks for a rule that expires files very quickly. It also looks for a rule added by an account that does not normally manage storage.

Why should you care?

A single rule can erase a whole bucket later, at a set time. No attacker command is needed after that. The loss may be permanent because the rule also removes older versions and snapshots. This is a business continuity risk, not only a security one.

How it works, in plain steps

  1. The cloud records every management action, including changes to storage rules.
  2. The rule selects actions that create or change a lifecycle policy.
  3. It reads the expiration it sets, in days, and the objects it applies to.
  4. It adds the identity, the origin address, and the type of session that made the call.
  5. It removes the automation roles that manage storage as part of normal operations.
  6. A short expiration set by a person, outside a change window, is a critical alert.

Real-world example

Think of a library that allows a rule saying every book older than a year is thrown away. The rule is written in one minute, but the loss happens on its own later. A librarian would check who wrote a rule saying every book is thrown away in two days.

Key takeaways

  • Destructive rules hide the damage in a scheduled future action.
  • A very short expiration, set by a person, is the strongest indicator.
  • Version and snapshot rules matter, because they remove the recovery path.

In more detail

This strategy detects lifecycle policy changes in cloud storage that are configured to delete data automatically, the destructive behaviour tracked as T1485.001. A lifecycle rule is a scheduled instruction to expire objects, versions, or snapshots, so a single configuration change can cause permanent loss of a whole bucket without any further attacker action and without a conventional delete event to alert on. The telemetry is cloud audit data for storage policy changes, joined with the calling identity, the origin address, the session type, and the retention duration it set. It fails in practice because storage automation and backup tools legitimately manage lifecycle rules on a schedule, so alerts built only on the API call name are dominated by automation and the useful discriminators are the identity, the session origin, and an unusually short expiration.

What you will practise

  • Explain what a storage lifecycle rule does and how it can destroy data.
  • Identify cloud audit operations that create or modify a lifecycle policy.
  • Read the expiration duration and target scope from a policy change record.
  • Separate storage automation identities from human accounts in the audit data.
  • Recognise rules that also expire older versions and snapshots as high impact.
  • Plan a response that suspends the rule before it runs.
