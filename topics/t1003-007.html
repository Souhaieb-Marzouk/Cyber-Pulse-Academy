T1003.007 OS Credential Dumping: Proc Filesystem

T1003.007Credential AccessExtremeTechnique

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

On Linux, the proc filesystem shows information about running programs. One part of it lets a process read its own memory. This sub-technique means searching that memory for passwords. It differs from the parent because the source is a live system interface rather than a stored database file.

Why should you care?

Some programs keep passwords in memory as plainly readable text. An attacker with root can search every running program at once. No password file needs to change, so simple file checks may find nothing at all. Real debugging tools use the same interface, which helps hide the abuse. Watching unusual process memory reads gives you a way to notice it.

How it works, in plain steps

  1. Linux shows details about every running program inside the proc filesystem.
  2. For each program, one file describes where its memory is placed.
  3. Another file gives access to the actual content of that memory.
  4. An attacker with root reads those files and searches for password patterns.
  5. Text patterns such as sign in names and keys are collected into a list.
  6. The collected values are used later to reach services or other hosts.

Real-world example

Think of a busy hospital ward where each patient folder sits in an open tray. A cleaner with a master pass can walk past every tray and photograph the pages that mention account numbers. No folder leaves the room and nothing looks disturbed. Later, the photographs are used to open other systems. The proc filesystem is those open trays, and memory is the pages inside them.

Key takeaways

  • Linux process memory can hold credentials in clear readable text.
  • Root access makes the memory of every running process readable.
  • Debugging tools use the same files, so judge intent and context carefully.

In more detail

Proc Filesystem dumping uses the Linux proc pseudo-filesystem to read the virtual memory of running processes. The maps file describes how memory is laid out inside a process, and the mem file exposes the content itself, subject to file permissions. With root rights an adversary can walk every process on the host and search for patterns that indicate cached hashes or clear text credentials, and without root a process can still read its own memory, so a browser or service holding secrets in clear text is exposed to itself. The behaviour leaves few obvious files, so the artefacts are unusual reads of proc paths, command lines that name maps or mem, and processes such as a text processing tool touching another process memory. Separating abuse from genuine debugging and monitoring requires checking who ran the command and what it read.
