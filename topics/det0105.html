DET0105 Post-Credential Dump Password Cracking Detection via Suspicious File Access and Hash Analysis Tools

DET0105Detection StrategyVery hardDetection Strategy

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

This detection looks for password cracking after a theft of password files. Cracking means guessing a password from its stored scrambled form. The rule watches for the tools and files involved in that guessing.

Why should you care?

A scrambled password, called a hash, is not directly usable everywhere. Cracking turns it into the real password, which then works in many places. Attackers often crack on the victim machine or copy the hashes to a powerful machine. Detecting the cracking step buys time before the stolen secret is reused.

How it works, in plain steps

  1. Auditing records every read of the protected files that store account secrets, with the process that read them.
  2. The endpoint records new processes, including tool names and their full command line arguments.
  3. File events show hash files, wordlist files and result files being created or opened on the same host.
  4. All of this flows into the central log platform, often a SIEM, which means Security Information and Event Management.
  5. A rule links a secret file read with a cracking tool run. It also links a hash file with a wordlist file on the same host.
  6. The tool or the files may sit outside an approved testing host. The rule then alerts with the host, account and command line.

Real-world example

Imagine a thief who steals a locked cash box from an office. The box itself is useless until it is forced open. A guard sees someone carry the box into a workshop full of drills and files. The guard has spotted the real danger, even before the box is opened. This detection watches for the workshop and the tools, not just the theft.

Key takeaways

  • The cracking step is what turns stolen hashes into working passwords.
  • Watch the read of secret stores and the tools or files that follow it on the same host.
  • Approved testing machines will match the pattern too, so keep a short allowlist.

In more detail

This detection strategy targets T1110.002, password cracking, and specifically the stage that follows a credential dump, when an adversary moves hash material to a cracking host or starts a hash analysis tool on the victim machine itself. It matters because cracking turns a stolen hash into a plaintext secret that works against other systems, including legacy protocols that do not require a multi step challenge, and it converts a single host compromise into a fleet wide problem. The telemetry that makes detection possible is file access auditing on credential databases and registry hives, process creation records for names of common cracking and extraction utilities, command line arguments that reference wordlists and hash files, and file creation events for pot files and cracked output. It fails in practice because these tools are standard on penetration testing and forensics workstations, and because a determined attacker can rename a binary, so the rule should lean on access patterns and file relationships rather than tool names alone.

What you will practise

  • Describe the relationship between a credential dump and the cracking step that follows
  • Name the file, process and command line telemetry that reveals hash analysis activity
  • Explain why hash and wordlist file pairs on one host are a strong combined signal
  • Identify the accounts and hosts where cracking tools are legitimately used
  • Recognise the credential types whose theft most often leads to cracking
  • Plan response actions that contain the blast radius before cracked passwords are reused
