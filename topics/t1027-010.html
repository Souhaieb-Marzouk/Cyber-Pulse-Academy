T1027.010 Obfuscated Files or Information: Command Obfuscation

T1027.010StealthExtremeTechnique

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

Command obfuscation means writing a command in a strange way so that its real purpose is hard to read. The command still does the same job when the computer runs it. This is a sub-technique of Obfuscated Files or Information, which covers hiding content from security tools. Attackers use it because commands are often recorded in logs that defenders read.

Why should you care?

Defenders often spot attacks by looking for known command text. If the wording changes while the effect stays the same, those checks find nothing. An analyst may also skip a command that looks like random letters and never decode it. This means real activity can hide in plain sight in your own logs. You must learn to decode commands instead of only matching them.

How it works, in plain steps

  1. The attacker decides on an action, such as downloading a file, and writes the normal command for it.
  2. They rewrite that command using escape characters, extra spacing or unusual symbols.
  3. They may split words into pieces and join them again when the command runs.
  4. They can also change letter case, reverse text or use wildcards that the shell expands.
  5. Some tools encode the whole command as Base64 and pass the encoded text to the interpreter.
  6. The interpreter decodes everything at run time, so the action itself never changes.

Real-world example

Imagine a night manager who leaves instructions for the morning staff. Instead of writing the plain instruction, they write it with odd spacing, swapped letter sizes and one word spelled backwards. The staff read it slowly, and the message still makes sense. Anyone scanning a pile of notes for the usual phrase misses this one. Only a person who takes time to rewrite it in normal words sees what it really asks for.

Key takeaways

  • Treat any strangely written command line as suspicious until you decode it and read the real action.
  • Turn on command line and script block logging, because the recorded text is your main evidence.
  • Focus detections on what the command did, such as network use or file changes, not only on its wording.

In more detail

Command obfuscation rewrites a command so that its text no longer matches known bad strings, while the interpreter still performs the original action. Because command lines are one of the richest detection sources on a host, appearing in process creation events such as Windows Security 4688 and Sysmon 1 as well as shell history and endpoint telemetry, an attacker who can change the wording of a command without changing its effect defeats signature matching and complicates triage. Common forms include interpreter features such as PowerShell encoded commands, where a Base64 string is decoded and executed at run time; escape and splitting tricks using characters such as the caret, backtick, plus sign and percent sign; string concatenation, case changes, random casing and reversed text; wildcard expansion; and path traversal noise that hides which binary is really being invoked. The resulting strings look random or padded, yet resolve to ordinary tools. Strong detection therefore leans on behaviour and reconstruction rather than literal matching: decode or de-obfuscate the recorded command line, compare the parent process with the child, and profile what the command actually did, such as network connections, file writes or service changes. PowerShell script block logging and command-line auditing preserve the pre-execution text that makes reconstruction possible.

What you will practise

  • Explain how command obfuscation changes the appearance of a command without changing what it does.
  • Describe how this sub-technique differs from the parent technique of hiding files or whole scripts.
  • Recognise common obfuscation forms, including encoded commands, escape characters, splitting and wildcards.
  • Reconstruct an obfuscated command line from logs and explain the steps you would take to decode it.
  • Select the log sources, such as process creation records and script block logging, that reveal obfuscated commands.
