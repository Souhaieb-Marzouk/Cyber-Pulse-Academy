Industrial Control System

OT & ICS SecurityHardKeyword

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

An industrial control system is the set of computers and networks that run a real physical process, like a water plant or a factory line. It watches sensors and moves valves, motors and switches. You may see it shortened to ICS, which stands for industrial control system. Office computers handle information, but these systems handle machines.

Why should you care?

If an office laptop stops working, people lose time and read old files. If a control system stops working, a pump can overflow, a valve can stay shut, or a machine can hurt someone nearby. These systems were often built to run for many years, so old parts stay in service. That makes them hard to update and a target for attackers. Good security keeps the physical process safe and running.

How it works, in plain steps

  1. Sensors measure the real world, for example temperature, pressure or flow, and send those readings to a controller.
  2. A controller is a small industrial computer that runs a stored program and decides what the machines should do next.
  3. The controller sends commands to actuators, which are devices that move something, like a valve or a motor.
  4. A supervisory system collects readings from many controllers and shows them to the operators on screens.
  5. These parts talk over special industrial networks that often assume every device is friendly and trusted.
  6. Security teams add separate zones, passive monitoring and change windows instead of scanning or patching freely.

Real-world example

Picture a hospital night desk that also controls the building. The nurse can switch on corridor lights and adjust the medicine fridge. One small panel does both jobs, and it was installed years ago. Nobody wants a random update at three in the morning, because the fridge must stay cold. So changes happen only in a planned window, with the nurse watching the readings. If someone plugged a strange laptop into that panel and ran a scan, the lights could flicker and the fridge alarm could fail. That is why the control panel sits on its own network, away from the guest wifi and the office printers.

Key takeaways

  • A control system is judged by whether the physical process stays safe, not by whether data stays secret.
  • You cannot patch and reboot these systems like office computers, so you plan every change.
  • Aggressive network scans and discovery tools can disturb a running process.

In more detail

An industrial control system, or ICS, is the combination of hardware, software and communication networks that directly monitor and drive a physical process, such as a water pump, a turbine or an assembly line. It includes programmable logic controllers, remote terminal units, supervisory control and data acquisition software, and the human machine interfaces operators watch. What makes an ICS different from an office network is the consequence model and the timing model: the priority is availability and safe physical behaviour, not confidentiality, and control loops must close within milliseconds or seconds. Engineers therefore cannot simply patch and reboot on a weekly cycle. The common mistake is treating an ICS as ordinary information technology with older software and applying standard IT security habits such as aggressive scanning, automated patching or network discovery tools, which can stall a controller or corrupt a process. Security work in this space is usually done through segmentation, passive monitoring, engineered change windows and safety validation rather than by hardening the endpoint alone.

What you will practise

  • Explain what an industrial control system is and how it differs from ordinary office information technology.
  • Identify the main parts of a control system, including controllers, sensors, actuators and operator screens.
  • Describe why availability and physical safety outrank confidentiality in an industrial environment.
  • Recognise risky habits such as unscheduled patching and unannounced network scanning in a plant.
  • Summarise the defensive controls used in this space, including zoning, passive monitoring and change windows.
