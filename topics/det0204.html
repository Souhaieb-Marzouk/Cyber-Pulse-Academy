DET0204 Detection Strategy for T1547.010 – Port Monitor DLL Persistence via spoolsv.exe (Windows)

DET0204Detection StrategyVery hardDetection Strategy

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

This detection looks for a new print monitor on a Windows computer. A print monitor is a small program that helps the print service talk to a printer. Windows starts the print service every time the computer boots. An attacker adds a monitor so that their own code starts with it. The rule watches the registry key, the new file, and the loaded module.

Why should you care?

Persistence means the attacker comes back after a reboot. A print monitor is a quiet way to arrange that. The print service runs with high rights on the system. The monitor library loads inside that service every time the computer starts. Few people ever check print settings, so this can survive for a very long time. The registry key and the module load together give you a clear signal.

How it works, in plain steps

  1. The endpoint agent records registry changes, including the key path and the value written.
  2. It also records new files, so you can see the library that was just dropped on disk.
  3. The detection watches the print monitor registry location for any new entry.
  4. It compares the new entry with the list of monitors that your team has approved.
  5. It then looks for the print service loading that library when it next starts.
  6. A new monitor from a temporary folder or without a valid signature alerts immediately.

Real-world example

Think of a factory gate that opens for one delivery van. The guard knows the van, so he raises the barrier without checking the cargo. An attacker paints his own van the same colour and adds it to the guard's list. From then on, the barrier opens for him every single morning. A print monitor is that van. Windows writes it onto the trusted list, and the print service opens the gate at every boot.

Key takeaways

  • A port monitor gives an attacker code execution inside the print service.
  • The registry entry and the loaded library must be linked together.
  • Approved monitor baselines are essential, because vendors add monitors too.

In more detail

This strategy detects persistence through a Windows port monitor, covering T1547.010 Port Monitors. The technique matters because a port monitor runs inside the print spooler service and its library is loaded on every boot, so one registry change gives an attacker recurring code execution inside a long lived and highly privileged process. Detection is a correlation problem: the registry write that registers the monitor, the library file that appears on disk, and the module that the spooler loads on the next start. The common failure is that printer vendors install legitimate monitors, so the rule needs an approved baseline of monitor names, publishers, and file paths, and it must treat any edit made by a non administrative or unexpected process as the higher priority signal.

What you will practise

  • Describe how the Windows print spooler loads port monitor libraries.
  • Locate the registry location that registers a port monitor.
  • Correlate registry writes, dropped files, and spooler module loads.
  • Build an approved baseline of monitor names, publishers, and file paths.
  • Prioritise edits made by non administrative or unexpected processes.
