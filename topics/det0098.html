DET0098 Detect abuse of Windows BITS Jobs for download, execution and persistence

DET0098Detection StrategyVery hardDetection Strategy

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

This detection looks for misuse of a Windows service that downloads files in the background. The service is called the Background Intelligent Transfer Service, or BITS. Programs use it to fetch updates, and attackers use it because it is trusted and always available. The detection watches the commands that create transfer jobs, the service log and the files that arrive.

Why should you care?

Security tools often allow this service because Windows and update systems depend on it. That trust makes it a useful path for an attacker who wants to fetch a file quietly. A job can also be set to run a command when the transfer finishes, which turns a download into execution. Jobs can persist across restarts, so access can outlive the original session. Watching job creation and its arguments closes this gap.

How it works, in plain steps

  1. The endpoint agent records process creation, including the command line for job management tools.
  2. The rule looks for the command line interface and the scripting command that create transfer jobs.
  3. It reads the arguments, because a remote address, a notification command or a high priority flag changes the risk.
  4. The service operational log records the job identifier, the owner, the file path and the completion state.
  5. The rule links the job to any process that starts soon after the transfer finishes.
  6. Jobs created by ordinary user accounts that write to a temporary folder and run a command when done are the priority case.

Real-world example

Imagine a building with a trusted courier who is allowed through the gate without a search. Every department uses the courier for real deliveries, so the guard waves the van through each time. If someone starts sending the courier to collect a package from a strange address and to drop it in a back room on arrival, the guard would still wave the van through. The courier log and the delivery addresses are what reveal the misuse, just as the job log does here.

Key takeaways

  • BITS is a signed, trusted transfer service, so allowlists rarely block it.
  • A transfer job can run a command when it completes, which turns a download into execution.
  • Always read the job arguments and the owner, because normal patching uses the same service.

In more detail

This strategy detects misuse of the Windows Background Intelligent Transfer Service, a built in file transfer component, to download payloads, run commands when a transfer completes and survive reboots. The technique matters because the service is signed and trusted, it can reach the internet from hosts that block other tools, and a notification command gives it an execution path. Detection combines process creation showing command line job management, the service operational log that records job creation and completion, and the network connections the service makes. The typical failure is that patching and update platforms use the same service constantly, so job creation alone is meaningless and the command line and job owner must decide. What you will practise

  • Describe what BITS does and why attackers prefer a trusted transfer service.
  • Identify the command line, service log and network telemetry that reveal BITS jobs.
  • Recognise the notification command line argument as an execution path.
  • Baseline the software and accounts that legitimately create BITS jobs in your estate.
  • Triage a BITS job alert by checking the remote address, the file path and the owner.
