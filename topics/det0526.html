DET0526 Detect Archiving and Encryption of Collected Data (T1560)

DET0526Detection StrategyVery hardDetection Strategy

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

This detection looks for a program that packs many files into one file, often with a password. Attackers do this before they steal data. One small file is easier to move and harder for you to read. The alert fires when a machine creates a password protected archive, or packs many files in a short time.

Why should you care?

Data theft usually happens in stages. First the attacker gathers the files they want. Then they pack them into one file and send it out. The packing step happens on the machine, before the data leaves your network. Stopping it there keeps the data inside. It also gives you a list of the exact files the attacker wanted. That helps you judge the damage and warn the right people.

How it works, in plain steps

  1. Endpoint agents record process starts with full command lines, including archiving tools and their switches.
  2. The rule looks for switches that set a password on the archive, which normal compression jobs do not use.
  3. File creation events flag new files with archive extensions, and the rule records the folder and the creating process.
  4. File access auditing or endpoint read data counts how many different files the process read before the archive appeared.
  5. The rule raises an alert when three things appear together on one machine. They are password protection, archive creation and a high file read count.
  6. The alert lists the archive path, the file count and the account, so the analyst can find the staging folder.

Real-world example

Think of a till receipt at the end of a busy day. A cashier who rings up two hundred items in one minute is doing something unusual. Every single one of those sales still looks normal. The receipt does not prove a crime. It shows a bulk action that no ordinary customer performs. Here the bulk action is packing many files into one protected archive.

Key takeaways

  • Password protection plus archive creation plus a high file read count is far stronger than a file extension alone.
  • Staging happens before exfiltration, so this is a chance to keep data inside the network.
  • The file list in the alert tells you what the attacker wanted and who to notify.

In more detail

This detection strategy covers the staging step where an attacker packs collected files into an archive and often protects it with a password, the behaviour behind archive collected data. The archive is created on the victim host shortly before exfiltration, so it is one of the last chances to interrupt a theft. Process creation for archiving utilities with password switches, file creation events for archive extensions, and file read volume on the same host give the pattern. The common failure is alerting on every compressed file, because backup agents, log rotation and developers produce archives constantly, so password protection, archive creation and read volume must be weighed together rather than separately.

What you will practise

  • Explain why attackers archive and encrypt collected data before exfiltration
  • Identify archiving tool command line switches that indicate password protection
  • Correlate archive file creation with the process that created it and the files it read
  • Build a baseline of normal archive creation from backup, build and log rotation jobs
  • Choose thresholds that keep routine compressed files out of the queue
  • Describe how to hand the file list from an alert to an incident responder
