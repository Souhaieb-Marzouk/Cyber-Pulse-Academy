T1021.002 Remote Services: SMB/Windows Admin Shares

T1021.002Lateral MovementVery hardTechnique

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

Windows computers share files over a protocol called Server Message Block (SMB). Every Windows machine also has hidden administrative shares, which are special folders that administrators can reach over the network. These shares let a remote administrator copy a file and then start a program on the other computer.

Why should you care?

This is a quiet way to move across a network. The traffic uses the same file sharing that staff use every day, so nothing looks strange at the network level. An attacker with one administrator password can copy a tool onto many servers and run it. If you never check who is allowed to administer which machines, this activity hides in plain sight.

How it works, in plain steps

  1. The attacker already holds an administrator password for the network or for one machine.
  2. They connect to a hidden administrative share on a target computer and copy a file there.
  3. Next they ask the target to create a service, which is a background program that Windows runs.
  4. Windows starts that service, so the copied file now runs with high privileges on the target.
  5. The attacker deletes the copied file to tidy up, then repeats the process on the next host.

Real-world example

Imagine an office where every manager holds a master key to every desk drawer. Nothing is forced open, so security never notices. A thief who copies one master key can walk the whole floor, drop a package in each drawer, and ask each desk to open it. By morning the packages have all run. Administrative shares work like those master keys. They are meant for maintenance, but they also open every computer to anyone holding the right password.

Key takeaways

  • Hidden administrative shares exist on Windows by default and allow remote file copy and execution.
  • Use separate administrator accounts so one stolen password cannot unlock every machine.
  • Watch for one account touching many computers in a few minutes, because that is not normal.

In more detail

SMB and Windows administrative shares provide file and named pipe access over the Server Message Block protocol, and the administrative shares that exist on Windows systems by default can be used both to move files to a remote host and to request remote execution of a service or scheduled task. An adversary with administrative credentials can copy a payload to a target, then trigger execution through a remote service control or task scheduling interface, and finally clean up the staged file. Because the underlying protocol is the same one used for ordinary file sharing, the traffic does not look unusual at the network layer, and command-line administrative tools are also entirely normal on managed systems. The reliable evidence is a combination of authentication, share access, and service or task state changes. Destination hosts log network logons and, where detailed file share auditing is enabled, the specific share and path accessed together with the accessing account. Service creation and task registration events on the target record the moment execution was requested, including the binary path referenced, which frequently points at an administrative share path or a temporary directory. Process creation on the target shows what actually ran and under which account, and named pipe access may appear in telemetry from security tooling or from the endpoint agent. On the source side, administrative command execution produces process events that name remote hosts and share paths. Legitimate configuration management, patching, and backup products use exactly these mechanisms, often at high volume. Effective triage requires knowing which accounts and hosts are authorised to perform remote administration and at what times. Signals that raise confidence include a single account authenticating to many hosts in rapid succession, service creation referencing binaries in user-writable locations, administration activity outside deployment windows, and correlation with an earlier credential access alert.

What you will practise

  • Explain how administrative shares, remote service creation, and scheduled task registration combine to produce remote execution.
  • Interpret share access auditing and service or task creation records on the destination host to confirm execution.
  • Build a baseline of authorised administrative accounts and hosts to reduce false positives from management tooling.
  • Detect anomalous fan-out patterns where one account authenticates to many hosts in a short interval.
  • Explain what evidence survives on the source host and what must be recovered from the target or network capture.
  • Map SMB-based lateral movement to ATT&CK and evaluate segmentation and credential-tiering controls against it.
