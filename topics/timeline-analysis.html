Timeline Analysis

Incident Response & ForensicsVery hardKeyword

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

Timeline analysis means putting events from many sources into one time order. You line up logins, file changes, program starts, and network connections on a single clock. Then you can see what happened first and what followed. This turns a pile of evidence into a clear story of the intrusion.

Why should you care?

A single log rarely tells you the whole story. One system records a login, another records a file download, and a third records an outbound connection. On their own, each event looks harmless. In the right order they show an attack. Timeline analysis also tells you how long the attacker had access, which shapes your reports.

How it works, in plain steps

  1. Collect events from every source you can, such as hosts, accounts, and network logs.
  2. Convert all times to one time zone, usually UTC (Coordinated Universal Time).
  3. Place every event on a single list, sorted from the earliest to the latest.
  4. Check for clock differences between systems, because small drift can mislead you.
  5. Look for gaps and for events that appear only in one source.
  6. Build a short list of key events to answer one clear question about the incident.

Real-world example

Imagine a busy airport terminal with cameras in different rooms. One camera shows a person at check-in, another shows a bag on a belt, and a third shows a door opening. Alone, each clip is boring. Played on one clock, they show a clear journey. That is what a timeline does with log entries.

Key takeaways

  • One event rarely proves anything; the order of events builds the story.
  • Convert every source to the same time zone and note the difference.
  • Treat gaps and single-source events as questions, not as facts.

In more detail

Timeline analysis is the forensic practice of ordering events drawn from multiple evidence sources onto a single, comparable chronological axis so that an investigator can establish sequence, duration, causality and gaps in an intrusion. It is the discipline that turns a pile of artefacts into a story: which account logged in first, when the payload was written, what process created it, whether an outbound connection preceded or followed credential theft, and how long the adversary held access before anyone noticed. Source material includes file system metadata such as creation, modification and access times, file system journals and change records, registry hives and their key last-write values, operating system event and process telemetry, authentication logs from identity providers, browser and application histories, shell histories, container and cloud control-plane audit logs, and network flow or proxy records. The hard parts are rarely tooling and usually interpretation: clocks drift, time zones differ, some sources record local time while others use UTC, several timestamps are updated by ordinary activity, and artefacts can be deliberately manipulated by an adversary who understands the same metadata. A sound timeline states its normalisation decisions, records uncertainty rather than smoothing it away, and distinguishes corroborated events from single-source ones. Analysts typically build a full super-timeline for scoping and a filtered, focused timeline to answer one specific question such as dwell time, lateral movement path or data access. The output feeds incident scoping, legal and regulatory reporting, and detection engineering.

What you will practise

  • Define timeline analysis and explain how normalised event ordering establishes sequence, duration and causality.
  • Identify the artefact sources that contribute to a forensic timeline and state what each one can and cannot prove.
  • Normalise timestamps across time zones, clock drift and differing source granularity, and document those decisions.
  • Construct a super-timeline for scoping and a focused timeline for answering a specific investigative question.
  • Recognise artefact types that an adversary can manipulate and treat single-source events with appropriate caution.
  • Correlate host, identity, cloud and network telemetry to reconstruct lateral movement and data access.
  • Translate timeline findings into dwell time, affected scope and detection gaps for reporting.
