T1561.001 Disk Wipe: Disk Content Wipe

T1561.001ImpactExtremeTechnique

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

This sub-technique is about destroying the contents of a disk rather than the information that helps it start. The attacker opens the storage device itself and writes random rubbish over large areas of it. Files do not get deleted in the normal way, because the storage underneath them is spoiled. It is the content focused part of the wider disk wipe technique.

Why should you care?

When storage content is overwritten, the data is usually gone for good. Normal file recovery does not help. The tool that recovers files reads the storage where the data used to live. Even when the machine still starts, the files it shows cannot be opened. Some tools take a third route into the disk using a special driver. That driver can slip past protections which watch normal file access. That is why monitoring low level device access matters as much as monitoring files.

How it works, in plain steps

  1. The attacker needs high level rights, because ordinary users cannot touch raw storage.
  2. Their software opens the storage device as a whole instead of opening single files.
  3. It then writes random data across chosen regions until the original blocks are gone.
  4. Every write also destroys evidence of what the files contained before the damage.
  5. The file system may still mount but return errors whenever it tries to read blocks.
  6. Defenders see unusual raw device access and a very large burst of disk writes.

Real-world example

Picture a hospital night desk where the records are kept in named folders in a cabinet. One thief removes a few folders, so staff notice straight away. Another thief instead pours a bucket of black paint over the whole drawer. The folder labels are still there and the drawer still opens. Yet every page inside is unreadable. There is no way to copy or restore any of them.

Key takeaways

  • Disk content wipe overwrites storage areas, so file level recovery usually fails.
  • It requires raw device access, which is the behaviour most worth alerting on.
  • A sudden flood of input output errors across hosts is a strong warning sign.

In more detail

Disk content wipe is the half of disk wiping that destroys data itself rather than the structures that describe it. The adversary obtains direct access to the storage device and overwrites arbitrary regions of it, often with random bytes, so that whole areas of the volume become meaningless even though the disk is still readable by the hardware. Because the file system metadata may survive in places, a victim can be left with a volume that mounts and reports files that no longer contain anything valid, which is a different failure mode from deleting files one by one. On the detection side the observable behaviour is an unusual pattern of low level access. Processes that never normally open a raw device suddenly handle it, or the system writes an enormous volume of data to disk far beyond ordinary workload, or the file system begins returning input output errors as it reads back corrupted blocks. Third party kernel drivers that expose raw disk access have been used to reach the device without going through normal file application programming interfaces, so driver load events and unsigned or unexpected drivers are worth reviewing. The technique is frequently paired with worm like propagation because the goal is organisation wide unavailability, and it is distinguishable from data destruction of individual files by its scope: sustained direct writes to storage regions rather than targeted deletion inside the file system.

What you will practise

  • Explain how disk content wipe differs from deleting or destroying individual files.
  • Describe why raw device access is required and how third party drivers can provide it.
  • Identify telemetry such as driver load events and unusual raw device handles.
  • Recognise the symptoms of a partially wiped volume that still mounts and reports files.
  • Explain why counting file deletions is not enough to detect this technique.
  • Outline how offline backups and write protection limit the damage of a content wipe.
