T1213.003 Data from Information Repositories: Code Repositories

T1213.003CollectionExtremeTechnique

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

A code repository is an online store for software source code, such as GitHub or GitLab. It keeps a record of every version of every file. This sub-technique means an attacker searches these stores for secrets and valuable code. It is the parent idea, but aimed at code rather than documents.

Why should you care?

Source code explains how a company works from the inside. It often contains passwords, keys and server names that were left in by mistake. The history keeps old values even after somebody removes them. If an attacker reads the code, they can find new ways to break in. They may also steal the product itself, which is a serious loss.

How it works, in plain steps

  1. The parent technique covers shared repositories in general; this one targets code hosting services.
  2. The attacker gets a developer account, or steals an access token for the service.
  3. They copy many projects and read the commit history, not only the newest files.
  4. They search for words such as password, key, token and internal host names.
  5. They read build and deployment settings, where connection secrets are often stored.
  6. They may create their own token so their access survives a password change.

Real-world example

Think of a workshop where every plan the company ever drew is kept in a cabinet. Engineers pull out plans all day, so nobody questions another person reading them. But the old plans still list the safe combination that was changed last year. A new worker copies a stack of plans, including the old ones, and leaves. The workshop looked busy and completely normal the whole time.

Key takeaways

  • Code history keeps old secrets even after they are deleted from the newest file.
  • Watch for an account cloning far more repositories than that developer normally works on.
  • New access tokens and keys created by an account are always worth investigating.

In more detail

Code repositories are version controlled stores of source code, usually with build pipelines, issue tracking and package registries attached, and this sub-technique is the parent behaviour aimed at them. The valuable material is not only the current product source: commit history, configuration files, infrastructure definitions, build scripts, pipeline variables and developer notes frequently contain credentials, internal host names and architectural detail that shortens an adversary's next steps. Access typically uses the same authenticated interfaces as developers, whether a web application, the command line git client or a personal access token, so collection blends into daily engineering activity. Detection relies on repository audit logs and identity data: cloning or downloading an unusual number of repositories, large archive exports, newly created tokens or keys, permission changes, access to private repositories outside the user's team, and activity from a new address or client. The distinction from legitimate work is scope and purpose, because an engineer clones what they maintain, while mining sweeps many repositories quickly.

What you will practise

  • Explain how code repositories differ from document repositories as a target.
  • Describe why commit history and build settings often contain credentials.
  • Identify audit events such as mass cloning and personal access token creation.
  • Explain how stolen source code helps an adversary develop exploits later.
  • Outline practices that reduce the chance of secrets living inside code.
