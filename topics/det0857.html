DET0857 Detection of Employee Names

DET0857Detection StrategyVery hardDetection Strategy

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

An employee name on its own is public and harmless. A list of names with job titles is far more useful to an attacker. The attacker can write to the right person and mention the right project. This detection looks for bulk collection of names rather than for a single public page.

Why should you care?

A message that uses your name and your manager name feels safe. That is why attackers collect names first. Most organisations publish team pages because they help customers and hiring. Removing all of that information would damage the business. The defence is therefore to notice the collection step. A single account that reads the whole staff directory in one minute is a strong signal. It often arrives days before the phishing campaign.

How it works, in plain steps

  1. Your mail server or directory service writes a record each time an account searches for a user.
  2. The detection reads those records and counts how many different users one account looked up.
  3. It compares that count with the normal pattern for the role, such as help desk or recruitment.
  4. It also watches staff pages on your public site for rapid sequential reading.
  5. Deception accounts are checked too, because mail to a name that does not exist shows a harvested list.
  6. When a limit is passed, the rule raises an alert with the account, the count and the time window.

Real-world example

Think of a hotel reception desk with a guest list. Staff may look up one name to connect a call, and that is normal. Now imagine that somebody photographs the entire list in one minute. The list itself is not secret to the staff, but the way it was read is the problem. The receptionist notes the time, the person and the reason given. Your detection is that note. It does not stop the reading, but it tells security that a full list of names has left the building.

Key takeaways

  • Names are public, but bulk name collection is a clear warning sign.
  • Compare directory reads with what the role normally needs to do.
  • Deception entries catch a harvested address list before the phishing starts.

In more detail

This detection strategy covers collection of employee names and job roles, which an attacker uses to build a target list and to make a message look personal. Names are freely available on team pages, conference agendas, professional social networks and mail directory lookups, so the useful signal is not publication but bulk retrieval. The telemetry that makes it visible is directory or address book query logging, mail platform audit records for global address list searches, web access logs against staff pages and deception accounts that should never receive mail. It fails in practice because recruitment, sales and human resources genuinely perform large directory reads every day.

What you will practise

  • Explain how employee names support targeted social engineering.
  • Identify which logs record directory and address book searches.
  • Set a query threshold based on the normal pattern for each role.
  • Design a deception account that reveals a harvested address list.
  • Describe how to respond when bulk name collection is confirmed.
