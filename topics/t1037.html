T1037 Boot or Logon Initialization Scripts

T1037PersistenceExtremeTechnique

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

This is when an attacker puts their own script in a place the computer runs by itself at start or sign in. A script is a small text file with commands. The computer reads and follows those commands. The attacker only has to wait for the next restart or sign in.

Why should you care?

Anything that runs automatically comes back after a reboot. Attackers use this to keep access to a machine for a long time. On a shared or company machine, other users may run the script too. Some of these scripts run with more power than a normal user. Removing the attacker once is not enough if the entry stays.

How it works, in plain steps

  1. The attacker gains a way to run commands on the machine or the user account.
  2. They add their commands to a script or setting that runs at start or sign in.
  3. Windows logon scripts are often stored in a user setting or a policy.
  4. Unix systems read shell profile files and service definitions during start up.
  5. After the next restart or sign in, the script runs again without any help.
  6. If the script runs with higher rights, the attacker gains more power too.

Real-world example

Picture a shared flat with a morning checklist taped inside the front door. Everyone follows the list as they leave. A new line on the list says water the plants. Every flatmate waters the plants every day, without ever asking who added the line.

Key takeaways

  • Automatic startup is one of the most reliable ways to keep access.
  • Compare startup scripts and settings against a known good baseline.
  • Link sign in events to what actually ran straight afterwards.

In more detail

Boot or logon initialization scripts are the scripts and configuration files that an operating system or session manager runs automatically when a machine starts or a user signs in. Because execution is automatic, an entry placed in one of these locations gives an adversary persistence that survives restarts and, in domain settings, can spread to every user who logs on to a host. The mechanism differs by platform and scope: Windows offers logon scripts assigned to users or groups, startup scripts applied through policy, and per-user environment entries; Unix-like systems use shell profile files, system service units and startup scripts; macOS uses login items and per-user agent definitions. Many of these scripts run with higher privilege than the signed-in user, which is why the technique also supports privilege escalation. Detection requires a baseline of which scripts and entries the organisation legitimately deploys, because the scripts themselves are normal administration, and it depends on file and configuration monitoring for changes between baselines plus authentication and process telemetry linking a logon event to unexpected script execution and network activity.
