DET0095 Detect Persistence via Malicious Outlook Rules

DET0095Detection StrategyVery hardDetection Strategy

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

This detection looks for new mail rules that quietly move, forward, hide or delete email. An attacker who gets into an account can add such a rule while the owner is away. The rule then sends copies of messages somewhere else or pushes warnings out of sight. The detection watches the mail service records that describe rule changes.

Why should you care?

Email holds password resets, contracts, invoices and security warnings. A forwarding rule can copy all of it without the owner noticing anything unusual. Rules also let an attacker hide the alerts that would reveal the break in. Because no malware runs on the computer, endpoint tools may see nothing at all. Watching the mailbox itself is the only way to find this.

How it works, in plain steps

  1. The mail service writes an audit record each time a rule is created or changed, naming the mailbox and the operation.
  2. The record includes the rule parameters, such as the target folder and any forwarding address.
  3. The rule looks for forwards to addresses outside the organisation and for rules that delete or hide messages.
  4. It also checks the client used, because a script or a mail protocol tool is unusual for this job.
  5. The detection joins the rule change to the sign in records for the same account, looking for a new location or device.
  6. If a forwarding rule and a suspicious sign in appear together, the alert is escalated immediately.

Real-world example

Think of a household where all letters arrive in one basket by the front door. A visitor quietly adds a note telling the postal worker to leave the bank letters in a bag outside the back gate. The family keeps receiving most mail and notices nothing. Mailbox rules are that note: the mail still arrives, but the important part takes a different path, and the household diary of new instructions is where you find it.

Key takeaways

  • A forwarding or hiding rule is quiet persistence that needs no software on the device.
  • Mail service audit records show the rule, the destination and the client that created it.
  • Always check sign in records for the same account when a new external forward appears.

In more detail

This strategy detects mailbox rules that redirect, forward, hide or delete incoming mail, which attackers create after compromising an account so that replies and security alerts never reach the real owner. The technique matters because a forwarding rule turns a single stolen password into a long term, low noise channel for stealing messages and reset links. Detection works best from the mail service audit records that name the rule operation and its parameters, and it is strengthened by client side process and registry telemetry. The frequent failure is that users create rules every day for ordinary reasons, so the rule must weigh the destination, the folder and the client that made the change. What you will practise

  • Explain how mailbox rules are used to steal mail and to hide security alerts.
  • Read a mail audit record and identify the rule action, destination and client.
  • Write a rule that flags external forwarding and move to deleted or archive folders.
  • Correlate a rule change with sign in records for the affected account.
  • Describe the safe response steps for a confirmed malicious forwarding rule.
