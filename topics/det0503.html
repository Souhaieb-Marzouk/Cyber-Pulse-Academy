DET0503 Behavioral Detection Strategy for Exfiltration Over Symmetric Encrypted Non-C2 Protocol

DET0503Detection StrategyVery hardDetection Strategy

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

Exfiltration means stealing data by sending it out of the network. This detection looks for data leaving inside an encrypted channel, such as a secure copy session. It watches how much data leaves and where it goes. The aim is to catch the theft while the transfer is still running.

Why should you care?

Attackers know that defenders read unencrypted traffic, so they wrap stolen data in encryption. Content inspection then sees only random bytes and cannot help you at all. What stays visible is the size, the direction and the destination of the transfer. Those three facts are enough to raise a useful alert.

How it works, in plain steps

  1. Firewall and network flow records store the bytes sent and received for each session.
  2. The rule computes the ratio of outbound bytes to inbound bytes for each host.
  3. It flags a large outbound transfer to a destination that host has not used before.
  4. It checks the protocol and the port to see whether the traffic is encrypted.
  5. It links the session to the process on the host that owns the connection.
  6. The analyst confirms whether the process and destination fit the host role.

Real-world example

Think of a warehouse where every delivery van is checked at the gate. A driver fills a van with boxes at night and covers them with a heavy tarpaulin. The guard cannot see the boxes, but he can weigh the van on the way out. A van leaving far heavier than it arrived deserves a look. This detection is the weighbridge at the gate.

Key takeaways

  • When content is encrypted, size, direction and destination are your evidence.
  • Compare each host with its own normal outbound volume, not with a global number.
  • The owning process often decides whether a large upload is normal.

In more detail

This strategy detects exfiltration that hides stolen data inside a symmetric encrypted protocol which is not the implant's own command channel, such as an encrypted file transfer or a secure shell session to an unexpected host. The signal is direction and volume: a large one way outbound transfer from a host that normally receives data, to a destination it has never contacted, over a protocol that cannot be inspected. Telemetry comes from firewall session logs, network flow exports with byte counters, proxy logs and endpoint network connection events. It fails in practice because backups, replication and cloud sync also move large volumes outbound, so the destination and the owning process decide the verdict.

What you will practise

  • Explain why encrypted exfiltration defeats content inspection.
  • Name the telemetry that provides byte counts and destination data.
  • Calculate and baseline outbound to inbound ratios for one host group.
  • Link a network session back to the process that created it.
  • Write a pseudo-rule with a volume threshold and an approved backup filter.
