DET0540 Multi-Platform Behavioral Detection for Compute Hijacking

DET0540Detection StrategyVery hardDetection Strategy

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

This detection looks for computers doing work that earns money for someone else. Mining software uses your processors to create cryptocurrency. It slows your systems and it can raise your cloud bill.

Why should you care?

Stolen compute is expensive and it is easy to miss, because the machine still works. A cloud account can spend thousands in a week. Mining also tells you an attacker already has a foothold and may return for other work. Finding it early limits both the bill and the risk.

How it works, in plain steps

  1. The endpoint records every new process with its command line and its parent process.
  2. Container and host monitoring agents record processor usage and memory usage over time for each workload.
  3. Firewalls and routers record outbound connections to pool addresses and the ports used.
  4. Cloud billing tools report sudden increases in compute spend by account and by region.
  5. The platform groups the records by host or workload and compares the pattern with the workload baseline.
  6. A workload with high steady usage, a mining pool destination and an unapproved process becomes an alert.

Real-world example

Think of a shared laundry room in a block of flats. The machines work all day and that is normal. But if one flat runs the dryers all night every night, the neighbour notices the pattern, not just the noise. Steady all night processor use on a laptop is that dryer.

Key takeaways

  • Usage alone is not proof, the destination and the process matter just as much.
  • Cloud spend reports catch mining that endpoint tools never see.
  • Mining is often a sign of a wider compromise, so keep investigating after you stop it.

In more detail

This detection strategy covers the misuse of an organisation compute resources for resource hijacking, matching technique T1496.001, where an adversary runs cryptocurrency mining or similar workloads on your infrastructure. It matters because the impact is direct and financial: stolen central processing unit, or CPU, capacity, rising cloud bills, thermal stress on hardware and a common precursor to wider intrusion activity. The telemetry that makes it possible is process creation records with command lines, container resource metrics, network flow records showing mining pool connections, and cloud cost anomaly reports. It fails in practice because legitimate batch, rendering and analytics jobs also consume every available core, so utilisation alone cannot separate malicious mining from authorised heavy compute.

What you will practise

  • Explain what compute hijacking is and why cryptocurrency mining is its most common form
  • Identify the process, resource metric, network flow and billing telemetry that together reveal mining activity
  • Recognise the command line features that distinguish mining software from legitimate heavy compute jobs
  • Correlate sustained resource usage with outbound connections to mining infrastructure
  • Write a detection rule for unauthorised mining workloads and tune it against approved batch processing
