DET0592 Detection Strategy for Data from Configuration Repository on Network Devices

DET0592Detection StrategyVery hardDetection Strategy

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

Network devices such as routers and firewalls keep a settings file called a configuration. That file is the device's recipe book. This detection looks for people or programs reading, copying or changing those settings without a good reason. It also watches the servers that store copies of the settings.

Why should you care?

A network configuration often lists every subnet, every firewall rule and sometimes a shared password. An attacker who reads it can plan the next step without touching a single host. They can also change it to open a path for themselves. If nobody watches configuration access, that work is invisible. The damage is quiet and can last for months before anyone notices network behaviour that should not happen.

How it works, in plain steps

  1. Network devices send log messages to a central collector. These messages record logins, commands and settings changes.
  2. The rule reads those messages and looks for commands that display or copy the running configuration.
  3. It notes the account name, the source address and the time of the action.
  4. It also watches servers that hold configuration backups for file reads or downloads by unexpected accounts.
  5. Each action is compared with the approved change windows and the list of administrators.
  6. Anything that is not an approved administrator or an approved window becomes an alert.

Real-world example

Think of a hospital sign in sheet at the pharmacy. Every nurse who takes out medicine writes their name, the time and the amount. The sheet alone does not stop theft. It does mean that a missing box can be traced to a name and a minute. If someone signs in at three in the morning with a name nobody recognises, that line stands out at once. Network device logging works the same way. The device logs are the sign in sheet, and the approved change window is the shift roster.

Key takeaways

  • Device settings are as sensitive as the passwords inside them, so reading them counts as an event.
  • You must collect device logs centrally, or the activity happens only in a local buffer nobody reads.
  • Separate routine change windows from everything else first, or the alert list will be unusable.

In more detail

This strategy detects the collection of configuration data held on network devices, which ATT&CK tracks as T1602. Router, switch and firewall configurations describe the entire topology, address plan, access control lists, virtual private network settings and frequently reusable management credentials, so a single successful read is often equivalent to a network map. Detection depends on three telemetry streams that rarely share a platform: authentication and command accounting from the device itself through syslog or terminal access controller style accounting, configuration change notifications and simple network management protocol traps, and file integrity or access telemetry on the servers where configuration backups are stored. The pattern worth alerting on is a read or transfer action against configuration storage from an unusual account, host or time, and routine change windows are the dominant source of noise. The common failure mode is that many organisations do not centralise device logs at all, so collection must be proven before the rule can be trusted.

What you will practise

  • Describe why network device configuration data is a high value collection target
  • Name the telemetry that records configuration access on routers, switches and firewalls
  • Explain how command accounting differs from authentication logging on network devices
  • Correlate configuration read or copy actions with account, source address and change window
  • Identify configuration backup repositories as a second place the same data can be stolen from
  • Build an approved administrator and change window baseline to keep false alerts low
