T1680 Local Storage Discovery

T1680DiscoveryExtremeTechnique

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

This is when an attacker lists the disks and storage on a computer and checks their details. They want to know how big each disk is, how much space is free, and how it is formatted. This is a quiet step that comes before bigger actions. It tells the attacker where the data lives.

Why should you care?

Knowing where storage sits lets an attacker plan the fastest way to damage or steal data. In a ransomware case, the list of volumes shows what to encrypt and whether free space allows it. In a cloud case, it shows which storage volumes hold the important data. Because the commands used are ordinary administrative tools, this step is easy to dismiss as normal work. Watching for it gives you a chance to act before the damage starts.

How it works, in plain steps

  1. The attacker runs standard commands on the machine to list disks, partitions and volumes.
  2. The output shows each disk's size, free space, file system type and mount point.
  3. On Windows they query logical disks, and on Linux they list block devices and free space.
  4. On a virtualisation host, they list the datastores and the virtual disk files inside them.
  5. They may also call a cloud provider's interface to describe block storage volumes.
  6. They use this list to decide which disks to encrypt, copy or access directly.

Real-world example

Think of a removal company that has been hired to clear a large house. Before lifting anything, the foreman walks every room with a clipboard. He notes the furniture, the room sizes and which cupboards are locked. Nobody thinks this is strange, because measuring comes before moving. An hour later, the vans arrive and everything goes into the right crates without a wasted trip.

Key takeaways

  • Storage inventory is a planning step that often comes just before damage.
  • The tools involved are normal, so judge them by timing, parent process and host role.
  • Hypervisor and cloud storage listings are as important to watch as endpoint ones.

In more detail

Local storage discovery is the enumeration of drives, volumes and partitions on a host or hypervisor, together with their attributes: capacity, free space, file system type, mount path, device type and volume serial number. The information is cheap to obtain and directly shapes what the actor does next. On Windows, queries through the management instrumentation command line or the PowerShell drive cmdlet return logical disks and mapped network drives, and low-level interfaces expose the drive type. Linux offers tools that list block devices, partitions, hardware and free space, while macOS provides a disk utility command and a system profiler data type that also reports file system and physical drive details. On hypervisors the same need is met by command line storage listings that reveal attached datastores and the virtual disk files inside them, which is a direct precursor to mass encryption or deletion. Cloud infrastructure adds provider commands that list and describe block storage volumes. Detection rests on process telemetry and command history: these utilities are legitimate administrative tools, so the signal is a burst of storage enumeration from a scripting host, a management agent or an unusual parent process, especially on a host that does not normally run inventory jobs. Enumeration appearing shortly before volume level access or encryption is the pattern worth alerting on.
