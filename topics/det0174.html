DET0174 Detection Strategy for Exploitation for Credential Access

DET0174Detection StrategyVery hardDetection Strategy

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

Software sometimes has a flaw that lets an attacker run their own commands. This detection looks for the moments right after that, when the attacker tries to steal passwords or keys. It catches credential theft, not the flaw itself.

Why should you care?

One stolen password can open many systems, and staff reuse passwords. Attackers prefer this route because it avoids noisy guessing. The flaw may not be in your patch list yet, so signature tools stay quiet. Watching behaviour after the flaw is used gives you a chance to react anyway.

How it works, in plain steps

  1. Attackers usually reach credential material through a program that is already running, such as a web server or a database service.
  2. Windows records each new process, including the program that started it and the full command line.
  3. The detection looks for a service program starting a command shell, a scripting interpreter or a credential dumping tool.
  4. It also uses endpoint agent records that show one process reading the memory of another process.
  5. It then checks authentication logs for the same service account signing in from a new host soon afterwards.
  6. When the process behaviour and the authentication change happen close together, the alert is raised for urgent review.

Real-world example

Think of a bank where tellers follow a strict script. If a teller suddenly walks into the vault room and starts photographing the ledgers, the cameras catch it. The bank does not need to know how the teller got the vault code. The odd behaviour inside the building is enough to raise the alarm.

Key takeaways

  • You often cannot detect the exploit itself, so detect what the exploited process does next.
  • A service program spawning a shell or reading another process memory is a strong signal.
  • Pair process behaviour with authentication records to confirm a real takeover.

In more detail

This strategy detects exploitation for credential access, where an adversary takes advantage of a software vulnerability to reach credential material that normal access controls protect. The value of the technique is that it turns a code execution flaw into an account takeover, so detection must focus on the moments after exploitation: an application process spawning a command shell, a web server reading a credential store or process memory, or a service account authenticating from a host it never normally uses. The telemetry that enables this is process creation with parent lineage, endpoint detection and response memory and injection telemetry, application error and crash logs, and authentication records. The main weakness is that a patched or unknown vulnerability produces no signature, so the rule detects consequences rather than the exploit itself.

What you will practise

  • Explain how exploitation turns a code execution flaw into credential theft
  • Identify process lineage patterns in which a service process escalates into shell or memory access
  • Use endpoint memory and injection telemetry to confirm credential access behaviour
  • Correlate process level signals with authentication anomalies for the same account
  • Prioritise response actions that contain the host and rotate affected credentials
