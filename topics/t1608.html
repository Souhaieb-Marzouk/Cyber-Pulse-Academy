T1608 Stage Capabilities

T1608Resource DevelopmentExtremeTechnique

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

Staging means getting things ready before an attack. In this technique an attacker prepares tools, files and services in advance. They place them on computers or online services they can reach but do not own.

Why should you care?

Prepared infrastructure makes an attack fast and hard to trace. The attacker can rent a server, use a free web service or take over someone else machine. When defenders find the staging point, it often belongs to an innocent third party. Knowing this technique helps you spot preparations before the attack reaches you.

How it works, in plain steps

  1. The attacker first decides what tools and payloads the operation will need.
  2. They obtain hosting, either by renting it, compromising it or using a free service.
  3. They upload files, web pages or applications to that prepared hosting location.
  4. They install a certificate so their traffic looks like normal encrypted web traffic.
  5. They prepare domains, addresses and accounts that their tools will contact later.
  6. Later steps, such as phishing or tool download, reuse this prepared setup.

Real-world example

Think of a burglary crew that never stores tools at the target house. Instead they rent a garage across town, stock it with ladders and cutters, and hide a spare key under a nearby stone. Only on the night do they collect everything. If the police find the garage, it is rented under a false name and the crew is nowhere near it. Staging capabilities is that garage. The work happens early and far away, so by the time the attack begins the difficult preparation is already finished and invisible.

Key takeaways

  • Watch for internal hosts contacting newly created or low reputation infrastructure.
  • Treat unusual file downloads from code hosting or paste sites as suspicious.
  • Review cloud account activity for resources you did not create.

In more detail

Stage Capabilities covers the adversary work that happens before an intrusion, when tools, payloads and supporting services are placed on infrastructure from which they can later be used. The capabilities are usually ones the adversary either built or bought, and the hosting is usually either rented, compromised or borrowed from a legitimate web service, which is what makes this activity hard to attribute and hard to remove. Typical staging includes web content prepared for a drive by compromise or as the landing page behind a phishing link, malware or tooling uploaded somewhere the victim network can reach so it can be pulled in later, a Transport Layer Security certificate installed so follow on command and control traffic appears as ordinary encrypted web traffic, and accounts or serverless applications provisioned on cloud platforms to receive data or redirect requests. Staging can also include purchasing domains, registering lookalike names, and preparing email sending infrastructure. Most of the technical artefacts live with the provider rather than the victim, so detection is often retrospective: web proxy and domain resolution records showing internal hosts contacting newly registered or low reputation infrastructure, unexpected file downloads from code hosting or paste services, and cloud audit logs showing resource creation from unfamiliar accounts or regions. Legitimate business use of the same services exists, so context about who created the resource and when matters more than the service itself.

What you will practise

  • Explain why adversaries prepare infrastructure before an intrusion begins.
  • Describe the kinds of capabilities that are staged for later use.
  • Identify the log sources that can reveal staging indirectly.
  • Explain why staging on third party services complicates attribution and removal.
  • Compare legitimate use of cloud and code hosting services with staging behaviour.
  • Describe how staged resources support later access or command and control.
