T1218.011 System Binary Proxy Execution: Rundll32

T1218.011StealthExtremeTechnique

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

A dynamic-link library, usually shortened to DLL, is a file that holds reusable code which other programs can call. rundll32.exe is a signed Windows program that loads such a file and calls one function inside it. It does this without registering anything.

Why should you care?

An attacker can point rundll32 at their own library file and choose the function that starts the payload. It can also run JavaScript and open Control Panel items, which gives several routes to the same goal. rundll32 appears constantly in normal Windows activity, so simple allowlists and name checks are noisy and weak. If you ignore the arguments, you will not spot the malicious cases.

How it works, in plain steps

  1. A library file, or DLL, holds functions that other programs can call, and DLL means dynamic link library.
  2. rundll32.exe loads such a file and calls one function by name. It does not register the file.
  3. An attacker can point it at their own library file and the function inside that starts the payload.
  4. It can also open Control Panel items, which are settings tools stored in files ending with .cpl.
  5. Another form uses a script engine inside Windows to run JavaScript given on the command line.
  6. It can even use genuine Windows library files as a bridge, so the whole chain looks more normal.

Real-world example

A night manager holds a master key and is allowed into any room to fix problems. A thief takes that key and opens three rooms in one corridor, taking a laptop from each. The door logs show valid key use in every room, so the system reports nothing unusual at all. Only the pattern, three rooms in four minutes, tells the real story.

Key takeaways

  • rundll32 runs library functions and is normal Windows traffic, so context decides everything.
  • Arguments containing javascript, script or a web address are strong warning signs.
  • Look at which library it loads and what it starts afterwards.

In more detail

Rundll32.exe loads a dynamic-link library and calls a named exported function inside it, doing so without registering anything, which distinguishes it from the registration utilities in the same technique family. That simple capability has several abuse shapes. The classic form supplies an attacker DLL and function name directly, avoiding the shared module approach of loading code through a host process. A second form launches Control Panel items through the undocumented shell library functions Control_RunDLL and Control_RunDLLAsUser, which is also what happens when a user double-clicks a .cpl file. A third form reaches a script engine through the mshtml library, running JavaScript supplied on the command line and able to fetch a remote scriptlet, behaviour historically associated with fileless malware such as Poweliks. A fourth uses genuine signed system libraries such as zipfldr.dll or ieframe.dll as a bridge that starts other content, so the chain borrows additional legitimacy. Rundll32 also resolves the requested function name by checking wide Unicode and then ANSI variants, and tolerates some extra characters, so the same library can be invoked under differently formatted names that simple string matching may not catch. Because rundll32 appears constantly in normal Windows activity, detection depends on context rather than the process name: command lines containing a web address, a script or javascript prefix, or a path outside the system directory, image loads of unsigned or user-writable libraries, and child processes that a library call would not normally produce.
