DET0504 Detect Abuse of Dynamic Data Exchange (T1559.002)

DET0504Detection StrategyVery hardDetection Strategy

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

Dynamic Data Exchange, or DDE, is an old Windows feature that lets programs send messages to each other. Office documents can use it to start another program. This detection looks for an office file that starts a command shell. The goal is to catch this without any macro being used.

Why should you care?

Many companies block office macros, so attackers look for other ways to run code. DDE still works in some configurations and needs no macro at all. The user only has to accept one prompt on screen. Because the technique is rare today, the activity stands out clearly in your logs, which makes it a high value alert.

How it works, in plain steps

  1. Windows records each new process, including the program that started it.
  2. The rule looks for an office application as the parent of a shell or scripting host.
  3. It checks the command line for signs of a script, a remote address or an encoded string.
  4. It also checks for the office document that started the chain.
  5. A second stage looks for network connections or new files from the child process.
  6. The alert shows the document, the user and the child command.

Real-world example

Think of a hotel front desk that can call any service in the city. A guest cannot call out directly, so he asks the receptionist to order him a taxi. The call looks completely normal, because it comes from the desk phone. This detection checks who asked for the taxi, and whether that guest should be in the building at all.

Key takeaways

  • DDE can run commands without macros, so macro controls do not stop it.
  • The parent image is the key field: look for office applications starting a shell.
  • Rare techniques deserve high severity, because they are rarely benign.

In more detail

This strategy detects abuse of Dynamic Data Exchange (DDE), an old Windows feature that lets one application ask another to run commands, and which office documents can trigger without using macros at all. The signal is an office application process acting as the parent of a command shell, a scripting host or another binary it should never start, usually with a command line that points at a second document or remote content. Telemetry includes process creation with parent image and command line, office application event logs, and file or network events from the child process. It fails in practice because very few modern documents use DDE, so alerts are rare but must still be checked against line of business templates that rely on it for data refresh.

What you will practise

  • Describe what Dynamic Data Exchange is normally used for.
  • Explain why DDE can run commands without using macros.
  • Name the process creation fields that reveal the chain.
  • Distinguish approved line of business DDE templates from malicious documents.
  • Write a pseudo-rule that matches office applications starting a shell.
