DET0244 Detection Strategy for Login Hook Persistence on macOS

DET0244Detection StrategyVery hardDetection Strategy

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

This detection looks for a setting on a Mac that runs a program each time someone logs in. That setting is called a login hook, and it is stored as a preference for the login window. Attackers use it so their code starts again after a restart. The rule watches who changed it and what program it points to.

Why should you care?

Persistence means the attacker keeps coming back without breaking in again. A login hook runs with the rights of the person signing in, so it needs no special permission. It also runs early, before the user opens anything. Few modern Macs use this setting, which makes an unexpected change stand out.

How it works, in plain steps

  1. A program writes a preference that names a script or command for the login window.
  2. The system stores that preference and notes the change in its system logs.
  3. The rule watches for writes to that preference, by a shell command or by a file edit.
  4. It records which account made the change and where the named script lives.
  5. At the next sign in, the login window starts the named program.
  6. The rule matches the change with the later start, and compares both with the managed baseline.

Real-world example

Think of a night watchman who is told a friend will close the building tonight. The note is enough for the watchman to hand over the keys. The login hook is that note: the system trusts it, so whatever the note names is run at every sign in. The guard should ask who wrote the note and where the friend lives.

Key takeaways

  • A login hook is a note the system trusts at every sign in.
  • Check where the named script sits, because user writable paths are a warning sign.
  • Compare with the managed policy, since some fleets set hooks on purpose.

In more detail

This strategy detects the installation of a login hook on macOS, a preference that makes the system run a chosen command or script every time a user signs in at the graphical login window. The technique matters because login hooks survive reboots, run as the signing in user, and are an old mechanism that few administrators still use, so a hook pointing at a script in a user writable directory is a strong persistence signal. Detection depends on unified log entries for the login window process, endpoint process and file events that record preference writes, and configuration management inventory of hooks applied by policy. The main way it fails is that managed fleets may apply hooks by policy for legitimate reasons and legacy images may carry old ones, so the rule must compare the hook value with what management declares and with where the target file lives.

What you will practise

  • Describe what a macOS login hook is and when it executes.
  • Identify the log and event sources that record login window preference changes.
  • Explain why the location of the named script changes the risk.
  • Correlate the preference change with the process that later starts at sign in.
  • Separate managed hooks applied by policy from hooks written by hand.
  • Recognise related persistence locations that should be checked at the same time.
