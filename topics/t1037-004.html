T1037.004 Boot or Logon Initialization Scripts: RC Scripts

T1037.004PersistenceExtremeTechnique

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

RC scripts are small startup files on Unix and Linux systems. The computer reads them while it is booting and runs the commands inside. Because boot work needs high power, these files run as the root user, the most powerful account.

Why should you care?

Anything written into these files runs as root at every restart. That means an attacker can keep access for as long as the file stays changed. It happens during boot, before most monitoring tools and users are active. Many teams never check these files after the system is set up.

How it works, in plain steps

  1. At boot the service manager works through its startup list and runs the startup scripts in order.
  2. Each script contains shell commands that start services, mount disks or clean up files.
  3. An attacker with root access adds a line that launches their own program or downloads one.
  4. They may also replace a binary the script already calls, so the file itself looks untouched.
  5. On the next restart the system runs the added line with root privileges before anyone logs in.
  6. On some appliances the change must be rewritten at every boot, so the attacker hides it in a script that runs early.

Real-world example

Imagine a supermarket with an opening routine taped to the wall of the night office. It lists what the night team must do: switch on the lights, unlock the front doors, start the fridges. If someone adds a line saying to leave the side door open at four in the morning, the night team simply follows the list. Nobody broke in, because the door was opened from the inside on schedule.

Key takeaways

  • Startup scripts run as root while the machine boots, so they are a strong persistence spot.
  • Compare the contents of these files against a known good copy after every change.
  • Keep boot files writable only by root, and watch for new paths or commands inside them.

In more detail

RC scripts are the traditional Unix startup files, such as rc.local and the per-runlevel scripts under an rc directory tree, that a system executes while booting. They let an administrator define which services start and in what order, and they run as root, so editing one turns a plain text file into code that executes with full privilege on every boot. An adversary appends a binary path or shell command to a file such as rc.local or rc.common and waits for the next restart, after which the code is part of the normal startup sequence and leaves no interactive logon behind. The technique is attractive on lightweight or embedded systems that boot straight into a root context, and on ESXi hypervisors, where most system files live in memory and are discarded on shutdown, persistence in a startup script is one of the few changes that survives a reboot. Detection is mainly file integrity: baseline the contents and metadata of those scripts and alert on modification, new executable paths they reference, changed file permissions, and boot-time child processes whose parent is the init or service manager chain rather than an interactive session.

What you will practise

  • Describe what RC scripts do during a Unix-like system startup and which privilege they use.
  • Explain how adding a command to a startup script produces persistence across reboots.
  • Identify the artefacts, such as changed file contents and boot-time processes, that reveal the abuse.
  • Explain why this approach is especially relevant on appliances and hypervisors.
  • Recognise where RC scripts have been replaced by newer service managers and why that matters.
