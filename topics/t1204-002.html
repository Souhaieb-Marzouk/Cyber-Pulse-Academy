T1204.002 User Execution: Malicious File

T1204.002ExecutionExtremeTechnique

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

This means the attacker sends you a file and needs you to open it. The file might look like a document, an invoice or a photo. Opening it starts the attacker's code. A link is not needed, because the file itself carries the trick.

Why should you care?

People open files all day for their work, so an attached file seems normal. Attackers copy names and formats your team already uses. A password protected file may slip past email scanning, because the scanner cannot read inside. If you open it, the attacker gets a foothold on your machine.

How it works, in plain steps

  1. The attacker builds a file that runs code when opened, such as a document with a script inside.
  2. The file is sent as an email attachment or placed in a folder you can reach.
  3. They may protect the file with a password and send the password in the same message.
  4. You open the file, and the program that handles that type starts it.
  5. The file triggers its hidden action, or it points to another file that does.
  6. That action starts tools, sets up persistence, or opens a connection back to the attacker.

Real-world example

Think of a shared flat kitchen where a box arrives labelled as a birthday cake. Everyone trusts the label, so someone opens it. Inside is not cake but a note telling the reader to leave the back door open. The delivery looked normal, and the harm only started when the box was opened.

Key takeaways

  • Never open unexpected attachments, even when the file type looks familiar.
  • A downloaded file carries origin information, which helps you trace where it came from.
  • Watch for document or archive programs starting a shell, script host or downloader.

In more detail

Malicious file is the sub-technique where the adversary needs the victim to open a file, rather than click a link. The parent technique covers both cases; here the payload or the trigger travels as an object. The types used are chosen for what the operating system does when the file is double clicked: documents that run macros or embedded objects, shortcuts and installer packages that point at another program, registry files that change configuration, and disc image or archive containers whose real payload is only visible after mounting or extracting. Distribution is usually a phishing attachment, but the same file may simply be left in a shared folder or on a desktop after internal movement, and password protection or a familiar file name is often used to get past mail inspection and past the victim's hesitation. Detection starts with mail and web download records that show the file arriving, then file creation and execution evidence: Mark of the Web style download origin metadata, a document reader or archiver process spawning a shell or scripting host, the payload process writing to a start-up location, and the whole tree being one or two steps removed from the user's own open action. The decisive question is who initiated the process, because user driven file execution looks different from a service starting the same program.
