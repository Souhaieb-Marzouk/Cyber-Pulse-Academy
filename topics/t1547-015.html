T1547.015 Boot or Logon Autostart Execution: Login Items

T1547.015PersistenceExtremeTechnique

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

A login item is an application, document, folder, or server connection that macOS opens automatically when you sign in. Software often adds one so a chat or music program is ready after you log in. An attacker can add a login item that starts their own program too.

Why should you care?

Login items run quietly at the start of every session, so the attacker's program returns without any action from you. Some kinds of login item are hidden from the settings window, which makes them hard for a user to find and remove. Others can hide the application when it starts, so you never see a window appear. Because signing in is routine, the behaviour attracts no attention.

How it works, in plain steps

  1. macOS keeps two ways to register a login item: a shared file list and the service management framework.
  2. A shared file list item appears in System Settings and opens the named application or document at login.
  3. The framework route asks the system service manager to start the program when the user signs in.
  4. Framework items are not shown in the settings window and only their creator can remove them.
  5. An attacker registers a payload through either route, often with a familiar name and icon.
  6. Detection lists login items per user, checks where each program lives, and verifies its signature.

Real-world example

Picture a hotel where guests leave a card at reception asking for a wake-up call or a taxi at seven. Reception reads the cards each morning and fulfils every request. A stranger adds a card asking for a car to be waiting at the staff entrance. Reception arranges it politely, because the card looks just like all the others.

Key takeaways

  • List login items for every user, because some kinds are not visible in the settings window.
  • Check where the named program lives and whether it is signed by a known developer.
  • Remember that a program can launch hidden, so a session with no visible window proves nothing.

In more detail

Login items are macOS objects that launch automatically when a user signs in, and adversaries add them so a payload starts with each session. They can be registered through the Service Management framework, which delegates the launch to the system service manager and hides the item from the user interface, or through a shared file list, which appears in System Settings and opens applications, documents, folders, or server connections. The shared list route can be driven by scripting, including AppleScript, and the framework route is reachable through the enable call in the service management programming interface. The two routes leave different artefacts: a shared file list entry is recorded in a per-user login items property list and can be enumerated from the command line, while a framework item is described by service registration state and can only be removed by the application that created it. Defenders baseline login items per user, review the property list and service records for unexpected bundles, and verify the signing identity and location of any program named there.

What you will practise

  • Explain what a macOS login item is and when the system starts it.
  • Compare the shared file list route and the service management framework route for registering login items.
  • Describe why framework registered items are invisible in the user interface and are tied to their creator.
  • Detect suspicious login items using per-user enumeration, path review, and signature checks.
  • Explain how scripting can create a shared file list login item at logon.
  • Explain how this sub-technique differs from other macOS boot and logon autostart techniques.
