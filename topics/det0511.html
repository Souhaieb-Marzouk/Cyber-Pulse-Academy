DET0511 Detection of Data Access and Collection from Removable Media

DET0511Detection StrategyVery hardDetection Strategy

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

This rule looks for someone copying many files off a removable drive. A removable drive is a memory card or an external disk that you can plug in and take away. These drives often hold data that is saved nowhere else. The rule watches for a burst of file reads from that drive, and for the tools used to do it.

Why should you care?

Data on a removable drive is often not covered by the same protection as data on a server. It may hold camera footage, equipment exports or field notes that no one classified. Copying it leaves almost no trace in most file systems. File system logging usually records changes, not reads. A burst of reads from one device is a small but useful signal that this is happening.

How it works, in plain steps

  1. The agent records when a new volume is mounted, together with its drive letter and device identity.
  2. It also records file access events that name a path on that volume, when read auditing is enabled.
  3. The rule counts how many distinct files one process or user touched on the volume in a short window.
  4. Tools that copy or compress whole folders are weighted more heavily than a normal document viewer.
  5. Process records are checked to see whether the copying process is a signed backup or sync agent.
  6. A high file count from a non backup process raises the alert and starts a review of the device.

Real-world example

Think of a till receipt at a shop. The drawer opens many times a day and nobody counts the coins. But if one cashier opens the drawer forty times in five minutes, a supervisor walks over. This rule is that supervisor for removable drives.

Key takeaways

  • File systems usually log changes on removable media, not reads, so read auditing must be turned on.
  • The volume mount record tells you when to start looking, but it is not evidence by itself.
  • Compare the file count against the user normal behaviour before you decide the event is serious.

In more detail

This detection strategy covers collection of data from removable media, the technique tracked as T1025. Removable drives are usually outside endpoint backup, data loss prevention coverage and version control, so copying their contents is a quiet way to gather documents, exports and media that may be more sensitive than anything on the laptop itself. The telemetry that makes this visible is file access events that name the drive path, volume mount records that tell you when a device appeared, process creation for copy and archive utilities with removable drive arguments, and the outbound transfer that usually follows. The failure mode is that most operating systems only log writes and deletions on removable volumes by default, so without read auditing the technique is largely invisible and the rule degrades into watching for the drive itself rather than the collection.

What you will practise

  • Explain why removable media are attractive for collection and why reads are rarely logged by default.
  • Identify the telemetry that records a volume mount and the file access events that follow it.
  • List the copy, archive and synchronisation tools that commonly appear in these events.
  • Set a file count threshold that reflects the normal work of the user group being monitored.
  • Correlate a removable drive collection burst with later outbound network transfers.
  • Describe how to preserve the device as evidence before it is returned or wiped.
