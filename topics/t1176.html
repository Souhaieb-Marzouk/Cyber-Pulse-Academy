T1176 Software Extensions

T1176PersistenceExtremeTechnique

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

A software extension is an add-on that gives a program extra features, such as a browser add-on or a plugin for a code editor. This technique is when an attacker uses an extension to keep a way back into your computer.

Why should you care?

Extensions often ask for wide permissions, such as reading every web page you open. They run inside a program you already trust, so your defences may not stop them. Users install them by choice, and attackers can also add one silently. This makes them very hard to notice.

How it works, in plain steps

  1. Programs such as browsers and code editors can load extra parts called extensions.
  2. An extension inherits much of the access of the huge program that loads it.
  3. Attackers publish fake extensions that look just like well known real ones.
  4. They can also write an extension straight into a profile file or policy.
  5. The extension then starts every time you open the program, so it persists.
  6. It can read data, contact the attacker, or open a hidden tunnel out.

Real-world example

Think of a block of flats where each tenant may fit their own lock to the shared doors. A new tenant fits a lock that looks standard. The landlord checks only the main entrance. Each evening the tenant opens every flat with a key cut from that one lock, and nothing in the building looks broken.

Key takeaways

  • Treat extensions as trusted code with access to the data of the host program.
  • Keep a list of approved extensions and alert when a new one appears.
  • Watch the host program after start for strange child processes or connections.

In more detail

Software extensions are the modular add-on components that browsers, code editors, chat clients and similar platforms load to gain extra features, and they matter to attackers because the host application loads them automatically and hands them a share of its own permissions. The parent technique covers the whole family; the abuse can be split into three behaviours. The first is installation by deception, where a fake or typosquatted extension in a public marketplace convinces a user to add it. The second is installation without consent, where an attacker who already holds a session on the host writes the extension into a profile directory, a configuration file, a registry key or a management policy so that the host loads it silently at the next start. The third, and the hardest to spot, is the abuse of a benign extension that is already trusted: a remote access tool that can tunnel traffic or a code editor that can open a terminal becomes the delivery path with no malicious file at all. The persistence is durable because extension configuration usually syncs with a user account, so a reimaged machine can pull the same extension back. Artefacts that support detection include the extension directory and its manifest or metadata files, install and update events recorded by the marketplace client or the platform management channel, and the behaviour of the host process after start, such as unexpected child processes, network connections or file reads outside the host's normal working set. Because extensions are genuinely common and genuinely useful, defenders usually succeed by maintaining an inventory of approved extensions and by alerting on additions that no change record explains.

What you will practise

  • Define a software extension and explain why it inherits the rights of its host program.
  • Describe the three ways a malicious extension can end up on a system.
  • Explain how extension settings can persist and return after a rebuild.
  • Identify the files, directories and management channels that list installed extensions.
  • Explain why abuse of a benign extension is harder to detect than a malicious file.
