DET0291 Detection of Cloud Service Dashboard Usage via GUI-Based Cloud Access

DET0291Detection StrategyVery hardDetection Strategy

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

A cloud dashboard is the web page where you manage your cloud account. Administrators use it every day to check and change resources. An attacker who has stolen a password can use that same page to look around your environment. This detection watches dashboard sessions that do not match how that account normally behaves.

Why should you care?

The dashboard is a normal, fully supported way to work, so blocking it would break the business. Detection built only for command line tools often misses it, because the browser makes the calls instead of a script. A browsing session can reveal a great deal before anyone notices. Comparing a session with the account history is what makes it visible at all.

How it works, in plain steps

  1. The cloud provider records each console sign in, including the account, the source address and the browser string.
  2. The rule keeps sign ins that succeeded and that came from a browser rather than a command line tool.
  3. It then reviews the read only calls that follow, such as listing resources or reading configuration.
  4. A comparison with the last thirty days shows whether this identity or this address is new.
  5. Sessions that read many different services in a short time are scored higher than routine checks.
  6. The analyst confirms the session with the account owner before treating any change as hostile.

Real-world example

Picture a warehouse where staff may use a browser tool to look at the stock system. Using the tool is not a crime, and most people use it every single day. The interesting part is who signs in, from where, and how much they browse. A brand new visitor who opens every shelf in ten minutes deserves a second look.

Key takeaways

  • Console use is normal, so the alert depends on the identity and the browsing pattern.
  • Browser based access bypasses detection that only watches command line tools.
  • Confirm a new session with the account owner before you treat it as an incident.

In more detail

This strategy detects hands on keyboard use of a cloud provider management console, which adversaries use to browse and operate an environment with stolen credentials while avoiding the command line tooling that most cloud detections watch. The technique matters less for what the dashboard does and more for what it implies: a human is exploring the environment interactively, often minutes after a suspicious sign in and before any resource changes appear. The telemetry comes from cloud audit records for console sign in, the client user agent and application name that identify a browser, and the read only enumeration calls that follow the session. It fails because legitimate administrators use the console constantly, so the rule must compare a session against the established behaviour of that identity instead of flagging console use on its own.

What you will practise

  • Explain why a management console session can evade command line detection.
  • Read console sign in records and identify the fields that mark a browser session.
  • Summarise the enumeration calls that follow a session into a behaviour profile.
  • Compare a live session with the historic behaviour of the same identity and address.
  • Verify a suspicious session with the account owner without alerting an attacker.
