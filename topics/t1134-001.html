T1134.001 Access Token Manipulation: Token Impersonation/Theft

T1134.001Privilege EscalationExtremeTechnique

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

This is when an attacker copies the digital pass that another user already has on the same computer. The copied pass is then given to a single thread, which is the small worker inside a program. That worker can then do things as the other user, such as open protected files, without knowing that user password.

Why should you care?

The victim user may already be logged in, so their pass sits in the memory of a running program. An attacker with administrator rights can copy it and act as them. No password is needed and nothing obvious breaks. The copying step is the moment to detect, because after it the activity looks like the real user working.

How it works, in plain steps

  1. A logged-on high privilege user owns a pass that lives in the memory of their programs.
  2. The attacker, already an administrator, finds that program and reads its pass.
  3. A Windows function makes a copy of the pass, and the copy is called a duplicated token.
  4. Another function lets one worker thread inside the attacker program use that copy.
  5. The thread now opens files, registry keys or services as the other user.
  6. When the work finishes, the thread returns to its own weaker identity.

Real-world example

Think of a hospital night shift where the senior nurse leaves their badge on the desk while checking a patient. A visitor copies the badge code onto a spare blank badge. Now a single trip to the medicine cupboard opens for the visitor. The visitor never took the badge, and the nurse still has it, so nobody notices anything missing. The cupboard log only says the badge was used.

Key takeaways

  • Theft copies a pass that already exists, so no password and no new logon are required.
  • The stolen identity is used by one thread, not by the whole program.
  • Look for actions taken by an account that has no matching logon event on that machine.

In more detail

Token impersonation or theft is the token-focused behaviour where an attacker duplicates an access token that already exists in memory and then attaches that copy to a thread inside a process they control. Windows exposes duplication interfaces that clone a token handle from one process, and separate interfaces that let a thread adopt the cloned token temporarily, so the thread acts as the token owner for the duration of the impersonation while the owning process keeps its original identity. Attackers choose this path when the target account already holds an interactive session on the host but has no network logon to reuse, because the in-memory token needs no password and no fresh authentication. The artefact is a process whose threads are performing actions as one account while the process itself was created by another, which surfaces as handle duplication activity, mismatched user fields in access logs, and file or registry writes attributed to an account with no matching logon event on that host. Distinguishing it from legitimate use depends on context: service accounts and backup agents impersonate callers by design, so look for impersonation on hosts and by processes that never normally do it, and correlate the adopted identity with remote authentication that follows.

What you will practise

  • Explain how a token is duplicated from an existing process and then attached to a thread.
  • Describe how this sub-technique differs from the parent technique Access Token Manipulation.
  • Compare token impersonation with creating a new process from a token and with making a new token.
  • Identify which host and network logs show an account acting without a matching logon.
  • Explain why service accounts make normal impersonation look similar to this behaviour.
