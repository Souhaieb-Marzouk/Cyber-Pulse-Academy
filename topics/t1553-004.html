T1553.004 Subvert Trust Controls: Install Root Certificate

T1553.004Defense ImpairmentExtremeTechnique

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

A root certificate is a master key that tells your computer which secure websites to trust. This technique is when an attacker installs their own root certificate on your machine. After that, the computer trusts fake secure websites that the attacker controls.

Why should you care?

Secure browsing depends on trusting the right authorities. If an attacker adds their own, every lock icon stays green while traffic is read or changed. Login details can be captured without any warning. The change also persists, so it keeps working long after the first intrusion.

How it works, in plain steps

  1. A certificate authority is an organisation that issues certificates proving a website is genuine.
  2. Your computer and browser keep a list of which authorities they already trust.
  3. The attacker installs a root certificate they control into that trust list.
  4. They then create certificates for real websites, signed by their own root.
  5. Windows accepts those certificates, so the browser never shows you any warning.
  6. The attacker can read or alter traffic between you and the real site.

Real-world example

Picture a hotel where the front desk gives each guest a key card and keeps a list of which keys are valid. An attacker walks behind the desk and adds their own blank cards to the accepted list. Later they cut a card for any room and the lock opens it happily. Nothing about the door changed; the list of valid keys did.

Key takeaways

  • The list of trusted root certificates is a high-value security setting.
  • Alert on any addition to the root store that was not part of a managed update.
  • Remove unknown roots and rotate any credentials used while they were present.

In more detail

Operating systems and browsers decide whether to trust a secure connection by walking a certificate chain up to a root certificate held in a local trust store. This sub-technique covers the installation of an adversary-controlled root certificate into that store, which turns the insertion into a lasting capability: every certificate signed by that root is accepted without warning, so spoofed websites load cleanly and encrypted traffic can be intercepted. Historic campaigns combined the technique with a proxy on the infected host to capture login details over HTTPS, and manufacturer-installed roots have produced the same interception power at scale. Distinct from the sibling techniques that steal signing keys or modify signature policy, this one grants trust rather than borrowing it. Detection rests on comparing the root store against a baseline, watching store modification commands and their process lineage, and reviewing certificate chains for issuers that do not belong to the organisations in use.
