T1518.001 Software Discovery: Security Software Discovery

T1518.001DiscoveryExtremeTechnique

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

This is an attacker checking which security tools are running on a computer or in a cloud account. Security tools include antivirus programs, monitoring agents and firewalls. The attacker makes no changes here; they are only looking for cameras and alarms.

Why should you care?

If an attacker learns which defences are missing, they can choose the path that makes the least noise. They may also learn which monitoring shows which activity, so they can stay just below the alert line. Finding this early gives you a chance to respond before any damage is done. It also tells you where your own coverage has gaps.

How it works, in plain steps

  1. The attacker gets a foothold on a host or into a cloud account.
  2. They list running programs and services to spot security agents in the list.
  3. They read registry keys or configuration files where security products record their settings.
  4. They check firewall settings and logging agents to see what would be recorded.
  5. In cloud accounts they ask provider interfaces which monitoring extensions are attached to servers.
  6. They use the results to plan quiet actions, or to find servers with no agent at all.

Real-world example

Picture a shoplifter walking through a store and glancing at the ceiling to count cameras. They note the aisle with no camera and come back to it later. The walk costs nothing, and it decides exactly where the theft will happen.

Key takeaways

  • Looking for security tools is a normal step before an attack, so treat it as a warning.
  • Queries about antivirus and monitoring agents are easy to log and review.
  • Cloud checks for monitoring agents reveal the same intent in a different place.

In more detail

Security Software Discovery narrows the discovery phase to defensive tooling: endpoint protection, endpoint detection and response agents, host firewalls, logging shippers, and cloud monitoring agents such as provider-native metric and log collectors. The adversary wants to know what can see them and what cannot, so they enumerate installed products, running services, driver names, registry keys, and configuration files. On Windows this often looks like process listings, registry queries for security product keys, service enumeration, and firewall state checks; on macOS, malware commonly probes for local firewall and monitoring utilities. In cloud environments the same intent shows up as calls that list virtual machine extensions or monitoring agents attached to compute resources, which reveals both coverage and blind spots. Detection is not about the tool name alone, because administrators use the same commands, but about behaviour: an unexplained interactive shell executing several defensive product queries in a short window, discovery calls from a workload identity that has never used them, or queries followed by attempts to stop, uninstall, or reconfigure a sensor. Where endpoint telemetry records process creation, those events are the best starting point for correlation.

What you will practise

  • Describe what adversaries learn by enumerating security tools.
  • List the host, macOS and cloud sources that reveal defensive software.
  • Identify telemetry that records security product enumeration.
  • Explain why these queries must be judged by context rather than by name.
  • Assess your own monitoring coverage to reduce discoverable blind spots.
