T1056 Input Capture

T1056Credential AccessExtremeTechnique

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

Input capture means stealing what a person types or sends, usually to obtain usernames and passwords. The attacker does not break the password at all. Instead the attacker reads it while the real user enters it. This can happen quietly in the background, or through a fake window that looks real.

Why should you care?

Passwords typed by people are often the easiest way into a system, because they arrive already valid. Locking a door does not help if someone reads the key while you turn it. Input capture also produces very little noise, so it can run for a long time before anyone suspects. A captured password can be reused from anywhere the account normally works. That is exactly why knowing the different capture methods matters for detection.

How it works, in plain steps

  1. A user types a password into a login box, a mail client or a system prompt.
  2. Something sitting in between quietly records those characters before they are ever checked.
  3. The recording can happen in the operating system, in an application or on a web server.
  4. Some methods hide completely, while others show a fake prompt that looks genuine.
  5. The stolen details are written to a file or sent to a system the attacker controls.
  6. The attacker then signs in as the real user, so nothing on the system appears broken.

Real-world example

Think of a hotel night desk at the end of a long shift. Guests sign the register, and the clerk keeps the book behind the counter. A thief copies each signature and room number from that book. Later he can walk up to any room and ask for a replacement key card. No lock was forced, and no guest noticed anything unusual. The register still shows all the correct names. The entries were never changed, only quietly copied. The hotel's own records look perfect while every room is now reachable.

Key takeaways

  • Input capture steals credentials while they are in use, not from storage.
  • It can be invisible to the user or disguised as a normal prompt.
  • Stolen credentials are valid, so they bypass many technical controls.

In more detail

Input capture covers the methods used to collect what a person types or submits rather than what a system stores. Credentials are entered constantly at login portals, password dialogs, mail clients and remote access gateways, so intercepting that entry can yield valid accounts that never need to be cracked. The parent technique groups several distinct mechanisms: logging keystrokes at the programming interface, driver or hardware level; presenting imitation prompts that the user believes belong to a genuine service; planting recording code on an externally facing login page so submitted details are saved before authentication; and hooking the credential handling functions so the parameters passed to them are copied. Each variant leaves different traces, but the shared threads are processes interacting with input or credential interfaces outside their normal role, windows not created by the legitimate binary, unexpected writes of captured text to disk or network, and successful authentication from sessions whose client details do not match the real user.
