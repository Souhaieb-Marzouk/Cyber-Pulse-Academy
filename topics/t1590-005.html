T1590.005 Gather Victim Network Information: IP Addresses

T1590.005ReconnaissanceExtremeTechnique

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

This sub-technique is about collecting the Internet Protocol (IP) addresses that belong to a target. An IP address is the number a computer uses to find another computer on a network. Public address blocks are listed in public registries for everyone to read.

Why should you care?

Knowing your address block tells an attacker exactly where to aim. It can also suggest how big your organisation is and where it is located. It may reveal which hosting company runs your public services. That helps the attacker pick tools and approaches that fit your setup.

How it works, in plain steps

  1. The attacker reads public internet registry records to find address blocks assigned to your organisation.
  2. They resolve your domain names to addresses and group those addresses by range.
  3. They run reverse lookups, which turn an address back into a host name.
  4. They use routing data from the internet to see how your blocks are announced.
  5. They scan the ranges to learn which addresses answer and which stay quiet.
  6. They note which addresses belong to cloud or hosting providers rather than your own buildings.

Real-world example

Think of a city where every street has a postcode. Each postcode tells the postal service which sorting office handles the mail. The full list of postcodes is public, because the postal service could not operate without it. A stranger planning to visit many houses starts by reading that list. They learn which postcodes belong to which district and how far apart those districts sit. That tells them where to begin and how much ground there is to cover. Public IP addresses work like postcodes for computers. The registry list is public and cannot be hidden, and your logs only show activity when someone starts knocking.

Key takeaways

  • Public address lists are unavoidable, so record which blocks you own and what actually runs on them.
  • Reverse lookups and old records can reveal hosts you had forgotten were still reachable.
  • Watch for scanning that walks steadily through your whole address block in order.

In more detail

This sub-technique covers the collection of the Internet Protocol addresses allocated to a victim, typically as contiguous blocks rather than individual hosts. Regional internet registries publish allocation records linking blocks to organisations, and routing data shows how those blocks are announced, so much of this can be assembled without touching the target. Adversaries then use reverse lookups, historical passive DNS records, and scan results to work out which addresses are live, which are hosted by third parties rather than owned directly, and which have been abandoned but remain routed. The derived value is contextual: block size hints at organisational scale, registration country suggests legal jurisdiction, and hosting or internet service provider attribution shapes later infrastructure choices. Passive collection leaves nothing, while active scanning produces ingress firewall, flow, and web server log entries, usually distinguishable by steady sequential traversal of a block from few sources rather than the scattered, cache-driven pattern of legitimate internet traffic.

What you will practise

  • Explain what a public IP address allocation is and where registry records are published.
  • Describe how block size, registration country, and hosting provider inform an adversary.
  • Identify the secondary sources, such as reverse lookups and historical records, used to refine address lists.
  • Recognise ingress logs that indicate systematic scanning of an address block.
  • Recommend how to keep an accurate record of owned addresses and exposed services.
