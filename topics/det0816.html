DET0816 Detection of Threat Intel Vendors

DET0816Detection StrategyVery hardDetection Strategy

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

This detection looks for someone working out which security companies protect your business. Attackers want to know what monitoring you use. The rule watches for unusual visits to vendor pages, reseller sites and comparison websites. It can also watch public mentions of your tools.

Why should you care?

If an attacker knows your security products, they can choose methods those products miss. Public pages, job adverts and conference talks often name those products. This is quiet research, not an intrusion. Noticing it early tells you that someone is studying your defences.

How it works, in plain steps

  1. Web requests from company devices are logged. The log holds the site, the page path, the user agent and the user.
  2. Requests are grouped by the domain category, so known security vendor and comparison sites are easy to select.
  3. The rule counts how many different vendor or reseller pages one user visits in a window.
  4. It compares the count with the normal pattern for that user and for the security team.
  5. Marketing site analytics show when one external address reads many of your product and supplier pages.
  6. Alerts join the two views, so an internal reader and an external scraper can be seen as one campaign.

Real-world example

Think of a shoplifter who first reads the shop sign to learn which security firm watches the cameras. Knowing the firm tells the thief which blind spots to expect. Reading the sign is not a crime, yet it changes what happens next. This detection watches who keeps reading the sign.

Key takeaways

  • Security vendor research is quiet and often done through public pages.
  • Job adverts and conference talks leak your tooling, so review them as part of exposure.
  • A short burst of vendor page reads by one account is worth a look, not an incident.

In more detail

This detection strategy covers the search for threat intelligence vendors, the technique where an adversary identifies which commercial intelligence, brand monitoring or incident response providers the target uses, so they can avoid detection or pick a victim who is poorly monitored. It matters because the collection is mostly off network: it shows up as unusual reads of the organisation's own public security pages, supplier lists and job adverts that mention a product, plus requests to security vendor comparison sites and reseller portals from corporate addresses. The telemetry that makes it possible is web proxy and content delivery logs with the requested path and user agent, domain name system query logs for vendor and comparison domains, marketing site analytics with referrer and address data, and open source monitoring of brand mentions. Detection fails because security teams legitimately research vendors all day, and because much of this reconnaissance happens through third party sites the defender does not control.

What you will practise

  • Explain why knowing the defender's tooling helps an adversary avoid detection.
  • Identify the proxy, analytics and resolver fields that show vendor research.
  • Write a rule that counts distinct vendor and comparison domains per user in a window.
  • Describe how to review public material that names your security suppliers.
  • Explain how this collection supports later defence evasion choices.
