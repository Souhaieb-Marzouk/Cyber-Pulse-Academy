Service Account Hygiene

Identity & AccessHardKeyword

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

A service account is a login used by a program, not by a person. Service account hygiene means keeping these logins few, small in power and easy to track. It also means removing them when the program is gone.

Why should you care?

Programs cannot change their own password or notice a strange login. If their login is powerful and shared, an attacker can use it quietly for a long time. Nobody misses a password that never expires. Good hygiene limits the damage and makes unusual activity visible to the security team.

How it works, in plain steps

  1. List every service account, what created it, what it does and who owns it.
  2. Give each service its own account instead of sharing one between tools.
  3. Grant only the permissions that the task truly needs to finish its work.
  4. Prefer short-lived credentials from the cloud platform over stored keys and passwords.
  5. Keep any lasting secret in a managed store and rotate it on a schedule.
  6. Alert on interactive logins and remove the account when the service retires.

Real-world example

Think of a large building with a master key that cleaners, electricians and delivery drivers all share. Nobody knows who used it last, and it is never replaced. If a copy is lost, the whole building is at risk and the loss is invisible. A better arrangement gives each worker a key that opens only the rooms they need. Those keys expire at the end of the shift. Service accounts are those keys. Hygiene means knowing who holds each one, limiting what it opens, and taking it back when the work is finished.

Key takeaways

  • One service, one account, one named owner in a maintained list.
  • Use short-lived platform credentials instead of long-lived stored keys.
  • Alert on interactive logins from accounts that software should be using.

In more detail

Service account hygiene is the set of practices that keeps non-human identities controlled, accountable and minimal. A service account is an identity created for software rather than a person: a batch job, an integration, a monitoring agent or a scheduled report. These accounts are attractive targets because they often carry broad permissions, run unattended, hold credentials that never expire and are excluded from password reset campaigns. Hygiene means giving each service its own identity instead of sharing one, granting only the permissions the task needs, preferring short-lived credentials or workload identity over stored passwords and static keys, rotating whatever secrets must persist, storing them in a managed secret store, restricting where the account can be used from, and removing the account when the service is retired. In practice you see this work in cloud identity inventory, key rotation schedules, and alerts on interactive logins from service accounts. The classic mistake is a single shared administrator account used by several tools, with credentials in a configuration file and no owner recorded.

What you will practise

  • Define a service account and explain how it differs from a user account.
  • Describe an inventory process that records the owner and purpose of each account.
  • Explain how workload identity reduces reliance on stored secrets.
  • Identify monitoring signals that reveal misuse of a service account.
  • Outline a retirement process that removes accounts when a service ends.
