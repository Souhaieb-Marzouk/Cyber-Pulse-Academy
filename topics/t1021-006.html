T1021.006 Remote Services: Windows Remote Management

T1021.006Lateral MovementExtremeTechnique

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

Windows Remote Management, or WinRM, is a Windows feature. It lets one computer send commands to another over the network. It is built into Windows and is often used by administrators and by PowerShell. A person can start a program, change settings, or read information on the remote machine.

Why should you care?

WinRM is a normal administration tool, so it rarely looks suspicious by itself. If an attacker has a valid account, they can run commands on many computers at once. That work may blend into the daily tasks of system administrators. Without a baseline of who normally uses WinRM, unusual remote commands can pass unnoticed.

How it works, in plain steps

  1. An administrator or an attacker sends a request to the WinRM service on a remote computer.
  2. The service checks the credentials, then starts a host process to carry out the request.
  3. That host process launches the program and sends the output back to the sender.
  4. The work runs remotely, so nobody logs on at the keyboard of the target computer.
  5. An attacker repeats this across many hosts to run commands or move sideways.
  6. Normal administrators use the same path, usually from a few management servers.

Real-world example

Picture a hotel front desk that takes requests by phone. Any staff member with the right code can call the kitchen. The kitchen sends a meal to any room, and guests never see who called. If a stranger learns the code, they can order food all night. The kitchen will not ask questions, because the code is valid. WinRM works the same way and trusts any request with good credentials.

Key takeaways

  • WinRM traffic uses management ports, and remote actions appear as processes started by the WinRM host.
  • A valid account is all an attacker needs, so watch for unusual source hosts and odd commands.
  • Baseline which servers and accounts normally use WinRM before you call something malicious.

In more detail

Windows Remote Management, usually shortened to WinRM, is Microsoft's implementation of the WS-Management protocol. It lets an operator run commands, read the registry, or change services on a remote host, and it normally listens on TCP 5985 for HTTP and 5986 for HTTPS. It can be reached with the winrm command, PowerShell remoting, or tooling that drives Windows Management Instrumentation over it. A successful remote call starts a host process on the target, so process creation records often show child processes under the WinRM provider host rather than under an interactive logon. Defenders combine those parent-child relationships, the WinRM operational log, and connections to the management ports to separate routine administration from an intruder using stolen credentials. The absence of a matching interactive logon on the target is a useful signal.

What you will practise

  • Explain what WinRM is and which ports and services it relies on.
  • Describe how a remote WinRM request becomes a running process on the target computer.
  • Identify the process, log, and network artefacts a WinRM session produces.
  • Explain why valid credentials make WinRM hard to detect with signatures alone.
  • Build a simple baseline of normal WinRM use in an environment.
