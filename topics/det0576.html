DET0576 Email Forwarding Rule Abuse Detection Across Platforms

DET0576Detection StrategyVery hardDetection Strategy

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

This rule looks for mailbox rules that forward or copy email to another address. A mailbox rule is an automatic instruction that the mail system follows for you. The technique is abuse because an attacker uses that feature to read your mail.

Why should you care?

A forwarding rule keeps sending mail even after the attacker loses access. It is created in a few seconds and leaves no program on your computer. Only the mail system records it, so endpoint tools see nothing. Finding the rule early limits how much mail has already leaked.

How it works, in plain steps

  1. The platform collects mailbox audit records, which note each rule that is created or changed.
  2. A filter keeps rules whose action forwards or redirects mail to a destination outside your organisation.
  3. The platform checks the session that made the change, including the address and the client program used.
  4. It compares the destination domain with the domains your staff normally use.
  5. It also checks whether the same account signed in from a new location shortly before.
  6. An alert fires when a new external destination appears, or when the rule also deletes or hides messages.

Real-world example

Think of a postal redirect form at a shared house. A resident may ask for mail to be sent to a second address, and the post office allows it. Now imagine a form that sends every letter to a stranger. The redirect itself is the evidence. The letters keep flowing until someone reads the form.

Key takeaways

  • Forwarding rules survive password changes, so they must be found and removed.
  • External destinations and hidden or deleted copies are the strongest signals.
  • The sign in that created the rule adds vital context to the alert.

In more detail

This detection strategy covers email forwarding rule abuse, tracked as T1114.003, where an adversary with access to a mailbox creates an inbox rule that quietly copies or forwards messages to an address under their control. It matters because the rule runs server side, needs no malware on the endpoint, and continues to deliver content long after the initial access is gone, which makes it a durable collection and exfiltration channel for business email compromise. Detection uses mailbox audit records for rule creation and modification, message trace data showing automatic forwarding to an external domain, identity logs for the session that created the rule, and sign in records that show whether the change happened interactively or through a scripting interface. The usual failure is that staff create forwarding rules for legitimate reasons such as working from a personal device, so the rule must weigh the destination domain and the account history rather than the rule creation alone.

What you will practise

  • Explain what a mailbox forwarding rule does and why it persists.
  • Identify the audit records that capture rule creation and modification.
  • Describe how to classify a destination as internal or external.
  • Correlate a new forwarding rule with an unusual sign in for the same account.
  • Explain why recording rules without alerting can still close coverage gaps.
