DET0369 Detection Strategy for Event Triggered Execution via Trap (T1546.005)

DET0369Detection StrategyVery hardDetection Strategy

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

A trap is a rule you give to a command shell. It says that when a certain event happens, such as the shell closing or receiving a signal, run this other command. This detection looks for someone adding a trap that runs code they control. It catches the trap being set and the code running later.

Why should you care?

Traps are quiet. The handler runs later, when a signal arrives, so the person who set it does not need to stay logged in. The rule also survives inside scripts and profile files, which many people read but few review. Attackers use traps to keep access after a normal logon. Reviewing them therefore closes a gap that file scans often miss.

How it works, in plain steps

  1. Collect process execution events for command shells, including the full command line.
  2. Look for the trap keyword in that command line, together with a signal name or a shell event name.
  3. Collect file change events for shell profile files in user home directories and in the system profile directories.
  4. Link a profile file change to the next shell start on the same host and for the same account.
  5. Raise an alert when the handler target points to a writable temporary directory or to a remote download tool.
  6. Show the analyst the account, the file, the signal, and the command that was registered.

Real-world example

Think of a door log in an office. Most entries show people arriving in the morning. One entry says that if the fire alarm ever rings, a named stranger should open the side gate. That instruction is the trap. It does nothing until the alarm, and then it matters a lot.

Key takeaways

  • A trap is a delayed action that waits for a signal instead of running at once.
  • Profile files are the usual place to hide one, because they load on every new shell.
  • A handler that points at a temporary folder or a download tool is the strongest signal.

In more detail

This strategy detects event triggered execution through the shell trap mechanism, where an adversary registers a handler that runs their code when a chosen signal or shell condition occurs. On Linux and macOS the trap builtin is set in a shell profile, a system wide script, or an interactive session, so the handler fires on logon, on exit, or on an error without any further action by the user. Detection combines command line auditing of shell invocations that register handlers, file integrity monitoring of shell profile files under the home directories and the system profile directories, and process creation events showing a handler program starting with a shell as its parent. The main failure is that traps are ordinary shell features used by legitimate scripts, so context about the writing account and the handler target decides whether an alert is meaningful.

What you will practise

  • Explain what a shell trap is and how it delays execution until an event occurs.
  • Identify the profile files and system scripts where traps are commonly placed.
  • Write a rule that finds trap registration in a shell command line.
  • Judge the risk of a handler by looking at what the handler command actually does.
  • Decide which file integrity monitoring coverage you need to see profile file changes.
