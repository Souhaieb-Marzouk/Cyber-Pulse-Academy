T1071.004 Application Layer Protocol: DNS

T1071.004Command and ControlExtremeTechnique

DNS command and control describes adversary use of the Domain Name System to carry instructions and data between an implant and its controller, usually by encoding information into the queried name itself and receiving instructions in resource records returned by the authoritative server. The technique works because outbound name resolution is permitted almost everywhere, is rarely inspected beyond reputation filtering, and is often logged with more consistency than other egress protocols. Variants include high-volume subdomain encoding for data transfer, low-and-slow single-label lookups for tasking, and the use of DNS over HTTPS to hide the query content inside ordinary web traffic. The strongest artefacts are in resolver and naming data. Atypical query characteristics include very long or high-entropy labels, unusually deep label hierarchies under a single parent domain, a very high count of unique subdomains for one registered domain from a small set of hosts, and query types that a normal client population never emits in volume, such as text or null record requests. Timing analysis is equally important: automatic retry behaviour in the client stack, which yields near-constant intervals across a few resolver replicas, is a recognisable pattern. Where responses can be observed, unusually large answer sections or records carrying encoded payload deviate from normal caching behaviour. Endpoint evidence is often the decisive layer, since the process making the queries can be identified and tied to a file origin and command line. Legitimate high-volume DNS exists in the form of content delivery networks, security vendors performing lookups, and misconfigured applications that fail repeatedly against the same name. Investigations separate these by host population, domain registration age, absence of the domain from any approved service inventory, and whether the queried labels decode to structured data rather than readable service names.

What you will practise

  • Explain how encoded labels and resource record responses allow bidirectional communication over name resolution.
  • Identify query entropy, label length, unique subdomain counts, and record type anomalies as detection signals.
  • Interpret DNS retry timing patterns caused by client resolver behaviour and why they appear so regular in logs.
  • Correlate resolver telemetry with endpoint process data to attribute queries to a specific binary or script.
  • Evaluate the visibility loss introduced by encrypted DNS transports and describe compensating controls.
  • Map DNS command and control to ATT&CK and rank resolver policy, egress restriction, and host telemetry by effectiveness.
