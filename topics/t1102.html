T1102 Web Service

T1102Command and ControlExtremeTechnique

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

This technique means an attacker uses a normal, popular website or cloud service to send orders to malware and to receive stolen data. The service is real and legitimate, and the attacker simply has an account on it. Because the site is trusted, the traffic does not look obviously wrong.

Why should you care?

Blocking the attacker's address does not help, because there is no attacker address to block. The channel also hides inside traffic that your staff already generate every day. Without careful behaviour analysis, this kind of control channel can run for months.

How it works, in plain steps

  1. The attacker creates an account on a common web service, such as cloud storage or social media.
  2. Malware on the victim machine signs in or reads a public page on that service.
  3. New orders are placed as content the malware knows how to find, such as a post or a file.
  4. Stolen data is uploaded back to the same account or another account the attacker controls.
  5. Because the provider uses encryption, observers cannot read the content of the exchange.
  6. The attacker can swap accounts at any time without changing the malware itself.

Real-world example

Imagine a spy who never meets a contact. Instead, they read the public notices board in a busy train station and leave replies in a locker. Hundreds of people use the station every hour, so nobody notices one more commuter. The station is a real, trusted place that no guard would ever close down.

Key takeaways

  • Judge traffic by behaviour and volume, because the destination is a legitimate service.
  • Know which cloud services your organisation really uses, so the rest stand out.
  • Fixed polling intervals and unusual client details are stronger signals than the site itself.

In more detail

Web service abuse is command and control that rides on legitimate public platforms rather than attacker-owned servers. The implant talks to a well-known provider, for example a cloud storage or productivity application programming interface, a social network, a paste site or a webmail draft folder, and both tasking and stolen data are stored or exchanged through that service. The technique works because the traffic is encrypted, goes to a reputable address, and resembles the same provider traffic that already flows from the network, so it rarely stands out by destination alone. Because the control channel is a provider rather than a fixed server, the adversary can change the account or resource behind it without changing the implant, which improves resilience and hides the back end from static analysis of the malware. Identification rarely comes from a blocklist. Analysts work from behavioural signals: a host reaching a service the organisation does not use, uploads and downloads that follow a regular interval, an unusual client or user agent string for that service, traffic outside business hours, and volumes that are too consistent for a human user. Requests that read data before the device has legitimate reason to expect it, or that poll on a fixed sleep, also separate the implant from ordinary use.

What you will practise

  • Explain how legitimate web services can carry command and control traffic.
  • Describe the behaviours covered, including cloud application interfaces, social media and paste sites.
  • Identify the network and application log signals that separate abuse from normal use.
  • Explain why destination based blocking is ineffective for this technique.
  • Describe how the technique protects adversary infrastructure from discovery and disruption.
