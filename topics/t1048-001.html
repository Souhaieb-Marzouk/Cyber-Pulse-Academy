T1048.001 Exfiltration Over Alternative Protocol: Exfiltration Over Symmetric Encrypted Non-C2 Protocol

T1048.001ExfiltrationExtremeTechnique

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

This is a version of data theft where the stolen files are locked with a secret key before they are sent. Both the attacker and their server use the same secret key. That key is shared in advance, not during the transfer.

Why should you care?

If the data is locked before it leaves, anyone watching the network sees only unreadable noise. There is no certificate or public key to trace back to the attacker. The same secret can protect a channel that is normally unencrypted, which hides the theft inside dull traffic. Only the size and timing of the transfer give it away.

How it works, in plain steps

  1. The attacker chooses a symmetric method, where one shared secret both locks and unlocks the data.
  2. That secret is already inside the malicious program, or delivered over the control channel.
  3. Files are staged, compressed and encrypted with the shared secret on the victim machine.
  4. The locked data is sent over a protocol that is not the main control channel.
  5. If the protocol is already encrypted, the result is two layers of protection at once.
  6. The receiving server unlocks the data with the same secret, so no key is ever exchanged publicly.

Real-world example

Think of a courier who swaps a private codebook with a client months before the job. On the day, the notes are written in that code, placed in ordinary envelopes and posted through the normal mail. Anyone who opens an envelope on the way finds nonsense, and no codebook ever travels with the letters.

Key takeaways

  • Symmetric means one shared secret, so nothing about the key is visible on the network.
  • This variant is recognised by traffic shape, because the payload itself cannot be read.
  • It looks different from the asymmetric variant, which would leave certificate or public key traces.

In more detail

This sub-technique is the encrypted-by-shared-secret branch of exfiltration over an alternative protocol. The parent technique says data leaves over a protocol other than the command and control channel; here the payload is additionally encrypted with a symmetric algorithm, meaning both ends use the same secret key, which the adversary supplies in advance rather than negotiating through a protocol handshake. Because no key exchange is visible on the wire, the defender cannot tie the traffic to any certificate or public key, and a shared secret can be embedded in the malware itself, delivered through the control channel, or derived from a predictable value. The result is opaque payload inside a protocol that may already be encrypted, such as web traffic, producing layered encryption, or encryption applied to a plain protocol such as unencrypted file transfer, where the encoded content stands out sharply from normal use. Detection therefore leans on traffic analysis instead of content inspection: entropy and size patterns of uploads, unusual destinations, repeated large transfers between the same pair of hosts, sessions that ignore normal protocol behaviour, and hosts that begin encrypting traffic to a new endpoint shortly after other suspicious activity. The distinguishing feature against the asymmetric variant is that no certificate or public key material appears anywhere in the flow.

What you will practise

  • Explain how this sub-technique differs from its parent, which covers unencrypted channel choice rather than payload encryption.
  • Define symmetric encryption and explain why a shared secret needs no visible key exchange.
  • Describe how staged data is encrypted with a shared secret and sent over an alternate protocol.
  • Identify the traffic characteristics that can still reveal a symmetrically encrypted transfer.
  • Contrast this variant with the asymmetric encrypted variant of the same parent technique.
