T1218.009 System Binary Proxy Execution: Regsvcs/Regasm

T1218.009StealthExtremeTechnique

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

COM is an older Windows way for programs to offer features to each other, and its full name is Component Object Model. Regasm and Regsvcs are .NET tools that make .NET programs look like COM programs. Both are signed by Microsoft and live in the framework folders.

Why should you care?

The tools look for methods with special labels inside the program file. Those labelled methods run early, before the tools check whether registration can succeed. So an attacker's code runs even when the command ends with an error. These tools are rare on a normal workstation, which is good news, because almost any appearance deserves a look.

How it works, in plain steps

  1. COM is an older Windows system that lets programs offer features to each other, and .NET is a newer platform.
  2. Regasm and Regsvcs are .NET tools that register .NET programs so COM programs can use them.
  3. To do that work, the tools look inside the program file for methods carrying special labels.
  4. One label marks code to run at registration, and another marks code to run when it is removed.
  5. The tool calls that marked code early, before it checks whether the registration can succeed at all.
  6. The marked code therefore runs even when the tool later reports an error and stops working.

Real-world example

At a conference, a translator wears a staff badge, so she can enter almost any room in the venue. She is booked to translate one talk in the main hall, and that booking is genuine. In a corridor she uses the staff badge to open a locked storage door, then leaves the building. The organisers saw a valid badge and a real booking. The badge is the tool, and the side trip is the marked method.

Key takeaways

  • Marked methods run before registration succeeds, so an error does not stop the code.
  • Regasm and Regsvcs are rare on workstations, which makes alerts easier to trust.
  • Always read the file path argument and the parent process of these tools.

In more detail

Regsvcs.exe and Regasm.exe are .NET Framework command-line utilities that register managed assemblies so that they can be consumed as Component Object Model components, with Regasm targeting the assembly registration path and Regsvcs handling services installation for COM+ applications. The abuse mechanism lies in two attributes, ComRegisterFunction and ComUnregisterFunction, which mark methods the runtime must call during registration and unregistration. Code inside those marked methods runs before the registration work completes, and it runs even when the utility is executed without sufficient privileges and the operation ultimately fails, so a failed command leaves executed code behind. An adversary therefore only needs a managed assembly containing a decorated method and a command line that passes its path to one of the two signed, Microsoft-signed binaries, gaining execution inside a trusted process that application control policies frequently allow. Detection is comparatively tractable because these utilities are rare outside software installation: process creation telemetry showing Regsvcs.exe or Regasm.exe with an argument naming a file in a user profile, temporary or download directory, a parent process such as a script host, office application or web service rather than a deployment tool, image loads of unsigned or user-writable assemblies, and the absence of the COM registration entries a legitimate registration would create.
