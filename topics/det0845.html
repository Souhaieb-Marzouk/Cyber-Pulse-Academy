DET0845 Detection of Malware

DET0845Detection StrategyVery hardDetection Strategy

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

This detection looks for malicious software that arrives on your systems. Malicious software, or malware, is a program written to harm or control a computer. The rule watches files as they are written and checks what they try to do. It catches downloads from sources that are known to be bad.

Why should you care?

Malware is the part of an attack that actually runs. If you catch the file early, the rest of the attack may never start. Some malware is bought finished, so it looks the same on many victims. Watching where files come from links the sample to the wider campaign.

How it works, in plain steps

  1. The endpoint agent watches every file written to disk and records its hash.
  2. Brand new hashes are sent to a sandbox, which runs the file and reports what it does.
  3. The rule checks hashes and file behaviour against threat intelligence sources.
  4. Network logs show contacts with addresses that are known to deliver or control malware.
  5. The SIEM joins the file record to the process that created it and the user account.
  6. A match on reputation, or behaviour such as process injection, raises a high priority alert.

Real-world example

Picture a post room where every parcel is weighed and x rayed. Most parcels are ordinary supplies and pass through. One parcel ticks in the same way as a known bad item. Another comes from an address on the warning list. Both are opened in a safe room. The post room log is our file and network record.

Key takeaways

  • Behaviour and reputation carry the detection when the hash is new.
  • Joining file records to process and user records turns a sample into an incident.
  • Bought malware is reused across victims, so shared indicators help even before analysis.

In more detail

This detection strategy covers the technique of obtaining malware, where an adversary buys, downloads, or receives an existing malicious payload instead of writing one. It matters because the payload is the part of the intrusion that runs on your systems, so its first landing is often the earliest solid evidence you get. The telemetry that makes detection possible is endpoint detection and response alerts, file creation and hash records, sandbox analysis results, and network records of contact with known distribution or command servers. The main failure mode is that unknown samples have no hash history, so the rule depends on behaviour and reputation and must tolerate a steady stream of low confidence alerts.

What you will practise

  • Explain why obtaining malware is a distinct and observable step.
  • Name the endpoint, sandbox, and network records that support this detection.
  • Write a rule that combines reputation matches with suspicious file behaviour.
  • Describe how to triage a new sample with no hash history.
  • Identify the operational limits of signature based detection.
