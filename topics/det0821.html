DET0821 Detection of Spearphishing Service

DET0821Detection StrategyVery hardDetection Strategy

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

This detection looks for phishing messages that come from a rented service. These services host fake sign in pages and track who opens them. The rule watches for mail from very new domains that pretend to be your brand. It also watches for staff reaching known phishing kit pages.

Why should you care?

Building phishing infrastructure takes time and skill. A rented service removes both, so attacks arrive faster and more often. The fake pages look real, and the domain is new. Finding the campaign early lets you block the domain and warn the people who received it.

How it works, in plain steps

  1. The mail gateway records the sender domain, the reply to address, the links in the message and the authentication results.
  2. Domain registration and certificate feeds record when a lookalike domain was created and when it received a certificate.
  3. The rule selects messages where the sender domain is very new or closely resembles a company brand.
  4. It adds mismatches, for example a reply to address on a different free mail service.
  5. Proxy records are joined to see whether a recipient clicked and reached a known kit path.
  6. Matches raise an alert with the domain age, the recipient list and any page the user opened.

Real-world example

Think of a market stall that opens at six in the morning, sells one item, and is gone by noon. The stall holders never repair their reputation, because they will not return. A rented phishing domain works the same way. This detection watches for stalls that opened today.

Key takeaways

  • Very new sender domains are the strongest single clue in a rented phishing campaign.
  • Blocking one domain is not enough, because the service supplies a new one each time.
  • User reports are fast intelligence, so make reporting easy for staff.

In more detail

This detection strategy covers the use of spearphishing services, the technique where an adversary buys or rents a service designed to host lures, track clicks, clone sign in pages and manage a campaign, instead of building that infrastructure by hand. It matters because the service does the hard work: it provides a clean domain, a hosted page and a dashboard, which shortens the time between reconnaissance and a delivered message. The telemetry that makes it possible is mail gateway logs for messages from newly registered domains with mismatched reply to addresses, domain registration and certificate transparency feeds for lookalike domains, secure web gateway logs for staff reaching known phishing kit paths, and user reports forwarded to the security team. Detection fails because the lure domain is usually clean at send time, because each campaign uses a fresh domain, and because a single message to one person leaves very little to count.

What you will practise

  • Describe what a spearphishing service provides and why it shortens preparation time.
  • Identify the mail gateway, domain registration and proxy fields that reveal a rented campaign.
  • Write a rule that combines domain age with brand similarity and reply to mismatch.
  • Explain how clicked links confirm that a campaign reached real users.
  • Describe how to turn user reported messages into a blocking list.
