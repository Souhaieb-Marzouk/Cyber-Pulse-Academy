T1555.002 Credentials from Password Stores: Securityd Memory

T1555.002Credential AccessExtremeTechnique

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

macOS uses a helper service called securityd to manage encryption and unlock stored secrets. This technique is when an attacker with full system rights reads that service's memory. Inside it they find the key that unlocks your saved passwords. It is a more advanced form of the Keychain technique.

Why should you care?

This method leaves few traces, because no file is changed and no unlock prompt appears. The attacker only needs deep system rights, which they often gain first. Once the key is found, many passwords become readable. Detecting it requires watching privileged access to that service.

How it works, in plain steps

  1. A helper service named securityd handles the encryption and unlocking work for macOS.
  2. It keeps a derived key in memory for as long as you stay logged in.
  3. An attacker first gains the highest level of system rights, called root.
  4. They read the memory of that service and search it for the master key.
  5. With that key they can decrypt the remaining stored values one by one.
  6. They then recover the plaintext logins for mail, Wi-Fi, browsers and secure notes.

Real-world example

Picture a night-shift safe with an electronic lock. The keypad stores the current code in its own memory while staff are on duty, so nobody has to type it twice. Someone with access to the maintenance panel reads that stored code from the panel itself, opens the safe, and no alarm sounds because the lock was never forced.

Key takeaways

  • Full system rights on a Mac can expose secrets held in service memory.
  • Watch for debugging or memory tools pointed at security processes.
  • Reduce root access, because it is the main requirement for this technique.

In more detail

Rather than reading the keychain database directly, this sub-technique reads the memory of securityd, the macOS service that implements security protocols such as encryption and authorisation. An adversary with root access can scan the process memory for the derived master key that protects a logged-in user's keychain, and once that key is found the remaining encrypted values can be unlocked in turn, yielding plaintext passwords for accounts, Wi-Fi, mail, browsers, certificates and secure notes. The behaviour is attractive because nothing on disk is modified and no keychain prompt is shown, so the endpoint keeps working normally. Historically, versions of OS X before El Capitan cached plaintext passwords for logged-in users, and modern releases require the same root privilege plus memory access. Detection therefore depends on elevated process inspection, on direct memory access to securityd, and on core dumps or debugging tools being pointed at it.

What you will practise

  • Identify telemetry that reveals privileged access to security service memory.
  • Recommend privilege controls that reduce exposure to this technique.
