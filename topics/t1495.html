T1495 Firmware Corruption

T1495ImpactExtremeTechnique

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

Firmware is the small program built into a piece of hardware that makes it work and helps it start up. This technique means an attacker damages or overwrites that program. The device may then fail to start or stop working completely. It is very hard to repair because the damage is below the operating system.

Why should you care?

Reinstalling the operating system will not help when the hardware itself has been damaged. A machine that cannot start is useless, and repairing it may mean replacing parts. Firmware sits below your security tools, so those tools may never see the change. Network devices such as routers are also affected, and one broken device can cut off a whole office.

How it works, in plain steps

  1. Firmware is stored in a memory chip and runs first when a device powers on.
  2. The attacker needs a way to write to that chip, usually administrator rights or a faulty driver.
  3. They use a vendor update tool or a direct write to replace the firmware contents.
  4. The write may fail the built in checks, leaving the device unable to start correctly.
  5. Some firmware attacks also destroy data because the storage controller no longer works.
  6. Recovery often means reflashing the memory chip or replacing the affected circuit board.

Real-world example

Picture a building where every lift is controlled by a small circuit board hidden in the machine room. A vandal does not touch any office, desk or file. They simply load the wrong settings into the lift controller. Now nobody can reach the fifth floor at all, and repainting the offices will not fix it. The building is fine, but the thing that moves people through it is broken.

Key takeaways

  • Firmware lives below the operating system, so reinstalling the system does not remove the damage.
  • Enable boot integrity features that record a change to firmware measurements.
  • Keep records of expected firmware versions so you can spot unexpected changes.

In more detail

Firmware corruption targets the software stored in non volatile memory on hardware: the motherboard firmware that starts the machine, drive controller firmware, network adapter firmware, and the management controller used for remote administration. An attacker who can write to that memory, either through administrative access to a vendor flashing utility or through a vulnerable driver, can leave the device unable to boot or unable to perform its role, and the damage survives an operating system reinstall because it lives below the operating system. The same action often destroys data, since a corrupted storage controller can make its contents unreadable. Evidence is scarce because most platforms do not log firmware writes by default; defenders rely on boot integrity measurements, the records produced when secure boot or measured boot values change, and firmware version reporting from inventory tools. Network devices are especially exposed because they are rarely reflashed and rarely monitored.
