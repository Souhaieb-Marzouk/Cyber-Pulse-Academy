T1578.001 Modify Cloud Compute Infrastructure: Create Snapshot

T1578.001Defense ImpairmentExtremeTechnique

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

A snapshot is a saved copy of a cloud disk or virtual machine at one moment in time. It is normally used for backups. In this technique an attacker makes a snapshot of a disk they do not own properly. Then they attach that copy to a machine they control, where they can read it freely.

Why should you care?

Copies are easier to hide than live machines. The attacker reads data from the copy and never touches the original system. Access rules that protect the running machine often do not apply to the copy. This lets an attacker bypass rules and reach private information. It also gives a clean starting point they can restore whenever they need it.

How it works, in plain steps

  1. The attacker gains cloud credentials that allow snapshot creation.
  2. They choose a target disk or virtual machine and request a point-in-time copy.
  3. The cloud service stores the copy, and the activity appears in the audit log.
  4. The attacker builds a new machine or reuses one they already control.
  5. They attach the copied disk to that machine and read the data directly.
  6. They may share the copy with another account or keep it for later reuse.

Real-world example

Picture a bank vault that lets a trusted clerk photograph the contents for the records. The guard logs only that a photograph was taken. The clerk then opens that photograph in any room they like, outside the vault rules. Nothing was removed from the vault, yet everything inside it is now readable elsewhere.

Key takeaways

  • Watch for snapshot creation outside normal backup times or accounts.
  • Check who can attach an existing snapshot to a new machine.
  • Restrict snapshot sharing between accounts and regions.

In more detail

Creating a snapshot is the storage-side move in cloud compute evasion. A snapshot is a point-in-time copy of a virtual machine, volume, or virtual hard drive, and it is created through an ordinary authorised API call that leaves a clear audit record but no running workload to inspect. The value to an adversary is that the copy can be attached to a different instance under a policy the adversary controls, so data that was protected by the original instance permissions, network rules, or endpoint controls becomes readable elsewhere. It also supports lateral movement across accounts or regions when snapshot sharing is permitted, and it provides a blueprint that can be restored repeatedly. This is why the technique pairs naturally with creating a new instance and then applying a permissive firewall rule or identity policy. Detection looks at snapshot creation events in cloud audit logs, especially snapshots taken outside a change window, followed quickly by volume attachment or by modification of snapshot sharing permissions, or by the creation of an instance with no prior relationship to the volume. Legitimate backup automation produces predictable, tagged, scheduled snapshots under a service identity, and that baseline is what makes the irregular ones visible.

What you will practise

  • Explain what a cloud snapshot is and what it copies.
  • Describe why a copy can bypass controls that protect the original resource.
  • Recognise the create, attach, expose sequence in audit telemetry.
  • Compare snapshot creation with reverting an instance to a snapshot.
  • Recommend policies that limit snapshot sharing and attachment.
