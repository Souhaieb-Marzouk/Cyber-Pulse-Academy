DET0268 Detect Archiving via Library (T1560.002)

DET0268Detection StrategyVery hardDetection Strategy

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

This detection looks for the moment when files on a computer are packed into one compressed archive. It catches this even when the packing is done by code running inside another program. An archive is a single file that holds many files, and it is a common way to move stolen data quietly.

Why should you care?

Attackers rarely steal files one by one. They gather the files they want and pack them into one archive first. That archive is small, easy to move, and easy to hide. If you can spot the packing, you can stop the theft before any data leaves your network. This detection gives you that early warning.

How it works, in plain steps

  1. A logging agent records every new file that appears on the computer. This is called file creation monitoring.
  2. The detection watches for new files whose names end in known archive extensions, such as .zip, .7z, .rar or .tar.
  3. It then looks at which program created that file. The image field tells you the program name and its full path.
  4. It flags archives created by scripting interpreters, because those programs rarely need to compress files.
  5. It checks where the archive was written. Folders for temporary data and public shares are far more suspicious than a backup folder.
  6. An analyst receives an alert that lists the archive, the program that made it, and the account behind it.

Real-world example

Think of a post room in a large office. Every day, clerks collect letters and put them in boxes for the post van. That is normal. Now imagine one clerk walks through the whole building, gathers documents from every desk, and packs them into a single box at midnight. The box itself is not the crime. The strange gathering is the clue.

Key takeaways

  • Staging data into one archive is an early sign of theft, long before anything leaves the network.
  • A library call inside a running program leaves fewer traces than a separate compression tool.
  • You must pair the new archive file with the program and the account that created it, or the alert means little.

In more detail

This strategy detects collection and staging activity where an adversary compresses stolen files into an archive before exfiltration. T1560.002 covers archiving performed through a software library inside an existing process instead of a separate command line tool, which removes the obvious child process that analysts normally pivot on. The detection depends on file creation and process access telemetry that records new archive files, the image that created them, and the user context behind the write. In practice it fails most often because backup agents, log rotation, and software deployment tools create archives constantly on legitimate business schedules, so the rule has to be anchored on scripting interpreters and on archive files written into user-writable staging directories.

What you will practise

  • Explain why adversaries archive collected data before exfiltration and how T1560.002 differs from command line archiving.
  • Identify which telemetry fields prove that an archive was created by a script host rather than a backup agent.
  • Build a baseline of legitimate archive creation so that normal business compression stops generating alerts.
  • Recognise suspicious destination folders such as temp paths, staging shares and profile directories.
  • Describe the limitations of file creation logging when an archive is written through a library call inside a trusted process.
