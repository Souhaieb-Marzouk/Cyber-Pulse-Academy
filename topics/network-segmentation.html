Network Segmentation

Network SecurityVery hardKeyword

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

Network segmentation means splitting your network into separate groups and putting a control between them. Each group, or segment, holds systems that need to work together. Traffic between segments must be allowed by a rule. The aim is simple: if one machine is taken over, it should not be able to reach everything else.

Why should you care?

On a flat network, every machine can talk to every other machine. That is convenient until one laptop is infected, because the attacker then has a clear path to file shares, backups and management systems. Segmentation breaks those paths and creates places where traffic can be checked. It also slows an attacker down, which gives your team time to notice and respond. The work is ongoing, not a one-time purchase.

How it works, in plain steps

  1. List your systems and sort them by how sensitive and how important they are.
  2. Find out which systems really need to talk to each other, and on which ports.
  3. Group those systems into segments and write rules that allow only the needed traffic.
  4. Block everything else by default and log what gets blocked, so you can spot mistakes.
  5. Review the blocked logs until the rules are correct, then keep the logs for monitoring.
  6. Give every exception an owner and an end date, or the old flat network slowly returns.

Real-world example

Think of an office building where every door opened with the same key. Losing one key meant losing the whole building. Now imagine each floor, the server room and the finance office have their own locks. Your badge opens the doors your job needs and nothing more. A thief who takes your badge can still roam, but only through the rooms you already had. That limit is the whole point of segmentation.

Key takeaways

  • Segmentation limits how far one compromised machine can reach.
  • Start from real traffic needs, not from the organisation chart.
  • Every exception needs an owner and an expiry date, or the flat network returns.

In more detail

A network segment is a bounded group of systems that share a communication policy, and segmentation is the practice of inserting enforced boundaries between those groups so that a single compromised host cannot reach every other asset. Boundaries may be physical, built from separate switches and cabling, logical, built from VLANs with router or firewall access control lists, or identity-based, built from microsegmentation agents and policy engines that decide per workload rather than per subnet. The design goal is to limit blast radius and to create chokepoints where traffic can be inspected and logged. Flat networks fail catastrophically because one phished workstation inherits reachability to file shares, management interfaces, backup infrastructure and directory services. Good segmentation starts from data and service flows rather than from the organisational chart: classify assets by sensitivity, map which systems must talk to which on which ports, then enforce default deny and log the denials until the policy is proven. Segmentation is a programme rather than a purchase. Legacy applications with hard-coded addresses, unmanaged devices, and operational technology that cannot tolerate added latency all generate exceptions that erode the model over time, so each exception needs an owner and an expiry date. Attackers respond by tunnelling permitted protocols, chaining through dual-homed hosts and abusing management planes, which is why monitoring must exist on the boundaries themselves. Administrative tiering, jump hosts and dedicated management networks address the management-plane risk, while cloud security groups, network policies and service meshes reproduce the same ideas with their own drift problems. The practical test of any segmentation scheme is adversarial: assume a host inside a segment is already compromised and ask what it can still reach.

What you will practise

  • You will be able to classify assets by sensitivity and derive required communication flows from evidence rather than assumption.
  • You will be able to design enforced zone boundaries with default deny and documented, expiring exceptions.
  • You will be able to use flow and firewall logs to detect residual flat-network reachability.
  • You will be able to describe how administrative tiering and jump hosts reduce management-plane risk.
  • You will be able to distinguish network, host-based and identity-based microsegmentation and choose appropriately.
  • You will be able to assess a segmentation design from an assumed-breach perspective and rank the residual paths.
