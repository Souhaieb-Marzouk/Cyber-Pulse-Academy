T1599.001 Network Boundary Bridging: Network Address Translation Traversal

T1599.001Defense ImpairmentExtremeTechnique

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

Network address translation means a router rewrites the addresses inside packets. It lets many internal devices share one public address. This sub-technique means an attacker changes those rewriting rules. That lets traffic cross a boundary it should not cross. It differs from the parent because the change targets address translation rather than the general rule list.

Why should you care?

Translation is often the only reason two networks cannot talk directly. Change it, and that protection disappears. The change also hides the true addresses from your monitoring tools, so your records become misleading. You may see traffic that appears to come from the router itself. Reviewing translation entries is the way to catch it. If the device software was replaced, the normal interface may not show the real rules.

How it works, in plain steps

  1. The attacker gains control of a router or firewall that translates addresses.
  2. They examine the translation rules and the current mapping table on the device.
  3. They add a static mapping that links an external address to an internal system.
  4. They may change the translation so returning traffic reaches a machine they control.
  5. They pass command and control or stolen data across the boundary using that mapping.
  6. If they replaced the device software, they implement their own translation outside the normal interface.

Real-world example

Imagine a receptionist who rewrites the name on every parcel so it reaches the right room inside a secure building. Outsiders can only address the front desk. A thief who takes over the desk writes a new rule that sends parcels straight to the records room. The building still looks normal, and the parcels still arrive on time.

Key takeaways

  • Review translation rules and static mappings whenever a boundary device changes.
  • Treat traffic that appears to originate from the gateway itself with suspicion.
  • Keep device firmware and configuration backups so you can compare versions.

In more detail

This sub-technique is the address translation variant of boundary bridging. A device that performs network address translation rewrites the source or destination address in the IP header as packets cross it, which is how privately addressed networks reach the internet and how external requests find internal services. An adversary with control of that device edits the translation table or its rules so the two separated networks can exchange traffic directly. In designs where translation is mandatory, this defeats the routing limitation that kept external hosts away from protected systems. In designs where translation is optional, the same change hides real addresses in monitoring data, so flow records no longer show the true source. Unusual translation entries, new static mappings, and inbound sessions that appear to originate from the gateway itself are the practical indicators.
