T1574.007 Hijack Execution Flow: Path Interception by PATH Environment Variable

T1574.007ExecutionExtremeTechnique

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

PATH is a setting that lists folders in a fixed order. When you type a command without a full folder name, the system searches those folders in turn. It runs the first match that it finds. This sub-technique means putting a file with the same name in an earlier folder, so the wrong program runs. It is one branch of the Hijack Execution Flow parent.

Why should you care?

Many scripts and tools call other programs by name only. That makes the search order important. If an attacker can write to an early folder, their file may run in place of a trusted tool. The real tool is never called, yet everything appears normal. Checking where a program was loaded from shows the difference.

How it works, in plain steps

  1. The PATH setting holds a list of folders that the system searches in order.
  2. A command typed without a full folder path is looked up in that list.
  3. The system runs the first file with the matching name that it finds.
  4. The attacker places a file with that name in an earlier listed folder.
  5. The setting itself can also be edited to add a folder the attacker controls.
  6. The legitimate tool is never reached, so the attacker's file runs instead.

Real-world example

Imagine a kitchen shared by four flatmates. Everyone takes milk from the first shelf they see. One flatmate puts an unlabelled bottle on the front shelf. Anyone making tea picks up that bottle without checking the label. The real milk is still at the back, untouched. PATH interception works in the same way. The system picks the first matching file in the list and never reaches the real one.

Key takeaways

  • Commands without a full path are found using the PATH list.
  • Write access to an early folder in that list is a real risk.
  • Check the full path of the program that actually ran.

In more detail

This sub-technique intercepts execution by abusing the PATH environment variable, the ordered list of directories the operating system searches when a program is called without a full path. If the attacker can write to a directory that appears earlier in that list than the real binary's directory, a file with the same name is found and run first. The change may come from planting a file in an existing early directory, or from editing the variable itself so it points at a location the attacker controls. On Linux and macOS the same effect is reachable through shell configuration, the launchctl tool, or files added under the system paths directory, and on macOS by changing the home directory variable. The evidence is a mismatch between the binary that was expected and the path that actually executed, which appears in process creation telemetry on Windows and in audit records of program execution on Linux. Detection should weigh which account can write to the earlier directory.
