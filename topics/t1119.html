T1119 Automated Collection

T1119CollectionExtremeTechnique

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

Automated collection means using a script or tool to copy many files at once. It replaces a person clicking through folders one by one. It searches for the data the attacker wants and gathers it in one place. It is fast and can cover a whole computer or a whole cloud account.

Why should you care?

A person cannot copy thousands of files by hand in a few minutes, but a script can. Automation lets an attacker take everything of one type, such as spreadsheets or documents, from many machines. It also makes the theft quieter, because one script is easier to hide than many manual actions. If you only watch for human behaviour, you may miss it.

How it works, in plain steps

  1. The attacker runs a scripting interpreter on a system they already control. Such a program runs stored commands, such as PowerShell or bash.
  2. The script searches local drives or cloud storage for files that match criteria such as extension, name, folder or date.
  3. Matching files are copied to a staging folder, or uploaded to a cloud bucket that the attacker can reach.
  4. The script may repeat on a schedule, so newly created files are collected as they appear.
  5. In cloud environments the same job uses provider APIs, command line interfaces or data pipelines instead of local commands.
  6. Remote access tools may include the feature, so collection happens inside the tool and no separate script is visible.

Real-world example

Imagine a hospital records office at night. One clerk is asked to pull every file for patients treated in March. Doing it by hand would take weeks. So the clerk works from a list and a trolley, and clears the shelves in one night. The growing pile by the door is the staging point, ready for a van in the morning. The clue is not the trolley. The clue is that one person touched hundreds of files in an hour.

Key takeaways

  • Automation is detected by volume and speed, not by any single action.
  • A staging folder that suddenly fills up is a strong sign of collection.
  • Cloud storage read records can show bulk access by one account in a short time.

In more detail

Automated collection is the use of scripts, interpreters or cloud interfaces to gather data across a host or an estate without a human doing the copying. Instead of opening folders by hand, the adversary runs a loop that selects files by extension, name, path or date and stages the copies in one location for later exfiltration. In cloud environments the same outcome is reached through provider APIs, command line interfaces and extract, transform and load pipelines, which can read objects at a rate no person could match. Remote access tools increasingly build the feature in, so no separate script ever appears on disk. Detection depends on the shape of the behaviour rather than a signature: one process touching far more files than a person could in the same window, a staging directory that fills suddenly, or an unusual identity making bulk read calls against storage. Collection usually follows file and directory discovery and precedes transfer of the gathered data.

What you will practise

  • Explain how a script can collect files by type, name, location or date.
  • Describe the staging behaviour that usually follows automated collection.
  • Identify host and cloud log sources that reveal bulk file access.
  • Explain why automated collection can be harder to notice than manual copying.
  • Describe how cloud APIs and data pipelines are used to collect data at scale.
