T1114 Email Collection

T1114CollectionExtremeTechnique

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

Email collection means an attacker steals messages from a mailbox. They can read the mail files stored on a laptop. Or they can log in to the mail service and read the mailbox there. Either way, they take copies of messages that matter.

Why should you care?

Mailboxes hold contracts, personal details, password reset messages and shared files. During an incident, they also hold the security team's own notes and plans. A stolen mailbox can be kept open with a forwarding rule, even after the password is changed. Normal staff use mail constantly, so unusual access is easy to overlook.

How it works, in plain steps

  1. The attacker obtains credentials, a session token or access to a logged in workstation.
  2. They choose a route: the local mail files on a device, or the mail service itself.
  3. Mail searches use keywords chosen from the target organisation and its projects.
  4. Results are copied out or forwarded to an address the attacker controls.
  5. A forwarding rule or delegate access keeps copies flowing without further logins.
  6. The activity appears as normal mail use unless the pattern or the destination is reviewed.

Real-world example

In a shared flat, post arrives for everyone and sits in an open box by the front door. Residents take what belongs to them and never think about the box again. An outsider makes a spare key, copies every letter each night and leaves the originals exactly where they were. Nobody notices anything missing for months.

Key takeaways

  • Mailboxes hold some of the most valuable data in any organisation, including security plans.
  • Check for new forwarding rules and delegate access, because these keep working after a password change.
  • Mail access is so common that only volume, client type and destination make theft stand out.

In more detail

Email collection targets the mailbox, which concentrates business detail, personal data, password resets, shared documents and, in an incident, the plans and coordination of the responders themselves. Adversaries gather it in two broad ways: from the client side, by reading local mail store files or taking over an open session on a workstation, and from the server side, by authenticating to a mail platform with stolen credentials or tokens and querying it directly. Server side collection is attractive because it needs no code on the endpoint and returns the whole archive, and it can be persisted simply by adding a forwarding rule, delegation or application token that keeps copies flowing out after passwords are changed. Because mail access is constant and heavy, volume and pattern carry the detection weight: unusual client software, a first time source address, large mail searches, or forwarding destinations outside the organisation. Both directions should be monitored, since removing endpoint access does nothing about a stolen token, and vice versa.

What you will practise

  • Explain why email is a high value collection target during both routine intrusion and incident response.
  • Compare local mailbox collection on a device with server side collection from a mail platform.
  • Explain how forwarding rules, delegation and application tokens extend mailbox access beyond a password change.
  • Identify the log sources on clients and mail platforms that record mailbox access and mail searches.
  • Outline what to review to separate normal heavy mail use from deliberate bulk collection.
