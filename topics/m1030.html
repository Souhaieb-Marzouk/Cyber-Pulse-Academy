M1030 Network Segmentation

M1030Enterprise MitigationVery hardMitigation

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

Network segmentation means splitting a network into zones and allowing only the traffic each zone really needs. A flat network lets any computer reach any other computer. A segmented network puts walls between groups, such as users, servers, and payment systems. The goal is to keep one broken machine from becoming a path to everything else.

Why should you care?

Once an attacker gets one computer, the next step is usually to look around inside. On a flat network they can scan, find servers, and copy data from anywhere. Segmentation limits that movement and also restricts what can leave the network. It turns a company-wide incident into a small one. It also slows the fast spread of ransomware (malware that locks files and demands payment).

How it works, in plain steps

  1. First, map which systems talk to which, on which ports, and how often.
  2. Group systems into zones by trust level and by the data they handle.
  3. Write rules that allow the traffic the map proves is needed and deny the rest.
  4. Add host-level rules on servers, so a machine can be protected even inside a trusted zone.
  5. Control outbound traffic too, so a compromised host cannot reach any internet address.
  6. Review the rules on a schedule and remove temporary openings that were never closed.

Real-world example

Think of an office building with locked doors between departments. A visitor in reception cannot wander into the finance office or the server room. Staff who need to reach another floor use a door that opens only for them and only at certain times. If someone slips in through reception, they are stuck in one corridor. A building with every door propped open would let them walk anywhere.

Key takeaways

  • Assume one machine will be breached, and plan limits around that.
  • Segment the network to reduce movement, then review the rules regularly.
  • Segmentation still fails if administrators share one powerful login everywhere.

In more detail

Network segmentation is the practice of dividing an enterprise network into zones with defined trust levels and restricting traffic between them to what each zone genuinely needs. In modern environments it is implemented less by firewall interfaces and more by a combination of internal micro-segmentation policy enforced on the host or in the virtual network fabric, virtual local area network and routing separation, private endpoints that remove public reachability from data services, and identity-aware proxies in front of administrative interfaces. The purpose is to convert a single compromised host from a launching point for the whole estate into a contained incident. Segmentation breaks the behaviours that carry most intrusions from foothold to impact: internal reconnaissance that depends on broad reachability, lateral movement over remote service protocols such as remote desktop, server message block, and secure shell, and command-and-control that relies on unrestricted outbound access from user subnets. It also constrains exfiltration, because staging servers must reach a route that policy permits rather than any internet destination. The operational reality is that segmentation is a data problem before it is a firewall problem. Nobody can write correct policy without an accurate, current map of which systems talk to which on which ports, and that map is almost never in the documentation. Failure modes are predictable: allow rules written once for a migration and never removed, a broad any-to-any rule between two production zones created during an incident and left in place, flat management networks where hypervisors, backup infrastructure, and jump hosts share a broadcast domain with user devices, and cloud security groups that permit the entire corporate range because enumerating real sources was inconvenient. Segmentation also creates a false sense of safety when the identity plane remains flat, since a single set of reusable administrative credentials can still cross every zone boundary. Segmentation must therefore be paired with privileged access management, multi-factor authentication, and outbound egress filtering rather than treated as a standalone control.

What you will practise

  • Explain how to build a traffic dependency map and use it to design zone policy rather than guessing at requirements.
  • Describe the difference between network-level segmentation, host-based micro-segmentation, and identity-aware proxying of administrative access.
  • Identify the specific lateral movement protocols and internal reconnaissance behaviours that segmentation is intended to disrupt.
  • Explain how egress restriction from server and user zones constrains command and control and data exfiltration paths.
  • Describe how private endpoints and removal of public reachability reduce exposure of data services.
  • Identify the common failure modes that erode segmentation policy over time and the review process that prevents them.
  • Evaluate whether segmentation alone is sufficient given a flat identity plane and recommend complementary controls.
