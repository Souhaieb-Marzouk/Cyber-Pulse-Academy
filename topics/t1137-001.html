T1137.001 Office Application Startup: Office Template Macros

T1137.001PersistenceExtremeTechnique

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

This sub-technique puts harmful macro code inside an Office template file. A template is a file that Office loads when it starts, so the code runs as soon as Word or Excel opens. The user does not need to open a suspicious document, because the template is loaded for them automatically.

Why should you care?

A common protection is to warn about macros in files that arrive by email. A template already sitting on the computer does not arrive by email, so that warning may never appear. The code then runs every time the program starts, giving repeated access. It also survives restarts and looks like an ordinary Office setting.

How it works, in plain steps

  1. Word keeps a base template that every new document copies its styles from.
  2. Microsoft Excel can load a personal workbook file from a startup folder the same way.
  3. An attacker with access to the profile writes macro code into that file or adds one.
  4. The code runs each time the matching Office program starts, which is called application startup.
  5. The registry setting that names the global template can point to another folder or a remote share.
  6. The macro must be trusted before it runs, so the file is often marked as trusted first.

Real-world example

Think of a hotel front desk that reads the same welcome script every morning. A staff member rewrites the script so it also asks each new guest for a spare key. Every receptionist reads the script out loud all day long and follows it, because it is the official script in the official folder. No guest ever had to bring in a strange document.

Key takeaways

  • A template is loaded automatically, so macros inside it run without opening a document.
  • Watch the registry value that names the global template, because it can point anywhere.
  • Compare template and startup files against a baseline of known good versions.

In more detail

Office template macros is the variant of Office persistence that plants attacker code in a template file which Office loads when the application starts. Word keeps a base template in the user profile that supplies styles and settings for every new document, and Excel can load a personal workbook from a startup folder in the same way; because these files are read automatically at launch, a macro stored in one runs without any document being opened. The technique also covers moving the load point rather than the file: the registry value that names the global template can be redirected to any path the attacker chooses, and the template search order can be raced with a file placed earlier in the list, which allows a template to be pulled from a remote location. Two artefacts stand out. First, the template or startup file is modified or created where a user would rarely touch it, and second, macro execution is attributed to a document that the user did not open. Detection therefore compares template file hashes and timestamps against a baseline, watches the registry value that controls template loading, and treats macro execution at application start as suspicious unless the content is known and signed.
