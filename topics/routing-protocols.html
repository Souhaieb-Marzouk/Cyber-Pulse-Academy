Routing Protocols

Network FundamentalsHardKeyword

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

Routing protocols are the rules that routers use to find paths for data. A router must learn which direction leads to another network. It must also choose the best path when several exist. The protocol is the shared language that lets routers tell each other what they know.

Why should you care?

Without routing protocols, every path would need to be typed in by hand. That does not scale and it breaks when a link fails. Protocols let a network heal itself when a cable or a router goes down. They also create trust between devices, and that trust can be abused. A wrong route can send private traffic through a network you do not control.

How it works, in plain steps

  1. A router learns about directly connected networks first and places them in its routing table.
  2. It shares what it knows with neighbour routers, using a common language called a routing protocol.
  3. Common examples are OSPF (Open Shortest Path First) inside a site and BGP (Border Gateway Protocol) between networks.
  4. Each router puts what it learns into a table and applies rules to rank the possible paths.
  5. When a link fails, updates spread and the routers recalculate their best choices.
  6. Administrators limit what each neighbour may advertise, so a wrong route cannot spread freely.

Real-world example

Think of a postal service where each depot knows the roads nearby. Depots tell each other which routes are open and how long they take. A central clerk does not plan every van, because each depot chooses the next stop. If a bridge closes, the nearest depot passes the news along. Trust matters here, because a depot that reports a false shortcut can send every van the wrong way.

Key takeaways

  • Routing protocols let routers learn paths instead of relying on hand written routes.
  • Routers trust their neighbours, so unauthenticated updates are a real risk.
  • A more specific or cheaper route can override a correct one.

In more detail

Routing protocols are the rules routers use to learn which paths exist to a destination and to choose one, and they fall into distance vector, link state and path vector families. A router running a link state protocol floods information about its own links so that every router can build the same map, while a distance vector protocol exchanges reachability and cost with its neighbours and largely trusts what they report. In an enterprise you meet them as OSPF inside a site, BGP between autonomous systems and with an internet provider, and as the routing table that ultimately decides where a packet leaves. The mistake people make is to assume routing is secure by default, because a router will believe a more specific or more attractive route from a peer it has not authenticated, which is how accidental misconfiguration and deliberate route hijacks both propagate.

What you will practise

  • Explain what routing protocols do and why networks need them.
  • Describe the difference between learning routes and choosing between them.
  • Name common routing protocols and say where each is normally used.
  • Explain how a false or misconfigured route can redirect traffic.
  • Outline how authentication and route filtering limit that risk.
