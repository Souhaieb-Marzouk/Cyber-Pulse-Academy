T1482 Domain Trust Discovery

T1482DiscoveryExtremeTechnique

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

This is the work of learning which groups of computers trust each other inside a company network. Windows domains can be linked by trust relationships so users from one domain can use resources in another. An attacker with one account asks the network for that list of links.

Why should you care?

One stolen password is only the start. Trusts show the attacker where that password can reach next without new credentials. They also show where forged login tickets are likely to be accepted. If the attacker knows the whole picture, they can plan a path to the most valuable systems instead of guessing. Seeing this search early gives you a chance to react before that move happens.

How it works, in plain steps

  1. The attacker has one valid account, either stolen or created, and uses it to reach a domain controller.
  2. They ask the directory service which domains this domain trusts, and in which direction.
  3. They repeat the question for other reachable domains so they can build the full picture.
  4. Trust data also shows which domains share identity material, which matters for forged tickets.
  5. They save the list and use it to pick the next target, or to test logins against other domains.
  6. The questions are normal in shape, so only where and how often they happen makes them stand out.

Real-world example

Picture a hospital where staff badges from the city clinic also open certain doors in the main hospital. A visitor finds one working badge on the floor. Before going anywhere, they read the notice board by reception that lists which partner clinics have door access. That list tells them which corridors their single badge can open. The notice board is not secret and nobody guards it, but reading it is not normal behaviour for a visitor either.

Key takeaways

  • Trust discovery is a planning step, so treat it as an early warning signal.
  • The commands used are legitimate admin tools, so context and frequency matter more than the command.
  • Trust information feeds forged ticket attacks, so very few hosts should ever query it.

In more detail

Domain trust discovery maps the relationships that let one Windows domain or forest accept identities from another. An attacker who already holds one valid account queries that graph from inside, because trusts reveal which domains will accept a Kerberos referral or an access token issued elsewhere. The work is done through directory queries or through the Windows directory service trust enumeration interface, and it is frequently wrapped in the built in nltest utility using its trust listing options. What the defender sees is not a file but a short burst of directory and command activity on a host that has no business asking those questions. Trust metadata is valuable because forged tickets, injected security identifier history and cross domain logons all depend on the direction, type and transitivity of a trust.

What you will practise

  • Explain what a Windows domain trust is and why it exists.
  • Describe how an attacker uses trust information to plan lateral movement.
  • Name a built in Windows utility that reveals trust relationships and the interface it uses.
  • Explain how to separate normal administrator trust queries from attacker reconnaissance.
  • Explain why domain controller directory queries belong in your monitoring plan.
  • Describe how trust data supports ticket forging and similar credential abuse.
