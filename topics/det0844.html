DET0844 Detection of Digital Certificates

DET0844Detection StrategyVery hardDetection Strategy

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

This detection looks for new digital certificates that someone creates, rather than ones that arrive with software. A digital certificate is a file that proves a program or website is genuine. The rule watches the systems that make these certificates and the details written inside them. It catches certificates that copy your own naming style.

Why should you care?

A certificate that carries a trusted name can make a harmful file look safe. Attackers may copy your company name inside the certificate to gain trust. If you catch the certificate, you can warn about any file signed with it. The same alert also shows which machine is making certificates it should not.

How it works, in plain steps

  1. The internal certificate authority, or CA, writes a log line each time it signs a request.
  2. Each line records the subject name, the key usage, the requester, and the issue time.
  3. The SIEM collects these lines together with public certificate transparency records.
  4. The rule compares each new certificate with a baseline of approved names and templates.
  5. It also watches for signing activity on hosts that do not normally sign code.
  6. A certificate with an unusual name or a non signing host raises an alert.

Real-world example

Think of a till receipt at a shop. Each sale prints a receipt with the shop name, the item, and the time. One receipt is worth a look if it shows a product the shop never sells. A receipt from a machine that is not a till is also worth a look. The certificate log is that paper trail.

Key takeaways

  • The signal is a new certificate with an unexpected subject or from a non signing host.
  • Internal authority logs and certificate transparency records together give the full picture.
  • Watching the request side catches the work before signed files are used.

In more detail

This detection strategy covers the resource development technique of creating digital certificates, where an adversary builds or obtains a certificate to sign its own tooling so that signed code appears legitimate. It matters because a valid signature on a payload can satisfy trust checks in the operating system and reduce suspicion from users and from some security tools. The telemetry that makes it possible is internal certificate authority issuance logs, certificate transparency logs for public issuance, and endpoint records of signing operations. The main failure mode is that certificate issuance is a normal administrative task, so the rule must separate unusual subjects and non signing hosts from the routine rotation of approved certificates.

What you will practise

  • Explain how certificate creation helps an attacker appear trustworthy.
  • Identify certificate authority and transparency logs used for this detection.
  • Write a rule that flags unusual subjects or requesting hosts.
  • Explain why baseline knowledge of approved templates is necessary.
  • Describe the limits of certificate revocation as a response.
