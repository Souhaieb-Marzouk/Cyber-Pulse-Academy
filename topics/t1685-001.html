T1685.001 Disable or Modify Tools: Disable or Modify Windows Event Log

T1685.001Defense ImpairmentExtremeTechnique

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

On Windows computers, a service called the Event Log writes records of what happens, such as logins and program starts. This technique means an attacker changes that service so it stops writing. They may stop the service, set it to never start, or turn off parts of the audit settings. The aim is to prevent evidence from being created.

Why should you care?

This log is often the main record of who did what on a computer. If it stops writing, the attacker's next steps leave no trace, and the response team loses the timeline they need. Detecting the change itself matters, because after the log is off, evidence is gone. You also need a copy of the logs somewhere else, safely out of reach.

How it works, in plain steps

  1. The attacker gets administrator rights, or finds a registry path they can already change.
  2. They stop the Event Log service, or set its startup type to disabled.
  3. They may edit registry keys that control how the log starts at boot time.
  4. They can also use the audit policy tool to turn off whole audit categories.
  5. After a reboot, the service stays off and new events are never written.
  6. Activity continues while analysts see an empty or quiet log.

Real-world example

Imagine a hospital night desk where the shift book records every key handed out. Someone tears out the remaining blank pages and locks the book in a drawer. The staff still work through the night, but nothing is written down. In the morning, the manager cannot tell who took which key or when.

Key takeaways

  • Alert on changes to the Event Log service, its startup type, and audit policy.
  • Store log copies on a separate, well-protected collector.
  • An unexplained silence in event flow is itself a strong warning sign.

In more detail

This sub-technique targets the Windows Event Log service, the component that writes the records analysts depend on for authentication and process activity. Unlike clearing existing logs, the objective here is to stop or reconfigure collection, so the service no longer starts, no longer writes, or no longer receives the audit categories of interest. Behaviours include changing the service startup type, modifying the Start value under the service and WMI autologger registry keys, and adjusting audit policy through the Local Security Policy interface or with auditpol, including switches that disable success and failure auditing for an entire category. Because each of these actions is itself auditable, detection rests on correlating the change event with the expected service state, with the acting account, and with a change record. Legitimate maintenance follows a documented window and leaves monitoring intact; tampering usually happens outside those windows and is accompanied by a sudden silence in forwarded events.

What you will practise

  • Explain how this sub-technique differs from its parent by targeting collection rather than stored data.
  • Describe the service and registry changes that stop Windows Event Log writing.
  • Explain how audit policy settings control which events are recorded at all.
  • Identify the event and configuration artefacts that expose the tampering.
  • Describe why remote log forwarding limits the value of disabling the local service.
