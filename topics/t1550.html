T1550 Use Alternate Authentication Material

T1550Lateral MovementExtremeTechnique

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

When you log in, your computer receives a kind of proof that you already logged in. It uses that proof for the next few hours, so you do not type your password again. This parent technique is when an attacker steals that proof and logs in as you. They never learn your password.

Why should you care?

You cannot stop this attack by changing your password, because the password is not being used. The stolen proof keeps working until it expires. Attackers use it to move from one machine to the next, quietly collecting more and more access along the way.

How it works, in plain steps

  1. You sign in with your password and any second factor the organisation requires.
  2. The system creates proof of that login, such as a password hash or a ticket.
  3. The proof is kept in memory or saved on disk so you are not asked again.
  4. The proof is meant to be protected, but attacker tools can read it from the system.
  5. The attacker presents that proof to another computer or service, which accepts it.
  6. The new system sees a valid login, so the access looks normal in most reports.

Real-world example

Think of an airport lounge where the receptionist stamps your hand when you show your boarding pass. For the rest of the day, the stamp alone gets you in. If somebody copies the stamp, they walk past the desk without a ticket. The stamp is genuine, so nobody questions it. Changing your flight does nothing, because the desk never looks at your ticket again.

Key takeaways

  • Stolen login proof works without your password, so password resets are not enough.
  • Each type of proof expires on its own schedule, which limits or extends the damage.
  • Look for valid logins from unexpected machines or places, not just failed ones.

In more detail

This is a parent technique covering lateral movement that reuses material a system generated after a successful login instead of replaying a password. The material takes three main forms: NTLM password hashes, Kerberos tickets, and OAuth or API access tokens. Each is created precisely so the user is not asked for credentials again, which means each is stored on disk or held in memory where credential access tooling can lift it. Reuse bypasses the interactive logon path entirely, so password changes and some multi-factor prompts have no effect. The defender's evidence is therefore not a failed login but an anomalous successful one: authentication events whose source workstation, account pairing or logon type does not match that identity's baseline, plus the ticket and token artefacts themselves. Distinguishing abuse from legitimate activity depends on correlation, because every protocol involved is one the environment genuinely uses all day.

What you will practise

  • List the main kinds of alternate authentication material and where each is stored.
  • Explain why reused login proof defeats password changes and some second factors.
  • Describe how authentication events differ when material is replayed rather than typed.
  • Explain the difference between stealing a password hash and stealing a ticket.
  • Identify the log sources and baselines that help separate reuse from normal traffic.
