DET0183 Detection Strategy for Lateral Tool Transfer across OS platforms

DET0183Detection StrategyVery hardDetection Strategy

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

This detection looks for files that are copied from one computer to another inside your own network. Attackers do this to spread their tools after they break into the first machine. The rule watches how the file moves, not what the file contains.

Why should you care?

An attacker who stays on one computer is a small problem. An attacker who copies tools to twenty computers is a large one. The copy step is a rare event on most networks, so it is a good place to look. Catching it early limits how far the intruder can spread. It also gives your team a clear list of machines to clean.

How it works, in plain steps

  1. A computer writes a file to a shared folder on another computer.
  2. Your monitoring tool records that file creation, with the file name and the full path.
  3. At the same time, the receiving computer records a network logon from the sending machine.
  4. The detection joins these two events when they happen within a short time window.
  5. It then checks whether the account or the source computer is allowed to do this.
  6. If the account is unusual, or the folder is a temporary one, the rule raises an alert.

Real-world example

Think of a hotel where guests may use the business centre printer. Every print job leaves a log: who printed, from which room, and at what time. A guest printing one page is normal. A guest printing fifty pages, then walking to another floor and printing there, looks strange. The printer log does not tell you what was printed. It tells you the pattern, and the pattern is what makes the staff look up.

Key takeaways

  • Copying tools between hosts is a normal administrator action and a common attacker action.
  • The alert is about the pattern: who copied, from where, to which folder, and when.
  • You must baseline your normal deployment tools or the rule will be too noisy to use.

In more detail

This strategy covers lateral tool transfer, the stage where an adversary copies binaries, scripts or utilities from one compromised host to another inside your estate. The technique matters because it turns a single foothold into a distributed toolkit, and because the copy itself is often the first loud event of an intrusion chain. Detection depends on correlating network logon and share access telemetry with process creation and file creation on the receiving host. The main failure mode is noise: legitimate administrative scripting, software deployment and monitoring agents move files over the same administrative shares and remote service paths, so a rule that ignores the source identity and the destination directory will drown the analyst in benign hits.

What you will practise

  • Explain why lateral tool transfer turns one compromised host into an estate-wide problem.
  • Identify the telemetry that proves a file moved from one host to another.
  • Correlate a network logon event with a file creation event inside a short time window.
  • Separate administration shares used by deployment tooling from attacker staging paths.
  • Scope the rule to server tiers and service accounts where copying is rare.
  • Describe the coverage gap created by filtering out known management hosts.
