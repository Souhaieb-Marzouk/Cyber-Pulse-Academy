T1016.001 System Network Configuration Discovery: Internet Connection Discovery

T1016.001DiscoveryExtremeTechnique

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

This technique means checking whether a computer can reach the internet. The attacker sends a small test to a public address and waits for an answer. The parent technique maps all of a host's addresses and routes. This sub-technique asks only one question, which is whether this machine can get out at all.

Why should you care?

Harmful software needs to know whether its owner can be reached before it tries to connect. An answer helps the attacker choose a working path and avoid wasted attempts. It also shows whether a proxy or filter stands in the way. For you, the test looks like normal traffic, which makes it hard to spot.

How it works, in plain steps

  1. The attacker picks a simple test, such as a ping to a public address.
  2. They watch for a reply, and they note how long it takes.
  3. They try a web request to a well known site and check the response code.
  4. They may run a speed test to measure how much data the line can carry.
  5. They repeat the test through any proxy or redirector they plan to use.
  6. They use the result to decide whether to contact their command and control server.

Real-world example

Imagine you are about to post a letter, but the office door may be locked. Before writing anything, you walk down the corridor and try the handle. If it opens, you go back and fetch the letter. If it does not, you start looking for another exit. Internet connection discovery is that short walk to the door. The letter stays in your pocket until you know it can leave the building.

Key takeaways

  • This sub-technique answers one question, while the parent maps the whole network setup.
  • The probes look normal, so always pair them with what the host does next.
  • Public checker sites are common cover for this test on servers that should not browse.

In more detail

Internet connection discovery is the sub-technique of checking whether a host can reach the internet at all and by which path. It differs from its parent in intent rather than in tooling: the parent maps the host's addressing, gateway and routes, while this check answers a simple yes or no question before the adversary commits to contacting command and control infrastructure. Common methods are the ping utility, route tracing probes, simple web requests to public sites, and speed or bandwidth tests. The answers reveal whether the route out is filtered, whether a proxy or redirector sits in the path, whether a captive portal stands in the way, and roughly how much data the link can carry. Telemetry comes from process creation records, name resolution queries, proxy logs and firewall sessions. The difficulty for defenders is that these probes look exactly like ordinary user and update traffic, so the useful signal is the combination: an unusual host contacting a public checker, followed quickly by a connection to an unfamiliar destination.
