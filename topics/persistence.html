Persistence

Offensive SecurityVery hardKeyword

Persistence is the collection of mechanisms an intruder uses to retain access across reboots, password changes, session expiry and partial remediation, so that initial access does not have to be won again. Host-based persistence attaches to legitimate startup behaviour: autostart entries, scheduled tasks, system services, logon scripts, shell profiles, and browser or office extensions. Identity-based persistence is often more valuable and harder to see, because it lives in the directory or cloud tenant rather than on an endpoint; examples include newly created accounts, added credentials or keys, modified federation settings, and application registrations with delegated permissions that outlive any single session. Network-based persistence covers configurations that survive host rebuilds, such as remote access profiles, tunnels and backup channels. Every mechanism trades stealth against resilience, and defenders can exploit that trade-off: the more durable the mechanism, the more likely it is to touch a monitored location, generate an audit record, or require a privileged change. Practical detection therefore starts from an accurate baseline of what is allowed to autostart, which scheduled tasks and services normally exist, and which principals hold privileged roles. Deviations from that baseline, combined with audit events for account creation, permission grants and application registration, give far better coverage than hunting for specific tools. Mitigation combines application control, privileged access management with approval workflows, credential hygiene, and centralised logging that an intruder cannot quietly edit.

What you will practise

  • You will be able to categorise persistence mechanisms as host-based, identity-based or network-based.
  • You will be able to explain the trade-off between resilience and stealth for common autostart mechanisms.
  • You will be able to build a baseline of legitimate autostart locations, services and scheduled tasks.
  • You will be able to spot tenant-level persistence through account creation, credential addition and application registration.
  • You will be able to recommend controls that make durable access expensive for an intruder.
