T1556.006 Modify Authentication Process: Multi-Factor Authentication

T1556.006PersistenceExtremeTechnique

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

Multi-factor authentication asks for two different proofs when you sign in, such as a password and a code. This technique means an attacker switches that second check off or replaces it with something they control. After that, a password alone is enough to get in.

Why should you care?

Multi-factor authentication is one of the strongest protections you have when a password is stolen. If an attacker can weaken it quietly, every other account control loses much of its value. Administrators change these settings for real reasons, so the change blends into normal daily work. The attacker then keeps access even after the password is reset, unless somebody finds the change.

How it works, in plain steps

  1. After stealing a password, an attacker looks for a way to avoid the second proof.
  2. They remove the account or group from the policy that requires the second factor.
  3. They may register a new authentication method, such as a phone number they control.
  4. On a local server, they can edit the hosts file to send checks to the wrong place.
  5. The check then fails, and a lenient policy may allow the sign-in to continue.
  6. All of this uses normal administrative features, so it looks like ordinary management.

Real-world example

Imagine a bank that asks for your signature and then phones you to confirm a large withdrawal. Nobody can fake that phone call. Now somebody slips into the back office and removes your name from the list of customers who need a call. The signature is still checked at the counter, so nothing looks wrong to the teller. Withdrawals continue as normal, and the only evidence is the quiet change to the call list itself.

Key takeaways

  • Watch identity policy changes as closely as you watch the sign-ins themselves.
  • A new authentication method registered after an odd sign-in is a strong warning sign.
  • Review any policy that fails open when the second factor cannot be checked.

In more detail

Multi-factor authentication raises the cost of a stolen password by requiring a second proof, so attackers who already hold working credentials often weaken or remove that second check rather than breaking it. The work is usually administrative rather than technical: an intruder with enough rights edits the identity provider, removes a user or group from the policy that enforces the second factor, or registers an authentication method they control, such as a new phone number or application enrolment. Some approaches are local, for example editing the hosts file on a server so that requests to an external authentication service resolve to the local machine, which can make the check fail and, under a permissive failure policy, let the sign-in continue anyway. Because each of these actions uses supported administration features, the activity appears in the same audit records as routine identity management. Useful signals are policy changes outside working hours, exclusions that target a single account, new authentication methods registered soon after an unusual sign-in, and authentication successes that suddenly lack the second factor.

What you will practise

  • Explain what multi-factor authentication adds to a password.
  • Describe how exclusions and new authentication methods weaken the second factor.
  • Explain how a local hosts file change can make authentication fail open.
  • Identify the audit records for policy changes and authentication method registration.
  • Distinguish routine identity administration from malicious policy weakening.
