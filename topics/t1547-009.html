T1547.009 Boot or Logon Autostart Execution: Shortcut Modification

T1547.009PersistenceExtremeTechnique

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

A shortcut is a small file that points at another file or program. When you open the shortcut, Windows opens whatever it points at. An attacker can create a shortcut that points at their own program, or change an existing one to point somewhere else.

Why should you care?

Shortcut files are everywhere and people trust them. A shortcut in a startup folder runs as soon as you log in, so the attacker's program starts again after every reboot. Because the name and icon can look exactly like a program you already use, you may click it yourself without noticing. This method is also common in email attacks, where the shortcut arrives as an innocent-looking attachment.

How it works, in plain steps

  1. A shortcut stores a target path, plus arguments and a working folder, in a small structured file.
  2. Windows or the desktop shell reads those fields and launches the target when the shortcut is opened.
  3. Anything placed in a startup folder is opened automatically when the user logs in.
  4. An attacker writes a shortcut that targets their payload, or edits a shortcut the user already has.
  5. The attacker copies a familiar name, icon, and description so the file looks legitimate.
  6. Detection inspects the stored target and arguments, and checks what process the shortcut started.

Real-world example

Think of a post office where the courier follows a note pinned inside each front door. The note says which parcel to collect and where to leave it. Anyone who can reach the door can replace the note with one that sends the courier to a different address, and the courier will still deliver cheerfully, because the note looks exactly the same.

Key takeaways

  • Treat shortcut files as instructions that can be edited, not as harmless icons.
  • Review what shortcuts in startup folders actually point at, including their arguments.
  • Check which process a shortcut started and where that program lives on the disk.

In more detail

Shortcut modification uses the shortcut file format itself as the persistence carrier. A shortcut is a small file that points at a target, and anything that opens it launches whatever the target names, so an adversary can create a new shortcut whose target is their payload or edit an existing shortcut so the usual program is replaced. Placement in a startup folder means the shortcut is opened during user logon, and the visible name, icon, and description can mimic legitimate software, which makes the artefact read as a normal user convenience rather than an intrusion. The same indirection appears in infection chains, where a shortcut arrives as an email attachment and launches a script interpreter or a remote resource, and in browser extension directories, where a modified shortcut can relaunch unwanted code. Detection centres on file creation in startup locations, on the arguments and target paths stored inside shortcut files, and on the process lineage that follows, since a shortcut launched by the shell produces unusual parent and child combinations.

What you will practise

  • Explain what a shortcut file contains and how the operating system uses it to launch a program.
  • Describe how an attacker creates or edits a shortcut to achieve execution at logon.
  • Identify startup locations where a malicious shortcut provides persistence.
  • Detect suspicious shortcut creation and modification using file monitoring and process creation records.
  • Recognise how shortcut indirection and masquerading combine in email-borne attacks.
  • Explain why a shortcut that replaces a legitimate one is harder to notice than a new file.
