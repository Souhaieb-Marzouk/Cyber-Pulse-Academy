Defence in Depth

Security ArchitectureHardKeyword

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

Defence in depth means using several different protections instead of trusting one. If one control fails, another still stands in the way. The layers cover people, networks, devices, applications and data. The idea comes from armies that build more than one wall around a city.

Why should you care?

Any single protection can fail, because software has bugs and people make mistakes. If everything depends on one wall, one failure means a full breach. Different kinds of controls also fail in different ways, so a mix is stronger than a pile of similar tools. Layers give you time to notice an attack and to respond. Planning for recovery matters too, because some attacks will succeed.

How it works, in plain steps

  1. The team lists the assets worth protecting, such as customer data and payment systems.
  2. They choose several controls that work in different ways along the attack path.
  3. Each layer assumes that the layer before it may already have failed.
  4. They test the layers, including what happens when one is switched off.
  5. They watch the logs so that a failure in one layer is noticed quickly.
  6. They plan how to recover if several layers fail at the same time.

Real-world example

Imagine an airport on a busy night. A traveller passes a ticket check, a bag scan, a passport desk and finally a gate check. Each step looks at something different, so a person who slips past one is usually caught by the next. If all four checks used the same machine and asked the same question, one clever answer would open every door. The airport also has cameras and staff who watch for anything odd. It has a plan for closing a terminal if needed. That mixture of different checks, watching and recovery is defence in depth.

Key takeaways

  • Use different kinds of controls, so one failure does not open everything.
  • Test each layer, including what happens when it is removed.
  • Include detection and recovery, not only prevention.

In more detail

Defence in depth is the principle of layering independent security controls so that the failure of any single control does not lead directly to compromise. It comes from military thinking about overlapping defensive positions, and it appears in security architecture as identity checks, network segmentation, hardened hosts, endpoint detection, monitoring and recovery arranged so an attacker must defeat several different mechanisms. The layers should also be diverse: three products that inspect the same traffic in the same way fail together, whereas a network control and an application control usually fail for different reasons. The common mistake is counting controls instead of testing them, or adding layers that all depend on one shared component such as a single directory service or a single administrator account. Depth also means planning for detection and recovery, not only prevention.

What you will practise

  • Explain what defence in depth means and where the idea comes from.
  • Describe how layers are arranged along the path an attacker must take.
  • Explain why diverse controls are stronger than several similar ones.
  • Identify shared dependencies that can defeat a layered design.
  • Describe how testing, monitoring and recovery support a layered architecture.
