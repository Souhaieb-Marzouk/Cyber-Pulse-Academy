DET0826 Detection of Gather Victim Host Information

DET0826Detection StrategyVery hardDetection Strategy

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

This detection watches for signs that someone is learning about the computers in your network. It catches activity that collects details such as operating system, installed software, open ports, and hardware type. The aim is to spot the study phase that comes before an attack.

Why should you care?

An attacker who knows your systems can pick the right tools and the right weakness. That makes the later attack faster and more likely to work. Many teams only watch for the break in, not the study before it. Catching this early gives you time to block the source. It also tells you which systems an intruder already cares about.

How it works, in plain steps

  1. Endpoint and inventory tools record each time a program lists installed software or system details.
  2. A central log, such as a security information and event management system, collects those records.
  3. The rule looks for many inventory style lookups from one account or one host in a short time.
  4. It also adds records of port scans and directory computer searches that come from the same source.
  5. Analysts compare the source with a list of approved scanners and inventory servers.
  6. If the source is not approved, the system raises an alert for a person to review.

Real-world example

Think of a night watchman in a large office building. Before a burglary, someone often walks the halls and notes which doors are unlocked and which windows are old. The watchman alone cannot arrest anyone, but the walking pattern is a clear clue. In the same way, an odd burst of inventory lookups is not an attack by itself, but it tells you that someone is mapping your building.

Key takeaways

  • Host information gathering is the study step that comes before an attack.
  • The same tools your own team uses create the same pattern, so approved sources must be filtered out.
  • Correlating the source across endpoint, directory, and network logs turns weak signals into a useful one.

In more detail

This strategy detects Gather Victim Host Information, the reconnaissance step in which an adversary learns the hardware, software, and configuration of hosts in your environment. It matters because that inventory shapes everything that follows: the tooling they bring, the vulnerabilities they try, and the phishing lures they write. Detection depends on joining endpoint inventory queries, directory LDAP searches for computer objects, and external vulnerability or port scan telemetry, then correlating them by source. The usual failure mode is volume: legitimate asset management, patch, and inventory tools touch the same systems constantly, so the value comes from comparing a source against its own baseline rather than from a single event.

What you will practise

  • Explain why host information gathering is treated as a detectable step before exploitation
  • Identify the telemetry sources that record system, software, and port discovery activity
  • Correlate an inventory query with a later scan from the same source address or account
  • Build an allow list of approved inventory and scanning hosts to reduce false alerts
  • Recognise the point at which reconnaissance becomes preparation for a specific attack
