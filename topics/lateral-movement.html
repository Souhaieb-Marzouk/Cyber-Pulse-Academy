Lateral Movement

Offensive SecurityExtremeKeyword

Lateral movement is the progression from one compromised system or identity to others inside the same environment, performed to reach valuable data, higher authority, or a position from which the final objective can be achieved without returning to the internet. It rarely relies on a novel exploit; most real intrusions reuse credentials, sessions and administrative tooling that already exist. Typical mechanisms include interactive remote access over desktop, terminal or remote management protocols, authenticated file sharing and remote service creation, execution frameworks that push jobs to many machines at once, and control-plane operations in cloud or virtualisation platforms that reach many workloads through a single API. Credential reuse drives much of it, whether the material is a plaintext password, a password hash, a cached ticket or a long-lived API key, and it is frequently shared service accounts and duplicated local administrator passwords that make the movement cheap. Detection depends on joining authentication events to host and network context: a workstation authenticating to another workstation, an account logging in from a system it never normally touches, remote service or scheduled task creation, and east-west traffic that crosses a segmentation boundary. Mitigations reduce the number of usable hops rather than the number of alerts: segmented networks with default-deny rules between tiers, unique local administrator credentials, dedicated privileged access workstations, just-in-time administration, and removal of legacy authentication protocols. In cloud estates the same logic applies to role assumption paths and to network reachability between workloads.

What you will practise

  • You will be able to explain why lateral movement is dominated by credential reuse rather than exploitation.
  • You will be able to identify the authentication and host telemetry that reveals movement between systems.
  • You will be able to describe how segmentation, administrative tiering and unique local credentials reduce reachable paths.
  • You will be able to interpret east-west network flow data to spot traversal across trust boundaries.
  • You will be able to trace a role-assumption chain in a cloud tenant as a form of lateral movement.
