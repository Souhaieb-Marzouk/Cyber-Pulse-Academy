DET0410 Detection Strategy for Data from Network Shared Drive

DET0410Detection StrategyVery hardDetection Strategy

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

A network shared drive is a folder on a server that many people can open over the network. This detection watches for a computer or user reading far more files from such a share than usual. It catches an attacker who is stealing documents, not breaking in. The collection step is what this rule sees.

Why should you care?

Shared drives often hold contracts, finance files and personal data. An attacker who reaches one can copy years of work in minutes. The activity uses normal file access, so a firewall or anti virus product sees nothing wrong. File servers are also busy, so the reading hides among real work. Seeing the pattern early gives you time to block the copy and find the stolen data.

How it works, in plain steps

  1. The server writes an audit record when someone opens a file on a share. It includes the account, the file path and the client address.
  2. Those records are sent to the central log platform, which is the system that stores and searches security events.
  3. The rule counts how many different files each account reads per share in a set period, for example ten minutes.
  4. It compares that count with the normal number for the same account on the same share at the same hour.
  5. A large jump, or many files from folders the account never uses, increases the score for the event.
  6. When the score passes the threshold, an analyst gets an alert. The alert names the account, the client machine and the files.

Real-world example

Picture a hospital sign in sheet at a records office. Each clerk who takes a patient folder writes it down, and the office is busy all day. One visitor signs for folder after folder from shelves they have no reason to touch. No single signature is strange. The pattern of hundreds of folders in an hour tells the supervisor to step in.

Key takeaways

  • Theft from a shared drive looks like normal work, so you must measure volume and scope, not just access.
  • Per user and per share baselines are what make the rule usable on a busy file server.
  • Client address and file path are the two fields that connect the reading to a real person.

In more detail

This strategy detects collection of data from network shared drives, the behaviour described by T1039, where an adversary who already has access to a file server browses and copies documents rather than deploying new tooling. It matters because shared drives usually hold the most sensitive business records in an organisation, and theft from them looks like ordinary file access, so it is often discovered only after data appears elsewhere. The telemetry that makes detection possible is file server auditing: Windows Security event 5140 and 5145 for share and detailed file access, Sysmon event 11 for file creation on endpoints, and access logs from storage appliances that record the client address and the share name. The main way this fails is sheer volume, because normal business units read thousands of files a day, so a useful rule must model per user and per share read ratios rather than alert on any single file read.

What you will practise

  • Describe how share access auditing records who opened which file from which client.
  • Build a simple per user baseline of distinct files read per share per hour.
  • Identify the file paths and folder owners that should always be treated as sensitive.
  • Correlate share read activity with later outbound network transfer from the same client.
  • Choose thresholds that separate bulk copying from ordinary document review.
  • Explain to a business owner why the file server audit policy must stay enabled.
