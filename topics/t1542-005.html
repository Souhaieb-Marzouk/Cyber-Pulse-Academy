T1542.005 Pre-OS Boot: TFTP Boot

T1542.005PersistenceExtremeTechnique

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

Network devices can download their operating system from a server when they start. This is called network booting or netboot. This sub-technique is an attacker making the device download a harmful image instead of the real one.

Why should you care?

The device runs the wrong software from the first second. Its settings can look normal while its behaviour is changed. It can keep a hidden way in for the attacker. This is hard to spot because network booting is a normal, useful feature.

How it works, in plain steps

  1. The parent topic covers pre boot attacks in general. This sub-technique uses a file transfer server and the device's boot settings.
  2. Administrators normally set each device to fetch its image from one trusted server on the network.
  3. The attacker changes that setting so the device points to a server they control instead.
  4. They then place a modified image on their server. The file looks like the real one but contains extra code.
  5. When the device restarts, it downloads and runs that image, so the harmful code runs from the very start.
  6. Defenders compare each device's image version and checksum with the approved build and review boot setting changes.

Real-world example

Imagine a school where every classroom gets its worksheets from the print room each morning. Someone redirects one classroom to a different cupboard in the same corridor. The teacher collects the sheets and hands them out without noticing that the questions were changed overnight.

Key takeaways

  • Record the approved boot image version and checksum for each network device.
  • Watch for changes to boot server settings and for image downloads from unexpected servers.
  • Restrict access to the file transfer service used for booting, because it is the delivery path.

In more detail

TFTP Boot is the Pre-OS Boot sub-technique in which an adversary abuses network booting so that a network device loads an unauthorised operating system image from a file transfer server at start up. Network booting is a normal administration feature: a device is told which server holds its image, downloads that image over the Trivial File Transfer Protocol, and runs it, which lets a team keep many devices consistent from one central source. The attack works by changing the boot configuration on the device so it points at a server the attacker controls, so on the next start or reset the device fetches and runs a modified image. In practice it is often combined with image modification, because the attacker must alter the file the device loads, and the outcome is a device that behaves normally in configuration views while carrying changed behaviour, added capabilities or a backdoor. The parent technique covers pre boot persistence generally, and this sub-technique is closest to the network device boot loader case: both end with the device running an image the owner never approved, but this one depends on a server and a configuration pointer rather than on overwriting the loader itself. Detection looks at the transfer and the pointer: file transfer service logs showing boot image requests from unexpected clients or to unexpected servers, configuration changes to boot settings, restarts without a change ticket, and image version or checksum mismatches against the approved build.

What you will practise

  • Explain what network booting is and why organisations use a central image server.
  • Explain how this sub-technique differs from the ROMMONkit sub-technique of the same parent.
  • Describe how a boot configuration pointer is changed to load an unauthorised image.
  • Identify the logs and version checks that expose an unexpected image download at start up.
  • Explain why a modified boot image can leave device configuration views looking correct.
