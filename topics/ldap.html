LDAP

Identity & AccessVery hardKeyword

The Lightweight Directory Access Protocol (LDAP) is an application protocol for accessing and maintaining distributed directory information services, and it remains the directory backbone behind Active Directory, OpenLDAP and most enterprise identity stores. Data is organised as a hierarchical tree of entries, each identified by a distinguished name and described by attributes constrained by a schema, with object classes determining which attributes are permitted. Clients bind to the directory to establish an identity and a level of access, then search with a base, a scope and a filter to retrieve or modify entries. Authentication outcomes depend on the bind and on transport: simple binds send credentials that are only protected by the transport, so LDAP over TLS or a SASL mechanism such as GSSAPI is required for any operation crossing an untrusted segment, and referrals and anonymous binds must be deliberately disabled unless a specific integration demands them. The dominant application-layer weakness in directory-connected software is filter injection, where unescaped user input is concatenated into a search filter so that an attacker can alter the logic of the query and, in badly written authentication code, bind as another user or enumerate the directory. Directory design carries its own risk: overly broad read permissions on the user object class enable reconnaissance of accounts, groups, service principals and delegation settings, and stale accounts or nested groups accumulate effective privilege that nobody intended to grant. Defenders monitor for anomalous bind failures, unusual search filters, high-volume enumeration and changes to privileged groups or directory-integrated objects.

What you will practise

  • You will be able to describe the directory information tree, distinguished names, schema and object classes well enough to read an LDIF entry.
  • You will be able to choose an appropriate bind mechanism and explain why simple binds require transport encryption.
  • You will be able to identify LDAP filter injection in application code and describe how input escaping prevents it.
  • You will be able to reduce directory exposure by restricting anonymous binds, referrals and overly broad read permissions.
  • You will be able to detect directory enumeration and privileged group modification from directory server logs.
  • You will be able to trace effective group membership for an account and explain why nested groups complicate least privilege.
