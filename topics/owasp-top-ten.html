OWASP Top Ten

Application SecurityHardKeyword

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

OWASP is a community group that studies how web applications are attacked. It publishes a list called the Top Ten, which describes the ten most common kinds of weakness in web software. Each item on the list explains the problem and how to reduce it. The list is guidance for developers, not a law or a certificate.

Why should you care?

Most attacks do not use clever new tricks, they repeat mistakes that have been made for years. A shared list helps developers, testers and managers talk about the same problems in the same words. Building checks into the way you write software is far cheaper than fixing a breach later. If you ignore the list, you risk repeating faults that other teams already learned to avoid. It is also a useful teaching tool for new engineers.

How it works, in plain steps

  1. A community of security specialists collects data on weaknesses found in real applications.
  2. They group the findings into a small number of named risk categories.
  3. The list is published with a plain description of each category and how it causes harm.
  4. Teams use it to plan training and to write review checklists for their own software.
  5. Testers check each category against the actual application instead of just naming it.
  6. Findings are fixed in the code and the checklist is updated for the next release.

Real-world example

Think of a driving safety guide. It lists the most common causes of road accidents, such as speeding or driving too close. The list warns you where accidents happen, but it does not make you a safe driver by itself. You still have to check your own speed and distance, and a driving instructor watches you do it. Simply ticking the list after a short drive proves nothing about your driving.

Key takeaways

  • The OWASP Top Ten is awareness guidance, not a standard you can pass or fail.
  • Each category tells you where to look, and you must still verify your own application against it.
  • The list changes over time, so always say which edition you are referring to.

In more detail

The OWASP Top Ten is an awareness document published by the Open Worldwide Application Security Project that lists the categories of risk most commonly found in web applications, ordered by a combination of how widespread the weakness is, how often it is exploited and how much impact it has. It is not a standard you can be certified against, not a testing methodology, and not a complete list: it is a periodic snapshot of the community's view of which risk classes deserve attention, and each category is backed by a description, examples and prevention guidance. Practically, organisations use it as a common vocabulary in code review checklists, developer training, procurement questions and secure development lifecycle gates, while testers map technical findings back to a category so managers can see patterns. The recurring mistake is to treat the list as a test plan and then claim coverage because each heading was mentioned once, when in reality the categories only tell you where to look; the mapping must be translated into concrete verification activities, such as checking that access control decisions are enforced server side, that user supplied data never reaches interpreters unchecked, and that components are inventoried and updated. The numbering is revised over time as the threat landscape changes, so citing a position without the edition year is meaningless.

What you will practise

  • Explain what the OWASP Top Ten is and what kind of document it is not.
  • Describe how the categories are chosen and why the numbering changes between editions.
  • Use the list as a shared vocabulary in code review, training and procurement discussions.
  • Translate a listed risk category into concrete verification activities for a real application.
  • Explain why mentioning every category does not demonstrate that an application is secure.
