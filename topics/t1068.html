T1068 Exploitation for Privilege Escalation

T1068Privilege EscalationExtremeTechnique

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

A vulnerability is a mistake in a program that lets someone do something the author did not plan. This technique is when an attacker uses such a mistake to gain more power on a computer. That extra power may be administrator or system level.

Why should you care?

Most harmful code starts with the same rights as the person who is logged in. Those rights are often not enough to install a service or read protected files. A successful exploit removes that barrier. This means an unpatched computer can be lost even when nobody did anything obviously wrong.

How it works, in plain steps

  1. The attacker looks for a program that runs with high rights and has a known flaw.
  2. They run code that uses that flaw to take control of the program.
  3. The program then carries out the attacker's wishes with its own higher rights.
  4. Sometimes the target is the operating system kernel, which has the highest power.
  5. In one common variant, the attacker loads an old signed driver that is known to be unsafe.
  6. The same idea can let an attacker step out of a virtual machine onto the host.

Real-world example

Think of a hotel where guests may use the pool but not the manager's office. The office door has a faulty lock that opens if you push it in a certain way. A guest who notices this can walk in and take the master keys off the hook. Nothing was broken and no alarm rang. A software flaw used for privilege escalation works the same way. The door was already there, and the lock was already faulty.

Key takeaways

  • Patching removes the flaws that privilege escalation depends on.
  • Unexpected high rights activity by an ordinary user account is a serious signal.
  • A valid software signature proves who made a file, not that the file is safe.

In more detail

Exploitation for privilege escalation is the use of a programming flaw in software the victim already runs to gain rights the attacker was not granted. The target is chosen for its privilege level: a service running as system or root, a kernel component, a setuid program on Linux, or a driver that runs in the most trusted processor mode. The exploitation itself is usually a memory safety bug, a logic error in an interface, or a flaw in how an object is validated, and it is frequently paired with prior discovery to pick a component with a known unpatched flaw. A distinct variant avoids shipping a novel exploit altogether: the attacker brings a legitimately signed but outdated driver that is already known to be vulnerable and loads it, so the operating system accepts the file because the signature is valid while the code inside is unsafe, a pattern known as bring your own vulnerable driver. The same class of flaw lets an attacker cross a virtualisation boundary from a guest virtual machine or a container onto the host. Detection leans on context rather than a single signature. Process creation telemetry shows an unusual binary started by a low privileged user, or an unexpected child process of a privileged service; service installation events in the System log record new drivers being registered; memory protection and crash data hint at memory corruption; and an endpoint agent may see code running outside the expected image on disk. The benign lookalike is patching and driver installation, which is why the reviewer checks who installed the component, from which path, and whether a change record exists.

What you will practise

  • Explain what privilege escalation means and why a software vulnerability enables it.
  • Describe how exploitation moves an attacker from user rights to system or root rights.
  • Explain the bring your own vulnerable driver pattern and why a signature is not a safety check.
  • Identify the process, service and driver events that indicate exploitation on a host.
  • Distinguish malicious exploitation from routine patching and driver installation.
