T1566.001 Phishing: Spearphishing Attachment

T1566.001Initial AccessVery hardTechnique

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

A spearphishing attachment is a targeted email that carries an infected file. The message is written for one person or a small group, often using details from their job or a recent project. The attacker needs the reader to open the file, because the file starts the attack. It arrives as a document, an archive, or a shortcut rather than an obvious program.

Why should you care?

Email filters catch a lot, but they miss files that look harmless until they are opened. Attackers hide the real file inside an archive, or use a document that asks the reader to enable content. They also study the organisation first, so the message names a real colleague or a real invoice. One person opening one file can give an intruder a foothold inside your network, and from there they move quietly.

How it works, in plain steps

  1. The attacker researches a target and finds a topic that will feel familiar and urgent.
  2. They send an email with a file attached, and the message gives a reason to open it.
  3. Opening the file may ask the reader to allow macros, which are small programs inside documents.
  4. Once allowed, the document starts another program, such as a script or a system tool.
  5. That program contacts the internet, so the attacker now has a way in and can keep working.

Real-world example

Picture a parcel delivered to your desk with your name spelled correctly and a note saying it is the invoice you asked about. Nothing about it feels wrong, so you open the box. Inside, a small device wakes up and unlocks the loading bay doors. Spearphishing attachments are that parcel. The wrapping is familiar, the label is accurate, and you must open it for the trap to spring.

Key takeaways

  • A familiar sender and a familiar filename are not proof that a file is safe.
  • Treat any request to enable macros as a warning, not a routine step.
  • When one user reports a bad attachment, check every other recipient of the same file.

In more detail

Spearphishing attachment is a targeted social engineering technique in which an adversary sends an email containing a malicious or weaponised file to a specific individual or small group, relying on the recipient to open it and trigger execution. The attachment is usually a document format that supports embedded macros or scripting, an archive that conceals the true file type, a shortcut or container file that resolves to a remote resource, or a disk image that bypasses attachment filtering. Delivery is often preceded by reconnaissance to select a plausible sender identity and a pretext matching the recipient's role, and the message body typically supplies a reason to enable content or to ignore a warning. Artefacts span the mail gateway, the endpoint, and the network. The gateway logs record sender infrastructure, authentication results for the sending domain, attachment names, and hashes, which support correlation across recipients. On the endpoint, the file write event is followed by the spawning of a document reader or archive handler and then by an unexpected child process such as a script interpreter, a shell, or a system utility. Office applications may record the document's origin and protected view behaviour, and the mark-of-the-web alternative data stream indicates the file arrived from an untrusted source. Where the attachment fetches remote content, proxy records show the retrieval. Benign business attachments are constant, so triage is driven by the relationship between the file and what it caused. A document that triggered a script interpreter, a shortcut pointing at a remote host, or an archived executable whose extraction coincides with an outbound connection are high-confidence signals. Investigations that begin from a user report should confirm whether other recipients received the same message hash and whether any of them produced the same child process pattern.

What you will practise

  • Explain how attachment formats such as macro-enabled documents, archives, shortcut files, and disk images each reach an execution point.
  • Identify gateway, endpoint, and file system artefacts that link a delivered message to an observed process on a host.
  • Interpret parent-child process relationships that indicate a document reader or archive handler triggered execution.
  • Correlate attachment hashes across mail logs and endpoint telemetry to determine the true scope of a campaign.
  • Distinguish user-initiated benign macro use from adversarial weaponised documents using trust, origin, and behavioural context.
  • Map attachment tradecraft to ATT&CK and describe the detection coverage gaps left by email filtering alone.
