DET0416 Detection of File Transfer Protocol-Based C2 (FTP, FTPS, SMB, TFTP)

DET0416Detection StrategyVery hardDetection Strategy

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

FTP, FTPS, SMB and TFTP are protocols that computers use to move files. An attacker can also use them to send orders to a compromised computer and to take files out. This detection looks for that kind of file transfer traffic going somewhere it should not. It watches the destination and the pattern of the transfer, not the file contents.

Why should you care?

These protocols are old and widely used, so blocking them is rarely an option. Many networks allow them inside and out for real business reasons. Some of them accept anonymous logins, which means no stolen password is needed. Traffic is often not inspected for content, so hidden commands pass through. Noticing the wrong pairing of computers is what lets you act.

How it works, in plain steps

  1. Network devices record every connection, including the two addresses, the port and how many bytes moved each way.
  2. The rule selects connections that use the ports and services linked to FTP, FTPS, SMB and TFTP.
  3. It checks the two addresses against a list of approved server pairs, such as your backup server and your clients.
  4. It looks at timing, because transfers at three in the morning from an office computer are unusual.
  5. It also reads the protocol metadata, where an anonymous login or a large download stands out.
  6. Where the destination, the timing and the size are all unexpected for that host, the system raises an alert.

Real-world example

Think of a factory with a delivery bay. Vans come and go all day and the gate staff know the regular routes. One night a van arrives and shows no paperwork. It takes a large load to a depot the factory has never used. The van itself is ordinary. The unapproved route at that hour is worth reporting.

Key takeaways

  • File transfer protocols are normal business tools, so the destination and the timing carry the signal.
  • Anonymous or repeated failed logins on these services deserve a look on their own.
  • Baseline which internal hosts talk to which external file servers before enabling the rule.

In more detail

This strategy covers the use of file transfer protocols for command and control, tracked as T1071.002, where an adversary uses FTP, FTPS, SMB or TFTP as the channel for instructions and data because these protocols are common in business networks and are rarely inspected in depth. It matters because the command traffic blends with legitimate file movement, and because several of these protocols support unauthenticated or anonymous use that needs no credentials at all. The telemetry that makes detection possible is network flow and application protocol metadata: firewall or netflow records with destination, port and byte counts, proxy or secure gateway logs for file transfer sessions, Domain Name System query logs for the server names used, and endpoint network connection events from Sysmon. The main way it fails is that file transfer is exactly what a great many business processes do, so the analyst must anchor on unusual pairings of internal host to external server, outside-hours activity, anonymous or failed logon attempts, and payload sizes that do not match normal file sharing.

What you will practise

  • Name the file transfer protocols that are used for command and control and their usual ports.
  • Read network flow records and identify the fields that describe a file transfer session.
  • Build an allow list of approved internal to external file transfer pairings.
  • Recognise anonymous logon and repeated authentication failure patterns in protocol metadata.
  • Correlate a suspicious transfer with the endpoint process that started it.
  • Explain the risk of relying only on port based blocking.
