T1021.003 Remote Services: Distributed Component Object Model

T1021.003Lateral MovementExtremeTechnique

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

Distributed Component Object Model, often shortened to DCOM, is a Windows feature that lets a program on one computer ask a program on another computer to do something. It works with an account that is already valid on both machines. The parent technique covers remote services in general. This sub-technique is the use of this one Windows feature to run actions elsewhere.

Why should you care?

An attacker with one administrator account can use this feature to run code on many machines. The actions look like normal Windows activity, so they are hard to spot. It can start common office programs that then run harmful content for the attacker. Because it uses a real account, blocking it without breaking daily work is difficult.

How it works, in plain steps

  1. The attacker has a working account, usually an administrator, on both machines.
  2. From the first machine they ask the second machine to start a chosen program.
  3. The request travels over a Windows remote call service on the network.
  4. On the second machine the program starts and runs the harmful action for them.
  5. Common programs such as office tools or management consoles are used, so it looks normal.
  6. The attacker repeats this on other machines to spread through the network.

Real-world example

Imagine an office where every department shares a supply cupboard key. A visitor holding one caretaker's key can walk through the building and ask each office to hand over a box. The offices obey because the request looks official. Nobody breaks a door, and every room stays locked the whole time. That is how this remote Windows feature is abused: the machines do the work, and the attacker only asks.

Key takeaways

  • This sub-technique is one specific remote service inside the wider remote services parent.
  • It needs a valid, usually privileged account, so least privilege and account hygiene matter.
  • Correlate remote call traffic with unusual program starts on the destination host.

In more detail

Distributed Component Object Model is the remote extension of the Windows Component Object Model, and this sub-technique covers its use with valid accounts to act on another host. Component Object Model lets a client object call methods on a server object, which is typically a dynamic link library or an executable; the distributed form adds a remote procedure call transport so those calls cross the network. Permissions to activate and launch objects remotely are held in registry access control lists and are granted to administrators by default. An adversary with suitable rights can therefore instruct a remote machine to start a legitimate application that exposes a dangerous method, and that application runs in the target's own process context, which is why the activity blends into normal office, management console or instrumentation use. The network story is remote procedure call traffic to high dynamic ports, preceded by endpoint mapper lookups on a well known port. The host story is a client process on the source and an unexpected process starting on the destination without an interactive logon, so defenders correlate remote call reachability, destination process creation and the identity used for both.
