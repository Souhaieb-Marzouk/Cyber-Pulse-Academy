DET0221 Behavioral Detection Strategy for T1123 Audio Capture Across Windows, Linux, macOS

DET0221Detection StrategyVery hardDetection Strategy

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

This detection looks for a program that turns on the microphone. Many programs do this, such as meeting applications. The rule checks which program opened the microphone and when it did so. It raises an alert when the program is not one that should record sound.

Why should you care?

A microphone can pick up private conversations and meetings. An attacker can record them without touching a camera or a screen. The recording file is small and easy to move elsewhere. Very few teams watch microphone access at all. This detection gives you a first look into that blind spot.

How it works, in plain steps

  1. The operating system or an endpoint agent logs which process opens a microphone device.
  2. The rule builds a list of programs that may use the microphone on each host type.
  3. It keeps microphone opens that come from processes outside that list.
  4. It adds context such as the account, the hour, and whether the host is a meeting room device.
  5. It looks for a new audio file created by the same process soon afterwards.
  6. Two or more signals together raise the alert, while a single open stays at low severity.

Real-world example

Think of a meeting room with a sign out board for the speakerphone. The board shows who borrowed it and when. The speakerphone shows as in use at two in the morning. No meeting was booked, so that entry deserves a question.

Key takeaways

  • Microphone access by an unexpected program is the core signal.
  • Meeting and recording software creates a lot of normal noise.
  • The time of day and a new audio file make an open far more suspicious.

In more detail

This strategy covers T1123, Audio Capture, where an actor records microphone input to collect spoken information from meetings, calls, or a room. Detection rests on host telemetry: a process opening the microphone device that is not part of the approved conferencing or recording set, opened outside the user's normal call pattern, and sometimes paired with a new audio file written to a temporary or user directory. It fails in practice because meeting clients legitimately hold the microphone open for long periods, so the process signature, the host role, and the call context do most of the work.

What you will practise

  • Explain how audio capture can collect sensitive spoken information.
  • Identify telemetry that records which process opened a microphone device.
  • Build an allowlist of legitimate audio applications for each host role.
  • Combine microphone access with file creation and time of day to prioritise alerts.
  • Describe the privacy considerations that apply to monitoring microphone use.
