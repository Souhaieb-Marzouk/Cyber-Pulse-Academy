T1568.001 Dynamic Resolution: Fast Flux DNS

T1568.001Command and ControlExtremeTechnique

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

Dynamic resolution means malware works out its contact address instead of storing one. This version keeps a single domain name but points it at a large set of addresses. Each lookup gives a different address, and each address sits on a different computer. The attacker hides the real control server behind all of those machines.

Why should you care?

Blocking one address of a fast flux domain does not stop the connection, because many other addresses remain ready. Taking the domain down is also hard, since even the name servers move. Malware keeps working while defenders chase a moving target. Recognising the pattern quickly is often the only practical defence you have.

How it works, in plain steps

  1. The attacker builds a pool of computers, often compromised machines, that will pass traffic onward.
  2. They publish many address records for one domain name and give each record a very short lifetime.
  3. Each time a victim machine asks for that name, the name server returns a different address.
  4. The victim connects to that machine, which quietly forwards the traffic to the hidden control server.
  5. In the double flux version the name server list also changes, so even the lookup path moves.
  6. Defenders notice many different addresses for one name and very low record lifetimes.

Real-world example

Imagine a help line whose published number changes every two minutes, and each new number rings a different small office. All of those offices quietly forward your call to one hidden room. If someone blocks a single number, dozens of others still work. Investigators would have to watch the changing pattern rather than one number. Fast flux works in that way.

Key takeaways

  • Short record lifetimes and many answers for one name are the classic fast flux signals.
  • Know the difference between a content delivery network and a shifting pool of unrelated hosts.
  • Look at the pattern across many queries, because a single lookup rarely shows the trick.

In more detail

Fast Flux DNS hides command and control behind a domain that resolves to a large, constantly changing pool of addresses. Two variants exist. In single flux, many address records are published for one name with very short Time To Live (TTL) values, so the answer changes between queries and each query may return a different host. In double flux, the name server records for the zone rotate as well, so even the authoritative servers move and the query path itself becomes unstable. The hosts in the pool are frequently compromised machines or cheap virtual servers that proxy traffic to a hidden backend. Detection depends on DNS telemetry: abnormally low TTL values, an unusually high number of distinct answers for one name over a short window, wide geographic or autonomous system diversity for a single domain, and one client connecting to many addresses of the same name. Distinguishing this from a content delivery network matters, because those also return many addresses, but their answer sets are stable in ownership and reputation while flux pools mix unrelated networks and often appear soon after registration.
