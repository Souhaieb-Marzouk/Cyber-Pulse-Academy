T1674 Input Injection

T1674ExecutionExtremeTechnique

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

This is when an attacker makes a computer believe a person is typing, when a program or device really is. The fake typing can press shortcut keys, open a command window, or paste and run code. It can also change what you see on screen, such as a bank account number during a payment. To the computer, it looks exactly like you did it.

Why should you care?

Most security tools trust actions that come from the keyboard, because they assume a real person is responsible. When input is faked, that trust breaks, and malware can run commands without any file that looks suspicious. A malicious USB stick can act the moment it is plugged in, well before anyone notices. And because the typing can change what appears on screen, a victim may approve a payment with wrong details. Spotting this needs attention to how processes start, not just what files exist.

How it works, in plain steps

  1. The attacker gets a program onto the machine. Or they persuade someone to plug in a small device that pretends to be a keyboard.
  2. The program waits for a trigger, such as a browser opening a specific banking website.
  3. When the trigger happens, the program creates fake key presses that the system treats as genuine typing.
  4. Those keys open a developer console or select the address bar, using standard shortcuts.
  5. The program writes code to the clipboard, pastes it, presses enter, and the code runs on the machine.
  6. A hardware version skips the download and types a short command that fetches malware from a remote server.

Real-world example

Think of a bank counter where the teller trusts any form signed in the customer's own handwriting. An attacker learns to copy that handwriting perfectly. He does not need to fool the teller face to face, because the signature does all the work. The form reaches the counter looking exactly like the customer filled it in. The teller then processes a transfer the customer never asked for.

Key takeaways

  • Fake input is hard to detect because the system sees it as real user action.
  • Watch for command windows that start with no interactive user behind them.
  • Block or control unknown USB devices, because they can type the moment they connect.

In more detail

Input injection covers any mechanism that manufactures keystrokes, mouse movement or other user input on a victim machine so that actions appear to come from the person at the keyboard. Two delivery models dominate. Software tooling hooks the Windows message loop or an equivalent input path and synthesises events on a trigger, such as a browser navigating to a banking page, after which the tool opens a developer console or address bar, pastes clipboard content and runs it, altering what the user sees and submits. Hardware tooling presents itself as a Human Interface Device, typically a USB keyboard, and types a short sequence at machine speed the moment it is plugged in. The common thread is that the operating system and most application logs cannot tell injected input from real input, because the injection happens below the layer that records intent. The distinction from legitimate activity comes from timing and pattern: bursts of keystrokes arriving faster than a human can type, input with no preceding user session activity, clipboard writes immediately before execution, or command interpreters spawned by a process with no interactive session. Useful telemetry includes process creation with the parent being something unexpected, keyboard device arrival events, and browser or application logs showing an anomalous focused window. Because the payload is short and typed rather than downloaded, defenders usually catch it through process ancestry, not through a file artefact.

What you will practise

  • Define input injection and explain why the operating system treats it as genuine input.
  • Describe how a software tool can trigger injected keystrokes from a browser event.
  • Explain how clipboard content and shortcut keys are combined to run code.
  • Describe how a device pretending to be a keyboard delivers commands on connection.
  • Identify process and device telemetry that can reveal injected input.
