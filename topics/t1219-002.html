T1219.002 Remote Access Tools: Remote Desktop Software

T1219.002Command and ControlExtremeTechnique

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

Remote desktop software shows you another computer's screen and lets you use its keyboard and mouse. Support teams use it to help people without visiting their desk. Attackers install the same software so they can watch and control a computer as if they were sitting in front of it.

Why should you care?

This is the branch of remote access that gives a full picture of the screen, so the attacker can use any program, not just a terminal. Many of these tools can be set to reconnect without asking the user for permission each time. They are often allowed by company policy because support needs them, so a new installation may not be blocked. The result is that a single install gives an attacker lasting, comfortable control that looks like a support session.

How it works, in plain steps

  1. The attacker downloads a support tool, often presenting it to the user as a fix for a problem.
  2. The tool installs an agent and usually creates a service so it can start before anyone logs in.
  3. The agent opens an outbound session to the vendor's relay service and waits for a connection.
  4. The operator connects, sees the screen, and controls the keyboard and mouse with the user's rights.
  5. The attacker can store an unattended password so future sessions need no approval from the user.
  6. Network logs show a steady connection to a relay, and endpoint logs show the service that keeps it alive.

Real-world example

Imagine a hotel where a technician from the lift company carries a master key. The key is real, the technician is on the approved list, and the front desk waves them through. Now suppose someone orders an identical key from the same company and copies the uniform. The desk sees a familiar sight and opens the way. The building was never burgled by force; it was opened by trust in a recognised service.

Key takeaways

  • A remote desktop tool gives full interactive control, not just a command prompt.
  • Compare installations against the change record, because support tools are usually allowed.
  • Unattended access passwords mean an intrusion can continue after hours without user action.

In more detail

This sub-technique is the graphical branch of remote access: desktop support and remote monitoring and management software that carries screen output, keyboard input and mouse control between two machines. Well-known examples include VNC, TeamViewer, AnyDesk, ScreenConnect and LogMeIn, along with the remote control modules that ship inside products you would not normally classify as remote access, such as video meeting clients and browser-based remote desktop features. The sub-technique is distinguished from its parent by the interface it delivers: instead of a command shell over a protocol tunnel or a hardware device, the operator receives the full desktop and can therefore operate applications that offer no command-line equivalent. Deployment patterns matter for detection. A legitimate estate deployment is pushed by management tooling, appears on many machines in a short window, runs from a protected installation directory, and is registered with the vendor's management console. Adversarial use is the opposite: one machine, installed by a user context, an agent binary in a user-writable path or a downloaded temporary file, a service created moments later, and an outbound session to a relay at an hour when the user is not working. Because several of these tools support unattended access with a stored password, an operator can return without asking anyone for approval, which is why the session must be judged against the change record as well as against the process list. Telemetry to correlate includes process creation, service installation, file writes to the installation path, and long-lived outbound connections to vendor relay infrastructure.

What you will practise

  • Describe how desktop support software transfers screen, keyboard and mouse between computers.
  • Explain how this sub-technique differs from the general remote access parent technique.
  • Identify the persistence mechanism these tools commonly install on a workstation.
  • Distinguish an approved estate-wide deployment from a single suspicious installation.
  • List the process, service and network logs that reveal an unauthorised support session.
