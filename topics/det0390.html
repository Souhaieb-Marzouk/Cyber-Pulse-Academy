DET0390 Linux Detection Strategy for T1547.013 - XDG Autostart Entries

DET0390Detection StrategyVery hardDetection Strategy

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

On Linux desktops, a small text file can tell the system to start a program when a user signs in. These files live in a folder called autostart. This detection watches for new files in those folders and checks what program they point to.

Why should you care?

An added start entry means the attacker's program returns after every sign in, so removing it once is not enough. Users rarely look inside that folder. Comparing new entries against the programs that a package manager installed shows clearly which entries arrived by themselves.

How it works, in plain steps

  1. The file monitoring agent records every new file in the home directory, including the full path.
  2. The rule keeps files whose path is inside an autostart directory.
  3. It reads the entry to find the program path that the entry will run at sign in.
  4. It checks whether that program belongs to a package that the package manager installed.
  5. An entry that points to a temporary folder or a downloaded script raises an alert for review.

Real-world example

Think of a staff noticeboard where people pin reminders to themselves. Pinning a note is normal. A note that tells the cleaner to open a side door every morning, written in a handwriting nobody recognises, is the one the manager removes and reports.

Key takeaways

  • A file in an autostart folder survives reboots and sign ins, so it deserves attention.
  • The entry itself matters less than the program it points to, so read the target path.
  • Compare new entries with installed packages to find the ones nobody asked for.

In more detail

This detection strategy covers automatic start entries on Linux desktops, where an adversary drops a desktop entry file into a per user or system wide autostart directory so that a program runs again every time the user signs in. The activity is quiet because the format is plain text, the directories are ordinary, and the same mechanism is used by legitimate desktop applications every day. File creation telemetry, execution records for the referenced program, and package manager history provide the evidence, and authentication records show which session wrote the file. The strategy fails in practice because package installation and first run setup create the same files, so a rule that matches the directory alone triggers on normal desktop use rather than on abuse.

What you will practise

  • Locate the per user and system wide autostart directories on a Linux desktop
  • Describe the plain text format of a desktop entry and the field that names the program
  • Build a rule that alerts on new autostart files rather than on the directory listing
  • Correlate a new entry with package manager history to separate installed software from a dropped file
  • Follow the reference from the entry to the program and its download history
  • Explain why a system wide entry is a higher priority finding than a single user entry
