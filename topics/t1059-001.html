T1059.001 Command and Scripting Interpreter: PowerShell

T1059.001ExecutionVery hardTechnique

PowerShell is a task automation and configuration management framework from Microsoft, consisting of a command-line shell and an associated scripting language built on the .NET runtime. It is a first-class execution mechanism on Windows and is also available on Linux and macOS, which makes it attractive to adversaries because it ships with the operating system, is signed by Microsoft, and gives direct access to the .NET framework, WMI, Active Directory, and the registry without dropping a compiled binary to disk. Execution ranges from a simple encoded command passed to powershell.exe, to in-memory assembly loading through reflection, to full script blocks delivered over a remote session. The telemetry footprint is unusually rich compared with most interpreters. Process creation records the full command line, which frequently exposes switches such as -enc, -nop, -w hidden, or -exec bypass. Script Block Logging writes the de-obfuscated script text to the event log, and Module Logging captures cmdlet invocations even when the script itself is heavily encoded. PowerShell transcription can record console input and output to files, and the Antimalware Scan Interface reports suspicious script content to the registered antivirus engine. Network-enabled cmdlets produce connections associated with the responsible process, and constrained language mode changes appear in the runtime's own logging. Benign administrative use is pervasive in most enterprises, so volume alone proves nothing. Investigations distinguish malicious from routine activity by correlating parent process and user context, looking for scripting that originates from Office applications, web browsers, or service accounts that should never run interactive shells, and by comparing the target hosts against software deployment and configuration management baselines. Scripts arriving from temporary directories, download URLs appearing inside command lines, and execution outside change-management windows are stronger signals than the presence of PowerShell itself.

What you will practise

  • Explain how the PowerShell host resolves execution policy, what that policy actually constrains, and why it is not a security boundary in production.
  • Identify the specific process creation fields and log sources that expose encoded, obfuscated, or in-memory script execution.
  • Interpret Script Block Logging and Module Logging output and reconstruct a script's behaviour from the de-obfuscated text.
  • Correlate suspicious PowerShell process ancestry, such as Office or browser parents, with subsequent network and file activity.
  • Distinguish delegated administrative automation from adversary tradecraft using user context, host baseline, and change windows.
  • Map observed PowerShell behaviour to the relevant ATT&CK technique and describe the residual detection gaps in the environment.
