ARP

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

ARP stands for Address Resolution Protocol. It links an IP address to a physical network card address. An IP address is the logical address of a device. The physical address, called the MAC address, belongs to the network card itself. ARP finds the second address from the first one.

Why should you care?

A local network delivers traffic using physical addresses. If an attacker answers with the wrong physical address, traffic goes to the attacker first. This trick is called ARP spoofing. The attacker can then read or change traffic inside the same network. The protocol has no built in way to check those answers.

How it works, in plain steps

  1. Your computer wants to reach another device on the same local network.
  2. It knows the IP address but not the physical address of the card.
  3. It sends a broadcast question to the whole network asking who holds that IP address.
  4. The owner replies with its MAC address, and the answer is stored.
  5. That stored answer is reused for a short time, so later traffic goes directly.
  6. Because nobody checks the reply, any device on the network can send a false one.

Real-world example

Think of a shared office mailroom with open pigeonholes. You drop a letter showing the room number. A helpful colleague tells you which pigeonhole belongs to that room. If a prankster gives you the wrong pigeonhole, your letters go to him instead. He can read them, copy them or quietly pass them on.

Key takeaways

  • ARP has no authentication, so a local device can lie about its address.
  • Switch features such as dynamic ARP inspection and port security reduce that risk.
  • Keep untrusted devices off sensitive network segments wherever you can.

In more detail

The Address Resolution Protocol, ARP, maps a known IPv4 address to a hardware address on the same local network segment. When a host needs to send a frame to an address such as 10[.]0[.]0[.]5 and has no cached entry, it broadcasts a request asking who holds that address, and the owner replies with its MAC address, which is then cached for a short period. The design has no authentication of replies, so any device on the segment can send an unsolicited response claiming an address it does not own. That is the basis of ARP spoofing, and of on path interception, session hijacking and denial of service inside a broadcast domain, all of which stay invisible to tools that only inspect routed traffic. Practical defences are dynamic ARP inspection on managed switches, port security and DHCP snooping, static entries for critical gateways, network segmentation that keeps untrusted devices away from sensitive segments, and monitoring for duplicate or frequently changing address bindings. The mistake is assuming that because a switched network is not hub based, neighbours cannot see or influence each other's traffic.

What you will practise

  • Explain what problem ARP solves and why local networks need it.
  • Describe the request and reply exchange and how ARP caching works.
  • Explain how ARP spoofing enables interception inside one broadcast domain.
  • List the switch and network controls that reduce spoofing risk.
  • Describe the signs in ARP or switch logs that suggest address spoofing.
