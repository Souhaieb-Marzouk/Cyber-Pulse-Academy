T1213.005 Data from Information Repositories: Messaging Applications

T1213.005CollectionExtremeTechnique

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

Messaging applications are chat tools such as Microsoft Teams, Slack and Google Chat. This sub-technique means an attacker reads those chats to find useful information. It is the parent idea, aimed at conversations instead of documents. The attacker usually uses a normal account or a stolen token.

Why should you care?

People write quickly in chat and share things they would never put in a formal document. Passwords, server names and private plans often appear there. Security teams also talk about live incidents in chat, which tells an attacker what to avoid. That information helps them stay hidden and choose better targets. Chat history is easy to search, so one account can read years of talk.

How it works, in plain steps

  1. The parent technique covers shared repositories in general; this one targets chat and messaging tools.
  2. The attacker gains a user account, or steals a session token for the chat tool.
  3. They search old messages for words such as password, key or server name.
  4. They read channels they never belonged to, especially security and incident channels.
  5. They export conversation history, or copy the files that people shared in chat.
  6. They may add their own application to the workspace so they can keep reading later.

Real-world example

Imagine a hospital staff room with a whiteboard used for shift notes. Nurses write reminders, door codes and comments about difficult cases. A visitor waiting in the corridor steps in when the room is empty and photographs the whole board. Nothing was locked and nothing was broken, but the visitor now knows tonight's door codes and who is on duty.

Key takeaways

  • Chat holds informal detail, including secrets that people never meant to keep.
  • Incident response talk in chat tells an attacker how to stay out of sight.
  • Watch for newly installed applications and tokens, and for very wide message searches.

In more detail

Messaging applications are where much day to day business conversation happens, so this sub-technique is the parent behaviour applied to chat platforms such as Microsoft Teams, Slack and Google Chat. The material of interest is informal and often more revealing than formal documentation: credentials and connection strings pasted into channels, source code snippets, links to internal shares, product plans, and discussions about an incident that is still being handled. That last category makes chat valuable for defence evasion as well as collection, because an intruder who reads the security team's channel learns which hosts are under investigation and how. Access usually looks like ordinary client use, whether through a desktop application, a web session or an interface token, and search plus history endpoints allow broad retrospective reading. Detection uses platform audit logs and identity signals: new tokens or installed applications, wide message searches, exported channel history, direct messages far outside the account's normal contacts, and unusual client addresses. The distinguishing feature is breadth over time.

What you will practise

  • Explain how messaging applications differ from document repositories as a data source.
  • Describe the kinds of information an adversary looks for in chat history.
  • Explain why incident response discussions are valuable to an intruder.
  • Identify audit events such as message exports and new application installations.
  • Suggest ways to reduce the amount of secret material shared in chat channels.
