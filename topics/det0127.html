DET0127 Behavioral Detection of Masquerading Across Platforms via Metadata and Execution Discrepancy

DET0127Detection StrategyVery hardDetection Strategy

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

Masquerading means an attacker gives a file or a program a trusted name. The file may be called svchost.exe, or it may sit in a system folder. This detection compares what a file claims to be with what it really does. It catches programs that hide behind a familiar name.

Why should you care?

When a program wears a trusted name, people stop looking at it. Analysts and tools may skip it because it looks like part of the system. That gives an attacker more time to work inside your network. A name is easy to fake, so you need other evidence. This detection helps you trust behaviour instead of names.

How it works, in plain steps

  1. Your endpoint agent records every new process with its full path and its command line.
  2. The same record shows the parent process, which is the program that started it.
  3. A file event adds details such as the original file name and the digital signature.
  4. A digital signature is a cryptographic mark that shows who published the file.
  5. The rule compares these facts and flags the cases where name and evidence disagree.
  6. An analyst then checks the file hash, the signer, and the network connections before closing the alert.

Real-world example

Think of a night watchman at an office building. He knows the cleaners by their uniforms. So he lets them pass without a second look. One night a stranger buys the same uniform online. The uniform says cleaner, but the stranger has no key card. He has no work order and no name on the staff list. A good watchman checks those other things. This detection works in the same way. It does not trust the uniform, which is the file name. It checks the key card and the staff list. Those are the file path, the signature, and the parent process.

Key takeaways

  • A trusted file name is not proof that a program is trustworthy.
  • Compare the name with the path, the signer, and the parent process.
  • Renamed admin tools are common, so treat every alert as a question, not a verdict.

In more detail

Masquerading (T1036) covers adversaries naming, renaming, or relocating files and processes so they look like trusted software. This detection strategy does not hunt for one specific tool; it hunts for disagreement between what an artifact claims to be and what the operating system and the network observed it doing. Useful telemetry includes process creation with full image paths and command lines, file creation events carrying the original file name and digital signature status, loaded module records, and network connections attributed to the process. Correlation is the hard part, because a signed binary running from a temporary directory is weak evidence on its own, while an unsigned binary named after a system utility and started by a document reader is strong. The strategy fails most often because signature and version metadata are not collected at scale, because administrators rename utilities for legitimate reasons, and because very short lived processes are missed when process auditing is off.

What you will practise

  • Explain how masquerading abuses trusted file and process names to avoid review.
  • List the metadata fields that let you test whether a name matches an artifact.
  • Correlate process creation, file creation, and network telemetry into one evidence chain.
  • Separate benign renamed administration utilities from deliberate impersonation of system binaries.
  • Describe how to baseline signed software so that signature gaps stand out quickly.
