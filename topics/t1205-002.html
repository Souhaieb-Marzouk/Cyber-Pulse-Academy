T1205.002 Traffic Signaling: Socket Filters

T1205.002PersistenceExtremeTechnique

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

A socket filter is a rule attached to a network connection. It tells the computer to look at every incoming packet and react when one matches the rule. Attackers use it to keep a backdoor asleep until they send a secret signal. The backdoor then wakes up and starts working.

Why should you care?

If a backdoor sleeps until it hears a special packet, it makes almost no noise. You will not see a listening port or regular traffic to a strange server. Normal monitoring tools often miss it for months. This lets an attacker keep access to your network long after the first break-in. Knowing how it works helps you look for the small clues it leaves behind.

How it works, in plain steps

  1. The attacker already has high rights on a computer and wants a quiet way back in later.
  2. They attach a filter to a network socket using a packet capture library called libpcap.
  3. The filter describes a secret pattern, such as a certain port or a strange set of bytes.
  4. The operating system checks every incoming packet against that pattern inside the kernel.
  5. When a packet matches, the filter triggers an action, often starting a command shell.
  6. Until that packet arrives the host sends nothing, so the backdoor looks completely idle.

Real-world example

Think of a quiet hotel night desk. The clerk does not walk the corridors all night. Instead, a small sensor listens at the front door. The sensor ignores footsteps, cars and rain. It reacts only to one exact knock, three short taps and a pause. When that knock comes, the clerk wakes up and unlocks the staff door. Until then the hotel looks closed and silent, and nothing on the street suggests anyone is waiting inside.

Key takeaways

  • A sleeping backdoor can still be dangerous, because it waits for a signal instead of listening on a port.
  • Look for packet capture libraries loaded by unusual processes, not only for strange network traffic.
  • A sudden shell or outbound connection right after a packet arrives is a strong warning sign.

In more detail

Socket filters let an implant stay passive until one specific packet arrives, so the host opens no listening port and sends no traffic while it waits. With elevated rights an adversary attaches a filter to a network socket, using the libpcap library or the SO_ATTACH_FILTER socket option, and the operating system evaluates every incoming frame against that rule set in kernel space. A match then triggers a host action, such as starting a reverse shell or pulling down an implant. Detection is hard because there is almost no activity to see, so defenders look instead at raw socket creation, packet capture libraries loaded by unexpected processes, driver loads, and the child processes that appear immediately after a matching packet. Legitimate capture tools use the same libraries, so the useful differentiators are the parent process, the file path, and whether activation is followed straight away by a shell or an outbound connection.

What you will practise

  • Explain what a socket filter does and why it keeps a backdoor quiet on a host.
  • Describe how libpcap and the SO_ATTACH_FILTER socket option are used to attach a filter.
  • Identify the host artefacts that reveal a passive backdoor which sends no traffic.
  • Distinguish legitimate packet capture tools from a filter used for command and control.
  • Outline how a defender responds when a silent host suddenly starts a shell.
