DET0545 Detection Strategy for Cloud Administration Command

DET0545Detection StrategyVery hardDetection Strategy

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

This detection watches the cloud tools that run commands on servers for you. A cloud provider offers a service that sends a command to a machine through its agent. Amazon Web Services and Microsoft Azure both offer this. The detection looks for commands run by the wrong person or on the wrong machine.

Why should you care?

These commands need no open port and no password on the server. An attacker with cloud keys can use the same path as your own team. The cloud audit record shows the command. It is often the only place where the command appears. On the machine itself, the endpoint may name only the agent as the parent process.

How it works, in plain steps

  1. The cloud provider writes an audit record each time a command or document is sent to an instance.
  2. The record lists the identity that sent it, the target instances and the command parameters.
  3. The agent on the instance records the command it received and when it started.
  4. The endpoint records the process that the agent started, including its parent and command line.
  5. The platform compares the identity and the target tags with the normal administration pattern.
  6. Commands from unexpected identities or to sensitive instances become alerts.

Real-world example

Think of a building management system that lets a manager unlock any office door from a laptop. The door log shows the manager name and the time. If a cleaner account unlocks the finance office at midnight, the log answers the question before anyone walks the floor.

Key takeaways

  • Cloud administration channels bypass network controls, so identity is the main control.
  • The provider audit log is often the only complete record of what ran.
  • Sensitive instances and unusual sending identities deserve the highest attention.

In more detail

This detection strategy covers the use of cloud provider administration services to run commands on managed instances without any inbound network access, matching technique T1651. It matters because the same agent channel that performs patching and inventory can execute arbitrary commands as the local system account, and the resulting activity appears in provider audit logs while barely touching the endpoint. The telemetry that makes it possible is cloud audit records for command or patch operations, instance management agent logs on the target, and endpoint process creation records showing commands spawned by the agent service. It fails in practice because operations teams use these services constantly for legitimate administration, so the detection must profile who normally runs commands, against which instance tags, and at what times.

What you will practise

  • Explain how cloud administration services execute commands on instances without inbound access
  • Identify the cloud audit records and endpoint records that capture a remote administration command
  • Correlate the sending identity with the target instance tags and the normal administration pattern
  • Explain why command line content in the audit record is valuable evidence during triage
  • Write a detection rule for remote administration commands and scope it to sensitive assets
