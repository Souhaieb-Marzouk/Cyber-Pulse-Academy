Data Poisoning

AI SecurityHardKeyword

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

Data poisoning means an attacker spoils the data used to teach a machine learning model. The model then learns the wrong lesson and behaves badly later. The attack happens before or during training, not when the model is answering questions.

Why should you care?

A model is only as good as the examples it learns from. If some examples are wrong on purpose, the model can fail in ways that are hard to see. A poisoned model may work well in testing and fail on real work. It can also hide a special trigger that only the attacker knows. Because the damage sits inside the model, fixing it can mean retraining everything.

How it works, in plain steps

  1. A team collects examples and labels to teach a model a task.
  2. An attacker adds or changes some examples so that the labels are wrong.
  3. The model learns from the whole set, including the bad examples it was given.
  4. The finished model now makes mistakes on the inputs the attacker chose.
  5. Defenders check where the data came from and look for strange examples.
  6. They also watch the model's answers after release, and retrain without the bad data.

Real-world example

Imagine a new chef who learns to cook from a single recipe book. The book is the only guide, so the chef trusts every page. Someone sneaks in and changes a few pages, so one sauce is now far too salty. The chef practises the whole book many times and learns the salty version by heart. On opening night the dish is wrong, and the chef cannot tell why, because the book still looks normal. Only a careful check of each page shows the change. That is data poisoning: bad teaching material produces a confident but wrong result.

Key takeaways

  • Record where training data came from and who was allowed to change it.
  • Test the model on data that never entered training.
  • A model can pass its tests and still be poisoned.

In more detail

Data poisoning is the deliberate corruption of the data used to train or fine-tune a machine learning model, so the finished model behaves badly on inputs the attacker chooses. The attacker may add mislabelled examples, flip existing labels, or inject a backdoor trigger that stays dormant until a rare pattern appears. A supply chain variant tampers with a public dataset or with pre-trained weights that a build pipeline fetches automatically. Because models rarely ship with a full data lineage record, the damage is hard to trace and survives retraining while the poisoned samples remain in the corpus. Detection leans on provenance records, statistical outlier checks, label audits, holdout sets that never enter training, and output monitoring for behaviour that shifts after a data change. The common mistake is treating model security as only an input filtering problem at inference time, leaving the training pipeline open.

What you will practise

  • Explain what data poisoning is and why it targets the training stage.
  • Describe how mislabelled examples and hidden triggers change model behaviour.
  • Identify the supply chain paths through which training data can be tampered with.
  • List the controls that improve training data provenance and integrity.
  • Explain why output monitoring after release is part of the defence.
