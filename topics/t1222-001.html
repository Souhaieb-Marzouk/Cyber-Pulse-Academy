T1222.001 File and Directory Permissions Modification: Windows Permissions

T1222.001Defense ImpairmentExtremeTechnique

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

On Windows every file and folder has a list that says who may use it and how. This list is called a discretionary access control list. Attackers use built-in Windows commands to edit that list, so they can open a file that was closed to them or lock other people out of it.

Why should you care?

The commands used here are part of Windows, so they are present on every machine and are not suspicious by themselves. Administrators also use them for real work, which makes intention hard to judge from the command alone. An attacker can grant themselves access to a file they were denied, or remove the entry that lets a security tool read a file it needs to protect. This is the Windows version of the wider permission technique, and the difference is mostly in the tools it uses.

How it works, in plain steps

  1. The attacker identifies a file or folder that their account cannot currently read, change or run.
  2. They view the existing entries on the object to see which accounts hold which rights.
  3. If the object belongs to someone else, they may take ownership before any edit is accepted.
  4. They add an entry granting their account access, or delete an entry that protected the object.
  5. They may also change file attributes, such as clearing the hidden or read-only setting.
  6. The new rules take effect immediately, so the target file can now be replaced, read or deleted.

Real-world example

Think of a hotel front desk that keeps a list of which staff may enter each room. The list lives in a folder at reception and anyone on duty may edit it. A person adds their own name to the list for the manager's office and quietly removes the cleaner's name for the same door. Every key card is checked against the list as usual. The locks worked perfectly; the list simply said something new.

Key takeaways

  • Windows permission commands are normal tools that can be used for harm.
  • Object access auditing is off by default, so enable it if you want to see these changes.
  • Look at what was modified right after a permission change, because that is the real goal.

In more detail

On Windows, securable objects carry a discretionary access control list, an ordered set of entries that name a user or group and the actions they may or may not perform, and the system evaluates those entries in order on every access attempt. This sub-technique is the Windows-specific branch of permission modification, and its distinguishing feature is the toolset rather than the goal: the built-in commands that read and rewrite those lists and attributes, and the scripting cmdlets that return or set the same structures programmatically. The practical effect an adversary wants is either an added entry that grants their account access to a protected file, or the removal of a protective entry so that a security product or administrator can no longer read or replace it, or the clearing of restrictive attributes so a hidden file becomes usable. The change is often paired with taking ownership, because editing the list on an object you do not own is not permitted. Detection relies on success auditing for object access, which is off by default, joined to process creation telemetry that records the utility and its recursive, quiet or broadly targeted arguments. The context that separates abuse from administration is the target itself, such as a directory that holds a security agent's files or a system binary, together with the account performing the change and whether a change record exists. Because the affected technique is frequently a precursor to replacing files that load automatically at startup, alerts should be triaged with the following minutes of file write activity in mind.
