T1048.002 Exfiltration Over Alternative Protocol: Exfiltration Over Asymmetric Encrypted Non-C2 Protocol

T1048.002ExfiltrationExtremeTechnique

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

This is data theft where the stolen files are locked with a public key before they are sent. A public key can lock data but cannot unlock it. Only the attacker holds the matching private key that opens the files again.

Why should you care?

Even if you find the malicious program, the key inside it cannot unlock the stolen data. That means the attacker does not need to keep a readable secret on your machine. The same public key can be used against many victims at once. As with the other variants, only traffic patterns can warn you.

How it works, in plain steps

  1. The attacker creates a matching pair of keys, one public and one private.
  2. The public key is placed inside the malicious program, and the private key stays with the attacker.
  3. Files are staged, then compressed and encrypted on the victim machine with the public key.
  4. The locked data is sent over a protocol that is not the main control channel.
  5. Encryption can be added on top of a protocol that is already protected, such as web traffic.
  6. The attacker unlocks the data later using the private key, which never left their control.

Real-world example

Picture a donation box with a one-way slot, bolted to a wall in a public hall. Anyone may drop a note inside, but only the person with the key can open the box and read it. If you catch the person dropping the note, you still cannot reach what is already inside.

Key takeaways

  • Asymmetric means two keys: one to lock, one to unlock, and only the public one is on the victim.
  • Capturing the traffic does not help, because the private key stays with the attacker.
  • Detection depends on transfer size, timing, destination and the context around the activity.

In more detail

This sub-technique is the public-key branch of exfiltration over an alternative protocol. The parent technique describes moving data over a protocol other than the command and control channel; here the adversary encrypts the payload with asymmetric cryptography, also called public-key cryptography, where the key that locks the data differs from the key that unlocks it. The victim side holds only the public key, so compromise of that host does not expose the private key held by the operator, and the encrypted material can be transmitted over any available protocol including plain ones such as unencrypted web or file transfer. The practical difference from the symmetric variant is the direction of trust: the adversary never needs to place a decryptable secret on the target, which makes recovery of the key material from an infected host unlikely and lets the operator reuse one key pair across many victims. Detection is confined to traffic behaviour, because the payload cannot be decrypted even if captured. Defenders look for outbound transfers with high entropy and steady size patterns, protocol traffic whose content does not match expected structure, sessions to destinations that no comparable host contacts, and the correlation between such transfers and earlier suspicious activity on the same machine.

What you will practise

  • Explain how this sub-technique differs from its parent, which concerns the channel rather than how the data is protected.
  • Define asymmetric encryption and describe the roles of the public and private keys.
  • Explain why an adversary prefers a public key when the target host may be examined.
  • Describe how public-key encrypted payloads are transferred over an alternative protocol.
  • Identify the traffic-based indicators that remain available when content cannot be decrypted.
