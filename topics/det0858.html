DET0858 Detection of Scan Databases

DET0858Detection StrategyVery hardDetection Strategy

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

A scan database is a public collection of internet scan results. It shows which addresses answer on which ports. Anyone can search it, sometimes for free. An attacker uses it to learn about your exposed systems without sending you any traffic. This detection looks for the traces that remain.

Why should you care?

Research that never touches your network is very hard to detect. That is the main problem with these datasets. An attacker can learn your software versions and certificate names in silence. Your network sensors record nothing, so your monitoring looks calm. What you can control is your own exposure. If you know what the scan databases show, you can close the service before somebody uses the listing. Deception addresses help, because a service that nobody should find will still be probed.

How it works, in plain steps

  1. You place a deception service on a public address that no real system uses.
  2. Internet scanning engines and curious attackers connect to that address, and the service records the attempt.
  3. Your firewall logs also record denied connections from known scanning address ranges.
  4. The detection enriches each attempt with ownership data and with your exposure inventory.
  5. An attempt against an address that should be silent is a strong indicator of a scan database listing.
  6. The rule alerts with the address, the port and the first time that address was contacted.

Real-world example

Imagine a street of houses where one house is empty and dark. The owner wants to know who is looking at it. So he installs a movement sensor behind the front window. Every person who peers in and tries the handle is written into a small log. The neighbours receive deliveries all day, so their doorbells ring constantly and mean nothing. The empty house is different, because nobody has a reason to test its door. Your deception address is that empty house. The sensor log tells you when somebody has been reading a list of targets.

Key takeaways

  • Public scan databases let an attacker study you without touching your network.
  • Unused public addresses are valuable because no honest visitor should find them.
  • Watching your own exposure is as important as watching inbound traffic.

In more detail

This detection strategy covers adversary use of public internet scan databases, which continuously map exposed services and publish the results. An attacker queries those datasets to find your internet facing hosts, open ports, software versions and certificates without touching your network at all. The telemetry that makes it visible is honeypot or deception service logging on unused public addresses, firewall deny logs from known scanning ranges, passive domain name system and certificate records, and your own external attack surface inventory. It fails in practice because the query happens on somebody else's platform, so most organisations see only the later active scan or exploitation step.

What you will practise

  • Explain what a public internet scan database contains and who uses it.
  • Describe why deception addresses reveal scan database listings.
  • Correlate firewall deny events with address ownership information.
  • Summarise your own exposure using external inventory snapshots.
  • Prioritise closing services that appear in public scan results.
