DET0161 Password Policy Discovery – cross-platform behavior-chain analytics

DET0161Detection StrategyVery hardDetection Strategy

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

This detection watches for somebody asking how your password rules work. The attacker wants to know the minimum length, lockout limit and expiry age. Those numbers decide how easy the next password attack will be.

Why should you care?

Password policy is a map of the defences. A short minimum length and a high lockout limit mean weak passwords can be guessed quickly. Knowing the exact threshold also tells an attacker how many attempts fit before an account locks. This step comes early, so catching it gives you time to react.

How it works, in plain steps

  1. An operator runs a command or tool that reads the password policy from the directory.
  2. The operating system records the process and the full command line that was used.
  3. On Linux, the audit log records the program and the configuration files it opened.
  4. The detection keeps policy read commands and then looks at the same session or host.
  5. If that session follows up with account enumeration or a burst of logon attempts, it alerts.
  6. Analysts then check whether a change ticket covers the activity.

Real-world example

Imagine a burglar who first reads the building notice board. It states the alarm code length, how many tries before the alarm sounds, and when the guard changes shift. The burglar has not broken in yet, but the plan is now clear.

Key takeaways

  • Policy discovery alone is weak evidence, so chain it with the next action in the same session.
  • Cover Windows command lines, Linux audit records and cloud policy read events together.
  • Baseline the identity and audit tools that legitimately read policy every day.

In more detail

This strategy detects password policy discovery, the reconnaissance step where an attacker learns the minimum length, lockout threshold, complexity rules and rotation age that govern accounts in the environment. The covered technique matters because those numbers tell the attacker whether a fast offline crack is worthwhile and how many password guesses can be made before an account locks, which decides the shape of the next phase. Cross platform telemetry makes it possible because the discovery appears as process execution and command lines on Windows and Linux and as a directory service or cloud policy read on managed platforms. The main failure mode is that auditing tools, identity governance products and administrators query the same policy routinely, so the rule must chain the query with what the same session does next instead of alerting on the query alone.

What you will practise

  • List the policy values an attacker wants and explain what each one enables.
  • Recognise password policy read commands on Windows and Linux and the cloud equivalent.
  • Build a behaviour chain rule that links policy discovery to later enumeration or logon attempts.
  • Separate routine governance and audit activity from untrusted discovery using actor baselines.
  • Map the discovery step to the account and asset it points at so triage can be prioritised.
