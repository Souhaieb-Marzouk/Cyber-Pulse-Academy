T1098 Account Manipulation

T1098PersistenceExtremeTechnique

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

Account manipulation means an attacker changes an existing account so they can keep using it. They might set a new password, move the account into a powerful group, or give it extra rights. The account itself is the tool, and the attacker shapes it to suit their needs.

Why should you care?

A changed account looks legitimate because it is real. If an attacker gives themselves administrator rights, they can come back whenever they like. Simple password resets and lockouts then fail to remove them, because the account is not stolen, it is modified. Catching these changes early is often the last easy chance to stop the intrusion.

How it works, in plain steps

  1. The attacker already has some access, either to a user account or to an administrator console.
  2. They add their own credential, such as a password, key or certificate, to the account.
  3. They move the account into a group or assign it a role that carries more rights.
  4. They may reset the password again and again to defeat an expiry policy.
  5. Sometimes they change permissions on mailboxes, files or cloud resources to keep a copy of access.
  6. Each change is recorded by the system, so the audit trail names the actor and the target.

Real-world example

Imagine a shared flat where each tenant has a key. A stranger copies a key and then asks the landlord to add their name to the list of tenants. Nothing looks broken, no lock is forced, and the door still opens normally. The stranger now has the same rights as everyone else, and simply changing the locks will not remove their name from the list.

Key takeaways

  • Look for changes to accounts, not only for failed logins or strange processes.
  • Know which accounts should never gain new credentials, groups or roles.
  • Treat repeated password resets and profile changes as possible persistence.

In more detail

Account manipulation covers any change an adversary makes to an account so that access survives, grows or becomes harder to remove. It includes setting a new password or adding credentials, changing group memberships and delegated rights, altering role or permission assignments in a directory or cloud tenant, and editing account properties that weaken policy. Attackers also abuse lifecycle rules directly, for example by repeatedly resetting a password so the account never ages out of a maximum password age policy, or by extending an expiry date. The work requires existing privilege on the system or the directory, but the changes themselves often produce privilege escalation when the modified account inherits more access than its owner had. Detection rests on comparing the change against the identity's history: a password reset for an account that never uses self-service, a group or role change made outside a change window, a change made by an unusual actor or from an unusual address, and a burst of profile updates that no business process explains.

What you will practise

  • Explain what account manipulation is and how it supports persistence and privilege escalation.
  • Describe several behaviours covered by this technique, including credential changes and permission changes.
  • Identify the audit events that record who changed an account and what changed.
  • Distinguish malicious account changes from legitimate administration and self-service activity.
  • Describe how repeated credential changes can defeat password policy controls.
