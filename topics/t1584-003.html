T1584.003 Compromise Infrastructure: Virtual Private Server

T1584.003Resource DevelopmentExtremeTechnique

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

A virtual private server, shortened to VPS, is a rented computer in a cloud data centre. This sub-technique is about an attacker breaking into a rented machine that belongs to another customer. The parent technique covers compromising other people's infrastructure. Here the asset is someone else's cloud server.

Why should you care?

Both the cloud provider and the real customer are trusted, so the attacker borrows two reputations at once. They pay nothing and leave no purchase record. Investigators who trace the address reach an innocent company, and that company may lose time, money, and credibility while proving its innocence.

How it works, in plain steps

  1. The attacker finds a rented server with weak passwords, exposed services, or missing patches.
  2. They log in and create their own account or key so access survives later password changes.
  3. They install remote control tools and connect the machine to their wider infrastructure.
  4. The machine is used to send attack traffic, host content, or relay commands.
  5. The real owner often notices only when a provider warning or a blocklist entry arrives.
  6. The attacker abandons the machine when it is discovered and moves to another victim's server.

Real-world example

Someone borrows a neighbour's car without asking, drives it during a robbery, and returns it with a full tank. Witnesses describe the neighbour's car, and the police visit the neighbour. The car was never stolen, only used, which makes the trail very confusing.

Key takeaways

  • When your address appears in an incident, check whether your own server was taken over.
  • Known-good reputation can be borrowed, so it can never be the only trust signal.
  • Alerting on new accounts, keys, and unusual egress catches this quickly.

In more detail

This sub-technique covers seizing a virtual private server, meaning a rented machine or container at a cloud provider, that belongs to somebody else and using it as operational infrastructure. The parent technique covers compromising third-party assets in general; here the asset is a hosted virtual machine. The operator gains not only a machine but also the provider's reputation and the legitimate customer's history, so outbound traffic originates from a host that may already appear in allowlists and prior good standing. Incidents frequently surface first as a victim-side report, because the account holder sees unexpected outbound traffic, unfamiliar logins, or a provider abuse notice. Investigators distinguish it from ordinary cloud use by examining authentication records for the instance, recently created or changed accounts and keys, processes and network connections that do not match the server's documented role, and sudden shifts in the volume or destinations of egress traffic that continue after the owner denies making changes.

What you will practise

  • Explain how this sub-technique differs from the parent Compromise Infrastructure technique.
  • Describe how a seized cloud instance inherits provider and customer trust.
  • Identify the authentication and egress evidence left on a compromised instance.
  • Distinguish attacker persistence on a server from normal administrator access.
  • Describe the response steps an innocent account holder should be ready to take.
