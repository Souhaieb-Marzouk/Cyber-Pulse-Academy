T1030 Data Transfer Size Limits

T1030ExfiltrationExtremeTechnique

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

Data transfer size limits means sending stolen data in small pieces instead of one large file. Each piece stays under the size that monitoring tools usually watch for. This technique belongs to the exfiltration tactic, which covers stealing data from a victim network. The attacker still sends everything, just in many small amounts. Detection therefore has to count the total, not only the size of each piece.

Why should you care?

Many alert rules fire only when a transfer is large, so small transfers pass by unnoticed. The stolen data still leaves your network, only more slowly. Small regular uploads can also look like normal cloud sync or software updates. This makes the activity hard to spot on a single day of logs. Over weeks, the total can be far larger than anything the team expected.

How it works, in plain steps

  1. The attacker picks a piece size that sits below the alert threshold.
  2. They split a stolen file into many small parts, each sent separately.
  3. The parts travel through ordinary channels, such as web requests or cloud storage.
  4. Small delays are added between the parts so the traffic looks less like a bulk copy.
  5. The attacker reassembles the file on their own system once all parts arrive.
  6. Each individual request looks normal, but the count and total give the pattern away.

Real-world example

Think of an airport queue where the rule is that no single bag may weigh more than ten kilograms. A traveller with thirty kilograms does not try one heavy bag. Instead they bring three light bags over three days, each one under the limit. Every bag passes inspection and nothing looks wrong. Only when staff count the trips does the real total appear. The rule was followed exactly, so it never triggered.

Key takeaways

  • Look at the total sent over days, because small transfers can add up to a large theft.
  • Watch for one destination receiving many similar uploads from the same host or account.
  • Set alerts on upload volume and connection counts, not only on single transfer size.

In more detail

Data transfer size limits split exfiltration into fixed size chunks or cap packet sizes so that no single transfer crosses the thresholds defenders use to flag large outbound movements. The adversary's motive is economical rather than technical: many monitoring rules and data loss prevention policies are built around volume, so keeping each request small means the individual event looks like ordinary browsing or update traffic while the total over days may exceed everything the organisation sent out legitimately. Implementations vary. Files may be cut into parts and sent sequentially or interleaved, a remote access session may negotiate small chunks and pace them with delays, a protocol may be constrained to payloads below an inspection boundary so that reassembly never happens on the sensor, and cloud storage or web services may be abused as many small uploads that only together form one document. The tell is accumulation and repetition, not size. Usable signals include one destination receiving a steady series of similar-sized requests from the same host or user, a rising outbound share of traffic from a server that should mostly receive, uploads by a process that never uploaded before, and a count of connections that is far higher than the byte total would suggest. Baselining normal outbound volume per host makes the aggregate stand out even when each part does not.

What you will practise

  • Explain how splitting data into small chunks avoids volume based detection thresholds.
  • Describe how fixed size chunks and packet size limits differ from a single large transfer.
  • Identify the network artefacts, such as repeated similar uploads to one destination, that reveal chunked exfiltration.
  • Explain how to use per host baselines and long term totals when individual events look harmless.
  • Describe how chunking combines with other exfiltration techniques such as transfer over a command channel.
