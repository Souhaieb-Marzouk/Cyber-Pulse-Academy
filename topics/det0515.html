DET0515 Detection Strategy for T1528 - Steal Application Access Token

DET0515Detection StrategyVery hardDetection Strategy

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

This rule looks for the theft of a digital pass that lets one application act for you. That pass is called an access token. You can think of it as a key card for a service rather than a key to your account. With a copy, an attacker can read your mail or files without logging in. The rule watches where a token is used and which address it comes from.

Why should you care?

Tokens are stored in memory, in browser storage and in small files on developer machines. They are easy to copy and easy to reuse. Use of a token often produces no failed sign in. So it does not look like an attack in the usual login reports. Revoking the token is the only reliable response, and that requires knowing which token was taken.

How it works, in plain steps

  1. The identity provider records every time it issues or refreshes a token, with the client and the address.
  2. The rule builds a picture of which applications normally use which addresses for each user.
  3. A token used from an address that is new for that application is flagged for review.
  4. Any use of a token by a client that never requested one before is treated as more serious.
  5. The rule places the token use next to the user real location to find impossible travel.
  6. The response step revokes the token and the refresh token, then asks the user to sign in again.

Real-world example

Imagine a hotel where your room key is a card. The card opens your door and the gym, and it carries no name. Anyone who picks up the card can use the gym and your room until the front desk cancels it. This rule watches for a card being used at two doors in two cities at once.

Key takeaways

  • An access token is a temporary key that works without the account password.
  • Failed sign in reports will not show token theft, so you need token use logs.
  • Revoke the refresh token too, or a new access token will simply be issued.

In more detail

This detection strategy covers theft of application access tokens, the technique tracked as T1528. Modern applications and command line tools hold bearer tokens and refresh tokens that grant access to mail, files, chat and cloud resources, and a stolen token can be used directly against the service from anywhere without a password prompt or a second factor challenge. The telemetry that makes it visible is identity provider token issuance and refresh records with the client identifier and source address, service side audit logs that show the same token used from a new address or a new client, endpoint file and memory access to token caches and command line credential files, and network records that place the token use outside the expected network. The strategy fails in practice because normal remote work, virtual private network changes and shared automation tokens produce the same impossible travel and unusual client patterns, so the rule needs a per application baseline of which client identifiers ever use which addresses.

What you will practise

  • Explain what an application access token is and how it differs from a password.
  • Name the identity provider records that show token issue, refresh and use with source address.
  • Identify the endpoint files and memory regions where tokens are stored on workstations.
  • Build a baseline of expected client identifiers and addresses for each business application.
  • Recognise an impossible travel or hosting provider address as a token theft indicator.
  • Carry out a token revocation response that also invalidates the refresh token.
