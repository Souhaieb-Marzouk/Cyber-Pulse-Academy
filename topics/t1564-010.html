T1564.010 Hide Artifacts: Process Argument Spoofing

T1564.010StealthExtremeTechnique

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

When Windows starts a program, it stores the instruction line that started it. That line is called the command line, and it sits in a memory area called the process environment block. Spoofing means an attacker changes that stored line after the program starts. Tools that read it later see a harmless version.

Why should you care?

The command line often shows exactly what a program was told to do. It can reveal a suspicious script, a file path or a network address. Security tools and analysts rely on it heavily. If an attacker can rewrite it, that record becomes misleading. You may read a harmless command while something harmful is running, so the evidence must be checked against other sources.

How it works, in plain steps

  1. Windows keeps a process command line in memory so the process and monitoring tools can read it.
  2. The attacker starts the process in a paused state with harmless looking arguments.
  3. Monitoring tools record the process start and read the harmless arguments at that moment.
  4. The attacker then writes new arguments into the paused process memory, replacing the old text.
  5. The process is resumed, so it now runs with the hidden, malicious arguments.
  6. Sometimes the order is reversed, and harmful arguments are replaced with harmless ones later.

Real-world example

Imagine the visitor book at a hospital reception desk. A visitor writes a harmless reason for the visit, such as a delivery. The receptionist records it and lets them through. Once past the desk, the visitor rubs out the entry and writes a different reason in the same space. Anyone reading the book afterwards sees only the second entry. Process argument spoofing works like that. The record was made before the change, so it no longer matches what the visitor really did.

Key takeaways

  • A command line captured from process memory can be changed after the fact.
  • Compare process creation records from more than one source.
  • Behaviour that does not match the recorded arguments deserves a closer look.

In more detail

Process Argument Spoofing hides what a process was actually asked to do by rewriting its command line after the process has been created. Windows keeps a command line in the process environment block, and many sensors read it from there when they log a process start. An adversary can create a process suspended with harmless arguments, allow the creation event to be recorded, then overwrite the stored command line in memory before resuming execution. The reverse also occurs, where malicious arguments are replaced with benign text to defeat later memory review. Detection turns on mismatches between kernel side process creation telemetry and arguments read from the process environment block, on tooling that writes into another process, and on behaviour that does not fit the recorded arguments.
