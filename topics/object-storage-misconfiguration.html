Object Storage Misconfiguration

Cloud SecurityHardKeyword

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

Object storage is a cloud service that holds files, called objects, inside containers often named buckets. Misconfiguration means those settings are wrong, so the files are open to people who should not have them. Often the bucket is public and anyone on the internet can read it. No software bug is needed for this to happen, only a wrong setting.

Why should you care?

A single open bucket can expose millions of records, including personal data and passwords. The leak is quiet, because reading a public bucket looks like normal traffic. Fixing it after discovery is slow, since you cannot make copies disappear from other people's computers. Rules such as the General Data Protection Regulation make an exposure expensive as well as embarrassing. The safest habit is to block public access at the account level first, and only then decide what to share.

How it works, in plain steps

  1. Someone creates a bucket for backups, logs, images or website files.
  2. To share one file quickly, they turn on public access or write a broad permission rule.
  3. The rule applies to the entire bucket, not just the single file they had in mind.
  4. Search tools and scanners regularly look for open storage and list what they find.
  5. Anyone who finds it can download the objects, and sometimes upload or delete them too.
  6. Each object also has its own permissions, so fixing the bucket alone may leave old files exposed.

Real-world example

Imagine a self storage building where every unit is locked. One customer props the main door open with a brick, so a friend can collect a single box. The friend takes the box, but now anyone walking past can enter and open any unlocked unit inside. The manager must remove the brick. The manager must also check which units were left unlocked while the door stood open.

Key takeaways

  • An open bucket is usually a permission mistake, not a broken program.
  • Block public access at the account level so a single wrong setting cannot expose data.
  • Review object level permissions too, because bucket level fixes can leave older files readable.

In more detail

Object storage misconfiguration means a bucket or container in a service such as Amazon S3, Azure Blob Storage or Google Cloud Storage is left readable or writable by parties who should not have that access, or is placed behind controls that do not actually restrict reachability. The mechanism is rarely a software bug: the storage API behaves exactly as configured, but the effective policy is wrong. Common causes are public access granted deliberately for a one-off file transfer and never revoked, bucket policies with a wildcard principal while the service's account-level public access block is disabled, role trust or sharing features that issue long-lived unauthenticated links, cross-account access that trusts another party's identifiers, and default object ownership where every uploader can rewrite permissions. These buckets are among the most common causes of large unintended data disclosures because a single list call can reveal hundreds of thousands of objects. The usual mistake is assuming that an unguessable key name is protection, or that removing a public flag is enough without checking the effective policy, the access block settings and every historical object's own access control entries. Prevention is configuration hygiene: account-level blocks, policy that names explicit principals and conditions, encryption with keys you control, access logging and continuous external checks.

What you will practise

  • Explain what object storage is and what a bucket misconfiguration means in practice.
  • Identify common causes of exposed cloud storage, including broad policies and leftover sharing links.
  • Describe account level public access blocks and why they are preferred over per bucket fixes.
  • Explain why object level permissions must be reviewed in addition to bucket level settings.
  • Outline preventive controls such as explicit principals, encryption and access logging.
