T1059.010 Command and Scripting Interpreter: AutoHotKey & AutoIT

T1059.010ExecutionExtremeTechnique

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

AutoIt and AutoHotkey are two scripting languages that automate tasks on Windows. They can press keys, click buttons and open or close programs for you. This technique is about attackers using them to run harmful actions. They often compile the script into an ordinary program file first.

Why should you care?

These tools are made for automation, so their behaviour looks like a helpful assistant. That makes harmful use hard to spot with simple rules. An attacker can use them to record what you type or to drive other programs. If you do not know these tools are on your network, you will not look for them.

How it works, in plain steps

  1. The attacker writes a script in AutoIt or AutoHotkey, or reuses one from elsewhere.
  2. The script may be sent as a phishing attachment or downloaded by earlier malware.
  3. It can be left as a script file or compiled into a single program file.
  4. When it runs, it can send keystrokes and clicks to other windows as if a person acted.
  5. It can also call Windows interfaces directly, so it is not limited to the screen.
  6. Common goals are recording typed keys, starting more malware, or hiding a window.

Real-world example

Picture a workshop with a robot arm that copies whatever the workers do. It is genuinely useful and everyone trusts it. A visitor writes a small card of instructions and feeds it to the arm. The arm then walks to the store cupboard, opens it and passes out the tools, one at a time. Nothing looks broken, because the arm is doing exactly what it was built to do. AutoHotkey and AutoIt are that arm when a visitor writes the card.

Key takeaways

  • Compiled automation scripts look like normal programs, so check the file details.
  • Automation interpreters are rare on office machines, which makes them a useful signal.
  • A process that injects keys into other windows deserves investigation.

In more detail

AutoIt and AutoHotkey are Windows automation languages designed to drive the graphical interface, which makes them attractive to an intruder who needs to interact with a machine the way a person would. Scripts in .au3 and .ahk form can read keystrokes, move the mouse, click buttons, type into fields, start and stop programs, and capture window contents, and both languages can call Windows interfaces directly so they are not limited to screen automation. They are also commonly compiled into standalone executables, which means the visible artefact is an ordinary program rather than a script file, and the compiled binary still carries interpreter code and characteristic strings. Real intrusions have used AutoHotkey payloads delivered by phishing emails to load further malware, including keyloggers, and to blend in with legitimate desktop automation. Detection rests on process creation telemetry showing the interpreter image or a compiled automation binary, the parent process that launched it, and where it was written; a long-running automation process that injects keystrokes into other application windows, or that appears in a user's download folder on a workstation with no automation tooling deployed, is the pattern that separates abuse from a software packaging or testing script running from a managed location.
