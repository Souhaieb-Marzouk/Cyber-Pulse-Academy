DET0192 Detection Strategy for Email Hiding Rules

DET0192Detection StrategyVery hardDetection Strategy

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

This detection looks for inbox rules that move or delete messages so the owner will not see them. An attacker who has taken over a mailbox creates such a rule to hide replies. The rule is stored in the mailbox and keeps working after the attacker leaves. This detection watches for the creation and the shape of those rules.

Why should you care?

Hiding a message is quiet and effective. A fraudster can reply to invoices and hide the complaint replies from the real employee. Password changes do not remove the rule, so the problem continues. These rules are recorded in the mail system, which makes them findable. Catching the rule early usually explains other strange mail activity.

How it works, in plain steps

  1. Someone creates or changes an inbox rule in a mailbox.
  2. The mail service writes an audit record with the rule details and the client used.
  3. The record shows the rule name, the match condition, and the destination folder.
  4. The rule checks whether the destination is a rarely used folder, such as a news feed.
  5. It also checks whether the rule deletes or forwards messages automatically.
  6. An unusual rule created by an odd client raises the alert with the rule body attached.

Real-world example

Think of a shared office post tray. Every employee has a slot, and the post room delivers letters each morning. One day someone quietly adds a rule: all letters for desk twelve go into the skip behind the building. The letters still arrive and the desk looks empty. The post room log, not the tray, tells you what happened.

Key takeaways

  • Hiding rules survive password resets, so they need to be hunted, not just alerted on.
  • The destination folder and the client application are the strongest discriminators.
  • Review rules that forward or delete automatically, because those change the record itself.

In more detail

This strategy detects mailbox rules that hide or divert email, the behaviour an adversary uses after compromising a mailbox to conceal replies, security alerts and fraud notifications from the real owner. It matters because hiding rules turn a stolen mailbox into a durable, quiet fraud channel that survives password resets, and because the rules persist in the mailbox long after the initial access method is closed. Detection is built on mailbox audit records for rule creation and modification, the rule parameters themselves, and the API or client used to make the change. The main practical failure is the sheer volume of legitimate rules that users create on personal devices, so the rule must weigh the destination folder, the scope of the match, and whether the client was an unfamiliar application or automation interface.

What you will practise

  • Explain why hiding rules outlive the initial mailbox compromise.
  • Identify the mailbox audit records that capture rule creation and modification.
  • Read a rule definition and recognise a concealing pattern rather than a sorting pattern.
  • Correlate rule creation with the client application and source address used.
  • Hunt existing mailboxes for rules that divert messages to low visibility folders.
  • Describe why removing the rule is part of detection follow up, not only the alert.
