T1592.002 Gather Victim Host Information: Software

T1592.002ReconnaissanceExtremeTechnique

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

This is when an attacker learns which programs and versions run on your computers. The attacker does not break in yet. They only collect facts, such as software names, version numbers and security tools, so they can plan a later attack.

Why should you care?

If an attacker knows your exact software version, they can look up known weaknesses for it. That turns a guessing game into a targeted attack. It also lets them see which protection tools you run. Most of this collection leaves almost no trace, so you often learn about it far too late.

How it works, in plain steps

  1. The attacker sends requests to internet facing services and reads the version banner that many services send back.
  2. They may plant a page or advert that quietly records details your browser shares, such as the user agent string.
  3. They read public job adverts, invoices and support pages that name the products your teams use.
  4. They download files from your public website and inspect hidden metadata, like which program created a document.
  5. They build a list of products, versions and protection tools for your organisation.
  6. They compare that list with public weakness databases to choose which flaw to try first.

Real-world example

Think of a house where every window has a small label showing its make and model. A burglar walking past does not open anything. They simply read the labels and then look up which of those window types is easy to force. Your software version banners are those labels, and the public weakness lists are the burglar's notebook.

Key takeaways

  • Version banners on public services hand attackers a shopping list, so hide or limit them.
  • Public documents and adverts can leak software details without any hacking at all.
  • Unexpected interest in your software versions is a warning sign worth investigating.

In more detail

Adversaries map the software running on victim hosts so they can pick exploits that are known to work and avoid wasting effort on hardened systems. Collection is usually passive or semi-passive: reading version banners from exposed services, capturing user agent strings from a planted web page, mining file metadata such as PDF producer fields, or simply reading job adverts and purchase invoices that name products. The valuable output is a product and version pair, because that pair can be cross-referenced against public vulnerability databases to find an exploitable flaw. It also reveals the defensive stack, since the presence of endpoint agents or log collectors tells an attacker what will notice them. On the network side the artefacts are ordinary looking, although version banners and unusual user agents going to untrusted sites are the main traces. Defenders separate hostile interest from routine traffic by baseline, not by signature: software enumeration of your own estate is expected from internal scanners and patch tooling, whereas the same queries arriving from external ranges or in unusual volumes are not.

What you will practise

  • Explain what host software information is and why attackers collect it before an intrusion.
  • Describe at least three ways software and version details leak to an outside party.
  • Identify the log sources, such as web server and proxy logs, that record version enumeration.
  • Distinguish routine internal scanning from hostile software reconnaissance.
  • Recommend simple hardening steps that reduce exposed software detail.
