T1189 Drive-by Compromise

T1189Initial AccessExtremeTechnique

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

A drive by compromise means your computer is attacked simply because you visited a website. You do not have to click a file or open an attachment. Harmful code already sits on the page, placed there by an attacker.

Why should you care?

Web browsing is part of almost every working day, so this path reaches people who follow the rules. The page may be a well known site that was hacked. An old browser or plugin is often enough for the attack to succeed. The traffic looks like ordinary browsing.

How it works, in plain steps

  1. An attacker hides harmful code on a website, often one you already trust.
  2. You open the page, and your browser downloads the page content as usual.
  3. Script on the page quietly checks the versions of your browser and plugins.
  4. If a weakness is found, the script uses it to run code on your computer.
  5. If not, the page may trick you into downloading and opening a file.
  6. Some pages only ask to send notifications, which then carry more lures.

Real-world example

Think of a public library where one book on the shelf has been tampered with. You borrow the book in the normal way, using your own library card. As you open the cover, a hidden mechanism inside releases a cloud of dust. The librarian saw nothing unusual, because the loan was perfectly normal.

Key takeaways

  • Visiting a trusted website does not by itself mean the content is safe.
  • Keep browsers and their add-ons patched, because the attack favours old versions.
  • After a suspicious page, check what the browser process started on the machine.

In more detail

A drive by compromise needs no attachment and no convincing message: the user is infected while browsing, because content the browser loads on a page the user chose to visit has been placed there by an attacker. Delivery has several shapes. The site itself may be legitimate but compromised, with an injected script or frame that loads attacker content. The page may pull a script from a cloud storage bucket that was left publicly writable, so the operator can change the script without touching the site. The visitor may never reach the intended site at all, because a malicious advertisement served through a legitimate ad network runs the payload inside the ad frame. User contributed features, such as comment fields or profile pages, can also be abused to plant script. A second, distinct pattern skips exploitation of the browser entirely and relies on user execution instead: a page asks permission to send browser notifications, and the notification channel is then used to deliver further lures. The classic mechanism after delivery is version probing, where script quietly fingerprints the browser, its plugins and its fonts, and either exploits an unpatched component or convinces the user to download and run a file. The targeting may be broad or narrow, and the narrow form, often called a watering hole, selects a community such as a sector, a region or a vendor's customer base, and compromises the sites that community reads. Detection is difficult because the initial request is a normal outbound web request from a normal browser to a normal looking address, so defenders work from proxy and domain resolution records, from threat intelligence about the specific host, and above all from what happens next on the endpoint, namely a browser process that spawns a script interpreter, an office application, a command shell or an unsigned executable from a download directory. Blocking unknown hosts and keeping browsers and their components patched remain the controls that break the chain earliest.

What you will practise

  • Explain how malicious content reaches a user through ordinary web browsing.
  • Describe the main delivery routes, including compromised sites and malicious ads.
  • Describe the typical sequence from page load to code execution or user execution.
  • Identify network and endpoint records that reveal a drive by compromise.
  • Explain what a watering hole attack targets and why it is hard to spot.
