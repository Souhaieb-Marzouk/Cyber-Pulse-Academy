T1565.001 Data Manipulation: Stored Data Manipulation

T1565.001ImpactExtremeTechnique

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

Stored data is information kept on a disk, such as a database, a document or a saved email. Stored data manipulation means changing that saved information directly. The parent technique covers all data changes, including data that is moving or only in memory. This sub-technique focuses only on data that has already been written down and stays there.

Why should you care?

A change to saved data can stay hidden for months. The system keeps running and nobody sees an error. Reports quietly show wrong facts, and decisions follow those facts. Backups taken after the change will also contain the wrong version. Finding the change means comparing records, not just watching live network traffic.

How it works, in plain steps

  1. The attacker gains access to a database, a file share or a mail store.
  2. They open stored records and then change values, add rows or delete entries.
  3. The application does not complain, because the data it reads is still valid in shape.
  4. Office documents and saved emails can be edited in the same direct way.
  5. If audit logging is weak, the edit leaves no record of who made it.
  6. Later reports and backups then inherit those changed values without any warning at all.

Real-world example

Imagine the guest register at a hotel reception desk. Each evening the clerk writes down who stayed and what they paid. Someone with a spare key comes in at night. They change two entries in the book and put it back on the desk. In the morning everything looks tidy and no alarm has sounded. The accounts team later adds up a total that does not match the cash in the drawer. Nobody knows when the change happened. Stored data manipulation is that quiet edit to the register.

Key takeaways

  • Saved data can be changed without breaking the application that uses it.
  • Compare records against an independent copy to find quiet edits.
  • Modification times and audit trails help show when a change happened.

In more detail

Stored Data Manipulation narrows the parent technique to data at rest, meaning records sitting in databases, documents on file shares, archived mail and proprietary file formats. The adversary edits those records directly rather than intercepting data as it moves between systems or while it exists only in memory, so the change persists until somebody notices and corrects it. Because the edit is made through normal file or database access, the application may never log a suspicious transaction, and a later reader simply sees the altered value. Detection is therefore a reconciliation problem rather than a prevention one: row counts, checksums, modification times, database audit trails and comparison against an independent copy will expose a discrepancy that live monitoring never raised.
