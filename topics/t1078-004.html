T1078.004 Valid Accounts: Cloud Accounts

T1078.004Initial AccessExtremeTechnique

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

A cloud account is a login that exists in a cloud service or online application. It may live only in that service, or it may be linked to your office directory. Either way it controls resources that belong to your organisation online. This is a sub-technique of valid accounts, which covers the abuse of real logins.

Why should you care?

Cloud accounts often hold the keys to storage, mail and virtual machines. If an attacker takes one, they may reach data without touching your office network. They can also add a second set of keys that keeps working after you reset the password. Some cloud logins are linked to your office directory, so one theft can affect both. That is why cloud logins need the same care as office ones.

How it works, in plain steps

  1. An organisation creates user or service accounts in a cloud provider and grants them permissions through roles.
  2. Some of these accounts are synchronised or federated, meaning they are linked with the office directory.
  3. An attacker obtains one by guessing the password, tricking the user, or stealing an access token.
  4. With that identity the attacker can read storage, change settings, or start virtual machines.
  5. They then add their own long-lived access keys or application credentials to stay in place.
  6. Defenders detect new credentials on quiet accounts and logons from unusual networks or regions.

Real-world example

Picture a hospital night desk where one master badge opens the pharmacy, the records room and the car park. A visitor copies that badge for a minute and then makes a spare copy. Even after the hospital cancels the original badge, the spare still works. Cloud accounts behave like that badge, because an attacker can add their own permanent key that survives every password change you make.

Key takeaways

  • Review cloud identities often and remove access keys nobody needs.
  • Alert on new access keys and on logons from new locations.
  • Linked cloud and office accounts mean one theft can affect both.

In more detail

Cloud accounts are identities created inside a cloud service provider or a software-as-a-service product, and they may be cloud-only, synchronised from an on-premises directory, or federated through a single sign-on trust. Because one identity often reaches both worlds, a stolen token or password can pivot from the cloud back into on-premises systems, for example through a software deployment tool that runs commands on hybrid-joined devices. Adversaries favour these accounts for quiet persistence: they attach additional long-lived access keys or application credentials that survive a password reset and can sidestep multi-factor authentication. They also exploit over-permissive roles, or resource identities that request tokens on a virtual machine's behalf, to read storage and databases. Defenders look for new credentials on existing accounts, logons from unexpected networks, and role assumptions outside the account's normal pattern.

What you will practise

  • Define a cloud account and describe how it differs from a local or domain account.
  • Explain how federated and synchronised identities connect cloud and on-premises systems.
  • Describe how added cloud credentials create long-term persistence.
  • Identify cloud audit logs that reveal role changes and new access keys.
  • Explain why least privilege and multi-factor authentication lower cloud account risk.
