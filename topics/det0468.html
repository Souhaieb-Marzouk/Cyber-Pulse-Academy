DET0468 Detect DHCP Spoofing Across Linux, Windows, and macOS

DET0468Detection StrategyVery hardDetection Strategy

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

A rogue DHCP server is an unauthorised device that answers when computers ask the network for an address. It can also tell the computer to use the attacker as its gateway or name resolver. This detection looks for address answers that come from a device the network does not trust.

Why should you care?

If an attacker controls the gateway, all traffic can pass through their machine. That allows silent reading and changing of data. The attack needs no malware on the victim and works on wired and wireless networks alike. Finding it quickly limits how much traffic can be read.

How it works, in plain steps

  1. Network devices and servers send their address assignment logs to a central platform.
  2. The detection keeps a list of approved Dynamic Host Configuration Protocol server addresses and names.
  3. It flags any address offer or acknowledgement that comes from a device outside that list.
  4. It also watches client network settings for a gateway or name resolver that changed to an unknown value.
  5. It correlates both signals on the same network segment within a short time window.
  6. An analyst checks the switch port or wireless access point that the rogue device is connected to.

Real-world example

Picture a hotel reception desk that hands out room keys. A stranger sets up a second desk near the lift and starts handing out keys too. Guests take the nearest desk and never notice. The room log then shows guests entering rooms that the real desk never assigned. This detection compares the keys in use with the desk that issued them.

Key takeaways

  • A rogue address server can silently become the path for all traffic.
  • The reliable sign is an address answer from a device outside the approved list.
  • Segment level context, such as switch port, is what turns an alert into a location.

In more detail

This strategy detects rogue Dynamic Host Configuration Protocol (DHCP) servers that hand clients a false gateway or Domain Name System (DNS) resolver in order to intercept traffic, which maps to the DHCP spoofing technique in adversary-in-the-middle activity. The telemetry needed is DHCP server and relay logging, switch or wireless controller records of DHCP snooping violations, client address assignment events, and DNS resolver metadata showing where clients actually send queries. Detection succeeds when a client's gateway or resolver changes to a value that is not in the approved infrastructure inventory. It fails in practice because networks with legitimate redundant DHCP servers, temporary lab networks and failover events produce the same pattern, so the rule must distinguish approved server media access control (MAC) addresses from everything else.

What you will practise

  • Describe how Dynamic Host Configuration Protocol assigns addresses and settings to clients.
  • Explain how a rogue server redirects traffic by changing gateway or resolver values.
  • Identify the logging sources that record address assignment and snooping violations.
  • Build an allowlist of authorised address servers per network segment.
  • Trace a rogue server alert back to a physical switch port or access point.
