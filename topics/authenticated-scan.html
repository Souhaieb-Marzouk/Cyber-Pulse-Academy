Authenticated Scan

Vulnerability ManagementHardKeyword

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

An authenticated scan is a vulnerability scan that logs in to the target first. A vulnerability is a weakness that an attacker could use. With a login the scanner can look inside the system. Without a login it can only guess from the outside.

Why should you care?

An outside scan guesses software versions from network replies. Those guesses are often wrong, so teams waste time on false alarms. A logged in scan reads the real list of installed software. It also finds missing patches and weak settings that never appear on the network. Better data means better decisions about what to fix first.

How it works, in plain steps

  1. You create a service account with read only rights for this purpose.
  2. That credential is stored safely and given only to the scanner itself.
  3. The scanner connects to each host and logs in over a secure channel.
  4. It reads the installed packages, the patch level and the security settings.
  5. The findings are matched to known weaknesses and given a severity score.
  6. You fix the issues and scan again to confirm that the fix worked.

Real-world example

Think of checking a house for problems. From the street you can only guess at the wiring and the pipes. If the owner gives you the keys, you can look in every room. You can see the leaking pipe behind the cupboard. The authenticated scan is the visit with keys, and the outside scan is the view from the pavement.

Key takeaways

  • Authenticated scans report installed software instead of guessing from banners.
  • Give the scanning account read only rights and protect that credential carefully.
  • The lower finding count is better data, not weaker coverage.

In more detail

An authenticated scan, also called a credentialed scan, is a vulnerability assessment in which the scanner logs on to the target host with a dedicated account and inspects the system from the inside rather than inferring everything from network responses. With valid credentials the scanner can read the installed package inventory, patch level, kernel version, local configuration, registry or configuration files and service settings, so it reports installed but unpatched software accurately and produces far fewer false positives and false negatives than an unauthenticated scan. It depends on operational prerequisites: a service account with the correct read only privileges, a secure way to store and rotate the credential, host and network firewall rules that permit the connection, and a scope that keeps the account from being usable to change the host. The mistake teams make is comparing authenticated and unauthenticated finding counts as though they measured the same thing, then deprioritising the credentialed results simply because the total number fell.

What you will practise

  • Explain what an authenticated scan is and how it differs from an unauthenticated scan.
  • Describe the account privileges and firewall access a credentialed scan requires.
  • Explain why authenticated results carry fewer false positives and negatives.
  • Describe how to scope a scanning credential so it cannot change the target.
  • Explain to a manager why finding counts should not be compared across scan types.
