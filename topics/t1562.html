T1562 Impair Defenses

T1562Defense EvasionExtremeTechnique

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

This is when an attacker weakens or switches off the security tools that would notice them. They might stop an antivirus service, which is software that looks for harmful programs, add a scanning exclusion, change logging settings, or quietly alter a cloud policy that protects many accounts at once.

Why should you care?

Your alarms cannot help you if someone turned them off. Worse, the change may look like routine admin work, so nobody reacts. A gap in your logs is evidence in itself. Attackers usually do this early, because a silent environment lets them work without rushing. Watch for both a control being disabled and an unexplained silence.

How it works, in plain steps

  1. The attacker obtains an account with rights over security tools or policies.
  2. They stop a protection service or remove it from the startup list.
  3. They add exclusions, so chosen folders or files are never scanned.
  4. Logging is reduced, or alerts stop being sent to the security team.
  5. In cloud systems, an audit or access policy is quietly loosened.
  6. Defenders notice the change itself, the missing logs, or both at once.

Real-world example

Imagine a museum where every room has a motion sensor. The intruder does not smash the sensors. They walk to the control room, log in with a borrowed staff badge, and mark three galleries as out of service. The guards see nothing unusual on their screen, because the screen is telling the truth about a system that was quietly switched off.

Key takeaways

  • Protect your security tools so they cannot be switched off easily.
  • Missing logs are a warning sign, not just a technical hiccup.
  • Compare control changes against approved change records, owners, and timing.

In more detail

Impairing defenses is the deliberate degradation, misconfiguration or removal of security controls so that subsequent activity is neither observed nor blocked. The mechanism exploits the fact that defenders administer their own tools through the same operating system, directory and cloud control planes the adversary is trying to reach. On endpoints this can mean stopping or disabling antivirus and endpoint detection services, altering their configuration to add exclusions, unloading security drivers, tampering with logging agents, or editing firewall rules to permit traffic that policy would otherwise deny. In the identity and cloud control plane it can mean weakening audit configuration, disabling conditional access or log export, removing alerting integrations, or using a legitimate administrative role to change a policy that protects many accounts at once. A quieter variant disables nothing outright but blinds a specific sensor by reducing event verbosity, excluding a directory from scanning, or reconfiguring a collection rule so the activity of interest stops generating records. The artefacts are unusually valuable because they look administrative. Service state transitions, configuration and registry changes to security products, termination of protected processes, audit policy modifications, unexpected gaps in log ingestion and control plane change records all appear in the same places legitimate administration appears. Investigators therefore treat timing, actor and authorisation as the discriminators. A change made during a maintenance window by a known engineering account, with a change record and a plausible scope, is routine. The same change made outside any window by a newly created or compromised account, scoped narrowly to the hosts or accounts currently under investigation, and immediately followed by unusual authentication or execution activity, is a strong indicator. Gaps in telemetry matter as much as explicit disablement: a host that stops reporting, a sensor that no longer emits an expected event class, or a retention setting quietly shortened can serve the same objective with far less noise.

What you will practise

  • Explain how endpoint, directory and cloud control planes can each be used to degrade or disable security controls.
  • Recognise the administrative looking artefacts that indicate tampering, including service state changes and security product configuration edits.
  • Use telemetry gaps and unexpected changes in log volume as evidence in their own right.
  • Differentiate sanctioned maintenance from malicious impairment using change records, actor identity, scope and timing.
  • Correlate impairment events with the authentication, discovery or execution activity that follows them.
  • Recommend monitoring and hardening that keeps tamper attempts visible even when a control has been successfully disabled.
