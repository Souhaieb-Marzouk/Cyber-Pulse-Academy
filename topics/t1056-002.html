T1056.002 Input Capture: GUI Input Capture

T1056.002Credential AccessExtremeTechnique

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

This technique uses a fake window that looks exactly like a real password box. The attacker shows it when a prompt would seem normal, such as during an install. The user types a password into the fake box because it looks familiar. That password goes to the attacker instead of the real system.

Why should you care?

Technology finds it hard to tell a fake dialog from a real one. The person at the keyboard becomes the last line of defence. A convincing prompt can appear right after software is installed, when users expect it. If the trick works, the attacker gains working credentials without writing any malware. Warnings about phishing mention email and websites, not local windows.

How it works, in plain steps

  1. The attacker prepares a window that copies the look of a real system prompt.
  2. The window is shown when a prompt would be expected, such as after an install.
  3. The user types a username and password into the fake box without doubting it.
  4. The typed details are saved or sent to the attacker instead of the real service.
  5. The fake window closes, and the real action may still happen so nothing seems wrong.
  6. Some versions watch which site or program the user opened so the prompt fits the moment.

Real-world example

Picture a busy hospital night desk at two in the morning. A person in a nurse's uniform with a convincing badge walks up to the desk. He says the pharmacy system is down and needs her login. The nurse on duty writes her password on his clipboard because he looks official. He thanks her politely and then walks away. There is no form in the real system at all. Nobody checked the badge, and her password is now in his pocket.

Key takeaways

  • A password prompt on your own screen can still be fake.
  • Attackers choose the moment when asking for credentials seems most natural.
  • Local dialogs deserve the same suspicion you give to a strange email link.

In more detail

Graphical user interface input capture uses believable imitations of operating system and application prompts to make a person type credentials into attacker controlled code. The canonical case is a fake elevation dialog, which copies the look of the prompt Windows shows when a task needs administrator rights, but the same idea appears as fake installers asking for a licence key or password, fake malware removal tools, and lookalike browser or mail client sign in windows. Such prompts can be produced by many scripting languages, including AppleScript on macOS, PowerShell on Windows, and shell or command line dialog tools on Linux, and they run under the ordinary user's context so they inherit the desktop the victim already trusts. The attacker often pairs the prompt with monitoring of which window or site the user is visiting, so the request arrives at a plausible moment. Detection is awkward because the malicious window may be the only artefact, but process creation for scripting hosts with dialog arguments, prompts whose parent process is unexpected, and tight correlation between a credential prompt and a recent suspicious process start all help.
