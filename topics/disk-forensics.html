Disk Forensics

Incident Response & ForensicsHardKeyword

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

Disk forensics is the careful study of a computer's storage after an incident. Investigators make an exact copy of the drive and study that copy. They look for files, deleted data and hidden traces. The goal is to find out what really happened.

Why should you care?

When a computer is attacked, important clues live on its disk. Simply clicking around can erase those clues forever. A proper copy keeps the evidence safe and unchanged. This helps a company learn what went wrong and fix it. It also gives proof if the case goes to court or to an insurer.

How it works, in plain steps

  1. You stop using the machine and unplug it, so nothing changes the disk while you work.
  2. You connect the drive through a write blocker, a device that allows reading only.
  3. You make a full copy of every sector, including parts the file system does not use.
  4. You record a hash value, a long fingerprint, of the copy and of the original drive.
  5. You examine the copy with forensic software and rebuild a timeline of events.
  6. You write a report that explains each finding and how you reached it.

Real-world example

Picture a library after a break-in. The police do not let staff tidy the shelves, because a moved book hides a clue. Instead they photograph the whole room exactly as it is. Later, experts read the borrowing cards to see who touched which book and when. A disk is that library. Deleting a file is like removing a card from the drawer. The shelf still shows the gap, and the card is often in the bin underneath.

Key takeaways

  • Never investigate an original drive directly; always work on a verified copy.
  • Deleted does not mean gone, because the data often stays on the disk.
  • Write down every step you take, because the record proves your work is sound.

In more detail

Disk forensics is the practice of acquiring and analysing the contents of storage media, such as hard drives, solid state drives, USB keys and virtual disks, to reconstruct what happened on a system. The discipline rests on two principles: acquire before you analyse, and work from a write-blocked copy rather than the original. A forensic image is a sector-by-sector duplicate, so it preserves deleted files, slack space, unallocated clusters and file system metadata that ordinary file copies discard. Analysts then rebuild timelines from timestamps and artefacts such as the registry, event logs, browser caches, prefetch files and the master file table. In a real environment it shows up after a confirmed intrusion, during insider theft investigations, in litigation holds and in ransomware recovery where the payload must be attributed. The mistake people usually make is treating the live machine as a convenient place to look, then booting it or installing tools, which destroys volatile evidence and alters the very timestamps they later rely on.

What you will practise

  • Explain what disk forensics is and why an exact copy of a drive matters more than the original.
  • Describe the role of a write blocker and a hash value in keeping evidence trustworthy.
  • Identify common artefacts, such as logs and file system metadata, that analysts use to build a timeline.
  • Recognise actions that destroy disk evidence and explain how to avoid them at the scene.
  • Summarise the difference between examining a live system and analysing a stored forensic image.
