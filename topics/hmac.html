HMAC

CryptographyVery hardKeyword

HMAC is a keyed message authentication construction defined in FIPS 198-1 and RFC 2104 that wraps an unkeyed hash function in a specific two-pass structure using inner and outer padding constants. It produces a message authentication code that proves both integrity and authenticity when the verifier holds the same secret key, and its security proof holds under weaker assumptions about the underlying hash than a naive secret-prefix construction, which is why it resists length extension attacks. HMAC-SHA-256 is the workhorse for API request signing, webhook verification, session token integrity, network protocol message authentication and key derivation through HKDF. Correct use depends on details that are easy to get wrong. The key must be generated randomly at an adequate length and stored as securely as any other credential, because possession of the key is possession of the ability to forge. Verification must be constant-time, since an early-exit byte comparison leaks how many leading bytes matched and enables forgery byte by byte. Truncated MACs reduce work for the attacker, and comparing a MAC that arrives in a client-controlled field without binding it to the request body, timestamp or nonce invites replay. Key rotation for HMAC secrets is operationally awkward when both sides must change simultaneously, so overlap windows and dual-key acceptance are standard practice, and log pipelines should alert on signature verification failures as a signal of tampering or credential misuse.

What you will practise

  • Explain the HMAC inner and outer padding structure and why it resists length extension attacks.
  • Implement secure MAC verification using constant-time comparison and explain the consequence of early-exit equality checks.
  • Design request signing for an API including key scope, timestamp binding, nonce handling and replay protection.
  • Choose appropriate MAC lengths and justify truncation only against a documented risk decision.
  • Plan an HMAC key rotation with overlapping key validity and no downtime for dependent services.
  • Analyse authentication failure telemetry to distinguish misconfiguration from active forgery attempts.
