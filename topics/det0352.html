DET0352 Detection Strategy for T1550.003 - Pass the Ticket (Windows)

DET0352Detection StrategyVery hardDetection Strategy

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

This detection looks for a Kerberos ticket that is used without the normal first step. Kerberos is the system Windows domains use to prove who you are. A stolen ticket can be used from another computer, so the attacker never needs the password.

Why should you care?

No password is typed, so there is no failed logon to notice. The ticket is valid, so every service accepts it. One stolen ticket can give access to many servers in the same domain. This makes it a favourite step for moving from one computer to another. You need to compare the ticket with the request that created it to see the problem.

How it works, in plain steps

  1. Domain controllers record every request for a ticket, including the account, the service and the ticket type.
  2. The rule pairs each ticket use with the earlier request that should have created it.
  3. A ticket used on a host that never asked for it is the main signal.
  4. The rule also looks at the ticket encryption type and the target service name for odd values.
  5. Endpoint records show which programs were active on the host at that moment.
  6. Inventory data tells the analyst whether the account normally works from that computer.

Real-world example

Think of a train ticket that is checked at the gate. A stolen ticket still opens the gate, because the gate only checks that the ticket is real. What the gate cannot see is that the traveller never bought it. The purchase record is what exposes the theft, and the domain controller keeps that record.

Key takeaways

  • A valid ticket is a credential, so look at how it was obtained.
  • Pair a ticket use with the request that should have come first.
  • Inventory of where each account works turns a strange logon into a clear alert.

In more detail

This detection strategy covers Pass the Ticket (T1550.003), where an adversary steals a Kerberos ticket from memory or from disk and uses it from another host to reach services without knowing the account password. The technique matters because the stolen ticket is a valid credential, so authentication succeeds and no password guessing or forced prompt appears, and because a service ticket can be used against many services that trust the same realm. Detection depends on domain controller Kerberos request records, Windows Security event 4624 logons that carry the Kerberos authentication package, endpoint process telemetry from the host using the ticket, and inventory that shows where each account normally works. It fails most often because legitimate single sign on, service accounts and cached tickets produce similar patterns.

What you will practise

  • Explain how a stolen Kerberos ticket can authenticate without a password
  • Identify the domain controller and endpoint telemetry that records ticket requests and ticket use
  • Recognise anomalies such as a service ticket used without a preceding ticket request from that host
  • Write a rule that correlates account, host, service name, encryption type and logon type
  • Triage a match by checking where the account normally works and what ran on the host at the time
  • Describe how filtering service accounts reduces noise and what malicious activity it hides
