T1566 Phishing

T1566Initial AccessExtremeTechnique

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

Phishing is a deceptive message sent to a person, designed to make them hand over access. It might carry a harmful attachment, a link to a fake login page, or a request sent through a chat or collaboration tool. The attacker targets people because people are easier to reach than well-protected servers.

Why should you care?

Most intrusions start with one message that someone believed. A single click can give away a password or run harmful code. The cost is not only that first machine, because the stolen login may open mail, files, and cloud apps. Good filtering helps, but it never removes the problem. Training and quick reporting matter just as much.

How it works, in plain steps

  1. The attacker studies a target and picks a story that feels urgent or normal.
  2. They send the message to one person or to hundreds at once.
  3. The message asks for a click, a file to be opened, or a code to be shared.
  4. The link leads to a fake login page that copies what the user types.
  5. The attacker then uses that stolen access, often within a few minutes.
  6. Defenders trace the message, check who clicked, and reset what was exposed.

Real-world example

Picture a delivery driver at a gated community. They cannot get past the barrier, so they call a resident and say a parcel needs a signature at the gate. The resident walks out, unlocks the barrier, and signs. The driver was never expected. Nothing technical failed; a helpful person simply opened the way.

Key takeaways

  • Check the sender, the link address, and the tone before you act.
  • Report suspicious messages quickly; you are probably not the first target.
  • Turn on multi-factor authentication, a second proof such as a phone code, so one stolen password is not enough.

In more detail

Phishing is the delivery of a deceptive message to a person in order to obtain credentials, execution or access on a system the sender cannot reach directly. The parent technique spans three broad vectors: messages carrying a malicious attachment, messages carrying a link to adversary-controlled or compromised infrastructure, and messages sent through a third-party service such as a collaboration platform, social network or messaging application rather than through corporate mail. At a mechanism level the adversary convinces the recipient to open a file that executes or exploits a client application, to follow a link that harvests credentials or serves a browser exploit, or to act on social pressure alone and hand over a token, a code or a decision. The artefacts an investigation relies on are spread across the mail path and the endpoint: message headers and authentication results, attachment names, types and hashes, rewritten or proxied URL records, gateway verdicts, web proxy and DNS logs for the destination, identity provider sign-in records for any captured credential, and process creation on the endpoint if something executed. Benign mail that resembles phishing is extremely common, since bulk marketing, file-sharing notifications, e-signature requests and internal awareness campaigns all share the same shape, so triage should weigh sender reputation and authentication failures, the age and hosting of the destination domain, whether other recipients in the same tenant received an identical message, and whether any recipient actually interacted rather than merely received it. Containment decisions follow the same evidence: resetting credentials, blocking a domain and removing a message are cheap, while quarantining a mailbox or rebuilding a host demands proof of interaction.

What you will practise

  • Describe how attachment, link and service-based phishing differ in delivery path and in the telemetry each produces.
  • Read message headers, authentication results and gateway verdicts to decide whether a reported message is genuinely malicious.
  • Correlate mail, proxy, DNS and identity logs to determine whether a recipient interacted with a phishing message.
  • Explain how URL rewriting, sandbox detonation and attachment detonation change the evidence available during triage.
  • Separate high-volume legitimate mail from phishing by evaluating sender reputation, domain age and tenant-wide recipient patterns.
  • Write detection logic for newly registered domains, display-name mismatch and authentication failure without flooding the queue.
  • Choose proportionate containment for a confirmed delivery, a confirmed click and a confirmed execution.
