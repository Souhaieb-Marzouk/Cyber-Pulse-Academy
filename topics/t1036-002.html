T1036.002 Masquerading: Right-to-Left Override

T1036.002StealthExtremeTechnique

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

This is a trick that uses a hidden text character to flip the order of letters in a file name. The real name stays the same on disk. The screen shows it backwards, so a dangerous file looks safe. Attackers use it to make you open the wrong thing.

Why should you care?

Your eyes are the last check before you double click a file. If the name on screen is wrong, that check fails. The same trick works in email attachments and in the Windows Registry. Security tools may show the name in the same confusing way. One hidden character can hide the true file type from everyone.

How it works, in plain steps

  1. The attacker puts a special Unicode character called right-to-left override into a file name.
  2. That character is invisible in normal views, but it flips the text after it.
  3. So a name ending in a script extension can appear to end in a picture or document extension.
  4. The bytes on disk do not change, so the operating system still sees the real extension.
  5. When you open it, the hidden program runs instead of a harmless document.
  6. The same reversed text can be placed in registry keys and in archive file names.

Real-world example

Picture a post office parcel label printed on clear film. Part of the address is written backwards, so the label looks like it points to your own street. The parcel is really addressed somewhere else. The delivery van reads the printed route, not your eyes, and drives away with it.

Key takeaways

  • A file name that looks normal on screen can still be backwards on disk.
  • Check extensions with a tool that shows raw characters, not a friendly view.
  • Treat unexpected hidden or control characters in names as suspicious.

In more detail

Right-to-left override is a defence evasion sub-technique that abuses the Unicode formatting character U+202E, which reverses the display order of everything that follows it inside a string, file name or registry key. The bytes on disk are unchanged, so the real extension still decides how the operating system handles the file, while the rendered name in a file listing, mail client or document viewer reads backwards and appears harmless. Because the character is invisible in most interfaces, the mismatch is only visible when the raw string is examined, which is why analysts use tools that show code points rather than rendered text. Detection leans on scanning file names, email attachment names, archive entries and registry values for bidirectional control characters, and on correlating a visually benign name with the executable type recorded by file metadata or the process creation log. Registry editors and command line tools render these strings differently from each other, so evidence collected with one tool can look clean while another shows the true order.

What you will practise

  • Explain what the right-to-left override character does to displayed text.
  • Describe why the file name on screen can disagree with the extension used by the system.
  • State how this sub-technique differs from the wider masquerading parent technique.
  • Locate the places where reversed strings can hide, such as file names and registry values.
  • Select analysis tools that reveal Unicode code points instead of rendered text.
