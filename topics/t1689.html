T1689 Downgrade Attack

T1689Defense ImpairmentExtremeTechnique

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

A downgrade attack makes a system use an older and weaker version of something. The older version may have no security logging, or no strong encryption. The attacker does not break the protection, but chooses a path where it was never built. This works because systems keep old features for compatibility.

Why should you care?

You may believe a control protects every machine, but an old version can walk around it. Logging that never happened cannot help an investigation later. Weak encryption can be read by anyone sitting on the network path. Attackers like this method because it is quiet and needs no new malware. Knowing which old versions still work in your estate is the first step.

How it works, in plain steps

  1. The attacker studies the target to learn which versions and protocols it still accepts.
  2. For scripting, they start an older interpreter that does not support modern content logging.
  3. The commands then run and leave no record of their content, only a process start.
  4. For network traffic, they force the connection to fall back to an older protocol or cipher.
  5. With weaker encryption, the attacker can read or change data inside the session.
  6. On some systems they replace a boot component with an older one that skips secure boot checks.

Real-world example

Think of an airport queue with two lanes. One lane has a passport check and a scanner. The other lane is the old staff door, which is still open for deliveries. A traveller who wants to avoid the checks simply walks through the old door. Nobody broke the scanner, and the guards in the main lane saw nothing. Downgrade attacks are the old staff door of a network. The modern control exists, but the building still offers a weaker way in.

Key takeaways

  • Turn off old protocol versions and interpreters that your systems no longer need.
  • Alert on the start of legacy interpreters and on cipher suites below your baseline.
  • An encryption downgrade on the network is often the first sign of an interception attempt.

In more detail

Downgrade attacks abuse backward compatibility: instead of breaking a control, the attacker makes the system use an older component or protocol version that never had the control in the first place. On Windows this can mean invoking an earlier PowerShell engine that does not support script block logging, so the content of a script is never recorded even though the process start is, and on the network it means negotiating a plain protocol or an obsolete cipher suite so that traffic which should be encrypted can be read or altered, a step that also opens the way to interception and sniffing. Artefacts differ by target: the command line shows the older host being launched, the endpoint shows an unexpected legacy binary or module path, and the network shows protocol negotiation records that fall below the organisation's baseline. Legitimate software does use old interpreters and legacy ciphers for compatibility, so the decisive evidence is usually the version used compared with that asset's normal behaviour, plus the presence of tooling that forces the weaker choice.

What you will practise

  • Explain the principle of backward compatibility and why it enables downgrade attacks.
  • Describe how running an older interpreter can bypass script content logging.
  • Describe how protocol and cipher downgrades expose traffic to reading and alteration.
  • Identify telemetry that shows a weaker interpreter version or cipher was used.
  • Explain how removing unused legacy features reduces the attack surface.
