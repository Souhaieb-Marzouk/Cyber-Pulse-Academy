DET0563 Detection Strategy for Defense Impairment via Prevent Command History Logging across OS platforms.

DET0563Detection StrategyVery hardDetection Strategy

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

This rule looks for signs that command history logging has been switched off. Command history is the file where a shell writes the commands a user typed. When logging stops, the record of what happened on that machine disappears.

Why should you care?

An attacker who removes the trail makes the later investigation much harder. Analysts may never learn which commands ran or which tools were used. This behaviour is also a warning sign on its own, because normal users have little reason to disable logging. Catching it early gives you a chance to look at the host while evidence still exists.

How it works, in plain steps

  1. The agent sends every new process to the central platform, with the full command line and the name of the parent process.
  2. A filter keeps only shells and commands that relate to history settings, such as a shell startup command or a change of the history file variable.
  3. The platform also watches file changes on the history file and its parent directory, including permission and attribute changes.
  4. Each match is tagged with the user, the host name and the parent process that started the shell.
  5. The platform groups these events by host and compares the count with the normal baseline for that host.
  6. It raises an alert when the count is unusual, or when a tool that is not an administrator tool starts the command.

Real-world example

Think of a night watchman in a warehouse. His only job is to write down every person who enters and leaves. One evening somebody quietly tells him to stop writing, and then takes goods out of the building. The building still looks normal, and the page simply stays empty. The empty page is the clue, not a missing door or a broken lock.

Key takeaways

  • An empty or missing command history is a clue, not proof that nothing happened.
  • This behaviour removes evidence, so it usually appears next to other suspicious activity.
  • The alert is strongest on hosts where such a change is never expected.

In more detail

This detection strategy covers adversary attempts to impair defenses by preventing command history logging on Linux, macOS and other Unix-like hosts, which maps to T1690. Command history is one of the few reliable evidential sources for what an intruder typed, so turning it off removes audit evidence and reduces the chance that post-incident review can reconstruct attacker actions. The telemetry that makes this possible includes shell process creation with full command lines, file modification events on shell history and shell startup files, and security audit records for attribute changes to those files. In practice the detection fails for two reasons: short-lived interactive commands are often not collected unless command line auditing is enabled, and legitimate configuration management and hardening scripts also modify history settings, which pushes analysts toward permissive filters.
