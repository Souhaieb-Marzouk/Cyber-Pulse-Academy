Diamond Model

Threat IntelligenceExtremeKeyword

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

The Diamond Model is a way to describe a single attack using four parts. They are the adversary (the attacker), the capability (the tool), the infrastructure (the channel) and the victim (the target). Every event has all four, and drawing them as a diamond shows the links between them.

Why should you care?

One alert on its own tells you very little. The Diamond Model pushes you to ask the missing questions. Who did this? With what tool? Through which channel? Against whom? When you can fill all four corners, you understand the event much better. It also helps you connect separate alerts into one campaign. That turns scattered noise into a story you can act on.

How it works, in plain steps

  1. Write the four corners for the event you are studying: adversary, capability, infrastructure and victim.
  2. Mark what you actually observed, and leave the corners you are only guessing clearly empty.
  3. Pivot from a known corner. If you know the domain, ask which tool and which victim connect to it.
  4. Compare events. Two events that share infrastructure and tool may belong to one campaign.
  5. Note the gaps. Missing corners become questions for your next round of collection.
  6. Keep facts apart from guesses, and record how confident each link between corners is.

Real-world example

A hospital analogy. A patient arrives with a fever. The nurse records four things: who the patient is, what the symptoms are, how the illness arrived and what the likely cause is. Any single detail alone is weak. Together they point to a diagnosis. If three more patients arrive with the same symptoms from the same street, the nurse spots an outbreak. The Diamond Model links single events into patterns in the same way.

Key takeaways

  • Every attack event has four corners: adversary, capability, infrastructure and victim.
  • Known corners let you make careful, testable guesses about the unknown ones.
  • Shared corners across events suggest one campaign rather than many separate incidents.

In more detail

The Diamond Model is an intrusion analysis framework that describes every malicious event as the interaction of four core features: an adversary, a capability, an infrastructure and a victim. The adversary is the actor or group directing activity. The capability is the tool, malware, exploit or credential the actor wields. The infrastructure is the physical or logical channel used to deliver the capability and control it, such as a domain, mail service, virtual private server or compromised host. The victim is the target, whether a person, organisation, account, asset or data set. Each event is drawn as a diamond with those four vertices. The value of the model lies in its edges and the pivots they permit: given any single known vertex, an analyst can reason about the others, and a confirmed link on one edge strengthens hypotheses along the rest. If two events share infrastructure and a capability but differ in victim, that suggests a broader campaign. If two share a victim and a capability but use different infrastructure, that suggests the actor is rotating channels defensively. The model also carries a socio-political meta-feature layer and, in the extended form, a technology meta-feature, acknowledging that adversary motivation and victim characteristics shape activity as much as tools do. Because the Diamond Model is event-centric, it complements rather than replaces kill-chain and ATT&CK views: it answers who did what to whom using what, while ATT&CK answers how. In practice, analysts use it to cluster events, generate collection requirements, prioritise intelligence gaps and document confidence. Its limits are equally important. The model is descriptive, so it imposes no analytic rigour by itself, and pivoting from infrastructure alone is prone to the same false attribution traps as any single-source inference.

What you will practise

  • You will be able to label the four Diamond Model vertices and the edges between them for a given intrusion report.
  • You will be able to pivot from a known infrastructure vertex to defensible hypotheses about capability and adversary.
  • You will be able to cluster multiple events into a campaign by comparing shared and divergent vertices.
  • You will be able to explain how the Diamond Model complements ATT&CK and kill-chain analysis instead of replacing them.
  • You will be able to identify intelligence gaps as missing vertices or unsupported edges and turn them into collection requirements.
  • You will be able to document an intrusion narrative that keeps observed events separate from inferential claims.
