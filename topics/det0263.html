DET0263 Detecting Bulk or Anomalous Access to Private Code Repositories via SaaS Platforms

DET0263Detection StrategyVery hardDetection Strategy

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

A private code repository is an online store for a company's programming work. Only invited people can open it. Bulk access means one account copies many repositories in a short time. This detection watches the platform's own record of who copied what, and when.

Why should you care?

Program code often hides passwords, addresses, and design details. An attacker who copies many repositories at once can carry away years of work. A single stolen token is often enough, because tokens rarely ask for a second factor. Normal developers clone a few repositories a day, so a sudden wide copy stands out. The platform record is the best evidence you will have, and it is usually kept for only a short time.

How it works, in plain steps

  1. The platform writes an audit entry for every clone, download, and token change.
  2. Those entries are sent to your central logging system, where they are stored and searched.
  3. The rule counts clone events per account over a rolling window, such as one hour.
  4. It compares that count with a baseline built from the same account in earlier weeks.
  5. It also looks at how many different repositories one account touched in that window.
  6. An alert fires when the count, the spread, or both pass the baseline by a wide margin.

Real-world example

Think of a library where members may borrow a few books at a time. The librarian knows each member's usual habit. A member who suddenly borrows two hundred books in one afternoon is probably not reading them. They are emptying a shelf. The borrowing record alone does not prove a crime, but it tells the librarian exactly whom to ask.

Key takeaways

  • The platform audit log is the primary evidence, and it is often short lived.
  • Compare each account with its own history, not with a single company-wide number.
  • A new token followed by wide cloning is a stronger signal than either event alone.

In more detail

This detection strategy addresses bulk or anomalous access to private code repositories hosted on a software as a service platform, tracked as T1213.003. Source code is valuable on its own and often contains credentials and internal design detail, so a single account can cause serious loss in a short time. The telemetry lives in the platform audit log, which records clone, fetch, and archive download events with the actor, the address, and the token used. The strategy fails when the platform audit log is not collected, when tokens are shared between people, or when the collection is slow and steady enough to stay inside normal engineering behaviour.

What you will practise

  • Explain why source code repositories are a high value target
  • Collect and retain source control platform audit logs for clone and download events
  • Establish per-account baselines for repository access volume and spread
  • Correlate new token creation with a following burst of clone activity
  • Describe why shared tokens make attribution difficult
