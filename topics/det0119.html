DET0119 Detection Strategy for Steganographic Abuse in File & Script Execution

DET0119Detection StrategyVery hardDetection Strategy

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

This detection looks for files that carry hidden content inside them. Steganography is the practice of hiding a message inside a normal file. A picture can look unchanged while it carries a hidden payload. The rule watches how such files are written and then used.

Why should you care?

An attacker can move data past your defences inside a picture. Your tools see a normal image and allow it. The hidden part only appears when a special tool reads it. If you only scan file types, you will miss it.

How it works, in plain steps

  1. The rule watches for new files created on disk, with their name and location.
  2. It keeps files whose name suggests a carrier, such as common image formats.
  3. It looks for a process that reads and rewrites the file, which is how hiding works.
  4. It compares the file size with what the file extension normally expects.
  5. It looks for a second process that opens the file within a short time.
  6. A rewrite tool, an odd path and a quick follow up reader together raise an alert.

Real-world example

Think of a sealed envelope delivered through normal post. The paper inside is a birthday card, but a message is written in lemon juice between the lines. The post room checks the envelope and the paper type and lets it through. Only someone who knows to heat the paper sees the message.

Key takeaways

  • Hidden data survives when you only check file types.
  • Watch the tool that rewrites the file, not just the file.
  • A file written in an odd folder and read straight away is suspicious.

In more detail

This strategy detects the use of steganography to hide payloads or stolen data inside ordinary looking files. The technique matters because a carrier image or document passes file type checks and content filters that would stop an executable, and the hidden content only appears when a specific tool or key extracts it. Detection depends on file creation telemetry such as Sysmon event 11, process creation that shows a tool loading and rewriting a media file, and command lines containing least significant bit or carrier file options. It fails in practice because steganography at low volume produces almost no unique events, so the rule leans on the combination of a recent decode or encode tool run, a media file written outside normal application paths, and a script that reads the file immediately afterwards.

What you will practise

  • Explain how data can be hidden inside ordinary media files
  • Select file creation and process creation telemetry that reveals hiding activity
  • Recognise command line indicators of encoding and carrier file handling
  • Correlate a rewritten media file with the process that reads it next
  • Escalate an alert by isolating and preserving the carrier file
