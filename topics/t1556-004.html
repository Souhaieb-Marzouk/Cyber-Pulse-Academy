T1556.004 Modify Authentication Process: Network Device Authentication

T1556.004PersistenceExtremeTechnique

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

Routers and switches check their own administrator logons. This technique means an attacker changes the device software so that a secret password also works. The normal administrator passwords usually keep working as well.

Why should you care?

Network devices carry all of your traffic and often control the rules between network zones. A hidden way in can survive reboots and survive password changes made on other systems. These devices log very little, so the change is hard to see. If you ignore device integrity, an attacker can watch your traffic for a very long time.

How it works, in plain steps

  1. A router or switch runs its own operating system and checks administrator logons locally.
  2. An attacker obtains the device image and adds a small piece of checking code.
  3. They install the changed image on the device, often during a quiet period.
  4. At sign-in, the added code first compares the input with its own secret value.
  5. If that value matches, access is granted without any configured account being used.
  6. Otherwise the request goes to the original code, so normal logons still work.

Real-world example

Imagine an office building where the front door lock was quietly replaced by a locksmith. The new lock still opens for every staff key, so nobody complains about it. It also opens for one extra key that only the locksmith holds. The building manager checks the door each morning and it looks identical to before. Only a careful look at the parts inside the lock would show that it is not the original one.

Key takeaways

  • Network device integrity matters because their logs are limited and their position is central.
  • Verify firmware images against vendor checksums and known good versions.
  • Watch for configuration or image changes outside approved maintenance windows.

In more detail

Routers, switches and firewalls run their own operating systems and verify administrator logons locally, often against a small set of configured accounts. This sub-technique covers changes to that system image or its authentication logic so that a password known to the attacker is accepted. Rather than attacking a remote service, the adversary modifies the device firmware or image and installs it, and the inserted code sits in front of the normal checking routine. When a sign-in is attempted, the added code compares the supplied value with its own secret and grants access on a match, otherwise it hands the request to the genuine code, so ordinary administrators still log in as expected. Because the check happens before the real verification, no configured account needs to change and the device audit output can stay unremarkable. Evidence tends to be indirect: image checksum or version mismatches, configuration differences nobody can explain, unexpected outbound connections, and flash writes outside a change window. Network devices also keep weak logging, so dependable controls are image integrity checks, controlled firmware updates and comparison against a known good configuration.
