DET0342 Detection of Suspicious Compiled HTML File Execution via hh.exe

DET0342Detection StrategyVery hardDetection Strategy

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

This detection looks for a Windows help viewer that opens a compiled help file. A compiled help file is a single file that holds help pages and small programs. An attacker can hide harmful script inside one of those files.

Why should you care?

The help viewer is a normal part of Windows, so security tools often trust it. That trust lets an attacker run script while the activity looks legitimate. The file that carries the script is small and easy to send by email or a download link. If you catch the viewer opening a file from a user folder, you can stop the next stage. Without this rule, the first step of the attack looks like somebody reading a manual.

How it works, in plain steps

  1. Windows records the start of the help viewer and the path of the file it opens.
  2. The rule checks where that file lives, because documentation normally sits on a share or in a program folder.
  3. A file in a downloads, temporary or user application folder is treated as suspicious.
  4. The rule then looks for a child process or a network connection started by the help viewer.
  5. Those events are joined by host, user and time so the analyst sees one chain of activity.
  6. An alert is raised when a user folder path and follow on activity appear together.

Real-world example

Think of a visitor who signs in with a staff badge that was reported lost last week. The badge opens the front door, so the door log looks ordinary. What makes it strange is that the badge should no longer work. Here, the signed help viewer is the badge, and the file path is the report that it was lost.

Key takeaways

  • Trusted Windows binaries can still be misused, so watch what they open.
  • The file path is often the strongest signal in the whole alert.
  • Look for what happens after the viewer starts, not only the start itself.

In more detail

This detection strategy covers Compiled HTML File (T1218.001), the abuse of the Windows HTML help viewer to run script content stored inside a compiled help file. The technique matters because the viewer is a signed Microsoft binary, so execution appears to come from a trusted component and can be used to fetch or run a second stage while bypassing application controls. Detection depends on process creation telemetry for the help viewer with its command line and parent process, file creation events for the help file itself, and child process or network activity that follows. The common failure is that help files are also opened for legitimate documentation, so the rule must weigh the file location, the parent process and the speed of the follow on activity.

What you will practise

  • Explain why a signed Windows binary can be abused to run untrusted script content
  • Identify process creation, file creation and network telemetry produced by the help viewer
  • Distinguish help files opened from documentation shares from files opened in user folders
  • Write a rule that joins the viewer process with the path of the file it opened and its child activity
  • Triage a match by inspecting the help file source, its hash and any follow on process
  • Judge how much coverage is lost when the rule is limited to user writable directories
