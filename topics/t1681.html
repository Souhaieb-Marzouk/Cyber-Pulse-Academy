T1681 Search Threat Vendor Data

T1681ReconnaissanceExtremeTechnique

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

This is when attackers read public reports about their own attacks. Security companies publish articles describing how a group works, including the names and addresses they used. Attackers read those articles to learn what defenders already know. They then change their tools and addresses so the next attack is not recognised.

Why should you care?

Many defences rely on lists of known bad addresses and file fingerprints. Those lists are useful until the attacker simply changes them, which can happen within days of a report. A team that only uses such lists will find them quietly going out of date. It also means you should think before you publish exact details, because attackers read the same articles you do. Behaviour-based detection lasts longer than any single address.

How it works, in plain steps

  1. A security company investigates an intrusion and publishes what it found.
  2. That report includes the tools used, the steps taken, and specific addresses or file fingerprints.
  3. The attackers find the report, often by watching the same news and research sources defenders read.
  4. They compare the report with what they actually did and note which parts were detected.
  5. They replace the mentioned addresses, domains or files with new versions and may shut the old ones down.
  6. Their next campaign uses the updated tools, so the old list no longer recognises them.

Real-world example

Imagine a burglar who reads the neighbourhood watch newsletter every month. The newsletter describes a break-in on Elm Street using a blue van and a bent screwdriver. The burglar learns that the van and the tool were what gave him away. Next month he uses a white car and a different tool. The newsletter is still accurate, but it describes the past, and the neighbours are still watching for a blue van.

Key takeaways

  • Published indicators have a short useful life, because attackers react to them.
  • Build detections around behaviour so a changed address does not defeat you.
  • Weigh the benefit of publishing an exact indicator against the warning it gives.

In more detail

Search threat vendor data describes adversaries reading the reporting written about them. Instead of gathering information about a victim, the actor studies threat intelligence publications, vendor blogs, indicator feeds and incident write-ups that describe their own campaigns or those of groups working the same industries. The material is detailed: behavioural descriptions, attack breakdowns, atomic indicators such as file hashes and addresses, and timelines of activity. What the actor wants is a gap analysis, knowing which of their tools, domains and techniques a defender can currently see, so they can rotate them before the next operation. Reported behaviour includes replacing indicators named in a blog post within days, and locating their own domain names inside intelligence data and then taking those domains offline, likely to avoid seizure or further scrutiny. From a defensive standpoint this technique is mostly invisible: an actor reading public pages generates web traffic that looks like any researcher, analyst or journalist working the same subject. Detection therefore leans on correlation rather than on the reading itself, for example a public-facing indicator appearing in telemetry shortly before it disappears from use, hosting churn that follows a publication date, or infrastructure changes clustered around a report release. The practical response is to expect indicator decay, to prefer behavioural detections over static lists, and to assess whether publishing a specific indicator will cost more than it gains.

What you will practise

  • Explain what types of information threat reports give to an adversary.
  • Describe why atomic indicators lose value quickly after publication.

  • Recognise the defensive trade-off in publishing specific indicators.
  • Explain why behavioural detection outlasts indicator based detection.
