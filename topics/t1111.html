T1111 Multi-Factor Authentication Interception

T1111Credential AccessExtremeTechnique

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

Multi factor authentication means proving who you are with a password and a second thing. That second thing may be a code from an app or a hardware key. This technique means an attacker steals that second thing instead of breaking it. They then use your real password and your real code together.

Why should you care?

Multi factor authentication is one of the strongest simple protections you can add. So attackers work around it rather than through it. A stolen code gives them a short window to log in. The records then show a valid user doing a valid login. If a keylogger sits on the machine, every account touched there becomes exposed. Users who are swamped with approval requests may accept one just to stop the noise.

How it works, in plain steps

  1. The attacker already has a valid password and needs the second factor.
  2. A keylogger on the endpoint records the one time code as the user types it.
  3. Codes sent by text or email can be read by compromising the phone or the message provider.
  4. A fake login page collects the password and relays the code to the real service within seconds.
  5. With a hardware token inserted in an infected host, the attacker can proxy authentication through it.
  6. In some schemes, learning the algorithm and seed values lets an attacker predict future codes.

Real-world example

You stand at a secure door and type your personal number into the keypad. A thief watches from nearby and memorises the digits. A moment later the same thief types the same number and walks in. The door reported a valid entry, so nobody raised an alarm, even though you never opened it.

Key takeaways

  • Interception copies a valid second factor, so the login will look legitimate in most records.
  • Watch for new devices, impossible travel and repeated approval prompts after a successful login.
  • Phishing resistant factors, such as hardware keys bound to a site, are much harder to intercept.

In more detail

Multi factor authentication interception attacks the second proof of identity rather than the password. An adversary who already holds valid credentials may use a keylogger to capture a token generated code or a smart card personal identification number as the user types it, proxy authentication through an infected host that has the hardware token inserted, or read codes that arrive out of band by email or text message. Codes delivered to phones can also be taken by compromising the handset or the messaging provider that relays them. Some hardware tokens can be predicted when the adversary learns both the algorithm and any seed values used to derive the displayed codes, which turns temporary access into a repeatable one. The resulting logons use genuine credentials and genuine codes, so user visible alarms are rare; the useful signals are behavioural, such as an authentication from an unusual location or device, impossible travel between two sessions, a prompt that repeats until a tired user approves it, or new session artifacts that appear without another interactive logon.

What you will practise

  • Explain how one time codes, hardware tokens and smart cards can be intercepted during normal use.
  • Describe why an intercepted second factor produces logons that appear legitimate.
  • Identify log and alerting sources, such as sign in records and device registration, that expose this activity.
  • Explain how phishing resistant authentication reduces the risk of code interception.
  • Recognise user reportable signs, including repeated or unexpected authentication prompts.
