G0107 Whitefly

G0107Enterprise GroupExtremeThreat Group

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

Whitefly is the name for a spying group that has been active since about 2017. Public reports say it has attacked many kinds of organisation in Singapore. It mainly wants to steal large amounts of private information. It has been linked in reporting to an attack on a large public health organisation.

Why should you care?

The group steals personal records, which can harm the people in them for years. It usually gets in through software that was never updated, so a simple patch would have helped. It also names its harmful files after real security products, which fools anyone checking names only. Because it can download more tools when it wants, the files you find today are only part of the picture. If you clean up only what you can see, the group can return.

How it works, in plain steps

  1. The intruders look for a computer that is missing important security updates.
  2. They send a file that looks like a document or an image, but is really a program.
  3. They use a known weakness to raise their rights on that computer.
  4. They place a harmful file where a trusted program will load it by mistake.
  5. They take saved passwords from the computer memory and use them to reach other systems.
  6. They download more tools when they need them and copy large amounts of records out.

Real-world example

Picture an office where every delivery must be signed for by the named person on the parcel. A courier arrives with a parcel labelled for the head of security, so the front desk accepts it without question and puts it in the internal mail. Inside is not a document but a set of keys. The label was the trick, and the label was easy to print. Naming a harmful file after a trusted security product works exactly this way. The name is a claim, not a proof. Only checking the actual sender, contents and path tells you the truth.

Key takeaways

  • Missing security updates on just one computer can open the way for a whole intrusion.
  • A file name that matches a trusted product proves nothing about the file.
  • Protect stored passwords, because stolen ones let an intruder move between systems.

In more detail

Whitefly is a cyber espionage group described in MITRE ATT&CK as operating since at least 2017, targeting organisations based mostly in Singapore across a wide range of sectors, with a primary interest in stealing large volumes of sensitive information. The entry links the group to an intrusion at Singapore's largest public health organisation. Because the victim set spans sectors rather than a single industry, the common factor in reporting is geography and data value, not technology: an organisation that holds large quantities of personal or clinical records is a suitable target regardless of what business it is in. The described tradecraft is deliberately ordinary and depends on unpatched systems. Reported elements include documents and images that turn out to be executable files, exploitation of a known Windows privilege escalation flaw on machines that were never updated, and a search order hijacking technique in which a malicious library is placed so that a legitimate program loads it instead of the real one. The library is reported to be named after components of genuine security vendor products, which is a naming trick that defeats investigators who filter by file name alone. Credential theft from memory follows, using a widely available open source tool, and the group is described as able to pull additional tools from its command infrastructure on demand, so the toolset observed on one host is rarely the whole set. Defensive evidence therefore comes from patch state, from process and library load telemetry showing a signed program loading an unexpected module from a writable path, and from monitoring for memory access to authentication services. The repeated misunderstanding here is that a familiar software name in a file path is evidence of legitimacy; in this reporting the familiarity was manufactured.

What you will practise

  • Describe Whitefly and the targeting pattern that public reporting associates with it.
  • Explain how unpatched privilege escalation flaws turn a single workstation into a foothold.
  • Explain search order hijacking and why naming a file after a trusted component evades review.
  • Identify telemetry that reveals a legitimate program loading an unexpected library.
  • Explain why memory based credential theft lets an intruder move laterally without new malware.
