T1104 Multi-Stage Channels

T1104Command and ControlExtremeTechnique

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

Multi stage channels mean command and control is built in layers instead of one connection. A first small program makes contact and prepares the machine. Later, a second and larger program takes over and talks to a different server.

Why should you care?

If you find and block one server, the attacker may still keep access through another layer. Each layer may look harmless on its own, so a single alert can seem unimportant. The layers often live on separate hosting, which makes tracing the operation back to one owner harder. You need to join several events together before the full picture appears.

How it works, in plain steps

  1. A small loader on the victim host calls back to a first stage server for instructions.
  2. That first stage gathers basic system details and can download more files.
  3. The first stage writes a second, more capable tool onto the disk or into memory.
  4. The second tool connects to a different server, often on unrelated hosting.
  5. That second stage supports a shell and further actions against the host.
  6. Backup first stage addresses may exist in case the first path is blocked.

Real-world example

Think of a treasure hunt where each locked box holds one clue. Opening the first box gives you only the location of the second box, not the final prize. If someone takes the first box away, the hunt simply starts somewhere else. Only after following several boxes do you learn where the trail actually ends.

Key takeaways

  • Command and control may arrive in layers, with separate servers for each stage.
  • An early stage beacon can be quiet and short, so it is easy to miss on its own.
  • Follow the second stage callback to find the first: process lineage and file writes link them.

In more detail

Multi stage channels split command and control into successive layers rather than using one endpoint for the whole operation. A lightweight first stage beacon checks in, reports basic host details and can pull down additional files; it then hands the host over to a second tool that talks to a completely separate server and offers richer interaction such as a shell. Because each stage uses different hosting and usually different domains or providers, blocking or sinkholing one layer leaves the others intact, and defenders see only a fragment of the chain at a time. The first stage is typically short lived and sparse, so it may generate nothing but a few periodic connections to an unremarkable domain. Useful detection comes from joining the events: process lineage from the initial loader, the file written by the first stage, and the outbound connection made by whatever that file launched. Backup first stage callbacks or fallback channels are common, so removing one address is rarely enough to end access.

What you will practise

  • Explain why an adversary would separate command and control into multiple stages with distinct servers.
  • Describe the typical roles of a first stage beacon and a second stage remote access tool.
  • Identify endpoint and network telemetry that links an initial loader to a later stage callback.
  • Assess why disrupting a single stage may leave an intrusion active through fallback channels.
  • Outline how process lineage and file creation records expose a staged handover on one host.
