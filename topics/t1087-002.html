T1087.002 Account Discovery: Domain Account

T1087.002DiscoveryExtremeTechnique

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

This is asking the central directory for a list of all accounts in the organisation. The central directory is the service that stores logins for the whole network. Unlike the parent technique, which covers accounts of every kind, this sub-technique focuses on centrally managed accounts. It is not limited to one machine.

Why should you care?

The central directory holds every user, group and service account. A single query can reveal who the administrators are. That tells an attacker whose password is worth stealing. These queries use normal tools, so they rarely look like an attack. You catch them by noticing how much one account is asking for.

How it works, in plain steps

  1. The attacker uses an authenticated session with directory query tools or script commands.
  2. They list domain users to learn how accounts are named in the organisation.
  3. They list groups and their members to find the accounts with the most power.
  4. They may query repeatedly, paging through large results to build a full picture.
  5. They use the map to choose targets for password attacks or credential dumping.
  6. Defenders alert on broad directory queries by accounts that normally need none.

Real-world example

Think of a company staff directory that lists every employee and their department. A visitor who can read it learns who runs finance and who holds the keys to the building. Nothing was broken and nothing was stolen, but the visitor now knows exactly who to approach. Domain account discovery is that reading of the staff directory.

Key takeaways

  • Directory read access is powerful, so log it and review it.
  • Alert when an ordinary account lists privileged groups.
  • Keep the number of highly privileged domain accounts small.

In more detail

Domain Account discovery queries the central directory for users, groups, and memberships across the whole environment. The adversary uses directory-aware utilities and scripting interfaces to pull lists of accounts, privileged groups, and group members, turning a single valid session into a map of who holds power in the organisation. Because the queries are authenticated and read-only, they resemble ordinary directory use and may only be recorded when directory auditing is enabled. Detection is therefore behavioural: unusually broad queries, enumeration of the most privileged groups, paging through large result sets, and one account listing far more objects than its role requires. The practical purpose is target selection, because the names returned tell the adversary whose credentials are worth stealing and which service accounts are trusted broadly.

What you will practise

  • Describe what domain account discovery returns to an adversary.
  • Explain how it differs from local account discovery.
  • Identify the directory and scripting logs that record these queries.
  • Explain why read-only directory access still needs monitoring.
  • Describe how tiered administration limits the value of the results.
