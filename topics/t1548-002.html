T1548.002 Abuse Elevation Control Mechanism: Bypass User Account Control

T1548.002Privilege EscalationExtremeTechnique

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

User Account Control is the Windows feature that warns you before a program runs with administrator rights. Normally you see a prompt and must agree. A bypass is a trick that lets a program gain those rights without showing you the prompt.

Why should you care?

The prompt is your last chance to stop a program from acting as an administrator. If a bypass works, that chance disappears. The attacker's program then runs with high rights and can change system settings, install software, or turn off protections. Bypasses also give an attacker a quiet way to keep elevated access on a machine they already reached.

How it works, in plain steps

  1. Windows gives each process an integrity level, from low to high, and high level means administrator rights.
  2. Some Microsoft programs are marked as trusted, so Windows starts them elevated without a prompt.
  3. Certain privileged system objects can also be used without triggering a prompt.
  4. An attacker starts one of those trusted programs and makes it load or run their own file.
  5. The attacker's code then runs at high integrity, even though the user never agreed to anything.
  6. Detection looks for unusual child processes that trusted system programs have started unexpectedly.

Real-world example

Think of a staff entrance with a turnstile. Visitors must stop at the desk and sign in. Delivery drivers, however, have a pass that opens the turnstile automatically. A stranger borrows a delivery jacket and a clipboard, walks through the turnstile without stopping, and is inside the building before anyone asks a question.

Key takeaways

  • Watch what trusted system programs start, because a bypass hides inside that parent and child relationship.
  • Keep ordinary users out of the administrators group and use the strictest prompt setting where you can.
  • An unusual child process from a signed Windows utility deserves investigation even when nothing was flagged.

In more detail

User Account Control gates privilege elevation behind integrity levels and a consent prompt, and bypass techniques let a process reach high integrity without that prompt. The underlying conditions are specific: binaries that Windows itself marks as auto-elevating can start elevated because they are trusted, some elevated Component Object Model objects can be activated without a prompt, and code injected into a trusted high integrity process inherits its level. Adversaries chain these facts, commonly by launching an auto-elevating system binary that in turn loads or executes an attacker-controlled file, or by abusing a component that performs file operations with elevated rights. The result is a high integrity process whose parent is a signed Microsoft binary, which is precisely the artefact defenders should scrutinise: process creation where a privileged system utility spawns an unexpected child, usually a shell or an unsigned binary, plus file drops into protected directories. Removing administrator rights from ordinary users and raising the notification level reduce the available surface.

What you will practise

  • Explain what User Account Control does and what integrity levels mean.
  • Describe why some Windows programs can elevate without showing a consent prompt.
  • Explain how an attacker uses a trusted auto-elevating program to run code at high integrity.
  • Detect likely bypass activity using process creation records and parent and child relationships.
  • Explain how configuration choices reduce the number of available bypass routes.
  • Describe how this sub-technique differs from the other elevation abuse techniques in its parent.
