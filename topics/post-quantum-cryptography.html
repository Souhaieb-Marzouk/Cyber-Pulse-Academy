Post-Quantum Cryptography

CryptographyExtremeKeyword

Post-quantum cryptography is the family of public-key algorithms designed to remain secure against an adversary equipped with a large-scale quantum computer, alongside the migration work required to deploy them. The threat is asymmetric in time: Shor's algorithm would break RSA and elliptic curve cryptography outright, while Grover's algorithm only modestly reduces the effective strength of symmetric primitives, so AES-256 and SHA-384 remain comfortable. The most urgent operational risk is harvest-now-decrypt-later, where traffic captured today is stored for decryption once the capability arrives, which makes long-lived confidentiality requirements the first migration priority. NIST standardised a set of algorithms for key encapsulation and digital signatures built on lattice, hash-based and code-based mathematics, with a hybrid deployment pattern that combines a classical and a post-quantum exchange so that security holds unless both are broken. Migration is harder than swapping a library. Organisations must inventory where public-key cryptography is used, including embedded devices that will never receive an update, hardware modules with fixed algorithm support, certificate and protocol size assumptions that break under larger keys and signatures, performance budgets on constrained links, and the certificate authority and code signing infrastructure that has to issue and validate new algorithm types. Governance questions follow, such as which algorithms are approved, how hybrids are represented in policy, and how long a cryptoperiod must be before quantum resistance becomes mandatory.

What you will practise

  • Explain how Shor's and Grover's algorithms affect public-key and symmetric cryptography differently.
  • Describe harvest-now-decrypt-later and identify which data classes justify early migration.
  • Compare post-quantum key encapsulation and signature families on trust assumptions, key size and maturity.
  • Perform a cryptographic inventory that finds public-key usage in code, devices, protocols and third-party services.
  • Plan a hybrid classical-plus-post-quantum deployment and explain what property the hybrid preserves.
  • Assess protocol and infrastructure changes needed for larger keys, including certificate handling and constrained links.
  • Build a migration roadmap with cryptoperiods, priorities and a defensible policy position on algorithm approval.
