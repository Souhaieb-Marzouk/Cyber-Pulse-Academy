T1505 Server Software Component

T1505PersistenceExtremeTechnique

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

Many servers are built to accept add-on code, called components or modules, so that teams can extend what the server does. This technique is about an attacker adding their own hidden add-on instead of the ones you planned. The add-on then runs quietly inside the server and comes back after every restart, which makes it very hard to remove.

Why should you care?

The attacker does not need a new software flaw because the server is designed to load extra code. Anything the server can do, the hidden component can do too, including reading files, running commands, and talking to the attacker. Since the component sits inside a trusted program, many security tools see normal server behaviour. Removing it is not enough on its own, because the attacker may simply install it again unless you also close the way in.

How it works, in plain steps

  1. The attacker gets rights on a server, often by using stolen administrator credentials or a known flaw.
  2. They pick an extension point the server already supports, such as a module, filter, plug-in, or stored code.
  3. They place their file or package where the server expects to find it and register it in the product configuration.
  4. The server loads the component at start-up or on demand, so the hidden code runs inside the trusted process.
  5. The component usually keeps the normal service working while it adds a small quiet back door for the attacker.
  6. Because the change lives in configuration and on disk, it survives restarts, updates and user logoffs.

Real-world example

Think of a shared flat where the front door has a keypad that any flatmate may add a spare code to, for a cleaner or a dog walker. An intruder who reaches the keypad adds a code of their own, then leaves. The door still opens for everyone else, nothing looks broken, and the intruder can return whenever they like until somebody reviews the full list of codes.

Key takeaways

  • Server extension points are a normal feature that attackers can turn into persistence.
  • Look for new or unsigned components in server configuration and log files.
  • Compare the current component list against a known good baseline and your change records.

In more detail

Server Software Component describes persistence achieved by abusing the extension mechanisms that enterprise servers deliberately provide for developers and administrators. Web servers, mail servers, database engines, and hypervisors all accept third-party plug-ins, modules, filters, or stored code so that organisations can add features without rebuilding the product. The adversary does not need a new vulnerability for this: they need the ability to register, upload, or modify a component and the rights to make the server load it. Because the host trusts its own extension points, the malicious component executes inside the server process, inherits its identity and privileges, and survives reboots and service restarts. Each underlying platform stores this state differently, so detection is platform specific: unexpected DLLs in server directories, new Registry entries for service or module configuration, new stored code inside a database, changed transport or module configuration, and file hashes that no longer match the vendor baseline. The common thread in triage is change control, not pattern matching: confirm who installed the component, whether a signed deployment record exists, and whether the component is reachable from outside the host before treating it as suspicious.

What you will practise

  • Explain why server extension features are attractive for establishing persistence.
  • Describe how a malicious component is installed, loaded and kept alive across restarts.
  • Identify the configuration and file artefacts left by added server components.
  • Distinguish an approved server plug-in deployment from an unauthorised one.
  • Outline a response that removes the component and closes the access path used to install it.
