DET0195 Behavioral Detection of System Network Configuration Discovery

DET0195Detection StrategyVery hardDetection Strategy

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

This detection looks for commands that read a computer's network settings, such as its address, routes and name servers. Attackers run these commands to map where they are. The commands are ordinary and built into the system. The rule focuses on how many run, in what order, and who started them.

Why should you care?

Knowing the network layout helps an attacker choose the next target. The check happens early and quickly, often within minutes of gaining access. One command means little, but a burst of them in a row means someone is exploring. It is also useful when it comes from a service account that never logs in. Detecting the pattern gives you an early warning worth acting on.

How it works, in plain steps

  1. A process runs one or more commands that read network settings.
  2. The operating system records the process, the full command and the parent process.
  3. The rule counts how many different discovery commands ran in one session.
  4. It checks whether that combination is common for that host type and account.
  5. It also checks whether a scripting interpreter or a remote tool started them.
  6. A rare burst from an unusual parent produces an alert during the exploration.

Real-world example

Imagine a new cleaner starting at an office. On the first night they walk every corridor, read every door sign and check which lights are on. That is reasonable once. Nobody minds a person learning the building. Staff do notice a cleaner who reads the door signs every night for a week. That cleaner never cleans anything. The pattern, not the single walk, is the odd part.

Key takeaways

  • Network discovery is a weak single event, so count commands inside a session.
  • Rarity of the command and parent pair is what makes this rule workable.
  • A service account running these commands is far more interesting than a person doing it.

In more detail

This strategy detects system network configuration discovery, the set of built in commands an adversary uses to learn a host's addresses, routes, name servers and interface details after gaining access. It matters less because of what it reveals on one host and more because it marks the orientation phase of an intrusion, and because the same commands appear within automated chain activity such as remote management frameworks and batch reconnaissance scripts. Detection rests on process creation with full command lines, interpreter invocation records on Linux, and the sequence and frequency of the commands. The practical failure is that these commands are everyday administration, so the rule is only useful when it scores rarity of the command and parent pair per asset type and links a burst of commands to one session.

What you will practise

  • Explain why adversaries perform network configuration discovery early in an intrusion.
  • Identify the built in commands that read addresses, routes and name server settings.
  • Count distinct discovery commands within a single session as a scoring signal.
  • Use rarity of the command and parent process pair for each asset group.
  • Recognise discovery launched by a service account or a remote management tool.
  • Describe how to chain discovery with subsequent lateral movement detections.
