T1105 Ingress Tool Transfer

T1105Command and ControlExtremeTechnique

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

This describes how an attacker brings new files or tools into a network they have already broken into. The files can come over the existing control channel or through an ordinary download tool. Once the files are on the machine, the attacker can use them for the next step.

Why should you care?

The first foothold is often small, so the attacker must fetch more tools to do more. Most of the tools they use already exist on the system, which makes this activity hard to spot. A single download can also be the delivery of ransomware or a key stealing program. If you never notice the transfer, the later damage will surprise you.

How it works, in plain steps

  1. The attacker gains a foothold and then needs extra tools on the victim host.
  2. Files are pulled down over the control channel or a different protocol, such as a file transfer service.
  3. On Windows, built in tools like PowerShell web requests or certutil fetch the file.
  4. On Linux and macOS, utilities such as curl, wget or scp do the same job.
  5. Cloud sync clients can also deliver files once an account on the service is accessed.
  6. The attacker may then check the file hash to confirm the download arrived intact.

Real-world example

A courier cannot reach the front door of the building, so the staff let the parcel in through the side entrance instead. The parcel itself looks ordinary and is signed for like any other delivery. Once it is inside, the courier uses the same entrance again for the next delivery, and each parcel is a little bigger than the last.

Key takeaways

  • Attackers prefer tools that are already installed, because these rarely look suspicious on their own.
  • Watch the parent process: script hosts and office programs rarely need to download files.
  • Follow the file from the download to the moment it runs, or the whole story stays invisible.

In more detail

Ingress tool transfer covers bringing files and utilities from outside into a compromised environment so later stages have something to work with. The carrier, not the tool, is the technique: files can arrive over an existing command and control session, over alternate protocols such as file transfer and remote copy services, through cloud storage clients that sync automatically once an account is accessed, or through built in download utilities already present on the host. On Windows, PowerShell web request commands, certutil, and BITS style transfers are routinely abused; on Linux, macOS and ESXi, utilities such as curl, wget, scp and tftp do the same job. Because these programs are legitimate and common, detection depends on parent child relationships and correlation rather than on the tool name. The reliable signal is an unexpected parent, such as an office document or a scripting host, spawning a download utility and writing an executable file, followed closely by that file running or connecting out.

What you will practise

  • Explain how tools and files are moved from external systems into a compromised environment.
  • List the commonly abused built in download utilities on Windows, Linux, macOS and ESXi.
  • Interpret process creation telemetry to spot a download launched by an unusual parent process.
  • Describe how cloud file syncing clients can be used to place files on a victim host.
  • Correlate a new executable file with its later execution or outbound connection.
