DET0250 Detect Credential Discovery via Windows Registry Enumeration

DET0250Detection StrategyVery hardDetection Strategy

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

This detection looks for someone reading Windows registry keys that store saved passwords. The registry is a large settings book inside Windows. Some teams leave passwords in it so services can start on their own. The rule watches tools that read those exact keys, and how many they read at once.

Why should you care?

A saved password in the registry is already in clear or weakly protected form. Reading it needs no exploit and often no administrator rights beyond the key. Attackers like it because it looks like ordinary system work. Building a list of the keys that matter lets you spot the few reads that should not happen.

How it works, in plain steps

  1. Windows records every program that starts when command line logging is switched on.
  2. The rule reads those records and looks for registry query tools and their arguments.
  3. It compares the queried path against a list of keys known to hold credentials.
  4. It also counts how many different sensitive keys one program touches in a short time.
  5. The parent process is checked, because a script host or office program is unusual here.
  6. A sensitive key read from an odd parent, or a burst of such reads, raises an alert.

Real-world example

Think of a hotel where each room has a safe. A guest may open their own safe. Now picture someone walking the corridor and opening every safe in turn. They have no cleaning cart and no list of rooms. The keys they try are the sensitive registry paths, and the number of doors shows it is a sweep.

Key takeaways

  • Saved passwords live in known registry paths, so build and keep that list.
  • Command line logging is what makes registry queries visible at all.
  • Look at the parent process and the number of keys, not at a single read.

In more detail

This strategy detects credential discovery through Windows registry enumeration, where an adversary reads registry keys that hold stored passwords, automatic logon values and application secrets instead of running a dedicated dumping tool. The technique matters because the registry holds credentials that administrators left behind for convenience, and reading a key is quiet enough to sit inside normal administrative noise. Detection depends on process creation records with command line auditing enabled, PowerShell script block logging, and registry object access auditing on the keys that matter. The main way it fails is that software inventory, configuration management and troubleshooting all query the registry constantly, so the rule has to key on the sensitive key set, the burst shape and the parent process rather than on any registry read.

What you will practise

  • Describe why Windows registry keys can hold usable credentials.
  • Identify the registry paths that commonly store saved passwords and automatic logon values.
  • Explain the role of command line auditing in process creation records.
  • Correlate the queried registry path with the parent process and the querying user.
  • Recognise a burst of sensitive key reads as a discovery pattern.
  • Describe how PowerShell script block logging adds visibility to registry reads.
