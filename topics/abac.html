Attribute-Based Access Control

Identity & AccessVery hardKeyword

Attribute-based access control (ABAC) is an access control model that evaluates a policy against attributes of the subject, the resource, the action and the environment at the moment of the request, rather than relying solely on a pre-assigned role. Typical subject attributes include department, clearance, employment status, device compliance state and manager, while resource attributes include classification, owner, tenant and data residency, and environment attributes include time, network origin, authentication strength and risk score. Because the decision is computed rather than looked up, ABAC can express rules such as permitting access only when the requesting device is managed, the user is a current employee in the owning department, and the request arrives from a trusted network during business hours. That expressiveness is also the model's principal operational hazard: policies interact, and a rule written to satisfy one business case can silently widen access when combined with another. Policy authoring therefore needs the same rigour as code, including version control, review, automated testing against representative request scenarios, and documentation of the attribute sources that feed each decision. Attribute quality becomes a security dependency, because a stale human resources feed or a device compliance signal that fails open can convert a correct policy into an incorrect decision. Implementing ABAC usually starts alongside existing RBAC, using roles as coarse-grained building blocks and attributes as fine-grained conditions, and this is the pattern most cloud identity platforms and policy engines such as Open Policy Agent and Cedar-family languages support.

What you will practise

  • You will be able to define subject, resource, action and environment attributes and map them to real access requirements.
  • You will be able to write and test an attribute-based policy and reason about how it composes with existing role grants.
  • You will be able to identify attribute sources whose staleness or failure mode could cause a policy to fail open.
  • You will be able to explain how policy-as-code review, version control and automated tests reduce misconfiguration risk.
  • You will be able to compare ABAC with RBAC for a given decision and justify a hybrid design.
  • You will be able to troubleshoot an access denial by tracing which attribute evaluation caused the decision.
