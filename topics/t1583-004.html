T1583.004 Acquire Infrastructure: Server

T1583.004Resource DevelopmentExtremeTechnique

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

A server is a computer that provides a service to other computers. This sub-technique covers an attacker buying or renting one for their own use. The parent technique covers getting infrastructure in general. Here the specific asset is a server the attacker fully controls.

Why should you care?

A server the attacker owns is a staging area for an entire campaign. Files, fake login pages, and control traffic can all live there. Because it is theirs, no legitimate owner will notice odd activity and report it. That silence is what makes this approach so useful to criminals.

How it works, in plain steps

  1. The attacker purchases a server, rents a dedicated instance, or abuses a free trial period.
  2. They install an operating system and set up web, mail, or file services on it.
  3. They upload tools, fake pages, and stolen content that will be used later.
  4. They test the setup by sending harmless traffic and checking the logs they control.
  5. During the operation the server sends phishing mail, hosts exploits, or relays commands.
  6. When finished, they wipe it, cancel the rental, or move to a second provider.

Real-world example

Think of a market trader who rents a lock-up garage outside town. It is not a shop, so no customers walk in, and only the trader has the key. Goods go there first, then come to the market looking ordinary. The garage looked harmless because it belonged to nobody else.

Key takeaways

  • Free trial cloud hosts are cheap and easy to abuse, so treat them as low trust.
  • Ask whether your organisation has a business reason to talk to a given server.
  • Recording what your normal servers do makes an unexpected one easy to spot.

In more detail

In this sub-technique an adversary buys, leases, or otherwise obtains a server, meaning a real machine or a dedicated cloud instance that they configure and run, instead of hijacking someone else's box. The parent technique covers infrastructure acquisition broadly; here the asset is a stand-alone server that is fully under the operator's control. Such a server gives the attacker a place to stage payloads, host phishing pages, run a watering hole, or act as a command and control endpoint, and because free trial periods of cloud servers are frequently abused, the cost can be near zero. The signal is not the server itself but the pattern around it: a short-lived instance in a hosting range, email or web content served from it that imitates a brand, untrusted certificate chains, or first-seen DNS pointing at a provider with no other organisational relationship. Legitimate servers are separated from hostile ones by ownership records, expected service role, historical traffic, and whether the host appears in asset inventories maintained by the defender.

What you will practise

  • Explain how this sub-technique differs from the parent Acquire Infrastructure technique.
  • Describe how a controlled server supports staging, delivery, and control activity.
  • Identify artefacts such as short-lived instances and first-seen hosting ranges.
  • Distinguish a hostile server from a legitimate business partner server.
  • Describe how asset inventory and egress review reduce reliance on guesswork.
