Disk Imaging

Incident Response & ForensicsVery hardKeyword

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

Disk imaging means making an exact, bit-for-bit copy of a storage device. Every part is copied, including deleted files, empty space, and hidden system areas. You then examine the copy and leave the original safe. The copy is called an image, and it acts as your evidence.

Why should you care?

Deleted files often still sit on the disk, and a normal file copy misses them. An image keeps that hidden material in one verifiable package. It also protects the original device from accidental changes. Without imaging, your analysis may destroy the very clues you need, and nobody can check your work later.

How it works, in plain steps

  1. Decide what to copy and whether the machine can be safely taken offline first.
  2. Connect the drive through a write blocker, a device that allows reading but blocks writing.
  3. Copy every sector of the drive into one image file, including unused space.
  4. Calculate a hash, a fingerprint of the image, right after the copy finishes.
  5. Calculate the hash again before analysis, and check that both values match.
  6. Examine only the copy, and store the original drive sealed and labelled.

Real-world example

Think of photographing a messy room before anyone cleans it. One wide photo of everything is better than a few close-ups. If you tidy first, small details are gone forever. A disk image is that wide photo. It captures the whole scene, including the corners you did not know mattered. Later you can zoom in as often as you like.

Key takeaways

  • An image copies everything, including deleted files and unused space.
  • A write blocker stops you from accidentally changing the original drive.
  • Matching hashes before and after copying show the image is unchanged.

In more detail

Disk imaging is the process of creating a bit-for-bit copy of a storage device, or of a defined set of allocated and unallocated regions, so that examination happens on a working copy while the original remains sealed and unmodified. The image captures everything the file system exposes plus what it does not: deleted file remnants, slack space, partition and boot sectors, volume snapshots, swap and hibernation files, and file system metadata such as timestamps and journal records. Because a single capture preserves all of that in one verifiable artefact, imaging is preferable to live file copying whenever the media can be removed or safely quiesced, and it is frequently the only way to recover deleted or partially overwritten material. Acquisition runs through a write blocker, either hardware or a validated software equivalent, and the resulting image is verified with a cryptographic hash computed at acquisition and again after transfer, since a mismatch invalidates the copy. Formats matter for practicality: raw images are simple and widely supported but large, while compressed or segmented formats with embedded metadata suit evidence transport and long-term retention. Logistics are as important as tooling, including capacity estimation, planning downtime for servers that cannot simply be taken offline, documenting the exact device and range captured, labelling media, and storing images in access-controlled locations. Analysis then covers file system parsing, deleted file recovery, artifact extraction and correlation with memory, log and network evidence.

What you will practise

  • Explain what a bit-for-bit image captures that a live file copy does not, including unallocated and slack space.
  • Select an acquisition approach, image format and tool for a given device, downtime window and evidence volume.
  • Perform a write-blocked acquisition and verify it with cryptographic hashes at acquisition and after transfer.
  • Document device identity, captured range, tooling, operator and hash values in a defensible acquisition record.
  • Plan storage, labelling and retention for large images with sensitivity and legal-hold requirements in mind.
  • Recover deleted and partially overwritten artefacts from an image and explain their evidential limits.
  • Correlate disk artefacts with memory, identity and network evidence to support a scoped incident narrative.
