G1003 Ember Bear

G1003Enterprise GroupExtremeThreat Group

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

Ember Bear is a name used in public reporting for a group linked to Russian military intelligence. It steals information and also destroys data on the computers it reaches. Destroying data means making files permanently unreadable, so the victim cannot simply restore from a backup and carry on.

Why should you care?

This group does not only spy. It also wipes systems, which can stop an organisation from working for weeks. Public reporting describes attacks on government offices and news organisations, where lost records can harm many people. Because the group often uses tools that already exist on the system, there may be few unusual files to find. That means good logging and quick patching of internet facing services matter more than looking for known malware names.

How it works, in plain steps

  1. The group looks for internet facing services that are not patched or use weak passwords.
  2. They get one account, then use built in system tools so they do not need to install much.
  3. They steal passwords and move to other machines, looking for servers with broad access.
  4. They may install a web shell, which is a small script that gives remote control of a web server.
  5. They prepare destructive software and test it, sometimes on a small number of machines first.
  6. Finally they run it, overwriting files and making recovery difficult without offline backups.

Real-world example

Imagine a warehouse where the fire alarm is tested every month, so nobody reacts when it rings. A visitor enters through a staff door left open for deliveries. He walks the aisles calmly, learns where the sprinkler controls are, and later returns to switch them off. The fire itself is the last step. Everything before it, the open door and the quiet walk through the building, decided whether the damage was possible. That is how destructive intrusions work. The breach happens long before the destruction.

Key takeaways

  • Patch and authenticate everything that faces the internet, because that is where these intrusions start.
  • Keep at least one backup copy offline and tested, since wiping can reach connected backups.
  • Public reporting attributes this activity to Russian intelligence, with some overlap and debate around cluster names.

In more detail

Ember Bear is a cluster that public reporting links to Russian military intelligence and to destructive operations conducted alongside espionage, most visibly against Ukrainian government and media organisations. The tradecraft mix is unusual for a state linked actor: reporting describes reuse of publicly available offensive frameworks, scripted deployment, web shells and wiper payloads that overwrite data rather than encrypt it for extortion. Intrusions commonly begin with exploitation of an internet facing service, stolen credentials or brute force against remote access, and then rely on living off the land behaviour so that the operator leaves few custom artefacts. Evidence available to defenders includes web server child processes spawning shells, unexpected administrative tooling on servers, mass file modification, and boot configuration changes that precede a destructive payload. The important misunderstanding is that a destructive actor is only a destructive problem: the wiper is the final step, and every stage before it, especially credential hygiene and exposed service management, is where the intrusion is actually stopped. Public reporting attributes the activity to Russian intelligence services, while noting that some activity overlaps with other clusters and that exact boundary lines are debated.

What you will practise

  • Explain how destructive operations are built on top of ordinary intrusion stages that defenders can detect earlier.
  • Describe how built in system tools and web shells reduce the custom artefacts available for malware based detection.
  • Identify the evidence that precedes data destruction, including mass file modification and boot configuration changes.
  • Design a backup strategy that survives a wiper attack, including offline and immutable copies.
  • Discuss public attribution of this cluster to Russian intelligence services and the limits of that claim.
