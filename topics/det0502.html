DET0502 Detection Strategy for Hidden Artifacts Across Platforms

DET0502Detection StrategyVery hardDetection Strategy

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

A hidden artefact is a file, folder, account or process that the computer does not show by default. This detection looks for new hidden items that appear in unusual places. It catches an attacker who tries to keep evidence out of sight. The goal is to find the item while it is still on the host.

Why should you care?

After an attacker gains access, they need somewhere to keep tools and stolen data. A hidden folder is a simple hiding place that needs no special software at all. Responders who use normal file listings will walk straight past it. Detecting the hiding step helps you find the intrusion and the files before they are used.

How it works, in plain steps

  1. The endpoint agent records file creation and file attribute changes.
  2. The rule looks for the hidden attribute being set on a new file or folder.
  3. It also looks for names that start with a dot in folders where that is unusual.
  4. On Windows file systems it checks for extra data streams attached to a file.
  5. Account and service records are checked for hidden or unexpected entries.
  6. A hidden item in a temporary or public folder raises an alert with the creator.

Real-world example

Think of a shared kitchen with a cupboard for each worker. Most people keep their mugs in plain sight on the shelf. One worker drills a small space behind the cupboard panel and keeps his things there instead. The kitchen looks normal to everyone else. This detection is the caretaker who notices fresh sawdust on the floor.

Key takeaways

  • Hiding an artefact is a simple step that needs no special tool.
  • Always record which process created the hidden file.
  • Learn where hidden files are normal, such as user home directories.

In more detail

This strategy detects hidden artefacts, where an adversary conceals files, directories, data streams, accounts or services so that responders cannot find them during an investigation. Examples include the hidden file attribute on Windows, a leading dot or a dot dot name on Linux, alternate data streams on NTFS volumes, and hidden local accounts or unregistered services. Telemetry covers file creation and attribute change events, file system auditing, shell command records, alternate data stream creation and account management records. It fails in practice because operating systems, browsers and development tools create hidden files constantly, especially in user home and application data directories, so the rule must weigh the file location together with the process that created it.

What you will practise

  • List common ways files and accounts are hidden on Windows and Linux.
  • Name the telemetry that records attribute and data stream changes.
  • Explain why the creating process matters more than the hidden flag alone.
  • Baseline legitimate hidden files in user and application directories.
  • Write a pseudo-rule that excludes known hidden file locations.
