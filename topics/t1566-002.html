T1566.002 Phishing: Spearphishing Link

T1566.002Initial AccessVery hardTechnique

Spearphishing link is a targeted technique in which the adversary sends a message containing a hyperlink and relies on the recipient to click it, after which the browser is directed to infrastructure controlled by the attacker. The destination may host a credential harvesting page that mimics a legitimate login portal, a page that serves a malicious download, a redirect chain that filters out automated analysis, or a consent screen for an identity provider that grants persistent access. Links are frequently wrapped behind legitimate marketing or file-sharing domains, and the visible anchor text rarely matches the underlying destination, which defeats naive keyword inspection. The evidence trail is split between mail, identity, proxy, and endpoint sources. Mail gateway and message trace records capture the URL and its rewriting service, giving a campaign-wide view when the same link is sent to multiple recipients. Secure web gateway and proxy logs show the click, the redirect chain, the user agent, and any subsequent file download, while DNS records expose resolution of first-stage domains. If credentials were entered, identity provider sign-in logs show the authentication together with contextual signals such as geography, device, and whether multifactor authentication was satisfied or bypassed. Browser and endpoint telemetry capture the download and the process that followed it. Benign newsletters, password reset messages, and vendor notifications all generate clicks to external links, so prevalence alone is not actionable. Investigations focus on destination reputation and age, the mismatch between sender identity and link domain, the authentication outcome for the affected account, and whether a download or an unusual OAuth consent followed. Any credential submission must be treated as a potential account compromise rather than a simple click event, because the response differs substantially.

What you will practise

  • Explain how redirect chains, URL rewriting services, and hosted landing pages shape the evidence available after a click.
  • Correlate mail trace data with proxy and DNS records to reconstruct the full path from message to destination.
  • Analyse identity provider sign-in logs to determine whether a click resulted in credential or token compromise.
  • Identify contextual authentication anomalies such as impossible travel, new device, or unexpected consent grants.
  • Distinguish routine marketing-link clicks from adversary traffic using domain age, reputation, and post-click behaviour.
  • Map link-based phishing to ATT&CK and state which telemetry sources must be retained for retrospective hunting.
