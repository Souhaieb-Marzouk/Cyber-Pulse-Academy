T1518 Software Discovery

T1518DiscoveryExtremeTechnique

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

This technique is an attacker looking around a computer to see which programs are installed. It is like opening the kitchen cupboard to check what is there before deciding what to cook. Nothing is damaged or changed, but the attacker learns what they can use later.

Why should you care?

Knowing the exact programs and versions on a machine tells an attacker which known weaknesses are present. It also shows which security tools are running, so they can avoid the ones that would catch them. This step often happens early, which means it can warn you before real damage occurs. If you never look at these quiet checks, the first sign of trouble may be a full infection.

How it works, in plain steps

  1. The attacker gets a foothold, usually as a normal user account or a stolen session.
  2. They run built-in commands that list installed programs, versions and running services.
  3. They may read the system registry, which on Windows records installed software.
  4. In cloud environments they call provider interfaces that report software and agents on servers.
  5. They compare what they find against lists of known weaknesses and useful tools.
  6. The results guide the next move, such as trying a flaw or placing hidden code.

Real-world example

Think of a burglar walking past houses and noting which front doors are old and which have an alarm box. They never break in during that walk. They simply gather facts, then come back to the one house whose door matches a key they already have.

Key takeaways

  • Listing installed software is reconnaissance, so it is an early warning signal.
  • The same commands are used by administrators, so judge them by context.
  • Watch for broad, fast sweeps across many hosts from one account.

In more detail

Software Discovery is the reconnaissance step in which an adversary builds an inventory of installed applications and their versions on hosts or in cloud tenants. The value is decision support: knowing which endpoint agent is present tells the attacker what to avoid, and knowing which product and patch level is installed tells them whether a local privilege escalation or remote exploit is worth trying. Enumeration is usually performed with tools that already exist on the target, including registry queries through reg query, directory listings, process listings, package manager commands, and cloud APIs that return installed software inventory. Because those same commands appear in routine administration, help desk work, and inventory scanning, detection depends on context rather than on the command string. Useful signals include the parent process that spawned the query, the identity performing it, the breadth and speed of the sweep across hosts, the time of day, and what happens next. A single inventory check from a management tool is expected; the same enumeration issued from an interactive shell on a workstation, repeated across many hosts in minutes, or immediately followed by exploitation activity is not. Correlation with patch and asset data keeps false positives manageable.

What you will practise

  • Explain why adversaries enumerate installed software before acting.
  • Describe the built-in commands and interfaces commonly used for this discovery.
  • Identify log sources that capture software enumeration on hosts and in cloud tenants.
  • Distinguish routine asset inventory from adversary reconnaissance.
  • Use software inventory data to predict the next likely move of an attacker.
