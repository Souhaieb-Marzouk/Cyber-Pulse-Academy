DET0487 Distributed Password Spraying via Authentication Failures Across Multiple Accounts

DET0487Detection StrategyVery hardDetection Strategy

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

Password spraying means trying one common password against many accounts. The attacker hopes that one person uses it. This plan looks for many different accounts failing to sign in from a few places. It also looks for a very small number of failures per account, because that is how spraying avoids lockouts.

Why should you care?

Lockout policies stop an attacker who guesses at one account. Spraying stays under those limits, so lockouts never trigger. Spreading the attempts over many addresses defeats simple rate limits too. The only reliable view is across all accounts at once. Without that view the activity looks like ordinary typing mistakes.

How it works, in plain steps

  1. Authentication sources record each failed sign in with the account name, the source address and the time.
  2. The detection groups the failures by account, not by source address, over a window such as one hour.
  3. It counts how many different accounts failed in that window and how many failures each account had.
  4. Many accounts with one or two failures each is far more suspicious than one account with twenty.
  5. The source addresses are then checked, because spraying often comes from several addresses.
  6. Any later success for one of those accounts is escalated, because it may mean the guess worked.

Real-world example

Think of a thief with a single key trying it in every front door on a street. Trying one door twenty times would attract attention and might jam the lock. Trying every door once is quiet, and only one door needs to open. Neighbours each see nothing odd. The pattern is only visible when you look at the whole street at once. The detection works the same way, by looking at all accounts together.

Key takeaways

  • Count failures per account and per hour, not per source address.
  • One or two failures across many accounts is the signature of spraying.
  • A success after a spray is the event you must escalate.

In more detail

Password spraying trades depth for breadth: instead of many attempts against one account, the attacker tries a small number of common passwords against a large set of accounts, and often spreads the attempts across many source addresses so that per source rate limits never trip. The detection therefore aggregates failed authentication on the account dimension rather than the source dimension, looking for one password pattern hitting many distinct user names, a high ratio of failed to successful attempts, and a low failure count per account that stays under lockout thresholds. The usual failure is that the rule counts failures per source address, which distributed spraying defeats by design, and that legacy authentication paths are not included in the aggregation.

  • Describe how legacy authentication paths hide spray attempts.
  • Set thresholds that separate spraying from ordinary user error.
