DET0022 Detect Forced SMB/WebDAV Authentication via lure files and outbound NTLM

DET0022Detection StrategyVery hardDetection Strategy

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

A lure file is a harmless looking file, such as a shortcut, that points at another computer. When you open the folder and view it, your computer tries to log in to that other machine. This detection watches for such files and the login they cause. It catches a trick that steals a password hash instead of a password.

Why should you care?

You do not need to open the file or click anything. Just viewing the folder is enough to send your login material. The stolen value is not your password but a hash, a scrambled form of it. An attacker can crack it later or use it to reach other systems. This makes a simple file share a path to a much larger compromise.

How it works, in plain steps

  1. The sensor records files created on disk, including their names, paths and, where possible, their contents.
  2. The rule looks for shortcut and link file types commonly used as lures in shared or user writable folders.
  3. It reads the target address inside the file and checks whether that address is outside your approved file servers.
  4. Separately it collects authentication events that show a session or logon going out to a remote address.
  5. Both events are joined by host and user inside a short window. A lure file with no follow up login is only a lead.
  6. The resulting alert names the file, the account and the remote address so the analyst can block the destination.

Real-world example

Think of a sign that offers free coffee in room 12. Room 12 is in another building you do not control. To get in, the receptionist hands over your company badge details. You never drank the coffee. Forced authentication detection is the door log that shows your badge details going to a building you do not own.

Key takeaways

  • The trigger is viewing a folder, not opening or running a file.
  • What leaves the host is a hash, which an attacker can crack or relay.
  • Compare the destination against your approved file servers before you alert.

In more detail

This strategy detects forced authentication, mapped to ATT&CK technique T1187, where an adversary places a file in a location the victim browses so that merely viewing the folder makes the operating system authenticate outward, sending the user NTLM response to a server the attacker controls. The stolen material is then cracked offline or relayed to another service. Detection has two halves that must be joined: a file write creating a lure, typically a shell link, shortcut or search connector file whose target points at a remote universal naming convention or WebDAV path, and the authentication telemetry that follows, showing an outbound SMB or WebDAV session or an NTLM logon to an address that is not a known file server. The correlating fields are the host, the user, the destination address and the short interval between the file appearing and the logon attempt. The strategy fails mainly because legitimate shortcut files point at remote shares all the time, so the rule needs an inventory of approved file servers and a focus on destinations outside the normal server population.

What you will practise

  • Explain how a shortcut or connector file can trigger outbound authentication
  • Identify lure file types and the file creation telemetry that reveals them
  • Read outbound SMB and WebDAV session or logon events and pick out unusual destinations
  • Correlate a lure file write with the authentication attempt that follows it
  • Maintain an approved file server inventory used to judge destination addresses
