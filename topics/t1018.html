T1018 Remote System Discovery

T1018DiscoveryExtremeTechnique

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

Remote system discovery is the work of finding out which other computers, addresses and services can be reached from a machine you already control. An intruder uses it to build a target list before moving further into the network. It is the mapping step, not the break-in step.

Why should you care?

If you cannot see discovery happening, you will miss the quiet preparation before an attack. The intruder learns which servers hold data, which machines are old and which services are open. Your own tools do similar work, so you need to know what normal scanning looks like. When a workstation suddenly probes hundreds of addresses, that is a warning you can act on.

How it works, in plain steps

  1. The intruder already controls one machine, often a laptop or a server that was reached earlier.
  2. From there, they check which addresses answer, usually by sending quick connection attempts to many of them.
  3. They also ask name services and look at shared folders to learn the names of other computers.
  4. On a company directory, they can simply list computer accounts, which is quieter than scanning.
  5. In cloud platforms, they call inventory interfaces that list running servers and storage without any network scanning.
  6. The result is a target list that the next stage of the attack will use.

Real-world example

The intruder is like a stranger in a large office building. They cannot enter every room, so they walk the corridors and gently try each door handle. They note which doors are unlocked, which rooms have names on them and where the server room sits. Nothing is stolen yet and no door is forced. Later they return to the two or three rooms that looked most useful.

Key takeaways

  • Discovery is quiet preparation, not theft, so it often comes before any damage appears.
  • Learn what your own scanners and inventory tools look like, so you can spot the odd one.
  • A single machine contacting hundreds of addresses in minutes deserves a look.

In more detail

Remote system discovery is the mapping of hosts, addresses and services reachable from a compromised position, producing the target list that later lateral movement and exploitation depend on. The mechanism varies with access level. From an endpoint, an adversary can use address resolution and name resolution traffic, broadcast name service queries, connection attempts to common ports, and management interfaces that enumerate peers. From a domain joined host, directory and network browsing interfaces reveal computer objects, trusts and shares, frequently returning far more than a single address sweep would. From cloud or virtualisation control planes, inventory interfaces list running instances, network interfaces, security group rules and storage endpoints, so discovery happens entirely through authenticated interface calls with no scanning traffic at all. The observable artefacts are therefore both network and host based. Flow records show one internal host attempting connections to many distinct destinations or ports in a short window, with a high proportion of rejects or resets. Firewalls and intrusion detection systems record denied connection attempts and scan like patterns. Name resolution logs show bursts of reverse lookups or queries that follow a host naming convention. Endpoint logs capture the scanning or enumeration process with its command line, parent process and execution path. Cloud audit logs show bursts of describe and list operations across regions or accounts. The main investigative problem is that authorised vulnerability scanners, asset inventory platforms, network monitoring and deployment tools do exactly the same things. Analysts distinguish them by source identity, scheduling regularity, whether the source appears on an approved scanner list, whether the scan is credentialed and authenticated, the breadth relative to the source host's normal role, and the absence of any change management context. Discovery that originates from an ordinary workstation or a server that has never scanned before, especially shortly after a new foothold or credential access event, carries far more weight than identical traffic from a known appliance. Sequence remains the strongest signal, because discovery is meaningful mainly for what follows it.

What you will practise

  • Explain how host, service and cloud inventory discovery mechanisms produce different network and host artefacts.
  • Interpret flow, firewall and name resolution data to distinguish scanning from normal peer communication.
  • Whitelist and profile authorised scanners, inventory agents and monitoring platforms so their activity is not repeatedly triaged.
  • Detect cloud and virtualisation inventory enumeration through control plane audit logs rather than network traffic.
  • Correlate discovery bursts with the credential access, lateral movement or exploitation that follows.
  • Rank discovery alerts using source host role, breadth of targeting and deviation from historical behaviour.
