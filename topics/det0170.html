DET0170 Detection Strategy for Modify System Image on Network Devices

DET0170Detection StrategyVery hardDetection Strategy

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

Network devices such as routers and switches run software called firmware or a system image. This detection looks for someone replacing or changing that image. It catches tampering that normal computer monitoring cannot see.

Why should you care?

The image is the most trusted part of a network device. If it is changed, every packet the device handles can be watched or altered. Endpoint tools do not monitor these devices, so the change can stay hidden for months. Rebuilding a device is slow and costly. Catching the upload early avoids all of this.

How it works, in plain steps

  1. Administrators reach network devices in two main ways. They use a management session such as Secure Shell, or they load a file through a transfer service such as Trivial File Transfer Protocol.
  2. The device, or the server that controls access, writes a record of each login. The record includes the account name, the source address and the time.
  3. The device also writes configuration change records when the boot image setting or a stored image file is changed.
  4. The detection links an image upload or boot setting change to the administrator session that happened just before it.
  5. It then compares that account, address and time with the approved change window and the list of people allowed to perform it.
  6. Anything outside that approved pattern is raised for review before the next reboot.

Real-world example

Think of a hospital sign-in sheet at the pharmacy. Anyone can walk past the counter, but only listed staff may collect a controlled drug, and each collection is written down. If a name appears that is not on the list, or at three in the morning, staff investigate before the drugs leave the room.

Key takeaways

  • Network device firmware lives below your endpoint tools, so you need device and authentication logs.
  • The strong signal is an image change tied to an unexpected account, address or time.
  • You cannot detect this at all on devices that do not log administrative sessions.

In more detail

This strategy covers modification of the system image on network devices, which means replacing or altering the firmware or operating system image that a router, switch or firewall boots and runs. Because the change happens outside the endpoint operating system, ordinary endpoint telemetry never sees it; the evidence lives in device configuration and image management logs, in the authentication records of administrators who reach the device, and in file transfer records for image uploads. An analyst detects it by correlating an image or boot variable change with the administrator account, source address and maintenance window that produced it. The common failure is weak or missing logging on network gear, which leaves the change visible only after a reboot surprises everyone.

What you will practise

  • Describe what a network device system image is and why changing it affects all traffic through the device
  • List the telemetry sources that can show an image upload or boot variable change on network hardware
  • Correlate an administrative authentication event with a subsequent image or configuration change
  • Compare observed change activity against approved change windows and authorised administrator accounts
  • Identify which network assets lack adequate logging and prioritise them for improvement
