T1484.002 Domain or Tenant Policy Modification: Trust Modification

T1484.002Privilege EscalationExtremeTechnique

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

This is a change to the rules that let two different computer groups or cloud accounts trust each other. When trust is set up, one side agrees to accept logins approved by the other side. An attacker who can edit those rules can arrange for their own logins to be accepted. This is the trust part of the wider policy modification technique, which you should learn first.

Why should you care?

If the victim side accepts the attacker signing certificate, every forged login looks genuine. The attacker does not need to steal more passwords. In cloud services one new identity provider can hand out access to many accounts at once. These changes often involve no malware, no strange file, and no obvious break in. Only sharp monitoring of trust settings will show it happened.

How it works, in plain steps

  1. The attacker gains rights over trust or federation configuration in a domain or cloud tenant.
  2. They add a trust link or an identity provider that they themselves control and can sign for.
  3. They may also convert a normal domain into a federated one so tokens are accepted.
  4. They then present a token signed by their own material and the victim environment accepts it.
  5. Claim rules or identity mapping can be tuned so the token appears to be a privileged user.
  6. The forged logins appear in normal authentication logs without any malware being present.

Real-world example

Think of a club that agrees to accept guest passes stamped by a partner club down the road. The door staff only check that the stamp matches the agreed pattern. If someone can change the agreement so their own stamp is on the accepted list, they can print a pass for any member and walk in. The door staff did nothing wrong; the rule book was edited before they arrived.

Key takeaways

  • Trust and federation settings are credentials in disguise, so protect them like passwords.
  • Review accepted signing certificates and identity providers on a regular schedule.
  • A forged token can enter your environment without any malware running.

In more detail

Trust modification changes the relationships that let one domain or identity tenant accept authentication from another. In Active Directory this means editing existing trust objects, adding a new trust, or converting a domain to a federated one so that tokens signed by a certificate the attacker controls are accepted. In a cloud identity service it means registering an external identity provider or changing federation and claim rules so an attacker chosen identity maps to a privileged user. The key mechanism is that the victim environment itself validates the forged token, so the attacker never needs to break the signing key on the victim side. Detection depends on audit records of trust and federation changes, on unexpected certificate thumbprints in the configuration, and on logon events where the issuing authority of a token does not match the resource domain.

What you will practise

  • Explain what a trust relationship is between domains or identity tenants.
  • State how this sub-technique differs from the wider domain policy modification technique.
  • Describe how a federated trust lets an attacker forge accepted logon tokens.
  • Identify the audit records that capture trust and federation changes.
  • Explain how registering an external identity provider can expose many cloud accounts.
  • Explain how to tell a legitimate federation change from an attacker controlled one.
