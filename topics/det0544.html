DET0544 Detection Strategy for Process Doppelgänging on Windows

DET0544Detection StrategyVery hardDetection Strategy

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

This detection looks for a Windows trick that hides malicious code inside a file transaction. A transaction is a group of file changes that either all happen or all are undone. The attacker writes code, starts a process from it, then undoes the change.

Why should you care?

After the undo, the file on disk is the original clean program again. A file scanner finds nothing wrong, and the running process still holds the hidden code. That gap between what is on disk and what is in memory is why this needs its own detection logic.

How it works, in plain steps

  1. The endpoint records every process start together with the image path and the parent process.
  2. The endpoint records image load events and whether each loaded file carries a valid signature.
  3. File system monitoring records when a transaction begins, writes data and then commits or rolls back.
  4. The platform links these records by host and by a very short time window, usually seconds.
  5. The rule looks for a process start that follows a rolled back transaction touching the same file path.
  6. A match raises an alert with the image path, the transaction result and the signature state.

Real-world example

Think of a visitor who writes a note on a whiteboard, photographs it, then wipes the board clean. The board looks untouched, but the photograph in the visitor pocket still holds the note. Rolling back the transaction wipes the board while the running process keeps the note.

Key takeaways

  • The file on disk and the running copy can differ. That difference is the whole point of the trick.
  • Timing correlation matters, because the transaction and the process start happen seconds apart.
  • Unsigned image loads in a signed process are a strong supporting signal.

In more detail

This detection strategy covers process doppelganging on Windows, matching technique T1055.013, where an adversary writes a malicious image inside a file system transaction, creates a process section from the transacted file and then rolls the transaction back so the file on disk never shows the malicious content. It matters because the resulting process appears to run from a legitimate signed binary while file based scanning sees only the original clean file. The telemetry that makes it possible is process creation records with transaction and section information, image load events with signature status, and file system transaction activity correlated within a very short time window on the same host. It fails in practice because transaction events are high volume and partial implementations exist, so defenders often lack the exact transaction fields and must fall back to correlating transient file writes with process creation.

What you will practise

  • Explain how a file system transaction can be rolled back after a process is created from the modified file
  • Identify the process creation, image load and transaction telemetry needed to observe this behaviour
  • Describe how to correlate a rolled back transaction with a process start on the same host
  • Interpret image load signature status alongside process creation to judge whether an image is genuine
  • Write a detection rule for this pattern and explain its telemetry dependencies and blind spots
