DET0077 Detection of Exfiltration Over Alternate Network Interfaces

DET0077Detection StrategyVery hardDetection Strategy

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

A computer can reach the internet in more than one way. There is the office cable, the office wireless and a phone hotspot. This detection looks for large amounts of data leaving by another path.

Why should you care?

Your network sensors only see traffic that passes them. A laptop on a mobile hotspot is outside that view. An attacker can copy files out and leave almost no trace in your network logs. Spotting the change of path is often the only clue you get.

How it works, in plain steps

  1. The host sensor records each network connection and the adapter used.
  2. The system logs when a new adapter appears, such as a tethered phone.
  3. The detection tracks normal traffic for each computer and each adapter.
  4. It flags a host that sends a large volume over an adapter that is idle.
  5. It checks whether the main corporate connection was still active.
  6. It adds weight when the same host recently read many files or made an archive.

Real-world example

Think of an office that checks every bag leaving through the front door. Someone carries boxes down the fire stairs instead. The front door log stays perfectly quiet, and the guard sees nothing. The only hint is the fire door alarm, which shows a door that is never used.

Key takeaways

  • Data that leaves by a second path never reaches your inspection tools.
  • The useful clue is a change of path plus an unusual volume of data.
  • Approved remote and mobile devices need their own baseline, or alerts become noise.

In more detail

This detection strategy covers theft that leaves through a path outside the monitored corporate network, using a second network adapter, a wireless connection to an unmanaged network, or an encrypted tunnel to a third party service. It matters because the whole point of the technique is to avoid the inspection point: data that travels over a mobile broadband link or a personal tunnel never reaches the web proxy, the data loss prevention sensor or the firewall that the organisation relies on. The telemetry that makes it visible is endpoint network connection records that identify the interface carrying each flow, adapter and tunnel establishment records, and flow data with enough interface context to show traffic on a path that should be idle. The pattern worth alerting on is a host that suddenly sends significant volume over a newly appeared or normally idle interface while its primary corporate link is still connected and healthy. It fails in practice because legitimate users move between docking stations, wireless networks and mobile hotspots all day, so an interface change alone is meaningless and the rule has to earn its keep by combining volume, destination reputation and whether the data being read is sensitive.

What you will practise

  • Explain how alternate network paths bypass network based inspection and data loss controls.
  • Identify the interface, adapter and tunnel records that reveal which path carried a flow.
  • Correlate a change of network path with the volume and sensitivity of the data being read.
  • Separate approved mobile and remote working patterns from anomalous interface use.
  • Describe the containment options available when a host is exfiltrating over an unmanaged link.
