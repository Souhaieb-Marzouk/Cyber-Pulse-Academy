Host Firewall

Endpoint & MalwareHardKeyword

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

A host firewall is a filter that runs on one computer and checks the network traffic going in and out. It keeps a list of rules, such as allow this program or block this port. When a packet does not match a rule, the filter drops it. It protects that single machine, even when the machine leaves the office network.

Why should you care?

An office firewall protects the edge of the network, but it cannot see everything. A laptop taken to a coffee shop loses that protection. A virus on one server can talk to another server inside the same building. A host firewall stays with the machine and blocks traffic you did not allow. It also limits the damage when an attacker already has a foothold.

How it works, in plain steps

  1. The operating system sends every network packet through its local filter first.
  2. The filter compares that packet with an ordered list of its rules.
  3. A rule may match an address, a port, a program or a user.
  4. If no rule allows the packet, the default action simply drops it.
  5. Outbound rules can also block your programs from calling unknown outside servers.
  6. Logs record the blocked traffic so that an analyst can review it later.

Real-world example

Think of a shared flat with its own door chain. The building has a main entrance with a guard, but each flat still decides who may come in. If a stranger gets past the main door, the chain on your own flat still stops them. You can also decide that your flatmate should not shout instructions down the stairwell to strangers. A host firewall is that chain and those house rules for one computer.

Key takeaways

  • A host firewall protects one machine, wherever that machine happens to go.
  • Start from default deny, then add only rules that you can explain.
  • Check outbound rules too, because they can stop malware calling home.

In more detail

A host firewall is a packet filtering engine that runs on the endpoint itself, so rules can be written against that machine's interfaces, programs, users and services rather than only against network addresses. It normally enforces default deny for inbound traffic and can also constrain outbound connections, which is what stops a compromised process from quietly reaching a command-and-control server. Because the policy travels with the workload, it keeps protecting a laptop that joins an untrusted wireless network and a server that sits inside a flat, unsegmented internal network. The mistake is assuming the perimeter device or a cloud security group covers the endpoint: a security group filters at the virtual interface and cannot see traffic between two processes on the same host, and a locally disabled firewall leaves a forwarding path open for lateral movement. Host firewall logs also feed detection, so unmanaged endpoints are both an exposure and a visibility gap.

What you will practise

  • Explain what a host firewall is and how it differs from a network firewall.
  • Describe how packets are evaluated against an ordered rule set with a default action.
  • Explain the value of outbound filtering on laptops, servers and build agents.
  • Identify where host firewall logs are collected, retained and reviewed.
  • Apply host firewall rules to a real workload without breaking required traffic.
