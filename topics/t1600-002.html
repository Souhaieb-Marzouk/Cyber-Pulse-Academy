T1600.002 Weaken Encryption: Disable Crypto Hardware

T1600.002Defense ImpairmentExtremeTechnique

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

Many network devices contain a small special chip that does encryption very fast and safely. This sub-technique describes an attacker switching that chip off. The device then encrypts with ordinary software instead, which is slower and easier to interfere with.

Why should you care?

Dedicated encryption hardware is hard for an attacker to tamper with, because keys stay inside the chip. Software running on a normal processor is much easier to reach and change. Losing the chip also slows the device, so a network can become unreliable at the same time. Attackers often pair this step with a shortened key, which makes traffic simple to read.

How it works, in plain steps

  1. The attacker first takes full administrative control of the target network device.
  2. They disable the device setting that enables its own dedicated encryption chip.
  3. The device then sends all of its encryption work to the main processor.
  4. Keys and intermediate values now sit in ordinary memory, because software handles them.
  5. The attacker can then shorten the key or alter the encrypting software itself.
  6. Encrypted throughput falls, so users may notice slowness before they notice any theft.

Real-world example

Picture a bank with a heavy vault door and a cheap wooden inner door. The vault is slow to open but very hard to break. A dishonest guard cannot pick the vault, so he simply stops using it and moves the money behind the wooden door. Customers still see a locked building and a guard on duty. Nothing looks wrong from the street. The bank is now protected by something a burglar can push through. Turning off encryption hardware does the same thing inside a network device. The traffic is still scrambled, but the strong, hard to tamper with part of the protection has been removed from the path.

Key takeaways

  • Hardware encryption is harder to tamper with than software encryption.
  • Watch for sudden slowness or high processor load on devices handling encrypted traffic.
  • Verify boot image hashes and firmware versions against your inventory.

In more detail

Disable Crypto Hardware is the sub-technique of Weaken Encryption in which the adversary turns off or bypasses the dedicated encryption processor inside a network device and forces encryption onto general purpose CPUs running software. Devices such as routers, switches, firewalls and virtual private network concentrators carry specialised chips so that bulk encryption keeps up with line rate and so that keys and intermediate values stay out of ordinary memory where they could be manipulated. Once an adversary controls the device, removing that path has two effects. Performance for encrypted traffic drops, and all cryptographic work now happens in software that the adversary can influence, typically through a modified system image or an altered configuration. It is usually paired with Reduce Key Space, because software encryption with a short key is dramatically easier to attack. Detection leans on integrity and performance evidence: boot image hashes that fail verification, configuration flags or licences for hardware acceleration that are unexpectedly off, firmware and boot loader versions that do not match inventory, throughput and CPU graphs that show general purpose processors handling encrypted traffic, and reboots outside maintenance windows. Legitimate disabling happens on purpose, such as during troubleshooting or when a card fails, and is documented with a ticket and a planned reversal; malicious disabling is silent and persists.

What you will practise

  • Explain why network devices contain dedicated encryption hardware.
  • Describe how disabling that hardware moves cryptographic work into software.
  • Recognise the performance and configuration signs of this sub-technique.
  • Explain how this behaviour makes a related key weakening step more effective.
  • Compare a documented hardware acceleration change with an unauthorised one.
  • List the device artefacts that prove which encryption path is in use.
