Instance Metadata Service Version 2

Cloud SecurityVery hardKeyword

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

Instance metadata service version 2 is a safer way for a cloud server to ask about itself. The server calls a private address to learn its own name, network details, and short-lived login keys for its assigned role. Version 2 requires the server to prove it is a real session by fetching a token first.

Why should you care?

The old version answered any request that came from the server. That meant a web form bug could trick the server into fetching its own login keys and handing them out. Those keys often open other cloud services. Version 2 blocks that trick, because a simple forged request cannot get the token first.

How it works, in plain steps

  1. A program on the server asks the metadata address, a link-local address, for a token.
  2. The service replies with a token that expires after a short time.
  3. The program then sends its real request and includes that token in a header.
  4. A request without a valid token is refused, even if it comes from the server itself.
  5. A hop limit setting controls how far requests can travel through proxies and containers.
  6. Security teams count servers still allowing the old version and upgrade them.

Real-world example

Imagine a hotel reception that hands out room keys. In the old system, anyone who phoned from inside the building and sounded like a guest got a key. In the new system, you must first collect a short-lived claim ticket in person, then show it at the desk. A prank caller cannot collect the ticket, so no key is handed over.

Key takeaways

  • Metadata holds temporary cloud credentials, so treat it as sensitive.
  • Turn on version 2 on every server and node pool you run.
  • Watch metadata requests, because unusual ones can signal a compromise.

In more detail

Instance metadata service version 2 is the session-oriented revision of the link-local endpoint that cloud instances query to obtain information about themselves, most importantly the temporary credentials associated with their attached role. The original interface answered any request arriving from the instance, which meant that a server-side request forgery flaw in an application running on that instance was sufficient to read the instance role credentials and use them from anywhere on the internet. Version two changes the exchange in two ways: the client must first issue a PUT request to obtain a limited-lifetime token that is unique to that session, and every subsequent metadata request must present that token in a header, with a configurable hop limit that additionally restricts whether requests can traverse a proxy or container network layer. Because a naive request-forgery payload cannot set custom headers or perform the required PUT, the token requirement breaks the common exploit chain, while the hop limit constrains forwarding through intermediate proxies and container namespaces. Security teams track adoption by measuring how many instances still permit the older interface, since the setting is enforced per instance and inherited at launch, and they apply it to container platforms through the node launch configuration. The topic also covers the practical migration problems: software that read metadata directly, custom agents that proxy metadata to pods, and the need to monitor metadata requests as a detection signal.

What you will practise

  • You will be able to explain how the token and hop limit requirements break credential theft through a server-side request forgery flaw.
  • You will be able to determine whether an instance or node pool still permits the legacy unauthenticated metadata interface.
  • You will be able to migrate applications and agents that read metadata directly without breaking startup.
  • You will be able to configure hop limits appropriately for proxies, containers and load balancers.
  • You will be able to use metadata access patterns as a detection signal for in-instance compromise.
