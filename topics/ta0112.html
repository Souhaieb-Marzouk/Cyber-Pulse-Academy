TA0112 Defense Impairment

TA0112EnterpriseExtremeTactic

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

Defense impairment is when an attacker attacks your security tools instead of your computers. They turn off logging, stop updates, or feed your monitoring system false information. It is the difference between sneaking past the cameras and cutting the cables.

Why should you care?

Everything you rely on to find an attack can itself be attacked. If logging stops, the evidence never exists. If an endpoint agent is switched off, nothing reports in. If the monitoring pipeline is tampered with, you may see data that looks normal but is not true. This is dangerous because it weakens every other defence at the same time, and because no alerts looks exactly the same as no attacks.

How it works, in plain steps

  1. Work out which security tools are running and where they send their data, so the attacker knows what to target.
  2. Stop those tools from running, for example by disabling an endpoint agent or halting a log collector service.
  3. Change the tool settings so it keeps running but quietly stops recording the events that matter.
  4. Tamper with the pipeline itself, so reports are delayed, dropped or altered before an analyst ever sees them.
  5. Hide or reverse the change afterwards, so that a routine health check does not reveal what was switched off.

Real-world example

A shop owner installs cameras, a burglar alarm and a safe. A clever thief does not try to beat all three. They cut the power to the cameras and unplug the alarm first, then work calmly. The owner later finds an empty safe and no footage at all. The thief never had to defeat the cameras, only to stop them working. Security tools are useful only while they are running and telling the truth.

Key takeaways

  • Protecting your security tools is part of security, not a separate job.
  • No alerts is not the same as no incidents. Check that monitoring is still alive.
  • Catching this tactic often means watching your own tools, not watching the attacker.

In more detail

Defense Impairment is the ATT&CK tactic covering attempts to break, disable or corrupt the security mechanisms a defender depends on. Where the older Defense Evasion framing described an adversary slipping past controls, this tactic describes an adversary attacking the controls themselves: stopping log collection, disabling endpoint protection, degrading the detection pipeline, or manipulating what that pipeline reports so that defenders cannot see or trust the picture in front of them. It is a small tactic in terms of technique count and a disproportionately important one, because a successful attack here weakens every other defensive measure at the same time. The defining property for detection is that the evidence of the attack is an absence or a distortion rather than an obvious event: a host that stops sending logs, an agent that stops reporting, a service that silently stops running. Teams that monitor the health of their own telemetry, and that alert on the disappearance of data rather than only on suspicious data, are the ones that catch it.

What you will practise

  • Explain why disabling or corrupting telemetry is more dangerous than evading a single control.
  • Monitor the health of your own logging and detection pipeline, and alert on the disappearance of data.
  • Detect tampering with endpoint protection, audit policy and log forwarding as a first-class event.
  • Design collection so that a single disabled sensor degrades your visibility rather than removing it entirely.
