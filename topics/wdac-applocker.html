WDAC and AppLocker

Endpoint & MalwareVery hardKeyword

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

WDAC stands for Windows Defender Application Control, and AppLocker is a related Windows feature. Both decide which programs are allowed to run, an approach called application control or allow-listing. Instead of blocking known bad software, they permit only approved software and refuse everything else. WDAC enforces its rules deeper in the system than AppLocker does.

Why should you care?

Blocking known bad files only works until something new appears. Allowing only approved software flips the problem, because unknown programs simply cannot start. That stops a lot of malware, including scripts and borrowed system tools. The hard part is not the technology but the upkeep. You need an accurate list of what people really use, or the policy will break their work and get switched off.

How it works, in plain steps

  1. You first take an inventory of the software that people and servers genuinely need.
  2. You write rules that allow those programs, using publisher, path, or file fingerprint.
  3. You run the policy in audit mode, which records what would have been blocked.
  4. You review those records, add missing rules, and repeat until the list is stable.
  5. You switch to enforcement mode, so unapproved programs can no longer start.
  6. You keep a change process, because new software will always need approval later.

Real-world example

Imagine a members-only club with a guest list at the door. The bouncer does not try to recognise every troublemaker in the city. He only checks whether your name is on the list, and if it is not, you stay outside. That is much easier than memorising faces. But the list must stay current, or loyal members get refused and the door staff start waving everyone through.

Key takeaways

  • Application control allows only approved software and refuses everything else.
  • Run in audit mode first, and gather a real software inventory before enforcing.
  • Prefer publisher rules over file paths, which are easy to abuse and hard to maintain.

In more detail

Windows Defender Application Control and AppLocker are the two application control mechanisms Microsoft provides for Windows, and understanding their difference matters more than knowing either in isolation. AppLocker is policy-based, configured through Group Policy or a similar management channel, and enforces rules that permit or deny executables, installers, scripts, packaged applications and dynamically loaded libraries on the basis of publisher signature, file path or file hash. It is straightforward to operate, easy to audit in a reporting-only mode before enforcement, and widely used because it can be piloted on a subset of users without touching the underlying platform configuration. WDAC operates at a lower level and expresses policy as a signed binary policy that the kernel enforces, which makes it substantially harder for a local administrator or a malicious process with administrative rights to disable, and it can be used to protect the integrity of the code that is allowed to run at boot and in the kernel. In practice the two are complementary and both are frequently deployed together, because WDAC's strength is its resistance to tampering while AppLocker's strength is granular, easily reasoned-about rules for user-facing applications. The hardest part of either deployment is not the technology but the operational discipline: maintaining accurate inventory of what legitimately runs, designing publisher-based rules rather than brittle path rules, adopting managed installer concepts so that approved deployment tooling can introduce new software without policy churn, running in audit mode long enough to catch the long tail, and planning a change process for the inevitable application that must be allowed next week. A policy that is too permissive provides no protection; one that is too brittle is bypassed by an exception list nobody reviews.

What you will practise

  • Compare WDAC and AppLocker across enforcement location, tamper resistance, rule granularity and management model.
  • Choose between publisher, path and hash rule types and explain the maintainability consequences of each.
  • Design an audit-then-enforce rollout that gathers the legitimate software inventory before blocking anything.
  • Explain how managed installer and signed policy concepts reduce operational churn after enforcement.
  • Detect attempted policy tampering or the abuse of allowed binaries to execute unapproved code.
  • Plan an exception and change process that keeps the policy tight without blocking business operations.
