DET0025 Detecting Electron Application Abuse for Proxy Execution

DET0025Detection StrategyVery hardDetection Strategy

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

Electron is a toolkit used to build desktop applications with web technology. Many chat and meeting apps use it. This detection looks for those apps starting in strange ways. It catches an attacker using a trusted app to launch their own code.

Why should you care?

These applications are signed and expected on most laptops, so security tools trust them. If an attacker can make one start with the right option, their code runs under that trust. The behaviour is a normal parent starting a strange child, which is easy to overlook. Your allow list becomes the attacker's cover. Detecting the pattern lets you keep the application while still catching the abuse.

How it works, in plain steps

  1. The sensor records each process start together with the parent process name and both command lines.
  2. The rule matches a known Electron application binary being launched with option flags used for debugging or content loading.
  3. It also checks whether those options point at a path outside the application's own installation directory.
  4. It then looks for a child process started by that application. Examples are a shell, a script host or a temporary file.
  5. The parent and child facts are linked by process identifier. The whole chain is one event, not two unrelated ones.
  6. The alert shows the signed parent, the suspicious switches and the child binary. The analyst sees the full chain.

Real-world example

Picture an office where the CEO's assistant can sign for deliveries. A stranger asks the assistant to sign for a package, and the courier accepts it without question. The signature is real but the parcel is not. Electron proxy execution detection is the note that says the trusted assistant signed for something nobody ordered.

Key takeaways

  • Application control allow lists do not help when the trusted app does the launching.
  • Watch for debugging switches and for children that live outside the app directory.
  • The whole story is the parent, its options and the child it starts.

In more detail

This strategy detects abuse of Electron based applications for proxy execution, mapped to ATT&CK technique T1218.015, where an adversary makes a trusted desktop application start with unusual command line options or load a modified resource so that it runs attacker code under a signed, familiar process name. Electron applications are commonly allowed through application control and often carry update or inspection features that can load local content, which is exactly what makes them attractive as a launch pad. Useful telemetry is process creation showing a signed Electron binary started with debugging, remote debugging or inspection switches, or pointing at content outside its own installation directory, plus child process creation where the Electron parent spawns a shell, a script interpreter or a binary in a temporary directory. The correlation of parent image, parent command line and the child process is what makes the alert meaningful. The strategy fails frequently because desktop applications spawn helper processes constantly, so the rule must key on the switches and the child path rather than on the parent process name.

What you will practise

  • Explain why signed desktop applications are attractive for proxy execution
  • Identify command line switches on Electron applications that indicate debugging or local content loading
  • Correlate a parent application process with the child process it starts
  • Judge child process paths against the application installation directory
  • Describe how to keep coverage without blocking normal application helper processes
