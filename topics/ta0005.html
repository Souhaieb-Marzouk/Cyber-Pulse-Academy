TA0005 Defense Evasion

TA0005EnterpriseExtremeTactic

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

Defense evasion is everything an attacker does to stay unseen, unheard and unstopped. Unlike other steps, it is defined by the goal rather than one technique. It includes turning off security tools, deleting logs, hiding files and disguising malicious programs as normal ones.

Why should you care?

Your alarms only help if they keep working. If an attacker silences them, every later step becomes invisible. The tricky part is that the evidence you need is often the evidence they destroyed. So you learn to notice silence itself. A laptop that stops reporting, or a security setting that quietly changed, is a warning sign.

How it works, in plain steps

  1. The attacker learns which security tools and logging are running on the machine they reached.
  2. They try to disable, uninstall or weaken those tools, or change their settings.
  3. They hide their activity by renaming files, clearing logs or blending into normal system paths.
  4. They may make their code look like a trusted signed program so it is allowed to run.
  5. Defenders fight back with copies of logs sent far away, where the attacker cannot reach them.

Real-world example

Imagine a museum with security cameras. A thief does not only take the painting. They also switch off the cameras in that room and erase the recording. Guards watching the screens see nothing wrong, because there is nothing to see. The theft is discovered only when someone walks past an empty frame. A good museum therefore sends recordings to a separate building the thief cannot enter. That is how you protect your logs.

Key takeaways

  • Defense evasion is about hiding quietly, not about breaking in loudly.
  • Send your logs somewhere the attacker can never reach or delete them.
  • Missing data is a signal, so investigate silence, not just alerts.

In more detail

Defense Evasion is the tactic that groups everything an adversary does to avoid being seen, analysed, or stopped, and unlike most other tactics it is defined by intent rather than by a single technical primitive. Behaviours include disabling or tampering with security tools and logging, clearing or editing event records, obfuscating scripts and payloads, masquerading files by renaming or matching legitimate system paths, abusing signed binaries to proxy execution, uninstalling or suppressing agents, using alternate data streams, rootkits and bootkit techniques, and, increasingly, manipulating cloud audit settings or identity controls so that activity is never recorded. Defenders face a structural problem here: the telemetry that would prove evasion is often the telemetry the adversary is trying to remove. Detection therefore leans on independent evidence sources that are hard to reach, such as remote log shipping to a collector the endpoint cannot modify, EDR heartbeats and tamper protection events, agent health monitoring, service and driver load records, and configuration drift checks against a known baseline. Because much of this tactic consists of removing or weakening controls, absence of expected data is itself the signal: a host that stops reporting, a sensor whose configuration changed outside change control, or an audit policy quietly reverted. Analysts must treat these gaps as findings rather than as noise, and must be able to reconstruct what happened from the residual artifacts and the surrounding timeline.

What you will practise

  • Describe the main defense evasion behaviours and explain why the tactic is defined by intent rather than by a specific technique.
  • Design independent telemetry paths, such as remote log shipping and agent health monitoring, that survive local tampering.
  • Treat missing data, stopped agents, and reverted security configuration as high-priority detections rather than gaps to ignore.
  • Recognise obfuscation and masquerading patterns in process, file, and command line data without over-relying on signatures.
  • Investigate tampering with audit policy, log retention, or cloud control-plane logging and reconstruct the surrounding timeline.
  • Assess which evasion techniques would defeat the current tooling and propose concrete compensating controls.
