TA0005 Stealth

TA0005EnterpriseExtremeTactic

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

Stealth is all the ways an attacker tries to look normal. They do not smash a window. They copy a key and walk in like an employee. They avoid strange new programs and use the tools that are already on the computer. The aim is simple: nobody should notice anything unusual.

Why should you care?

Most attacks are caught because something looked out of place. A strange program ran, a login came from a new country, or a file changed at three in the morning. If an attacker can make their actions look like ordinary daily work, those warnings never appear. A quiet day is not proof that you are safe. It may only mean you cannot see what is happening.

How it works, in plain steps

  1. Study what normal looks like first. The attacker learns which tools, logins and network connections happen every day in this company.
  2. Use those same everyday tools instead of bringing new ones, because existing software rarely looks suspicious.
  3. Disguise the activity so it matches the normal pattern, for example by giving a harmful file a boring, ordinary name.
  4. Reduce the traces that get recorded, so fewer warnings are created in the first place.
  5. Move slowly over days or weeks instead of acting fast, because quiet activity spread over time is much harder to notice.

Real-world example

Think about a busy office building. A stranger in a suit carrying a laptop looks normal, so nobody stops them at the door. Someone wearing a mask would be stopped in seconds. The person in the suit might even hold a fake staff badge. Security guards look for people who stand out, so standing out is the thing to avoid. Attackers work exactly the same way: the quiet approach usually wins.

Key takeaways

  • Stealth is about intent. It means not being noticed, not using one particular tool.
  • A quiet system is not automatically a safe system. It may simply be invisible to you.
  • Catching stealth means knowing normal well enough to notice small differences.

In more detail

Stealth is the ATT&CK tactic that groups the behaviours an adversary uses to keep their activity looking ordinary. It replaces what earlier versions of ATT&CK called Defense Evasion, and the rename matters: the tactic is defined by the goal of not being noticed rather than by a fixed list of tricks. An adversary working in this tactic avoids introducing new artefacts, prefers tooling that already exists on the host, blends into legitimate administrative patterns, and accepts a slower pace in exchange for a smaller footprint. From a defender's perspective this is the hardest tactic to detect, because the whole point is that the telemetry looks unremarkable. Detection therefore depends less on spotting something unusual and more on strong baselining: knowing which processes, parent processes, logon patterns, destinations and working hours are genuinely normal for each host and each user, and then treating small deviations from that baseline as signal rather than noise.

What you will practise

  • Explain why this tactic is defined by the adversary's intent to remain unnoticed rather than by a fixed set of techniques.
  • Build a baseline of normal process, logon and network behaviour for a host so that deviations become visible.
  • Distinguish genuinely quiet activity from activity that is invisible because telemetry has been weakened.
  • Recognise the limits of signature-based detection against an adversary whose whole method is to look ordinary.
