DET0421 Detection Strategy for System Services Service Execution

DET0421Detection StrategyVery hardDetection Strategy

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

A Windows service is a program that runs in the background, often with high rights and before anyone signs in. An attacker can create a service that points at their own program. This detection looks for new or changed services, especially ones whose program sits in a strange folder. It watches the setup record and the program that made the change.

Why should you care?

Services run with the highest rights on the computer. They can also survive a restart, which gives an attacker lasting access. Creating a service is a normal administration task, so it raises no alarm by itself. Attackers can create one on a remote computer to move sideways. Matching the service program to the person who made it is what exposes the abuse.

How it works, in plain steps

  1. Windows writes a record when a new service is installed. It holds the service name, the program path and the account.
  2. The system log also records when a service is started, stopped or changed.
  3. The rule takes those records and reads the program path and the account from each one.
  4. It compares the path with the normal places where installed software lives.
  5. It looks at what started the change, because an installer and a remote shell are very different parents.
  6. A service that points to a temporary folder and was made by a shell raises the alert.

Real-world example

Think of a building where the maintenance crew has a master key and works at night without signing in. A new worker is added to the crew list and given a key. Nobody questions a crew member entering at night. The clerk only notices because a person who is not a supervisor added the name.

Key takeaways

  • A new service is a normal event, so judge the program path, the account and the parent process.
  • Services are a favourite way to keep access after a restart.
  • Look outside the usual program folders for service binaries.

In more detail

This strategy covers service execution through the Windows service control manager, tracked as T1569.002, where an adversary creates or starts a service so that the service host runs their code with high privilege and often with persistence. It matters because service creation is a documented, supported administrative action that grants system level execution, and because remote service creation was a classic lateral movement step in well known intrusions. The telemetry that makes detection possible is service installation records, system log service state changes, process creation where the parent is the service host, and registry writes under the service control manager keys. The main way it fails is that software installation creates services constantly, so the rule must look at the binary path, the account the service runs as, the parent process that triggered the installation and whether the image lives outside the program directories.

What you will practise

  • Explain what a Windows service is and why service execution is valuable to an adversary.
  • Identify the event that records service installation and the fields it provides.
  • Read the service binary path and account and compare them with normal install locations.
  • Correlate a service installation with the process and session that requested it.
  • Recognise remote service creation as a lateral movement step.
  • Describe how to respond to a suspicious service without breaking the host.
