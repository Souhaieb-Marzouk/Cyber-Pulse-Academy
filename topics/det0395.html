DET0395 macOS AuthorizationExecuteWithPrivileges Elevation Prompt Detection

DET0395Detection StrategyVery hardDetection Strategy

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

This detection watches for programs on a Mac that ask the system for administrator rights. It uses an old service that is now deprecated. It catches the privilege request and the helper tool that runs after it. The alert means a process asked for a password prompt instead of running as a normal user.

Why should you care?

Administrator rights let a program change almost anything on the computer. When an attacker has a normal account, asking the system for rights is the shortest path to full control. The system shows a password prompt, so a careless click is enough. Because the request itself is recorded, you can still see what happened even when the user clicked yes. Without this detection, privilege escalation on Macs often leaves no useful trace.

How it works, in plain steps

  1. The Mac writes authorization events to the unified log, including the path of the program that asked for rights.
  2. A log collector forwards those records to your security monitoring platform, where it stores the time and host name.
  3. The rule looks for a helper tool launched through the deprecated security authorization service.
  4. It then correlates the request with a process creation event that shows a child process running as the root user.
  5. The rule drops known software management and installer paths that legitimately prompt every day.
  6. What remains becomes an alert for an analyst to review against the change record.

Real-world example

Think of a hotel front desk. A guest can only open their own room with their key card. If the guest wants the master key, they must ask the front desk and sign for it. This detection is the sign-in sheet that records every request for the master key. It also notes which staff member walked to the room afterward with that key.

Key takeaways

  • Privilege requests on macOS are recorded even when the user approves them, so they are worth collecting.
  • Any unexpected program asking for administrator rights deserves a look at the tool it launches.
  • Software management agents cause the same prompts, so a filter list is essential.

In more detail

This detection strategy covers the deprecated macOS authorization service path that lets a program ask the operating system to run a helper tool with administrator rights, which maps to abuse of the elevation control mechanism technique for macOS. It matters because a single approval click by the user turns a normal process into a privileged one, so the only durable evidence is the authorization request itself plus the child process that follows it. The telemetry that makes this possible is the macOS unified log authorization subsystem records, Endpoint Security framework process execution events, and the parent and child relationship between the requesting bundle and the tool it launches. In practice it fails in two ways: the log records the prompt but not always the signed identity of the caller, and noisy software management agents trigger identical prompts during routine patching, so analysts drown in expected approvals.

What you will practise

  • Explain why an authorization request is useful evidence even when the user approves the prompt.
  • Identify the macOS log sources that record privilege requests and helper tool launches.
  • Correlate an authorization event with the privileged child process it produced.
  • Build a filter list of approved software management tools that prompt for rights.
  • Describe the limits of this detection when log collection is partial or delayed.
