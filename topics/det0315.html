DET0315 Detect Persistence via Office Test Registry DLL Injection

DET0315Detection StrategyVery hardDetection Strategy

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

Microsoft Office can load an extra library file when it starts. The name of that file sits in a registry key used for testing. A registry is a settings database on Windows. An attacker can put their own file name there so Office loads it every time.

Why should you care?

Persistence means access survives a restart. Because Office loads the file automatically, the attacker does not need to run anything again. The setting applies to all users on the computer, so one change affects everyone. Few teams watch this key, which makes quiet abuse more likely.

How it works, in plain steps

  1. Office reads a machine registry value during startup to find out whether a test library is configured.
  2. If a file name is present, Office loads that library into its own process.
  3. The endpoint agent records the registry change, including the value data and the process that wrote it.
  4. It also records library load events, which show the full path of every loaded file.
  5. The rule looks for a write to the Office test key whose value points outside the normal Office program folder.
  6. It then confirms that the same file appears in a library load event from an Office program, and alerts.

Real-world example

Think of a workshop with a note on the wall. The note tells the morning team to warm up a machine before work starts. A stranger rewrites the note to name a machine of their own. Every morning the team dutifully starts it. Nobody broke in, because the wall note was edited during the day.

Key takeaways

  • The Office test key loads a library for every Office start and every user.
  • Registry writes plus library load events together prove the technique.
  • Value data outside the Office program folder is the strongest sign of abuse.

In more detail

This strategy detects persistence registered through the Office test registry key, the technique recorded in the assignment as t1137-002, in which a value under the Office test path names a library that Microsoft Office loads whenever any Office application starts. The value sits in the machine configuration store, so it applies to every user on the host and re-arms itself each time Word, Excel or Outlook opens, which makes it durable and quiet. Detection rests on registry value modification for that key path joined to image load events for the named library, so the rule can confirm the library was actually loaded rather than merely written. The main failure mode is that the key is obscure enough that many teams never baseline it, so a single unremarkable registry event is the only visible trace.
