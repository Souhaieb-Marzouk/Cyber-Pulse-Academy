T1588.001 Obtain Capabilities: Malware

T1588.001Resource DevelopmentExtremeTechnique

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

Malware is software written to harm or take control of a computer. This technique is about attackers getting that software from someone else. They may buy it, download it, or steal it from another attacker.

Why should you care?

A person with almost no coding skill can rent a full attack toolkit online. That means more attacks, and many of them use the same well-known code. Knowing the common families helps you spot them, but the attackers change the files often to avoid detection.

How it works, in plain steps

  1. The attacker chooses what the malware must do, such as steal files or hold a connection open.
  2. They rent or buy a ready made kit from a criminal seller, sometimes with support included.
  3. They configure the rented kit with their own server address and other settings.
  4. They deliver it to the victim through a malicious email attachment, a link, or an infected download.
  5. The malware runs, hides itself, and contacts the attacker's server for orders.
  6. It leaves traces such as new files, scheduled tasks, and regular network connections.

Real-world example

Think of a shared flat kitchen where nobody wants to cook. One person orders a ready meal from a delivery app and heats it up. Another copies a neighbour's recipe card. The meal appears on the table either way, but only the person who cooked from scratch truly understands the ingredients and could change them.

Key takeaways

  • Rented malware means the attacker may not understand the code at all.
  • File hashes change often, so detect behaviour instead of names.
  • New executables in user folders with regular outbound traffic deserve a close look.

In more detail

This sub-technique describes acquiring malicious software rather than writing it, covering the full range of payloads, droppers, packers, backdoors, and command and control protocols. The distinguishing feature of this era is service provision: malware is sold as a product, sometimes under subscription terms, with a customer portal, updates, and technical support. That lowers the skill floor considerably, because the buyer never has to understand the code they deploy. Common purchase routes are criminal marketplaces and individual developers; free routes are public repositories and leaked builder kits. Stealing malware from another group also happens, and stolen code often carries recognisable artefacts such as reused strings, distinctive encryption routines, or the same hardcoded configuration format. On a victim host the traces are behavioural first and file based second: a new executable or dynamic library in a user writable directory, run keys, scheduled tasks, or services created for persistence, unusual child processes, and regular beaconing to a small set of destinations. Commodity malware is distinguishable from genuine software largely by context, including unsigned or mismatched signer information, installation outside managed software paths, and short-lived processes that delete their own files. Endpoint telemetry from Sysmon 1 process creation, Windows Security 4688, and network flow records is where that picture forms. Because builders are rented and updated, defenders should expect file hashes to change constantly and should anchor detection on behaviour.

What you will practise

  • Explain how malware is bought, downloaded, and stolen, and how a rented kit lowers attacker skill.
  • Describe what malware traces it leaves on a host and in network records.
  • Distinguish commodity malware behaviour from normal installed software behaviour.
  • Name the endpoint and network telemetry that supports malware detection.
  • Explain why hash based detection alone fails against rented malware.
