DNS Tunnelling

Network SecurityExtremeKeyword

DNS tunnelling is a technique for carrying arbitrary data inside DNS queries and responses, exploiting the fact that name resolution is permitted almost everywhere, including networks where most other outbound traffic is blocked. An adversary who controls an authoritative name server can encode payload in the leftmost labels of a query, for example a long high-entropy subdomain, and receive data back through the response, producing a bidirectional covert channel without ever opening a direct connection to an external host. The same mechanism supports exfiltration, with stolen data chunked across successive queries, and it can carry a command channel, which is why defenders usually treat it as DNS-based command and control or exfiltration over DNS rather than as a standalone intrusion technique. Detection rests on behaviour rather than payload, because the queries themselves are well formed. Useful signals include sustained query volume to a single domain, unusually long or random-looking labels, high randomness in subdomain strings, unusual record types, elevated rates of non-existent domain responses, and low-and-slow patterns designed to stay under rate thresholds. Tuning is difficult because legitimate services share some of those characteristics: content delivery networks, endpoint telemetry agents and software update mechanisms all generate high query volume to a small set of names, and security products themselves use DNS for reputation lookups. Effective detection therefore combines several weak signals, baselines per host and per domain, and enrichment with reputation, registration age and resolution history rather than relying on any single rule. Mitigation is layered: restrict recursive resolvers to internal clients, block direct outbound DNS from endpoints, log and retain query data centrally, monitor authoritative servers for the organisation's own domains, and use response policy zones to block known malicious names.

What you will practise

  • You will be able to explain how data is encoded into DNS queries and responses and why the channel bypasses egress filtering.
  • You will be able to build detection queries using label length, entropy, volume and response-code patterns.
  • You will be able to baseline legitimate high-volume DNS consumers and reduce false positives.
  • You will be able to distinguish exfiltration over DNS from beaconing and from ordinary resolution failures.
  • You will be able to design resolver, egress and response policy controls that constrain tunnelling without breaking resolution.
  • You will be able to assess why a hard block of DNS is rarely acceptable and what compensating controls apply.
