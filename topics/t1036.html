T1036 Masquerading

T1036StealthExtremeTechnique

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

Masquerading means making something harmful look like something normal. Attackers change names, folders or file details so that you trust the file or process. This technique belongs to the defense evasion tactic, which covers avoiding detection. The harmful content itself does not change, only how it appears. A familiar name in the wrong place is the clue.

Why should you care?

People and tools both trust names, so a trusted looking name can pass a check that only reads labels. Windows hides known file extensions by default, so a harmful program can appear to be a document. A process can copy the name of a real system tool and look normal in a task list. If your rules allow or ignore certain names, attackers will use those names. You must confirm identity, not just recognise a name.

How it works, in plain steps

  1. The attacker renames a harmful file to match a trusted program, such as a common system utility.
  2. They may move it into a system folder so its location looks correct as well.
  3. They give a document a double extension, such as a document name ending in both .pdf and .exe.
  4. They copy an icon, a description and version text from real software so file details look right.
  5. They register a service or scheduled task under a name that sounds like a normal component.
  6. Nothing about the harmful file changes, only the way it presents itself to users and tools.

Real-world example

Picture a person in a courier uniform walking into a shared office building. Staff see the uniform and open the door, because couriers come and go all day. The visitor never shows an identity badge, and the uniform was bought online. The clothes were the whole trick. To catch this, the receptionist would need to check the badge and call the courier company. Trusting the colours alone is not enough.

Key takeaways

  • Check where a file really lives and what it really is, not only the name shown to you.
  • Watch for double extensions and for known tool names running from temporary or user folders.
  • Compare a process with its on-disk file and its signature before you trust the name.

In more detail

Masquerading is the manipulation of an artefact's name, path or metadata so that it is mistaken for something legitimate, whether by a person, an automated control or an analyst reviewing evidence. The abuse usually targets the gap between what a file claims to be and what it does. A tool is renamed to a trusted system utility name, or dropped into a system directory to borrow that directory's reputation, an executable is given a double extension so that the hidden type is what actually runs, version information and icons are copied from known software so that file properties look convincing, and a malicious service or scheduled task is registered under a name that resembles a legitimate component. Because the disguise is about presentation, the file's own content and behaviour may be unchanged and perfectly detectable if examined. Detection therefore depends on verifying identity rather than trusting labels: compare the recorded path against where the genuine binary lives, check digital signatures and their validity plus the embedded version data, look for mismatched extension pairs and unexpected executables in user or system directories, review process names against their on-disk image path, and treat a familiar name found in an unusual location as the anomaly. Legitimate software also stores odd names and runs from temporary folders during updates, so the strongest verdicts combine an inconsistency in name, path or signature with behaviour that the assumed identity would never produce.

What you will practise

  • Explain how renaming or repositioning an artefact makes it appear legitimate to users and tools.
  • Describe common forms, including double extensions, fake metadata, trusted directory placement and lookalike service names.
  • Explain why Windows hiding known file extensions makes the technique more effective.
  • Identify the artefacts, such as path and signature mismatches, that expose a disguised file or process.
  • Distinguish masquerading from legitimate software that uses similar names or unusual locations.
