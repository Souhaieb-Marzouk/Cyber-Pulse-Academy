T1098.005 Account Manipulation: Device Registration

T1098.005PersistenceExtremeTechnique

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

This is a sub-technique of account manipulation. It means an attacker adds their own phone or computer to a company account as a trusted device. Multifactor authentication is a second check, such as a code sent to a phone, used after your password. A device added by the attacker can pass that check or satisfy rules that only allow registered computers.

Why should you care?

It turns a stolen password into lasting access, even after the password is changed. The attacker's device looks approved, so access rules open for it. Many organisations review passwords but never review which devices are enrolled, so this stays invisible for a long time.

How it works, in plain steps

  1. The attacker gets a valid username and password, often from a phishing page.
  2. They sign in and start enrolling their own phone in the multifactor service.
  3. Some services only need the password for the first device, so the check is easy to pass.
  4. Alternatively they register a machine into the directory so it counts as managed and compliant.
  5. Access rules that demand a managed device now allow the attacker through.
  6. Multiple registrations at once can also flood the tenant and use up its resources.

Real-world example

Imagine an office that only lets in staff with a company badge. A visitor finds a working password and then prints their own badge at the lobby machine. The door system sees a valid badge and opens every time. The staff records still show a real employee, and the visitor walks in beside them.

Key takeaways

  • Review which devices and authenticators are enrolled for each user, not just their password.
  • Treat a new enrollment from a strange place or time as a possible account takeover.
  • Require an existing trusted method to approve any new device enrollment.

In more detail

This sub-technique of account manipulation covers enrolling a new device into a system that either proves identity or enforces device policy, so the adversary gains access that survives a password reset. In multifactor authentication services, which are the platforms that ask for a second proof of identity, an attacker holding a valid username and password can simply enroll their own phone or token. Some enrollment flows only require the account password for the first device, or accept an enrollment onto an inactive account, which makes this straightforward. In directory and device management systems the attacker registers a machine or virtual machine so it appears compliant and trusted, which can satisfy conditional access rules that require a managed device and allow access to mail and files from an unmanaged system. A registered device can also send messages that look internal, and bulk registration can consume tenant resources. Detection looks at enrollment and registration events: new authenticators added for a user with no helpdesk history, registrations from an unusual address or outside working hours, devices that never appear in inventory, and bursts of registrations that no rollout explains.

What you will practise

  • Explain how this sub-technique differs from the parent account manipulation technique.
  • Describe how a new authenticator or registered device can bypass multifactor checks.
  • Identify the enrollment and registration events that reveal this activity.
  • Distinguish a sanctioned device rollout from adversary enrollment.
  • Explain how device registration interacts with conditional access policy.
