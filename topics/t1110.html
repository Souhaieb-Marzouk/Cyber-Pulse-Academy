T1110 Brute Force

T1110Credential AccessExtremeTechnique

Brute force is a credential access technique in which an adversary makes repeated authentication attempts, systematically varying one or more credential components, until a logon succeeds. The mechanism is simple: the attacker obtains a valid account identifier, then submits candidate secrets such as passwords from a word list, mutated variations, default vendor credentials, PINs or short numeric codes against whichever authentication interface is reachable, including VPN gateways, webmail portals, SSH, remote desktop services, database listeners and application programming interfaces. Modern variants avoid hammering a single account. Password spraying submits one weak candidate across many accounts to stay below per-account lockout thresholds, while credential stuffing replays username and password pairs harvested from unrelated breaches, betting on password reuse. The technique appears on every platform: Windows domain services such as Kerberos and NTLM, Linux and Unix authentication stacks reachable over SSH, network device management planes, cloud identity providers and consumer facing applications. The telemetry that matters most is authentication logging. On Windows this means records of failed and successful logons, account lockouts and Kerberos pre-authentication failures; on Linux it means authentication daemon, sudo and pluggable authentication module messages; identity providers expose sign-in logs with failure reason, source address, client application and risk score, and VPN concentrators record the source address and assigned session. Investigators distinguish brute force from ordinary user error by looking at volume and shape: many failures against few accounts from few sources, or few failures against many accounts from distributed sources, unusually uniform request timing, impossible travel between successes, and a success that immediately follows a burst of failures. Benign causes include stale saved credentials on a mobile client, a service account whose password was rotated without updating configuration, and an automation script that never received the new secret, so a finding usually needs corroboration before it is treated as malicious.

What you will practise

  • Explain how brute force, password spraying and credential stuffing differ in request volume, account targeting and detection signature.
  • Identify the authentication telemetry sources that record guessing attempts across Windows, Linux, network devices and cloud identity providers.
  • Write SIEM-style queries that surface distributed low-volume spraying which per-account lockout thresholds never trigger.
  • Distinguish malicious guessing from stale saved credentials, misconfigured service accounts and password rotation drift.
  • Prioritise authentication alerts by exposure, separating internet facing services from internal systems behind segmentation.
  • Recommend mitigations that combine multi-factor authentication, throttling, lockout policy, credential screening and monitoring of successful logons after failure bursts.
