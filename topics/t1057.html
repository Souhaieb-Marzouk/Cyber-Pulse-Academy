T1057 Process Discovery

T1057DiscoveryExtremeTechnique

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

Process discovery simply means listing the programs that are running on a computer. A process is one running program, and every operating system can show you a list of them. Attackers do this to learn what is on a machine, such as security tools or important applications. It is exactly the same thing an administrator does when checking why a computer is slow.

Why should you care?

Before acting, an attacker wants to know what is watching and what is valuable. A process list answers both questions quickly and quietly. The commands used are completely ordinary, so blocking them would break normal administration. This makes process discovery hard to detect and easy to overlook. Understanding it helps you notice the moment when quiet reconnaissance turns into real action.

How it works, in plain steps

  1. The operating system keeps a record of every running program and its details.
  2. Simple built in commands can print that list inside a terminal window.
  3. On Windows, an attacker may use the task list command or a PowerShell process command.
  4. On Linux and macOS, the process status command or the proc filesystem gives the same view.
  5. Programs can also call system functions that return a snapshot of all running processes.
  6. The attacker reads the output to find security tools, backups and other valuable software.

Real-world example

Picture that same hospital night desk again, late on a quiet evening. Before deciding anything, a stranger walks the corridors reading the room signs and the duty board. He learns where the pharmacy is, when the night nurse takes her break, and which rooms have cameras watching them. He touches nothing and speaks to nobody, so no alarm ever sounds. The walk is exactly what any visitor might do. Only later, when something happens, does anyone think about who was reading the board.

Key takeaways

  • Listing running programs is normal administration, so the command alone proves nothing.
  • Context such as who ran it, from where and what happened next is the real signal.
  • Attackers use this step to choose targets and to avoid security tools.

In more detail

Process discovery is the enumeration of running processes to learn what software, agents and services exist on a host. Attackers use it early to judge whether a target is worth infecting, to identify security tooling that must be avoided, and to choose follow on actions during automated discovery. On Windows the information comes from command line utilities such as the task list tool, from PowerShell process cmdlets, or directly from native calls that snapshot the process list; on Linux and macOS the process status command and the proc filesystem serve the same purpose, and hypervisor platforms expose their own process listing commands. Network devices offer comparable commands through their command line interfaces. The behaviour is nearly indistinguishable from routine administration, so detection leans on context rather than a single command name: the parent process that launched the enumeration, the account used, whether elevated rights were needed, the timing relative to other suspicious activity, and whether one host issues a rapid burst of discovery commands in sequence. Correlating process creation records, command line arguments and the executing user is far more useful than matching a command string.

  • Identify the contextual factors that make process enumeration suspicious.
