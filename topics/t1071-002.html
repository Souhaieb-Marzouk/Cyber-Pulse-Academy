T1071.002 Application Layer Protocol: File Transfer Protocols

T1071.002Command and ControlExtremeTechnique

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

This is when an attacker sends commands and receives results using file transfer protocols. These are the standard rules computers use to copy files. The traffic looks like normal file copying, so it is harder to notice.

Why should you care?

Many networks block strange traffic but allow file transfers. That traffic is often large and frequent, so it is easy to hide in. If you only watch for unusual ports or unusual protocol names, you will miss a channel that uses the protocols you already allow.

How it works, in plain steps

  1. The attacker sets up a server somewhere that will hold files for their malware to collect.
  2. Malware on your network opens a standard file transfer session to that server, which may be inside your own network.
  3. The attacker hides commands inside the transferred file or inside unused fields of the protocol messages.
  4. The malware reads the file, carries out the instruction, and writes the result into another transferred file.
  5. Because the protocol is normal and used all day, the traffic does not stand out by port or by name alone.
  6. The same channel is also used to move stolen data out, which makes the sizes and the timing worth watching.

Real-world example

Think of a courier company that delivers parcels all day. Someone starts sending parcels with secret notes hidden inside the wrapping. The vans, the labels, and the routes all look normal to the gate staff. Only the pattern of deliveries, such as many parcels to one unusual address, gives it away.

Key takeaways

  • A legitimate protocol used in the wrong place is still suspicious, so check who talks to whom.
  • Look at transfer size, direction, and timing rather than only at protocol names.
  • Internal file transfers between workstations are unusual and deserve investigation.

In more detail

File transfer protocols are an attractive command channel because they are already trusted, already permitted, and already noisy. The parent technique covers the use of ordinary application layer protocols to blend command and control with legitimate traffic; this sub-technique narrows that to the protocols built for moving files, such as Server Message Block (SMB), File Transfer Protocol (FTP), its encrypted form FTPS, and Trivial File Transfer Protocol (TFTP). An implant can place its instructions inside the transferred file itself, inside unused or optional protocol fields, or inside a file name or path, and it can read the result from a file the server offers back, so the exchange may look like nothing more than a routine transfer of a document or an update. Defenders rarely gain from inspecting protocol headers alone, because the traffic is well formed. The useful signals are behavioural: a workstation offering files to another workstation, outbound FTP or TFTP sessions to addresses that are not approved file servers, large or oddly timed transfers involving a host that normally only browses file shares, repeated small transfers in both directions at a regular rhythm, and network telemetry or proxy logs that pair an internal source with an external destination outside any known file transfer service.

What you will practise

  • Explain how the file transfer protocols relate to the broader application layer protocol technique.

  • Identify network telemetry that reveals suspicious file transfer sessions.
  • Explain why allow listed protocols still need behavioural monitoring.
  • Describe how the same channel can be reused for data exfiltration.
