T1578.002 Modify Cloud Compute Infrastructure: Create Cloud Instance

T1578.002Defense ImpairmentExtremeTechnique

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

A cloud instance is a virtual computer you rent inside a cloud account. This technique means an attacker starts a new one. The new machine is built with weaker network and access rules than the machines already in the account. The attacker then uses it to read data or run tools quietly.

Why should you care?

Your existing machines may be protected by strict rules and watched by security tools. A new machine starts with none of that history. The attacker can attach copies of your data to it and read them without touching your production systems. Later they can delete it, so little evidence remains. Unexpected new machines are one of the clearest warning signs in a cloud account.

How it works, in plain steps

  1. The attacker obtains permissions that allow creating a new virtual machine.
  2. They pick an image, a size, and a network setting for the new machine.
  3. They may attach a snapshot of an existing volume to get a copy of your data.
  4. They start the machine with a security rule that allows their own access.
  5. They copy or stage data from the new machine to a location they control.
  6. They can then stop or delete the machine to remove the evidence.

Real-world example

Think of an office building where every tenant needs a badge to enter the file room. A person with a manager pass rents an empty office on another floor. That floor has no visitor log and no locked file room. They quietly move copies of files there and read them at leisure.

Key takeaways

  • Any machine you did not provision is a finding worth investigating.
  • Compare cloud instance lists against your asset records often.
  • Make sure logging and monitoring cover new machines automatically.

In more detail

Creating a cloud instance is the compute-side counterpart to snapshot creation, and the two are usually seen together. The adversary provisions a new virtual machine inside the victim account, often from an image they supply or from a snapshot of an existing volume, and deliberately selects a network placement, security group, or identity role that is less restrictive than what guards the existing estate. The new machine has no history, no endpoint agent baseline, and often no logging pipeline, so activity on it is quiet. From there the adversary can mount copies of data, stage it, or move it onward, and can later terminate the instance so only the audit record of the creation survives. Instances may also be created purely to run malicious workloads without disturbing production systems that are monitored for performance. Detection relies on cloud audit events for instance creation, on correlation between identity, source address, and requested configuration, and on the gap between provisioning telemetry and the configuration management database: an instance that exists in the account but never appears in the asset inventory, or one launched with an unusual public address or a default security group, is a strong signal. Automated provisioning under a known pipeline identity behaves predictably, so deviation from that pattern is the discriminator.
