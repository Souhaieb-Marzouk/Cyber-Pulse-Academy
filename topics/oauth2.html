OAuth 2.0

Identity & AccessVery hardKeyword

OAuth 2.0 is an authorisation framework that lets a client application obtain limited access to a resource on behalf of a user or another service without handling that user's credentials. It defines roles (resource owner, client, authorisation server, resource server), grant types (authorisation code, client credentials, device code, and the deprecated implicit and resource owner password grants), and token types, most importantly the access token and the optional refresh token. The framework deliberately separates authorisation from authentication, which is why building a login flow on OAuth alone produces the confused-deputy problems that OpenID Connect was created to solve. Security depends heavily on implementation choices rather than on the framework's defaults: public clients must use proof key for code exchange to bind the authorisation request to the token request, redirect URIs must be matched exactly, state parameters must be unpredictable and verified, and bearer tokens must be protected in transit and at rest because anyone holding the token can use it. Common real-world failures include open redirectors leaking authorisation codes, permissive redirect URI matching with wildcards or path traversal, tokens stored in browser local storage where cross-site scripting can reach them, excessive scope grants that let a low-privilege client call high-value APIs, and consent phishing in which a user grants a malicious application durable access. Defenders focus on token lifetime, scope minimisation, sender constraint, and the authorisation server's audit log of grants, consents and token issuance.

What you will practise

  • You will be able to describe the authorisation code, client credentials and device code flows and select the correct one for a given client type.
  • You will be able to explain why OAuth 2.0 is not an authentication protocol and how that leads to confused-deputy vulnerabilities.
  • You will be able to identify insecure redirect URI handling, missing state validation and absent proof key for code exchange in a client registration.
  • You will be able to evaluate access token lifetime, scope breadth and refresh token rotation against least-privilege expectations.
  • You will be able to investigate suspicious OAuth consent grants and illicit consent attacks using authorisation server audit logs.
  • You will be able to explain token sender-constraining options and when bearer token protections are insufficient.
