DET0009 Supply-chain tamper in dependencies/dev-tools (manager→write/install→first-run→egress)

DET0009Detection StrategyVery hardDetection Strategy

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

Modern software is built from many ready made parts, called dependencies. A build machine downloads those parts and runs them. An attacker can hide code inside a part or inside the tool that fetches it. This detection looks for a newly installed part that runs and then reaches out to the network.

Why should you care?

One poisoned part can end up inside thousands of products and updates. The code arrives through a trusted process, so it may be signed and approved like any other release. Build machines hold keys that sign software and credentials for publishing, which makes them a high value target. They are also busy, which makes their activity easy to hide in. Watching the build path protects everything downstream of it.

How it works, in plain steps

  1. The endpoint agent records the package manager or build tool that runs, with its command line and working directory.
  2. It records the files that the tool creates or changes during installation, including scripts inside the package.
  3. It records the next process to start from that freshly installed location, along with its parent.
  4. It records network connections from that new process, including the destination address and port.
  5. The detection ties these events together by host and short time window and scores the combination.
  6. Alerting happens when a first run process from a new install makes egress to an address outside the approved package sources.

Real-world example

Think of a bakery that buys ready made pastry from a supplier. One delivery contains a filling nobody ordered. The baker uses it without checking, and every cake that day is affected. The shop looked normal. Only the delivery note and the kitchen log show what changed.

Key takeaways

  • The build path is high value because its output is trusted everywhere.
  • No single event proves tampering, so link install, first run and egress together.
  • Fresh install directories making outbound connections are the strongest clue.

In more detail

This strategy detects tampering with software dependencies and developer tooling in the build path (T1195.001, Supply Chain Compromise: Compromise Software Dependencies and Development Tools). The technique matters out of proportion to its frequency because a single poisoned package or build script propagates to every downstream system and can reach production with valid signatures. Detection is behavioural and chain based: a package manager or build tool writes or installs files, a process runs from the fresh install for the first time, and that process makes network egress to an address the build host has never contacted. Correlating those four stages is what makes it work, since any one stage alone is routine. It fails in practice because build hosts are noisy, ephemeral and often excluded from endpoint monitoring.

What you will practise

  • Explain how dependency and development tool tampering reaches production systems.
  • Identify the four observable stages of the attack chain and the telemetry for each.
  • Describe why build and continuous integration hosts need endpoint monitoring like servers.
  • Correlate a package installation with the first run of a new binary and its network egress.
  • List the legitimate package sources and registries your builds are allowed to contact.
  • Choose a response that preserves evidence without breaking an active build pipeline.
