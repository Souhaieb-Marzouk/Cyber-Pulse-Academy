T1569.003 System Services: Systemctl

T1569.003ExecutionExtremeTechnique

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

systemctl is the main command used to control services on a Linux computer. A service is a program that runs in the background, often from the moment the machine starts. systemctl can start, stop or enable those services. An attacker can use it to make their own program run as a service.

Why should you care?

Services start on their own and often run with strong permissions. If an attacker adds a service, their program can return after every restart. It may look like ordinary system work, so nobody questions it. This makes the intrusion harder to find and harder to remove. Learning to read service changes helps you spot it early.

How it works, in plain steps

  1. The attacker already has a shell on the Linux host, often through a stolen login.
  2. A service file is written that names the program the attacker wants to run.
  3. That file is saved in a directory systemd reads, such as the system service folder.
  4. The systemctl enable command links the service so it starts at each boot.
  5. The systemctl start command asks systemd to launch the program right away.
  6. Because systemd starts it, the program keeps running after the shell closes.

Real-world example

Think of a large office building with a facilities manager. Staff do not open every door themselves. They write a job on the manager's list, and the manager unlocks the room. systemd is that manager on a Linux computer. Attackers cannot always open their own doors, so they add a job to the list. The manager then runs their program using the manager's own keys. The door is opened by a trusted person, so nobody looks twice. A careful guard checks the list for new jobs that nobody approved.

Key takeaways

  • systemctl controls background services, so a new or changed service file deserves a look.
  • Compare each service start with the person and the process that asked for it.
  • Services survive restarts, so check what starts automatically after an incident.

In more detail

Systemctl is the command line front end for systemd, the service manager used by most Linux distributions. An operator who already holds a shell can call it to start, stop, enable or restart a unit, and the program described in that unit then runs as a child of the service manager rather than as a child of the operator's shell. The durable artefacts are the unit file itself, usually a .service file placed in a system or user unit directory, plus journal and audit records that show the systemctl invocation and the process it launched. Because administrators run the same commands daily, the version string and exit status prove little. Defenders separate abuse from routine maintenance by checking who ran systemctl, from which parent process, whether the referenced unit file was created or modified shortly beforehand, and whether the launched binary sits in a directory it has no business running from.
