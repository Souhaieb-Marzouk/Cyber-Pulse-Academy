T1593.002 Search Open Websites/Domains: Search Engines

T1593.002ReconnaissanceExtremeTechnique

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

This is when an attacker uses search engines to find information you published by mistake. Search engines copy pages into a big index. Attackers then use special search words to find exposed files, login pages and notes that should have stayed private.

Why should you care?

One careless upload can put a list of passwords or internal addresses on the open internet. Search engines will find it and keep a copy for a long time. Attackers use these finds to skip the hard work of guessing. Your own logs may never show the search, because it happens on the search engine's servers.

How it works, in plain steps

  1. A search engine crawler visits your website and copies your pages into its index.
  2. An attacker types a normal search for your organisation's name to see what is visible.
  3. The attacker adds special search words that limit results to your site or to certain file types.
  4. They look for exposed folders, backup files, spreadsheets, log files and admin pages.
  5. They open whatever the search finds and check whether it contains useful detail.
  6. They save the links for later use, such as a login page to attack or a leak to exploit.

Real-world example

Think of a library that puts every donated box on open shelves, including a box of staff rota sheets. The catalogue tells anyone exactly which shelf to check. The attacker is the reader who follows the catalogue, and the exposed file is the box that should never have reached the shelf.

Key takeaways

  • Anything reachable on the open internet may end up in a search index within days.
  • Remove the exposed file first, then ask the search engine to drop the cached copy.
  • Review your own site with the same search operators an attacker would use.

In more detail

This sub-technique covers the use of search engine indexing and advanced query syntax to find victim information that was published but never meant to be found. Adversaries combine ordinary keyword searches with operators that restrict results by site, file type or URL pattern, which surfaces exposed directories, configuration backups, log files, spreadsheet exports and administrative pages that were left reachable. This is distinguished from the parent by method: instead of reading pages the victim chose to publish, the adversary interrogates a third party index built by a crawler, so nothing touches victim infrastructure and victim logs stay silent. The useful artefacts for a defender are the search engine's own indexes and the fact that the exposed files still exist on the origin server, so remediation means removing the object and requesting removal from the index. Detection depends on web server logs showing that a resource was retrieved suddenly and repeatedly, which often only becomes visible after the address was indexed and someone else found it.

What you will practise

  • Explain how search engine indexing turns a hidden file into a discoverable one.
  • Describe how advanced query operators narrow results to a specific site or file type.
  • List the file types and page patterns attackers look for in exposed content.
  • Explain why victim side logs often miss this collection entirely.
  • Carry out a basic self assessment of publicly indexed content.
