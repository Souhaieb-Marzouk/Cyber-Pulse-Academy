Passwordless Authentication

Identity & AccessVery hardKeyword

Passwordless authentication is a set of authentication methods in which the user proves possession of a registered authenticator bound to their identity and never supplies a shared secret that can be phished, reused or cracked offline. The two dominant families are asymmetric key credentials based on the Web Authentication standard, where the private key stays in a hardware security key or platform authenticator and the public key is registered with the relying party, and certificate-based authentication, where a device or smart card certificate issued by enterprise certificate authority replaces the password. Both defeat password-centric attacks structurally rather than by policy: there is no secret to spray, no hash to crack, no code to relay to a waitress-style adversary-in-the-middle proxy, and the signature is bound to the origin so that a lookalike domain cannot harvest a usable response. Passkeys extend the same primitive to consumer use by synchronising or device-linking credentials, which improves usability and recovery but changes the threat model, since the credential now follows the user's platform account rather than a single physical token. Deployment work is mostly in the unglamorous details: recovery and enrolment, because account recovery becomes the weakest authentication path once passwords are gone; attestation and device inventory, to decide which authenticators are acceptable; account identifier design, to avoid silently re-enrolling a credential to the wrong person; and legacy systems that cannot speak the protocol and therefore need a brokered or certificate-based compromise. Hybrid environments usually run passwordless for interactive users and retain vaulted secrets for machine identities, where the equivalent control is short-lived certificates and automatic rotation.

What you will practise

  • You will be able to explain how asymmetric key credentials resist phishing and credential replay structurally rather than by policy.
  • You will be able to compare hardware security keys, platform authenticators and synchronised passkeys by assurance and usability.
  • You will be able to design enrolment and recovery procedures that do not reintroduce a weak authentication path.
  • You will be able to identify systems that cannot support passwordless authentication and select a brokered or certificate-based alternative.
  • You will be able to detect suspicious authenticator registration, deletion and re-registration events in identity provider logs.
  • You will be able to plan a phased migration that keeps break-glass access available without standing passwords for administrators.
