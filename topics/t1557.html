T1557 Adversary-in-the-Middle

T1557Credential AccessExtremeTechnique

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

An adversary-in-the-middle attack happens when an attacker secretly sits between two devices that are talking to each other. Both sides believe they speak directly, but every message passes through the attacker first. The attacker can read those messages, change them, or store them for later. This is a position rather than a single tool, and many other attacks start from it.

Why should you care?

Most network traffic trusts the path it travels, and that trust is often misplaced. If an attacker controls the path, only strong encryption still protects your data. A fake network device can hand your computer wrong settings and send your traffic to a stranger. From there, passwords, session cookies and documents can be taken without any malware on your machine. The network keeps working, so nobody notices straight away.

How it works, in plain steps

  1. Your device joins a network and asks its neighbours for the hardware address of a server it needs.
  2. The attacker answers first with their own address, so your traffic goes to them.
  3. A name lookup trick such as Link-Local Multicast Name Resolution (LLMNR) makes your device ask who owns a host name.
  4. A fake address service or a fake Wi-Fi hotspot gives you a gateway or name server the attacker controls.
  5. Your traffic now passes through the attacker, who copies it, changes it, or replays it later.
  6. Everything still works, so the attacker keeps collecting quietly for as long as possible.

Real-world example

Imagine a shared office building where the mail room trusts anyone who claims to be the mail room. Each floor sends a form asking for the correct desk number of the finance department. An impostor answers first and gives their own desk number. All invoices for finance now arrive at the impostor, who opens them, copies the bank details, reseals them and walks them over to finance. Finance still receives its post and never complains, so the building manager has no reason to look. The only clue is that the mail room log shows two different desks claiming the same department.

Key takeaways

  • If traffic is not encrypted, whoever controls the path can read it.
  • A sudden network problem and a sudden login problem may share one cause.
  • Escape the attacker's position first, then change the affected passwords.

In more detail

Adversary-in-the-middle (AiTM) describes an attacker who positions themselves on the network path between two parties that believe they talk directly. Instead of defeating encryption head on, the attacker abuses the protocols that decide where traffic goes, such as ARP, DNS, LLMNR, NBT-NS or DHCP, so a victim host hands its traffic to an attacker-controlled system. From there the attacker can read or replay traffic, rewrite it in transit, harvest credentials and session cookies, or negotiate weaker protocol options. Detection is usually indirect: conflicting ARP bindings, DNS or gateway settings changed outside a maintenance window, authentication events from unexpected source hosts, and successful logons where the client address does not match the user's usual device. Legitimate causes for each signal are common, so defenders correlate the network anomaly with the authentication event rather than alerting on either alone.

What you will practise

  • Explain what an adversary-in-the-middle position is and why encryption limits it.
  • Describe how address resolution, name resolution and address assignment can each redirect traffic.
  • Compare this technique with its sub-techniques and state what each one abuses.
  • Identify the network, authentication and endpoint log sources that reveal an attacker on the path.
  • Distinguish a genuine network fault from deliberate traffic redirection.
  • Choose practical network controls that stop an attacker taking a position on the path.
