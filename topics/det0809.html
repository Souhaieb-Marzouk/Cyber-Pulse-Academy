DET0809 Detection of CDNs

DET0809Detection StrategyVery hardDetection Strategy

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

Many companies put a content delivery network in front of their websites. This is a worldwide set of servers that keeps copies of a site close to visitors. Attackers want to know which delivery network you use. This detection looks for patterns that reveal it. One pattern is many address lookups for the same name. Another is a request that reaches your server while skipping the delivery layer.

Why should you care?

Your delivery network also acts as a shield. It hides your real server address. It also filters some hostile traffic. An attacker may learn your provider and then find the real server behind it. They can then aim straight at the unprotected machine. That bypasses protections you paid for and believed were working. Knowing this is happening lets you test your own exposure first. It also tells you when to lock down direct access.

How it works, in plain steps

  1. Your domain name system resolver logs record every name lookup made from inside the network.
  2. The rule collects lookups for your own public hostnames and looks at how the answers change.
  3. Answers that rotate between many addresses belonging to known delivery providers point to a delivery network.
  4. It also looks at requests that reach your origin server while bypassing the delivery layer.
  5. Each finding is compared with a baseline of which services are supposed to be delivered through a content delivery network.
  6. Lookups or direct requests that disagree with the baseline are grouped by source and raised for review.

Real-world example

Picture a shop that uses a national warehouse. Every customer gets goods fast, and the real stockroom address stays secret. Now someone walks around the neighbourhood. They ask which warehouse serves this shop. Later they knock on a back door of the stockroom itself. The questions are legal. The pattern is not. This detection watches the asking and the knocking. It then compares that with what the shop says it does.

Key takeaways

  • A content delivery network hides your real server and filters traffic, so learning it helps an attacker.
  • You must record which of your services are meant to be delivered through one, or the rule has no baseline.
  • Direct to origin traffic is the most useful finding, because it shows a bypass path worth closing.

In more detail

This strategy detects the identification of content delivery networks used by the victim, ATT&CK sub technique T1596.004. An adversary wants to know which content delivery network fronts a target service, because that knowledge supports both evasion and origin discovery: it explains which address ranges belong to a third party, helps the attacker recognise where protective filtering sits, and encourages a hunt for an origin server that answers directly and bypasses the delivery layer. Detectable telemetry is indirect. Recursive domain name system resolver logs show repeated lookups of the same hostname resolving to rotating delivery infrastructure, certificate transparency and passive domain name system sources show the delivery hostnames associated with the target, and origin side logs show requests that arrive with the delivery network's addressing but without its normal headers. Detection depends on a baseline of which hostnames are expected to be delivered through a content delivery network and which of your services are meant to be reachable only through it. The strategy fails because delivery infrastructure is shared and noisy, because most organisations never record that baseline, and because a single lookup proves nothing without context.

What you will practise

  • Explain what a content delivery network does and why an adversary profiles it
  • Identify resolver, passive domain name system and certificate transparency telemetry that reveals delivery infrastructure
  • Baseline which of your public services are intended to be delivered through a content delivery network
  • Detect direct to origin requests that bypass the delivery layer
  • Describe how origin discovery defeats filtering and address hiding protections
  • Turn a finding into an origin lock down and exposure validation task
