DET0820 Detection of Client Configurations

DET0820Detection StrategyVery hardDetection Strategy

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

This detection looks for someone learning how your users work. The attacker wants to know which browser, which programs and which versions people use. The rule watches for pages that collect browser details, called fingerprinting. It also watches for many different browser strings arriving from one address.

Why should you care?

An exploit works only on specific versions. Knowing your versions lets the attacker send a lure that matches. Users notice nothing, because the page looks like an ordinary web page. Catching the collection early helps you warn the right group of staff.

How it works, in plain steps

  1. Browsers send a user agent string with every web request. That string names the browser, the version and the system.
  2. A web gateway or proxy logs the string, the requested page, the address and the signed in user.
  3. Fingerprinting pages are known by their address, because they collect screen size, installed fonts and plug in lists.
  4. The rule selects requests to those pages and groups them by the requesting address or user.
  5. It counts how many different user agent strings one site receives from one address in a short window.
  6. A single external address visiting your pages with many fingerprints is treated as collection, not normal use.

Real-world example

Think of a hospital sign in sheet that records the name, the ward and the shift of every visitor. The sheet helps staff. However, a visitor who reads the whole sheet learns when each ward is quiet. This detection watches who reads the whole sheet.

Key takeaways

  • Version detail is worth more to an attacker than a name, because it selects the tool.
  • Fingerprinting usually hides behind an ordinary looking web page.
  • One external address showing many browser versions is a strong sign of collection.

In more detail

This detection strategy covers the gathering of client configurations, the technique where an adversary learns how target users work before crafting a lure or an exploit: browser and operating system versions, installed extensions and plug ins, virtual private network clients, mail clients and the scripts a public web page runs in the visitor's browser. It matters because it converts a general attack into a precise one, and the collection is split between off network activity the victim cannot see and on network activity that looks similar to ordinary browsing if you only review single requests. The telemetry that makes it possible is secure web gateway logs with the user agent string, version fingerprinting endpoints served by the organisation or by a lure page, endpoint management inventory reports, and public site analytics that show one address visiting the same page with many different fingerprints. Detection fails because user agents vary across the estate and version checks are built into normal web browsing.

What you will practise

  • Explain how client configuration detail improves a targeted attack.
  • Identify the proxy, endpoint and web server fields that record fingerprinting.
  • Write a rule that counts distinct user agent strings per external address.
  • Describe how to inventory browser and plug in versions across the estate.
  • Explain why ordinary browsing makes this detection noisy without a baseline.
