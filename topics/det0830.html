DET0830 Detection of Active Scanning

DET0830Detection StrategyVery hardDetection Strategy

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

This detection looks for someone probing your network to find open doors. Probing means sending many connection attempts to learn which hosts answer and which services run. The detection watches for scans from sources you do not recognise.

Why should you care?

A scan is often the first time an attacker touches your systems. If you see it, you know someone is interested and you can block them early. Scans also show which of your services are exposed to the internet. Most scans are automated and repeated, so they are easy to miss in busy logs. Grouping them by source turns thousands of small events into one clear alert.

How it works, in plain steps

  1. Firewalls and network devices write a record when they block or allow a connection.
  2. The rule counts blocked connections by source address and by destination port.
  3. A single source touching many ports on one host looks like a port sweep.
  4. A single source touching the same port on many hosts looks like a host sweep.
  5. Known scanner addresses, monitoring probes, and cloud health check ranges are removed.
  6. What remains is scored by breadth and speed, and alerts when it passes the threshold.

Real-world example

Think of a person walking down a street trying every car door handle. They do not break anything. They just want to know which cars are unlocked. A single handle pull tells you nothing, but someone pulling fifty handles in two minutes is worth a call to the police. The detection counts the handle pulls, not the cars.

Key takeaways

  • Active scanning is usually the earliest visible sign of an interested adversary.
  • Counting distinct ports and hosts per source is what turns noise into a clear signal.
  • Approved vulnerability scanners create identical traffic, so source based filtering is essential.

In more detail

This strategy detects Active Scanning, the reconnaissance technique in which an adversary probes victim infrastructure with network traffic to find live hosts, open ports, and running services. It matters because scanning is often the first observable contact an organisation has with an attacker, and it turns a theoretical exposure into a targeted one. Detection relies on firewall deny logs, network flow records, intrusion detection alerts, and service logs showing repeated connection failures. The classic failure is that vulnerability scanners, monitoring probes, and cloud health checks produce the same traffic profile, so the rule must distinguish approved scanners by source and schedule from unknown sources that sweep broadly and slowly.

What you will practise

  • Describe the difference between a port sweep, a host sweep, and a service version probe
  • Identify the network telemetry that records blocked and allowed connection attempts
  • Threshold scan detection by distinct destination ports and hosts per source address
  • Maintain a registry of approved scanners and monitoring systems for filtering
  • Judge severity from whether the scanned targets are internet facing or internal only
