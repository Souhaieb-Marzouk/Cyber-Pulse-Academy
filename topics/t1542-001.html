T1542.001 Pre-OS Boot: System Firmware

T1542.001PersistenceExtremeTechnique

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

This is the version of pre boot attack that changes the main firmware of the machine. Firmware is built in software on the mainboard. The acronyms BIOS and UEFI name the two common kinds of this firmware.

Why should you care?

This code lives on the board itself, so a new hard disk will not remove it. It runs before your antivirus, so antivirus may never see it. The machine may look healthy while the code stays hidden. Fixing it can mean replacing hardware.

How it works, in plain steps

  1. The attacker first gets high level rights on the machine, often as a system administrator or through the kernel.
  2. Parent topic pre boot boot attacks target the start up chain in general. This sub-technique targets the board firmware only.
  3. They run a firmware update tool or abuse a weak update path that does not properly check what it writes.
  4. The malicious code is written into the firmware chip. The chip keeps its contents when power is off.
  5. On the next start, that code runs first and can hide itself or restore other malicious files.
  6. Defenders find it by comparing the firmware version and settings with a trusted record, not by scanning files.

Real-world example

Think of a building whose entry system is wired into the wall. Changing the locks on every door does not help, because the attacker edited the wiring that decides who the doors open for. You must inspect or replace the wiring itself, not the doors.

Key takeaways

  • Keep a record of approved firmware versions and settings for every model you own.
  • Alert on firmware update tools and unexpected update attempts, because that is often how the change arrives.
  • Treat a confirmed firmware implant as a hardware integrity problem, so rebuild or replace rather than clean.

In more detail

System Firmware is the sub-technique of Pre-OS Boot in which the attacker writes malicious code into the mainboard firmware itself, that is the BIOS or the UEFI firmware that both initialises hardware and starts the boot process. Unlike a bootkit, which alters boot records or files on the boot disk, this behaviour persists in flash memory on the board and therefore survives disk replacement, operating system reinstallation and most host based clean up. Attackers reach it in several documented ways: abusing legitimate but unsigned or unverified update paths, using an existing kernel or system privilege to invoke a firmware update utility, exploiting weaknesses in the firmware update process, or replacing the flash contents directly when the platform allows it. Because the implant is active before any operating system defence loads, it can hide files, intercept the boot chain or reinstall malicious components after remediation. Detection is measurement based rather than signature based: compare current firmware versions, settings and boot measurements against a known good baseline, review firmware update attempts and update utility execution, and treat mismatches or unexpected changes to secure boot configuration as a serious integrity failure that warrants hardware level rebuilding.
