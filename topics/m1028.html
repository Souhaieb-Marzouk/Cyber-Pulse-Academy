M1028 Operating System Configuration

M1028Enterprise MitigationVery hardMitigation

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

Operating system configuration means changing the settings of a computer so that only the features you really need are switched on. It means taking a default install and making it safer before anyone attacks it. You remove unused programs, close unused network ports, and limit who can change important system files.

Why should you care?

Every computer ships with many features switched on, and each extra feature is another way in. If you leave them alone, an attacker has an easier path to steal data or take control. Good configuration also records what happens on the machine, so you can see an attack later. It does not stop every attack, but it makes the simple ones much harder.

How it works, in plain steps

  1. Start with a written baseline that lists the settings your organisation agrees on for each type of computer.
  2. Turn off services, protocols and programs that the machine does not need for its daily work.
  3. Limit write access to system folders so normal users cannot change important files.
  4. Switch on built-in protections that make memory attacks much harder to run successfully.
  5. Record security events so you can review who did what, and when they did it.
  6. Check every machine against the baseline again and again, because settings drift over time.

Real-world example

Think of a new laptop like a house with every window and door unlocked. The builder left them open so you could move in easily. Operating system configuration is the evening walk you take around that house. You close the windows you never use, lock the back door, and keep a light on in the hallway so you can see who walks past. You do not rebuild the house. You simply decide which openings should stay open, and you check them again after guests have visited.

Key takeaways

  • Defaults are built for convenience, not for safety, so every machine needs review before it goes live.
  • Apply one agreed baseline everywhere, or you will never know which machines are weak.
  • Check for drift regularly, because new software can quietly re-open settings you closed.

In more detail

Operating system configuration is a preventative mitigation that shrinks a host's attack surface by changing what the platform allows by default. Typical work includes disabling unneeded services and legacy protocols, removing unused interpreters and administrative shares, restricting who can write to system directories, enabling built-in exploit mitigations such as memory randomisation and data execution prevention, and turning on the audit settings that make later investigation possible. In real environments it appears as a configuration baseline expressed through group policy, a configuration management profile, a golden image or a compliance benchmark that is scanned continuously. Evidence lives in configuration inventory data, benchmark scan results, policy reports and change tickets, while drift shows up as hosts sliding out of compliance between scans. The common misunderstanding is that hardening is a one-time build step. Unpatched software and newly installed applications re-open services, so configuration has to be monitored and re-applied, and overly aggressive hardening breaks business applications, which is why baselines are tested before wide rollout.

What you will practise

  • Summarise the audit settings that make later incident investigation possible.
  • Recognise the trade-off between aggressive hardening and broken business applications.
