T1218.012 System Binary Proxy Execution: Verclsid

T1218.012StealthExtremeTechnique

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

verclsid.exe is a signed Windows program that checks shell extensions before Explorer uses them. A shell extension is a small add-on that changes how File Explorer looks or behaves. Each one is identified by a long number called a class identifier, or CLSID.

Why should you care?

You can also run the checker yourself and give it any class identifier you like. If that number points at an attacker's object, the check itself loads and runs the object. The object can even be a script fetched from a remote server, so no payload file is left on disk. If you ignore this, a program that is supposed to verify code becomes a way to run it.

How it works, in plain steps

  1. Windows Explorer shows your files and folders, and it uses small add-ons called shell extensions.
  2. Every shell extension is identified by a long number, which is called a class identifier or CLSID.
  3. verclsid.exe is the helper that verifies such an extension before Explorer loads it into memory.
  4. You can also run that helper yourself and hand it any class identifier you choose to verify.
  5. If the class identifier points at an attacker's object, the verification step loads and executes it.
  6. That object can be a script from a remote server, so the payload never needs to be stored locally.

Real-world example

A building inspector arrives to check all the fire doors and is let into every corridor without question. The inspector is genuine and the visit is entirely normal. However, the person with the clipboard is not from the fire service at all, and while checking doors they unlock a fire exit for someone else. Everyone trusted the role, not the person. verclsid.exe is that inspector's role.

Key takeaways

  • A program whose job is to check code can itself be used to load code.
  • A class identifier on the command line tells you exactly where to look next, in the registry.
  • Watch for verclsid.exe started by anything other than Explorer.

In more detail

Verclsid.exe is the Extension CLSID Verification Host, a signed Windows binary whose role is to verify a shell extension before Windows Explorer or the shell loads it for use. It accepts a command line form combining a silent switch with a class identifier, the unique number that identifies a Component Object Model object, and in that mode it resolves and instantiates the object as part of the check. An adversary abuses precisely that behaviour: by supplying a class identifier they control, they cause the verification host to load and execute their object, and that object may in turn load a COM scriptlet from a remote server, in a manner closely related to scriptlet abuse through Regsvr32. Because the binary is Microsoft-signed and native to the operating system, application control solutions that do not account for it can be bypassed, and the payload can arrive without a persistent local file if the object is fetched remotely. Detection is aided by how unusual the invocation is: verclsid.exe rarely appears in interactive command lines, so process creation telemetry showing it with a class identifier argument, especially when the parent is a script host, office application or web service rather than Explorer, is a strong indicator. Investigators then pivot to the registry to see what that class identifier maps to and check for network connections from the process.
