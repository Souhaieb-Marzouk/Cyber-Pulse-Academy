AES GCM

CryptographyVery hardKeyword

AES-GCM is an authenticated encryption with associated data (AEAD) mode that combines the AES block cipher in counter mode with a GHASH-based universal hash to produce ciphertext plus a 128-bit authentication tag, so confidentiality and integrity are delivered by a single key. The construction takes a 128-bit block cipher key (AES-128, AES-192 or AES-256), a unique nonce of typically 96 bits, the plaintext, and optional associated data that is authenticated but not encrypted. Decryption fails closed: if the tag does not verify, no plaintext is released, which is why GCM is preferred over unauthenticated modes such as CBC in modern protocols like TLS 1.3, IPsec ESP, and 802.11 WPA3. The security proof of GCM depends absolutely on nonce uniqueness per key; reusing a nonce with the same key leaks the XOR of plaintexts and, worse, exposes the GHASH authentication subkey, letting an attacker forge arbitrary messages. Other practical failure modes are truncating the tag too aggressively, ignoring tag verification in application code, reusing keys across contexts, and exhausting the 96-bit counter space on long-lived high-volume keys. Implementations also vary in constant-time behaviour, so side channels during GHASH multiplication matter on embedded and shared hardware. For defenders this means key and nonce lifecycle management, per-message key derivation, envelope encryption patterns, and reliable detection of downgrade or fallback to legacy cipher suites are all first-class operational concerns rather than implementation details.

What you will practise

  • Explain how AES-GCM composes counter-mode encryption with GHASH authentication and what the authentication tag guarantees.
  • Describe exactly what breaks when a nonce is reused with the same key, and how that failure surfaces in captured traffic.
  • Choose appropriate tag lengths and associated data for a protocol, and justify why tag truncation is a risk decision.
  • Recognise downgrade and fallback behaviour in TLS or IPsec logs that indicates traffic is no longer protected by an AEAD mode.
  • Design envelope encryption and per-message key derivation so that high-volume services never exhaust nonce space.
  • Evaluate a code review finding where a GCM tag is computed but not actually verified before use.
  • Map cryptographic weakening of transport encryption to adversary techniques for collection and command and control.
