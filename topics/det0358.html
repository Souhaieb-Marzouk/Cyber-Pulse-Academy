DET0358 Programmatic and Excessive Access to Confluence Documentation

DET0358Detection StrategyVery hardDetection Strategy

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

This detection watches for a person or program reading a very large amount of documentation from Confluence, a shared wiki. Normal reading is slow and spread out. Bulk reading looks like many pages, spaces or attachments collected in a short time.

Why should you care?

Internal documentation often contains the details an intruder needs. It can describe how systems are built, what the network looks like and who has access. One stolen account can copy all of it in minutes. The copy is quiet and the account is real.

How it works, in plain steps

  1. Confluence records each user action, including page views, searches and exports.
  2. The web or proxy log records the request path, the account and the client program name.
  3. A rule counts requests and distinct pages per account over a rolling window.
  4. It filters out known integration accounts and the normal client program a browser uses.
  5. If the count is far above the account baseline and the client looks like a script, an alert is raised.

Real-world example

Think of a library sign-in sheet. One reader who borrows three books a month is normal. Another reader who carries out the whole reference shelf in one trip, using a trolley instead of a bag, is worth a conversation.

Key takeaways

  • Bulk documentation reads are quiet, and the account used is usually legitimate.
  • The client program name is often the clearest sign that a script is reading instead of a person.
  • Compare each account with its own history, not with a single global number.

In more detail

This strategy detects bulk or automated collection from Atlassian Confluence, the T1213.001 sub-technique for information repositories. Confluence pages often hold architecture notes, runbooks, credentials in code blocks and internal network detail, so an intruder with a valid account can harvest years of design documentation in a few minutes with the representational state transfer (REST) interface, which most audit programmes never review. Detection depends on Confluence audit log entries, web and proxy access logs that capture user agent and request path, personal access token records and export or attachment download records. It fails in practice because automated read access is also how integrations, backup jobs and search indexers work, so a rule that only measures request rate flags the company's own tooling and drowns the analyst.

What you will practise

  • Explain why internal documentation is a high-value collection target
  • Identify the audit, access and token telemetry that reveals programmatic Confluence use
  • Build a per-account baseline of pages viewed and exports per day
  • Distinguish approved integrations from scripted collection using client and token attributes
  • Describe how to scope and time limit an investigation into bulk documentation access
  • Recommend access review actions that reduce the value of a single stolen account
