T1036.006 Masquerading: Space after Filename

T1036.006StealthExtremeTechnique

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

This is a trick that adds a space to the end of a file name. The space is hard to see in a file list. It changes how the computer decides what kind of file it is. So a program can look like a harmless text file.

Why should you care?

You decide what to open from the file name and its icon. One hidden space can make the computer run a program while you expect a document. The same file looks harmless in an email or a download list. This behaviour mainly affects Apple computers, but the lesson about hidden characters applies everywhere.

How it works, in plain steps

  1. The attacker takes an executable file and renames it with a document extension.
  2. They add a single space after that extension, which is easy to miss.
  3. The file listing shows the name with the harmless document extension.
  4. When you double click it, the system checks the real file type instead of the extension.
  5. Because of the trailing space, the system treats the file as a program.
  6. The program runs, and a terminal window or the payload appears.

Real-world example

Imagine a suitcase at an airport queue with a label that reads soft clothes. The label has one extra trailing mark that the scanner reads as fragile goods. The scanner sends it to a different belt than the label suggests, and nobody at the desk notices.

Key takeaways

  • A single trailing space in a file name can change how it is handled.
  • Show hidden and invisible characters when you check a suspicious file name.
  • Watch for a document that starts a terminal or shell when opened.

In more detail

The space after filename sub-technique hides a program's true type by adding a trailing space to the file name. On platforms where the extended attribute that marks an executable is what decides how a file is handled, the trailing space makes the operating system treat the file by its real type, while the extension shown in a file listing suggests a harmless document. The result is that a double click executes code instead of opening a viewer, and the label on screen still shows a document or text extension. The behaviour is essentially absent on Windows, where the final extension determines handling, and it does not apply to application bundles. Detection is a file name inspection problem: trailing whitespace and other invisible characters in attachment names, download names and archive entries, combined with an executable file type reported by the operating system or an unexpected child process such as a terminal or shell after the user opens a document. Because trailing spaces break naive string comparisons, defenders should also expect tooling inconsistencies when the same name is normalised differently across systems.
