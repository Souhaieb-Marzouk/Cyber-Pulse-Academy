DET0555 Detection Strategy for Event Triggered Execution via emond on macOS

DET0555Detection StrategyVery hardDetection Strategy

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

emond is a background service on macOS that watches for events, such as a file arriving in a folder. When an event happens, it runs a command that a rule tells it to run. This detection looks for new or changed rules, and for the programs those rules start.

Why should you care?

Attacks often need to survive a restart. A rule book that runs a command at boot gives exactly that. Because the rules live in system folders, they are easy to overlook in a normal review. Finding a changed rule early stops the attacker from returning.

How it works, in plain steps

  1. A file monitoring tool on the Mac records when files are created or changed in system folders.
  2. The emond service reads its rules from a configuration folder, and the file events show when those files change.
  3. A SIEM, which is a central system that collects and searches log events, collects file and process events from the Mac.
  4. The rule looks for changes in the emond rule folders, and for commands started by the emond service.
  5. It compares what it sees with a baseline of approved rules that the fleet management team maintains.
  6. Any rule or launched program outside that baseline is sent to the endpoint team, with the rule file attached.

Real-world example

Think of a hotel wake up call service. Guests may schedule a call, which is normal. A call scheduled to a room that has no guest, by someone who never checked in, is the thing you want to spot. This detection reads the wake up call book and asks who wrote each entry.

Key takeaways

  • emond is legitimate macOS software, so the signal is the rule content and the program it launches, not the service itself.
  • Process parentage is the strongest evidence, because it shows the program was started by the event monitor.
  • Baseline the rules your fleet management tool deploys, or every managed Mac will look suspicious.

In more detail

This strategy covers Event Triggered Execution: emond, the macOS event monitor daemon that runs a program when a watched condition occurs, such as a file appearing in a folder or a system state change. It matters because emond gives an attacker durable local persistence that runs as root, survives reboots and produces no obvious scheduled task or login item for a reviewer to find. The telemetry that makes it visible is file creation or modification events on the emond configuration and rule directories, process creation showing the emond daemon reading its rule set, process creation of the action programs that emond launches, and the parent child relationship that ties those programs back to emond. It fails in practice because emond rules are legitimate on managed fleets, the daemon starts at boot so the initial load is normal, and many endpoint agents collect process events on macOS without recording the parent that would prove the link.

What you will practise

  • Describe what the emond daemon does and why it provides durable persistence on macOS.
  • Identify the file and process events that record emond rule creation and command execution.
  • Use process parentage to attribute a launched program to the event monitor service.
  • Compare emond rule files against a fleet baseline to find unauthorised rules.
  • Explain the limits of macOS endpoint telemetry without a full process auditing agent.
  • List the containment steps for a suspicious emond rule, including rule review and file collection.
