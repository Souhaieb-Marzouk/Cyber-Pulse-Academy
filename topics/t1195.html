T1195 Supply Chain Compromise

T1195Initial AccessExtremeTechnique

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

A supply chain compromise means an attacker changes software or hardware before it reaches you. The change happens at the maker, the builder or the delivery company, not on your computer. You install what looks like a normal, trusted product.

Why should you care?

You install vendor software because you trust the vendor. The attacker borrows that trust and often gets administrator rights with it. Your usual defences may stay quiet, because the file is signed and official. One poisoned part can reach thousands of customers at once.

How it works, in plain steps

  1. Attackers look for a weak point where a product is built or delivered.
  2. They may change source code, a shared dependency or a build system.
  3. They may also take over the update server or the download page.
  4. The vendor then ships the changed product through the same channel as always.
  5. You install or update as usual, often with administrator rights on the machine.
  6. The hidden part runs and gives the attacker access, and often only on selected machines.

Real-world example

Think of a bakery that supplies bread to many shops. Someone adds something harmful to the flour at the mill. Every loaf is baked and wrapped normally. Each shop checks its own ovens and its own staff, and none of them ever looks at the flour bag, because flour has always been fine.

Key takeaways

  • Trust in software comes from who built it and how it was delivered.
  • A valid signature shows who signed a file, not that it is safe.
  • Watch trusted applications for behaviour that no release note explains.

In more detail

Supply chain compromise is the parent category for attacks that modify a product or the way it is delivered before the final consumer receives it, which moves the point of failure away from the victim entirely. The interference can happen at any stage: the development tools an engineer uses, the development environment itself, a public or private source code repository, a third party dependency that many applications share, the build pipeline that assembles releases, the update and distribution channel that ships them, or the physical chain that produces and transports hardware. Because the modified item arrives through the vendor's own trusted channel, it commonly carries a valid signature, an expected file name and a familiar installer, and it may be installed with administrator rights as part of routine maintenance. The attacker can aim broadly, poisoning an artefact used by thousands of downstream consumers, or narrowly, shipping a payload only to chosen victims, and the two can be combined by distributing widely and behaving maliciously only on selected hosts. A notable variant is the second order compromise, in which access obtained from one poisoned component is used to poison another, multiplying reach. The defender's problem is that endpoint reputation checks, allow lists and even good patch discipline all assume the vendor is honest, so detection shifts to provenance and behaviour: a signed application that suddenly contacts an unfamiliar address, a vendor process that spawns a command shell, binaries or configuration files appearing in an installation directory after an update, or a trusted update package whose hash differs from the one published by the vendor. Where integrity metadata exists, such as signed release manifests or reproducible builds, verifying it after installation is the control that catches tampering rather than assuming the update was clean.

What you will practise

  • Define supply chain compromise and list the stages where tampering can occur.
  • Explain why a signed and officially delivered product can still be malicious.
  • Distinguish a broad distribution attack from one aimed at specific victims.
  • Describe a second order compromise and how it increases the attacker reach.
  • Identify behaviour based signs that a trusted application has been tampered with.
