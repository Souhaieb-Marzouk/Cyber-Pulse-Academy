DET0426 Detection of Direct Volume Access for File System Evasion

DET0426Detection StrategyVery hardDetection Strategy

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

This detection looks for programs that read or write a hard disk directly instead of opening files normally. The disk device is the raw storage underneath the file system. Only certain tools should touch it, so unusual access is worth a look.

Why should you care?

Normal file access is recorded by the operating system and can be blocked by permissions. Raw disk access skips all of that. An attacker can use it to read protected data, to corrupt the boot area or to hide files. Very few legitimate programs need this ability. That is what makes the event worth an alert.

How it works, in plain steps

  1. A process asks the operating system for a handle to a raw disk device.
  2. The kernel returns the handle and the access is recorded by an endpoint sensor or audit policy.
  3. The record includes the process image, its parent process and the requested access rights.
  4. The rule compares the process against a list of approved disk tools and drivers.
  5. It also checks whether the process came from a temporary folder or an unsigned file.
  6. An unexpected process holding a raw volume handle becomes an alert for the analyst.

Real-world example

Think of a library where every book has a sign out card. Members borrow books the normal way, and the cards show who took what. A person who unscrews the shelves and carries the whole bookcase out leaves no cards at all. The door camera still shows them, though. Raw disk access is the bookcase, and the device log is the camera.

Key takeaways

  • Raw disk access removes the file system layer and its audit records.
  • Legitimate disk access comes from a small set of signed tools and drivers.
  • Without device level auditing enabled, this activity leaves little to detect.

In more detail

This strategy detects software that opens a raw disk device instead of using the normal file system, a technique used to read, overwrite or destroy data while bypassing file level logging, access controls and even some encryption layers. It matters because a process that talks to a physical drive directly can read protected files, wipe a master boot record or hide data, and the file system audit trail records none of it. Detection rests on kernel device access telemetry, which may come from endpoint sensor drivers, object access auditing, or kernel level tracing, correlated with process identity and privilege. The main way it fails in practice is the platform dependency and the noise floor: disk utilities, backup agents and file system drivers all touch volumes legitimately, and without auditing enabled on the device object there is simply nothing to read.

What you will practise

  • Explain how direct volume access bypasses file system permissions and file level auditing.
  • Identify the telemetry sources that record raw device handles and the access rights requested.
  • Correlate a raw device handle with the process image, parent process and signature status.
  • Build an allowlist of approved disk utilities, imaging tools and storage drivers.
  • Assess the risk of a process that reads a volume and then writes to it.
  • Describe the visibility that is lost when object access auditing is not enabled on the device.
