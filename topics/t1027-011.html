T1027.011 Obfuscated Files or Information: Fileless Storage

T1027.011StealthExtremeTechnique

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

Fileless storage means keeping data somewhere that is not a normal file. On Windows this is often the Registry, a database of settings that the system uses. On Linux it can be a folder that lives in memory instead of on the disk. This is a sub-technique of Obfuscated Files or Information, which is about hiding content from security tools. The data is not gone, just stored where file scans rarely look.

Why should you care?

Many security tools only inspect files on the disk. Data kept in the Registry or in memory does not appear as a file, so those tools see nothing. This storage can survive a reboot, so an attacker does not need to stay active. Malware can also hide stolen data there before sending it out. You need to monitor these storage places directly, not only the file system.

How it works, in plain steps

  1. The attacker chooses a store that the operating system itself uses, such as the Windows Registry.
  2. They write a payload, script or collected data into a location there, often with an odd name.
  3. They may encode, encrypt or compress the content so that reading it shows nothing clear.
  4. The data sits quietly and may survive a restart of the computer.
  5. Later, a script or program reads the store back and rebuilds the payload in memory.
  6. On Linux, the same idea uses memory backed folders such as shared memory directories.

Real-world example

Think of a hotel night desk that keeps a guest register in a drawer. A visitor does not rent a room. Instead, they hide a sealed envelope among the register pages, where nobody expects to look. The morning cleaner tidies rooms, not drawers, so the envelope stays through several days. When the visitor returns, they take the envelope out and use it. The building was searched, but only the rooms were checked.

Key takeaways

  • File based scanning alone leaves gaps, because malicious data can live in the Registry or in memory.
  • Turn on change monitoring for the Registry and for system databases such as the WMI repository.
  • Look for unusual names, very large or encoded values, and scripts that read configuration stores at run time.

In more detail

Fileless storage means holding attacker data somewhere other than an ordinary file on disk, so that file scanning and integrity checking have nothing to inspect. Typical locations include the Windows Registry, the WMI repository, event logs, and memory mounted directories on Linux and network devices such as the directories for shared memory or temporary runtime data. Because these stores are built into the operating system, data placed there can survive reboots while generating no conventional file write, which is exactly the sort of event most endpoint controls watch. The technique is mainly a holding pattern: it is used to keep a payload, shellcode or staged collection data until the next step needs it, and the store may hold the content encoded, encrypted or compressed. Artefacts still exist but live in specialised logs. Registry change monitoring, WMI activity auditing, review of the repository, Sysmon registry value set events, Linux audit records for mounts and executions from shared memory, and unusual process or configuration changes on network devices all help. Legitimate software also stores configuration in these places, so context, location, size and entropy usually separate normal use from abuse.

What you will practise

  • Define fileless storage and explain why it can evade tools that only scan disk files.
  • List common storage locations, including the Windows Registry, WMI repository, event logs and Linux memory backed directories.
  • Describe the artefacts that reveal fileless storage, such as registry value set events and WMI activity records.
  • Explain how this sub-technique differs from in-memory behaviours such as process injection.
  • Distinguish legitimate use of operating system data stores from suspicious encoded or hidden content.
