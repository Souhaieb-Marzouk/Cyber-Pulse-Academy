Shadow Copy Deletion

Detection StrategyVery hardDetection Strategy

Shadow copy deletion detection identifies execution of commands or interfaces that remove volume shadow copies, resize the shadow storage allocation, or disable the recovery services that maintain them, which is a preparatory step that removes the fastest local recovery path before data is encrypted or destroyed. The behaviour matters because it converts a recoverable incident into an unrecoverable one: with local snapshots intact an organisation can often restore without paying, and attackers know this, so recovery inhibition reliably precedes impact activity by minutes to hours and provides a rare opportunity to interrupt the campaign. The telemetry required is process creation with full command line for the binaries and script hosts that expose shadow management functionality, including their parent process and user context; service control manager events recording stop, disable or deletion of recovery related services; scheduled task and service creation records that show the deletion being wrapped into a recurring job; and storage management interface activity where it can be collected. The signal survives common evasion because the operation must reach the volume snapshot provider through a documented interface; an operator may script it, invoke a management tool, call a backup product's own utility with destructive arguments, or load the interface through a signed binary, but the recovery service state or the storage configuration still changes and the initiating process still appears in process telemetry. The detection breaks down in practice because legitimate administration does delete snapshots: storage reclamation, imaging workflows, backup software that prunes old snapshots, and troubleshooting scripts all produce similar commands. Distinguishing malicious from routine use requires context such as the parent process, the account, the timing relative to other suspicious events, and whether the deletion was paired with disablement of recovery services or deletion of backup catalogues. Environments where the command line is not captured, or where the destructive action is taken through a remote management interface that logs nothing locally, will not be covered by process telemetry alone.

What you will practise

  • Explain why recovery inhibition is a high confidence precursor to destructive attacks and how to prioritise it accordingly.
  • Identify the process, service and storage telemetry that reveals shadow copy deletion and service disablement.
  • Distinguish administrative snapshot pruning from malicious deletion using parent process, account and timing context.
  • Correlate deletion activity with simultaneous service configuration changes and backup catalogue tampering.
  • Describe containment actions appropriate at the first confirmed deletion event and the sequencing of evidence collection.
  • Assess detection coverage gaps where deletion is performed through remote management or backup product interfaces.
