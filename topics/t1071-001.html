T1071.001 Application Layer Protocol: Web Protocols

T1071.001Command and ControlExtremeTechnique

Web protocols command and control describes adversary use of HTTP and HTTPS to carry instructions and exfiltrated data between an implant and its controller. The traffic is designed to resemble ordinary web browsing: it uses standard ports, valid transport encryption, conventional request methods and headers, and often a legitimate-looking hostname or a domain fronted by a content delivery network. Because the channel is encrypted and rides on the same infrastructure the business depends on, network inspection cannot rely on payload signatures, and detection shifts toward metadata, timing, and behavioural consistency. Observable artefacts are concentrated in proxy, DNS, TLS, and endpoint data. Proxy logs capture the requested host, full URL path, method, user agent, response size, and byte counts in each direction, and beaconing appears as a strikingly regular interval between requests to the same endpoint from a single internal host, often continuing outside working hours. TLS metadata may reveal a self-signed or unusual certificate, a mismatch between the certificate subject and the requested hostname, or a client that fails to perform expected revocation checks. DNS logs show resolution of the controller domain, sometimes to hosting ranges rather than content networks. On the endpoint, the responsible process is frequently an unexpected binary or a legitimate one with no reason to make network connections, and its command line and file origin provide additional context. Benign web traffic is the largest data source in any environment and includes software updates, telemetry, and cloud applications, several of which also beacon on fixed intervals. Investigations therefore combine multiple weak signals: an unusual process making regular requests, to a domain with a short registration history, with a consistent user agent that matches no deployed software, and either a long-lived connection or a request pattern that persists through nights and weekends.

What you will practise

  • Explain how adversaries shape HTTP and HTTPS traffic to resemble legitimate browsing and why payload inspection fails.
  • Identify beaconing through interval regularity, byte-size consistency, and persistence outside business hours in proxy logs.
  • Analyse TLS metadata such as certificate subject, issuer, and validity to surface infrastructure that does not match its hostname.
  • Correlate endpoint process telemetry with proxy and DNS records to attribute a network connection to a specific binary.
  • Build baselined detection logic that suppresses known update and cloud application beaconing without losing coverage.
  • Map web protocol command and control to ATT&CK and describe the value and limits of each mitigation available.
