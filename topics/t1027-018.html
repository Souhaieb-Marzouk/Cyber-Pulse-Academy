T1027.018 Obfuscated Files or Information: Invisible Unicode

T1027.018StealthExtremeTechnique

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

Invisible Unicode characters are characters that use space in a file but show nothing on screen. Unicode is the system that gives every character a number so computers can store text. Some of those numbers are for characters that are not printed at all. This is a sub-technique of Obfuscated Files or Information. Attackers use them to hide messages, code or their own instructions.

Why should you care?

When you read a script on screen, you cannot see the hidden characters, so it may look harmless. A tool that only reads the visible letters will also miss them. Hidden text can be turned back into working code while the program runs. Some characters also change the direction of the text on screen. A name can look like a harmless document while the computer sees something else. Reviewing text with your eyes alone is not enough.

How it works, in plain steps

  1. The attacker encodes the payload as numbers and turns those numbers into Unicode characters.
  2. They choose characters that take space but produce no visible mark when printed.
  3. They paste those characters into a script, a document or a file name.
  4. The visible part of the text looks normal or looks completely empty.
  5. At run time, JavaScript or similar code reads the characters and their numbers.
  6. It rebuilds the original payload from those numbers and then executes the result.

Real-world example

Picture a museum sign that looks completely blank. A guide explains that the sign is not blank at all. The letters are written in the same colour as the paper, so your eyes slide over them. Only a tool that measures ink can find the words. Try to picture that sign, and imagine what a visitor would miss. Other characters work on direction instead of colour. A line of text can read one way on the wall. The frame is built to be read the other way. Visitors then walk away with the wrong message.

Key takeaways

  • Read suspicious text with a tool that shows character codes, not only with your eyes.
  • Expect hidden characters to survive copy and paste into a terminal or a settings file.
  • Check pasted commands carefully, because on screen order and real order may differ.

In more detail

Invisible Unicode characters let an attacker put content into a file or script that a human reader cannot see. Unicode assigns a code point to every character, and some valid code points render as nothing at all: zero width spaces and joiners, variation selectors, bidirectional formatting controls, and undefined Private Use Area characters that a font draws as blank. Those characters still occupy bytes, so a payload can be encoded as a sequence of them and carried inside text that looks empty or ordinary, then read back at run time through string indexing and character code lookups, and finally rebuilt with a dynamic execution call. Bidirectional controls add a second abuse, because they change how a line of text is displayed without changing the underlying order, so a filename or command can appear to end in one way while the interpreter reads it in another. The technique is effective against visual inspection and against scanners that tokenise only visible characters, and it survives copy and paste, which lets a hidden character set travel into a terminal or configuration file. Defenders counter it by normalising text and stripping non printing characters before review, comparing code point listings rather than rendered text, reviewing raw script content in logs, and checking command text that was pasted from an external source.

What you will practise

  • Explain how invisible Unicode code points can carry hidden data inside ordinary looking text.
  • Identify the character types commonly abused, including zero width characters and bidirectional controls.
  • Explain how this sub-technique differs from encoding a whole file or hiding data inside an image.
  • Describe the analysis steps, such as normalising text and listing code points, that reveal hidden characters.
  • Explain why hidden characters can survive copying between a document, a terminal and a script.
