DET0893 Detection of Link Target

DET0893Detection StrategyVery hardDetection Strategy

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

A link target is the page that a link really opens. Attackers build a fake page first, then send links to it. This detection looks for freshly built pages that copy your brand, and for links whose real destination does not match what the user sees.

Why should you care?

The link is the moment a user decides whether to trust something. A short link or a link on a well known file service hides the real destination, so a careful person can still be fooled. Fake login pages are usually new and short lived, which means they will not be on any blocklist yet. Catching them at delivery gives you time to block them and warn staff.

How it works, in plain steps

  1. The email gateway keeps a copy of each message and the links inside it.
  2. The detection compares the visible link text with the real destination address.
  3. It adds outside context, such as how old the destination domain is and whether it copies your brand.
  4. Links that pass through shorteners or redirect chains are followed in a safe sandbox.
  5. A high score blocks the link, warns the user, and creates a case.
  6. The analyst checks what the page asked for, such as a password, and resets any affected account.

Real-world example

Think of a courier who writes the real address on the parcel but shows you a different label. The label looks right, so you accept the parcel. Only by comparing the label with the address written underneath would you notice the difference. This detection compares the two.

Key takeaways

  • Most fake pages are new and short lived, so reputation lists alone are not enough.
  • Compare what the user sees with where the link really goes, because that gap is the trick.
  • Blocking at delivery is far cheaper than handling a stolen password afterwards.

In more detail

This strategy detects adversary staging of link targets, mapped to MITRE ATT&CK T1608.005 (Stage Capabilities: Link Target). Before a phishing campaign, an adversary prepares the destination that a link will point to: a cloned login page, a file hosted on a legitimate service, a shortened uniform resource locator, or a redirect chain that hides the final site. Because the staging happens on infrastructure you do not own, detection is mostly external monitoring combined with the point of delivery and the point of click. Useful telemetry includes certificate transparency records for brand lookalikes, passive domain name system and reputation data, email gateway logs that capture message links, proxy logs that record the resolved destination and blocked categories, and secure web gateway detonation results. The practical failure mode is scale: thousands of links flow through a large organisation each day, so the rule has to prioritise by brand match, recency, and the gap between the link text and the real destination rather than by attempting to judge every uniform resource locator.

What you will practise

  • Explain how adversaries prepare link targets such as cloned pages and redirectors
  • Identify gateway, proxy, sandbox, and external intelligence telemetry that expose staged targets
  • Detect mismatches between visible link text and the resolved destination
  • Prioritise alerts using brand similarity, domain age, and credential capture behaviour
  • Design a block, warn, and credential reset response for a delivered malicious link
