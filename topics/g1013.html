G1013 Metador

G1013Enterprise GroupExtremeThreat Group

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

Metador is the name for a small and careful group of attackers. Public reports say it targets telephone companies, internet providers, and universities, mostly in the Middle East and Africa. It is known for staying quiet, using its own custom tools, and attacking very few victims at a time. Researchers describe it as a skilled espionage group rather than a criminal gang.

Why should you care?

Most security tools look for files that are already known to be bad. Metador often leaves no such file, because its code runs only in memory. It also looks like ordinary system activity, so a scanner may report that nothing is wrong. That means you cannot rely on antivirus alone. Your monitoring may only check the file system. An intrusion like this can then run for months with no alert, and the lost information may never come back.

How it works, in plain steps

  1. The attackers gain access to a small number of carefully chosen targets, not thousands at once.
  2. They place custom backdoor code that has never been seen by security vendors before.
  3. Much of the code runs only in memory, so no suspicious file is written to disk.
  4. They disguise harmful code as ordinary system files or normal image files.
  5. They send traffic that looks unremarkable, often through services staff already use.
  6. They slowly collect email, documents, and technical designs, then change tools when needed.

Real-world example

Imagine an office where the security guard only checks people carrying boxes. A visitor walks in with empty hands and sits down. He reads every file in the cabinets and leaves with nothing in his arms. He never triggered the rule because the rule looked only at boxes. Metador behaves like that visitor. Its code lives in memory instead of on disk, so the guard who checks only for files sees nothing unusual.

Key takeaways

  • Antivirus alone is not enough, because malicious code can run without ever being saved to disk.
  • Watch outbound network traffic, since quietly sending data out is how espionage causes harm.
  • Note any running program that has no corresponding file on disk, as it deserves a closer look.

In more detail

Metador is a low-volume espionage intrusion set that public reporting describes as one of the more capable and careful operators working against telecommunications, internet service providers, and universities in the Middle East and Africa. Activity has been observed from around 2020 onward. It stands out less for novel exploitation and more for tradecraft discipline: the operators appear to write or maintain their own tooling, including the metaMain backdoor and the Mafalda implant, and they run a small number of intrusions at a time to keep exposure low. Reported behaviour includes running entirely in memory to avoid files touching disk, disguising malicious code as legitimate system files or graphics files, and constant small adaptations that reduce the value of static signatures. Public research has discussed a possible link to a Chinese-nexus contractor-like arrangement, but that attribution is presented as uncertain and contested, so defenders should focus on behaviour rather than a label. Practical detection depends on memory analysis, network egress monitoring, and hunting for unusual processes that have no matching file on disk.

What you will practise

  • Explain what fileless execution means and why it defeats signature based detection.
  • Describe why low volume targeting makes an intrusion harder to discover through statistics.
  • Identify memory and network evidence that would reveal a running implant with no file on disk.
  • Explain how custom tooling shortens the useful life of indicator-based detection.
  • Summarise how public reporting frames this group's attribution and its stated uncertainty.
  • Outline a basic hunting plan for unusual processes on servers in a telecom environment.
