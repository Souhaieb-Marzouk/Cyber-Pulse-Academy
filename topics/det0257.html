DET0257 Detect Mark-of-the-Web (MOTW) Bypass via Container and Disk Image Files

DET0257Detection StrategyVery hardDetection Strategy

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

Mark of the Web is a small note that Windows adds to files downloaded from the internet. The note tells Windows to open the file in a safer, restricted way. Some file types, such as disk images and container archives, do not pass that note to the files inside them. This detection looks for programs that run from such a container soon after it is opened.

Why should you care?

The warning that appears before you open a downloaded program stops many real attacks. If an attacker can hide a payload inside a container, that warning never shows. The user sees a normal-looking folder and double-clicks a file that really came from the internet. Detection at this point catches the attack before the payload runs freely. It also gives you a chance to warn users before they click.

How it works, in plain steps

  1. A file event records that a container file, such as a disk image, was created in a user download folder.
  2. A second event records that a program started from a drive letter that did not exist on the host before.
  3. The rule joins the two events on the host name and a short time window of a few minutes.
  4. It adds a check on the signature status of the program, where that detail is collected.
  5. If both events fit, the rule raises an alert naming the container, the drive, and the program.

Real-world example

Think of a sealed shipping box. Everything sent by post gets a customs stamp on the outside, so the receiver knows it came from abroad. A disk image is like a box that the post office cannot stamp inside. When the receiver opens the box, the items look local and unstamped. A guard who only checks stamps on packages will wave those items through. This detection watches the moment the box is opened, not the stamp.

Key takeaways

  • Container and disk image files can carry content that carries no download warning.
  • The strongest signal is a program running from a freshly mounted volume.
  • Time matters, so keep the window short and tie both events to the same host.

In more detail

This detection strategy targets defense evasion using container and disk image files, tracked as T1553.005. Files that arrive inside an ISO, IMG, VHD, or similar container are often extracted or mounted without inheriting the Mark-of-the-Web zone marker, so the usual protected view prompt never appears. Detection is built from file creation of the container plus process execution from the mounted volume, joined by a short time window and the drive letter. It fails on hosts without file creation telemetry, when the container is mounted by a legitimate virtualization product, or when the payload runs through a signed binary that already sits on the mounted disk.

What you will practise

  • Describe how Mark of the Web is lost when a payload travels inside a container
  • Detect container file creation in user download directories
  • Correlate a mounted volume with process execution from that volume
  • Use signature status to separate legitimate software images from payloads
  • Explain why a disk image mounted by virtualization software is a normal event
