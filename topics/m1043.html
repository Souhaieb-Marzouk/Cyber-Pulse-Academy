M1043 Credential Access Protection

M1043Enterprise MitigationVery hardMitigation

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

Credential Access Protection covers all the ways you stop attackers from stealing logins. Credentials include passwords, the scrambled password hashes a computer stores, session tickets and secret keys. An attacker who steals these can often log in as a real user without breaking anything. This control hardens the places where those secrets are kept, and watches them closely.

Why should you care?

If an attacker steals one administrator credential, they may not need to exploit anything else. They can simply log in and look like a normal user. Stolen hashes and tickets are reusable, so the damage continues after the first machine is cleaned. Many intrusions grow from a single harvested password. Protecting credentials makes the attacker's job much harder and gives you time to notice them.

How it works, in plain steps

  1. You reduce where credentials are stored, so fewer machines keep cached logons in memory.
  2. You limit which accounts and processes may read the memory of the authentication service.
  3. You block or monitor known dumping tools and the debug privileges they rely on.
  4. You move application secrets into a managed vault instead of configuration files.
  5. You watch for unusual reads of logon data, registry hives and ticket files.
  6. You rotate passwords and keys quickly when you suspect they were taken.

Real-world example

Picture a hotel where every room key is made at the front desk. The desk drawer holds blank cards, a machine and a list of which guest has which room. A thief who reaches that drawer can copy any key and walk into any room, so the hotel locks the drawer, logs each use and keeps the blanks in a safe. Managers also notice if someone lingers behind the desk at three in the morning. The lesson is that you protect the place keys are made, not only the doors they open. If a key is copied anyway, you change the locks.

Key takeaways

  • Credentials are a target, so protect the places where they are stored and read.
  • Monitoring matters as much as blocking, because dumping leaves clear traces.
  • Treat a stolen credential as usable until you have rotated it.

In more detail

Credentials are the passwords, password hashes, Kerberos tickets, API keys and session tokens that prove identity, so an adversary who lands on an endpoint usually tries to harvest them. This control reduces that theft by hardening where credentials live and travel: limiting cached logon storage, restricting which accounts and processes may read the memory and registry areas that hold secrets, protecting the local security authority, blocking remote dumping utilities, and moving application secrets into managed vaults. It also covers detection, because extraction produces loud evidence such as processes opening the memory of an authentication service, unexpected handle requests, reads of registry hives that store logon data, and a burst of successful logons that follows a stolen hash. Directory services add their own layers, including tiered administration, restrictions on delegation and hardware backed credential protection. The residual risk is that any credential typed into a compromised machine can still be captured, which is why detection and fast rotation matter as much as prevention.
