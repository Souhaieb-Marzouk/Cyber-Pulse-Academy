DET0171 Detection Strategy for Forged Web Cookies

DET0171Detection StrategyVery hardDetection Strategy

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

A web cookie is a small note your browser keeps after you log in. It proves to a website that you already signed in. Forging a cookie means making a fake note that the website accepts. This detection looks for sessions created without a real login.

Why should you care?

A forged cookie lets an attacker skip the password and the second check on your phone. Nothing looks broken, and no malware runs on the computer. This is how some of the largest cloud intrusions continued after a password change. Detecting it protects accounts that normal login alarms would never flag.

How it works, in plain steps

  1. When you log in, your identity provider gives your browser a signed token. A signed token carries a digital signature so the site can check it is real.
  2. The signature is made with a private key, and only the provider is supposed to hold that key.
  3. Sign-in records show which account signed in, when, from where, with which authentication method and which signing key was used.
  4. The detection looks for a session or token that has no matching sign-in event, or that was signed with a key that is not the current, expected one.
  5. It also watches for new certificate or federation settings added to the provider, because those can let an attacker sign tokens the site will trust.
  6. Alerts are grouped by account and by the signing material used, so an analyst can confirm the token and revoke the session.

Real-world example

Think of a members only club. The doorman checks the stamp on your hand. A forger can copy the stamp design and mark any hand. The doorman sees a perfect stamp, so he waves the person in. The only clue is that the guest book shows no entry for that person, and the stamp ink does not match the club's own pad.

Key takeaways

  • Forged cookies bypass passwords and second factors, so login alarms will not catch them.
  • Compare sessions against real sign-in events, and watch the signing keys your provider trusts.
  • New or changed federation and certificate settings deserve immediate attention.

In more detail

This strategy detects forged web cookies, the technique where an adversary mints a session or authentication token by signing it with a stolen or attacker controlled certificate key, bypassing password and multi-factor authentication entirely. It matters because the resulting session looks like a normal login to most controls: there is no failed password, no prompt and no malware on the endpoint. The telemetry that makes it discoverable is the identity provider sign-in and audit log, which records token issuance, the signing key or certificate thumbprint used, session identifiers and single sign-on events, plus federation configuration changes. The main practical failure is that a correctly forged token is cryptographically valid, so detection must lean on anomalies in signing material, token lifetime, or a session that exists with no matching authentication event.

What you will practise

  • Explain how signed authentication tokens and session cookies are validated by a web application
  • Identify the sign-in and audit fields that reveal token issuance, signing material and session identifiers
  • Detect sessions that exist without a corresponding authentication event in the identity provider
  • Recognise federation trust or signing certificate changes as high priority signals
  • Plan a response that revokes sessions and rotates signing material safely
