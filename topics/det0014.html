DET0014 Detection of Data Staging Prior to Exfiltration

DET0014Detection StrategyVery hardDetection Strategy

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

Staging means putting things in one place before moving them. An attacker copies files from many folders into a single folder, then packs them into an archive such as a compressed file. This detection looks for that gathering step. It uses file records and program records on the computer.

Why should you care?

Copying files inside a machine is faster and quieter than sending them out one by one. Attackers stage data so the transfer can be short and simple. During staging, the evidence is still local and still readable by your tools. After the transfer, an encrypted channel may hide everything. This makes staging the best moment to intervene, and also the last comfortable one.

How it works, in plain steps

  1. The endpoint agent records every file created, together with the process that created it and the folder.
  2. It records the programs that run, so archiving tools and scripting hosts are visible with their command lines.
  3. The detection looks for a pattern where many files are read from different folders and one large file appears.
  4. It checks whether the new file sits in a staging location, such as a temporary folder or a share that the user does not normally use.
  5. It compares the size and count with what the same user and host usually produce.
  6. Related events are grouped into a single alert that lists the source folders and the new archive.

Real-world example

Think of someone leaving a shared office. Instead of carrying items out one at a time, they pile everything into one box by the service door. The pile is visible inside the building. Once the box leaves, only the door log remains.

Key takeaways

  • Staging is a local, visible step that happens before the hidden transfer.
  • The signal is many reads plus one large new file in an unusual location.
  • Backup jobs create the same shape, so host role and schedule matter.

In more detail

This strategy detects data staging, the step where an adversary gathers what they intend to steal into one place before moving it out (T1074, Data Staged). Staging matters because it is the last point at which the theft is still visible on the endpoint: after the transfer begins, the only remaining evidence is network metadata for encrypted traffic. The behaviour to catch is a burst of reads across many unrelated directories followed by the creation of one large file or archive in a location the user does not normally use. Detection works best when file creation telemetry and process creation telemetry are joined, and it fails when backup and compression jobs run constantly on the same host, when file auditing is limited to writes, and when the staging directory is a legitimate temporary folder.

What you will practise

  • Explain why attackers stage data locally before exfiltration.
  • Identify the file creation and process creation telemetry that reveals staging.
  • Describe how to profile normal file creation volume per host and per user.
  • Recognise archiving tool command lines that collect files from multiple directories.
  • Correlate staged files with later network transfers from the same host.
  • Distinguish staging from legitimate backup and deployment activity.
