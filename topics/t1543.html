T1543 Create or Modify System Process

T1543PersistenceExtremeTechnique

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

A system process is a program that the computer starts by itself at boot and keeps running in the background. Windows calls these services, Linux calls them daemons, and macOS runs something similar through launchd. This technique is when an attacker adds or changes one of those entries so their own program starts automatically too.

Why should you care?

If an attacker can register their program as a system process, it starts again every time the machine reboots. You cannot remove the problem by closing a window or killing one process. These entries also run with very high rights, so the attacker often gains more power at the same time. Checking these entries is therefore a standard part of any investigation.

How it works, in plain steps

  1. The attacker places their malicious program somewhere on the disk, often in a temporary or user-writable folder.
  2. They then register that program with the operating system as a new service, daemon, or agent.
  3. The registration stores a name and the full path of the program to run, plus when it should start.
  4. The attacker can also edit an existing entry so a well-known service runs their program instead.
  5. Names are often chosen to look like normal vendor software, which makes the entry easy to overlook.
  6. From then on the operating system launches that program at every boot, usually with high privileges.

Real-world example

Think of a hospital night desk that keeps a printed list of tasks to repeat every night. A stranger cannot stay in the building, so instead they add one line to that list, telling staff to unlock a side door at two in the morning. Every night the list is followed and the door is opened again. The list looks official, the new line is short, and nobody notices unless someone reads the whole page.

Key takeaways

  • System processes restart automatically, so malicious entries survive reboots and even cleanup attempts.
  • They normally run with SYSTEM or root rights, which also gives the attacker privilege escalation.
  • Look for who registered the entry, where the program sits, and whether the path makes sense.

In more detail

Creating or modifying a system-level process means registering the payload with the component that the operating system already starts at boot and keeps alive afterwards. On Windows that component is the Service Control Manager with service entries under the registry key HKLM\SYSTEM\CurrentControlSet\Services; on Linux it is the init system, usually systemd; on macOS it is launchd, which reads property list files. The shared property that makes this attractive is the second execution context: the artifact is written with ordinary user or administrator rights, but the process it names usually starts as SYSTEM or root, so the same change often buys privilege escalation alongside persistence. Defender telemetry is therefore a configuration change plus a start event, never the initial file write alone. Windows evidence sits in service image path values, Sysmon event 13 registry value sets, and Windows Security 4688 process creation where the parent is services.exe; Linux evidence sits in unit files, their modification times, and systemctl or journal records; macOS evidence sits in plist creation, launchctl activity, and process ancestry. Benign activity looks similar because installers register services constantly, so the differentiators are path, signature, publisher, timing relative to other suspicious behaviour, and whether a change to a long-stable entry was ever explained by a patching window.

What you will practise

  • Explain what a system process is on Windows, Linux, and macOS.
  • Describe how an attacker abuses service registration to survive a reboot.
  • Explain how the same change can also escalate privileges.
  • Identify the registry keys, unit files, and plist files that hold these entries.
  • Distinguish a legitimately installed service from a suspicious one during triage.
