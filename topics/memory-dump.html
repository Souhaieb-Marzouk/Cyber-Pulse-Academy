Memory Dump

Incident Response & ForensicsVery hardKeyword

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

A memory dump is a saved copy of everything inside a computer's working memory, called RAM (random access memory). It is written to a file so you can study it later. It holds running programs, open network connections, and recent commands. Some evidence, including fileless attacks, exists only there.

Why should you care?

When you switch a computer off, memory is wiped in seconds. Anything that lived only in memory disappears with it. Attackers know this and use tools that never write a file to disk. If you reboot first, you may destroy the best evidence you had. A memory dump captures it before that happens.

How it works, in plain steps

  1. Keep the machine running, because switching it off erases the evidence you want.
  2. Run a trusted capture tool on the live system and write the image to external storage.
  3. Record the tool name, its version, the exact command, and the time of capture.
  4. Calculate a hash of the image, a fingerprint that shows it has not changed.
  5. Analyze the image to list processes, network connections, and hidden code.
  6. Store the large, sensitive image under strict access control with the case file.

Real-world example

Think about the steam rising from a hot cup of coffee. Once it cools, the steam is gone and you cannot get it back. Memory evidence behaves the same way. A reboot or a shutdown is like waiting for the cup to cool. A memory dump is you sealing the steam in a jar while it is still there.

Key takeaways

  • Memory holds evidence that never touches the disk at all.
  • Do not reboot a suspect machine before you capture its memory.
  • Record the tool, the command, the time, and a hash for every capture.

In more detail

A memory dump is a capture of the contents of a system's physical or virtual memory, preserved as an image file for later analysis. It is the primary source for evidence that never touches disk: running and recently terminated processes, injected code regions, loaded drivers, kernel structures, network connections, command histories, encryption keys and, in many intrusions, the only surviving copy of fileless malware and its configuration. Dumps are taken either from a live host with a trusted acquisition tool, from a virtual machine through the hypervisor, from a cloud instance through provider snapshot or capture mechanisms, or from a crashed system via a configured crash dump or hibernation file. Fidelity depends on the method: hardware-assisted or hypervisor-level capture generally produces the most complete image, while software tools running inside a potentially compromised operating system may themselves be tampered with by a kernel-mode rootkit, so the trustworthiness of the tool and the order of acquisition both matter enormously. A defensible acquisition records the tool and version, the exact command, the memory range captured, a cryptographic hash of the image, the time of capture and the identity of the collector, because the image becomes evidence the moment it is written. Analysis then reconstructs process trees, extracts strings and configuration, looks for injected or unbacked executable regions, recovers credential material, and correlates findings with disk, identity and network evidence. Memory images are large and sensitive, so handling, retention and access controls are part of the process rather than an afterthought.

What you will practise

  • Explain what evidence a memory dump can recover that disk and log sources cannot.
  • Compare live, hypervisor, cloud-provider and crash-dump acquisition methods and their fidelity tradeoffs.
  • Perform a documented memory acquisition that records tooling, scope, capture time and cryptographic hash.
  • Assess whether a dump taken through a possibly compromised operating system can be trusted.
  • Analyse a memory image to reconstruct processes, network connections and injected code regions.
  • Correlate memory findings with disk, identity and network telemetry to build a defensible narrative.
  • Handle, store and retain memory images under access controls appropriate to their sensitivity and legal status.
