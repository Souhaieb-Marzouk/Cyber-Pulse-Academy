DET0346 Detect Screen Capture via Commands and API Calls

DET0346Detection StrategyVery hardDetection Strategy

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

This detection looks for programs that take pictures of the screen. A picture of the screen can hold passwords, emails and internal pages. Most programs never need to do this unless the user asked for it.

Why should you care?

People often have secrets open on the screen that are never saved to a file. One picture can capture all of them at once. The action is quick, and the image can be small enough to hide in a temporary folder. Because many work tools also capture the screen, the rule needs context to be useful. A good alert tells you which program captured the screen and what it did with the image.

How it works, in plain steps

  1. The endpoint agent records calls to the system functions that read the screen into memory.
  2. Each record carries the process image, its parent, the user account and the host.
  3. The rule removes programs that capture the screen only when the user starts a share or a support session.
  4. It then watches for image files written to temporary, downloads or user folders.
  5. It also looks at how often captures happen, because a script may take one image every few minutes.
  6. When the pattern repeats without a user session, the rule raises an alert for review.

Real-world example

Think of a photocopier in an office. Copying a page is normal and nobody notices. But if one person copies a hundred pages at midnight, the copier log becomes interesting. The capture call is the copy, and the count is the clue.

Key takeaways

  • A screen capture can steal data that was never saved to a file.
  • Frequency and timing matter more than a single capture event.
  • Keep an approved list of meeting, support and accessibility tools.

In more detail

This detection strategy covers Screen Capture (T1113), where an adversary takes images of what is displayed on a host to collect credentials, documents or internal application data. The technique matters because the screen often shows content that is never written to disk, such as a password vault, an email body or a database console, and a single image can hold many secrets. Detection relies on endpoint interface call telemetry for capture functions, process creation for capture utilities and scripting hosts, the image files that appear afterwards, and host privacy consent records that show which applications may record the screen. It fails most often because conferencing, support and accessibility tools capture the screen as a normal part of their job.

What you will practise

  • Explain why screen content is valuable to an adversary who already runs code on a host
  • Identify interface call, process and file telemetry produced by screen capture activity
  • Build an allowlist of conferencing, remote support and accessibility applications that capture the screen
  • Write a rule that scores capture frequency, process type and nearby image file creation
  • Triage a match by locating the captured images and checking whether a user session explains them
  • Describe how scoping the rule to non interactive accounts reduces coverage of interactive capture
