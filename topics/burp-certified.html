Explained in plain language

Written for beginners. No security background needed.

Simple definition

This is a practical exam from PortSwigger that tests whether you can find and use weaknesses in real web applications. Burp Suite is a tool that sits between your browser and a website so that you can read and change the traffic. The certification shows you can use that tool, plus your own knowledge, to break into deliberately vulnerable practice sites. It is not a multiple choice quiz.

Why should you care?

Web applications are where most attackers get in, so companies pay well for people who can test them properly. A written exam shows that you remember facts, but this exam shows that you can find a real flaw in a running system within a time limit. That makes your result believable to an employer who has been disappointed by candidates who only passed a quiz. It is a strong step toward a penetration testing or application security career, and it stays valid for several years once earned.

How it works, in plain steps

  1. Learn the core web vulnerability classes first, using the free online labs from the same vendor, such as cross site scripting, which is injecting script into a page that other users will view.
  2. Practise with Burp Suite every day until reading and editing requests in the proxy feels as natural as using a browser.
  3. Solve every apprentice and practitioner level lab in each topic without opening the offered solution, then write short notes on the cause and the fix.
  4. Use mystery labs, which give you no clue about the vulnerability type, because the exam does not label anything for you.
  5. Practise chaining flaws together, since each exam application needs three linked steps rather than one isolated trick.
  6. Take a practice exam to rehearse the clock, then read the vendor's exam hints before you book the real thing.

Real-world example

Think of a website as a hotel with many doors. A normal user walks in the front entrance and goes to their room. A tester tries the fire exit, the staff lift and the window on the second floor. One small gap, such as a window left open for the cleaner, may be enough to get in. The exam then asks for more than entry. You must reach the manager's office using that first foot in the door, and finally open the safe inside. Each step uses a different weakness, and you have four hours to link all three.

Key takeaways

  • You cannot pass by memorising answers, so budget many hours of hands on lab practice before booking.
  • You must own an active Burp Suite Professional licence, because the exam cannot be completed without it.
  • PortSwigger publishes no domain list, so treat the Web Security Academy topic list as your syllabus and check the current exam guidance before booking.

In more detail

The Burp Suite Certified Practitioner exam, code BSCP, is a four hour practical web security certification from PortSwigger, the company behind the Burp Suite testing tool. It is aimed at penetration testers, application security engineers and bug bounty hunters who already work through web vulnerability classes confidently and now want independent proof. The exam gives you two deliberately vulnerable applications, each solved in three stages: get into any user account, reach the admin interface, then read a specific file from the server's filesystem. You must hold an active Burp Suite Professional licence, test unaided, and hand in your Burp project file for analysis. It proves to an employer that you can chain separate flaws into a working exploit and explain the impact. It leads to roles such as application security analyst, penetration tester and security consultant. PortSwigger publishes no numbered exam domains, so the chapters below follow its published exam process and the skills it names for preparation, not a vendor syllabus. Exam domains and objectives

  • Intercept, inspect and modify web traffic with a proxy tool during a live test
  • Identify and exploit common injection, authentication and access control weaknesses in running applications
  • Chain two or more separate flaws together to reach a goal that neither flaw allows on its own
  • Escalate a foothold on the server side in order to read files or run commands
  • Deliver an attack that another user or an administrator will trigger in their own session
  • Work methodically against unlabelled targets and keep a clean record of the testing process
