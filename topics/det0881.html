DET0881 Detection of SEO Poisoning

DET0881Detection StrategyVery hardDetection Strategy

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

Search engine optimisation poisoning means an attacker pushes their own page to the top of search results. A person searching for a popular tool finds the fake page and downloads a harmful file. This detection looks for the download and the file that runs afterwards.

Why should you care?

The user trusts a search result more than an email. They chose to look for the tool themselves. No message needs to pass your mail filter. The harmful file often arrives inside an archive, so the first evidence appears on the endpoint. Catching the moment a downloaded file starts a program lets you block it before the malicious code runs widely.

How it works, in plain steps

  1. Your web proxy records the page the user came from and the address of the file they downloaded.
  2. Your endpoint agent records the file being written and any process that starts from it.
  3. The rule links the download to the process that follows within a short time window on the same host.
  4. It adds context such as the age of the site, the file type and how the file was launched.
  5. When a download leads straight to execution, the alert shows the page, the file and the process so the analyst can contain the host.

Real-world example

Think of a market where a new stall appears beside a well known one and copies its sign. Shoppers who came for the known brand walk to the wrong stall and buy a box they never open. The market register shows the stall, the sale and the time. The shoppers cannot tell the difference, but the register can.

Key takeaways

  • The victim starts this attack, so mail controls give no warning at all.
  • The strongest signal is a download followed by execution within seconds.
  • Domain age and referrer data are the cheapest way to add context to the alert.

In more detail

This detection strategy covers search engine optimisation poisoning, where an adversary shapes search results so that a query for a popular download, tool or document returns a page they control. It matters because the victim chooses the visit themselves, which removes the need for a phishing email and defeats many mail controls, and because the resulting traffic looks like ordinary web browsing until a file is written and run. The telemetry that makes it possible includes web proxy logs with referrer and destination fields, DNS query logs for newly registered domains, endpoint process creation showing an archive or document reader spawning a child process, and file creation events recording what was extracted. It fails in practice because you cannot see the search results themselves, so the detection rests on inference from network and endpoint events, and because ordinary search driven downloads look exactly the same.

What you will practise

  • Explain how search result manipulation replaces a phishing email as a delivery path
  • Name the proxy, DNS and endpoint fields that record a search driven download
  • Correlate a download event with the process that runs from it on the same host
  • Assess the risk of an archive or script download using domain age and file type
  • Describe user awareness steps that help staff recognise a poisoned search result
