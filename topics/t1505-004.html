T1505.004 Server Software Component: IIS Components

T1505.004PersistenceExtremeTechnique

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

Internet Information Services, usually shortened to IIS, is the web server program built into Windows. It accepts add-on pieces called components, such as filters and modules, so developers can change how it handles web requests. This technique is about an attacker installing a hidden component so their own code runs inside the web server.

Why should you care?

A component inside the web server sees every request and response that reaches the site. It can change what visitors receive, run commands on the server, or keep a quiet channel open to the attacker. Because it is part of the web server configuration, it loads again after every restart. Normal website monitoring may show a healthy site while the hidden component works in the background, so you need to check configuration and files.

How it works, in plain steps

  1. The attacker gets administrator or web server rights, often by using a flaw in the website or stolen passwords.
  2. They build or bring a dynamic link library, which is a Windows file full of reusable code.
  3. They place the file in a folder the web server can read, sometimes inside the website folder itself.
  4. They register it as a filter, module or extension in the IIS configuration, which is stored on the server.
  5. The web server loads the component into its worker process, so the hidden code runs with the identity of the site.
  6. The component examines or rewrites web traffic and reloads each time the service starts.

Real-world example

Think of an office mailroom with a rule that extra sorting machines may be added by any manager who fills in a form. Someone installs an unmarked machine that opens every envelope, copies the contents, and sends them out the back door. Letters still arrive on time, so the mailroom looks fine until somebody reviews the machine list and sees one that nobody ordered.

Key takeaways

  • IIS keeps a configuration list of filters and modules that is worth reviewing.
  • Compare dynamic link libraries in web folders against your known baseline.
  • A web server restart after an undocumented configuration change deserves a look.

In more detail

IIS Components is the Windows web server branch of Server Software Component persistence. Internet Information Services supports three extension surfaces: ISAPI extensions, which handle requests mapped to them; ISAPI filters, which observe or alter every request and response passing through the worker process; and IIS modules, introduced with IIS 7.0, which are native dynamic link libraries that register themselves or managed code that hooks the request pipeline. All of these run inside the worker process with the identity of the site, so a malicious component inherits the trust of the web server and can read request bodies, rewrite responses, execute commands, or relay command and control traffic. Registration state lives in the IIS configuration store, which is why a component can be installed once and reload with the service on every restart. Detection is almost entirely about configuration and file integrity: new filter or module entries in the IIS configuration, unsigned or unexpectedly located dynamic link libraries in web directories, components registered by commands that differ from the standard administration tooling, and worker process restarts that immediately follow a configuration change. Legitimate modules are installed with software deployments and are backed by change records; a component that appears between deployments without documentation is the signal.

What you will practise

  • Name the IIS extension surfaces an attacker can abuse for persistence.
  • Explain why components in the web server process inherit the trust given to the site.
  • Identify IIS configuration and file system artefacts left by malicious components.
  • Tell an approved module installation apart from an undocumented one.
  • Describe how to baseline IIS components so changes become visible.
