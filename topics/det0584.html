DET0584 Detection Strategy for Resource Forking on macOS

DET0584Detection StrategyVery hardDetection Strategy

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

On macOS a file can carry two parts: the visible content and a second hidden part that stores extra information. Malicious code can be placed in the hidden part. This detection looks for files whose hidden part is written, especially in unusual places.

Why should you care?

Many tools read only the visible part of a file, so hidden content passes review. It can also travel with a file into an archive and back out. Attackers use this to keep a payload on disk without obvious signs. Catching the hidden write gives you a chance to inspect it properly.

How it works, in plain steps

  1. The endpoint agent records every program that runs, with its full command line.
  2. It also records files created and changed, including companion files that start with a dot and underscore.
  3. The rule matches commands that write directly into a file's hidden part.
  4. It checks whether the affected file sits in a user folder, a temporary directory, or a download folder.
  5. The agent reads the hidden content and looks for script or executable material.
  6. Suspicious findings are sent to your security information and event management (SIEM) platform.

Real-world example

Think of a delivery box with a false bottom. The courier checks the label, weighs the box, and sees nothing unusual. The real contents sit in the hidden compartment. Only a checker who opens the base of the box, not just the lid, finds what is really being shipped.

Key takeaways

  • A resource fork is a hidden second part of a file that most simple scanners ignore.
  • Companion files that begin with a dot and underscore are the visible clue worth watching.
  • The location of the file decides whether the write is normal or suspicious.

In more detail

This strategy detects T1564.009, Resource Forking, a macOS hiding technique in which an adversary stores payload or data in the resource fork of a file, for example inside an AppleDouble companion file, rather than in the visible data fork. Many scanners, archive tools, and reviewers only inspect the primary stream, so hidden content survives both inspection and casual copying. Detection draws on endpoint process telemetry for the commands that create or extract these files, file system events for companion file creation, and content inspection of extended attributes. The failure mode is that legitimate macOS software and archives constantly create companion files, so volume and path context must be filtered carefully.

What you will practise

  • Describe the difference between a data fork and a resource fork on macOS
  • Recognise the file naming pattern produced when resource fork data is written to a non-native file system
  • Identify the command line tools that create or extract resource fork content
  • Judge whether the affected path makes a resource fork write suspicious
  • Plan an inspection step that reads the hidden content safely
