TTP

Threat IntelligenceExtremeKeyword

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

TTP stands for tactics, techniques and procedures. It describes how an attacker behaves, not the specific tools they used. A tactic is the goal and a technique is the method. A procedure is the exact way one group carries it out. Behaviour changes slowly, so it stays useful for a long time.

Why should you care?

Attackers swap tools constantly. A web address can change in minutes and a file can be rebuilt in seconds. Blocking those things gives you short lived protection. Behaviour is different. An attacker still needs to log in, move between machines and take data out. If you learn to spot those patterns, your detection lasts far longer. It also hurts the attacker more, because changing habits is hard.

How it works, in plain steps

  1. Read the report and find the goal. Was the attacker trying to break in or to steal data?
  2. Name the technique, which is the method used to reach that goal.
  3. Record the procedure, meaning the exact commands, order and habits of that group.
  4. Find the telemetry, which is the log record that would capture this activity.
  5. Write a detection rule, then check how much normal work looks the same.
  6. Track coverage, so you can see which techniques you can spot and which are blind spots.

Real-world example

Think of how a pickpocket works. The tools may be a coat, a bag or simply a pair of hands, and those change. The method does not. They choose a crowd, distract the target and slip away quickly. Guards who learn the method catch thieves using any tools. Guards who only memorise one coat miss everyone else. Defence based on behaviour studies the method, not the coat.

Key takeaways

  • TTP describes attacker behaviour, which outlives tools and network addresses.
  • Turn behaviour into detection rules, and check how much normal activity looks similar.
  • Measure which techniques you can detect, then hunt the blind spots you find.

In more detail

A TTP is the behavioural layer of threat intelligence: the tactics, techniques and procedures an adversary uses to achieve an objective, expressed independently of the specific tools, hashes or domains observed in any single intrusion. Tactics describe the goal, such as gaining initial access or exfiltrating data. Techniques describe how the goal is achieved, such as abusing a valid account, injecting into a trusted process, or tunnelling command and control inside a protocol the network already permits. Procedures describe the specific implementation an actor prefers, including the exact command line shape, the order of operations and the operational security habits around them. Because TTPs are constrained by how software and operating systems actually work, they change far more slowly than infrastructure. An actor can re-register a domain overnight but cannot easily abandon the need to persist after reboot or to move laterally with stolen credentials. That asymmetry is why behavioural intelligence retains value for months or years while atomic indicators decay in hours, and why the widely used pyramid of pain ranks TTPs near the top for the difficulty they cause an adversary when defenders detect them. In practice, TTP intelligence is codified as technique mappings, detection-as-code rules, hunting hypotheses and control requirements rather than as blocklists. The defensive translation step matters: a report stating that an actor abuses signed system binaries is not actionable until an engineer identifies which telemetry would capture it, which legitimate activity resembles it, and what the detection will cost in analyst time. TTP-driven detection also supports coverage reasoning, because defenders can measure which techniques are instrumented and which are blind spots. The main risks are over-generalisation, where a technique is treated as unique to one group, and abstraction drift, where a mapping is recorded without the procedure detail that would make it detectable.

What you will practise

  • You will be able to separate tactics, techniques and procedures and explain why each layer has a different detection lifetime.
  • You will be able to translate a prose intrusion report into technique mappings and concrete telemetry requirements.
  • You will be able to explain why TTP-based detection resists adversary infrastructure rotation better than indicator matching.
  • You will be able to judge when a technique mapping is too generic to be actionable and what procedure detail would fix it.
  • You will be able to derive hunting hypotheses from a technique and define what evidence would confirm or refute them.
  • You will be able to measure detection coverage by technique and identify blind spots that no current rule addresses.
