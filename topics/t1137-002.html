T1137.002 Office Application Startup: Office Test

T1137.002PersistenceExtremeTechnique

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

Office Test is a registry setting that tells Microsoft Office to load a chosen library file whenever an Office program starts. A registry is the Windows database of settings. This key is not created by a normal Office installation, so it only appears when someone adds it on purpose.

Why should you care?

The library file runs inside Office itself, so it starts with the same trust that Office has. There is no document to open and no macro warning to click past, which removes the usual warning sign. Because the key should not exist on a healthy machine, it is easy to check for once you know about it. Attackers also gain a foothold that returns after every restart.

How it works, in plain steps

  1. The Office Test registry key exists for testing and should never appear on a healthy computer.
  2. An attacker adds the key and a value that names a library file to load.
  3. The key can be set for one user, or for the whole machine, which reaches everyone.
  4. The named library file is placed in a folder the attacker can write to.
  5. Whenever Word, Excel or another Office program starts, Office loads that library.
  6. The code inside runs as the logged on user and inherits the trust given to Office.

Real-world example

Imagine a hotel where a maintenance note is taped inside the staff cupboard door. The note says to unlock room twelve every morning. Nobody questions it, because it is stuck inside the cupboard the building uses for its own instructions. The guest never had to ask for anything, and the night manager simply follows the cupboard note on every shift.

Key takeaways

  • The Office Test key is not part of a normal installation, so its presence is suspicious.
  • The key makes Office load a library file with no document and no macro prompt.
  • Check both the per user and the whole machine versions of this registry key.

In more detail

Office Test is the registry based variant of Office persistence, and it works by creating a key that Office does not write during a normal installation. The key sits under the Office branch for the current user or for the whole machine and tells Office to load a chosen library file every time an Office application starts, a capability that appears to exist for testing and debugging during development rather than for production use. Because the key is absent by default, its presence is itself the anomaly, and the value it holds points at an arbitrary path, so the attacker can name a library in a user writable folder or on a remote share. Once Office starts, that library is loaded into the Office process, which means the code runs under the identity and privileges of the person who opened the application and inherits the trust that Office already enjoys. The forensic picture is short and clear: creation of the test registry key, a library file in an unusual location, and Office processes loading a module whose path does not match any installed add-in. Detection is practical because the baseline is simple, since a healthy system has no such key at all.
