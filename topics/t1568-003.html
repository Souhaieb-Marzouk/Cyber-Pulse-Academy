T1568.003 Dynamic Resolution: DNS Calculation

T1568.003Command and ControlExtremeTechnique

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

Dynamic resolution means malware works out its contact address instead of storing one. This version uses a normal name lookup and then calculates the port from the answer. The malware does a small sum on parts of the address it receives back. The result tells it which port to use for its hidden connection.

Why should you care?

Firewalls often allow certain ports, such as those used for secure web traffic. If the malware works out an allowed port at run time, those rules do not stop it. The domain it looks up may be completely innocent, so blocklists do not help either. Defenders need to compare each connection with the service that should really be running there.

How it works, in plain steps

  1. The malware asks the name system for a domain that often belongs to a real, harmless service.
  2. The answer contains an address, for example one whose first parts are the numbers 10 and 20.
  3. The malware takes parts of that address and does simple arithmetic, such as adding them together.
  4. The result becomes the port number that the malware uses for its command and control connection.
  5. It then connects to that port, which may already be allowed through the firewall.
  6. Defenders see a connection on a port that does not match the usual service for that address.

Real-world example

Imagine a note that says only, find the blue book. Inside the blue book, on the first page, is a number. That number is the locker you should open. The note itself looks harmless, and the locker changes whenever the book changes. Malware that calculates a port works like this: the name lookup is the harmless note, and the address inside it decides which door opens.

Key takeaways

  • A host connecting on a port that does not match the destination service deserves investigation.
  • Join name lookups, network flows and process activity together, because no single record shows the trick.
  • Keep a service inventory so that you know which ports each application may legitimately use.

In more detail

DNS Calculation derives the command and control port from values inside an ordinary Domain Name System (DNS) answer rather than using a fixed port or the returned address itself. A documented implementation takes the first three octets of an address in the response and performs simple arithmetic on them to compute the destination port, so the implant resolves a normal looking name and then connects to a port that defenders had no reason to expect, often one that egress rules already permit, such as those used for web or name service traffic. Because the queried domain can be reputable and the connection may reach a legitimate address, reputation based blocking is weak here. The clearest signals are indirect: a host connecting to a port that does not match the service normally associated with that address, encrypted traffic whose certificate does not match the name, a process resolving a name and then talking to unrelated infrastructure, and port numbers that differ between victims while the queried name stays the same. Separating this from legitimate activity requires a service inventory, plus flow records that join the query, the connection and the process.
