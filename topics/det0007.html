DET0007 Detection of Domain Trust Discovery via API, Script, and CLI Enumeration

DET0007Detection StrategyVery hardDetection Strategy

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

A trust is a link between two directories that lets accounts from one work in the other. Attackers look up these links to find an easier way into a bigger network. This detection watches for programs that list or describe those links. Such listing is not needed for normal daily work on most computers.

Why should you care?

Trust information tells an attacker where to go next and which accounts are worth stealing. It is cheap to gather and hard to notice, because it uses built in tools that are already on the machine. Many intrusions pause at this stage, so catching it early can stop a breach before it spreads. Ordinary users never run these commands, which is what makes the behaviour stand out.

How it works, in plain steps

  1. The endpoint agent records each program that starts, together with its full command line and its parent process.
  2. Your scripting logs record the same activity when a person runs a query through a scripting interface instead of a command.
  3. The detection matches known trust query utilities and query interfaces against the recorded command lines and script blocks.
  4. It checks the account that ran the query and the host role, because domain controllers and identity administrators are expected to run some of them.
  5. It looks at how often the query ran, since a burst of different queries in a short time suggests a person exploring.
  6. Matching events are grouped by host and account so that one alert shows the whole pattern of discovery.

Real-world example

Imagine a courier studying the internal phone list of a large company. Reading the list is allowed for staff. A visitor who copies the whole directory, then studies the list of branch offices that share a mail room, is planning something. The list itself is not the crime. The interest is.

Key takeaways

  • Trust discovery is planning activity, and it often comes before lateral movement.
  • The tools are built in and legitimate, so host role and parent process decide the verdict.
  • Group related queries into one alert to see the shape of the exploration.

In more detail

This strategy detects domain trust discovery, the reconnaissance step where an adversary maps which domains trust each other and which rights flow across those trusts (T1482, Domain Trust Discovery). Trust relationships define the blast radius of a compromise, so this step usually signals that an operator is planning lateral movement rather than running opportunistic malware. Detection is achievable because trust enumeration is exposed through a small number of well known command line utilities, scripting interfaces and directory APIs, and because these calls happen from hosts that rarely perform them. The main failure is that some administrative tooling and directory health checks run the same queries on a schedule, so the rule must be scoped by host role and by the parent process.

What you will practise

  • Explain what a directory trust is and why its details guide lateral movement.
  • Name the command line utilities and scripting interfaces commonly used to enumerate trusts.
  • Identify the endpoint and scripting log fields needed to detect trust queries.
  • Describe how to use host role and expected administrators to separate legitimate checks from reconnaissance.
  • Recognise a burst of varied discovery queries as a stronger signal than a single query.
  • Plan a hunting baseline of which hosts legitimately enumerate directory relationships.
