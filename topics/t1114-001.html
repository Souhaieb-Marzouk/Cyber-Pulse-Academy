T1114.001 Email Collection: Local Email Collection

T1114.001CollectionExtremeTechnique

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

This is email theft from a single computer. Mail programs keep a copy of your messages in a local data file on the disk. An attacker who can read that file gets the messages inside it. Sub-technique version of email collection, focused on the device rather than the mail server.

Why should you care?

It differs from the parent technique because nothing has to be stolen from the mail service at all. If an attacker already has file access on a laptop, the mailbox comes with it. Mail files also grow large, so a single copy can contain years of history. Standard file permissions protect them only as well as they protect the logged in user and any administrator.

How it works, in plain steps

  1. The mail client stores messages locally in a database file inside the user profile.
  2. Cached and IMAP accounts use one file type, while personal stores use another.
  3. An attacker with user or administrator access locates those files by their usual paths.
  4. The files are copied to a staging folder, an archive or a temporary directory.
  5. If the user is logged in, the attacker may instead read the mailbox through the client.
  6. The copy is later opened with forensic or mail conversion tools to extract messages.

Real-world example

A shared flat keeps a folder of household letters in a kitchen drawer. A visitor with access to the drawer photographs the whole folder in one go. Nobody notices the letters are still in place. The visitor studies the copies at home, at leisure, without ever returning to the kitchen.

Key takeaways

  • Local mail files are as sensitive as the mailbox itself, so protect the endpoint that holds them.
  • The tell is a bulk read or copy of a mail store, since normal use touches it in small pieces.
  • Sub-technique note: this is device level theft; the parent also covers theft from mail servers.

In more detail

Local email collection is the client side half of email theft: the adversary reads mailbox data that already sits on a compromised workstation rather than querying a mail server. Outlook keeps messages in local database files, with .ost files backing cached and IMAP accounts and .pst files used for personal stores such as POP accounts or exports, and both typically live under the user profile in the Outlook Files folder or a local application data path. Because these files are ordinary user documents, anyone with the user's file access, or with administrator rights, can copy them wholesale; they may also be read through the mail application itself if a session is already open. What makes the behaviour recognisable is access pattern rather than content: the mail store is rarely read end to end during normal work, so a large sequential read or a copy to a staging folder, a temporary directory or an archive is the interesting event. Analysis usually happens off host later, using the stolen file rather than the running mailbox.

What you will practise

  • Explain how mail clients store messages locally and which file types are involved.
  • Describe the usual locations of local mail store files within a user profile.
  • Distinguish local email collection from server side collection of the same mailbox.
  • Identify file access telemetry that reveals bulk reading or copying of a mail store.
  • Outline how a copied mail store is analysed after removal from the original host.
