Endpoint Detection and Response

Endpoint & MalwareHardKeyword

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

Endpoint detection and response, or EDR, is software that watches each computer in a company. It records what programs run, what files change and what the machine connects to. When something looks dangerous, it alerts the security team. The team can then isolate that computer with one click.

Why should you care?

Old antivirus tools only recognise bad files they have seen before. Attackers now use ordinary tools in unusual ways, so new files often look harmless. EDR notices the strange behaviour instead. It also keeps a record, so investigators can see how an attack started. Without it, a stolen laptop can reveal very little about what the attacker did.

How it works, in plain steps

  1. A small agent runs on every computer and records important system events.
  2. The events are sent to a central console, where they are stored and linked together.
  3. Detection rules and analytics look for behaviour that matches known attacker patterns.
  4. An alert shows the whole story: what ran, what started it and what it touched.
  5. An analyst investigates and can isolate the machine or stop the harmful process.
  6. The same stored data is searched to find other computers with the same problem.

Real-world example

Think of a night guard in an office tower. He ignores nothing, but he cares about actions rather than faces. A cleaner with a valid badge carries a filing cabinet to the basement at three in the morning. The guard stops this, even though the badge is real. The guard can also lock a floor instantly and then review the camera history.

Key takeaways

  • EDR watches behaviour, not just known bad files, and keeps the history.
  • Alerts are useless without people who triage and respond to them.
  • Isolation and fleet-wide search turn a single detection into a full response.

In more detail

Endpoint detection and response, or EDR, is a class of tooling that continuously records activity on hosts such as laptops, servers and virtual machines, then gives analysts the ability to investigate and act on what it recorded. Where classic antivirus matches files against known bad signatures, EDR focuses on behaviour: process creation with full command lines and parent relationships, file and registry changes, script execution, network connections, driver loads, and authentication events. Those events are normalised, enriched and usually shipped to a central platform, which applies detection logic, threat intelligence lookups and simple analytics to raise alerts. The response half is what distinguishes it from pure monitoring: an analyst can isolate a host from the network, kill a process, quarantine a file, collect forensic artefacts, or run a hunt across the whole fleet using the same event data. Endpoint agents also make the data useful after the fact, since the recorded history often answers what happened before a detection fired. The mistake people usually make is buying the platform and never staffing the alert queue, because unread EDR telemetry provides no protection at all.

What you will practise

  • Explain what endpoint detection and response is and how it differs from signature-based antivirus.
  • Describe the kinds of host activity an endpoint agent records and why each matters.
  • Explain how centralised telemetry supports investigation, hunting and response actions.
  • Identify the operational requirements, especially staffing, that make an EDR deployment effective.
  • Recognise common failure modes such as untuned detections or agents missing from key hosts.
