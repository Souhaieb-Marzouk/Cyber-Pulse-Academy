DET0298 Detect Archiving via Utility (T1560.001)

DET0298Detection StrategyVery hardDetection Strategy

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

This rule looks for programs that pack many files into a single smaller file. That action is called archiving. Attackers use it to gather stolen documents into one package before sending it out. The rule is not about the tool, because your own staff use the same tools. It is about where and how the tool is used.

Why should you care?

Copying thousands of files one by one is slow and easy to notice. Packing them into one archive is fast and looks less suspicious on the network. If the archive is protected with a password, a security scanner cannot read what is inside it. Catching the moment of packing gives you a chance to stop the theft before it leaves.

How it works, in plain steps

  1. The host agent records every program start, including the full text of the command that was used.
  2. The rule checks whether the program is a known archiving tool. Examples include a compression utility, a scripting engine or a backup tool.
  3. It reads the command line for signs of bulk collection. Look for a whole folder, a wildcard or a long list of paths.
  4. It also checks for options that add a password or a strong key to the new file.
  5. At the same time it looks for the new archive file on disk. It checks temporary and public folders too.
  6. If a bulk archive appears in an unusual location, made by an unusual account, the system alerts an analyst.

Real-world example

Think of a warehouse worker who must move a whole aisle of goods. They do not carry boxes one by one through the front door. Instead they stack everything on one pallet and wrap it in plastic. The wrapper hides what is on the pallet. A forklift moving a full pallet is still easy to spot, and this rule watches for the wrapping moment.

Key takeaways

  • Archiving is normal, so the alert is about context: unusual account, unusual folder, or a password protected output.
  • The command line is the most valuable piece of evidence because it shows what was collected.
  • A large archive in a temporary or staging folder is far more interesting than one in a normal project folder.

In more detail

This detection strategy targets archiving collected data with a built-in or third-party utility, mapped to T1560.001, which adversaries use to compress and often password protect files before exfiltration. It matters because archive creation is the last quiet step before data leaves the network: a single command can turn thousands of documents into one file, and encryption hides the content from inspection. The telemetry that makes it detectable is process creation with full command lines, file creation events for archive extensions, and the file access patterns that precede them. The main way it fails in practice is volume and ambiguity: archiving is a completely normal business activity, so a rule that alerts on every archive utility produces overwhelming noise, and a rule tuned to one command line misses the same behaviour performed through a scripting language or a renamed binary.

What you will practise

  • Explain why adversaries archive data before exfiltration and how that changes the risk picture.
  • Identify the process and file creation telemetry that reveals archive creation.
  • Interpret archive utility command lines to recognise bulk collection and password protection options.
  • Separate routine business archiving from collection staging by using account, path and volume context.
  • Define a baseline of approved archiving jobs in your own environment before enabling alerts.
  • Describe follow-up steps such as checking outbound transfers for the newly created archive.
