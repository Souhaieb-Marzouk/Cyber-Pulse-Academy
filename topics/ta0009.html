TA0009 Collection

TA0009EnterpriseExtremeTactic

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

Collection is when an attacker gathers the information they want and puts it in one place. They search shared folders, mailboxes, databases and cloud storage. Then they copy the chosen files into a single folder or archive. This staging step happens before the data leaves your network.

Why should you care?

This is often your last real chance to stop a data theft. Once the files are packed and sent, you can only measure the damage. Collection leaves traces, because reading and copying many files is not quiet. The challenge is that backups and normal reports also read many files. Look for copying that does not match a person's usual work.

How it works, in plain steps

  1. The attacker searches drives and shared folders for words like invoice, salary or password.
  2. They pick the files that look valuable and readable with the access they have.
  3. They copy everything into one folder, often on a machine they already control.
  4. They compress that folder into a single archive, which makes it smaller and easier to move.
  5. Defenders notice unusual file reads and large new archives on machines that rarely have them.

Real-world example

Imagine packing for a move. You walk through the house and choose what is worth taking. You put it all into a few boxes by the front door, ready for the van. The boxes sit there while you fetch the car. A neighbor who peeks inside sees your belongings gathered in one spot. That is the moment when someone could still stop the move. Collection is the packing, and it happens before the van arrives.

Key takeaways

  • Collection is the packing step, done before data leaves your network.
  • Bulk reading and new archives are the clues to watch.
  • Always compare file access with what that person normally does at work.

In more detail

Collection is the tactic covering the adversary's staging of information of interest before exfiltration, including locating, gathering, and organising data from endpoints, file shares, mail systems, databases, and cloud storage. Behaviours include searching volumes and shares for keywords and file extensions, archiving and compressing selected files into a single staging container, capturing screen or clipboard content, collecting email from mailboxes, dumping database contents, copying data from software-as-a-service platforms into personal locations, and using built-in utilities to enumerate and read files at scale. This tactic is where defenders still have a reasonable chance of catching an intrusion before data leaves, because collection is usually noisy relative to normal user behaviour. Useful telemetry includes file access and creation events with volume metrics, archive utility execution and the size of what it produced, bulk download and share actions in cloud audit logs, mailbox export and delegated access events, and abnormal read patterns on file servers or databases. Detection in isolation is difficult because archiving and bulk reads are ordinary business activities for backup software, developers, finance teams, and administrators. What distinguishes malicious collection is concentration and mismatch: a single workstation compressing hundreds of documents it has never touched before, a service account reading an entire database schema, or a user downloading their whole mail archive shortly before resigning. Judging those cases requires peer-group baselines and business context as much as technical rules.

What you will practise

  • Describe how adversaries locate and stage data across endpoints, file shares, mail systems, databases, and cloud services.
  • Identify the telemetry that reveals collection, including file access volume, archive creation, mailbox export, and bulk download events.
  • Distinguish malicious staging from legitimate backup, development, and administrative behaviour using peer-group baselines.
  • Build detections that weight data volume and rarity of access over the mere existence of an archive utility.
  • Explain how data classification and least-privilege access reduce what collection can reach in the first place.
  • Connect a confirmed collection event to an exfiltration hypothesis and the evidence needed to test it.
