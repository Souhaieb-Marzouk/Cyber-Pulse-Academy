T1059.011 Command and Scripting Interpreter: Lua

T1059.011ExecutionExtremeTechnique

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

Lua is a very small scripting language, a set of instructions a program can read and follow. It was made to be built into other programs rather than to stand alone. This technique is about attackers using Lua to run their own code.

Why should you care?

Because Lua lives inside other programs, its code can run under a name you already trust. A game or a management tool may suddenly do something new. There may be no separate program file to notice. If you only watch for strange program names, this kind of activity can pass you by.

How it works, in plain steps

  1. The attacker writes Lua code, or takes an existing script and changes it.
  2. It can run through a small stand-alone interpreter program started from a terminal.
  3. It can also be loaded by a larger application that already contains a Lua engine.
  4. In the harder case, the attacker replaces a Lua library file beside that application.
  5. The trusted application then loads the changed file and runs the attacker code.
  6. Because the host is trusted, the network traffic looks like it came from that program.

Real-world example

Think of a hotel where guests may leave written instructions for the cleaner. The cleaner is trusted and has a master key. A guest writes a note. It says please empty the safe in room twelve and leave the contents at the front desk. The cleaner follows it, because the note is in the usual place and on the usual paper. Lua code hidden in a trusted program works like that note. The messenger is trusted, so nobody questions the message.

Key takeaways

  • A trusted program can still run harmful code if it loads a changed add-on.
  • Watch for library files written next to applications in user folders.
  • Network traffic from a game or appliance process is worth questioning.

In more detail

Lua is a very small scripting language built to be embedded inside other programs, and that design choice is exactly what makes it useful to an intruder. There are three distinct execution shapes. A stand-alone interpreter binary can run .lua files or accept commands from a terminal, giving a compact cross-platform scripting engine that leaves no compiler artefacts. A host application that already embeds Lua, such as a game, a network appliance, or an administrative tool, can be handed a script through its own plugin or configuration path, so the code executes inside a trusted process. The third shape is substitution: an attacker replaces or adds a Lua library or binding next to a legitimate program so that the program loads the tampered component and executes attacker logic at startup, a pattern seen in real malware families that hijack a signed host to gain a trusted execution context. Evidence is therefore split between easy and hard. Process creation telemetry captures a stand-alone interpreter and its script path, and file telemetry captures dropped .lua files and newly written library files beside an application. The harder signals are behavioural: a game or appliance process suddenly making network connections, or loading a library from a user-writable directory, rarely has a benign explanation.
