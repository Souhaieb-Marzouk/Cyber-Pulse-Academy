DET0180 Detection Strategy for T1547.009 – Shortcut Modification (Windows)

DET0180Detection StrategyVery hardDetection Strategy

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

A shortcut is the small arrow icon that opens a program, such as the one on your desktop. An attacker can edit it so it runs something else. This detection looks for shortcut files that were changed or created in the wrong place.

Why should you care?

People click shortcuts without thinking, and security tools often only check real programs. A changed shortcut can point to a malicious file while keeping the same name and icon. It can also start automatically from a startup folder. Spotting the edit is easier than cleaning up the infection later.

How it works, in plain steps

  1. Windows writes a file when a shortcut is created or changed, and endpoint monitoring records that event.
  2. The detection reads where the shortcut sits, such as the desktop or a startup folder.
  3. It reads the shortcut's target path, arguments and working directory, because those show what will run.
  4. It checks who or what made the change by looking at the program that wrote the file.
  5. It watches for the shortcut being opened, which appears as a process whose parent is the shortcut file.
  6. A change in a startup location, or a target in a temporary or user folder, is raised for urgent review.

Real-world example

Think of a labelled drawer in a workshop. The label says screws, and everyone trusts it. If someone moves the label to a drawer of broken glass, workers still reach in without looking. Nobody checks the label until someone gets hurt.

Key takeaways

  • A changed shortcut can run anything while keeping a trusted name and icon.
  • Location matters most: startup folders and desktop shortcuts are high value.
  • Read the target path and arguments, not just the shortcut file name.

In more detail

This strategy detects modification of shortcut files on Windows, where an adversary edits the target, arguments or working directory of a link file so that opening it starts attacker code instead of the intended program. It matters because users trust shortcuts on the desktop and in startup folders, and a modified shortcut is not a new executable, so hash and signature checks on programs do not flag it. Detection relies on file creation and modification events for link files, registry and startup folder monitoring for shortcut based autoruns, process creation showing a link file as the parent, and shell or command line telemetry where a script writes a new shortcut. The main difficulty is that installers, deployment tools and users create and update shortcuts constantly, so the useful signals are location, timing and what the link points to.

What you will practise

  • Explain how shortcut files store a target, arguments and working directory that determine what runs
  • Identify file, registry and process telemetry that records shortcut creation and modification
  • Recognise high risk shortcut locations such as startup folders and desktop links
  • Attribute a shortcut change to an installer, a deployment tool, a user action or a script
  • Remediate a modified shortcut and check for the same change on other hosts
