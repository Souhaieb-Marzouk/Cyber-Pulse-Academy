DET0215 Detection of Multi-Platform File Encryption for Impact

DET0215Detection StrategyVery hardDetection Strategy

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

This detection looks for a program that changes many files very quickly. It often gives each file a new name or a new ending. It may also destroy the backup copies first. The rule warns you while the damage is still starting.

Why should you care?

Encryption for impact stops a business from working. Files become unreadable, and the backups may be deleted first. Every minute between the first encrypted file and your response changes the cost. Catching the pattern early can save the backup copies. It also tells you which machine to isolate first.

How it works, in plain steps

  1. File system monitoring records writes, renames, and deletes on servers and workstations.
  2. The rule counts how many different files one process changes inside a short window.
  3. It looks for a sudden change of file endings, such as many files gaining the same new suffix.
  4. It watches process and command logs for tools that delete backup copies or restore points.
  5. It raises a high-severity alert when volume, extension change, and backup deletion appear together.
  6. Automation can then isolate the host while an analyst confirms what happened.

Real-world example

Think of a night watchman who walks the same corridor every hour. On one round, every door handle is warm. That single detail tells him something happened in many rooms at once. Counting changed files is that warm handle.

Key takeaways

  • The strongest sign is one process changing many files in seconds.
  • A shared new file ending across many files is a classic clue.
  • Backup and restore point deletion usually comes first, not last.

In more detail

This strategy covers T1486, Data Encrypted for Impact, the final encryption stage of most ransomware operations. Detection rests on file system telemetry, such as a single process writing or renaming an abnormal number of distinct files in seconds, a shared new file extension appearing across many files, and concurrent deletion of backup or shadow copy data visible in process and service logs. Because this is the last line of defence, speed matters more than precision, and the common failure is that the rule only fires once enough files are encrypted to be obvious to everyone.

What you will practise

  • Explain the file system patterns that appear in the first minutes of an encryption event.
  • Identify telemetry that records bulk file rename, write, and delete activity per process.
  • Describe why monitoring backup and shadow copy deletion belongs to this detection.
  • Set thresholds that balance early warning against analyst fatigue.
  • Plan an automated containment action that is safe to run on a confirmed alert.
