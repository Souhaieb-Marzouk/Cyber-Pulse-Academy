DET0111 Detect Unsecured Credentials Shared in Chat Messages

DET0111Detection StrategyVery hardDetection Strategy

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

This detection looks for passwords and secret keys pasted into team chat. Chat is the messaging tool people use at work every day. The rule watches messages and uploads for text that looks like a real secret.

Why should you care?

Chat messages are stored, copied into backups and searchable later. Anyone who joins the channel can read the old messages. A pasted key often works right away and nobody notices it was shared. Cleaning it up after the fact is hard, because copies already exist.

How it works, in plain steps

  1. A content scanning tool reads messages in approved chat channels and looks for secret patterns.
  2. Patterns include long random strings, key headers and connection text that contains a password field.
  3. The platform audit records show who sent the message and in which channel. They also show the time and whether a file was attached.
  4. A secrecy check measures how random the string is, so ordinary words such as password do not raise alerts.
  5. All of this reaches the central log platform, often a SIEM, which means Security Information and Event Management.
  6. A rule scores the finding by pattern strength and channel reach. It then alerts the owner so the secret can be rotated.

Real-world example

Think of a staff noticeboard in a busy corridor. Someone pins a note with the safe combination so a colleague can open the safe later. Hundreds of people walk past, and the note stays there for months. This detection is the person who scans the board each day and removes notes that contain combinations.

Key takeaways

  • A chat message is a permanent, widely readable copy of a secret.
  • Detect the pattern of a real secret, not the word password on its own.
  • The fix is rotation first, because deletion does not remove existing copies.

In more detail

This detection strategy covers T1552.008, unsecured credentials shared in chat messages, where a user pastes a password, an application programming interface key, a connection string or a private key into a team chat channel instead of a secret store. It matters because chat platforms are backed up, indexed, searchable and often retained for years, and because membership of a channel changes constantly, so a single pasted secret quietly spreads far beyond the people who need it. The telemetry that makes detection possible is data loss prevention or secret scanning output for message content, chat platform audit logs for message creation and file upload, discovery or compliance application programming interface records that expose message bodies, and process telemetry for clients that read chat data or export message history. It fails in practice because chat is genuinely used for code review and configuration discussion, so pattern matching on the words key or password produces heavy noise unless it is combined with entropy checks, channel scope and the presence of real secret formats.

  • Identify which channels and which secret types deserve the strictest scanning
  • List the response steps, in order, from containment to rotation to verification
  • Explain why deleting a message is not sufficient remediation on its own
