DET0254 Detection Strategy of Transmitted Data Manipulation

DET0254Detection StrategyVery hardDetection Strategy

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

This detection looks for data that changes while it moves from one system to another. The data is correct when it leaves the sender and wrong when it reaches the receiver. The detection compares what was sent with what arrived. It catches tampering that never touches a stored file.

Why should you care?

Most integrity tools only watch files that sit on a disk. Data in flight is invisible to them. An attacker can change a payment amount or a record value and leave no trace. The victim system then acts on the wrong value and stores it as if it were real. This kind of change can move money or hide a record. The damage is often found long after the event. Watching the trip between systems closes that gap.

How it works, in plain steps

  1. Network sensors or a proxy record each transaction request and response. The record includes the session identifier and the payload size.
  2. Application logs record the value the sender submitted, such as an amount or an account number. The same entry holds a transaction reference.
  3. A correlation rule joins the two records on that shared reference and compares the values field by field.
  4. Any difference between the sent value and the received value raises a candidate alert for the analyst to review.
  5. The rule ignores mismatches where a known gateway rewrites the field, such as a currency conversion service.

Real-world example

Think of a cashier who writes a receipt for a customer. The receipt copy stays in the till, and a second copy travels to the finance office in a bag. A night watchman compares the two copies at the end of the day. If the two amounts do not match, someone changed the paper. The change happened while the bag was in transit. The watchman cannot see the change happen. He only knows that the two copies do not match.

Key takeaways

  • Data can be changed while it is moving, not only while it is stored.
  • You need two records of the same event to compare: the sender copy and the receiver copy.
  • Encryption hides the payload unless a logging device ends the session.

In more detail

This detection strategy covers transmitted data manipulation, tracked as T1565.002, where an adversary alters data while it travels between systems rather than editing it at rest. Because the change happens in flight, file integrity monitoring on the endpoints sees nothing at all. Detection therefore depends on network capture, proxy and application logs, transaction reconciliation records, and database or message queue audit trails. In practice the strategy fails when traffic is encrypted end to end and no logging endpoint terminates the session, or when the application itself keeps no record of the value before and after transmission.

What you will practise

  • Explain how transmitted data manipulation differs from changing stored data
  • List the telemetry sources that record a transaction before and after transmission
  • Correlate sender side and receiver side records using a shared transaction reference
  • Identify benign gateways that legitimately rewrite field values
  • Write a tuning plan that reduces false alerts without losing transaction coverage
