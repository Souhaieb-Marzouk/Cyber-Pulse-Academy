DET0841 Detection of Gather Victim Identity Information

DET0841Detection StrategyVery hardDetection Strategy

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

This detection looks for signs that someone is collecting names and contact details about the people in your company. That list often includes full names, work email addresses, and job titles. The rule watches your own systems for the fast, repeated lookups that such collection creates.

Why should you care?

A short list of real names makes a fake email much easier to believe. An attacker who knows your coworkers can pretend to be one of them. If you catch the lookups, you can warn the staff whose details were taken. It also gives you an early warning before a phishing wave starts.

How it works, in plain steps

  1. The SIEM, short for security information and event management system, stores web and identity logs in one place.
  2. The web server access log shows every request, including the ones that fail.
  3. The rule counts requests to staff listing pages and directory pages from a single internet address.
  4. It also counts failed sign ins where many different real accounts are tried in a short time.
  5. The email gateway records messages that ask staff to confirm their own details.
  6. When one source hits many names quickly, the rule raises an alert for the analyst to review.

Real-world example

Picture a hospital sign in sheet at the front desk. One visitor who arrives and asks for the names of thirty doctors in ten minutes is unusual. A visitor who asks for one doctor is normal. The sheet gives you the visitor details, and the pattern of many names from one visitor is what draws attention.

Key takeaways

  • Identity collection often happens before any sign of a real intrusion appears.
  • Fast and repeated lookups of many employee records from one source are the main signal.
  • Public collection leaves no logs, so the rule only covers activity that touches your systems.

In more detail

This detection strategy addresses the reconnaissance technique of gathering victim identity information, where an adversary collects employee names, email addresses, job titles, and phone numbers before an intrusion begins. It matters because these details power convincing phishing and password reset fraud, yet the collection usually happens outside the monitored estate on public sources. The telemetry that makes detection possible is web server and reverse proxy logging, identity provider sign in and failed authentication records, email gateway logs for directory style messages, and mail or web content inspection events. The main failure mode is that public collection generates no telemetry at all, so the rule can only catch the on premises or cloud side of the activity.

What you will practise

  • Describe what victim identity information means and how attackers use it.
  • Identify which logs can show employee detail collection inside your estate.
  • Build a rule that counts directory lookups from a single source.
  • Distinguish normal onboarding or marketing lookups from hostile collection.
  • Point out the coverage gap that public data collection creates.
