DET0573 Cross-Platform Detection of Data Transfer to Cloud Account

DET0573Detection StrategyVery hardDetection Strategy

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

This rule looks for data being copied to a cloud account. A cloud account is the space a customer rents from a cloud provider. The copy may go to a different account, or even a different provider. The technique is transfer because the data moves to a place the attacker can reach.

Why should you care?

Cloud providers offer copying tools that are fast and reliable. The copy can stay inside the provider network, so your network monitors may see nothing. Permissions are the only barrier, and one wrong setting removes it. This makes the cloud side of your logs essential.

How it works, in plain steps

  1. The platform collects management events from the cloud account, which record permission and sharing changes.
  2. A filter keeps actions that share a snapshot, change a storage policy, or assume a role in another account.
  3. The platform reads object level events to see how much data was read or copied afterwards.
  4. It records the identity that performed the action and the account that received the access.
  5. Each destination account is checked against the list of accounts your organisation uses.
  6. An alert fires when a first time destination receives access, or when the volume is unusual.

Real-world example

Think of an office with a shared filing room. Staff may copy a file to another branch, which is allowed. But imagine an employee copying the entire archive to a branch nobody has ever used. The copy is legal and the file room looks unchanged. The new branch name on the label is the clue.

Key takeaways

  • Cloud copies can bypass your network monitoring, so use cloud logs.
  • A destination account that has never been used before is a strong warning sign.
  • Permissions come before the copy, so watch permission changes closely.

In more detail

This detection strategy covers the transfer of data to a cloud account, tracked as T1537, where an adversary uses legitimate cloud interfaces to copy data into storage or an account they control instead of sending it to an external destination over the network. It matters because the copy often happens inside the provider network, so it may never cross a monitored egress point, and because a single permission change can expose an entire bucket or disk snapshot. Detection relies on cloud management event logs showing snapshot sharing, cross account role assumption, bucket policy changes and new storage access points, together with object level read and write events for the resources involved and identity logs for the principal performing the change. The weakness is that legitimate cross account sharing, backup replication and migration projects produce almost identical entries, so the rule must weigh the principal, the destination account and whether that destination has ever been used before.

What you will practise

  • Explain how data can leave through cloud provider interfaces rather than the network.
  • Identify the management events that record snapshot sharing and policy changes.
  • Describe how to track destination accounts and mark new ones as unusual.
  • Correlate a permission change with the object read volume that follows it.
  • Explain why backup and migration projects require separate handling.
