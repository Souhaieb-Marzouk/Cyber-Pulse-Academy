T1546.014 Event Triggered Execution: Emond

T1546.014PersistenceExtremeTechnique

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

This technique uses a macOS service called the Event Monitor Daemon, or emond. The service watches for events, such as a system start or a user sign in. It reads small rule files that say what to do when an event happens. An attacker writes a rule that starts their own program. The daemon then runs that program when the chosen event occurs. This sub-technique differs from its parent because a named system event, and not a logon, sets off the code.

Why should you care?

The daemon runs with root rights, which are the highest rights on a macOS system. A user with administrator rights can therefore use one rule file to reach full control. The rule is a small text file, so it hides easily among system settings. If you never review the rule folder, an attacker can keep coming back after every restart.

How it works, in plain steps

  1. macOS has a service called the Event Monitor Daemon that listens for events from other services.
  2. The daemon reads rule files in the property list format from a folder under the etc directory.
  3. Each rule names an event, such as system startup or a user sign in, and an action to run.
  4. An attacker writes a rule whose action starts their own program when that event happens.
  5. The daemon runs as root, so a user with administrator rights can gain full root control.
  6. The service stays off when the queue folder is empty, so the attacker may add a marker file.

Real-world example

Think of a night porter in a large building. The porter holds a rulebook that says if the front door opens after midnight, call the manager. The porter follows the book exactly and carries a master key. If someone adds a page saying if the front door opens, let this stranger in, the porter obeys without question and uses the master key. The rules of the event daemon are that rulebook.

Key takeaways

  • Emond rules are property list files that start actions when a chosen system event occurs.
  • The daemon runs as root, so one rule file can lead to full control.
  • The service needs a file in its queue folder, and any rule on a normal host is unusual.

In more detail

The Event Monitor Daemon on macOS, called emond, is a launch daemon that accepts events from other services, passes them through a simple rules engine and performs the matching action. It loads rule files in the property list format from the rules directory under the etc folder, and its launch daemon configuration names a queue directory that must contain at least one file, otherwise the service does not start. Rules define an event type, such as system startup or user authentication, and an action, such as running a command or sending mail. An adversary writes a rule whose action runs their own program when the chosen event occurs, which gives persistence, and because the daemon runs as root, it also allows an administrator to reach root. The artefacts are a new or modified rule file, the creation of a file in the queue directory, launchd loading the daemon, and child processes spawned by emond rather than by a user session. The mechanism is rarely used on modern macOS, so any rule on a production host is worth investigating.

What you will practise

  • Explain why this mechanism can raise administrator rights to root.
  • Decide when a rule file is legitimate on a production host.
