DET0134 Detect Suspicious Access to Windows Credential Manager

DET0134Detection StrategyVery hardDetection Strategy

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

Credential Manager is a built-in Windows feature that saves passwords for you. It keeps them in files inside your user profile. This detection looks for programs that read those saved passwords. It catches theft of stored logins for shared drives and websites.

Why should you care?

Saved passwords are convenient, so many people store logins for file shares and internal sites. If an attacker reads that store, they gain access without guessing anything. The theft is quiet, because no login screen appears and nothing looks broken. Stolen credentials can later be reused across many systems. This detection gives you a chance to reset those passwords before they are used.

How it works, in plain steps

  1. Each user profile holds vault files that contain the saved credentials.
  2. The rule watches for processes that read those files or copy them elsewhere.
  3. It also watches for programs that ask the system for stored credentials directly.
  4. It compares the requesting program with a list of tools that should do this.
  5. Each alert shows the user, the program path, and the time of the access.
  6. An analyst then checks whether backup software or a script explains the access.

Real-world example

Think of a coat check at a theatre. Guests hand over their coats and receive a ticket. The attendant keeps everything in a locked room behind the desk. Now imagine someone slips behind the desk and copies every ticket number. No coat is missing, so nobody complains that evening. Later they return with the copied numbers and collect coats that are not theirs. Credential Manager is that locked room, and reading its files is copying the ticket numbers.

Key takeaways

  • Saved credentials are as valuable as typed ones and easier to steal.
  • Watch both the vault files and the programs that request stored credentials.
  • Treat any read by an unexpected program as a password reset event.

In more detail

The Windows Credential Manager (T1555.004) stores saved domain, application, and web credentials in encrypted vault files inside each user profile, which makes it a high value and low noise target during credential access. This detection strategy looks for three related behaviours: a process requesting stored credentials when that process has no business reading them, direct access to the vault files on disk including copying them to another location, and any vault access that originates from a non interactive context such as a service, a scheduled task, or a remote logon session. Telemetry comes from process creation with command lines, endpoint file access and file creation events, sensitive object access records, and the short list of signed utilities that legitimately query stored credentials. It fails because vault access leaves only a thin trail, because vault files are ordinary files in a user profile that backup software also reads, and because automation platforms genuinely do need stored credentials to run scheduled jobs.

What you will practise

  • Describe what the Windows Credential Manager stores and where the vault files live.
  • Identify the file access, file creation, and process events that indicate vault access.
  • Recognise the small set of legitimate tools that query stored credentials.
  • Prioritise alerts that originate from a service, a scheduled task, or a remote session.
  • Plan the credential rotation that follows a confirmed read of the credential store.
