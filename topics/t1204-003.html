T1204.003 User Execution: Malicious Image

T1204.003ExecutionExtremeTechnique

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

This means the attacker prepares a ready made system image and hides something bad inside it. You use that image to start a server or a container. The workload starts as normal but already contains the attacker's code. Nothing needs to be opened by a person.

Why should you care?

Teams trust images the way they trust a recipe that already works. Names can be copied so closely that a quick search picks the wrong one. The attacker's code runs the moment the workload starts, so there is no click to catch. Mining and data theft can then run quietly while the bill grows.

How it works, in plain steps

  1. The attacker builds an image, or takes a popular one and adds hidden code to it.
  2. They publish it to a public image library or package marketplace.
  3. The image is named to look like an official or popular choice, so searches find it.
  4. A user or pipeline pulls the image and starts an instance or container from it.
  5. The hidden code runs during start-up, before or alongside the real application.
  6. It may then mine cryptocurrency, take credentials from the environment, or keep access.

Real-world example

Imagine a shared flat where everyone buys a ready meal from the same brand. Someone prints an almost identical label and leaves boxes in the shop freezer. A flatmate cooks one and eats it, noticing nothing at first. The wrapper looked right and the cooking was normal, but the contents were never checked.

Key takeaways

  • Use only approved base images, and check the identifier or digest each time you deploy.
  • Scan or inspect images before they run, and watch for unexpected start-up processes.
  • A sudden processor load on a new cloud instance often means hidden mining code.

In more detail

Malicious image is the sub-technique in which the adversary relies on the victim deploying a prepared machine image or container image. The other sub-techniques need a click or an install; this one needs a deployment decision. A backdoored image can be published to a public registry or marketplace, given a name that closely matches a popular or official one, and then pulled by a developer or an automation pipeline that believes it is starting from a trusted base. Because the malicious content runs as part of the normal start-up of the instance or container, nothing about the deployment looks abnormal at the infrastructure level, and the technique effectively replaces initial access: the workload begins life already compromised. The usual purpose is resource theft rather than espionage, with cryptocurrency mining being the commonest observed outcome, alongside credential harvesting from the instance profile or environment and persistence through a modified entry point. Detection combines cloud audit records for the image pull and instance launch, a comparison of the image identifier and digest against the approved base images, static or dynamic inspection of the image layers before use, and runtime signals such as a sudden processor load on a new instance, an unexpected outbound connection, or a process in the container that does not belong to the application.
