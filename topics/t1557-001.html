T1557.001 Adversary-in-the-Middle: Name Resolution Poisoning and SMB Relay

T1557.001Credential AccessExtremeTechnique

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

This sub-technique is the name resolution version of an adversary-in-the-middle attack. When a Windows computer cannot find a name in the normal Domain Name System (DNS), it shouts a fallback question to the whole local network. An attacker answers first and pretends to be the machine you wanted. Your computer then connects to the attacker and hands over a hashed form of your password. Unlike the parent technique, nothing on the network path is broken: only the name is a lie.

Why should you care?

Fallback name lookups are switched on by default on many Windows networks. One attacker machine on the same office network can answer those lookups for every colleague. The attacker receives a copy of the password hash, which they can attack offline for as long as they like. Sometimes they do not even need to crack it, because the hash can be passed straight to another server. Nothing crashes and no file is encrypted, so the attack is easy to miss.

How it works, in plain steps

  1. A user opens a share whose name the normal Domain Name System (DNS) server cannot resolve.
  2. The computer then asks the whole local network instead, using Link-Local Multicast Name Resolution (LLMNR) or NetBIOS Name Service (NBT-NS).
  3. The attacker replies before the real host can and claims the name that was requested.
  4. Your computer connects to the attacker, because it believes the answer is genuine.
  5. That connection asks for authentication, so the computer sends the username and a password hash.
  6. The attacker cracks the hash offline or relays it to another server to log in directly.

Real-world example

Think of a big office where the internal phone book is out of date. You dial the extension for the finance printers, but that number no longer exists, so you call out loud across the open floor asking who has the finance printers. A stranger answers first with their own extension. You send your confidential document to that extension, and the form you sign includes a copy of your door code. The stranger cannot read the code straight away, but they can work on it at home until they can. The real finance department never knows you called, and the switchboard log looks perfectly normal.

Key takeaways

  • Turn off fallback name lookups you do not need, and require signing on file sharing.
  • Long unique machine account passwords make captured hashes much harder to crack.
  • Treat an authentication from an unexpected source machine as a real alert.

In more detail

Name resolution poisoning targets the fallback lookups that Windows hosts use when normal Domain Name System (DNS) resolution fails. Instead of resolving a name themselves, the requesting host broadcasts a query with LLMNR, NBT-NS or mDNS, and any host on the local segment may answer. An attacker replies first, claims the requested name, and the victim connects to the attacker believing it reached the intended share or service. That connection asks for authentication, so the victim automatically hands over its username and an NTLMv2 response. The attacker can crack that response offline or relay it in real time to another server that accepts the authentication. Detection combines network and authentication telemetry: fallback name service traffic on a segment where it should be disabled, hosts answering names they do not own, and SMB or LDAP authentications whose source is not the user's workstation. This sub-technique differs from the parent because the attacker poisons the name, not the routing path.

What you will practise

  • Describe how LLMNR, NBT-NS and mDNS fallback lookups work and why any host can answer them.
  • Explain how a captured NTLMv2 response can be cracked offline or relayed to another server.
  • Explain how this sub-technique differs from the general adversary-in-the-middle position.
  • Identify the network and authentication evidence that a poisoned name lookup leaves behind.
  • List controls that reduce the value of captured authentication attempts.
