T1218.010 System Binary Proxy Execution: Regsvr32

T1218.010StealthExtremeTechnique

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

regsvr32.exe is a signed Microsoft program that registers and removes Windows components. It works with files called dynamic-link libraries, which hold reusable code. Windows and installers use it often, so its name appears in normal activity all the time.

Why should you care?

The program can load a script from an internet server and run it. Nothing is registered, so the registry stays clean and many checks find nothing. It can also register a component that Windows loads later by itself, which keeps an attacker on the machine. If you ignore this, a normal-looking command can run remote code or set up persistence.

How it works, in plain steps

  1. Windows programs can offer their features through COM, a system that works with registered objects.
  2. Each object has a long number called a class ID, and Windows stores that number in the registry.
  3. regsvr32.exe registers these objects when it is given a library file, and Microsoft signs the program.
  4. With a special switch it can load a scriptlet, which is a script packaged for COM, from a web address.
  5. That script runs but is never registered, so no new entry appears anywhere in the registry.
  6. Another use registers an object the attacker controls, so Windows loads it later without any help.

Real-world example

A school lets any teacher with a staff card cover a class when the usual teacher is away. A stranger prints a staff card at home and teaches one lesson, then leaves the building. The timetable still shows the usual teacher for that room, so nothing looks out of place. The staff card is regsvr32, and the unchanged timetable is the empty registry.

Key takeaways

  • regsvr32 can run script from the internet without leaving a registration entry.
  • A command that loads the scriptlet library from a web address is rarely legitimate.
  • It can also register an object that Windows loads later, which is persistence.

In more detail

Regsvr32.exe is the signed Windows program that registers and unregisters object linking and embedding controls, including dynamic-link libraries, by calling their registration entry points. Its abuse takes two distinct shapes. The first loads a COM scriptlet from a remote URL by requesting the scriptlet runtime library, a variation widely called squiblydoo; the script executes without any registry change because the object is never actually registered, and Regsvr32 is both network and proxy aware, so the scriptlet can be hosted externally. The second registers an attacker-controlled COM object so that Windows loads it later on its own, which supports persistence through component object model hijacking. Because Windows itself uses Regsvr32 routinely during installation, monitoring that relies on process names or allowlists tends to produce noise or miss the malicious case entirely. Detection evidence includes command lines that pass a URL or the scriptlet runtime library as the registration target, references to files in temporary, download or public directories, network connections from Regsvr32.exe, and registry writes under COM class identifier keys that do not correspond to installed software. Legitimate registration names local, trusted libraries and results in the expected registration outcome, which the malicious variants deliberately avoid.
