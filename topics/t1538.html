T1538 Cloud Service Dashboard

T1538DiscoveryExtremeTechnique

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

A cloud dashboard is the web page where you manage your cloud services. This technique is an attacker logging into that page with stolen details. They use it to see what you run and where the weak spots are.

Why should you care?

The dashboard shows a lot at a glance, so an attacker learns quickly. It can show more than a single tool query would return. Using a normal web page leaves almost no trace on your own machines. It is often the quiet first step before real damage.

How it works, in plain steps

  1. The attacker gets a working account name and password, usually from phishing, a leaked key or reused passwords.
  2. They sign in to the provider web console. This looks like a normal login, so it may not raise an alarm.
  3. They browse the resource list to see every server, database and storage account in the environment.
  4. They open the security or recommendation pages, which often list weak settings the provider already found.
  5. They look at network details to spot public addresses and open ports they could reach later.
  6. They may export or screenshot the views, then close the page. The provider still logs the sign in and the pages viewed.

Real-world example

Think of a hotel front desk computer. A thief in a cleaner's jacket sits at the screen and reads the room list, the safe codes and the staff rota. No door is forced and no guest is disturbed. The only record is the key card used to reach the office at an odd hour.

Key takeaways

  • A console login from a new place or device is a strong signal, so log and review those events.
  • Read only access still matters, because it tells an attacker exactly where to strike next.
  • Protect console access with extra sign in checks that resist stolen passwords.

In more detail

Cloud Service Dashboard describes discovery performed through the provider's own web console rather than through programming interfaces. With stolen but valid credentials, an attacker opens the management portal and reads what it renders: the inventory of services and resources, security findings and misconfiguration reports, network layouts with public addresses and open ports, identity and permission views, and cost summaries. Console use is attractive because a dashboard can surface more than a single interface call returns, it aggregates data the provider already computed, and it requires no tooling on the attacker's side, so very little appears in the victim environment. The activity is nevertheless recorded, but on the provider side and in identity logs: console sign in events with client details, sessions from an unusual address or device, and a burst of page or read only interface calls that never touch the data plane. Console sign ins are concentrated in a small IP or ASN range and often originate from hosting providers, virtual private servers or anonymising services. Because administrators legitimately use the same dashboard, detection rests on comparing the pattern with each identity's normal working hours, location and behaviour, and on correlating dashboard browsing with later resource changes.

What you will practise

  • Explain how the cloud management console differs from programming interfaces during discovery.
  • List the information an attacker can gather from a provider dashboard with valid credentials.
  • Identify the identity and provider logs that record console sign ins and read only browsing.
  • Describe how unusual location, device or timing helps separate attacker console use from administrator work.
  • Explain why read only console access is still a significant risk.
