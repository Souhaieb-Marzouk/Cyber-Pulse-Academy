T1608.004 Stage Capabilities: Drive-by Target

T1608.004Resource DevelopmentExtremeTechnique

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

A drive by target is the web page or script an attacker prepares in advance. When you visit that page, your browser may be attacked without you clicking anything. The attacker sets all of this up before sending anyone to the site. This is one part of a wider idea called staging capabilities, where an attacker prepares everything before the attack starts.

Why should you care?

People trust websites they already use, so a hacked page reaches many visitors quickly. No email and no download are needed, which removes the warnings users are trained to spot. If the site is popular at your company, one bad script can affect hundreds of machines in a day. Watching what your browsers load is the main way to catch it.

How it works, in plain steps

  1. The attacker chooses a website that the people they want will visit.
  2. They hide their code inside the page, often inside a script file.
  3. The code first checks your browser type, its version, and your installed software.
  4. If your browser matches, the page sends a second piece of code to attack it.
  5. If it does not match, visitors see a normal page and notice nothing at all.
  6. The attacker may also buy ad space so the code reaches many sites at once.

Real-world example

Picture a market street where shoppers wander between stalls. One trader does not call out to anyone. Instead they quietly swap the sign on a busy shop door so it points into their own alley. Only shoppers wearing a certain kind of shoe are waved through, and everyone else simply sees a poster and walks on. The trap was built and set hours before the first customer arrived. Nothing about the shop looked wrong from the street.

Key takeaways

  • A drive by attack needs no click beyond visiting a page you already trust.
  • Attackers stage the trap in advance and often hide it inside normal script files.
  • Your browser loading a script from an unexpected domain is a signal worth chasing.

In more detail

Before a drive by compromise can occur, the adversary prepares the web content that will run in a visitor's browser. This sub technique covers writing or buying the exploit and the profiling script, then placing that content on a site the intended target is likely to visit, whether the site is attacker owned or a legitimate site that has been compromised. Typical placements include injecting script tags into content management system templates, replacing JavaScript files served from a publicly writable cloud storage bucket, and buying advertising space so the malicious creative is served through a legitimate ad network. A profiling step often runs first, collecting browser version, installed plugins, and language settings, so the payload is delivered only to visitors who match the chosen profile. Defenders see the result indirectly, through unexpected script references in served pages, sudden changes to files in web roots, and browser requests from the internal network to newly seen domains.

What you will practise

  • Explain what a drive by target is and when it is prepared.
  • Describe three ways malicious web content can be placed on a site.
  • Explain why a profiling step is used before an exploit is delivered.
  • Identify the log sources that reveal unexpected browser script requests.
  • Explain how this staged content supports a later drive by compromise.
