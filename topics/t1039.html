T1039 Data from Network Shared Drive

T1039CollectionExtremeTechnique

New to this? Start here

Explained in plain language

Written for beginners. No security background needed.

Simple definition

A network shared drive is a folder on one computer that other computers can open over the network. Many offices use them as a common place for team files. An attacker who has already broken into one machine can read those shared folders from it.

Why should you care?

Shared drives often hold the most useful files in a company. They are open to many accounts by design, so an attacker rarely needs extra effort. The copying looks like normal file opening, so simple antivirus tools may not react. Data taken this way usually leaves the building before anyone notices.

How it works, in plain steps

  1. The victim machine already has shares mapped, or the attacker lists available shares on the server.
  2. The attacker uses the operating system's own commands to browse folders and read names.
  3. Files of interest are copied to a local folder on the compromised machine, ready to be packed.
  4. The collection may be filtered by name, type or date to reduce the noise and the size.
  5. Copied files are staged and compressed so they can be sent out in fewer, larger transfers.
  6. Shared drives can also be used to push files onto other machines instead of pulling them.

Real-world example

Picture an office where every team keeps its paperwork in one shared filing room. All staff with a key may walk in and read any folder. If a visitor steals a key and starts photographing whole shelves, nothing is broken and no alarm sounds, because the room was open to key holders. Only the size of what left the room tells the story.

Key takeaways

  • Collection from shared drives uses normal file access, so it blends into daily work.
  • Watch the server side, where reads, volumes and account names are recorded.
  • Know which accounts should touch which shares, and alert when that pattern changes.

In more detail

Network shared drives are a collection source rather than an intrusion method: an adversary who already holds an account or a session on a host browses file shares reachable from it and copies whatever looks valuable. Shares are commonly mounted by the operating system as drive letters or mount points and are accessed with built-in tooling, so the intruder issues ordinary directory listings and file copies instead of deploying a custom collector. The resulting artefacts live mostly on the server: read access to shares far outside the account's normal working set, bursts of file opens by one account, access from a workstation that has no business reason to touch that share, and large outbound copies pulled through an administrative or hidden share. Detection therefore depends on file server auditing, share access telemetry, and baselining which accounts touch which shares. Legitimate activity that looks similar includes backup jobs, roaming profile copies, and file migration projects, so defenders separate them by matching the reader account against its role and by looking at the timing, volume, and destination of the reads.

What you will practise

  • Explain what a network shared drive is and why it is a target for data collection.
  • Describe how an adversary browses and copies files from a reachable share.
  • Identify the server-side telemetry that records share access and file reads.
  • Distinguish malicious bulk collection from backup, migration or profile copying.
  • Recommend access reviews and monitoring that reduce the blast radius of one stolen account.
