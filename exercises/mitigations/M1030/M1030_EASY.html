What you will learn here

You will learn what M1030 — Network Segmentation is and why defenders care about it. In MITRE ATT&CK, this is a Mitigation. A mitigation is a defensive control: something the good side builds so the bad side has fewer paths. Imagine the network as an office building. Without segmentation it is one big open hall — anyone inside can walk to any desk. With segmentation it has locked doors between rooms: a visitor area (the DMZ), the offices (user VLANs), and the server room (the server zone). That is the whole idea, and it is one of the strongest controls in real security work.

You will see where this object is used in daily jobs. SOC analysts read firewall DENY lines to see the walls working. Network engineers build the walls: VLANs on switches, firewall rules between zones, jump hosts for admins. Security architects design the zones and write the segmentation policy. Control owners check the rules still match the design months later. GRC analysts map the control to frameworks like CIS Control 12.2. Incident responders rely on segmentation to keep a ransomware outbreak small. The tools you will meet: zone firewalls, VLANs, the DMZ, the jump host, deny-by-default rules, and the logs they produce.

The risks it addresses: an attacker who lands on one workstation using T1021.001 Remote Services: Remote Desktop Protocol to hop further, T1210 Exploitation of Remote Services attacking a server across zones, T1046 Network Service Discovery scanning servers, or T1133 External Remote Services reaching in from outside. Segmentation limits all of these paths, so one lost laptop does not become one lost company.
