About M1013, in simple words

M1013 is a Mitigation. A Mitigation is defensive advice in MITRE ATT&CK. It tells defenders how to stop or weaken attack techniques. M1013 is called Application Developer Guidance. It moves defence left, into the software development lifecycle: the moment software is designed, written, tested, and shipped.

Its named measures are concrete. Threat modeling (STRIDE) at design time. Parameterized queries and input validation against SQL injection. Output encoding against XSS. Authenticated APIs that never leak sensitive data. SAST as a CI/CD gate — the page's use case: hardcoded credentials caught before deployment. Supporting tools: DAST (Burp Suite, OWASP ZAP) and secure-by-default frameworks (Django, Spring Security).

Its technique coverage is precise, and these senior exercises expect you to know it. For T1212: validate authentication requests — one-time passwords, message timestamps or sequence numbers, digital signatures, random session keys. For T1574.001: hash values in manifest files against DLL side-loading. For T1564.009 and .012: use the bundle structure and trusted install folders instead of custom exclusions. For T1559.003 and T1647: enable macOS Hardened Runtime and never set the com.apple.security.get-task-allow entitlement to true. For T1496.003: CAPTCHA on forms that send SMS. For T1593.003: never publish credentials to public repositories. For T1195 and T1195.001: caution with third-party libraries, locked dependency versions, GitHub Actions pinned to commit hashes. For T1550.001: bind tokens (Azure AD token protection, OAuth Proof of Possession). For T1078: no plaintext credentials in code, repositories, or cloud storage. On mobile: minimal elevation (T1626), no sensitive notification text (T1517), FLAG_SECURE (T1513), App Links / Universal Links plus PKCE (T1635.001), and library caution (T1474).

The expert layer is judgement under pressure. You will meet two artefacts that disagree (a clean SAST run versus a reproducible fuzzing crash), a waiver that quietly defeated the SCA control eight months before a breach, a CISO demanding a full rewrite in 90 days, and a release train leaving while a build runner phones an unknown domain. The correct answer is often the least dramatic one: it preserves evidence, respects cost, and fixes the code.

How this exam works

  • Level: EXTREMELY HARD. Three or more chained concepts per exercise, at least one ambiguous or conflicting signal to resolve, realistic noise, and missing information you must reason around. Several options are defensible in some world; only one is correct in this one.
  • Pass mark: 70%. Only answered exercises count.
  • Exercise types: multi-artefact branching incidents, evidence classification, precise measure-to-technique mapping, constrained ranking, and five classic multiple-choice decisions. No command-line tasks.
  • Partial credit: multi-item exercises score per item with max(0, (H − W) / N) — wrong picks subtract from correct ones.
  • Timer: 70 minutes, two kinds of pause: the Pause button (break, exercise hidden) and the Check auto-pause (Check stops the timer while you study the feedback; it resumes on Next or on returning to the review list).
  • Hint: one per exercise, costs 10% of that exercise's credit. Hints restate a constraint; they never point at the answer.
  • Skip: free; the review list holds skipped exercises until you finish or time ends; skipped-and-unanswered exercises are excluded from the score.
  • Retake: reshuffles questions and choices.
