● What you will learn here

You are about to practise MITRE ATT&CK mitigation M1025 — Privileged Process Integrity. This is a mitigation. In ATT&CK, a mitigation is something defenders can put in place to stop an attacker technique from working. M1025 protects the processes a Windows system trusts most — for example LSASS (the process that handles your logon), the antivirus service, and other system services — so attackers cannot inject code into them, change them, or read their secrets. The page also names the Linux side of the same idea: SELinux and AppArmor.

Who uses this at work? SOC analysts meet M1025 when a protection event appears on the queue. System engineers implement it: they set one registry value (RunAsPPL) and restart the host. Detection engineers build alerts from the events the blocks produce. GRC analysts collect proof that the setting is really on. Incident responders meet it when a dump tool suddenly fails against a protected host.

What will you practise here? The protections named by M1025 (RunAsPPL, DEP, ASLR, CFG, AppLocker, SELinux, AppArmor, PatchGuard, sandboxing), the attacker techniques it maps to (like LSASS Memory dumping), and the plain rules behind them. Every exercise walks you through one clear idea, step by step, in short sentences.

● Keywords covered in this exam

Mitigation goal and scope

  • Privileged processes (LSASS, antivirus, system services)
  • Tampering, injection, compromise — what M1025 defends against
  • M1025 as a preventive, defensive control object

Protected process mechanisms

  • RunAsPPL registry value under HKLM\SYSTEM\CurrentControlSet\Control\Lsa
  • LSA Protection and Protected Process Light (PPL)
  • Microsoft-signed DLL requirement for LSA plug-ins

Memory and injection defences

  • DEP — no code from data-only pages
  • ASLR — randomised addresses
  • Control Flow Guard (CFG) — checked indirect calls

Named tools and platforms

  • AppLocker and Windows Sandbox (Windows)
  • SELinux and AppArmor (Linux kernel enforcement)
  • Kernel Patch Protection (PatchGuard) (Windows)
  • Firejail and QEMU/KVM isolation (Linux sandboxing)

Techniques addressed by the mapping

  • T1003 / T1003.001 — OS Credential Dumping: LSASS Memory (Credential Access)
  • T1547.002 Authentication Package, T1547.005 Security Support Provider, T1547.008 LSASS Driver
  • T1556 / T1556.001 — Modify Authentication Process (incl. Domain Controllers)
