● What you will learn here

This exam drills MITRE ATT&CK mitigation M1025 — Privileged Process Integrity at working depth. M1025 is a mitigation: a defensive control you implement, verify and document. It defends privileged processes — LSASS, antivirus, system services — against tampering, injection and credential theft, using measures you will combine here: Protected Process Light (the RunAsPPL registry value), memory protections (DEP, ASLR, CFG), code-signing validation (WDAC, AppLocker), access controls (DACLs, integrity levels, disabling unneeded debugging), and kernel protections (PatchGuard, SELinux, AppArmor).

Who uses this at work? You will act as the people who really run this control: the detection engineer who reads Code Integrity and Sysmon events, the system engineer who verifies registry baselines across servers, the SOC analyst who triages refused-module alerts against the change calendar, and the GRC analyst who maps the control to the M1025 technique table during an audit.

What will you practise here? Two-step reasoning on real artefacts: reading event logs, checking dword values, completing policy clauses with the exact keyword, sorting runbook lines into correct and mistake, and mapping every measure to the behaviour it enforces. Multi-answer exercises give partial credit, so careful thinking always pays.

● Keywords covered in this exam

How the measures fit together

  • PPL signature gate vs host-wide code-signing (WDAC / AppLocker)
  • CFG indirect-call checks; DEP data-page rule; ASLR address randomisation
  • DACLs + Mandatory Integrity Control as the Access Controls measure
  • Disabling unnecessary debugging capabilities

Techniques addressed

  • T1003.001 LSASS Memory; T1547.002 / .005 / .008 autostart tampering
  • T1556 Modify Authentication Process; T1556.001 Domain Controller Authentication
  • Tactics: Credential Access; Boot or Logon Autostart Execution

Deployment and verification

  • RunAsPPL = dword:00000001; Windows 8.1 / Server 2012 R2+ requirement
  • Restart needed — the value is read at boot
  • Code Integrity 3033 / 3065; LsaSrv protected-mode event
  • Denied LSASS handle requests (0x1010) in Sysmon-style logs

Operational triage

  • Change-record matching for hardening events
  • Investigating unsigned modules with no owner
  • Routing out-of-scope alerts (phishing) to their playbooks

Supporting tools named in M1025

  • Windows Defender Credential Guard (virtualization-based protection)
  • Windows Sandbox (Windows isolation); Firejail (Linux sandbox)
