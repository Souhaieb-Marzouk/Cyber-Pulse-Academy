◈ What you will learn here

Welcome! This exam teaches you M1038 — Execution Prevention. You will learn what it is, why attackers hate it, and how real security teams use it every day.

First, the basics. In the MITRE ATT&CK framework, a Mitigation is a defensive action that stops or weakens attacker techniques. Mitigation IDs start with the letter M. M1038 is called Execution Prevention. In plain words: it stops attacker code from running on a computer. The most common way to do this is application control — an allowlist that says which software may run, while everything else is blocked by default.

Where will you meet this at work? Almost everywhere. As a SOC analyst, you will see its block events in your alert queue and confirm that a control caught malware before it ran. As an incident responder, you will recommend block rules for tools the attacker abused, like mshta.exe or wmic.exe. As a GRC or control owner, you will write the policy, manage exceptions, and map M1038 to frameworks like NIST CSF and the CIS Controls. As a detection engineer, you will tune the rules in audit mode and read what they would have blocked. Even red teamers know M1038 well — they test whether their techniques survive a good allowlist.

The tools behind M1038: on Windows it is AppLocker, Windows Defender Application Control (WDAC), and Software Restriction Policies (SRP). The ATT&CK page also names SELinux for Linux, PowerShell Constrained Language Mode for scripts, and TACACS+ command control on network devices. The same idea — only approved code runs — appears on every platform.

The risks it addresses: attackers love to run scripts (T1059), trick users into running files (T1204), abuse Windows tools like mshta.exe and rundll32-style proxies (T1218), install autostart persistence (T1547), and block your recovery tools (T1490). A good execution prevention policy makes all of these much harder.

Take your time, read each scenario, and remember: in this exam you are the defender. Good luck!
