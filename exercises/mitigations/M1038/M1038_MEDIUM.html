◈ What you will learn here

Ready for the next step? This exam deepens your mastery of M1038 — Execution Prevention, the ATT&CK Mitigation that stops attacker code from running. At MEDIUM level you will not just recognise the concept — you will combine two ideas at a time, exactly like in real SOC, IR, and GRC work.

Here you will practice the two-step thinking the M1038 page assumes. First you identify the behaviour: which technique is running, loading, or installing code? Then you choose the control that acts at that exact step: an AppLocker script rule, a WDAC block for an unneeded binary like CMSTP.exe or wmic.exe, or a DLL rule against hijacking. That pairing — technique then control — is the daily craft of a detection engineer.

You will also work the real rollout flow: inventory software, draft allow rules, run the policy in audit mode, read WOULD BLOCK events (Event IDs 8003/8004/8007 and friends), tune, pilot, enforce, and monitor. Most M1038 projects fail by skipping a phase — after this exam you will know exactly which one.

The MEDIUM file also widens your platform view. The M1038 page is not Windows-only: it names SELinux for Linux restrictions, execInstalledOnly for ESXi hosts (only signed vSphere VIB bundles run), and TACACS+ command authorization for network devices. It also names concrete binaries worth blocking when unneeded: mshta.exe, wmic.exe, msxsl.exe, diskshadow.exe, AutoIt3.exe, and more.

Who uses all this? SOC analysts triage block events; detection engineers tune rules from audit data; incident responders add block rules for tools the attacker abused; GRC/control owners manage the policy, exceptions, and framework mappings (CIS Controls allowlisting safeguards, NIST CSF Protect); CTI analysts trace which techniques the mitigation blunts. This exam walks you through all four seats at the table.
