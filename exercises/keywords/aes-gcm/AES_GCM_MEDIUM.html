AES GCM MEDIUM

What is AES GCM? (read this before you start)

AES GCM is a way to protect data. AES is a famous encryption method. It scrambles your data so nobody can read it without the key. GCM (Galois/Counter Mode) is a "mode" that tells AES how to work. GCM does two jobs at once. First, it encrypts: it turns readable data into unreadable ciphertext. Second, it creates a small fingerprint called a tag. The receiver checks the tag. If even one bit of the data was changed on the way, the tag check fails, and the receiver knows the data is not trustworthy. Security experts call this combination "authenticated encryption", or AEAD. AEAD stands for "authenticated encryption with associated data".

Some ideas are important. GCM needs a fresh value called a nonce (a "number used once") for every message. The standard nonce size is 96 bits, which is 12 bytes. The nonce does not need to be secret, but it must never repeat with the same key. If it repeats, an attacker can uncover parts of both messages and can even build fake data that passes the tag check. GCM also supports AAD (additional authenticated data): extra information that the tag protects but that is not encrypted. Headers and file names are common examples. The tag normally has 128 bits. The standard allows shorter tags down to 32 bits, but shorter tags are easier to fake.

You will meet AES GCM in many places at work. Websites and APIs use it inside TLS, so connection logs show names like TLS_AES_256_GCM_SHA384. VPNs, disk and file encryption, cloud storage, and messaging apps use it too. Cloud key services (KMS) use GCM inside their envelope encryption.

Almost every team touches it. SOC analysts see GCM cipher names in TLS logs and see "tag verification failed" alerts. Incident responders investigate those failures: was the data corrupted, or was someone tampering? Security engineers build services with GCM through libraries such as OpenSSL, Python cryptography, Java JCA, Go crypto/cipher, and Node.js crypto. GRC teams write the rules: which cipher suites are allowed, how long keys live, and how often they rotate. Red teams and pentesters hunt for the classic mistakes: a reused nonce, a hardcoded nonce, or code that ignores a failed tag check. The risks AES GCM protects you from are simple: someone reading your data, or someone silently changing it. The risks it introduces come from the same simple mistakes, made by the people using it. This exam teaches you to spot both sides.

Keywords covered

Crypto foundations

  • AES block cipher, 128-bit blocks, key sizes 128 / 192 / 256
  • GCM = counter mode (CTR) + GHASH
  • AEAD: confidentiality + integrity + authenticity
  • Keystreams and stream-style encryption

Nonces and IVs

  • 96-bit (12-byte) standard nonce
  • Uniqueness rule: never repeat a (key, nonce) pair
  • Random vs counter-based nonce construction
  • NIST SP 800-38D limit: 232 invocations per key with random nonces

Authentication and tags

  • GHASH over GF(2128), authentication subkey H
  • 128-bit full tag; allowed shorter tags (96, 64, 32...)
  • AAD: authenticated but not encrypted
  • Verify the tag before releasing plaintext

Failure modes

  • Nonce reuse: the "forbidden attack"
  • Plaintext recovery by XOR of ciphertexts
  • Tag forgery after subkey recovery
  • InvalidTag / AEADBadTagException handling

Protocols and TLS

  • TLS 1.3 suites: TLS_AES_128_GCM_SHA256, TLS_AES_256_GCM_SHA384
  • TLS 1.2 GCM suites (ECDHE vs static RSA)
  • IPsec ESP with GCM (RFC 4106), SSH GCM, JWE/JOSE
  • ChaCha20-Poly1305 and CCM as neighbour AEADs

Engineering and operations

  • OpenSSL CLI limits, Python cryptography, Java JCA, Go, Node.js
  • KMS / envelope encryption, key rotation, crypto inventory
  • NIST SP 800-38D, FIPS 140-3, audit findings
  • Post-quantum view: Grover vs AES key sizes
