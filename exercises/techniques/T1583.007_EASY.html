What you will learn here

You will learn about T1583.007 — Acquire Infrastructure: Serverless. This is a sub-technique in the MITRE ATT&CK framework. MITRE ATT&CK is a public catalogue that describes what real attackers do. A sub-technique is one specific way to carry out a bigger job. The bigger job here is the parent technique T1583 — Acquire Infrastructure: getting resources ready before an attack starts.

This sub-technique is about serverless cloud tools. Imagine you are a new analyst in a Security Operations Centre (SOC) — the team that watches a company's systems and networks. Before attackers touch a victim, they often rent small pieces of cloud computing. The ATT&CK page names three examples: Cloudflare Workers, AWS Lambda functions, and Google Apps Script. These services run small bits of code on demand, and the attacker never owns or manages a server.

Why do attackers like this? Because traffic to these services looks like ordinary cloud traffic. It comes from subdomains of well-known cloud companies, so it is hard to tell apart from normal work. It is also cheap — sometimes free — and hard to link back to a real person. The technique page also explains that a serverless function can answer infected machines directly, or proxy (forward) their traffic to a hidden command and control (C2) server.

You will see where this matters in real work. Detection engineers and threat hunters use this page to know where to look — for example, beacons to fresh workers[.]dev addresses. Incident responders use it to understand what the attacker prepared in advance. Threat intelligence analysts use it when they write reports about groups like APT41, which used infrastructure behind Cloudflare and Cloudflare Workers for C2 during the APT41 DUST campaign. Red teamers study it too, because it shows how cheap and quiet hidden infrastructure can be. In this exam you will practise recognising the technique, its place in the attack lifecycle, and the simple ideas defenders use around it.
