What you will learn here

You will learn about T1608.003 — Install Digital Certificate, a Sub-Technique of T1608 Stage Capabilities in the Resource Development tactic (TA0042). Resource Development is where an adversary prepares before touching any victim. In this sub-technique the preparation step is small but powerful: the adversary uploads an SSL/TLS certificate file to a server it controls, then configures that server to use the certificate for encrypted communication.

In plain words: an SSL/TLS certificate is a data file. When a server uses it, visitors see the HTTPS padlock and their traffic is encrypted. The certificate names an issuer — the entity that checked the certificate's contents and signed them. An adversary can obtain a certificate from such an entity, or make a self-signed certificate — one it created itself, so no public authority vouches for it. A certificate also carries a SAN (Subject Alternative Name — the list of hostnames the certificate covers). Keep the golden rule in mind: the padlock means the connection is encrypted; it never means the site is honest.

This topic shows up in many real jobs. A SOC analyst reads TLS alerts and checks which certificates servers present. A CTI analyst pivots on certificate details — issuer, serial number, SAN — to cluster adversary infrastructure. A threat hunter watches Certificate Transparency logs (public records that list certificates when they are issued) to spot lookalike domains early. A detection engineer maps this technique to telemetry. A pentester installs certificates on authorized lab infrastructure so test pages behave like real ones. And a simple phishing-site assessment always starts with one question: does this lure have a valid padlock?

You will look at this from both sides. From the attacker side, a padlock makes a fake login page look trustworthy and helps C2 traffic hide inside normal-looking encryption. From the defender side, you will read proxy and access logs, weigh what a padlock does and does not prove, and run one guided command to fetch the certificate a suspicious server presents.

Everything here stays at EASY level: short scenarios, one idea per exercise, guided wording, and hints that point at the concept itself. Take your time — steady and accurate beats fast and guessing.
