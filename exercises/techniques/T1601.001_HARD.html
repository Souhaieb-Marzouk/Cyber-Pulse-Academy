What you will learn here

This is the hard tier. The scenarios now look like real ISP and enterprise work: several artefacts per case, evidence that contradicts itself, and answer options where two choices are technically defensible but only one is right here. You will need the full area of T1601.001 — Patch System Image, sub-technique of T1601 Modify System Image, tactic TA0005 (Defense Evasion, renamed Defense Impairment in current ATT&CK).

What the hard cases add: a patched image can make CLI commands lie — ATT&CK describes compromising the version command so it shows the original, higher revision after a downgrade. A checksum can match your internal server and still be malicious, because the server copy may have been replaced too — ATT&CK says compare against a known good copy from a trusted source. Memory patches (native debug commands, or a boot-loader implant combined with them) leave flash clean. The detection strategy for the family (DET0170 / AN0482) watches anomalous CLI commands, integrity check failures, version/checksum mismatches, reloads after image replacement, and boot-config changes that load non-standard images.

Who works this tier? Senior SOC analysts and threat hunters tune those analytics and chase the false positives (planned upgrades, rollbacks). IR leads choose the least destructive containment that preserves evidence. Detection engineers weigh every signal against noise. CTI analysts brief on the real procedure example ATT&CK cites for this sub-technique: S0519 — SYNful Knock, malware inserted into a network device by patching the operating system image.
