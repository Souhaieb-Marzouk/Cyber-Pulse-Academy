🎯 What you will learn here

Imagine you close a shift and your team lead asks: “What exactly did the intruder type on our server?” If the intruder quietly switched off the shell’s memory before doing anything else, that question becomes very hard to answer. T1690 is the MITRE ATT&CK name for exactly this behaviour: an adversary prevents command history logging so the commands they run on a compromised system are never saved.

In ATT&CK, T1690 is a Technique — one specific way of doing something — and it lives in the Defense Impairment tactic area (TA0112). That is the part of the matrix that covers breaking the security tools and records that defenders rely on.

You will meet this technique in many real jobs. As a SOC analyst, you triage alerts about changed shell settings and decide what is real. As a threat hunter, you look for shells that stayed active but wrote nothing to history. In incident response, you preserve what is left before it disappears. As a CTI analyst, you track which groups and implants — BPFDoor-style implants on Linux web servers, or the Medusa Group on Windows — use these tricks. As a detection engineer, you write absence-based analytics and learn their false-positive traps. In GRC, you judge whether controls like M1039 and M1028 are strong enough. As a red teamer, you learn why quiet prevention beats loud deletion. In this exam you will read logs, configs, tickets and ATT&CK excerpts, make triage calls under time pressure, run one safe evidence-preservation command in a simulated shell, and learn where the near-misses hide.
