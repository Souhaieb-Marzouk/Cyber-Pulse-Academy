What you will learn here

Welcome to the HARD tier for T1608.005 — Link Target. It is a Sub-Technique of T1608 (Stage Capabilities) and it lives in the Resource Development tactic (TA0042) on the PRE platform: everything happens before any victim is touched. The one rule this file never relaxes is the core of the technique — the page or file that a phishing link points to is put in place before the phish is sent. At this level you will not just recognise that rule; you will apply it when the evidence is messy and two labels both look right.

The staged destination is usually an HTML page with a little client-side JavaScript (code that runs inside the visitor's browser) deciding what content to serve. Very often it is a cloned login page — a copy of a real sign-in screen that collects the credentials and one-time MFA codes victims type into it. Other times the link simply points at a hosted malware file, or the whole destination sits on a lookalike domain bought during infrastructure acquisition (T1583.001).

HARD also means the wrapping gets serious. URL masking means the visible link text and the true destination differ. Shorteners and PaaS pages (pages rented on a widely trusted app-hosting provider) borrow trust so blocklists hesitate. One-time per-victim URLs stop scanners from re-visiting a link, and IPFS (a decentralised file network) keeps content alive after takedown requests. Each trick defeats a different defensive habit, and this file makes you tell them apart under pressure.

You will work the cases real teams work. SOC analysts classify staged destinations from mail and click evidence. CTI analysts track phishing-kit fingerprints and file registrar abuse reports. Threat hunters reason about why the assigned analytic (DET0893 / AN2025, built on internet scanning) pivots to the downstream phases. IR contains whatever a clone captured. Detection engineers pre-position coverage for the phishing wave, and awareness teams lower the click probability that every link target depends on.

The real campaigns are here on purpose: FIN7's fake link redirecting to an adversary Dropbox that downloaded an executable, LuminousMoth's Dropbox file link, Silent Librarian's staged clones behind varied shorteners, the C0059 Okta panel reached during vishing calls, and MirrorFace's OneDrive links in Operation AkaiRyū. Expect the two classic HARD traps: the least-aggressive correct action when a clone is staged but no phish has been seen, and the alarming-but-benign finding that turns out to be a researcher's rehost.
