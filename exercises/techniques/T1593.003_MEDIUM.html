💡 What you will learn here

This is part of the T1593.003 — Code Repositories exam series. Imagine you are a new analyst, and your company's developers use GitHub every day. Now imagine an attacker using the same website — not to attack it, but to read it. In this exam you will learn about a real technique from the MITRE ATT&CK framework: T1593.003 — Search Open Websites/Domains: Code Repositories. It is a sub-technique of T1593 (Search Open Websites/Domains). Its job: adversaries search public code repositories — GitHub, GitLab, SourceForge, BitBucket — for information about victims. People use these sites through a web page or command-line tools such as git, and much of what they publish is public by default.

What can an attacker find? Two layers. General information: which programming languages and libraries a company uses, and even employee names. Sensitive information: credentials and API keys that developers accidentally leak in commits — and here is the trap most people miss: deleting a file in the newest version does not remove the secret, because it stays in the commit history. Real actors do exactly this: Contagious Interview used GitHub to find and contact victims; HAFNIUM discovered leaked corporate credentials on GitHub; LAPSUS$ searched public repos for exposed credentials; ShinyHunters dug through target companies' GitHub repositories for logins and API keys; and the Shai-Hulud malware itself searches repositories for compromised credentials. Findings feed later phases: logging in with valid accounts, phishing, or taking over infrastructure.

This object is daily work for several roles. AppSec engineers run secret scanning and pre-commit checks (that is mitigation M1013 — Application Developer Guidance, plus M1047 — Audit: scan before commits and clean the history). CTI analysts map "leaked key found on GitHub" stories to T1593.003. IR teams handle the scary version: a leaked cloud key that starts showing strange API calls from a new region — rotate first, audit usage, purge history. Red teamers search public repos in their OSINT phase. And everyone learns the ATT&CK distinction on the page: searching public repos is reconnaissance (this object), while pulling data from private, internally hosted repos is a different, later-stage activity.

By the end of this exam you will spot repo-based recon in evidence, read repo-search queries, and know exactly what to do when a secret leaks.
