🎓 What you will learn here

You already met the basics: T1578.001 is the ATT&CK sub-technique where an adversary creates a point-in-time copy (a snapshot) of a cloud disk, virtual hard drive, or volume, to evade defenses and reach data the normal rules block. This exam pushes one level deeper.

Here you work like a real cloud-aware analyst. You will read pairs of log events and correlate them — the ATT&CK detection strategy DET0423 says the signal is not one event but a sequence: snapshot creation followed by instance creation and mounting. You will compare benign automation (backup jobs, infrastructure pipelines) with adversary patterns (new identities, missing change records, cross-account sharing), because on a real shift the two look almost the same at first glance.

You will also use the technique's family: the parent T1578 and its siblings T1578.002 Create Cloud Instance, T1578.003 Delete Cloud Instance, T1578.004 Revert Cloud Instance and T1578.005 Modify Cloud Compute Configurations. Attackers chain them; defenders must tell them apart in logs.

Who uses all this at work? The SOC analyst triages snapshot alerts. The detection engineer turns analytic AN1187 into a SIEM rule. The incident responder decides what to contain first without destroying evidence. The cloud security engineer implements mitigations M1018 (least-privilege snapshot permissions) and M1047 (routine permission audits). The CTI analyst reports that tools like Pacu can create EBS and RDS snapshots. Each exercise below is a small version of one of those real tasks.

🔑 Keywords covered in this exam

Every exercise below is built from these concepts. They come directly from the ATT&CK page for T1578.001 and its linked objects.

Technique mechanics

  • Snapshot as a point-in-time copy — and what it does NOT capture (live memory, traffic)
  • Bypassing access restrictions by mounting the copy elsewhere
  • Snapshot sharing via ModifySnapshotAttribute (cross-account exposure)

Family and tactic

  • Parent T1578 — Modify Cloud Compute Infrastructure
  • T1578.002 Create Cloud Instance · T1578.003 Delete Cloud Instance
  • T1578.004 Revert Cloud Instance vs T1578.001 — copying vs wiping evidence
  • T1578.005 Modify Cloud Compute Configurations (firewall rules)
  • Tactic: Defense Impairment

Detection logic (DET0423 / AN1187)

  • Correlating snapshot creation with instance creation and mounting
  • Suspicious sequences: new/unexpected IAM users, sensitive volumes without change control, unauthorized mounts
  • Cross-referencing user behavior, IP geolocation, automation context

Telemetry and platforms

  • Cloud audit logs (CloudTrail) event pairs and fields
  • IaaS coverage — same pattern in AWS and Azure CLI forms

Mitigations

  • M1018 User Account Management — least privilege, entitlement reviews
  • M1047 Audit — routine permission checks
