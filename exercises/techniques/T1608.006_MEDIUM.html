What you will learn here

You already met the basics of T1608.006 — SEO Poisoning in the EASY file — now we open the machinery. It is still a Sub-Technique of T1608 Stage Capabilities in the Resource Development tactic (TA0042), platform PRE: preparation work that runs before any victim appears. The goal is unchanged — poison the signals that decide search placement so victims find the attacker's page through their own queries — but here you learn how the rigging is actually done.

Two manipulation tools take centre stage. First, incoming links: the attacker buys or plants links from other sites to a staged page, because crawlers count each link as a small vote of relevance and reputation. A farm of dozens of fresh domains all pointing at one thin site can push it above real vendors. Second, in-site search: the search box inside a developer platform such as GitHub ranks results with its own algorithms and metrics such as popularity. Game those metrics and a barely-used, backdoored package rises to the top — the doorway to Supply Chain Compromise (T1195).

Then comes cloaking — showing different content to different visitors at the same address. The crawler gets a stuffed, keyword-rich page so the ranking rises; a person gets something else. What the server shows can depend on the browser user agent, the visitor's language and localization settings, or other HTTP headers, and client-side scripts can even measure mouse movements to prove a human is present. Evasive redirects complete the trick: scanners and wrong audiences stall on a harmless decoy, while a verified human is waved onward to the payload.

This behaviour sits inside a lifecycle. Upstream, the stuffing canvas usually comes from compromised sites (T1584 Compromise Infrastructure). Downstream, the click leads to Drive-by Compromise (T1189) and often a client exploit (T1203 Exploitation for Client Execution); the in-site variant leads to backdoored packages (T1195). The attacker accepts trade-offs: durable, self-selected traffic with no phish for defences to catch, but volatile rankings, crawler-penalty risk, and paid ads (malvertising) as the costly alternative.

Who uses this file at work? A SOC analyst reads poisoned-result alerts and redirect traces. A CTI analyst doing brand monitoring watches search results and link graphs for abuse of your name. A threat hunter compares crawler views with visitor views and replays chains in a real browser. Incident response traces what follows the poisoned click. A detection engineer writes the pivot logic — most staging stays invisible, so the hunt starts at post-click telemetry. And an SEO or web admin patches and audits owned sites so they never become the attacker's canvas. Expect two connected ideas per exercise: think one step beyond the first obvious fact.
