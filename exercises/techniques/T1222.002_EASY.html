🧭 What you will learn here

This exam is about one small piece of the MITRE ATT&CK framework. ATT&CK is a big catalogue of the things real attackers do. Each entry is called an object. The object here is a sub-technique — a detailed child of a bigger technique. Its parent is T1222 — File and Directory Permissions Modification, and this child, T1222.002, covers the same behaviour on Linux and macOS systems.

What is the behaviour? Imagine an attacker who is already inside a computer. Files on Linux and macOS have permissions — simple rules that say who can read, write, or run each file. The attacker can change those rules with commands like chmod (change mode), chown (change owner), chattr (change attributes on Linux) and chflags (change flags on macOS). They do this to reach files they should not touch, to make their own tools runnable, to hide files, or to lock defenders out. That is why ATT&CK puts this behaviour under the Defense Impairment tactic — the phase where the attacker blunts the defences. (Older ATT&CK versions called this tactic Defense Evasion.)

Where will you use this at work? Almost everywhere. A SOC analyst sees alerts like “chmod 777 on /etc/shadow” and must say if it is an attack. A threat hunter searches logs for these commands. An incident responder checks file permissions during forensics. A CTI analyst reports which groups used it — for example APT38 used chmod 777, and TeamTNT used chattr. A detection engineer writes rules for tools like auditd. A GRC analyst writes the permission policy. A red teamer uses the same commands quietly in tests. The risks are real: hidden malware, backdoors, and files the defenders cannot change.

By the end of this exam you will recognise the commands, know what each one changes, and spot the difference between a normal admin action and an attacker action. All words are explained in simple English as we go.
