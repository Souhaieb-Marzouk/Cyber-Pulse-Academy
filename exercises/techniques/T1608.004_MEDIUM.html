What you will learn here

You will learn how T1608.004 — Drive-by Target works in MITRE ATT&CK. It is a Sub-Technique of T1608 Stage Capabilities and lives in the Resource Development tactic (TA0042) on the PRE platform, which means the work happens before any victim appears. The adversary prepares web content so that a later, completely normal visit to a page can infect the visitor's browser or quietly profile the visitor's system. Profiling means the staged code reads the browser's details first, before any exploit is used.

This file goes deep on the three staging methods ATT&CK names. Method one: inserting malicious scripts into web pages or into user-controllable content such as forum posts — any field a member can edit. Method two: modifying script files that many websites load from publicly writeable cloud storage buckets — one edit, many victims, a huge blast radius. Method three: malvertising — crafting a malicious web advertisement and buying ad space through a legitimate ad provider, so trusted sites serve the payload without being breached. The staged code is usually JavaScript, and it often hides inside an iframe — an invisible window inside the page that silently loads a second site.

You will also learn the order of the drive-by chain. The staging you study here is T1608.004; when the visitor lands on the prepared page, that event is T1189 Drive-by Compromise, and the code running in the browser is T1203 Exploitation for Client Execution. Before exploiting, adversaries may stage a small profiling script — ATT&CK names the ScanBox framework — so the exploit is only spent on browsers that are truly vulnerable; that profiling visit is T1592 Gather Victim Host Information. When the prepared site is one a whole community — a government body, an industry, a region — visits regularly, the campaign is a strategic web compromise, better known as a watering hole.

You will meet the infrastructure side too: adversaries may buy lookalike domains (T1583.001) — homoglyphs, typosquats, or the same brand name on a different top-level domain — to funnel visitors into their staged pages, and they may rent ad space (T1583.008) instead of compromising a single site. Each choice trades effort against reach, and this file makes you pick the right door for each report.

This material is daily work for several roles. A SOC analyst reads proxy logs for new external scripts after normal page loads. A threat hunter checks the organisation's own sites for injected content and audits third-party script sources. A CTI analyst tracks watered domains and warns the community. An incident responder cleans up after drive-by events. A web admin locks down writeable buckets, user fields and ad slots. A detection engineer documents what staged pages look like. In the 15 exercises you will classify real-looking reports, order two full operations, read two proxy logs, and run one read-only iframe audit in a simulated terminal.
