ⓘ What you will learn here

▣ YOUR TRAINING GOAL

You will learn about one small but important piece of the MITRE ATT&CK framework: the sub-technique T1578.002 — Create Cloud Instance. Imagine you are a new defender at a company. An attacker steals a cloud login, and instead of touching the company’s servers, the attacker creates a brand-new virtual machine inside the company’s own cloud account. Why? To hide. The new machine does not carry the firewall rules, the monitoring agents, or the strict permissions of the machines the company already watches.

ATT&CK is a big catalogue of attacker behaviours. This object is a sub-technique: a specific child of the bigger technique T1578 — Modify Cloud Compute Infrastructure. It belongs to the tactic Defense Impairment (older ATT&CK versions called it Defense Evasion) — the attacker goal of avoiding your defenses.

You will meet this object in many real jobs. SOC analysts triage alerts when a new instance appears. Threat hunters search cloud logs for instances created at odd hours or from odd places. Incident responders isolate and image rogue virtual machines. Detection engineers build alerts from the ATT&CK detection strategy DET0449. Cloud engineers apply least-privilege permissions (mitigation M1018) and run permission reviews (mitigation M1047). CTI analysts report real groups — Scattered Spider and LAPSUS$ — that did exactly this. Red teamers emulate the behaviour to test the blue team. The risk it addresses is simple: an attacker who can create instances can watch, move, and steal from inside your own cloud — with your money and on your trusted network.
