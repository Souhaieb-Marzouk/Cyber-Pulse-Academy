🎓 What you will learn here

You will learn what the MITRE ATT&CK technique T1574 — Hijack Execution Flow is and why attackers love it.

Imagine a program you trust, like a backup tool or an updater. Now imagine an attacker makes that trusted program run the attacker's own code, without touching the program itself. That is a hijack of execution flow. The trick works because every operating system follows fixed rules when it looks for programs to start and for library files (shared code files that programs load) to attach. If an attacker can put a file with the right name in one of the places the operating system looks, the trusted program loads the attacker's file instead.

T1574 is a parent technique: it groups 12 sub-techniques, and each sub-technique is one specific way to hijack the flow (fake DLLs on Windows, dylibs on macOS, the Linux dynamic linker, weak service paths, and more). ATT&CK maps it to the Execution and Stealth tactics.

Why does this matter in real work? A SOC analyst triages alerts where a signed program loaded a strange file. A threat hunter looks for planted libraries next to signed programs. An incident responder checks service paths after a break-in. A CTI analyst writes reports naming the exact sub-technique. A detection engineer turns the page's detection strategy (DET0218) into rules. A GRC or control owner funds the fixes: safer permissions, allowlisting, patched software. The risk this family addresses is big: malware that looks legitimate, comes back at every start (persistence), gains high rights, and slips past application control.
