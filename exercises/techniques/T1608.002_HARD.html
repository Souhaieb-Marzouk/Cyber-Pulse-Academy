T1608.002 Upload Tool is a Sub-Technique of T1608 Stage Capabilities, and it lives in tactic TA0042 Resource Development on the PRE platform. It describes one quiet act: an adversary uploads a tool — legitimate software repurposed, like PsExec (S0029) — to third-party or adversary-controlled infrastructure so the tool is reachable when the operation needs it. Unlike malware (its sibling T1608.001), a tool was not built to be malicious; it becomes part of the attack because of where it sits and who pulls it later.

Staging happens before a victim is touched. The adversary buys or rents a server (T1583 Acquire Infrastructure), takes over somebody else's (T1584 Compromise Infrastructure), or borrows a public web service — a code repo, a Platform-as-a-Service tenant, a file-transfer portal, a paste site. Upstream, T1587 Develop Capabilities and T1588 Obtain Capabilities put the tool in their hands. Downstream, Ingress Tool Transfer (T1105) pulls the file onto the victim side and User Execution (T1204) runs it — that is the moment staging turns into real capability.

Why should a SOC analyst or detection engineer care? ATT&CK assigns exactly one detection strategy to this technique: DET0834 (analytic AN1966), which leans on Internet Scan — external scanning of attacker-controlled infrastructure. Staging rarely crosses victim sensors, so your honest coverage comes from victim-side transfer and execution telemetry. Knowing that gap keeps a detection roadmap truthful and stops a tool purchase from being sold as full coverage.

Threat hunters and CTI analysts use T1608.002 to read campaigns: Medusa Group hosting an RMM installer zip on the file hosting service filemail[.]com, Lazarus hosting tools on multiple servers in Operation Dream Job (C0022), UNC3890 staging on their own infrastructure (C0010), the 2025 Poland Wiper Attacks keeping tools on Dropbox and Pastebin (C0063), and Threat Group-3390 parking gsecdump (S0008) and WCE on previously compromised websites. Each location class tells you what to look for and what to pivot on next.

Incident responders meet this technique from the other side: a tool directory on your own compromised web server is staging evidence — snapshot first, then remove the minimum. Red teamers stage tools in authorized operations and must manage the same exposure risk: a staged copy gives control but paints the infrastructure for scanners and takedowns. GRC and intel teams track it under M1056 Pre-compromise, the only mitigation assigned here. All jargon — staging, dual-use, pinned build, RMM, observable — is explained where it first appears.
