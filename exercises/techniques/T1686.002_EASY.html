What you will learn here

You will learn about T1686.002 — Network Device Firewall, a sub-technique in the MITRE ATT&CK framework. A sub-technique is one specific way an attacker carries out a bigger technique. The big technique here is T1686 — Disable or Modify System Firewall. This sub-technique is about firewalls that protect a whole network: routers, switches, and perimeter firewall appliances. It does not cover the firewall inside one Windows computer — that is its sister sub-technique, T1686.003. It also does not cover cloud firewalls — that is T1686.001.

Imagine you are a security analyst. An attacker has stolen the password for your border firewall. From a far-away computer, the attacker logs in and adds a new rule: allow all traffic. Doors that were closed are now open. The attacker can send commands out (command and control) and jump deeper into your network (lateral movement). That behaviour is exactly what T1686.002 describes.

You will see where this object is used in real work: a SOC analyst triages the alert; a firewall administrator keeps the rules clean; a threat hunter looks for hidden rule changes; an incident responder restores the trusted configuration; a CTI analyst reports which attacker groups did this; a GRC or control owner checks that only the right people can change rules. The tools are the firewall CLI and GUI, the SIEM that collects firewall logs, and change tickets. The documents are config backups, change tickets, and threat-intel reports. The risk it addresses: an attacker quietly opening the network so they can stay inside and move around.

Technique basics

  • T1686.002 — Network Device Firewall: what the sub-technique describes
  • Parent technique T1686 — Disable or Modify System Firewall; sisters T1686.001 Cloud Firewall and T1686.003 Windows Host Firewall
  • Tactic: Defense Impairment (this tactic was formerly called Defense Evasion) — the attacker's goal of weakening protections
  • Platform: Network Devices (routers, switches, perimeter firewall appliances)
  • ACLs and firewall rules in plain words: an ACL (access control list) is the firewall's list of who may talk to whom

Attacker behaviour

  • Adding an allow-all rule on a perimeter firewall
  • Blocked traffic becoming allowed traffic
  • Why attackers do it: open a path for command and control and lateral movement
  • The simple order of steps: get admin access → change the rule → reach blocked servers

Defender view

  • The firewall configuration change log — the diary of rule changes
  • Mitigations M1047 Audit, M1051 Update Software, M1018 User Account Management
  • Telling a network firewall change apart from a Windows host firewall change
