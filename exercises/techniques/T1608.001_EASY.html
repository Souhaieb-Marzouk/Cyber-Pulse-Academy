What you will learn here

Welcome! In this exam you will learn about T1608.001 — Upload Malware. It is a Sub-Technique of T1608 (Stage Capabilities), and it sits in the Resource Development tactic (TA0042). ATT&CK lists it on the PRE platform only: everything happens before the attacker ever touches a victim network.

Staging is easy to picture: the attacker puts malware somewhere reachable, like placing bait in a trap before setting it. The malware can be a payload (the harmful file itself), a dropper (a small file that installs the real malware), a post-compromise tool (a tool used after a break-in), or a backdoor (a hidden way back inside). The attacker uploads it to a rented web server, a hacked server, a paste site, a cloud folder, or even a software store. No victim is attacked yet — but the trap is armed.

You will use this in real work. As a SOC analyst, you will see alerts where a workstation quietly pulls a file from a server nobody recognises — that pull often starts at a staged link. As an IR analyst, you will trace where a downloaded payload came from and find the staging host behind it.

As a CTI analyst, you will track staging infrastructure and record its URLs, hashes and patterns. As a threat hunter, you will pivot on staging URLs and open directories. As a detection engineer, you will build coverage for the downstream pull (T1105 Ingress Tool Transfer) and the execution (T1204.002 User Execution), because ATT&CK's own detection note (DET0824) says staging usually happens outside victim view.

Red teamers stage payloads in authorized operations so defenders can practise seeing it, and GRC teams (governance, risk and compliance) use the single ATT&CK mitigation, M1056 Pre-compromise, to plan defensive work before any victim contact. Ready? The fifteen exercises below walk you from the definition to your first safe handling command.
