What is T1595.001 — Scanning IP Blocks?

MITRE ATT&CK is a public catalogue of attacker behaviours. Each behaviour has an ID. This exam is about T1595.001 — Scanning IP Blocks. It is a sub-technique: a child of the technique T1595 (Active Scanning). It belongs to the tactic Reconnaissance (TA0043). In ATT&CK, a tactic is the goal of a phase, and a technique is the way to reach that goal.

What the behaviour is: imagine a thief who wants to rob one house in a big neighbourhood. Before touching any door, the thief walks down the whole street and notes which doors exist and which ones look open. Scanning IP Blocks works the same way: the attacker sends small network messages (probes) to many internet addresses that belong to the target company. Each address is like a door. The attacker notes which addresses answer and which ports (numbered doors) are open. Ports reveal services: a login portal, remote desktop, a file share, and so on.

Key facts you will use in every exercise: the attacker is still outside the target network — ATT&CK marks this platform PRE. The attacker needs no account and no special rights, just an internet connection. Because the probes touch the target’s own addresses, this is active scanning; looking data up in a search engine such as Shodan would be passive (no packets touch the target). Because the probes stop at the company’s border, the company’s computers usually log nothing. The best telemetry sits at the edge: perimeter firewalls, flow records, intrusion detection, and honeypots (fake servers set as traps).

Why it matters at work: this behaviour is usually the first visible step of a planned attack, and different roles use that fact differently. SOC analysts watch edge logs for sweep patterns — one source touching many addresses. Detection engineers write analytics for those patterns, including slow and distributed scans that hide under thresholds. Threat-intelligence analysts link scanning campaigns to known groups — public reporting documents mass scanning before attacks by groups such as Lazarus, Sandworm and Volt Typhoon. Incident responders use scan evidence to show pre-attack intent in reports. Red teamers and pentesters scan with written permission to test exposure like a real attacker. GRC analysts and control owners shrink what a scan can find: close unneeded ports, restrict admin interfaces, keep the exposed surface boring. You cannot stop someone scanning public addresses — you can control what the answers tell them.

In this exam you will use T1595.001 from both sides: how an attacker runs it and what they gain, and how a defender detects it and blunts it.
