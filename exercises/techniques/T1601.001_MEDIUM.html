What you will learn here

You already know the basics: T1601.001 — Patch System Image means an attacker modifies the operating system image of a network device — one single file that contains the whole OS. This exam takes you one step deeper, the way a real shift would.

Why does an attacker patch the image? The ATT&CK description is clear: by modifying the instructions in the image, the attacker can weaken defences (encryption via Weaken Encryption T1600, authentication, perimeter defence) or add new capabilities — keylogging, a multi-hop proxy, port knocking. A patched image can even make CLI commands lie about the device's version.

Where does it happen? In storage: download an image with TFTP/FTP/SCP, overwrite flash or point the boot variable at the new file, reload. Or in memory: native debug commands (this needs administrative access) or a boot-loader implant. Memory patches die at reboot; storage patches survive. The sibling T1601.002 installs an older image — expect weaker ciphers and older defences.

Who works with this? SOC analysts combine three log sources — TACACS+/RADIUS command accounting, file-transfer logs, and syslog boot/reload messages. Threat hunters keep per-device checksum baselines. Detection engineers tune analytics (like ATT&CK's detection strategy for Modify System Image) against false positives from planned upgrades. IR responders contain, preserve evidence, and rebuild with signed images. GRC/control owners enforce MFA (M1032), least-privilege admin accounts (M1026), password policy (M1027) on top of image integrity controls (M1045, M1046).

Keywords covered in this exam

Keylogging, Multi-hop Proxy, Port Knocking — capabilities a patched image can add

Weaken Encryption (T1600) — a defence a patched image can weaken

⚙️ Theme 2 — The two patching paths

Storage chain — transfer → overwrite/boot variable → reload → persists

Memory patch — native debug commands, administrative access, dies at reboot

T1601.002 Downgrade System Image — the sibling: older image, weaker ciphers

🔍 Theme 3 — Telemetry and analytics

TACACS+ / RADIUS command accounting — which admin ran image commands

File-transfer logs + syslog boot/reload messages — the chain of evidence

Checksum baselines — per-device fingerprints to compare against

🛡 Theme 4 — Controls and response

M1032 / M1026 / M1027 — MFA, privileged account management, password policy: stop the access

M1045 / M1046 — code signing, boot integrity: stop the image

IR phases — detect, verify, contain, recover with signed images
