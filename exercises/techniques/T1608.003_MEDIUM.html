What you will learn here

You will learn about T1608.003 — Install Digital Certificate, a Sub-Technique of T1608 Stage Capabilities in the Resource Development tactic (TA0042). This is staging work: it happens before any victim is touched. The adversary uploads an SSL/TLS certificate file to a server it controls — a web server or an email server — and configures that server to use the certificate for encrypted communication. From that moment the host can speak hxxps.

Why does a padlock help an adversary? Two reasons. First, a working certificate gives visitors the padlock and no browser warning, so a staged host looks legitimate — exactly what a credential-harvesting page needs. Second, the certificate enables encrypted C2: ATT&CK's example is Asymmetric Cryptography (T1573.002) over Web Protocols (T1071.001), so beacon traffic hides inside ordinary-looking hxxps. Two words of jargon: the issuer is the entity that verified the certificate's contents and signed them; the SAN (Subject Alternative Name) is the list of hostnames the certificate covers.

Certificates come from two directions. The obtain path (T1588.004) gets a real, CA-signed certificate: buy one, enroll with a free automated CA (Let's Encrypt-style — nearly free and instant), or capture one from a victim — Sea Turtle did exactly that in 2019. The develop path (T1587.003) creates a self-signed certificate that no public CA vouches for. Self-signed is free and fast but triggers browser warnings; CA-issued earns trust but leaves an issuance paper trail. The install lands on infrastructure that is acquired (T1583) or previously compromised (T1584).

This topic is daily bread for several roles. A SOC analyst reads proxy and egress logs and asks what an hxxps beacon hides. A CTI analyst pivots on certificate details — issuer, serial number, SAN — to cluster adversary servers. A threat hunter watches Certificate Transparency logs — public records of every certificate issued — to spot lookalike domains the moment they are certified. A detection engineer maps the downstream observables. A phishing assessment always asks whether the lure carries a valid padlock. And a pentester stages authorized test hosts the same way.

This MEDIUM file raises the bar one step: every exercise connects two ideas, distractors are plausible but explainable, and hints narrow the direction without handing over the answer. You will weigh the attacker's trade-offs, sequence the staging lifecycle, read egress and handshake artefacts from both the attacker's and the defender's side, and finish with one defender command that reads the paper trail behind a suspicious host's certificate.
