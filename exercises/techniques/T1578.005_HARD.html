T1578.005 — Modify Cloud Compute Configurations (MITRE ATT&CK sub-technique of T1578 — Modify Cloud Compute Infrastructure)

Severity: ◆ HARD Exercises: 16 Estimated time: about 45 minutes · Timer budget: 45:00 countdown Pass mark: 70%

What you will learn here

You are now training the same ATT&CK object at a harder level: T1578.005 — Modify Cloud Compute Configurations, sub-technique of T1578 — Modify Cloud Compute Infrastructure, Defense Impairment tactic (TA0112; the April 2026 ATT&CK v19 update split the old Defense Evasion tactic), IaaS platform. The behaviour: an adversary with cloud credentials changes account-wide compute settings — service quotas, subscription associations, tenant-wide policies, and allowed regions — so that later abuse fits under limits and outside views. The ATT&CK description stresses the stealth property: the changes happen without affecting running instances, so no host breaks and no host alarm fires.

At this level you practise the discriminations that real analysts get paid for. The same change can be a migration step or an intrusion step — only identity, ticket, and follow-on context tell them apart, and the wrong shortcut leads to the wrong answer. You will weigh a Terraform plan against a CloudTrail log against a change ticket; you will spot a policy diff that "looks approved" but quietly removes a guardrail instead of adding a region; you will order an evidence-first response, because reverting a policy too fast destroys the proof of who changed it. You will also tune the ATT&CK detection analytic for this technique: its chain logic (configuration change followed by provisioning) and its mutable elements — UserContext, TimeWindow, ChangeType, GeoLocation.

The work context is real: detection engineers own the analytic and its tuning; cloud security engineers own guardrail policies (AWS service control policies, Azure Policy, Google Cloud organization policy); IR leads own the evidence-first sequence; CTI analysts brief findings with the ATT&CK mapping and citations such as the Microsoft Threat Intelligence cryptojacking reporting of 2023; GRC analysts verify that M1018 User Account Management and M1047 Audit actually cover this behaviour. Expect near-miss answers: several options will look right in a different incident. In this incident, only one is right.

Keywords covered in this exam

ATT&CK position & stealth

  • T1578.005 sub-technique of T1578 · Defense Impairment (TA0112) · IaaS
  • Settings named in the description: quotas, subscription associations, tenant-wide policies, locations
  • Silent property: running instances untouched
  • Chain: T1578.005 → T1496 Resource Hijacking / T1535 Unused Regions

Guardrails under attack

  • AWS service control policies (UpdatePolicy)
  • Azure Policy assignments (allowed locations)
  • Region-deny guardrails & allowed-locations rules
  • Quota codes (L-1216C47A on-demand vCPUs)

Sibling discrimination

  • T1578.001 Create Snapshot vs T1578.002 Create Instance
  • T1578.003 Delete Instance vs T1578.004 Revert Instance
  • T1578.005 = account-wide configuration, not instance lifecycle

Detection engineering

  • Configuration-then-provisioning correlation chain
  • Mutable elements: UserContext, TimeWindow, ChangeType, GeoLocation
  • Exclusion lists for automation roles
  • False positives: migrations, planned capacity work

IR & evidence handling

  • Evidence-first ordering (export before revert)
  • Read-only lookups (cloudtrail lookup-events, region status)
  • Revert-versus-preserve tension
  • Least-aggressive containment

Real-world reporting & controls

  • Microsoft Threat Intelligence cryptojacking (2023): quota + region abuse
  • M1018 User Account Management (preventive)
  • M1047 Audit (detective)
  • Red/blue dual perspective on the same scenario
