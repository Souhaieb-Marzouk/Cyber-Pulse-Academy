🎓 What you will learn here

Welcome! This practice exam teaches you T1578.001 — Modify Cloud Compute Infrastructure: Create Snapshot, a sub-technique in the MITRE ATT&CK framework.

First, what is ATT&CK? It is a big catalogue of the ways real attackers behave. Each behaviour gets an ID like T1578.001. A sub-technique is a detailed version of a bigger behaviour (the parent technique T1578). Think of the parent as "attackers change cloud machines" and the sub-technique as one exact way to do it.

This sub-technique is about snapshots. A snapshot is a photo-like copy of a cloud disk at one moment in time. Cloud teams use snapshots every day for backups. Attackers like them too: with the right permissions, they can copy a disk without touching the running machine, then read the copy somewhere else. That helps them reach data the normal rules would block, and it helps them stay quiet.

You will learn where this object is used in real work. A SOC analyst reads cloud logs and looks for snapshot events. An incident responder checks if an attacker copied a disk during a breach. A threat hunter searches for strange snapshot patterns. A CTI analyst reports which tools (like the open-source tool Pacu) can create snapshots. A detection engineer writes rules for snapshot events. A cloud security engineer limits who may create snapshots. A GRC analyst checks that permission reviews really happen.

The tools and documents you will see here: cloud audit logs (for example AWS CloudTrail), IAM policies, change calendars, and ATT&CK pages for mitigations M1047 and M1018. By the end, you will know what a snapshot is, why attackers create them, which tactic this belongs to (Defense Impairment), and what defenders do about it.
