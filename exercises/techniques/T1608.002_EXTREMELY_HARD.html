T1608.002 Upload Tool is a Sub-Technique of T1608 Stage Capabilities, and it sits in the TA0042 Resource Development tactic on the PRE platform — the preparation phase, before any victim is touched. It describes one quiet act: an adversary uploads a tool to third-party or adversary-controlled infrastructure so the tool is reachable when the operation needs it. A tool here is legitimate software repurposed — think PsExec (S0029) — not malware that was built to be bad.

Where do tools wait? On rented servers (T1583), hacked websites (T1584 — Threat Group-3390 staged gsecdump and WCE this way), GitHub-class repos, Platform-as-a-Service tenants, one-shot file-transfer portals (Medusa Group used filemail[.]com for an RMM zip), and cloud drives or paste sites (the 2025 Poland Wiper attacks used Dropbox and Pastebin). Staging alone delivers nothing: the value arrives when the victim side pulls the file — T1105 Ingress Tool Transfer — and runs it — T1204 User Execution.

This file is the EXTREMELY HARD tier, and its theme is response: what defenders do about staging. CTI analysts track staging infrastructure as observables — URL and hash records shared on intel platforms (MISP / Recorded Future / Anomali-class) with a confidence level saying how sure the sharer is. OSINT monitors (SpiderFoot / Recon-ng-class) sweep public paste sites and portals for posted artefacts. Takedowns and blocking are real answers, but timing them wrong tips off an adversary who rotates within hours.

SOC, IR and GRC teams meet this under M1056 Pre-compromise, the only mitigation ATT&CK assigns here: scan your own external attack surface (Shodan / Censys-class) to find staged tool directories on forgotten hosts, watch for lookalike domains, and run a hunt loop that captures file hashes and watches repo and account re-uploads. Incident responders face the costly calls: a staged directory on your own public portal means accepting downtime to preserve evidence and take it offline.
