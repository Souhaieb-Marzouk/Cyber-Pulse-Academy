🎓 What you will learn here

This is the HARD tier for T1578.001 — Create Snapshot (sub-technique of T1578 Modify Cloud Compute Infrastructure, tactic Defense Impairment, platform IaaS). You already know the definition: an adversary creates a point-in-time copy of a VM disk, virtual hard drive or volume to evade defenses and bypass restrictions that block access to running compute infrastructure.

At this level the exercises stop being definitions and start being work. Scenarios give you several artefacts at once — CloudTrail extracts, IAM policy diffs, change-calendar entries, chat messages — and expect you to correlate them the way analytic AN1187 does: correlate snapshot creation with instance creation and mounting, then separate benign automation from adversary exploitation using user behavior, IP geolocation and automation context. Expect near-miss answers: at least two options will look technically defensible, and only one survives the specific facts you were given.

Real-world procedure examples are now in scope. The ATT&CK page names Pacu (S1091), the open-source AWS exploitation framework from Rhino Security Labs, which can create snapshots of EBS volumes and RDS instances — you will meet its modules in evidence. You will also decide containment order, pick the least aggressive action that stops the harm, and occasionally conclude that the scary-looking event is actually the scheduled backup job.

This tier mirrors the daily judgement calls of a senior SOC analyst, a cloud-focused incident responder and a detection engineer tuning DET0423 — plus the red-team side: why an operator shares a snapshot out of the account instead of mounting it locally, and what that trade-off leaves in the logs. The two mitigations, M1047 Audit and M1018 User Account Management, appear as live decisions, not vocabulary.

🔑 Keywords covered in this exam

Every exercise below is built from these concepts. They come directly from the ATT&CK page for T1578.001 and its linked objects.

Correlation and detection (DET0423 / AN1187)

  • Snapshot creation correlated with instance creation and mounting
  • Red flags: new/unexpected IAM users, sensitive volumes without change control, unauthorized mounts
  • Cross-references: user behavior, IP geolocation, automation context
  • Benign look-alikes: scheduled DLM jobs, CI pipelines, approved change windows

Real-world tooling (S1091 Pacu)

  • Pacu can create snapshots of EBS volumes and RDS instances
  • Pacu modules: enumeration, EBS snapshot duplication/exfiltration, RDS snapshot abuse, IAM permission discovery
  • User-agent evidence in CloudTrail events

Attacker economics and trade-offs

  • Sharing a snapshot to an external account vs mounting a volume in-place
  • What a snapshot contains — and what it never contains
  • Chain mapping onto T1578.001 / T1578.002 / T1578.005

Evidence and containment

  • Preserve-then-contain: least aggressive action that stops the harm
  • Containment order: stop the leak, stop the actor, keep the evidence, clean up, report
  • Monitoring priorities across volume classes

Controls (M1047 / M1018)

  • M1047 Audit — routine entitlement checks on snapshot capability
  • M1018 User Account Management — least privilege, few admin roles, periodic reviews
