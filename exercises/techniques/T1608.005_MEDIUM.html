What you will learn here

Welcome to the MEDIUM tier for T1608.005 — Link Target. It is a Sub-Technique of T1608 (Stage Capabilities) and lives in the Resource Development tactic (TA0042), on the PRE platform: everything happens before any victim is touched. The core rule is unchanged — the page or file that a phishing link points to must be staged before the phish is sent. This file goes one level deeper: how that destination is wrapped, timed, rotated and traced.

The staged destination is usually an HTML page with a little client-side JavaScript (code that runs inside the visitor's browser) deciding what content to serve. Very often the page is a cloned login page — a copy of a real sign-in screen. The lure tricks the user into typing credentials, and sometimes a one-time MFA code (the second-step number), straight into the clone. Other times the link simply points at a hosted malware file waiting to be downloaded.

The link itself is dressed up. A shortener hides the true destination behind a tiny address on a widely trusted domain. A lookalike domain imitates a real name: a homoglyph swaps a letter for one that looks identical from another alphabet, a typosquat makes a tiny typing-error, and a different top-level domain (the suffix after the last dot) changes the ending. User-info abuse parks a trusted name in front of an @ sign, and a project page on a trusted PaaS provider (Platform-as-a-Service — rented app hosting) quietly bounces visitors onward.

Timing is tradecraft. Stage the target too early and it rots — scanners find it and hosts take it down. Stage too late and the campaign window closes. Careful operators sanity-check the target against scanners, send the wave, and rotate to fresh infrastructure once the current destination is flagged. Every clone also leaves kit fingerprints — shared asset paths and repeated typos that let defenders link pages built by the same phishing kit.

You will use this in daily work. A SOC analyst triages reported links without opening them. A CTI analyst tracks kits and panels through their fingerprints. A threat hunter pivots on staging URLs found in internet scans. In IR (incident response) you contain credentials a clone already captured. Awareness training lowers the click probability, and a detection engineer hardens the mail channel that carries the link.
