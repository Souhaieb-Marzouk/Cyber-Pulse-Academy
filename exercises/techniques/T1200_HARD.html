📘 About the ATT&CK object: Hardware Additions (T1200)

T1200 — Hardware Additions is a Technique in MITRE ATT&CK under the Initial Access (TA0001) tactic: an adversary physically introduces computer accessories, networking hardware, or other computing devices into a system or network, and that hardware becomes the vector to gain access. It has no sub-techniques and runs on Linux, Windows and macOS.

The technique is broader than payload drops by USB stick (that contrast is T1091). The ATT&CK description names the capability families: passive network tapping, network traffic modification (Adversary-in-the-Middle, T1557), keystroke injection, kernel memory reading via DMA, and new wireless access points. It also states that public threat-actor usage is scarce while red teams use it heavily — one documented example is G0105 DarkVishnya, which connected Bash Bunny and Raspberry Pi class devices to bank LANs.

At this level you also need the detection side. ATT&CK defines detection strategy DET0069 — Detect unauthorized or suspicious Hardware Additions (USB/Thunderbolt/Network). Its analytic AN0185 (Windows) chains: a new external device recognized by Windows (Security event 6416 / Kernel-PnP), then — within a short window — the same user session spawning a process or mounting a volume, then optional follow-on activity such as HID keystroke injection, a DMA driver load, or a new network interface MAC on DHCP, all correlated with Sysmon and DHCP/network metadata. Analytic AN0186 (Linux) chains udev/kernel hot-plug messages, block devices, and optionally a new interface or DHCP lease, correlated with syslog, auditd SYSCALL open/creat on /dev, and DHCP/Zeek. The macOS chain (AN0187) uses unified logs (IOUSBHost/IOThunderbolt), diskarbitrationd, and optionally config profile manipulation. Mitigations stay the same two: M1034 (endpoint block of unknown devices) and M1035 (NAC: 802.1x, device certificates, DHCP for registered devices only).

Who uses this at work: detection engineers write and tune these chains; SOC analysts judge arrival alerts against the inventory and the follow-on window; IR teams scope rogue devices with switch and DHCP evidence; NAC engineers run M1035; red teamers emulate the behaviour with tools like passive LAN taps or pocket network boxes. The hard part is never the single event — it is telling the benign device apart from the rogue one using correlation, inventory and context.

In this HARD exam you will correlate 2–4 artefacts, separate near-miss answers, and justify every call. Several options will look almost right; only one is right here.

🔑 Keywords covered in this exam

These are the related concepts this practice exam trains. They come from the ATT&CK page for T1200 and from the objects linked to it.

🔍 Detection strategy

  • DET0069 — Detect unauthorized or suspicious Hardware Additions (USB/Thunderbolt/Network)
  • Chain logic: arrival → follow-on → optional network indicator

⚙️ Analytics

  • AN0185 — Windows: EID 6416 / Kernel-PnP + Sysmon + DHCP metadata
  • AN0186 — Linux: udev/kernel + auditd on /dev + DHCP/Zeek
  • AN0187 — macOS: unified logs + diskarbitrationd
  • Correlation window · follow-on: HID injection, DMA driver load, new MAC

🐧 Linux telemetry

  • udev / kernel hot-plug messages
  • /var/log/messages · syslog
  • auditd SYSCALL open/creat on /dev
  • DHCP · Zeek

🍎 macOS telemetry

  • Unified logs: IOUSBHost · IOKit · diskarbitrationd
  • FSEvents
  • Config profile manipulation

🛡 Mitigation design

  • M1034 vs M1035 — endpoint vs network layer
  • Trade-offs: user friction, exceptions, ops cost
  • Physical security as the root precondition

🏦 Example & tooling

  • G0105 DarkVishnya — banks, direct LAN connection
  • Bash Bunny · Raspberry Pi
  • Throwing Star LAN Tap · Pwn Plug class · DMA readers

🧩 Matrix neighbours

  • T1190 · T1133 · T1078 (same column)
  • T1557 AitM — different column, named in the description

📝 How this exam works

  • Goal: reach 70% or more to pass. Each exercise can give partial credit.
  • Exercise types: log-correlation cases, mapping with near-miss answers, an incident decision tree, an evidence-ordering task, and one terminal task where you pick the tool yourself.
  • Partial credit (in plain words): exercises with more than one correct item score per item. Correct picks add credit, wrong picks subtract it. The formula is (right − wrong) ÷ total, never below zero. So a half-right answer still earns part of the point.
  • Check = free time: when you press Check, the timer stops by itself. You can read the feedback and the explanation for as long as you want. Nothing is lost. The timer starts again only when you press Next (or Final Submit on the last exercise).
  • Manual pause: the Pause button is for a real break. It stops the timer and hides the exercise until you press Resume.
  • Hint: one hint per exercise. A hint costs 10% of that exercise's credit (never below zero). It gives a nudge, not the answer.
  • Skip: every exercise has a Skip button. Skipping is free. Skipped exercises go to a review pool. Before you finish, you may return to them and answer them, as long as the timer is still running. A skipped exercise that stays unanswered does not count at all — it is not right, not wrong, and not in your total.
  • Retake: if you fail, you can retake the exam. Questions and answer positions are shuffled again.
