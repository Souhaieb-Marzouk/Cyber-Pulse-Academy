What you will learn here

Imagine you guard the network of a mid-size company. One night, an attacker quietly changes the operating system file of an internet-facing router. No alarm rings. The router keeps forwarding traffic. But the attacker now controls the device from the inside. That attack has a name in MITRE ATT&CK: T1601.001 — Patch System Image.

This object is a sub-technique. In ATT&CK, a sub-technique is a more specific way of doing a bigger technique. The parent here is T1601 — Modify System Image. The sibling is T1601.002 — Downgrade System Image. Both live in tactic TA0005, which older ATT&CK versions call Defense Evasion and newer versions call Defense Impairment — it is the same tactic: the attacker tries to weaken or blind your defences.

You will learn what "patching the image" means. Many network devices (routers, switches, firewalls) keep their whole operating system in one single file, usually stored in flash memory. If an attacker replaces or edits that one file, they change the whole device. The change can survive restarts, and normal antivirus on a laptop will never see it.

Who uses this knowledge at work? SOC analysts name this technique in tickets when they see image files moving at strange hours. Threat hunters compare image checksums (a checksum is a fingerprint of a file) against the vendor's published values. Incident responders collect the image as evidence and rebuild devices. CTI analysts write reports that map attacker behaviour to T1601.001. Detection engineers build rules from device logs. GRC analysts and control owners ask for signed images and multi-factor login for admin access. Red teamers study the technique to test whether defences would catch it.

By the end of this exam you will recognise the object, its tactic, its family, the simple evidence it leaves, and the two controls that stop it: M1045 Code Signing and M1046 Boot Integrity.

⚙️ Theme 2 — How the attack works

Monolithic operating system — the whole OS lives in one image file

Patching in storage (flash) vs patching in memory — file change vs live change

TFTP / SCP image transfer and reload — how a new image arrives and when it activates

🔍 Theme 3 — What defenders look at

Checksum comparison — compare the image fingerprint with a known good copy from a trusted source

File-transfer logs, device syslog, TACACS+ command log — the simple telemetry

Boot configuration — which image the device loads at start

🛡 Theme 4 — Controls

M1045 Code Signing — vendors sign images; a changed file fails the check

M1046 Boot Integrity — the device verifies the image signature at boot

M1032 Multi-factor Authentication — a stolen password alone is not enough for admin access
