What you will learn here

You are working again with a Detection Strategy — that is the ATT&CK object type of DET0456. At the EASY level you learned what it watches. Here you learn how it thinks: how its rule AN1253 chains evidence, and how real teams tune it so it stays useful.

Quick recap in plain words. A token is a digital pass that says who a process is and what it may do. On Windows, an attacker who gets admin-level access can steal or duplicate such a pass and then start a new program that runs as someone else — for example as SYSTEM or as a finance administrator. That is the technique T1134.002 Create Process with Token. DET0456 catches it by chaining four stages: a suspicious API call, a privileged token access, a child process with a different security context (its SID, LogonId, or integrity level differs from the parent), and follow-on privileged actions.

Where you will use this at work: as a SOC tier-1 or tier-2 analyst you will triage the alerts and decide true or false positive. As a detection engineer you will own the five tuning knobs (the mutable elements): the correlation TimeWindow, the AllowedImpersonators allow-list, the IntegrityEscalationDelta, the ParentChildUserMismatch switch, and the SensitiveTargets list. As a threat hunter you will read raw logs with filters, the way the log viewer in this exam lets you do. As an incident responder you will turn the chain into a timeline. And as a CTI analyst you will connect the behaviour to real actors: ATT&CK documents groups like Lazarus Group and Turla, and software like Empire, PoshC2, and REvil using exactly this technique.

These exercises ask two connected questions each — for example: recognise the evidence, then choose the tuning change. Read the artefacts carefully; the answer is always in front of you.
