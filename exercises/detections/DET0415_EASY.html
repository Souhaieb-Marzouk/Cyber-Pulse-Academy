What you will learn here

Hello! In this exam you will learn about DET0415, a Detection Strategy in the MITRE ATT&CK framework. ATT&CK is a big, public catalogue that describes what real attackers do.

First, the attacker side: T1499.003 — Application Exhaustion Flood is a sub-technique of T1499 — Endpoint Denial of Service. It means the attacker finds a feature of an application that uses many resources (for example an expensive report page) and calls it again and again. The CPU and memory fill up, and the application stops working for real users. The attacker goal here is Impact (TA0040): hurting the availability of a service.

Now the defender side: a Detection Strategy is ATT&CK’s plan for how to see that behaviour in logs. DET0415 has four analytics, one per platform: AN1165 for Windows, AN1166 for Linux, AN1167 for macOS, and AN1168 for cloud (IaaS). Each analytic reads known log sources, such as Windows Event Logs, Sysmon, perfmon, auditd, Linux syslog, network flow records, the macOS unified log, osquery, and AWS CloudWatch, CloudTrail and CloudMetrics.

Who uses this at work? A SOC analyst triages the alerts these analytics raise. A detection engineer tunes their thresholds. An incident responder uses them during an outage. A cloud engineer watches CloudWatch dashboards. A threat intelligence analyst maps attack reports to T1499.003. A GRC analyst tracks the availability controls around it.

The main risk this object addresses is simple: a service that paying customers cannot use. That means lost money, broken promises (SLA), and a hard day for everyone. ATT&CK also lists one mitigation for this technique: M1037 — Filter Network Traffic, for example a CDN or a DoS-protection provider that drops flood traffic before it reaches your application.

Keywords covered in this exam

Technique & behaviour

  • T1499.003 — Application Exhaustion Flood
  • Parent technique T1499 — Endpoint Denial of Service
  • Tactic: Impact (TA0040) · Impact type: Availability

Detection strategy structure

  • DET0415 — one Detection Strategy, four analytics
  • AN1165 Windows · AN1166 Linux
  • AN1167 macOS · AN1168 IaaS (cloud)

Log sources & telemetry

  • DC0038 Application Log Content (WinEventLog:Application, linux:syslog, macos:unifiedlog, AWS:CloudWatch)
  • DC0032 Process Creation (Sysmon EventCode=1, auditd:SYSCALL execve, osquery)
  • DC0018 Host Status (Windows:perfmon, AWS:CloudMetrics)
  • DC0085 Network Traffic Content (NSM:Flow on 80/443/25)

Mitigation

  • M1037 — Filter Network Traffic
  • CDN / DoS-protection provider, upstream filtering

Benign vs malicious

  • Real user surges (flash crowds) are not floods
  • One signal alone is not proof
