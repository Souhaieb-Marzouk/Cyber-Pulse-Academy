Coverage Dashboard

Every topic on CyberPulseAcademy reserves three exercise batches: one on detection and triage, one on response and hands-on configuration, and one written from the attacker's side. Three batches across 2011 topics is 7801 batches planned, and this page is the public contribution roadmap for all of them: which exist today, which are still open, and in which catalog.

Nothing on this page is asserted by hand. Each count is read from data/catalog.json, the same manifest the catalog pages and every topic page are built from, and a batch is counted only when its recorded status is published. That is deliberate: a roadmap that can be edited for encouragement is worth nothing, and this one cannot be. If a topic reads as empty here, it is empty.

Where the project stands today

246 topics. 738 batches planned. At launch, 0 of those batches were published. Everything after that is the manifest's business: the counter above is recomputed from it on every build, so it reports how many batches really exist instead of a number typed into this page by hand. The first contributions are therefore the most valuable ones this project will ever receive: a single finished batch takes a topic from nothing to something for every visitor who studies it from then on, and there is no queue to wait in behind other work.

This summary is what the page says without JavaScript. With JavaScript, the table below replaces it with every topic and the state of each of its three batches.

How to read this dashboard

Each row in the table is one topic and its three reserved batches. Colour is never the only signal anywhere on this page: every cell also carries a symbol and the word published, draft or missing, and the same 0 to 3 scale is written out in words beside each swatch below. The batch pips on catalog cards follow the same rule.

0 of 3 batches — nothing published yet 1 of 3 batches — one published 2 of 3 batches — two published 3 of 3 batches — complete
  • ✓ published — the batch exists on its canonical path and the topic page links to it.
  • ○ draft — the batch is being written or reviewed. A draft is not counted as published, and a link to it is not offered yet, so nobody is sent to a half-finished exercise.
  • — missing — nothing has been written. The topic page says so plainly and points at the contribution guide instead of opening an empty frame.

The filter, the search box and the per-catalog select need JavaScript, because the table is drawn from the manifest in the browser. Without it this page shows the totals above and the seven catalog pages still list every topic.

Contribute a batch

Pick any topic with a gap, write the missing batch with the prompt and the content rules in the contribution guide, and open a pull request. You do not need permission, you do not need to be an expert, and you do not need to claim a topic before starting. A batch that is reviewed and corrected by someone else is still your contribution, and the review counts for the reviewer as well.

Why this dashboard cannot drift from the data

The manifest behind this page is regenerated by scripts/build_catalog.py from the topic files themselves, and the dashboard is recomputed from that manifest every time the page loads. No count is typed into the HTML, so publishing a batch cannot be forgotten here and a missing batch cannot be hidden. A generated page claims exactly what the data says and nothing more.
