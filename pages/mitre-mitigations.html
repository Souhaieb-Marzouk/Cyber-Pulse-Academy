MITRE ATT&CK Mitigations

CyberPulseAcademy covers 44 ATT&CK mitigations, from Multi-factor Authentication and Privileged Account Management through to Filter Network Traffic and Application Developer Guidance. Read them as categories of control, never as products. A mitigation in ATT&CK names the change you make to an environment, and the same category can be implemented well or implemented as a line in a spreadsheet.

Every mitigation topic states what the control actually changes, where it is normally bypassed, and how you would tell whether it is working. The cards below carry the count of techniques each control addresses; the coverage table shows exactly which techniques, with a link to every one, so you can see at a glance that a control described as broad is not automatically broad in your estate.

How to read a mitigation honestly

ATT&CK mappings are a starting point for a control assessment, not evidence that a control exists. Four questions separate the two.

  • The plan is not the control. Multi-factor Authentication is a sentence in a policy document until the legacy authentication protocols are switched off, the break-glass account has a monitored credential rather than a shared static password, and remembered sessions expire in hours rather than months. The test is not whether the control is documented, but what an attacker who already holds a valid password can still do with it.
  • Addressing a technique is not stopping it. The count of techniques a mitigation addresses comes from the mapping, and a mapping describes relevance rather than effect. Update Software addresses a broad set of techniques in ATT&CK, and its real coverage in your estate is still bounded by how accurate the asset inventory is and how long the window between public disclosure and patch deployment is. Multiply the mapping by your own numbers before you believe it.
  • A deployed but unmonitored control is not a control. Execution Prevention that blocks a script and writes a log entry nobody reads has changed nothing about your ability to see the intrusion; it has only changed where the evidence sits. The control counts when it produces an alert, that alert has an owner, and someone has decided what to do with it at three in the morning.
  • Ask for the last three times it fired. A control that has never produced a triaged event is an assumption, not a capability. Ask for the last three hits, who handled them, and what changed afterwards — including the awkward case where the answer is that the hits were excluded months ago during a noisy week and the exclusion was never revisited.
