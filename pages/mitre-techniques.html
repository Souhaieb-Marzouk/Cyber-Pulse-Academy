MITRE ATT&CK Techniques

CyberMastery covers 33 ATT&CK techniques: 20 parent techniques and 13 sub-techniques. A parent technique names a class of behaviour — Command and Scripting Interpreter, Phishing, Valid Accounts — and a sub-technique narrows it to something you can write a rule against. That distinction is the whole point of the hierarchy, and it is why the sub-technique count matters more than the parent count when you are building detection coverage.

The default view groups the techniques by parent tactic, because that is the question defenders usually start from: what is the adversary trying to achieve here? Switch the grouping to theme for the catalog's own organising labels, or turn grouping off for the standard searchable card list with its theme and batch filters. The tactic filter and the text filter apply in every mode, and each technique card links to its own study topic.

Sub-techniques are where the real work is

A parent technique is a category and a sub-technique is an observable. Four points worth internalising before you build coverage around either.

  • A parent technique is nearly undetectable on its own. "Command and Scripting Interpreter" covers PowerShell, the Windows command shell, Unix shells and every other runtime an adversary can reach. As a detection concept it is almost useless, because the behaviour is legitimate for most of the estate most of the time. T1059.001 PowerShell with an encoded command line, launched from an Office process, is a rule. Learn the parent for the taxonomy and the sub-technique for the detection.
  • Each sub-technique has a different log source behind it. The Windows command shell leaves process-creation records with unusual parent lineage; the Unix shell leaves execve audit records and shell history; PowerShell leaves script-block and module logging, if it was ever enabled. Knowing which telemetry answers which sub-technique is the actual study task, and it is what the exercise batches test.
  • Mitigations do not flow down automatically. A control can address a parent technique while leaving a specific sub-technique reachable — Execution Prevention may stop an unsigned script and do nothing about a signed management binary used as a proxy. Read the per-technique mitigation list rather than assuming the parent's controls cover the children.
  • The sub-technique id is the shared vocabulary. Detection engineers, threat intelligence reports and coverage spreadsheets all key on T1059.001 far more often than on T1059. Learn the 13 covered here, then use the parent id only when you are deliberately talking about the category.
